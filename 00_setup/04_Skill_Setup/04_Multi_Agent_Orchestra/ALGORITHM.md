# อัลกอริทึม KC-QUEST (KMITL–Chanwanich Quota-Urgency Expiry-aware Scheduling Technique) · อธิบายเป็นสไลด์

![KC-QUEST คืออะไร: K = KMITL · C = Chanwanich ร่วมมือกัน · Q = Quota โควตา · U = Urgency ความเร่งด่วน · E = Expiry วันหมดอายุ · S = Scheduling จัดตารางงาน · T = Technique เทคนิค](image/kcquest-name.png)

> **KC-QUEST** = **K**MITL–**C**hanwanich **Q**uota-**U**rgency **E**xpiry-aware **S**cheduling **T**echnique · แปลว่า *เทคนิคจัดตารางงานที่คำนึงถึงโควตา ความเร่งด่วน และวันหมดอายุ* · พัฒนาเป็นสื่อการสอนร่วมกันระหว่าง **สถาบันเทคโนโลยีพระจอมเกล้าเจ้าคุณทหารลาดกระบัง (KMITL)** และ **บริษัท จันวณิช (Chanwanich · CWN)** · (ชื่อเดิม: EUBF · Expiry-Urgency Best-Fit)

> เอกสารประกอบ [LAB 04.2](readme.md) — อัลกอริทึมที่ `tools/orch.py` ใช้เลือกว่า "งานไหนให้บัญชี AI ไหนทำ"
> **อ่านทีละภาพ — 1 ภาพ = 1 ไอเดีย** · ทุกขั้นเริ่มจาก **ทฤษฎี (ไอเดียมาจากไหน)** → **ตัวแปรแต่ละตัวหมายถึงอะไร มาจากไหน** → **คำนวณด้วยตัวเลขจริง**
> ตัวเลขทั้งหมดมาจากรอบแจกงานจริง **23:37:26** ของงาน BuildMart ซึ่ง replay ด้วยโค้ดจริง (`plan_assignments()`) แล้วได้ **ตรงกับ log 9/9 งาน** (บัญชี · ลำดับ · คะแนน · อันดับ 2)

![ตารางที่ 1 ขั้นตอนของอัลกอริทึม KC-QUEST: ขั้น อินพุต สมการ เอาต์พุต ความซับซ้อน](image/paper-table1-pipeline.png)

![Algorithm 1 KC-QUEST-Dispatch และ Algorithm 2 KC-QUEST-Monitor แบบ pseudocode](image/paper-algorithm.png)

![ตารางที่ 2 สัญลักษณ์ที่ใช้ในอัลกอริทึม KC-QUEST](image/paper-table2-notation.png)

**สิ่งที่รับประกัน / ไม่รับประกัน**

| ข้อ | ค่า |
|---|---|
| เวลาแจกงานต่อรอบ | $O(N\lvert A\rvert)$ — < 1 วินาที · ไม่ใช้โทเคน |
| ทุกงานที่แจก "ปิดได้" ตามค่าประเมิน | $\sigma r c_j\le H-m-Q$ ทั้ง 5 ชม. และสัปดาห์ |
| ไม่ย้ายไปมา | เส้นแจกงาน (มี $\sigma$) อยู่ใต้เส้นย้ายงานเสมอ (unit test ข้อ 13) |
| ไม่ค้าง | relay เมื่อทีมรวมกันพอ · best-effort เมื่อทีมว่าง |
| ไม่ได้รับประกัน | KC-QUEST เป็น heuristic (ปัญหาจริงเป็น NP-hard) — ในตัวจำลองเร็วสุด 6/7 สถานการณ์ · สถานการณ์โควตาตึงช้ากว่าการสุ่ม ~6% |

**การตรวจความเข้าใจ:** เนื้อหาชุดนี้ผ่านการให้ AI สวมบทนักศึกษา IT ปี 3 จำนวน 3 แบบ (ทั่วไป · คณิตอ่อน · เขียนโปรแกรมเก่ง) อ่านและคำนวณตามทีละขั้น — 2 รอบ ปรับแก้ตามจุดที่สะดุดทั้งหมด เช่น เพิ่มสไลด์อ่านสัญลักษณ์และคำ · ไทม์ไลน์ · ข้อมูลตั้งต้นครบ · บอกที่มาของทุกตัวเลข · บอกวิธีปัดเลขและกรณีเสมอ · แยกขั้น ⑤ เป็น “ค่ามาจากไหน” กับ “ตัดสิน” · ใช้ตัวเลขจริงแทนค่าประมาณ · นักศึกษาสายโปรแกรมคำนวณตามสไลด์ได้ **ตรงกับ log 9/9 งาน**
