# FRONTEND_RECIPE — สร้างหน้าแชทบอทร้านค้าจาก requirement ในพรอมต์

> ไฟล์นี้บอก AI ว่า **สร้าง frontend อย่างไร และตรวจงานอย่างไร**
> ส่วน **"ร้านเป็นอย่างไร"** (ข้อมูลร้าน · บริการ · กฎของบอท) และ **"ต้องตอบถูกแบบไหน"** (เงื่อนไขทดสอบ) ผู้ใช้เขียนมาในพรอมต์
> AI เขียนโค้ดเอง รันเอง ทดสอบเอง ทำ GIF เอง · เฉลยของผู้สอนอยู่ที่ `_solution/ex2_chatbot/frontend/` — **AI ห้ามเปิดหรือคัดลอกโฟลเดอร์เฉลย**

## 0) อ่านจากพรอมต์

| หัวข้อในพรอมต์ | ใช้ทำอะไร |
|---|---|
| `MODE=ai` หรือ `MODE=mock` | `ai` = ต่อ AI จริงบน Vast.ai (อ่านจาก `_solution/ex2_chatbot/backend/.env.vast`) · `mock` = สร้างบอทจำลองเอง ไม่ต้องใช้ GPU |
| `OUT=` | โฟลเดอร์ปลายทาง (ไม่ระบุ = `00_setup/04_Skill_Setup/01_VastAi_Skill/my_chatbot`) |
| **ข้อมูลร้าน** | ชื่อร้าน เวลา ที่อยู่ โทร โปรโมชัน นโยบาย ที่จอดรถ → ลงตาราง `shop_info` |
| **บริการ** | ชื่อ · นาที · ราคา · รายละเอียด → ลงตาราง `services` |
| **กฎของบอท** | เพิ่มเข้า system prompt |
| **เงื่อนไขทดสอบ** | แต่ละข้อมี 3 ส่วน: ลูกค้าทำอะไร → **ต้องมีอะไรในคำตอบ** (ใช้ตรวจ) \| **คำตอบที่ควรได้** (baseline ไว้ให้คนเทียบ) → แปลงเป็นเทสต์ Playwright ข้อละ 1 เคส |

ข้อมูลร้าน/บริการ **ต้องมาจากพรอมต์เท่านั้น** ห้ามแต่งเพิ่ม

## 1) สถาปัตยกรรม (ต้องเป็นแบบนี้ เพราะ README ใช้สอน)

```
เบราว์เซอร์ ── หน้าแชท (Next.js page) ──► /api/chat (Next.js API route, Node)
                                            │ ① ดึงข้อมูลร้าน+บริการ+ประวัติแชทจาก PostgreSQL
                                            │ ② สร้าง system prompt จากข้อมูลนั้น
                                            │ ③ เรียก LLM แบบ OpenAI (stream) ──► Qwen บน Vast.ai :8080 (หรือ mock)
                                            │ ④ ส่งคำตอบกลับทีละส่วน (SSE)
                                            └ ⑤ ถ้าจองครบ → INSERT bookings → ส่งการ์ดจองสำเร็จ
หน้า /bookings (Next.js page) ── อ่านตาราง bookings จาก PostgreSQL
```

- **Next.js (App Router, TypeScript) + PostgreSQL 16** · รันด้วย **Docker Compose** (service `web`, `db` และ `mock-llm` เฉพาะ `MODE=mock`) · เว็บที่ **http://localhost:3300** · db ไม่เปิด port ออกนอก
- ตาราง: `shop_info(key,value)` · `services(id,name_th,duration_min,price_thb,description_th)` · `bookings(id,customer_name,phone,service_id,booking_time,status,created_at)` · `chat_messages(id,session_id,role,content,created_at)` · ใส่ข้อมูลจากพรอมต์ด้วยไฟล์ init SQL ตอนสร้าง db ครั้งแรก
- **LLM**: env `LLM_BASE_URL` (ไม่มี `/v1`) · `LLM_MODEL` · `LLM_API_KEY` (Bearer) · timeout 120 วินาที · `temperature` ต่ำ (~0.3) · ตัด `<think>…</think>` ถ้ามี
  - `MODE=ai` → คัดลอก 3 บรรทัด `LLM_*` จาก `backend/.env.vast` ไปไว้ใน `.env` ของโปรเจกต์ (**ห้ามแสดง key บนจอ** · `.env` อยู่ใน `.gitignore`)
  - `MODE=mock` → บริการ mock แบบ OpenAI-compatible (รองรับ stream) ตอบจากคำสำคัญ + ข้อมูลร้านใน system prompt ให้ผ่านเงื่อนไขทดสอบ
- **system prompt**: บทบาทพนักงานร้าน · ตอบไทยสุภาพ ลงท้าย ค่ะ/นะคะ กระชับ · ตอบเฉพาะเรื่องร้าน ห้ามแต่งข้อมูล · ห้าม markdown · แนบข้อมูลร้านและรายการบริการทั้งหมด · วันเวลาปัจจุบัน (Asia/Bangkok) · กฎของบอทจากพรอมต์
- **การจอง**: ให้ LLM ถามให้ครบ ชื่อ · เบอร์ · บริการ · วันเวลา (ในเวลาเปิดร้าน) แล้วปิดท้ายด้วยบรรทัดเดียว `[BOOKING]{"customer_name":…,"phone":…,"service":…,"booking_time":"YYYY-MM-DD HH:MM"}` → server ตัดแท็กออกจากข้อความที่แสดง จับคู่ชื่อบริการ แล้วบันทึก
- **หน้าแชท**: ข้อความต้อนรับตั้งแต่เปิดหน้า · ปุ่มลัด 5 ปุ่ม (ดูราคา · เวลาเปิดปิด · แนะนำนวดแก้ปวดหลัง/บริการแนะนำ · โปรโมชัน · จองคิว) ปิดกดระหว่างบอทตอบ · "กำลังพิมพ์…" · การ์ดจองสำเร็จ · ลิงก์ไป `/bookings`
- ใส่ `data-testid` ให้ส่วนสำคัญ (ช่องพิมพ์ ปุ่มส่ง ฟองข้อความ+บทบาท ปุ่มลัด การ์ดจอง แถวในตารางจอง) เพื่อให้เทสต์หาเจอ
- มี `README.md` สั้น ๆ ภาษาไทยในโปรเจกต์ อธิบายโครงสร้างไฟล์ตามสถาปัตยกรรมข้างบน

## 2) ขั้นตอน (AI ทำเองทั้งหมด · ทำให้จบในรอบเดียว)

1. ตรวจ Docker ทำงาน · port 3300 ว่าง (ถ้าโปรเจกต์เดิมของ LAB นี้รันอยู่ให้ปิดก่อน) · `MODE=ai` ต้องมี `backend/.env.vast` และ `GET <LLM_BASE_URL>/health` ผ่าน — ไม่ผ่านให้หยุดและบอกผู้ใช้
2. สร้างโปรเจกต์ใน `OUT` ตามข้อ 1 → build + รันด้วย Docker Compose → รอจน http://localhost:3300 ตอบ
3. **สร้างเทสต์จากเงื่อนไขทดสอบในพรอมต์** ไว้ที่ `OUT/e2e` (Playwright + Chromium, ข้อละ 1 เคส, ชื่อเคส `caseN-<คำสั้น>`):
   - พิมพ์/กดปุ่มแบบเห็นการพิมพ์ทีละตัว (`pressSequentially` delay ~45 ms, `slowMo` ~40) ขนาดจอ 1000×720 · บันทึกวิดีโอทุกเคส
   - ตรวจตามส่วน "ต้องมี" ของแต่ละข้อ (regex คำสำคัญ/ตัวเลข ตัดช่องว่างและ comma ในตัวเลขก่อนตรวจ) — **ไม่ต้องตรงกับ baseline ทุกคำ** เพราะ LLM จริงตอบไม่เหมือนเดิมทุกครั้ง · เคสจองคิวให้ตอบคำถามบอททีละขั้นจนเห็นการ์ดจองสำเร็จ แล้วไปหน้า `/bookings` ต้องเห็นแถวนั้น
   - หยุดค้างหน้าจอ ~2 วินาทีหลังได้คำตอบ ให้คนดูวิดีโออ่านทัน
4. รันเทสต์ทั้งหมด → ถ้าตก ให้แก้**แอป** (เช่น system prompt) แล้วรันซ้ำ ไม่เกิน 3 รอบ · **ห้ามแก้เงื่อนไขให้หลวมกว่าที่ผู้ใช้เขียน**
5. แปลงวิดีโอเป็น **GIF** (ffmpeg: fps 8, กว้าง 800, palette) ไว้ที่ `OUT/test-gifs/caseN-<คำสั้น>.gif` (ถ้าไม่มี ffmpeg ให้ใช้ npm `ffmpeg-static`)
6. เขียน `OUT/TEST_REPORT.md` เป็นตาราง: เคส · ลูกค้าทำอะไร · **คำตอบที่ควรได้ (baseline)** · **คำตอบจริงของบอท** (เต็ม ไม่ย่อ) · ต้องมี · ผ่าน/ไม่ผ่าน · ไฟล์ GIF — ให้คนเทียบ baseline กับของจริงได้ทันที
7. สรุปบนจอเป็นภาษาไทย: ผ่านกี่ข้อจากทั้งหมด · ข้อที่ไม่ผ่านและเหตุผล · URL หน้าแชท/รายการจอง · ประโยคที่ผู้ใช้ใช้สั่งปิดได้ (เช่น "ปิดหน้าแชทบอท")

## 3) กติกา
