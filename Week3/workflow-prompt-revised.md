## เป้าหมายการเรียนรู้
   จัดลำดับเนื้อหา Slide และ LAB ตามพัฒนาการต่อไปนี้
    1. **Single Prompt:** ใช้คำสั่งเดียวสร้างผลงาน เพื่อเก็บผลลัพธ์ตั้งต้นสำหรับเปรียบเทียบ
    2. **Loop:** ตรวจสอบและปรับปรุงผลงานเป็นรอบ โดยมีเกณฑ์ประเมินและเงื่อนไขหยุด
    3. **Static Graph:** แบ่งงานเป็นขั้นตอน กำหนดความสัมพันธ์และลำดับการทำงานไว้ล่วงหน้า
    4. **Conditional Graph:** เลือกเส้นทางตามเงื่อนไข โดยเส้นทางที่เป็นไปได้ถูกกำหนดไว้ก่อนเริ่มงาน
    5. **Dynamic Workflow:** สร้างหรือปรับรายการงานและความสัมพันธ์ระหว่างงานระหว่างการทำงาน ตามข้อมูลที่พบ
    6. **Re-planning Workflow:** ประเมินแผนเดิมและวางแผนใหม่เมื่อข้อมูล ข้อจำกัด หรือผลลัพธ์เปลี่ยนไป
   
   เมื่อจบบทเรียน นักศึกษาต้องสามารถ:
    - อธิบายความแตกต่างและข้อจำกัดของแต่ละแนวทาง
    - เลือก Workflow ให้เหมาะกับปัญหา ความเสี่ยง และงบประมาณ
    - ออกแบบการแบ่งงาน การตรวจทาน การรวมผล และการรับมือกับงานที่ล้มเหลว
    - ผลิตเอกสาร SA ที่เชื่อมโยงกันตั้งแต่ User Story ถึงสิ่งส่งมอบให้ Developer และ QA
    - เปรียบเทียบคุณภาพ เวลา จำนวนรอบ และต้นทุนจากหลักฐานการทำงานจริง



## เนื้อหาใน Slide ทฤษฎีที่ต้องอธิบายอย่างละเอียด

    ### Loop Engineering
    - วงรอบสร้างผลงาน → ตรวจสอบ → ระบุข้อบกพร่อง → แก้ไข → ตรวจซ้ำ
    - บทบาทของผู้สร้าง ผู้ตรวจ และเกณฑ์ประเมินที่ใช้ร่วมกัน
    - ความต่างระหว่างการลองใหม่เมื่อทำงานล้มเหลว กับการปรับปรุงเนื้อหาตามข้อเสนอแนะ
    - เงื่อนไขหยุด ได้แก่ ผ่านเกณฑ์ ถึงเพดานรอบ หมดงบ หรือคุณภาพไม่ดีขึ้น
    - วิธีบันทึกผลแต่ละรอบและป้องกันการวนซ้ำโดยไม่มีความคืบหน้า
    - ตัวอย่างการแก้ User Story ที่กำกวม เกณฑ์รับที่วัดไม่ได้ และข้อกำหนดที่ตกหล่น
    
    ###  Graph Engineering
    - Node, Edge, Dependency, State และข้อมูลที่ส่งต่อระหว่างขั้นตอน
    - Static Graph และ Conditional Graph รวมถึงความต่างระหว่างการเลือกเส้นทางเดิมกับการสร้างแผนงานใหม่
    - รูปแบบ Sequential, Fan-out/Fan-in และการตรวจทานหลายมุมมอง
    - การใช้ DAG กับงานที่ไม่มีวงย้อนกลับ และการแสดง Loop ใน Graph ที่มีวงรอบอย่างชัดเจน
    - การแบ่งวิเคราะห์ตามบทบาท แล้วรวมผลโดยจัดการข้อกำหนดซ้ำและข้อขัดแย้ง
    - การกำหนดรูปแบบผลลัพธ์ เกณฑ์รวมงาน และวิธีรับมือเมื่อบางงานล้มเหลว
    - Self-consistency: สร้างคำตอบหลายชุดแล้วเปรียบเทียบด้วยเกณฑ์และหลักฐาน โดยไม่ถือว่าความเห็นส่วนใหญ่ถูกเสมอ
    
    ###  Dynamic Workflow และ Re-planning
    - การใช้ข้อมูลระหว่างทางเพื่อเพิ่ม แยก ยกเลิก หรือจัดลำดับงานใหม่
    - บทบาทของ Planner, Executor และ Evaluator พร้อมขอบเขตการตัดสินใจ
    - ความต่างระหว่าง Conditional Routing, การแก้ผลงานใน Loop และการวางแผนใหม่
    - การวิเคราะห์ผลกระทบต่อผลงานเดิม และเลือกใช้ซ้ำเฉพาะส่วนที่ยังถูกต้อง
    - การบันทึกแผนแต่ละเวอร์ชัน เหตุผลที่เปลี่ยน และข้อจำกัดด้านเวลา/งบประมาณ
    - ตัวอย่างเหตุการณ์ เช่น วัตถุดิบหมดระหว่างมีออเดอร์ ทันตแพทย์ลาฉุกเฉิน หรือสต็อกออนไลน์ขัดกับหน้าร้าน
    ต้องแสดงให้เห็นด้วยว่าเหตุการณ์ทางธุรกิจเหล่านี้ทำให้ **แผนงานของ AI ในการวิเคราะห์ระบบ** เปลี่ยนอย่างไร แยกจากการเปลี่ยนสถานะออเดอร์ นัดหมาย หรือสินค้าในระบบธุรกิจ

## กติกา
- เอกสาร LAB ใช้ **placeholder เท่านั้น** — ห้ามใส่ email/ชื่อจริง/token/username จริง
- วาดรูปด้วย **Excalidraw MCP** · ทดสอบ web + capture ภาพจริงด้วย **Playwright CLI**




แต่ละ Lab ต้องมี:
1. ปัญหาธุรกิจและเหตุผลที่ใช้ Workflow นี้
2. เป้าหมาย ความรู้ก่อนเรียน และเวลาประมาณการ
3. ข้อมูลตั้งต้น ไฟล์ที่ใช้ และสิ่งส่งมอบ
4. แผนภาพ Workflow พร้อมคำอธิบายการส่งต่องาน
5. Prompt ที่คัดลอกไปใช้ได้ และขั้นตอนสำหรับ Claude Code หรือ Codex
6. แนวทางแก้ปัญหา ตัวอย่างผลลัพธ์ที่คาดหวัง และข้อผิดพลาดที่พบบ่อย
7. เกณฑ์ตรวจงาน เงื่อนไขหยุด และคำถามอภิปราย

##  การวัดผลและเปรียบเทียบ

ใช้เกณฑ์เดียวกันเมื่อเปรียบเทียบ Workflow บนกรณีศึกษาเดียวกัน โดยพิจารณา:
- ความครบถ้วนของบทบาทและกฎธุรกิจ
- ความชัดเจนและความสามารถในการทดสอบ Acceptance Criteria
- ความสอดคล้องระหว่าง User Story, Requirements, Flow และ UI
- จำนวนข้อขัดแย้ง ข้อมูลตกหล่น และสมมติฐานที่ยังไม่ยืนยัน
- ความสามารถในการตรวจสอบย้อนกลับและรับมือกับการเปลี่ยนแปลง
- เวลา จำนวนรอบ จำนวนการเรียก Agent และต้นทุนที่วัดได้
