# บท 04 · สบายใจ สปา: จากการฟังร้าน สู่เว็บจริงและแผนทดสอบ (Copy & Paste)

บทนี้เริ่มจาก **บันทึกสัมภาษณ์เจ้าของร้านและลูกค้า** ไม่มีเว็บ ไม่มีสเปก แล้วเดินครบเส้นทางของงานจริง: ฟังร้าน → เขียน FR / BR / NFR → ออกแบบระบบ → ให้ agent ช่วยกันสร้างเว็บ → สำรวจ → เขียนแผน → ทดสอบจริงด้วย Playwright → ล่าบั๊กปริศนา

เราไม่ต้องเขียนโค้ดเอง หน้าที่ของเราคือ **คัดลอกพรอมต์ → วางใน Claude Code → อ่านผล → ตัดสินใจ**

![คุณจันทร์เจ้าของร้านคุยกับเทสเตอร์ที่โต๊ะไม้สัก (ภาพจำลอง)](img/c-listen.jpg)

![GIF ภาพรวม 5 ช่วงของบท: ฟังร้าน LAB 1–4 · สร้างเว็บ LAB 5–6 · สำรวจ LAB 7–9 · เขียนแผน LAB 10–11 · พิสูจน์ LAB 12–13 ปิดท้ายด้วยประโยค ร้านขอ ไม่เท่ากับ AI บอกว่าทำแล้ว ไม่เท่ากับ เว็บทำจริง](img/overview-5-phases.gif)

ประโยคหลักของบท: **"ร้านขอ ≠ AI บอกว่าทำแล้ว ≠ เว็บทำจริง"** เว็บนี้ AI สร้างเองทั้งหมด และ AI ก็รายงานว่าตรวจกฎผ่าน แต่งานของ tester คือ **พิสูจน์** ไม่ใช่เชื่อ

> บทนี้ **ยังไม่ใช้ skill** ทุกขั้นเป็นพรอมต์ที่คัดลอกไปวาง · ภาพคนและภาพร้านทุกภาพเป็นภาพจำลองจาก image gen บุคคลในภาพไม่มีตัวตนจริง · ตัวเลขใน ✅ ผลจริง มาจากการรันจริงเมื่อ 6 พ.ย. 2569

## LAB 0 · เช็กเครื่อง

🎯 รู้ก่อนว่าเครื่องพร้อมไหม จะได้ไม่ไปติดกลางทาง

📋 **วางพรอมต์**

![หน้าต่าง Claude Code วางพรอมต์ LAB 0](img/lab0-paste.png)

```text
ตรวจเครื่องให้พร้อมสำหรับบทนี้ ทุกค่าต้องมาจากคำสั่งที่รันจริง (ห้ามแก้ไฟล์ · ติดตั้งได้แค่ playwright-cli ในข้อ 5)
1. Docker Desktop เปิดอยู่ไหม: docker version และ docker compose version
2. Node.js: node -v (ต้อง 20 ขึ้นไป) และ npm -v
3. ffmpeg -version (ใช้ทำ GIF ตอนทดสอบ)
4. พอร์ต 3000 (เว็บ) และ 5433 (ฐานข้อมูล) ว่างไหม ถ้ามีอะไรใช้อยู่ให้บอกชื่อ (ยังไม่ต้องปิด)
5. playwright-cli --version ถ้าไม่มีให้ npm install -g @playwright/cli@latest · จากนั้นลองเปิดเบราว์เซอร์ 2 ตัวพร้อมกัน ชื่อ a และ b (playwright-cli -s=a open https://example.com) แล้ว playwright-cli list ต้องเห็น 2 ตัว แล้วปิดทั้งหมด
6. โฟลเดอร์นี้มี interview/INTERVIEW.md, interview/OWNER-ANSWERS.md และ brand-kit/ ไหม นับจำนวนรูปใน brand-kit
สรุปเป็นตาราง: รายการ | ผล | พร้อมไหม | ถ้าไม่พร้อมต้องทำอะไร
```

✅ **ผลจริง (1 นาที)** Docker · Node · ffmpeg · playwright-cli พร้อม · พอร์ต 3000 และ 5433 ว่าง · เปิดเบราว์เซอร์ 2 ตัวพร้อมกันได้ · `brand-kit/` มี 60 รูป

👀 **สังเกต**
- พอร์ตฐานข้อมูลเป็น **5433** ไม่ใช่ 5432 จะได้ไม่ชนกับ Postgres ที่อาจติดตั้งในเครื่องแล้ว
- `playwright-cli` เปิดเบราว์เซอร์แยกกันได้หลายตัว นี่คือเหตุผลที่ LAB 8 แบ่ง agent ได้ (บท 03 อธิบายไว้แล้ว)

✔️ **ไปต่อได้เมื่อ:** Docker · Node · playwright-cli พร้อม และพอร์ตว่าง

## LAB 1 · ฟังร้าน → User Story

🎯 เปลี่ยนคำพูดของคุณจันทร์และลูกค้า 5 กลุ่ม เป็น `USER-STORIES.md` ที่ตรวจได้ทุกข้อ และรู้ว่าต้องถามร้านเรื่องอะไรกลับ

### 1.1 ฟังก่อนสร้าง

ถ้ารีบเขียนโค้ด เราจะสร้างสิ่งที่ "คิดว่าร้านอยากได้" งานจึงเริ่มจากการฟังให้ครบทุกกลุ่ม แล้วแยกให้ออกว่าใครพูดอะไร

![เทสเตอร์จัดโน้ตบนผนังใต้รูปลูกค้าแต่ละกลุ่ม (ภาพจำลอง)](img/c-story-wall.jpg)

![GIF ลูกค้า 6 กลุ่มพร้อมรูปจริงและสิ่งที่อยากได้ แล้วขึ้นตัวเลขผลจริง User Story 39 ข้อ คำถามกลับถึงร้าน 21 ข้อ เรื่องที่พูดขัดกันเอง 11 ข้อ](img/lab1-six-voices.gif)

### 1.2 User Story = 3 ส่วน + เกณฑ์ยอมรับ

"จองง่าย" ตรวจไม่ได้ ต้องแปลงเป็น **ในฐานะ… ฉันอยาก… เพื่อ…** แล้วบอกให้ชัดว่าเห็นอะไรถึงนับว่าเสร็จ

![GIF คำพูดของคุณจันทร์และคุณเมย์ไหลเข้าการ์ด US-03 ห้ามจองเวลาทับกัน ขึ้นทีละบรรทัด ในฐานะ ฉันอยาก เพื่อ เกณฑ์ยอมรับ และป้าย Must](img/lab1-interview-to-story.gif)

### 1.3 ลงมือ

📋 **วางพรอมต์**

![หน้าต่าง Claude Code วางพรอมต์ LAB 1](img/lab1-paste.png)

```text
อ่าน interview/INTERVIEW.md (บันทึกสัมภาษณ์เจ้าของร้านและลูกค้าของ "สบายใจ สปา" รอบแรก) แล้วเขียนไฟล์ USER-STORIES.md
1. เขียน User Story แบบ "ในฐานะ… ฉันอยาก… เพื่อ…" ให้ครบทุกเรื่องที่ทุกคนพูด ใส่รหัส US-01, US-02, …
2. แต่ละข้อมี "เกณฑ์ยอมรับ" 1–2 ข้อ ที่ตรวจได้จริง (มีตัวเลขหรือข้อความชัด ๆ)
3. ติดป้ายความสำคัญ Must / Should / Could
4. ท้ายไฟล์ใส่ "คำถามที่ยังไม่ชัด" ที่ต้องถามร้านกลับ (รหัส Q1, Q2, …) และ "เรื่องที่พูดขัดกันเอง"
ใช้ภาษาไทยง่าย ๆ ใน story ห้ามใช้ศัพท์โปรแกรม (database, API) · ยังไม่ต้องอ่าน interview/OWNER-ANSWERS.md
แล้วสรุปเป็นตาราง: รหัส | เรื่อง | ใครขอ | ความสำคัญ และนับจำนวน Must / Should / Could
```

| ส่วนของพรอมต์ | มีไว้ทำไม |
|---|---|
| รหัส US-01, US-02, … | อ้างอิงต่อได้ทุก LAB จนถึงรายงานทดสอบ |
| เกณฑ์ยอมรับตรวจได้ | ไม่มีตัวเลขหรือข้อความชัด ๆ ก็เขียน test ไม่ได้ |
| "คำถามที่ยังไม่ชัด" และ "เรื่องที่พูดขัดกันเอง" | ไม่ให้ AI เดาเงียบ ๆ |
| ห้ามใช้ศัพท์โปรแกรม | เจ้าของร้านต้องอ่านแล้วเข้าใจ |
| ยังไม่อ่าน `OWNER-ANSWERS.md` | ฝึกตั้งคำถามก่อนรู้คำตอบ |

✅ **ผลจริง (6 นาที)** **39 story** (Must 14 · Should 15 · Could 10) · คำถามถึงร้าน 21 ข้อ · เรื่องที่พูดขัดกัน 11 ข้อ

| รหัส | เรื่อง | ใครขอ | ความสำคัญ |
|---|---|---|---|

| US-03 | ห้ามจองเวลาทับกัน | คุณจันทร์ | Must |
| US-05 | จองรอบ 20:00 จากมือถือแบบไม่ยุ่งยาก | คุณเมย์ | Must |
| US-26 | เห็นค่ารถก่อนจ่ายเงิน | Mr. Li Wei | Must |
| US-38 | ส่งเซลฟี่วิเคราะห์ผิว โดยรูปไม่ถูกส่งออกไปเก็บ | น้องแพร | Could |

## 📖 คำศัพท์

| คำ | ความหมายง่าย ๆ |
|---|---|
| **User Story** | คำขอ 1 ข้อ "ในฐานะ… ฉันอยาก… เพื่อ…" |
| **FR / BR / NFR** | ระบบทำอะไรได้ / กฎร้าน มีตัวเลข / ดีแค่ไหน วัดได้ |
| **ค่าขอบ (Boundary)** | ค่าที่อยู่ตรงเส้นของกฎ เช่น ฿9,999 / ฿10,000 |
| **System Architecture** | แผนผังว่าระบบมีกล่องอะไร คุยกันยังไง |
| **Use Case / Flowchart / ERD / Sequence** | ใครทำอะไร / ขั้นตอนและทางแยก / ตารางข้อมูล / ลำดับการคุยกัน |
| **EXCLUDE constraint** | กฎในฐานข้อมูลที่ห้ามข้อมูลทับกัน เช่น คิวเวลาซ้อน |
| **API-CONTRACT** | สัญญากลางระหว่างหน้าเว็บกับ API ทำให้แยกกันทำได้ |
| **Charter** | ภารกิจสำรวจ 1 ใบ มีส่วนของเว็บ ข้อมูล และสิ่งที่ตามหา |
| **Test oracle** | แหล่งที่บอกว่าผลแบบไหนถูก บทนี้ใช้ [D] [R] [A] [O] |
| **อบบั๊ก** | ลอกค่าผิดจากหน้าจอไปเป็นผลที่คาดหวัง |
| **Traceability** | สายโยงจาก test ย้อนไปหากฎและคำพูดของร้าน |
| **Coverage matrix** | ตารางฟีเจอร์ × เทคนิค ใช้หาช่องที่ขาด |
| **BUG_MODE** | สวิตช์เปิดบั๊กที่ฝังไว้ให้ฝึกหา |
