## ตัวอย่างแถวเด่น (ใช้ใน README)

1. `healthcheck ด้วย node: node -e "fetch('http://127.0.0.1:3000/api/health')...process.exit(j.db?0:1)"` — ไม่ต้องพึ่ง curl ใน image
2. `docker network inspect sabai-net *> $null; if (-not $?) { docker network create sabai-net }` — คำสั่ง PowerShell ล้วน
3. "ห้ามต่อฐานข้อมูลตอน build: `export const dynamic = "force-dynamic"` และสร้าง Pool แบบ lazy"
4. "ทุกตัวต้องเป็นแบบ ถ้าลอกค่าจากหน้าจอไปเป็นผลที่คาดหวัง จะจับไม่ได้ (หน้าจอกับ db ผิดตรงกัน)"
5. "ต้องผ่านครบที่ BUG_MODE=0 ถ้าไม่ครบให้แก้โค้ด (ห้ามแก้ค่าที่คาดหวังให้ตรงกับโค้ด)"
6. "ข้อไหนเอกสารขัดกัน: TEST-DATA.md > REQUIREMENTS.md > DESIGN.md"

## ข้อสังเกต 👀

- 👀 พรอมต์ LAB 5 ยาวและมี 11 ข้อ — ถ้าเขียนทุกข้อเต็มรูปจะเกิน 150 บรรทัดง่าย ต้องอ้าง "ตาม DESIGN.md / TEST-DATA.md" แทนการลอกตาราง
- 👀 seed ต้องใช้ได้ 2 ที่ (init ของ postgres + /api/test/reset) — ใส่คำสั่ง "ห้ามมีค่าซ้ำ 2 ที่" กัน seed กับ reset ไม่ตรงกัน
- 👀 healthcheck ของ web ใช้ `127.0.0.1` แทน `localhost` เพราะใน alpine `localhost` อาจ resolve เป็น ::1 ขณะที่ server ฟัง 0.0.0.0
- 👀 บั๊กแบบ "ลอกค่าจากจอแล้วจับไม่ได้" = หน้าจอกับ db ต้องผิดเหมือนกัน ถ้าจอผิดแต่ db ถูก NFR-17 (ยอดสรุป = ยอดเก็บจริง) จะจับได้ทันที — เขียนกำกับไว้ในขั้น 9
- 👀 ข้อห้ามเปิดเผยบั๊กอยู่ 2 ที่ (ขั้น 9 และขั้น 11 ข้อ 7) เพราะตอนสรุปท้ายเป็นจุดที่ Claude มักเผลอเล่า
- ไม่มีปัญหาทางเทคนิคในการรัน LAB นี้ (ไม่ได้รัน Docker ตามข้อห้าม "ขั้นนี้ห้ามเขียนโค้ดเว็บ")
