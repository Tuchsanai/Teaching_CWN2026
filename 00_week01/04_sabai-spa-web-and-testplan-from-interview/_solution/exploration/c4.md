3. **เครื่องคำนวณไม่ส่งค่าต่อ**: ลูกค้าคำนวณ 5 คนแล้วเข้าหน้าจองที่ 1 คน เสี่ยงลืมเปิดรถแล้วจองโดยไม่มีรถ เพราะรถเป็นส่วนเสริมที่ปิดอยู่
4. **ยอดเก่าค้างตอนระยะไม่รับ**: มีป้ายเตือนและปุ่มล็อก จึงจองผิดไม่ได้ แต่ยังเห็น "ค่ารถ ฿0 จ่าย ฿2,900" คู่กับ 15.1 กม. ซึ่งอาจอ่านผิด
5. **รีโหลดที่ขั้น 3 ข้อมูลหาย**: วัน รอบ รถ ชื่อ และเบอร์หาย ต้องเริ่มใหม่
6. **ข้อจำกัดของผลทดสอบ**: ไม่ได้ทดสอบ race จริงของ quote · E148–E149 หลังกดเสร็จ · FR-55 รถหลายคันรอบเดียวกัน · U03, U05, U10 ไม่ได้กดยืนยันตามข้อห้าม · ไม่ได้ลองหน้าจอแคบ · ภาษา `/en` ทั้งหมด

**สิ่งที่ยังไม่ได้ทำ:** รายการข้อ 6 · สมัครบัญชีใหม่ `c4-*` (ไม่ได้ใช้ใน charter นี้) · E66 เป็น unit test นอกขอบเขตเว็บ · E103 ส่งต่อ C3

**ไม่พบการชนกับ charter อื่น:** ไม่มี 409 หรือรอบหายนอกเงื่อนไขในวันของ C4 · 409 ที่พบมาจากการตั้งใจส่ง P01 4 คนและราคาผิด

## E คำถามถึงทีม

### ถามร้าน

1. พนักงานขับรถดูข้อมูลการรับจากที่ไหน ต้องการเห็นโรงแรม ระยะ และจำนวนรถในตารางคิวรายวันหรือไม่
2. ลูกค้าที่พิมพ์ระยะเอง ร้านต้องการที่อยู่หรือชื่อสถานที่เพิ่มหรือไม่ และใครเป็นคนตรวจระยะจริง
3. ถ้าระยะจริงต่างจากที่ลูกค้าพิมพ์ เช่น พิมพ์ 5.0 แต่จริง 8 กม. ร้านเก็บ ฿300 หน้างานหรือไม่
4. Bangkok Relax 2 คนใช้ Couple Suite และ 3 คนไม่ใช้ เป็นกติกาที่ร้านต้องการจริงหรือไม่ (D-01, A-34)
5. ระยะ 15.1 กม. ขึ้นไป ร้านอยากให้โทรคุยเป็นกรณีพิเศษ หรือไม่รับเลย

### ถามคนสร้างเว็บ

1. ลิงก์ "จองคิวพร้อมรถรับส่ง" ควรส่งโรงแรม ระยะ และจำนวนคนต่อไปยังหน้าจองหรือไม่
2. ตอนระยะถูกปฏิเสธ ควรซ่อนยอดเก่าแบบเดียวกับตอน P01 ยังไม่ระบุระยะหรือไม่
3. API รับทั้ง `hotelId` และ `distanceKm` แล้วเงียบกับระยะ เป็นความตั้งใจหรือไม่
4. `.5`, `5.`, `-0` และ `+5` ตั้งใจให้ปฏิเสธหรือไม่ ถ้าใช่ควรใช้ข้อความที่ตรงสาเหตุ
5. จำนวนคนผิดในเครื่องคำนวณขึ้นแค่ "ข้อมูลไม่ถูกต้อง" ควรบอกช่องที่ผิดหรือไม่
6. P01 4 คนผ่าน API ตอบ `not-enough-therapists` แทนรหัสที่สื่อว่าเกินเพดาน 3 คน ตั้งใจหรือไม่
