# F4 · สมมติฐานที่สัญญาไม่ได้ระบุ

## การทำงาน
1. **แขกหรือสมาชิก**: หน้า server อ่าน `getSession()` แล้วส่ง role ให้ client · แขกไม่ยิง `/api/wallet` จึงไม่มี 401 ใน console · `CUSTOMER` ยิง wallet และถ้าได้ 401 (session หมดอายุ) ถือเป็นแขก · `OWNER` นับเป็นแขกตามสัญญา 2.2 ต้องกรอกชื่อและเบอร์
2. **รายชื่อนักบำบัดหน้าจอ 2** อ่านจาก `GET /api/therapists?service=<id>` ไม่ใช่ `availability.therapists` เพราะต้องแสดงก่อนเลือกวัน และแสดงต่อเมื่อวันที่ผิด · คาดว่า `?service=K01` ตอบ T01, T05 (FR-39)
3. **deep link ไม่ข้ามหน้าจอ**: `?service=&party=` เลือกค่าไว้ในหน้าจอ 1 ลูกค้ากดถัดไปเอง · `therapist` ที่ทำบริการนั้นไม่ได้ หรือจองหลายคน ถือเป็นใครก็ได้ · `?service=K01` ไม่มี `course` เลือกคอร์สแรกที่ใช้ได้
4. **`?code=` ของ `/booking/cancel`** เพิ่มเอง เติมรหัสล่วงหน้าจากหน้ายืนยันการจอง (ไม่ใส่เบอร์ใน URL)
5. **จำนวนคนเกิน `Service.maxParty`** (เช่น S07 3 คน): แสดง `error-not-enough-therapists` จากแคตตาล็อกทันทีในหน้าจอ 1 และปิดปุ่มถัดไป โดยไม่ต้องรอ API
6. **แลกแต้มเป็นปุ่มเพิ่มลดชุด** ส่ง `pointsToRedeem = ชุด × 100` จึงไม่มีทางส่ง 99 หรือ 150 จากหน้านี้ (`points-not-enough`, `points-not-multiple` ทดสอบที่ API) · `points-exceed-service` แสดงในแผงแต้มเมื่อเปลี่ยนส่วนลดแล้วยอดลดลง
7. **สิทธิ์เดือนเกิดที่ไม่เข้าเงื่อนไข** ยังติ๊กได้ ไม่ปิดช่อง ราคาใช้ % ถัดไปตามสัญญา 2.3 และแสดงเหตุผลใน `booking-birthday-reason`
8. **`ShuttlePicker` แสดง `error` เอง** ตามที่ prop ระบุ · F4 จึงไม่แสดง error รถซ้ำ · ถ้า `required` ไม่ได้ส่ง ถือว่า picker มีช่องติ๊กของตัวเอง และ `value=null` คือไม่ใช้รถ
9. **P01 ก่อนเลือกโรงแรม** ยิง quote ได้ `distance-required` ตามสัญญา จึงเห็น error นี้ใต้ picker ตั้งแต่เข้าหน้าจอ 3 และปุ่มยืนยันปิดจนกว่าจะเลือก
10. **quote error ใด ๆ ปิดปุ่มยืนยัน** แสดงราคาล่าสุดแบบจางพร้อม `booking-quote-stale` · บรรทัดที่เป็น 0 ก็แสดงเป็น ฿0 ทุกบรรทัด (FR-28)
11. **เบอร์โทรลิงก์** `tel:021234567` ไม่มีขีด

## data-testid ที่สัญญาไม่ได้กำหนดชื่อ
- จำนวนคน `booking-party-1` … `booking-party-7` (7 = "7+")
- ปุ่มเดินหน้าถอยหลัง `booking-step1-next` `booking-step2-back` `booking-step2-next` `booking-step3-back` · ยืนยัน `booking-confirm` · หลัง slot-taken ปุ่มย้อนเปลี่ยนเป็น `booking-back-to-slots`
- ตัวบอกหน้าจอ `booking-flow` (`data-screen`), `booking-progress` (`data-step`), `booking-screen-1|2|3`, `booking-confirmation`
- ทางลัดวัน `booking-date-chip-<YYYY-MM-DD>`
- ส่วนเสริม `booking-toggle-points|birthday|shuttle|giftcard` · `booking-extra-*` · แต้ม `booking-points-dec|inc|max|value` · เดือนเกิด `booking-use-birthday` · บัตร `booking-giftcard-code|apply|remove|info`
- หลังจอง `booking-assigned-T01` `booking-link-account` (สมาชิก) `booking-link-cancel` (แขก) `booking-done-*`
- ทุกบรรทัดราคามี `data-amount` เป็นตัวเลขเต็ม (ค่าสัมบูรณ์) ไว้เทียบยอด · ยอดซ้ำเหนือปุ่มยืนยัน `booking-confirm-amount`
- คอร์สตัวแรก `booking-use-course` ตัวถัดไป `booking-use-course-<id>`
