# CONTRACT-NOTES · A5

สมมติฐานที่สัญญาไม่ได้ระบุ

## ถึงหัวหน้า

1. **`฿` อยู่ในช่วงที่ NFR-07 ตรวจ:** `฿` คือ U+0E3F ซึ่งอยู่ใน `[฀-๿]` (U+0E00–U+0E7F) ดังนั้นทุกจุดในโหมด 中文 ที่ใช้ `formatBaht` จะนับเป็นอักขระไทยตาม regex ของ NFR-07 รวมถึง `giftcard-amount-invalid` ภาษาจีนใน `i18n/errors.ts` · ไฟล์เหล่านั้นเป็นไฟล์กลาง A5 ไม่ได้แก้ · แชตของ A5 ใช้ `1,000 泰铢` ในโหมดจีนแทน · หัวหน้าควรตัดสินว่าจะแก้ `formatBaht` ให้รับ locale หรือให้ regex ของ NFR-07 ยกเว้น `฿`

## แชต

2. **ChatState เพิ่ม 2 ช่องตอนรันจริง โดยไม่แก้ `types/`** (`ChatFlowState` ใน `lib/rules/chat.ts`)
   - `language`: คำตอบอย่าง `2` หรือ `S01` ไม่บอกภาษา และ `ChatRequest` ไม่มีช่องภาษา จึงต้องจำภาษาของบทสนทนาไว้ ไม่งั้นโหมดจีนจะเด้งเป็นภาษาของ request
   - `quotedPayAtShop`: ยอดที่ลูกค้าเห็นล่าสุด ส่งเป็น `expectedPayAtShop` ให้ `createBooking` ถ้าไม่มีก็จองได้ตามปกติแต่ไม่ได้ตรวจ `price-changed`
   - F8 ต้องส่ง `state` ที่ได้รับกลับมาทั้งก้อน ไม่เลือกเฉพาะบาง field · ตอน idle state เป็น `{step:'idle'}` พอดี
3. **ลำดับเลือกภาษา:** ตัวอักษรในข้อความ (จีน → ไทย → อังกฤษ) → `state.language` → ภาษาของ request · ขั้นกรอกชื่อไม่นับชื่อเป็นสัญญาณภาษา เช่น `Li Wei` ในโหมดจีนยังตอบจีน
4. **P01 และ K01 จองผ่านแชตไม่ได้:** P01 ต้องระบุรถ และ K01 ต้องเลือกคอร์ส ซึ่งอยู่นอกขอบเขต D-17 · แชตตอบให้ไป `/{lang}/booking?service=P01` · ถามราคาทั้งสองตัวได้ตามปกติ
5. **ลิงก์ในคำตอบเป็น path ข้อความล้วน** และคำตอบหลายบรรทัดคั่นด้วย `\n` · F8 ควรแสดงด้วย `white-space: pre-line`
6. **กฎที่แจ้งทันทีก่อนถึงขั้นคิดราคา:** วันที่ (`same-day-call`, `date-out-of-range`), รอบ (`isBookableSlot` ของ A1), จำนวนคน ≥7, เบอร์ผิด เพื่อไม่ให้ลูกค้าตอบครบแล้วค่อยรู้ว่าผิด · ตัวตัดสินจริงยังเป็น `loadAndQuote` และ `createBooking` ใช้ข้อความจากแคตตาล็อกกลาง
7. **`not-enough-therapists` ถามอะไรต่อ:** เกิน `maxParty` ถามจำนวนคนใหม่ · ไม่เกินแต่รอบนั้นคนไม่พอถามเวลาใหม่
8. **ระบบขัดข้อง (`internal`) ไม่แปลงเป็นคำตอบแชต** ตอบ 500 ตามปกติ · error อื่นที่แชตแก้ไม่ได้ แจ้งข้อความแล้วแนะนำหน้าจองและกลับเป็น idle
9. **`validation`:** `message` ไม่ใช่ string ว่าง หรือยาวเกิน 1,000 ตัวอักษร · `state` ที่ผิดรูปแบบไม่ error แต่ทิ้งค่าที่ผิดแล้วถามใหม่
10. **ชื่อภาษาไทยในโหมดจีนไม่สะท้อนกลับ:** สรุปแสดงเฉพาะเบอร์ เพื่อคง NFR-07 · ชื่อยังเก็บครบใน state และการจอง
11. **ขั้นกรอกชื่อ:** ข้อความทั้งหมดคือชื่อกับเบอร์ ยกเว้นคำถามเวลา/ราคาที่ไม่มีตัวเลข และคำว่ายกเลิก · จึงแก้บริการหรือเวลาในขั้นนี้ไม่ได้ ต้องไปแก้ที่ขั้นยืนยัน

## แคตตาล็อก

15. **ลำดับสมุนไพรใน `Service.herbs` เรียงตาม id** เพราะ `service_herbs` ไม่มีคอลัมน์ลำดับ · TEST-DATA เขียน S03 เป็น ไพล, ขมิ้น, ตะไคร้, มะกรูด จึงอาจต่างลำดับ แต่ชุดสมุนไพรครบ
16. **`/api/therapists`:** `service` ไม่มีในระบบได้รายการว่าง · `minRating` ที่อ่านไม่ได้ถือว่าไม่ส่ง เพราะสัญญาไม่มี error ของเส้นนี้
17. **`passesRatingFilter` ปัดค่าให้ก่อนเทียบ** จึงรับค่าที่ยังไม่ปัดได้ (4.45 ผ่าน, 4.44 ไม่ผ่าน) และไม่เปลี่ยนผลของค่าที่ปัดแล้ว
18. **`roundAverage` ถือเศษต่ำกว่า 10⁻¹⁰ เป็นเศษ float** เช่น 4.449999999999999 ปัดเป็น 4.5 · ค่าเฉลี่ยจริงจากดาวห่างขอบ .x5 มากกว่านี้เสมอเมื่อรีวิวไม่ถึงพันล้าน

## เครื่องมือทดสอบ

19. **`now`:** ต้องเป็นรูปแบบ ISO จริง · ไม่บอกเขตเวลาถือเป็น Asia/Bangkok · มีแต่วันถือเป็น 00:00 กรุงเทพฯ · วันที่ไม่มีจริงและ `now: null` ได้ 400 `validation`
20. **ตรวจโหมดทดสอบก่อนอ่าน body** ปิดโหมดแล้ว POST ทุกแบบได้ 404 · method อื่นได้ 405 จาก Next ตามปกติ
21. **`/api/test/lock` ไม่ส่ง body หรือไม่ส่ง `now`** ได้ 400 `validation` · `/api/test/reset` body ว่างใช้ค่าเริ่มต้น
