# CONTRACT-NOTES · F8

สมมติฐานที่สัญญาไม่ได้ระบุ · ทำต่อตามนี้

1. **`QuizRequest.answers`**: ส่งรหัสตัวเลือก (`option.id`) เรียงตามลำดับข้อที่ `GET /api/quiz` ส่งมา 1 ค่าต่อ 1 ข้อ
2. **`QuizQuestion.id` และ `option.id`**: ต้องเป็นตัวอักษรที่ใช้ใน data-testid ได้ (kebab-case หรือตัวอักษรกับตัวเลข) เพราะ testid คือ `quiz-option-<questionId>-<optionId>`
3. **`Service.imagePath`** จาก API: เป็น URL พร้อมใช้ขึ้นต้นด้วย `/` เช่น `/brand/services/svc-s04-aroma.jpg` จึงส่งเข้า `next/image` ตรง ๆ
4. **`MoodResponse.imagePath`**: ไม่ได้ใช้ · ผลลัพธ์แสดงรูปบริการจาก `service.imagePath`
5. **คำถามตัวอย่างของแชต**: ปุ่มส่งข้อความตามภาษาของหน้า และ A5 ต้องจับ intent ได้
   - เวลาเปิด: `ร้านเปิดกี่โมง` · `What are your opening hours?` · `营业时间是几点？`
   - ราคา: `ราคาเท่าไหร่` · `What is the price?` · `价格是多少？`
   - จอง: `ขอจองคิว` · `I want to book` · `我想预约`
6. **ลำดับข้อความแชต**: ข้อความต้อนรับเป็นป้ายคงที่ ไม่นับเป็นข้อความ · `chat-message-0` คือข้อความแรกของผู้ใช้ และ `chat-message-1` คือคำตอบแรก
7. **testid ของสรุปในแชต**: หนึ่งบทสนทนามีได้หลายสรุป จึงต่อท้ายด้วยเลขข้อความ: `chat-quote-<i>` `chat-quote-total-<i>` `chat-booking-<i>` `chat-booking-code-<i>`
8. **error**: `<ErrorMessage>` ให้ `error-<code>` ตามสัญญาข้อ 1 จึงครอบด้วย `chat-error` `mood-error` `quiz-error` `quiz-load-error` `skin-error` อีกชั้น · เชื่อมต่อไม่ได้ใช้ code `network` · วิเคราะห์ผิวไม่เรียก API จึงใช้ code ฝั่งหน้าเว็บ `skin-file-type` และ `skin-image-unreadable` · แชตเปิดอยู่ทุกหน้า ถ้า error code เดียวกันเกิดพร้อมกับหน้าอื่นจะมี `error-<code>` ซ้ำ ให้เลือกผ่าน `chat-error` ได้
9. **ตารางวิเคราะห์ผิว (A-26)**: ความสว่าง `0–84 → S07` · `85–149 → S06` · `150–255 → S04` · ภาพตัวอย่าง `skin-sample.jpg` ได้ราว 173 จึงได้ S04 และอยู่ห่างขอบช่วงพอที่ผลไม่เปลี่ยนตามวิธีย่อภาพของเบราว์เซอร์
10. **สูตรความสว่าง**: `floor(ผลรวม(299R + 587G + 114B) / (1000 × จำนวนพิกเซล))` ไม่นับพิกเซลที่ alpha = 0
11. **ภาพตัวอย่างใช้ `new Image()`** อ่านไฟล์ JPEG ต้นฉบับ มี GET `/brand/misc/skin-sample.jpg` 1 ครั้งซึ่งเป็นรูปของร้าน ไม่มีข้อมูลจากผู้ใช้ · รูปของผู้ใช้ไม่เกิด request เลย
12. **`MoodPicker variant="section"`** เป็น `<section>` เต็มกว้าง พื้นเขียวเข้ม มี `.container` และหัวข้อในตัว (testid `mood-section`, `mood-heading`) · F1 วางตรง ๆ ระหว่าง section ได้โดยไม่ต้องครอบด้วย `Section`
13. **`variant="page"`** ไม่มีหัวข้อในตัว เพราะหน้า `/mood` มีหัวข้อของหน้าแล้ว · ค่าเริ่มต้นของ prop `variant` คือ `page`
14. **รอยต่อภาพทัวร์**: `pano-couple.jpg` ขอบซ้ายและขวาไม่ใช่ภาพเดียวกัน (เป็นภาพกว้าง ไม่ใช่ equirectangular) จึงใส่เงาเข้มที่ขอบทั้งสองด้านเหมือนเงามุมห้อง เพื่อกลืนรอยต่อ
15. **ทัวร์**: ลาก 1 ความกว้างภาพ = 360° · ปุ่มหมุนครั้งละ 30° · คีย์บอร์ดครั้งละ 15° · ลากซ้ายหรือกดขวา มุมเพิ่ม
16. **ราคาในโหมด 中文**: `฿` คือ U+0E3F อยู่ในช่วง `[฀-๿]` ที่ NFR-07 ตรวจ F8 จึงใช้ `components/widgets/price.ts` แสดง `1,000 泰铢` เหมือน A5 และ F1 · ภาษาไทยและอังกฤษยังใช้ `formatBaht` · หัวหน้าควรแก้ `lib/format.ts` ให้ทั้งเว็บเหมือนกัน
17. **`Header.tsx` ของหัวหน้า** ใส่ `aria-label="ไทย"` และ `lang="th"` ที่ปุ่มเลือกภาษาในทุกโหมด ไม่กระทบ `innerText` ตาม NFR-07 แต่เป็นตัวอักษรไทยใน attribute ของโหมด 中文 · ตั้งใจให้เป็นชื่อภาษาของตัวเองหรือไม่ ให้หัวหน้าตัดสิน
