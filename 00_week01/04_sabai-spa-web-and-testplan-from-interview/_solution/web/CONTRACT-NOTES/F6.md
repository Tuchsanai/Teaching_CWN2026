# CONTRACT-NOTES · F6 (Wallet + หลังร้าน)

## สมมติฐานที่ใช้

1. **ชื่อลูกค้าใน 中文** `AdminBooking.customerName` เป็น `string` ไม่มีคำแปล แต่ NFR-07 ห้ามอักษรไทยในโหมด 中文
   → โหมด `zh` ถ้าชื่อมีอักษรไทย หลังร้านแสดงป้าย "会员" หรือ "访客" แทนชื่อ (ยังดูรหัสนัดและเบอร์ได้) · ถ้าอยากให้เห็นชื่อจริง API ต้องส่งชื่อแบบไม่มีอักษรไทยมาให้
2. **ราคาคอร์สบนปุ่มซื้อ** `WalletResponse` ไม่มีราคาคอร์สที่ยังไม่ซื้อ → อ่านจาก `GET /api/services` รายการ K01 (`Service.price` = ราคาต่อคอร์ส) · โหลดไม่ได้จะปิดปุ่มซื้อและแสดง error
3. **ยืนยันก่อนซื้อ** กด `wallet-buy-course` เปิดกล่องยืนยันในหน้า ยังไม่ POST · POST เกิดเมื่อกด `wallet-buy-course-confirm` · ยกเลิกด้วย `wallet-buy-course-cancel` · ไม่ใช้ `window.confirm`
4. **`next` ของหน้า login** ส่งแบบไม่ encode ตามตัวอย่างในสัญญา ข้อ 5: `/th/login?next=/th/wallet` และ `/th/login?next=/th/admin`
5. **เหลือ 0 ครั้ง** ตัดสินจาก `remaining <= 0` ไม่ใช้ `usedUp` เพราะข้อกำหนดพูดถึงจำนวนที่เหลือ (รวมกรณีที่เหลือเป็น 0 เพราะกันไว้) · หมดอายุใช้ `expired` จาก API
6. **`Gift Card.imagePath`** ถือว่าเป็น URL พร้อมใช้ เช่น `/brand/giftcard/gc-gold.jpg`
7. **`Wallet` ของบัญชี OWNER** API ตอบ 200 พร้อมรายการว่าง หน้าแสดงสถานะว่าง · กดซื้อคอร์สได้ 403 `forbidden` (โค้ด A4 ปัจจุบัน แต่สัญญาระบุแค่ 401) แสดงด้วย `<ErrorMessage>`
8. **`POST /api/admin/bookings/{id}/complete`** ส่งแบบไม่มี body · `CompleteBookingResponse.booking` ไม่มี `customerName` จึงรวมทับแถวเดิมเฉพาะ field ของ `BookingDetail`
9. **FR-45 ประวัติทรีตเมนต์** หน้าอยู่ที่ `/account/history` ของ F5 · Wallet มีเพียงลิงก์ `wallet-history-link`
