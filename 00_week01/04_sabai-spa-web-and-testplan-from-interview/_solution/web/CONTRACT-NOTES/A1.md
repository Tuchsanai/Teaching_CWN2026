# CONTRACT-NOTES · A1

สมมติฐานที่ใช้เมื่อสัญญาไม่ได้ระบุ

1. `GET /api/availability` จำนวนคนเกิน `maxParty` ไม่ตอบ error (สัญญาไม่ได้ระบุ `not-enough-therapists` ที่เส้นนี้) ตอบ 200 `slots: []` · `POST /api/bookings` ขั้น 5 ยังตอบ 409 ตามเดิม
2. `GET /api/availability` ไม่ส่ง `party` ถือเป็น 1 · ส่งแล้วไม่ใช่จำนวนเต็มบวก หรือ <1 → 400 `validation` · `date` ขาดหรือผิดรูปแบบ → 400 `validation`
3. `GET /api/availability` ลำดับตรวจเหมือน POST ขั้น 1–3 แล้วค่อยตรวจคอร์ส: `service=K01` ไม่ส่ง `course` → `course-required` · แขกหรือ OWNER ส่ง `course` → `course-login-required` · ใช้ used-up ก่อน expired
4. `GET /api/availability` `therapist` ที่ทำบริการไม่ได้หรือไม่มีจริงไม่ตอบ error (สัญญาไม่ได้ระบุ) ตอบ `slots: []` · `therapist` มีผลเฉพาะ 1 คน · `ANY` เท่ากับไม่ส่ง · `autoAssignIds` คงเป็นคนที่ระบบจะจัดให้เสมอแม้เลือกคนเองอยู่
5. ส่ง `coursePurchaseId` กับบริการที่ไม่ใช่ K01 หรือเป็นรหัสที่ไม่ใช่ uuid → `course-not-found` (POST ตรวจก่อนเรียก `loadAndQuote` กันราคา ฿0 กับบริการอื่น) · A2 ควรทำแบบเดียวกันใน `/api/quote`
6. "ลองใหม่ไม่เกิน 3 ครั้ง" (D-29) นับเฉพาะครั้งที่ลองใหม่ จึงรวมครั้งแรกเป็นไม่เกิน 4 transaction
7. `40P01` (deadlock) จาก `INSERT` ของ `booking_items` นับเป็นการชนเหมือน `23P01` เพราะ EXCLUDE ที่แทรกพร้อมกันอาจรอกันเองได้ · อีกฝั่งยังสำเร็จ ฝั่งที่แพ้จึงตอบ `slot-taken` หรือลองใหม่ตาม D-29
8. `gift_cards` ที่ `lines.giftCardAmount = 0` (ยอดเป็น ฿0 จึงไม่ถูกหัก) ไม่ผูกกับการจอง: `gift_card_id` เป็น NULL และไม่มีรายการ REDEEM เพราะ `gift_card_transactions.amount` ต้อง > 0
9. `cancel-guest` รหัสการจอง trim และแปลงเป็นตัวพิมพ์ใหญ่ก่อนเทียบ · เบอร์ trim แล้วเทียบตรงตัว · ขาดฟิลด์ตอบ `booking-not-found` (ไม่บอกว่าขาดอะไร)
10. `POST /api/bookings/{id}/cancel` OWNER ยกเลิกของคนอื่นไม่ได้ (สัญญาระบุ "เจ้าของ") ตอบ `booking-not-found`
11. ค่า `therapist_id` ที่ไม่มีจริงในคำขอของ POST ตอบ `therapist-cannot-perform`
