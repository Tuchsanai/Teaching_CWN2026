# F2 · สมมติฐานที่สัญญาไม่ได้ระบุ

1. **รูปแบบ `Service.imagePath` / `Herb.imagePath` / `Therapist.photoPath`**: สัญญาระบุเฉพาะรูปตัวของ Wallet (ตัด `public` ออก) ส่วน TEST-DATA เขียนเป็น `brand-kit/...` · ฝั่ง F2 ใช้ `imageSrc()` ใน `components/services/helpers.ts` รับได้ทั้ง `/brand/x.jpg`, `brand/x.jpg`, `public/brand/x.jpg`, `brand-kit/x.jpg` และแปลงเป็น `/brand/x.jpg` · คาดว่า A5 ส่ง `/brand/...`
2. **คำอธิบายบริการ**: type `Service` ไม่มีช่องคำอธิบาย จึงเก็บใน `i18n/f2.ts` (key `descS01`…`descK01`) · ชื่อบริการ สมุนไพร นักบำบัด ยังมาจาก DB
3. **การจัดกลุ่มหน้า `/services`**: แสดง `kind = SERVICE` ก่อน แล้วตามด้วย PACKAGE, COURSE โดยคงลำดับจาก `listServices()` · สมมติว่า sort_order เป็น S01…S07, P01, K01 ลำดับบนหน้าจึงตรงกับ sort_order
4. **K01 บนหน้า `/services` และ `/services/K01`**: มี 2 ปุ่ม คือ `service-buy-K01` (ซื้อคอร์ส ไป `/{locale}/wallet`) และ `service-book-K01` (จองด้วยคอร์สที่มี ไป `/{locale}/booking?service=K01`) · หน้าจองของ F4 ต้องจัดการกรณีไม่มีคอร์สเอง (`course-required`)
5. **P01 ใน `/services`**: ลิงก์ `service-detail-P01` ไป `/services/P01` เหมือนรายการอื่น และเพิ่ม `service-package-P01` ไปหน้า `/packages/bangkok-relax`
6. **ลิงก์จองรายนักบำบัด**: `/services/[id]` มีลิงก์ `service-therapist-book-T0X` ไป `/{locale}/booking?service=<id>&therapist=T0X` ตาม deep link ข้อ 5 · ซ่อนสำหรับ K01 เพราะต้องมีคอร์สก่อน
7. **ระยะ 15.0 กม. และข้อความเงื่อนไข P01**: ค่า 15.0 อยู่ในข้อความ `i18n/f2.ts` เพราะ `Service` ไม่มีช่องนี้ · จำนวนคนสูงสุดใช้ `Service.maxParty` จาก DB
