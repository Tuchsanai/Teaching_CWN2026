# A4 · สมมติฐานที่สัญญาไม่ได้ระบุ

1. **OWNER ซื้อคอร์ส** → 403 `forbidden` เพราะ D-08 ให้เฉพาะสมาชิก และ OWNER ไม่มีระดับสมาชิก (สัญญาระบุแค่ 401 สำหรับไม่เข้าสู่ระบบ)
2. **session ค้างหลังรีเซ็ตข้อมูล** (ไม่มีแถวใน users): ซื้อคอร์ส → 401 `unauthorized` · ซื้อ Gift Card → นับเป็นแขก (buyer NULL) กัน foreign key ชน
3. **มูลค่า Gift Card แบบ string** ต้องเป็นตัวเลขล้วนหลัง trim: `'2150'` ✓ · `'2150.00'` `'2,150'` `'1e3'` `'0500'` ✗ → `giftcard-amount-invalid` · แบบ number ใช้ `Number.isInteger`
4. **body ของ `POST /api/gift-cards`** ไม่ใช่ object (เช่น `null`, array) หรือ `recipient`/`message` ไม่ใช่ string หรือยาวเกิน 200/500 ตัว → 400 `validation` · ลำดับตรวจ มูลค่า → ลาย → ช่องทาง → ข้อความเสริม
5. **`simulatedMessage`** ไม่ใส่ `recipient` และ `message` เพราะเป็นข้อความอิสระ อาจเป็นคนละภาษากับ request (NFR-07)
6. **รหัส Gift Card ที่ออกใหม่** รูปแบบ `GIFT-` + 10 ตัว (A–Z, 2–9 ไม่มี 0 O 1 I) · `GET /api/gift-cards/{code}` เทียบตรงตัว (case-sensitive) รหัสที่มีอักขระนอก `[A-Za-z0-9_-]` หรือยาวเกิน 64 ตอบ `giftcard-not-found` · ตรงกับ `loadAndQuote` ของ A2 ที่ใช้ `code = $1`
7. **OWNER ซื้อ Gift Card ขณะเข้าสู่ระบบ** → buyer คือบัญชี OWNER ไม่นับเป็นแขก (ข้อ "นับเป็นแขก" ในสัญญาพูดถึงการจองเท่านั้น)
8. **`?date=` ของ `/api/admin/schedule`** ค่าว่างถือว่าไม่ส่ง · รูปแบบผิดหรือวันไม่มีจริง → 400 `validation`
9. **`POST /api/admin/bookings/{id}/complete`** id ไม่ใช่ UUID → 404 `booking-not-found` (ไม่ส่งถึง PostgreSQL ซึ่งจะได้ 22P02)
10. **ลำดับล็อกตอนกดเสร็จ** อ่าน user_id และ course_purchase_id แบบไม่ล็อก แล้วล็อก `users → course_purchases` จากนั้นจึง `UPDATE bookings ... WHERE status='CONFIRMED'` ให้ตรงกับ `lib/booking/cancel.ts` ของ A1 ที่ล็อก bookings ท้ายสุด · DESIGN 3.4 เขียน UPDATE เป็นขั้นแรก แต่ถ้าทำตามตัวอักษรจะ deadlock กับการยกเลิกนัดเดียวกัน ผลทางธุรกิจไม่ต่างกัน เพราะ UPDATE นี้ยังเป็นด่านตัดสิน
11. **`member` ใน `CompleteBookingResponse` เมื่อจองด้วยคอร์ส** คืนยอดและแต้มปัจจุบันของผู้จอง (ไม่เปลี่ยน) ไม่ใช่ null เพราะ type ระบุว่า null เฉพาะแขก
12. **ลำดับรอง** เมื่อคีย์หลักเท่ากัน: คอร์สใช้ id · บัตรใน Wallet เรียงวันซื้อล่าสุดก่อนแล้วตามรหัส · รูปเรียง taken_on แล้ว BEFORE ก่อน AFTER · ตารางคิวเวลาเท่ากันตาม booking_code
13. **`/api/admin/schedule` อ่าน therapists ด้วย SQL ตรง** ไม่ผ่าน `listTherapists` ของ A5 เพราะใช้แค่ id ชื่อ รูป ไม่ต้องคำนวณรีวิว
