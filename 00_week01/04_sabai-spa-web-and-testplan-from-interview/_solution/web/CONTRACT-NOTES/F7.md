# CONTRACT-NOTES · F7 (Gift Card · รถรับส่ง)

สมมติฐานที่ใช้ เพราะสัญญาไม่ได้ระบุไว้

## ShuttlePicker (F4 อ่าน)

1. ติ๊กใช้รถแล้วยังไม่เลือกอะไร `onChange({})` ส่ง `{}` ไม่ใช่ `null` · F4 ส่ง `shuttle: {}` ต่อให้ API ได้เลย จะได้ `distance-required` ตามสัญญา §2.3 (FR-53)
2. `required=true` และ `value=null`: ไม่ยิง `onChange` เองตอน mount · P01 ที่ไม่ส่ง `shuttle` ได้ `distance-required` เหมือนกัน
3. ลบข้อความระยะจนว่าง ส่ง `{}` ไม่ใช่ `{distanceKm:''}` · ค่าอื่นส่งตรงตามที่พิมพ์ ไม่ trim
4. ช่องเลือกโรงแรมและช่องพิมพ์ระยะแสดงคู่กันเสมอ โดยมี radio `{prefix}-mode-hotel` `{prefix}-mode-distance` บอกวิธีที่ใช้อยู่ · เลือกหรือพิมพ์ที่ช่องไหนก็สลับไปวิธีนั้นเอง จึงไม่มีทางส่ง `hotelId` กับ `distanceKm` พร้อมกัน
5. H06 (15.1 กม.) เลือกได้ เพื่อให้ API ตอบ `distance-too-far` ก่อนยืนยันการจอง (FR-54, E171)
6. Picker แสดง `error` เองด้วย `<ErrorMessage>` · F4 ส่งเฉพาะ `distance-*` และ `hotel-not-found` เข้ามา และอย่าแสดงซ้ำ ไม่งั้น `error-<code>` ซ้ำในหน้า
7. props ไม่มีตัวบอกบริการ จึงแสดงกฎครบทุกข้อเสมอ พร้อมบรรทัด "Bangkok Relax รวมค่ารถเมื่อไม่เกิน 15.0 กม." (BR-37)

testid เพิ่มนอกเหนือจากที่กำหนด: `{prefix}-picker` `{prefix}-mode-hotel` `{prefix}-mode-distance` `{prefix}-hint` `{prefix}-rules`

## หน้า /shuttle

8. โรงแรมอ่านจาก `GET /api/hotels` ฝั่งเบราว์เซอร์ตามที่สั่ง ไม่เรียก `listHotels` ตรง ๆ · รายชื่อโรงแรมจึงไม่อยู่ใน HTML ที่ SSR
9. ตารางโรงแรมแสดงแถบค่ารถ ฟรี / ฿300 ต่อคัน / ไม่รับ โดยเทียบ `distanceKm` กับเกณฑ์ BR-34, BR-35 ในหน้าเว็บ เพื่อแสดงกฎเท่านั้น · ผลของเครื่องคำนวณมาจาก `POST /api/quote` อย่างเดียว · ไม่ import `lib/pricing/rules.ts` เพราะผูกกับ `lib/errors` ฝั่งเซิร์ฟเวอร์
10. เครื่องคำนวณใช้ `required` (ไม่มีช่องติ๊ก) เพราะทั้งหน้าเป็นเรื่องรถอยู่แล้ว · ยังไม่เลือกอะไรส่ง `shuttle: {}` จะได้ `distance-required`
11. อ่าน `GET /api/clock` ทุกครั้งที่กดคำนวณ จึงตรงกับวันที่ล็อกไว้จากแผงทดสอบโดยไม่ต้องโหลดหน้าใหม่
12. แก้ค่าในฟอร์มเมื่อไร ผลเดิมถูกล้างและคำขอที่ค้างถูกยกเลิก

## หน้า /gift-cards

13. ค่าเริ่มต้น ลาย ORCHID ช่องทาง LINE · จึงไม่เจอ `giftcard-design-invalid` และ `giftcard-channel-invalid` จากหน้าเว็บ
14. ซื้อสำเร็จแล้วฟอร์มยังอยู่ แต่ล้างมูลค่า ผู้รับ ข้อความ กันกดซื้อซ้ำโดยไม่ตั้งใจ · ผลแสดงใต้ฟอร์ม และถูกล้างเมื่อกดซื้อครั้งถัดไป
15. รหัสบัตรว่าง ไม่เรียก API (`/api/gift-cards/` ไม่มี route) แสดง `error-giftcard-code-required` ซึ่งเป็น code ฝั่งหน้าเว็บเท่านั้น ไม่อยู่ในแคตตาล็อก
16. รหัสบัตร trim ก่อนส่ง ไม่แปลงตัวพิมพ์ · สถานะบัตร: `expired` ก่อน → `balance <= 0` → ใช้งานได้ (`data-status` = `expired` `empty` `active`)
17. วันหมดอายุแสดงตามภาษา ค่าดิบอยู่ใน `data-date`
18. `error-internal` อาจซ้ำได้เฉพาะตอน API ล่มแล้วกดทั้งฟอร์มซื้อและฟอร์มตรวจยอด เพราะ 2 ฟอร์มแยกกัน

19. NFR-07 ใช้ regex `[฀-๿]` (U+0E00–U+0E7F) ซึ่งรวม `฿` (U+0E3F) ด้วย · `formatBaht` และแคตตาล็อก error ของไฟล์กลางแสดง `฿` ทุกภาษา ข้อความจีนของ F7 จึงคง `฿` ตามนั้น โดยตีความว่า `฿` เป็นสัญลักษณ์เงิน ไม่ใช่ตัวอักษรไทย (เหมือน `lib/wallet/helpers.test.ts`) · ถ้าตรวจด้วย regex นี้ตรง ๆ จะเจอ `฿` ในโหมด 中文 ทั้งเว็บ หัวหน้าต้องตัดสินว่าจะยกเว้น `฿` หรือแก้ที่ `formatBaht`
