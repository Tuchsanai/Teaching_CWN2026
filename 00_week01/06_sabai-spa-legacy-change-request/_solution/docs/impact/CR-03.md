### ต้นเหตุ (API → service → DB)
1. `web/app/api/bookings/route.ts:12` ส่งต่อ `createBooking` ทันที · ไม่มีการตรวจตัวคน
2. `web/lib/server/booking.ts:343-378` ตรวจแค่ราคา (`:354`) นักบำบัดว่าง (`:359-372`) และห้องคู่ (`:374-378`) — **ไม่มีที่ไหนดูว่า customer_id / เบอร์นี้มีนัดทับอยู่แล้ว** · ระบบจัดนักบำบัดว่างคนถัดไปให้ (`:371`) จึงได้นัดที่ 2
3. DB: EXCLUDE มีแค่ `booking_slot_no_overlap` (therapist_id, period) `db/init/01-schema.sql:152` และ `booking_room_no_overlap` (room_id) `:137` · ไม่มี constraint ระดับ "คน" · เบอร์เก็บตามที่พิมพ์ (`guest_phone` VARCHAR) จึงเทียบ `081-000-0003` กับ `0810000003` ไม่ได้แม้จะมี constraint
4. ทำไมหน้าเว็บกดสองครั้งไม่ซ้ำ: ปุ่ม `book-confirm` `disabled={busy}` `BookingWizard.tsx:616` + `setBusy(true)` `:211` และจองสำเร็จแล้วเปลี่ยนเป็นหน้าเสร็จ `:220-222` — กันได้เฉพาะ**แท็บเดียวกันขณะรอคำตอบ** · เน็ตค้างแล้วรีโหลด/เปิดใหม่ หรือยิง API ตรง หรือแชท `chat.ts:238` ไม่มีปุ่มนี้ → ซ้ำได้
5. ทำไมชุดตรวจที่ส่งมอบไม่จับ: เทสต์พร้อมกันมีแค่ "คนละคน แย่งนักบำบัดคนเดียว" (`therapists: ["T04"]`) — `web/scripts/check-rules.mjs:196-204` (E14 U03+U04) และ `e2e-legacy/tests/book.api.spec.ts:7-11` → พิสูจน์ EXCLUDE ของนักบำบัด ไม่ใช่ตัวคน · ไม่มีเคส "คนเดียวกัน 2 คำขอ" หรือ "จองซ้ำหลังมีนัดแล้ว" เลย · SPEC เดิมไม่มีกฎนี้ (ไม่มี BR คนเดียวกัน)

### ออกแบบการแก้ (เล็กที่สุด · ไม่มี migration)
- ใน `withTx` ของ `createBooking` หลังตรวจ `CONTACT_REQUIRED` ก่อนตรวจราคา: หา "ตัวคน" → สมาชิก `m:<customer_id>` · ไม่ล็อกอิน `g:<เบอร์ตัวเลขล้วน>` (`replace(/\D/g, "")`)
- `SELECT pg_advisory_xact_lock(hashtext('cr03-person:' || key))` — **ล็อกเดียวต่อคำขอ และขอเป็นอย่างแรกก่อน insert ใด ๆ** (ลำดับคงที่: ล็อกคน → ตรวจ → insert booking → insert booking_slot) จึงไม่มีวงล็อกค้าง · คำขอที่ 2 รอจนตัวแรก commit แล้วเห็นนัดใหม่ (READ COMMITTED)
- ตรวจ: สมาชิก `customer_id = $1` · ไม่ล็อกอิน `customer_id IS NULL AND regexp_replace(coalesce(guest_phone, contact_phone), '\D', '', 'g') = $1` · `status <> 'cancelled' AND period && tstzrange(start, end, '[)')` · `ORDER BY start_at, id LIMIT 1` → 409 `DUPLICATE_BOOKING` `{ existing: code }`
- ทำไมไม่ใช้ EXCLUDE: เบอร์เก่าในฐานมีหลายรูปแบบ และ "สมาชิกกับแขกไม่เทียบกัน" ต้องมีคอลัมน์ใหม่ + migration + ฐานจริงมีนัดซ้ำอยู่แล้ว (Q9) → สร้าง constraint ไม่ผ่าน · และ `23P01` ทุกตัวกลายเป็น `SLOT_TAKEN` (T11 `http.ts:42`)
- ไม่ normalize ค่าที่บันทึก (เก็บเบอร์ตามที่กรอกเหมือนเดิม · เทียบแบบตัวเลขล้วนตอนตรวจ) → หน้าหลังร้าน/golden ไม่เปลี่ยน

ตรวจกับดัก: T1 room_id ไม่เกี่ยว · T2 ไม่มีตารางใหม่ · T3/T4 ไม่แก้ seed/init · T5/T6 ไม่เกี่ยว · **T7/T8 ข้อความใหม่ใน i18n + แชท** (เกี่ยว) · **T9 ใช้ช่วงเวลาจาก quote (ไม่มี `new Date()`)** · T10 ไม่เกี่ยว · **T11 ไม่ใช้ EXCLUDE ใหม่ จึงไม่ชน 23P01→SLOT_TAKEN** · T13 grep ทั้งสองแบบแล้ว
