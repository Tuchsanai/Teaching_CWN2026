# BUGS · เฉลยบั๊กที่ตั้งใจใส่ (เปิดเมื่อ `BUG_MODE=1`)

> ไฟล์นี้สำหรับผู้สอน/ผู้ตรวจเท่านั้น · `BUG_MODE=0` (ค่าเริ่มต้น) ไม่มีบั๊กเหล่านี้ — `node scripts/check-rules.mjs` ผ่าน 90/90
> ทุกตัวอ่านค่าผ่าน `lib/flags.ts` จุดเดียว · หน้าจอและฐานข้อมูลผิด "ตรงกัน" (ยอดหน้าสรุป = ยอดใน db, รอบที่ไม่แสดง = API ก็ปฏิเสธ, แต้มบนหน้าบัญชี = แต้มใน db)
> → ถ้าลอกค่าจากหน้าจอไปเป็นผลที่คาดหวังจะจับไม่ได้ ต้องคิดจาก BR / TEST-DATA เอง

วิธีเปิด (PowerShell):

```powershell
$env:BUG_MODE = "1"; docker compose -f web/compose.yaml up -d --force-recreate
# ปิด
$env:BUG_MODE = "0"; docker compose -f web/compose.yaml up -d --force-recreate
```

ผล `check-rules.mjs` ที่ `BUG_MODE=1`: **ผ่าน 80 / 90** — ล้ม E05, E07, E09, E20, E39, E40, E50, E87, E88, E89

## บั๊ก 1 · เรื่องเงิน — ลำดับคิดราคาผิด (BR-20)

| หัวข้อ | รายละเอียด |
|---|---|
| BR ที่ผิด | **BR-20** ลำดับ ① ราคาเต็ม → ② ส่วนลด % → ③ หักแลกแต้ม → ④ ค่ารถ · บั๊กสลับเป็น **หักแต้มก่อน แล้วค่อยคิด %** จากยอดที่หักแต้มแล้ว |
| อาการ | ยอดสูงกว่าที่ถูกเล็กน้อยเฉพาะเคสที่มีทั้งส่วนลด % และแลกแต้ม (ส่วนลด % คิดจากฐานที่เล็กลง) · ไม่มีแต้มหรือไม่มี % = ถูกต้องปกติ จึงดูเหมือนทำงานดี |
| เคสที่จับได้ | **E87** ได้ ฿3,810 (ควร ฿3,800: ฿4,000 −10% = ฿3,600 −฿100 +฿300) · **E88** ยอด ฿3,810 จ่ายเพิ่ม ฿1,810 (ควร ฿1,800) · **E89** ได้ ฿675 (ควร ฿670: ฿800 −10% = ฿720 −฿50) |
| ทำไมลอกหน้าจอไม่เจอ | `/api/price` (หน้าสรุป) กับ `POST /api/bookings` ใช้ `calcPrice()` ตัวเดียวกัน → `quotedTotal` ตรงกับยอดที่คิดใหม่ ไม่เกิด 409 · `total_amount` ใน db = ยอดหน้าสรุป (E90 ผ่าน) |
| ไฟล์ / ฟังก์ชัน | `lib/rules/pricing.ts` → `calcPrice()` วนตาม `flags.priceSteps` · `lib/flags.ts` → `priceSteps` (`BUG_MODE=1` = `["points", "percent"]`) |

## บั๊ก 2 · เรื่องการจอง — รอบสุดท้ายที่จบ 22:00 พอดีหายไป (BR-01)

| หัวข้อ | รายละเอียด |
|---|---|
| BR ที่ผิด | **BR-01** บริการต้อง "จบไม่เกิน 22:00 (จบ 22:00 พอดีได้)" · บั๊กเผื่อเวลาเก็บห้อง 1 นาที ทำให้เงื่อนไขกลายเป็น "จบก่อน 22:00" |
| อาการ | รอบที่จบ 22:00 พอดีไม่ถูกสร้าง: S02/S04 (90 นาที) ไม่มี 20:30 · S01/S03/S05–S07/K01 (60 นาที) ไม่มี 21:00 · P01 (120 นาที) ไม่มี 20:00 · ยิง API จองรอบนั้นได้ 422 "ไม่มีรอบเวลานี้" |
| เคสที่จับได้ | **E05** (S02 20:30) · **E07** (S01 21:00) · **E09** (P01 20:00) · **E20** (คู่ที่ 2 รอบ 20:30 วันที่ 17 ต.ค.) |
| ทำไมลอกหน้าจอไม่เจอ | หน้าจอแค่ "ไม่แสดง" รอบนั้น (ไม่มี error) และ API ก็ปฏิเสธด้วยกฎเดียวกัน · รอบอื่นทุกรอบปกติ ต้องรู้ว่า 22:00 พอดีต้องจองได้ |
| ไฟล์ / ฟังก์ชัน | `lib/rules/slots.ts` → `fitsDay()` ใช้ `CLOSE_MIN - flags.closingBufferMin` · `lib/flags.ts` → `closingBufferMin` (`BUG_MODE=1` = 1 นาที) |

## บั๊ก 3 · เรื่องตัวเลขที่อัปเดตหลังทำรายการ — แต้มหลังใช้บริการคิดจากราคาก่อนส่วนลด % (BR-09)

| หัวข้อ | รายละเอียด |
|---|---|
| BR ที่ผิด | **BR-09** + สมมติฐาน A8/T16: แต้ม = floor(ยอดจ่ายจริง**หลังหักส่วนลดทุกชนิด** ไม่รวมค่ารถ − ส่วนที่จ่ายด้วย Gift Card ÷ 100) · บั๊กใช้ฐาน = ราคาเต็ม − ส่วนลดแต้ม − Gift Card (**ไม่หักส่วนลด %**) |
| อาการ | หลังร้านกด "ใช้บริการเสร็จ" แต้มที่บวกเข้าบัญชีมากเกินเมื่อนัดนั้นได้ส่วนลดกลุ่ม/ระดับ/เดือนเกิด · นัดที่ไม่มีส่วนลด % ได้แต้มถูกต้อง |
| เคสที่จับได้ | **E39/E40** B05 (฿800 −5% = ฿760) ได้ 8 แต้ม รวม 107 (ควร 7 แต้ม รวม 106) · **E50** Gold ฿1,250 ได้ 12 แต้ม (ควร 11 จาก ฿1,187.50) · **E88** แต้มที่จะได้/ได้จริง 19 (ควร 15) |
| ทำไมลอกหน้าจอไม่เจอ | "แต้มที่จะได้" บนหน้าสรุป, `points_earned` / `point_txn` ใน db และแต้มคงเหลือในหน้าบัญชีใช้ `earnBase()` ตัวเดียวกัน จึงตรงกันหมด |
| ไฟล์ / ฟังก์ชัน | `lib/rules/points.ts` → `earnBase()` เลือกฐานตาม `flags.loyaltyBasis` (`BUG_MODE=1` = `"list"`) · ถูกเรียกจาก `calcPrice()` (หน้าสรุป) และ `completeBooking()` ใน `lib/server/booking.ts` (ตอนร้านกดเสร็จ) |
