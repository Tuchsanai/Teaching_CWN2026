# จุดตัดสินใจ + กับดัก (จากการรันจริงรอบแรก PawPantry 2 พ.ย. 2569: 40 ข้อ ผ่าน 39 ใช้ ~12 นาที)

บทเรียนไม่ได้บอกเรื่องเหล่านี้ ให้ทำตามนี้เป็นค่าเริ่มต้น และ **บอกผู้ใช้ในสรุปทุกครั้ง** ว่าใช้การตัดสินใจไหน

## A. เรื่องที่บทเรียนสั่ง แต่ทำแบบนั้นไม่ได้ / ไม่ควร

1. **ไม่ใช้ Chrome ของผู้ใช้ (Playwright MCP --extension)** → ใช้ Playwright headless ทั้งหมด ทั้งดูหน้าแรกและสำรวจ
2. **จอดู agent (agents.log / agents.html / ภาพทุก 5 วินาที) เป็นของสอนใน LAB 5 — ค่าเริ่มต้นข้าม** ทำเฉพาะเมื่อผู้ใช้ขอ ("ขอดูจอ agent") ถ้าขอ: หน้าที่เปิดจาก `file://` fetch log ไม่ได้ → `agents-dashboard.mjs` render ข้อมูลจาก log ฝังลง HTML ใหม่ทุก 1 วินาที + `<meta refresh 2>` และ `watch-agents.mjs` ถ่ายภาพแทนการเปิดใน Chrome
3. **"agent พร้อมกัน 8 ตัว" อาจไม่ถึง 8** — Agent tool เปิดทีละตัวห่างกัน ~15 วินาที และโมดูลเล็ก (2 ข้อ) เสร็จใน ~30 วินาที ก่อนตัวที่ 8 จะเริ่ม รอบแรกได้สูงสุด 6 ใช้ทั้งหมด 10 → ถ้าวัดด้วยจอ agent ให้ **รายงานค่าจาก log ตามจริง** · ถ้าไม่ได้วัด ห้ามอ้างตัวเลขพร้อมกัน บอกแค่จำนวน agent ที่ใช้ · อยากเข้าใกล้ 8: ส่งโมดูลใหญ่ก่อน โมดูลเล็กทีหลัง
4. **จำนวน agent ทั้งหมด = จำนวนโมดูลที่เหลือ** (ไม่รวมโมดูลที่เขียนเองในขั้น 4) โมดูลที่มีบางข้อทำแล้ว (เช่น คูปองมี CPN-01 ในไฟล์ตะกร้า) ให้ agent ทำเฉพาะข้อที่เหลือในไฟล์ใหม่ และห้ามซ้ำ

## B. การรันขนานไม่ให้ชนกัน

5. **reset ชนกัน** — reset endpoint ล้างทั้งเซิร์ฟเวอร์ ถ้า agent สั่งระหว่างที่ตัวอื่นรัน ข้อมูลของคนอื่นหาย → `global-setup.ts` reset เฉพาะเมื่อไม่มี `SKIP_RESET=1`; agent รันของตัวเองด้วย `SKIP_RESET=1` เสมอ; รอบรวม reset ครั้งเดียว
6. **outputDir ชนกัน** — Playwright ลบ `test-results/` ทุกครั้งที่เริ่มรัน agent จะลบวิดีโอของกันเอง และ json reporter จะทับ `results.json` → agent ใช้ `--reporter=list --output=scratch/<AID>/test-results`
7. **ข้อมูลชนกัน** — สมัครสมาชิกใช้อีเมลไม่ซ้ำ (`Date.now()+random`); test ที่สั่งซื้อจริงใช้สินค้าคนละตัวกัน และไม่ใช้สินค้าที่ test อื่นตรวจสต็อก (สินค้าหมด/ใกล้หมดตามแผน) หรือที่ test ตะกร้าใช้ — ระบุชื่อสินค้าต้องห้ามใน brief
8. **ตะกร้า/รายการโปรดเก็บใน localStorage** (ตรวจได้จากหน้าเว็บ) → แต่ละ test ได้ context ใหม่ เริ่มว่างเสมอ ไม่ต้อง reset
9. รอบรวมใช้ `workers: 8`, `fullyParallel: true`, `retries: 0` (ไม่ซ่อน flaky)

## C. GIF ให้คนดูทัน

10. `slowMo: 350` + fixture `holdResult` (auto) ค้างหน้าผล ≥ 2.5 วินาที และเติมจนวิดีโอ ≥ 6.5 วินาที → GIF จริง 7–12 วินาที ไม่ต้องอัดใหม่
11. ห้ามยืด GIF ด้วย ffmpeg (tpad) — ถ้าสั้น ให้แก้ test ให้ช้าลง/ค้างผล แล้วรันข้อนั้นใหม่ (`make-gifs.mjs` exit 2)
12. GIF: fps 8, กว้าง 720, palette 128 สี → ~1–2 MB/ไฟล์ (40 ไฟล์ ≈ 60 MB, อยู่ใน .gitignore)
13. ทุก test จบด้วย `scrollIntoViewIfNeeded()` บน element ที่ assert เพื่อให้หลักฐานอยู่ในภาพสุดท้าย
14. **test API ไม่มีหน้าเว็บ** → ใช้ `showApiEvidence()` แสดง method / URL / status (เทียบที่คาดหวัง) / request / response บนหน้าจอ
15. ตรวจด้วยตาอย่างน้อย 2–3 ไฟล์ (เฟรมสุดท้าย) ก่อนบอกว่าเสร็จ

## D. การตีความแผน (เข้มตามตัวอักษร · ห้ามเลือกแบบที่ผ่านแล้วเงียบ)

กติกา: แผนอ่านได้หลายแบบ → ใช้แบบที่ตรงตัวอักษรที่สุด (ไม่ใช่แบบที่ทำให้ผ่าน) · ลองอีกแบบกับเว็บจริง · จดลง `test-report/interpretations.json` → รายงานคัดเอง: ถามเฉพาะข้อที่พลิกคำตัดสิน/เปลี่ยนผล P1 ที่เหลือลงภาคผนวก (ข้อ 18.1) ข้อ 16–23 คือค่าเริ่มต้นที่ใช้รอบแรก ข้อไหนกำกวมจริงให้จดด้วย

16. "error ทุกช่อง" = **ทุกช่อง** มี error ของตัวเอง (รอบแรกจับบั๊กได้: ช่องยืนยันรหัสผ่านไม่มี error)
17. "พบ N รายการที่ทำจาก X ทั้งหมด" = ตรวจจำนวน **และ** ตรวจทุกรายการว่าเป็น X จริง (ดูรายละเอียดสินค้า/คุณสมบัติ ไม่ใช่แค่ชื่อ)
18. **ตัวอย่างที่รอบแรกพลาด:** "อาหารแมว" ในระบบแนะนำ — agent ตีความว่า "สินค้าทุกชิ้นของแมว รวมขนม" แล้ว REC-01 ผ่าน โดยบอกแค่ในข้อความตอบกลับ ไม่ขึ้นในรายงาน ถ้านับแค่อาหารหลัก REC-01 จะล้ม (ขนมแมวเลียอยู่ในผลลัพธ์) และ P1 ล้ม = คำตัดสินเปลี่ยนเป็น "ยังไม่ปล่อย" → **เรื่องแบบนี้ (P1 ที่ผลเปลี่ยน) ต้องอยู่ใน "ข้อที่ต้องถามผู้ใช้" เสมอ**
18.1 **ถามให้น้อย (บทเรียนรอบ BUG_MODE=1, 2 พ.ย. 2569):** รอบนั้นถาม 13 ข้อ ผู้ใช้อ่านไม่ไหว → ถามเฉพาะ (ก) ข้อที่คำตอบพลิกคำตัดสินได้ (ข) ข้อ P1 ที่ผลจะเปลี่ยนหรือยังไม่รู้ · ข้ออื่นใช้แบบตรงตัวอักษรที่สุด จดในภาคผนวกท้ายรายงานสั้น ๆ ไม่ต้องถาม · ยังต้องจดทุกจุดลง interpretations.json และลองอีกแบบจริงเหมือนเดิม (สคริปต์ต้องใช้คัด) · ผลรอบนั้นหลังใช้กติกานี้: เหลือถาม 2 ข้อ (TC-CHK-02, TC-AUTH-06) ตีความเอง 11 ข้อ
19. "คูปองผิด / หมดอายุ" = ทดสอบทั้ง 2 กรณีใน test เดียว และตรวจว่ายอดไม่เปลี่ยน
20. "ตัวเลขลดลงทันที" = ตรวจภายใน ~1 วินาที โดยไม่รีโหลด
21. "สต็อก 3 กด + 5 ครั้ง" = กดครบ 5 ครั้งจริง (แม้ปุ่มจะ disabled) แล้วจำนวนต้องเป็น 3
22. API "สั่งซื้อโดยไม่ login ต้อง 401" = ส่ง body ที่ถูกต้องเหมือนหน้าเว็บส่ง (ดักจาก network ตอนกดสั่งซื้อ โดย `route.abort` ไม่ให้เกิด order จริง) เพื่อให้ 401 หมายถึง "ไม่ login" ไม่ใช่ข้อมูลผิด; API 404 = ลองของที่มีอยู่ก่อนได้ 200 แล้วค่อยของที่ไม่มี
23. มือถือ: ใช้ `devices['Pixel 7']` ตัด `defaultBrowserType` ออก (ยังเป็น Chromium) และ `test.use({ video: { size: … } })` ต้องอยู่ **ระดับบนสุดของไฟล์** ไม่ใช่ใน describe
24. ความรุนแรงของบั๊ก = ระดับ P ของ test ข้อนั้นตามแผน
24.1 **คำตอบของเจ้าของแผนเก็บแยกรายแผน** ที่ `references/plan-answers/<เว็บ>.json` — ใช้ได้เฉพาะแผนที่ scope ตรง (ชื่อแผน + baseURL + จำนวน test) และถ้อยคำ `planText` ยังอยู่ในแถว test นั้น (`plan-answers.mjs` ตรวจให้) · **ห้ามเอาคำตอบของแผนหนึ่งไปใช้กับแผนเว็บอื่น** แม้คำจะเหมือนกัน (เช่น "อาหารแมว รวมขนม" เป็นคำตอบของ PawPantry เท่านั้น เว็บอื่นต้องตีความเข้ม + ลองอีกแบบ + ถามใหม่ตามข้อ 16–23) · แผนเปลี่ยนถ้อยคำ = คำตอบข้อนั้นหมดอายุ ต้องถามใหม่
24.2 ตัวอย่างรอบ 2 (PawPantry 2 พ.ย. 2569): เจ้าของแผนตอบ 8 คำถาม → REC-01/03 ผ่าน (ขนมนับเป็นอาหาร), AUTH-02 ยังล้มแต่ยืนยันว่าเว็บผิด, 3 เรื่องนอกแผนเป็นข้อสังเกต (คูปองหลุด = 💰) → 39/40 ปล่อยได้ · คำตอบของเจ้าของแผนเปลี่ยนคำตัดสินได้จริง จึงต้องถามทุกครั้งที่ไม่มีคำตอบเดิม

## G. ส่วนที่คนต้องตัดสินเอง (AI ทำให้ แต่ต้องบอก)

35. คำตัดสินปล่อย/ไม่ปล่อย คำนวณจากเกณฑ์ในแผน แต่ต้องบอก "ส่วนเผื่อ" (ล้มเพิ่มอีกกี่ข้อจะไม่ผ่าน) บั๊กที่ต้องแก้รอบหน้า และ **ถ้าตีความอีกแบบแล้วคำตัดสินพลิก ต้องบอกว่าคำตัดสินยังไม่เด็ดขาดจนกว่าผู้ใช้จะตอบ** · "พลิกได้จริงไหม" ให้ `build-report.mjs` คิด (กรณีที่เอื้อให้พลิกที่สุด) — รอบ BUG_MODE=1 สคริปต์เดิมเขียน "ยังไม่เด็ดขาด" เพราะมีข้อ unknown (CPN-03 P2) ทั้งที่ TC-CPN-01 P1 ล้มทุกการตีความ จนต้องแก้มือ → แก้สคริปต์แล้ว ห้ามแก้ TEST-REPORT.md ด้วยมืออีก
36. ข้อมูลที่ test ทิ้งไว้ในเว็บ (order, สต็อกที่ลด) — บอกผู้ใช้; reset รอบถัดไปจะล้างให้
37. ถ้าพลาดละเมิดกติกาเอง (เช่น `ls` โฟลเดอร์เว็บ) ให้บอกตรง ๆ ในสรุป
