# แม่แบบรายงานบั๊ก (Bug Report Template)

> ทีม QA · ผู้ดูแล มินท์ รัตนพงศ์ (`qa-mint`) · ใช้ใน ticket ทุกใบ
> กติกา: Dev ต้องทำซ้ำได้จากรายงานนี้อย่างเดียวโดยไม่ต้องถาม QA · ห้ามมีข้อมูลลูกค้าจริง (ใช้ user ทดสอบ) ตาม `customer-data-policy.md`

```
# [BUG] <สิ่งที่พัง> เมื่อ <เงื่อนไข>          ← ชื่อบอกอาการ + เงื่อนไข ไม่เกิน 80 ตัวอักษร

ระบบ / repo / เวอร์ชัน : <repo> · <branch> · <commit>
สภาพแวดล้อม          : <dev|uat|prod> · <URL> · browser/device · timezone ถ้าเกี่ยว
ความรุนแรง (Severity) : Sev1 ระบบใช้ไม่ได้ | Sev2 ฟีเจอร์หลักพัง ไม่มีทางเลี่ยง | Sev3 มีทางเลี่ยง | Sev4 เล็กน้อย/หน้าตา
ความเร่งด่วน (Priority): P1 ก่อน release ถัดไป | P2 sprint นี้ | P3 เมื่อว่าง
พบเมื่อ / โดย          : <วันที่> · <ชื่อ QA> · จาก <test id / ทดสอบมือ>

## ขั้นตอนทำซ้ำ
1. ...
2. ...
(ใส่ค่าที่ใช้จริงทุกขั้น: user ทดสอบ, สาขา, วันที่, เวลา)

## ผลที่คาดหวัง
...

## ผลที่เกิดจริง
...

## ทำซ้ำได้บ่อยแค่ไหน
<x / y ครั้ง> · เกิดเฉพาะเงื่อนไข: ...  · ไม่เกิดเมื่อ: ...

## หลักฐาน
- ภาพหน้าจอ / วิดีโอ / trace : <path>
- request/response ที่เกี่ยว (ตัดข้อมูลส่วนตัวออก)
- log ฝั่ง server (requestId)

## ข้อสังเกตของ QA (ไม่ใช่การวินิจฉัย)
สิ่งที่ต่างระหว่างกรณีผ่าน/ไม่ผ่าน, commit ที่น่าสงสัย

## ผลกระทบ
ใครโดน, กี่คน, มี deadline อะไรผูกอยู่
```

## เกณฑ์ Severity สำหรับระบบจองคิว

| อาการ | Severity |
|---|---|
| จองไม่ได้ทุกสาขาทุกเวลา | Sev1 |
| จองไม่ได้บางช่วงเวลา/บางสาขา ที่ควรจองได้ | Sev2 |
| แสดงจำนวนที่ว่างผิด แต่จองได้ถูก | Sev3 |
| ข้อความ/สีผิด | Sev4 |
