## 1. ความเป็นมา

ธนาคารมีสาขา 120 แห่งทั่วประเทศ ลูกค้าต้องรอคิวเฉลี่ย 38 นาที (สูงสุด 95 นาทีช่วงวันที่ 25–5 ของเดือน) และสาขาจัดพนักงานไม่ตรงกับช่วงที่คนมาก
ธนาคารต้องการระบบให้ลูกค้าจองคิวล่วงหน้า และพยากรณ์ปริมาณคิวเพื่อให้ผู้จัดการสาขาจัดคนได้ล่วงหน้า

## 2. วัตถุประสงค์

1. ลดเวลารอเฉลี่ยที่สาขาลง 30% ภายใน 6 เดือนหลังเปิดใช้
2. ให้ลูกค้าจองคิวได้ผ่าน **เว็บ** และ **LINE Official Account** ของธนาคาร
3. พยากรณ์จำนวนลูกค้าต่อสาขาต่อชั่วโมงล่วงหน้า 7 วัน เพื่อจัดตารางพนักงาน

## 3. ขอบเขตงาน

### 3.1 ระบบจองคิว (ลูกค้า)
- จอง / เลื่อน / ยกเลิกคิว ผ่านเว็บ และ LINE OA (LIFF)
- เลือกสาขา (120 แห่ง), ประเภทบริการ (ฝาก-ถอน, เปิดบัญชี, สินเชื่อ, บัตรเครดิต, อื่น ๆ), ช่วงเวลา 15 นาที
- ยืนยันตัวตนลูกค้าเดิมด้วยเลขบัตรประชาชน + วันเดือนปีเกิด + OTP แล้วดึงข้อมูลลูกค้าจากระบบ core banking (ข้อ 3.4)
- แจ้งเตือนก่อนถึงคิว (1 วัน, 30 นาที) และเมื่อใกล้ถึงคิว (เหลือ 3 คิว)
- รองรับลูกค้าที่ไม่ได้จอง (walk-in) ให้กดบัตรคิวที่ตู้สาขาเข้าระบบเดียวกัน

### 3.2 ระบบสาขา (พนักงาน)
- หน้าจอเรียกคิว, ย้ายคิวระหว่างช่องบริการ, บันทึกเวลาให้บริการจริง
- ผู้จัดการสาขาปรับจำนวนช่องบริการต่อช่วงเวลา และดูผลพยากรณ์ 7 วัน
- เข้าสู่ระบบด้วย SSO (Microsoft Entra ID ของธนาคาร)

### 3.3 โมเดลพยากรณ์คิว (Machine Learning)
- พยากรณ์จำนวนลูกค้าต่อสาขาต่อชั่วโมง ล่วงหน้า 7 วัน อัปเดตทุกคืน
- ความแม่นยำที่ยอมรับ: MAPE ไม่เกิน 20% ในภาพรวม ทดสอบกับข้อมูล 3 เดือนล่าสุด
- ต้องคำนึงวันหยุดนักขัตฤกษ์, วันเงินเดือนออก, วันหยุดยาว
- ธนาคารจะส่งข้อมูลบัตรคิวย้อนหลัง 24 เดือน (ไม่ระบุตัวตน) ให้หลังเซ็นสัญญา
- ต้องมีวิธีติดตามความแม่นยำหลังใช้งานจริง และถอยกลับรุ่นเดิมได้

### 3.4 การเชื่อมต่อระบบ
- **Core banking — Customer Lookup API** (REST, ผ่าน API Gateway ของธนาคาร, mTLS) ใช้ค้นข้อมูลลูกค้า (ชื่อ, ระดับลูกค้า, CIF) จากเลขบัตรประชาชน
- LINE Messaging API / LIFF ของบัญชี LINE OA ธนาคาร
- ระบบตู้กดบัตรคิวเดิมของสาขา (ผู้ผลิต: Q-Matic รุ่นเดิม ใช้ REST API)

### 3.5 รายงาน
- Dashboard ผู้บริหาร: เวลารอเฉลี่ย, จำนวนคิว, อัตราไม่มาตามนัด รายสาขา/ภาค/ทั้งประเทศ
- ส่งออก Excel ได้

## 4. ข้อกำหนดด้านความปลอดภัย

- ปฏิบัติตามแนวนโยบายการบริหารความเสี่ยงด้านเทคโนโลยีสารสนเทศของธนาคารแห่งประเทศไทย และ พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
- เข้ารหัสข้อมูลขณะส่ง (TLS 1.2 ขึ้นไป) และขณะจัดเก็บ (AES-256), เลขบัตรประชาชนห้ามเก็บแบบข้อความธรรมดา
- Audit log ทุกการเข้าถึงข้อมูลลูกค้า เก็บไม่น้อยกว่า 2 ปี
- ผ่าน penetration test โดยผู้ทดสอบอิสระที่ธนาคารกำหนด ก่อนเปิดใช้งานจริง
- ผู้รับจ้างต้องลงนามข้อตกลงรักษาความลับ (NDA) ทุกคนที่เข้าถึงข้อมูล

## 5. ระยะเวลาและการส่งมอบ

- ระยะเวลาดำเนินงาน **6 เดือน** นับจากวันลงนามสัญญา (คาดว่า 4 มกราคม 2027)
- นำร่อง 10 สาขาในเดือนที่ 5 ขยายครบ 120 สาขาภายในเดือนที่ 6
- รับประกันและบำรุงรักษา (MA) 1 ปีหลังขึ้นระบบ, SLA uptime ≥ 99.5%, Sev 1 ตอบรับภายใน 30 นาที

## 6. งบประมาณ

วงเงินไม่เกิน **4,800,000 บาท (ไม่รวมภาษีมูลค่าเพิ่ม)** รวมค่าพัฒนา, hosting ปีแรก และ MA ปีแรก

## 7. เอกสารที่ต้องยื่น

1. ข้อเสนอทางเทคนิค (โซลูชัน, สถาปัตยกรรม, ทีมงาน, แผนงาน)
2. ข้อเสนอราคาแยกรายการ
3. ผลงานที่ผ่านมากับสถาบันการเงิน อย่างน้อย 2 โครงการ
4. ระดับการให้บริการ (SLA)
