# นโยบายวงจรชีวิตผลิตภัณฑ์ (Product Lifecycle Policy) v2026.2

> เจ้าของ: บีม ศิริวัฒน์ (`pm-beam`) · อนุมัติโดย MD (`md-somchai`) · มีผล 2026-08-01
> ใช้กับ: `prd-writer` (หัวข้อ 1), `product-sunset` (หัวข้อ 2–4)

## 1. PRD ทุกฉบับต้องมี

1. ปัญหาของลูกค้า พร้อมหลักฐาน (ตัวเลขหรือจำนวนครั้งที่ถูกพูดถึง) — ห้ามมีข้อมูลส่วนบุคคลของลูกค้าปลายทาง (ทำตาม `customer-data-policy.md`)
2. ตัวชี้วัดความสำเร็จที่วัดได้ และค่าปัจจุบันก่อนทำ
3. ขอบเขต: ทำ / ไม่ทำในรอบนี้
4. user story + เกณฑ์ตรวจรับ (acceptance criteria) ที่ QA เขียน test ได้
5. ผลกระทบต่อเวอร์ชันอื่น (ฟีเจอร์ใหม่ทำบน v2 เท่านั้น)

## 2. เลิกให้บริการ (sunset / EOL): ลำดับและกำหนดเวลา

| ขั้น | กำหนด | รายละเอียด |
|---|---|---|
| 1. ขออนุมัติ | ก่อนประกาศ | MD ต้องอนุมัติถ้า **รายได้ค่าดูแลรายปี (MA) ที่จะหายไปรวมเกิน 500,000 บาท** หรือมีลูกค้าธนาคาร/สถาบันการเงิน |
| 2. ประกาศ | **ล่วงหน้าอย่างน้อย 180 วัน** ก่อนวันปิด | แจ้งเป็นหนังสือถึงลูกค้าทุกราย + เสนอทางย้าย |
| 3. ย้ายระบบ | ระหว่าง 180 วัน | เสนอย้ายไปเวอร์ชันใหม่ (ดูหัวข้อ 3) |
| 4. ส่งออกข้อมูล | เปิดให้ส่งออก **อย่างน้อย 90 วันก่อนวันปิด** | ไฟล์ CSV + คู่มือ ลูกค้าเป็นเจ้าของข้อมูล |
| 5. ปิดระบบ | วันปิด | ห้ามปิดก่อน **วันหมดสัญญา MA** ของลูกค้ารายใดที่ยังไม่ย้าย (ถ้าจำเป็นต้องปิดก่อน ต้องเจรจาและได้หนังสือยินยอม) |
| 6. ลบข้อมูล | **ภายใน 30 วันหลังปิด** | ลบข้อมูลส่วนบุคคลทั้งหมด รวม backup และ log แล้วส่ง **หนังสือยืนยันการลบ** ให้ลูกค้า (ลูกค้าธนาคาร: ทำตาม DPA ที่เซ็นไว้) |

## 3. ข้อเสนอย้ายเวอร์ชัน (มาตรฐาน)

- ค่าย้ายระบบ **ฟรี** ถ้าเซ็นสัญญา v2 ภายใน 90 วันหลังประกาศ
- ค่าบริการ v2 ปีแรก ลด 20% สำหรับลูกค้าที่ย้ายจาก v1
- ข้อมูลย้ายได้ครบ ยกเว้นรายงานที่ลูกค้าปรับแต่งเอง (ต้องทำใหม่บน v2)

## 4. สิ่งที่ห้ามทำ

- ห้ามประกาศวันปิดกับลูกค้ารายใดรายหนึ่งก่อนได้รับอนุมัติตามข้อ 2.1
- ห้ามบอกลูกค้าว่า "ข้อมูลถูกลบแล้ว" จนกว่า DevOps (`ops-art`) ยืนยันว่าลบครบทั้ง backup และ log
