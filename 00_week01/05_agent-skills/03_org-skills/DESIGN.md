## 3. สถาปัตยกรรมแล็บ: remote 1 ที่ + local หลายโต๊ะ (หัวข้อ 22.2)

```text
┌──────────────── docker compose (03_org-skills/_solution/compose.yml) ────────────────┐
│  gitea  (localhost:3300)  ← 🌐 REMOTE: คลัง novatech/org-skills, PR, รีวิว, CODEOWNERS │
│  gitea-runner             ← CI ของ Gitea Actions (ไวยากรณ์เหมือน GitHub Actions)        │
│  seed (รันครั้งเดียว)       ← สร้าง user 10 คน + ทีม 7 ทีม + branch protection             │
└──────────────────────────────────────────────────────────────────────────────────────┘
          ▲ git push / PR                         │ claude plugin marketplace update
          │                                       ▼
desks/ ← 💻 LOCAL: โฟลเดอร์ = โต๊ะทำงานของพนักงาน 1 คน
├─ sales-nida/.claude/settings.json   → รู้จักคลัง novatech + เปิด core, shared, sales
├─ sales-krit/ …                      → เหมือน nida (ใช้พิสูจน์ LAB 5)
├─ md-somchai/ · dev-pond/ · dev-new/ · qa-mint/ · hr-fah/ · admin-joy/
└─ _personal/<คน>/                    → skill ส่วนตัว ชั้น 5 (ยังไม่แชร์)
```

| การตัดสินใจ | เลือก | เหตุผล |
|---|---|---|
| คลังกลาง | **Gitea ใน Docker** (ไม่ใช่ GitHub จริง) | ผู้เรียนทุกคนมีบริษัทของตัวเอง ไม่ต้องมีบัญชี GitHub/องค์กร, มี PR + รีวิว + CODEOWNERS + Actions ครบ, ลบทิ้งได้หมด · ท้าย LAB บอกว่าใช้ GitHub จริงต่างกันแค่ URL |
| พนักงานหลายคน | **โต๊ะ = โฟลเดอร์** + plugin แบบ `--scope project` | ใช้บัญชี Claude เดียวก็เล่นได้หลายบทบาท แต่ละโต๊ะเห็นเฉพาะแพ็กของตัวเอง (หัวข้อ 24.4 แพ็กตามบทบาท) |
| admin บังคับติดตั้ง `core` | จำลองด้วย `desks/_template/.claude/settings.json` (`extraKnownMarketplaces` + `enabledPlugins`) | managed settings ของจริงต้องใช้สิทธิ์ admin ของเครื่อง ไม่แตะในแล็บ แต่บอกว่าของจริงใส่ที่ไหน (หัวข้อ 22.3) |
| ใครเป็นคนทำงาน | Claude Code ทุกขั้น ผู้เรียน **แค่สั่งเป็นภาษาคน** (หัวข้อ 22.2 กล่อง 💡) | ตรงกับสายการเรียนบท 05: ไม่ต้องเป็นโปรแกรมเมอร์ก็เปิด PR ได้ |

### LAB 1 · แต่ละแผนกหางานซ้ำ แล้วทำ skill ส่วนตัว (ชั้น 5) 🤖 ×6
- 🧑 คิดก่อน: ใช้หลัก "อันนี้เคยทำแล้วนี่" (หัวข้อ 18.1) ทุกแผนกเลือกงานซ้ำ 2 งาน

- 💬 พรอมต์ (ร่าง ต่อแผนก วางในโต๊ะของแผนกนั้น): `คุณคือพนักงานแผนก Sales ของโนวาเทค ลองทำ proposal ให้ลูกค้าธนาคารจาก novatech-kit 1 ฉบับ แล้วเก็บวิธีทำเป็น skill ส่วนตัว ใส่หัวไฟล์ owner/layer/uses/next/follows ตามหัวข้อ 21.1`
- รันจริง: 6 แชตพร้อมกัน (6 แผนก) → แสดงว่า **ต่างคนต่างทำ** = ภาพ "ความรู้ติดอยู่ในหัวคน" (หัวข้อ 18.2)
- 👀 สังเกตที่คาดว่าจะเจอ: 2 แผนกเขียน "นโยบายข้อมูลลูกค้า" ซ้ำกันเองคนละแบบ → เหตุผลที่ต้องมีชั้น `core` (นำเข้า LAB 2)
- 🧑 ตรวจหัวไฟล์ด้วยเช็กลิสต์ (ต่อยอด LAB 3 ส่วน 02): description มีคำที่คนในแผนกพิมพ์จริงไหม · เล็กและโฟกัสไหม
