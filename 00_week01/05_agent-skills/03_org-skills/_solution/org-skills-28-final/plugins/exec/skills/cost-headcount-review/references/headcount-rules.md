# ต้นทุนคน การตัดสินใจรับคน และมุมเงินสด

> ต้นทาง: `company-kit/hr-benefits-faq.md` ปี 2026 (`hr-fah`), `company-kit/jd-template.md`, วิธีคิดของ `cfo-ying`

## 1 · ต้นทุนต่อเดือนของพนักงาน 1 คน (ส่วนที่รู้ตัวเลข)
```
ต้นทุนขั้นต่ำ/เดือน = เงินเดือน + กองทุนสำรองฯ 5% ของเงินเดือน + ค่าอินเทอร์เน็ต WFH 500 + ค่าฟิตเนส 1,000
ต้นทุนต่อปี        = ต้นทุนขั้นต่ำ/เดือน × 12  (+ โบนัส ปี 2025 เฉลี่ย 1.8 เดือนของเงินเดือน)
```
ยังไม่มีตัวเลข (ต้องเขียนว่า "ยังไม่รวม"): ประกันสุขภาพกลุ่ม, ประกันสังคม, ตรวจสุขภาพ, อุปกรณ์ (MacBook Pro สาย Dev/QA/DevOps/ML, MacBook Air สายอื่น), งบพัฒนาตัวเอง 20,000 บาท/ปี

ข้อเท็จจริงที่มีผลกับเวลา/เงิน:
- สรรหา 3 รอบ ไม่เกิน 3 สัปดาห์ (HR → เทคนิค → MD)
- ทดลองงาน 119 วัน ได้สวัสดิการทุกอย่างตั้งแต่วันแรก (โบนัสคิดตามสัดส่วน)
- ปรับเงินเดือนปีละครั้ง เม.ย. · จ่ายโบนัส ม.ค. → **เงินสดออกก้อนใหญ่ ม.ค.**
- ค่า on-call 3,000 บาท/สัปดาห์ (เฉพาะ DevOps และ Dev ที่ดูแลระบบหลังขึ้นจริง)

## 2 · จุดคุ้มเงินเดือน
```
man-day ที่ต้องคิดเงินได้/เดือน = ต้นทุนขั้นต่ำ/เดือน ÷ ราคาขาย/วันของบทบาท (finance-rules.md ข้อ 3)
```
เป็นเกณฑ์ขั้นต่ำ (ยังไม่รวม overhead) — ถ้างานในมือให้ไม่ถึง ตำแหน่งนั้นกินกำไร

## 3 · ตารางตัดสินรับคน (ทีละตำแหน่ง)
| สถานการณ์ | คำแนะนำ |
|---|---|
| มีงานคิดเงินรองรับแล้ว (โปรเจกต์ active เกินกำลัง, ตรงเวลาลด, man-day เกินแผน) | **เดินหน้า** |
| งานผูกกับดีลเดียวที่ยังไม่ชนะ และไม่มีงานอื่นใช้ทักษะนี้ | **ชะลอ** สรรหาไว้ก่อนได้ แต่ออก offer หลังรู้ผลดีล |
| ไม่มีชื่อตำแหน่ง/เหตุผล/ช่วงเงินเดือน | **ขอข้อมูลจาก HR ก่อน** ห้ามแนะนำ |
| margin ต่ำกว่าเป้าติดกัน ≥ 2 เดือน | เข้มขึ้น: ทุกตำแหน่งต้องชี้งานคิดเงินที่รองรับได้ |

สัญญาณกำลังคนที่ดูจาก KPI: โปรเจกต์ตรงเวลา % (on-time = ไม่เลื่อน milestone เกิน 1 สัปดาห์), รายได้/กำไรขั้นต้นต่อหัว, win rate (เดือนเดียวแกว่งมาก ให้ดูเฉลี่ย 2–3 เดือนด้วย), pipeline เทียบเป้า, คนรับเข้าแต่ยังไม่ลงโปรเจกต์

## 4 · มุมเงินสด ("เดือนหน้าเงินพอไหม")
- รายได้ที่รับรู้ ≠ เงินสด: ดูหมายเหตุ KPI ว่างวดไหน "ออกใบแจ้งหนี้เดือนหน้า" → เงินเข้าหลังจากนั้นอีกตามเครดิตเทอม
- ไม่มีเงินสดคงเหลือ/ลูกหนี้/เงินเดือนรวม → **ห้ามตอบว่าพอ** ให้ระบุเงินเข้า-ออกที่รู้แน่ + ขอข้อมูลจาก `fin-joy`
- ดีลที่รอ MD: คำนวณ "เงินเข้าวันเซ็น" และ "วันที่ก้อนใหญ่เข้า" = เหตุการณ์ (UAT/go-live) + เงื่อนไขหน่วง + เครดิตเทอม · เทียบกับต้นทุนทีมที่ต้องจ่ายก่อน
- งวดที่หนักกว่าปกติ (ก้อนสุดท้าย > 30%, เครดิต > 30 วัน, ค่าปรับไม่มีเพดาน) → เสนอให้ต่อรองก่อนอนุมัติ
