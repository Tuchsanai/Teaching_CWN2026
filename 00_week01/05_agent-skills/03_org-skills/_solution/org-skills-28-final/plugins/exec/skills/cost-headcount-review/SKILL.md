# สรุปต้นทุน-กำลังคนรายเดือน (cost-headcount-review)

เปลี่ยน "ไฟล์ KPI รายเดือน" เป็น **รายงานที่ MD อ่าน 30 วินาทีแล้วตัดสินได้**: กำไรเท่าไหร่ ทำไม รับคนเพิ่มไหม เงินพอไหม
กติกาการเงินและตัวเลขต้นทุนคนที่ต้องใช้สรุปไว้ใน `references/` แล้ว ใช้ได้แม้เครื่องนั้นไม่มี `company-kit`

## ข้อห้าม (เช็กก่อนทำทุกครั้ง)

1. **ห้ามแต่งตัวเลข** ไม่มีในข้อมูล = เขียน "ยังไม่มีข้อมูล — ขอจาก ..." (โดยเฉพาะ SG&A, เงินสด, ลูกหนี้, เงินเดือนจริง)
2. คำว่า "กำไร" ต้องบอกเสมอว่าเป็น **กำไรขั้นต้น** หรือ **กำไรสุทธิ** — KPI มีแค่ gross margin จึงตอบได้แค่กำไรขั้นต้น
3. ตัวเลขที่เป็น**ค่าประมาณ**ต้องแสดงสูตรและช่วง (ต่ำ–สูง) ไม่ใช่ค่าเดียว
4. รายงานเป็น **เอกสารภายใน** มีต้นทุนและ margin ห้ามส่งออกนอกบริษัท (กติกา `references/finance-rules.md` ข้อ 5)
5. ห้ามใส่เงินเดือนรายบุคคลที่ระบุตัวตนได้ ใช้ช่วงเงินเดือนของตำแหน่งเท่านั้น

## ขั้นตอน

### 1 · หาข้อมูล
- ไฟล์ KPI รายเดือน (ปกติ `company-kit/monthly-kpi.csv`) คอลัมน์ดูที่ `references/kpi-file.md` ไม่เจอให้ถามผู้ใช้
- ไฟล์ประกอบ (ถ้ามี): ตำแหน่งที่เปิด (`jd-template.md`), สรุปดีลรออนุมัติ (`deal-summaries/`), TOR ดีลใหญ่ที่ตำแหน่งใหม่ผูกอยู่ (`deal-00x/`), โน้ตของผู้ใช้ใน `notes/`
- เดือนที่สรุป = เดือนล่าสุดที่ปิดแล้ว เทียบกับเดือนก่อนหน้าและ `target_monthly`

### 2 · คำนวณ
```
python -I <SKILL_DIR>/scripts/kpi_calc.py <monthly-kpi.csv> [เดือนนี้] [เดือนก่อน]
```
ได้ตาราง Markdown: รายได้, margin, กำไรขั้นต้น, ต้นทุนตรง, คน, รายได้/กำไรขั้นต้นต่อหัว, โปรเจกต์ตรงเวลา, win rate, pipeline + หมายเหตุทุกบรรทัด
→ **อ่านหมายเหตุทุกข้อ** มันมักเป็นคำตอบของ "ทำไม"

### 3 · อ่านตัวเลข (ตอบ 4 คำถามตามลำดับ)
1. **กำไรเท่าไหร่** — กำไรขั้นต้น vs เดือนก่อน vs เป้า (บาท) · รายได้ขึ้นแต่กำไรลง = ต้นทุนโตเร็วกว่า ต้องชี้
2. **ทำไม margin เปลี่ยน** — แปลง pts ที่หายเป็นบาท (รายได้ × pts) แล้วจับคู่กับเหตุในหมายเหตุ เช่น man-day เกินแผน × ต้นทุน/man-day จาก skill `core:pricing-rules` (ไม่รู้บทบาท → ใช้ช่วงบทบาทที่เป็นไปได้) · ส่วนที่อธิบายไม่ได้ให้ระบุเป็นเงินและขอข้อมูลรายโปรเจกต์
3. **ควรรับคนเพิ่มไหม** — ใช้ตารางตัดสินใน `references/headcount-rules.md`: คิดต้นทุนต่อเดือนต่อตำแหน่ง, จุดคุ้มเงินเดือน (man-day ที่ต้องคิดเงินได้), ผูกกับดีลไหน และดีลนั้นรู้ผลเมื่อไร → แนะนำทีละตำแหน่ง: เดินหน้า / ชะลอถึง <เหตุการณ์> / ขอข้อมูลก่อน
4. **เดือนหน้าเงินพอไหม** — ถ้าไม่มีเงินสด/ลูกหนี้ ห้ามสรุปว่า "พอ" ให้ระบุเงินเข้า/ออกที่รู้แน่ และผลของงวดเงินดีลที่รอ MD (ดู `references/headcount-rules.md` หัวข้อเงินสด)

### 4 · เขียนรายงาน
- ใช้โครงใน `references/report-template.md` ตามลำดับ · ภาษาไทยสั้น ตรง ตัวเลขมีคอมมา หน่วยบาท
- บันทึกที่ `work/<YYYY-MM ของเดือนที่ส่ง>-cost-headcount-review.md`
- ถ้าผู้ใช้ถามแค่คำถามเดียว (เช่น "เดือนนี้กำไรเท่าไหร่") ตอบสั้นในแชตพร้อมตัวเลข 3–4 บรรทัด แล้วเสนอว่าทำรายงานเต็มได้

### 5 · ตรวจก่อนส่ง
- [ ] ทุกตัวเลขย้อนกลับไปหาไฟล์ต้นทางหรือสูตรได้ (คำนวณซ้ำด้วยสคริปต์ ไม่คิดในหัว)
- [ ] กำไรขั้นต้น ≠ กำไรสุทธิ บอกชัด
- [ ] ค่าประมาณมีช่วงและสูตร · ข้อมูลที่ขาดอยู่ในตาราง "ข้อมูลที่ต้องขอเพิ่ม" พร้อมชื่อผู้ให้ข้อมูล
- [ ] มีหัวข้อ "ขอให้ MD ตัดสิน" ไม่เกิน 3 ข้อ
