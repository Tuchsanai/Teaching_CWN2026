# ฟีเจอร์ไหนควรทำก่อน — วิธีของบีม

1. **รวมเป็นเรื่อง (theme)** — feedback ที่แก้ด้วยฟีเจอร์เดียวกันรวมกัน เช่น "เตือนก่อนถึงคิว" + "เตือนผ่าน LINE" + "ดูคิวปัจจุบัน" = เรื่องเดียว "รู้ว่าใกล้ถึงคิว"
   ระวัง: รวมเฉพาะที่แก้ได้จริงด้วยของชิ้นเดียว เขียนเหตุผลการรวมไว้
2. **ตรวจประตูก่อนคิดคะแนน**
   - 🚫 ขัดนโยบาย/สัญญาที่ลูกค้าธนาคารให้ ธปท. (ความเป็นธรรมของคิว) หรือ PDPA → ไม่จัดลำดับ ส่ง MD / plat-may
   - 🏦 ดีลที่กำลังขายหรือข้อบังคับธนาคารต้องใช้ → ดันขึ้นแม้คะแนนต่ำ (เขียนเลข TOR/ดีล)
   - ต้องทำบน v1 → ไม่รับ เสนอย้าย v2
3. **คะแนน = จำนวนครั้งที่ถูกพูดถึง × ผลกระทบ ÷ แรงที่ใช้**
   - ผลกระทบ 3 = ขยับตัวชี้วัดหลัก (no-show, เวลารอ, ต้นทุน) หรือเพิ่มรายได้ · 2 = แก้ปัญหาที่ทำให้คิวหลุด/เสียลูกค้าบางส่วน · 1 = สะดวกขึ้น
   - แรง S=1 (≤ 2 สัปดาห์ทีม 2 คน), M=2 (≤ 1 เดือน), L=3 (> 1 เดือน) — ถ้าไม่แน่ใจ ให้ถาม Dev lead (`dev-pond`) แล้วระบุว่าประมาณเอง
4. **ผลลัพธ์**: ตารางเรื่อง | feedback | ถูกพูดถึง | ผลกระทบ | แรง | คะแนน | ประตู แล้วตามด้วยลำดับที่เสนอ 3–5 ข้อ + เหตุผล "ทำไมอันดับ 1 ก่อน" ที่มีตัวเลข
