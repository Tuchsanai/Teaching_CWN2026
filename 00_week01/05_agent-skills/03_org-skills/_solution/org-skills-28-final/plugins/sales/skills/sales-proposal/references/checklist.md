# เช็กลิสต์ก่อนส่ง proposal

## เนื้อหา
- [ ] 9 หัวข้อครบตามลำดับ (`proposal-template.md`)
- [ ] ตอบทุกข้อใน "เอกสารที่ต้องยื่น" ของ TOR (เช่น จำนวนผลงานอ้างอิงขั้นต่ำ)
- [ ] ทุกข้อกำหนดความปลอดภัยใน TOR มีมาตรการตอบในหัวข้อ 4.2
- [ ] SLA ระบุชั่วโมงที่ครอบคลุม ตรงกับแพ็ก MA ที่ขาย
- [ ] แผนงานตรงกับระยะเวลา/นำร่องใน TOR
- [ ] ไม่อ้างผลทดลอง/ต้นแบบเป็นคำสัญญา

## ราคา
- [ ] ตารางมาจาก `scripts/price.py` (ไม่พิมพ์เลขเอง) · รวมก่อน VAT ≤ งบ TOR
- [ ] margin และส่วนลดผ่านเกณฑ์ หรือส่ง `deal-approval` แล้ว
- [ ] ไม่มีต้นทุน/margin/buffer ในเอกสารลูกค้า · ระบุสิ่งที่ไม่รวมในราคา

## แบรนด์
- [ ] ผ่านน้ำเสียงและโครงเอกสารตาม skill `core:brand-guide`
- [ ] เลขที่เอกสารใช้ประเภท `NVT-PRP-<ปี>-<ลำดับ>`

## PDPA
- [ ] ค้นในไฟล์หาเลขแบบ `0[689]\d-\d{3}-\d{4}` / เลข 13 หลัก — ต้องไม่เจอ
- [ ] ไม่มีชื่อลูกค้าปลายทาง เลขบัญชี เลขบัตร
- [ ] ถ้าลูกค้าเป็นธนาคารหรือสถาบันการเงิน: มีหัวข้อชื่อ "ภาคผนวก PDPA" ต่อจากหัวข้อ 9 ครบ 3 ข้อตาม `references/bank-pdpa-annex.md` ของ skill `core:customer-data-policy` (DPA ระบุบทบาทผู้ประมวลผล/ผู้ควบคุม · Data residency รวม backup และ log · Breach notification ภายใน 72 ชั่วโมง)
- [ ] ถ้าลูกค้าเป็นธนาคารหรือสถาบันการเงิน: หัวข้ออื่นไม่ขัดกับภาคผนวก เช่น ไม่มี backup หรือ log อยู่นอกประเทศไทย
- [ ] ถ้าลูกค้าเป็นธนาคารหรือสถาบันการเงิน: SA หรือ DevOps ยืนยันแล้วว่าข้อมูลส่วนบุคคล รวม backup และ log ของโซลูชันที่เสนออยู่ในประเทศไทย และจดชื่อผู้ยืนยันไว้ใน internal-notes ถ้ายังไม่มีผู้ยืนยัน ให้ใช้เส้นทางใน `references/bank-pdpa-annex.md` ของ skill `core:customer-data-policy`
