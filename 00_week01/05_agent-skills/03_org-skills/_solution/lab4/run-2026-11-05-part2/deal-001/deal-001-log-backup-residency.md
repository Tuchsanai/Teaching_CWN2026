## คำตอบ ณ วันนี้: 🔴 ยังยืนยันไม่ได้ทั้งหมด

C1 ยังไม่ปิด จึง**ยังยื่นหัวข้อ 4.1 และภาคผนวก ก ข้อ 2 ไม่ได้** เพราะข้อความในเล่มรวม "backup และ log ทั้งหมด" ไว้ด้วยกัน ต้องพิสูจน์ได้ทุกชิ้น

| ข้อมูล | อยู่ที่ไหนตามแผน | ยืนยันได้ไหม | หลักฐานที่มีตอนนี้ | ที่ยังขาด |
|---|---|---|---|---|
| ฐานข้อมูล PostgreSQL (prod/uat/dev) | managed PostgreSQL HA ใน CL-M | 🟢 ได้ (ระดับราคา) | price-list CL-M = "Thailand region" · arch-standards ข้อ 4 "ระบบลูกค้าธนาคาร: cloud region ประเทศไทยเท่านั้น" | ชื่อ region จริงในบัญชี cloud ตอนสร้างระบบ |
| **Backup DB** (สำรองอัตโนมัติ + snapshot ก่อน deploy) | ระบบสำรองของ managed PostgreSQL ใน CL-M | 🟡 **ได้แบบมีเงื่อนไข** | อยู่ในบัญชี cloud เดียวกับ CL-M ซึ่งเป็น region ไทย | (1) เอกสารผู้ให้บริการ cloud ว่า automated backup / snapshot เก็บใน region เดียวกับฐานข้อมูล (2) ตั้งค่า **ห้ามคัดลอก snapshot ข้าม region** และ DR/สำรองนอกไซต์ต้องอยู่ในไทยเท่านั้น (3) ถ้าแผน DR ตาม ธปท. (proposal 4.2) ต้องมีไซต์สำรอง ต้องเป็น region/data center ในไทยอีกแห่ง ไม่ใช่ต่างประเทศ |
| ไฟล์ / object storage และ **audit log 2 ปี** | PostgreSQL + object storage ใน CL-M (SA ข้อ S8) ไม่ฝากไว้กับ LIC-APM | 🟢 ได้ (ระดับราคา) | price-list CL-M + arch-standards ข้อ 4 "object storage ภูมิภาคไทย" | สำเนาสำรองของ bucket ต้องไม่ตั้ง replication ข้าม region |
| **log แอป / APM / trace / metric** | **LIC-APM** "Monitoring / APM + log management license" 5,500 บาท/เดือน (ต้นทุน) | 🔴 **ยืนยันไม่ได้** | price-list **ไม่ระบุ region และไม่ระบุผู้ให้บริการ** · arch-standards ข้อ 5 บอกแค่ "ส่งเข้า log management กลาง" ไม่ระบุที่ตั้ง · ในโต๊ะ DevOps ไม่มีเอกสารสัญญา/region ของบริการนี้ | เอกสารลายลักษณ์อักษรจากผู้ให้บริการ: region/data center ที่เก็บ log, APM, trace **และสำเนาสำรองของผู้ให้บริการเอง**, ระยะเก็บ, ที่ตั้งของทีม support ที่เข้าถึงข้อมูลได้ |

หมายเหตุ: การปิดบังเลขบัตร/CIF/ชื่อ/เบอร์ ใน log ก่อนส่งออก (SA ข้อ 4 + coding-rules ข้อ 8) **ลดความเสี่ยง แต่ไม่ทำให้ข้อความ "log ทั้งหมดอยู่ในไทย" เป็นจริง** — ห้ามใช้เป็นเหตุผลแทนหลักฐาน region
