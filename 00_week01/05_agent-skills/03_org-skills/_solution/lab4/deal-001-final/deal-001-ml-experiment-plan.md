## ข้อสังเกตที่ต้องระวัง
- **ข้อมูลไม่ใช่ของลูกค้า**: ต้นแบบคือเกษตรไทย 40 สาขา · นครหลวงฯ 120 สาขา ลักษณะสาขาอาจต่าง (ห้าง, ต่างจังหวัด) → ตัวเลขต้นแบบใช้ได้แค่เลือก "สูตร" ไม่ใช่สัญญาผล
- **สิทธิ์ใช้ข้อมูล/โมเดลเกษตรไทยกับนครหลวงฯ** ยังไม่ได้เช็ก (`plat-may`) → แผน P1 จึงย้ายเฉพาะ "สูตร feature/params" และเทรนใหม่บนข้อมูลนครหลวงฯ ทั้งหมด ไม่นำ `model_r03.txt` ไปใช้
- **ช่วงเที่ยงพยากรณ์ต่ำ −20 ถึง −30%** ไม่สะท้อนใน MAPE รวม · under-forecast อันตรายกว่า over-forecast (สาขาจัดคนไม่พอ) และ TOR/FR-FCT-03 สั่งให้รายงานแยกช่วงนี้
- **การวัด MAPE**: ชั่วโมงที่ลูกค้า = 0 ทำให้ MAPE หารศูนย์ — ต้องเขียนนิยามให้ตายตัวและใช้เหมือนกันทุก run (ข้อเสนอ: คิดเฉพาะชั่วโมงทำการ 08:30–15:30 ที่ค่าจริง > 0 และรายงาน WAPE คู่กัน) · ยังไม่รู้ว่าต้าใช้นิยามไหน → r03b ต้องได้ผลเดิมก่อนถึงจะเชื่อนิยาม
- **tune บน test set**: r02 เลือก num_leaves จากผลบนชุดเดียวกับที่รายงาน → ตัวเลขอาจดีเกินจริง · P1 แยก validation ออกจาก hold-out
- **ความเสี่ยงคน**: ต้าเป็นสัญญาจ้างและไม่อยู่ในทีมดีลนี้ (workplan หัวข้อ 3) → ต้องเอา notebook + นิยาม MAPE ออกจากเครื่องต้าให้ได้ใน W46 ก่อนอย่างอื่น
