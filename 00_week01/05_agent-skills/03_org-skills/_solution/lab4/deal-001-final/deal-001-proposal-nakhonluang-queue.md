## 1. บทสรุปผู้บริหาร

เราเสนอระบบจองคิวผ่านเว็บและ LINE OA ที่เชื่อมกับตู้บัตรคิวเดิมของทั้ง 120 สาขา พร้อมโมเดลพยากรณ์ลูกค้ารายชั่วโมงล่วงหน้า 7 วัน เพื่อลดเวลารอเฉลี่ยลง 30% ภายใน 6 เดือนหลังเปิดใช้
ปัจจุบันลูกค้ารอคิวเฉลี่ย 38 นาที และนานถึง 95 นาทีช่วงวันที่ 25–5 ของเดือน เพราะสาขาไม่รู้ล่วงหน้าว่าคนจะมาเมื่อไร
ระบบนี้ให้ลูกค้าเลือกเวลามาเอง และให้ผู้จัดการสาขาเห็นตัวเลขพยากรณ์ก่อนจัดตารางพนักงาน
ส่งมอบภายใน 6 เดือน (ม.ค. – มิ.ย. 2027) · มูลค่า **4,780,000 บาท (ไม่รวม VAT)** รวมค่าพัฒนา, hosting ปีแรก และ MA ปีแรก ภายในวงเงินที่ธนาคารกำหนด

2. **ช่วงเวลาให้บริการของระบบ** — สาขาในห้างที่เปิดเสาร์–อาทิตย์มีกี่แห่ง (กำหนดเวลาดูแล SLA ในหัวข้อ 8)

5. **ค่าจ้างผู้ทดสอบเจาะระบบ (penetration test) อิสระ** — ธนาคารเป็นผู้ว่าจ้างโดยตรงใช่หรือไม่

## 4. ภาพรวมสถาปัตยกรรม

### 4.1 โครงสร้างระบบ
- Modular monolith (ระบบเดียวที่แบ่งโมดูลชัดเจน ดูแลง่ายและแยกออกเป็นบริการย่อยได้ภายหลัง) ด้วย Next.js + Node.js/TypeScript แยกโมดูล booking / branch / forecast / notification / integration / report
- PostgreSQL (managed, HA — ฐานข้อมูลสำรองพร้อมสลับอัตโนมัติ) + Redis เก็บช่องว่างต่อช่วงเวลา ป้องกันจองซ้อน (slot lock — ล็อกช่องเวลาระหว่างยืนยัน)
- คิวงาน (queue) สำหรับแจ้งเตือนและงานเชื่อมตู้คิว แยกจาก request หลัก
- งานพยากรณ์รันเป็นชุดอัตโนมัติ (batch) ทุกคืน เก็บทุกรุ่นของโมเดลพร้อมผลวัด เลือกรุ่นที่ใช้งานได้ทันที
- Hosting บน cloud ภูมิภาคประเทศไทย ขยายได้โดยไม่ต้องเขียนระบบใหม่

### 4.2 ความปลอดภัยและการปฏิบัติตามข้อกำหนด
เราตอบข้อกำหนดความปลอดภัยใน TOR ข้อ 4 ครบทุกข้อ ดังนี้
- **แนวนโยบายความเสี่ยงด้าน IT ของธนาคารแห่งประเทศไทย** — จัดทำเอกสารควบคุมการเข้าถึง การจัดการการเปลี่ยนแปลง (change management) การสำรองและกู้คืนข้อมูล ให้ฝ่ายความเสี่ยงของธนาคารตรวจในเดือนที่ 1 และกรอกแบบประเมินผู้ให้บริการของธนาคาร
- **พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562** — เก็บข้อมูลลูกค้าเท่าที่จำเป็นต่อการจองคิว ทำบันทึกกิจกรรมการประมวลผลข้อมูลให้ธนาคาร และลงนามข้อตกลงประมวลผลข้อมูล (DPA) ในฐานะผู้ประมวลผลข้อมูล · รายละเอียด DPA การเก็บข้อมูลในประเทศไทย (รวม backup และ log) และการแจ้งเหตุละเมิดภายใน 72 ชั่วโมง ดูภาคผนวก PDPA
- เข้ารหัสข้อมูลขณะส่ง (TLS 1.2 ขึ้นไป) และขณะจัดเก็บ (AES-256)
- **เลขบัตรประชาชนไม่ถูกเก็บแบบข้อความธรรมดา** — ใช้ยืนยันตัวตนกับ Customer Lookup API แล้วเก็บเฉพาะค่าแฮชแบบมี secret key สำหรับจับคู่คิว
- WAF (Web Application Firewall — ไฟร์วอลล์กรองการโจมตีหน้าเว็บ) และป้องกัน DDoS หน้าระบบ
- Audit log ทุกการเข้าถึงข้อมูลลูกค้า เก็บ 2 ปี แก้ไขย้อนหลังไม่ได้
- สิทธิ์ตามบทบาทผ่าน Microsoft Entra ID ของธนาคาร
- ข้อมูลที่ใช้เทรนโมเดลเป็นข้อมูลไม่ระบุตัวตนตาม TOR และลบสำเนาภายใน 90 วันหลังส่งมอบ
- ทดสอบช่องโหว่ภายในทุกรอบปล่อยงาน และเผื่อเวลาแก้ไขก่อน penetration test โดยผู้ทดสอบอิสระของธนาคาร
- ทีมงานทุกคนที่เข้าถึงข้อมูลลงนาม NDA ก่อนเริ่มงาน

### 4.3 การดูแลโมเดลพยากรณ์หลังใช้งานจริง
- วัด MAPE (ค่าคลาดเคลื่อนเฉลี่ยเป็นเปอร์เซ็นต์) รายสัปดาห์ แยกรายสาขาและรายช่วงเวลา
- เฝ้าระวังเป็นพิเศษช่วงที่พยากรณ์ต่ำกว่าจริง (เช่น พักเที่ยงในสาขาย่านสำนักงาน) เพราะทำให้สาขาจัดคนไม่พอ
- ทดลองแบบ shadow (โมเดลรุ่นใหม่คำนวณคู่กันโดยยังไม่แสดงให้สาขา) ก่อนเปลี่ยนรุ่นทุกครั้ง
- เกณฑ์ถอยกลับรุ่นเดิมกำหนดร่วมกับธนาคารในเดือนที่ 1 และถอยกลับได้ภายใน 1 วันทำการ

- **ผลงานกับสถาบันการเงิน 2 โครงการที่ใกล้เคียงที่สุด** (ตาม TOR ข้อ 7.3):
  - ธนาคารสยามรุ่งเรือง — พอร์ทัลติดตามสถานะสินเชื่อ เชื่อมระบบสินเชื่อ (LOS) เดิมผ่าน API โดยไม่แก้ระบบเดิม ผ่าน penetration test ของธนาคาร ขึ้นระบบ ก.พ. 2025
  - ธนาคารออมทรัพย์เกษตรไทย — แอปนัดหมายสาขาผ่าน LINE OA และเว็บ 40 สาขานำร่อง ขึ้นระบบ ส.ค. 2025
- ระบบจองผ่าน LINE OA พร้อม slot lock ที่เราใช้งานจริงแล้ว ผ่านการทดสอบโหลด 2,000 การจองพร้อมกัน ลดความเสี่ยงและเวลาพัฒนา
- ทีมพยากรณ์ของเรากำลังพัฒนาโมเดลพยากรณ์คิวสาขาอยู่แล้ว รู้จุดยากที่ต้องดูแล ได้แก่ วันเงินเดือนออก สัปดาห์ที่มีวันหยุด และช่วงพักเที่ยง
- มาตรฐานความปลอดภัย: เข้ารหัสข้อมูล, audit log, สิทธิ์ตามบทบาท, ทดสอบช่องโหว่ทุกรอบปล่อยงาน
- รายงานความคืบหน้าทุกสัปดาห์ เห็นปัญหาก่อนกลายเป็นความล่าช้า

## ภาคผนวก PDPA

1. **ข้อตกลงการประมวลผลข้อมูลส่วนบุคคล (DPA)** — โนวาเทคเป็นผู้ประมวลผลข้อมูลส่วนบุคคล และ ธนาคารนครหลวงพัฒนา จำกัด (มหาชน) เป็นผู้ควบคุมข้อมูลส่วนบุคคล โนวาเทคประมวลผลข้อมูลส่วนบุคคลตามคำสั่งของ ธนาคารนครหลวงพัฒนา จำกัด (มหาชน) เท่านั้น
2. **การเก็บข้อมูลในประเทศไทย (Data residency)** — ข้อมูลส่วนบุคคลทั้งหมดจัดเก็บใน data center ในประเทศไทยเท่านั้น รวมถึงข้อมูลสำรอง (backup) และ log
3. **การแจ้งเหตุละเมิดข้อมูลส่วนบุคคล (Breach notification)** — โนวาเทคจะแจ้ง ธนาคารนครหลวงพัฒนา จำกัด (มหาชน) ภายใน 72 ชั่วโมง นับจากที่ทราบเหตุ
