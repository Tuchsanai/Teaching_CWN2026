## ข้อสังเกต

1. **`deal-001-pricing-input.json` เดิมใช้กับ `pricing-calc` ไม่ได้ตรง ๆ** — ใช้ key `budget` / `discount` แต่ script ของบัญชีอ่าน `budget_thb` / `discount_thb` ถ้ารันไฟล์เดิมจะไม่เห็นส่วนลด (ได้ 5,209,000) · ใช้ไฟล์ `deal-001-optA-input.json` / `deal-001-optB-input.json` แทน
2. **เรื่อง % ส่วนลดที่ notes ตั้งข้อสังเกต** — `pricing-calc` คิดจากยอดที่ลดได้ (9.5% / 17.8%) ตรงกับ `margin-rules.md` อยู่แล้ว ตัวที่หารราคาเต็ม (7.9%) คือ `price.py` ฝั่งขาย ให้ยึดตัวเลขของบัญชี
3. **ส่วนลด A 9.5% ชิดเพดาน 10%** — ลดเพิ่มได้อีกไม่ถึง 22,000 บาทก่อนต้องไป MD · margin B 25.1% ถ้าลดเพิ่มเกิน ~5,700 บาท จะต่ำกว่า 25%
4. **MA-STD กับ TOR** — benchmark ของบัญชีระบุ Sev 1 ตอบรับ 30 นาทีให้ใช้ MA-PREM · ถ้ากรรมการตีความว่า 24x7 ตัวเลือก A ไม่ตรง TOR
5. **ความเสี่ยง estimate** (ไม่ใช่การตัดสินของบัญชี แต่ต้องเตือน):
   - QA 44 = 32% ของ Dev+Dev-Sr (138) อยู่ในช่วง 25–35% ✅
   - PM 40 วันใน 6 เดือน (~120 วันทำการ) ≈ 1/3 ต่ำกว่าเกณฑ์ประมาณครึ่งเวลา (~60 วัน) สำหรับ rollout 120 สาขา
   - ค่าแรงไม่รวม ML 269 วัน สูงกว่าเกษตรไทย (225 วัน, 40 สาขา) ราว 20% ทั้งที่ขอบเขตใหญ่กว่า → อาศัย reuse โค้ด ถ้า reuse ไม่ได้หรือสิทธิ์ในโค้ดไม่ใช่ของเรา margin จะลดลง
6. ร่างใบเสนอราคา (`*-quotation-draft.md`) ไม่มีต้นทุน/margin/buffer ในตาราง · บรรทัดท้ายที่เป็นตัวเอียง ("ร่างจากบัญชี…") เป็นข้อความภายใน ต้องลบก่อนใส่ในเอกสารลูกค้า · ไม่พบเบอร์มือถือหรือเลขบัตรในไฟล์ที่บัญชีออก
