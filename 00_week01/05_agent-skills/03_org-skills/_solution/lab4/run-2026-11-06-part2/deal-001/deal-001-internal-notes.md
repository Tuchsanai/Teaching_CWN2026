2. **กำลังคน:** DS-2026-034 ระบุว่า tech lead (ปอนด์) จะถือ 3 โปรเจกต์ช่วง ม.ค.–ก.พ. 2027 รวมดีลนี้ และ `monthly-kpi.csv` ยังมีตำแหน่ง Senior Full-stack กับ ML Engineer เปิดอยู่ ถ้าทีมไม่ครบ ประโยค "ทีมชุดเดียว / ไม่ใช้ผู้รับเหมาช่วง" จาก proposal เก่าใช้ไม่ได้ จึงตัดออก
3. **ML:** ผล r03 (MAPE 15.2%) **ไม่ได้ใส่ใน proposal** เพราะเป็นผลต้นแบบบนข้อมูลของอีกธนาคาร จำนวนสาขาและรุ่นข้อมูลต่างจาก r02 (ยังไม่เคยเทียบแบบแฟร์) ยังพยากรณ์ช่วงเที่ยงต่ำกว่าจริง −20 ถึง −30% ในสาขาย่านออฟฟิศ และยังไม่มี monitoring/MLflow ส่วนสิทธิ์ใช้ข้อมูลเกษตรไทยกับดีลนี้ก็ควรตรวจก่อน
4. **เกณฑ์ MAPE ≤ 20% เป็นเกณฑ์ตรวจรับ:** ยังไม่มีผลบนข้อมูลของนครหลวงฯ เราผูกตัวเองตาม TOR โดยไม่มีหลักฐานจากข้อมูลนี้ และข้อมูลยังมาหลังเซ็นสัญญา ไม่ได้ระบุวันใน TOR
5. **เป้าลดเวลารอ 30%:** ขึ้นกับการจัดคนของสาขาด้วย ใน proposal เขียนเป็นเป้าหมาย ไม่ใช่การรับประกัน ควรระวังไม่ให้กลายเป็นเงื่อนไขสัญญาหรือค่าปรับ
6. **แผนงานตึง:** แผนใหม่แยกงานซ้อนแล้ว แต่ขึ้นกับธนาคาร ถ้า sandbox ช้าเกิน 12 ก.พ. หรือคิว pentest เริ่มหลัง 29 มี.ค. จะไม่ทัน UAT ถ้านำร่องเลย 18–19 พ.ค. จะติดช่วงห้าม deploy โดยมีทางสำรองคือคืน อ. 1 มิ.ย. (สาขาเริ่มใช้ พ. 2 มิ.ย. ยังอยู่ในเดือนที่ 5 แต่เห็นพีคเพียงช่วงท้าย) และถ้าวันลงนามเลื่อนจาก 4 ม.ค. ต้องจัดวันใหม่ ไม่ใช่เลื่อนตามกันได้ทั้งแผน · ถ้าพลาดคืน 23 มิ.ย. คืน 24 มิ.ย. ใช้ได้ต่อเมื่อธนาคารยอมรับให้เริ่มใช้ 25 มิ.ย. ไม่อย่างนั้นไป พฤ. 1 ก.ค. และ go-live กับ MA เลื่อน 8 วัน
7. **SLA 8x5 กับ uptime 99.5%:** ความล่มนอกเวลาทำการยังนับ uptime แต่ไม่มีคนตอบรับ จึงเสี่ยงผิด SLA รายเดือนได้ง่าย (99.5% ≈ 3.6 ชั่วโมงต่อเดือน) เป็นเหตุผลให้ทบทวนข้อตัดสินใจ 1

### ภาคผนวก PDPA และผู้ยืนยัน data residency

ใส่ "ภาคผนวก PDPA" ต่อจากหัวข้อ 9 แล้ว 3 ข้อ คัดลอกข้อความจาก `bank-pdpa-annex.md` โดยไม่แก้

**ผู้ยืนยัน data residency (SA หรือ DevOps): ยังไม่มี** และยังไม่มีข้อสรุปจาก `plat-may` และ MD จึง**ห้ามยื่นธนาคาร**จนกว่าจะได้ข้อสรุปตาม `bank-pdpa-annex.md`

จุดที่ต้องยืนยัน เพราะเอกสารที่อ่านได้ไม่ได้บอกที่ตั้งชัดเจน ยังไม่พบว่ามีจุดใดอยู่นอกประเทศไทย

| จุด | สิ่งที่เอกสารระบุ | ที่ยังไม่รู้ |
|---|---|---|
| Hosting (CL-M, CL-S) | price-list ระบุ Thailand region และ `arch-standards.md` ระบุว่าระบบลูกค้าธนาคารต้องอยู่ใน cloud region ประเทศไทย | backup และ snapshot อยู่ region เดียวกันหรือไม่ |
| Log management (LIC-APM) | `arch-standards.md` ระบุว่า log ส่งเข้า log management กลาง แต่ price-list ไม่ระบุ region | log และ APM เก็บที่ใด |
| WAF + DDoS (LIC-WAF) | price-list ไม่ระบุ region | log และ traffic ของ WAF ถูกประมวลผลหรือเก็บที่ใด |
| LINE Messaging API / LIFF (LIC-LINE) | เป็นบริการภายนอกที่ TOR กำหนด | ข้อมูลที่ส่งผ่าน LINE ขัดกับคำว่า "ทั้งหมด" ในข้อ 2 หรือไม่ ต้องให้ `plat-may` ตีความ |
| OTP ทาง SMS | ยังไม่รู้ gateway (ถามธนาคารใน proposal ข้อ 2) | เบอร์ปลายทางผ่านระบบที่ใด |
