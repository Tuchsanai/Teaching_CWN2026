## 2. QA, PM และ CL-M

**PM: ไม่พอ เสนอ 47 วัน.** 39 วันคิดเป็น 32.5% ของ 120 วันทำการ ต่ำกว่าเกษตรไทย (30 ÷ 80 = 37.5%) และสยามรุ่งเรือง (40 ÷ 100 = 40%) ทั้งที่งานนี้มี 120 สาขาและต้องรอธนาคารหลายจุด 47 วันได้ 39.2% ส่วนครึ่งเวลาตามฐานเทียบของบัญชี (ก่อน buffer 60 วัน) ยังไม่จำเป็น ถ้าคุณนิดาเห็นว่าสาขาต้องการมากกว่านี้ margin จะลดอีก

**QA: เสนอ 47 วัน.** 38 วันเดิมได้ 30% ของ Dev ก็จริง แต่ Dev เปลี่ยน เมื่อคง 30% ของ 141 วันจะได้ 42 วันก่อน buffer อยู่ในช่วง 25–35% และใกล้เกษตรไทย 29% กับสยามรุ่งเรือง 28% ไม่ควรลดเพื่อคุมราคา

**CL-M: ผ่านแบบมีเงื่อนไข ไม่เสนอ CL-L**

- **ปริมาณงานประมาณการ:** 120 สาขา × 15 คน/ชม. × 7 ชม. ≈ 12,600 คน/วัน ถ้าพีค 3 เท่าพร้อมกันทุกสาขา ≈ 1.5 คน/วินาที หรือราว 15 request/วินาทีฝั่งจอง ค่าเฉลี่ยมาจากข้อมูลเกษตรไทย เพราะ TOR ไม่ให้ปริมาณจริง
- **ต้องยืนยันก่อนใช้เลขนี้:** ปริมาณจริงของธนาคาร, จำนวนช่องบริการ, การรีเฟรชของ Console และขนาด disk ของ CL-M ซึ่ง price-list ไม่ระบุ
- **`ops-art` ต้องดู:** 3 เครื่องวาง app, worker, core-connector แยกเครือข่าย และ batch พยากรณ์ได้โดยไม่มีจุดเดียวล่มหรือไม่
- **ความเสี่ยงถ้าผิด:** ใช้ CL-L ที่ราคาเดิมกับ man-day ชุดนี้ ต้นทุนเพิ่ม 360,000 margin เหลือ 13.7% ต้องปฏิเสธ และทดสอบโหลดจริงจะเกิดหลังเซ็นสัญญาแล้ว (15–19 มี.ค. 2027)

## 4. สิทธิ์ reuse: ยังยืนยันไม่ได้

**ยังไม่มีเอกสารใดที่ SA อ่านได้ที่บอกว่าใครถือสิทธิ์โค้ด** และหลักฐานเรื่องที่มาของโค้ดยังขัดกันเอง

| ทรัพย์สิน | สิ่งที่เอกสารบอก | สถานะ |
|---|---|---|
| โค้ดแอปเกษตรไทย (Next.js) | Proposal 2025 ไม่มีข้อกำหนดสิทธิ์ และไม่พบสัญญาในพื้นที่ที่อ่านได้ | 🔴 ต้องดูสัญญา |
| NovaQueue v1 | Java 8 ที่เลิกออกแพตช์แล้ว on-prem ไม่ตรงกับ stack มาตรฐาน | ❌ ไม่นับ reuse ไม่ว่าสิทธิ์เป็นอย่างไร |
| NovaQueue v2 | ผลิตภัณฑ์ของเราบน cloud แต่ไม่ระบุ stack และเป็น SaaS หลายลูกค้า | 🔴 ต้องตรวจสิทธิ์และโครงสร้าง |

**จุดที่ขัดกันและ `pm-beam` ต้องตอบ**

- `novaqueue-overview.md` บอกว่า NovaQueue "ต่อยอดจากแอปที่ทำให้เกษตรไทยในปี 2025" แต่ v1 เปิดตัว เม.ย. 2023 และ v2 เปิดตัว มิ.ย. 2025 ก่อนเกษตรไทย go-live (18 ส.ค. 2025)

- **ผลคือสองทรัพย์สินนี้อาจไม่แยกกัน:** ถ้า v2 มีโค้ดจากงานเกษตรไทยจริง สิทธิ์ตามสัญญาเกษตรไทยจะกระทบ v2 ด้วย จึงอ้าง v2 เป็นทางออกโดยไม่ดูสัญญาไม่ได้

## 5. Data residency: ยังไม่ลงชื่อ

SA ไม่มีสิทธิ์เข้า cloud console และเอกสารไม่ระบุผู้ให้บริการ log กับ WAF **จึงไม่ลงชื่อแทนการตรวจจริง** โน้ตภายในข้อ 7 ยังคงเป็น "ยังไม่มีผู้ยืนยัน" ข้อความภาคผนวก PDPA ไม่ได้แก้

SA เพิ่ม 3 แถวล่างจากที่ MD ขอ เพราะข้อ 2 ของภาคผนวกเขียนว่า "ทั้งหมด"

| จุด | สิ่งที่เอกสารระบุ | หลักฐานที่ต้องใช้ | อยู่ที่ไหน | ผู้ยืนยัน / วันที่ |
|---|---|---|---|---|
| Backup + snapshot ฐานข้อมูล | hosting เป็น Thailand region แต่ไม่พูดถึงที่เก็บ snapshot และสำเนาข้ามภูมิภาค | ค่าตั้งใน console + นโยบาย replication | | |
| Log management + APM (LIC-APM) | "log management กลาง" ไม่ระบุ region | สัญญาหรือเอกสารผู้ให้บริการ + ที่ตั้ง tenant | | |
| WAF + DDoS (LIC-WAF) | ไม่ระบุ region | จุดถอดรหัส TLS, จุดประมวลผล traffic, ที่เก็บ log ของ WAF | | |
| Redis, คิว, dead-letter, object storage | object storage ไทยตาม arch-standards ส่วนอื่นอยู่ใน CL-M | ค่าตั้งระบบ | | |
| Trace (OpenTelemetry), การแจ้งเตือน, CI | ไม่ระบุ | ปลายทางจริงและข้อมูลที่ส่งออก | | |
| ข้อมูลเทรน ML | โมเดลต้นแบบทำบน laptop และ drive ทีม | bucket ในไทยสำหรับดีลนี้ และห้ามใช้วิธีเดิม | | |

**ถ้าจุดใดอยู่นอกไทย** ต้องได้ราคาจริงก่อนตัดสิน ตัวเลขนี้เป็นการประเมินคร่าว ๆ และยังไม่รวมในข้อ 1

| จุด | ทางเปลี่ยน | ผลกระทบ |
|---|---|---|
| Backup | snapshot ใน region ไทยเท่านั้น ปิดการสำเนาข้ามภูมิภาค | ค่าตั้ง อาจมีค่าพื้นที่เพิ่ม |
| Log/APM | ติดตั้งระบบ log เองบน cloud ไทย | DevOps เพิ่มราว 6–9 วันหลัง buffer (ต้นทุน 54,000–81,000) + ค่าเครื่องตามใบเสนอราคา |
| WAF | WAF ระดับ region ไทย ไม่ใช้ edge นอกประเทศ | ราคาผู้ขายจริง + อย่างน้อย 20% |

**ข้อมูลทางเทคนิคสำหรับ `plat-may` (ไม่ใช่การตีความ):** ออกแบบให้ข้อความ LINE มีเฉพาะรหัสอ้างอิงและเวลานัด ไม่มีชื่อหรือข้อมูลส่วนบุคคล ส่วน OTP ใช้ SMS gateway ของธนาคารได้ถ้าธนาคารยืนยัน แต่ LINE ยังรับรู้ userId ของผู้ใช้ และ `plat-may` ควรพิจารณาจุดนี้ด้วย
