# exec-deck — สไลด์ประชุมผู้บริหารต้นเดือน

เป้าหมาย: MD อ่านจบใน 5 นาที และรู้ทันทีว่า **ต้องตัดสินอะไร ภายในวันไหน**

## ขั้นตอน

1. **หาข้อมูล** (ถามผู้ใช้ถ้าหาไม่เจอ อย่าเดาตัวเลข)
   - KPI รายเดือน (CSV แบบ `metric,unit,YYYY-MM...,target_monthly,note`) — ในโนวาเทคคือ `company-kit/monthly-kpi.csv`
   - สรุปดีลที่ส่งถึง MD (`deal-summaries/`) · log/incident ล่าสุด · โน้ตของผู้ใช้ใน `notes/` ถ้ามี
   - วันประชุม — ถ้าไม่ได้บอก ให้ใช้วันทำการถัดไปและแจ้งผู้ใช้ว่าสมมติ
2. **สรุปตัวเลข** ด้วยสคริปต์ (อย่าคิดเลขเอง):
   ```
   python scripts/kpi_summary.py <monthly-kpi.csv> [--month YYYY-MM] > work/<YYYY-MM>-kpi-summary.md
   ```
   ได้ตารางเทียบเดือนก่อน + สถานะเทียบเป้า + กำไรขั้นต้นเป็นบาท + อัตราตรงเวลา
3. **เขียนหัวสไลด์ก่อนทำหน้าตา** — 1 สไลด์ = 1 ประโยคข้อสรุป ที่มีตัวเลข อ่านเรียงกันแล้วต้องเล่าเรื่องได้ครบ
   ดูว่า MD อยากเห็นอะไรก่อนใน [references/md-reading-order.md](references/md-reading-order.md)
4. **ประกอบ deck** ตามโครง 7 หน้า + ภาคผนวก โดยแก้จาก [assets/example-deck.html](assets/example-deck.html)
   (CSS สี ฟอนต์ โลโก้ฝังในไฟล์แล้ว) กติกาแบรนด์ทั้งหมด (สี ฟอนต์ โครงสไลด์ โลโก้) ใช้ skill `brand-guide` (core) ข้อ 1, 2, 4, 6 — ไม่เก็บสำเนาไว้ใน skill นี้
5. **ตรวจก่อนส่ง** (checklist ท้ายไฟล์นี้) แล้ว export PDF:
   ```
   msedge --headless=new --no-pdf-header-footer --print-to-pdf=work/<YYYY-MM>-exec-deck.pdf work/<YYYY-MM>-exec-deck.html
   ```
   (Chrome ใช้ flag เดียวกัน) · ถ้ามี screenshot ได้ ให้ดูภาพว่าไม่มีข้อความล้นกรอบ
6. **บันทึกผล** ใน `work/` ชื่อ `<YYYY-MM ของเดือนประชุม>-exec-deck.html|pdf` และ `-kpi-summary.md`

## โครง deck (ตายตัว)

| # | หน้า | ต้องมี |
|---|---|---|
| 1 | ปก | เดือนประชุม + วันประชุม + "ผลการดำเนินงานเดือน…" (ไม่มีโลโก้มุมขวาล่าง) |
| 2 | สรุป 3 บรรทัด | ดี / น่าห่วง / ต้องตัดสินใจ (บรรทัดสุดท้ายมีวันกำหนดตอบ) |
| 3 | การเงิน | รายได้, margin %, กำไรขั้นต้น (บาท) เทียบเป้าและเดือนก่อน + เหตุผลจากคอลัมน์ note |
| 4 | Pipeline + ดีลรออนุมัติ | ตารางดีล: มูลค่าไม่รวม VAT, margin, เกณฑ์ที่เข้า, วันต้องตอบ |
| 5 | ส่งมอบ + เหตุขัดข้อง | ตรงเวลา x/y, Sev1/Sev2, NPS, งานค้างจาก incident ก่อน |
| 6 | คน | headcount, ตำแหน่งว่าง, ลาออก, ความเสี่ยงกำลังคนที่ผูกกับดีล |
| 7 | เรื่องที่ขอให้ MD ตัดสิน | ≤ 3 เรื่อง เรียงตามวันกำหนด, ข้อเท็จจริงที่ต้องรู้ (ไม่ใส่ความเห็นว่าควรอนุมัติไหม) |
| ภาคผนวก | KPI ทั้งหมด | ตารางเต็มจากสคริปต์ |

## ข้อห้าม

- **ไม่ตัดสินดีลแทน MD** — ใส่แค่ข้อเท็จจริงและเกณฑ์ที่ดีลเข้า (การประเมินเป็นงานของ skill `deal-approval`)
- ไม่ใส่เบอร์มือถือ เลขบัตร เลขบัญชีของลูกค้า (ตาม `customer-data-policy`) — deck นี้ใช้ชื่อบริษัท/รหัสดีลพอ
- ไม่ใช้คำ "ดีที่สุด", "100%", ไม่ใช้อีโมจิ, ไม่ใช้สีแดงสด/gradient

## Checklist ก่อนส่ง

- [ ] ≤ 10 สไลด์ (ไม่รวมภาคผนวก) · ≤ 6 บรรทัดต่อสไลด์ · หัวสไลด์เป็นประโยคที่มีตัวเลข
- [ ] ตัวเลขทุกตัวตรงกับ kpi-summary / ใบสรุปดีล (เงินมีคอมมา ระบุ "ไม่รวม VAT")
- [ ] Spark Orange ไม่เกิน 1 จุดต่อหน้า — ใช้กับเรื่องสำคัญสุดที่ต่ำกว่าเป้า/ต้องตัดสินใจ ที่เหลือใช้ตัวอักษรปกติ
- [ ] ตัวเลขผ่านเป้าใช้ Teal · ทุกหน้า (ยกเว้นปก) มีโลโก้มุมขวาล่างและบรรทัด "ที่มา:"
- [ ] วันกำหนดตอบในหน้า 2 กับหน้า 7 ตรงกัน และสอดคล้องกับวันประชุม (วันนี้/พรุ่งนี้)
- [ ] แจ้งผู้ใช้ทุกจุดที่สมมติเอง (วันประชุม, ข้อมูลที่ขาด เช่น ชื่อโปรเจกต์ที่เลื่อน)
