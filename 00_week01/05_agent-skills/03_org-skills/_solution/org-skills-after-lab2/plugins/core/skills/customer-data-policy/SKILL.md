# customer-data-policy: ตรวจ PDPA ก่อนเอกสารออกจากมือ

ทำเรื่องเดียว คือเอาเอกสารเทียบนโยบายข้อมูลลูกค้า แล้วบอกว่า **ส่งได้ / ส่งไม่ได้** ตรงไหน ต้องแก้อย่างไร
(ไม่ตรวจตัวเลขเงิน ส่ง `invoice-check` · ไม่ตรวจแบรนด์/สไลด์ ส่ง `brand-guide` · ไม่รีวิวโค้ด ส่ง `coding-standard`)

`SKILL_DIR` = โฟลเดอร์ของ skill นี้ · ความรู้ทั้งหมดอยู่ใน `references/` ไม่ต้องมี company-kit ก็ใช้ได้

## ขั้นตอน

1. **รู้ก่อนว่าเอกสารไปไหน**: ภายนอก (ลูกค้า/คนนอก) หรือภายในบริษัท และเป็นเอกสารประเภทอะไร ถ้าผู้ใช้ไม่บอก ให้เดาจากเนื้อหา (มีผู้ซื้อ = ใบแจ้งหนี้ภายนอก, "โน้ตภายใน ยังไม่ส่งลูกค้า" = ภายใน) แล้ว **เขียนข้อสันนิษฐานไว้ในรายงาน**
2. **สแกนหาผู้ต้องสงสัย**: `python SKILL_DIR/scripts/scan_pii.py <ไฟล์>` (stdlib ล้วน) ได้ `ไฟล์:บรรทัด | ประเภท | ค่า` · ถ้าเป็นข้อความที่วางมาในแชต ให้อ่านทั้งหมดเอง สคริปต์จับไม่ได้ทุกอย่าง (ที่อยู่บ้าน, ชื่อที่ไม่มีคำว่า "คุณ", ข้อมูลในภาพ) **ต้องอ่านทั้งเอกสารซ้ำด้วยตาเสมอ**
3. **ตัดสินทีละจุด** ตาม `references/policy-summary.md` (นิยาม, รายการห้าม, ตาราง mask) + `references/doc-type-rules.md` (กติกาเฉพาะประเภทเอกสาร) ให้ผล 3 ระดับ
   - 🔴 **ห้าม**: ต้องแก้ก่อนส่ง (ตัดทิ้งก่อน ถ้าจำเป็นจริงค่อย mask/ใช้รหัสเคส)
   - 🟡 **ระวัง/ควรแก้**: ไม่ผิดข้อห้าม แต่เกินจำเป็น หรือผิดที่เก็บ (เช่น เบอร์มือถือในโน้ตภายใน ควรย้ายไป CRM)
   - 🟢 **ได้**: บอกเหตุผลสั้น ๆ ด้วย เพื่อให้คนถามไม่ต้องถามซ้ำ (เลขภาษีนิติบุคคล, บัญชีบริษัทเราเอง, อีเมลบริษัทของผู้ติดต่อ)
4. **เช็กว่าเป็นเหตุรั่วหรือยัง**: ถ้าเอกสารที่มีจุด 🔴 **ถูกส่งออกไปแล้ว** ให้บอกผู้ใช้ให้แจ้ง `plat-may` (#ask-pdpa / dpo@novatech.example) **ภายใน 1 ชั่วโมง** และห้ามแก้เงียบ ๆ เอง
5. **เขียนผล** ตาม `references/report-format.md` ได้คำตัดสิน → ตารางรายจุด → ข้อความแทนที่ → เรื่องนอกขอบเขตที่เห็น → ข้อความตอบกลับที่ copy ได้ (ในข้อความตอบกลับให้ mask ค่าที่เจอด้วย ห้ามยกค่าเต็มกลับไปในแชต)
6. ถ้าผู้ใช้ขอให้แก้ ให้ทำ **ฉบับแก้แยกไฟล์** (ห้ามเขียนทับต้นฉบับของคนอื่น) แก้เฉพาะจุด PDPA แล้วรัน `scan_pii.py` ซ้ำบนฉบับแก้ จนเหลือแค่ 🟢

## ตัดสินเองไม่ได้ ให้ส่งต่อคน

- ข้อมูลอ่อนไหว ม.26 (สุขภาพ ศาสนา ชีวภาพ ประวัติอาชญากรรม) ในเอกสารใดก็ตาม → ตอบว่า "ต้องให้ `plat-may` ดูเอง" พร้อมบอกจุดที่เจอ
- ลูกค้าขอให้ใส่ข้อมูลส่วนบุคคลเอง หรือสัญญากำหนดต่างจากนโยบาย → ยึดนโยบายไว้ก่อน แล้วส่งให้ `plat-may` + เจ้าของดีลตัดสิน
- การเข้าถึงข้อมูลจริงใน production / การขอสำเนาข้อมูลลูกค้าปลายทาง → ต้องมี ticket และผู้อนุมัติฝั่งลูกค้า ไม่ใช่เรื่องที่ skill อนุมัติได้

ตัวอย่างงานจริง (ใบแจ้งหนี้ INV-2026-0142) อยู่ใน `references/report-format.md`

## สำหรับ skill อื่นที่อ้าง skill นี้

นี่คือ **สำเนาเดียว** ของนโยบายข้อมูลลูกค้าในคลัง skill — skill ที่แตะข้อมูลลูกค้าให้ระบุ `follows: [customer-data-policy]` ใน header แล้วเรียก skill นี้ตอนตรวจก่อนส่ง **ห้ามคัดลอกรายการห้าม/ตาราง mask ไปไว้ใน references ของตัวเอง** (เดิมมีสำเนา 8 ที่) · กติกาเฉพาะประเภทเอกสารใหม่ ให้เปิด PR เพิ่มแถวใน `references/doc-type-rules.md`
