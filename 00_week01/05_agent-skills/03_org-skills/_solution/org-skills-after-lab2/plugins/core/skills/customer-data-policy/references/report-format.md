# รูปแบบผลตรวจ + ตัวอย่างจริง

## โครง (ตามลำดับนี้เสมอ)

```
# ผลตรวจ PDPA: <ชื่อเอกสาร>
- ผู้ตรวจ / วันที่ · เอกสาร (path) → ส่งให้ใคร · ประเภท: ภายนอก|ภายใน (+ข้อสันนิษฐานถ้าเดา) · อ้างอิงเวอร์ชันนโยบาย

## คำตัดสิน
🔴 ยังส่งไม่ได้ (N จุด) | 🟡 ส่งได้แต่ควรแก้ | 🟢 ส่งได้
+ สถานะเหตุรั่ว: ยังไม่ส่ง = ไม่ใช่เหตุ / ส่งไปแล้ว = แจ้ง plat-may ภายใน 1 ชม.

## รายจุด  (เรียง 🔴 → 🟡 → 🟢)
| # | บรรทัด | เจออะไร (mask ค่าในแชต) | ประเภทข้อมูล + ของใคร | ผล | เหตุผล / ข้อนโยบาย | ต้องทำ |

## ข้อความแทนที่   เดิม → ใหม่ ทีละจุด 🔴/🟡

## เรื่องนอกขอบเขต PDPA ที่เห็น   (ส่งต่อ skill/คนที่ดูแล ห้ามแก้เอง)

## ข้อความตอบกลับ (copy ได้)   2–4 บรรทัด, ค่าที่เจอต้อง mask
```

หลักเขียน: ทุกจุดต้องบอก **ของใคร** (ลูกค้าองค์กร / ลูกค้าปลายทาง / บริษัทเรา) เพราะชนิดข้อมูลเดียวกันได้ผลต่างกันตามเจ้าของ
