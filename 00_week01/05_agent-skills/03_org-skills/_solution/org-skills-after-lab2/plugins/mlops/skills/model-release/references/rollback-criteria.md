# เกณฑ์ถอยกลับ (rollback) โมเดลพยากรณ์ — ค่าเริ่มต้น

> ค่าเริ่มต้นเหล่านี้ = ค่าใน `scripts/check_rollback.py` · ปรับได้ต่อโมเดล แต่ต้องเขียนเหตุผลลง release plan
> ที่มา: ข้อเสนอของ DS ใน `ml-queue-forecast/notes.md` + กติกา rollback ของ deploy runbook ("ข้อมูลผิดแม้รายการเดียว = ถอยทันที")

## เกณฑ์

| รหัส | สัญญาณ | WATCH (เฝ้า + แจ้งทีม) | ROLLBACK (สลับกลับตัวเดิม) |
|---|---|---|---|
| R1 | MAPE รายสัปดาห์ (จันทร์–อาทิตย์) ของโมเดลใหม่ | > 22% 1 สัปดาห์ | > 22% **2 สัปดาห์ติด** |
| R2 | โมเดลใหม่แย่กว่า baseline/ตัวเดิม (รันคู่ขนาน) ในสัปดาห์เดียวกัน | 1 สัปดาห์ | **2 สัปดาห์ติด** |
| R3 | bias ช่วงพักเที่ยง 11:00–13:00 สาขาย่านออฟฟิศ = Σ(พยากรณ์−จริง)/Σจริง | ต่ำกว่า −20% | ต่ำกว่า **−30%** (สัปดาห์เดียวก็ถอย) |
| R4 | ข้อมูลพยากรณ์ผิด: ไม่มีพยากรณ์ของสาขา-ชั่วโมงใด, ค่าติดลบ, ค่าเกิน 3 เท่าของจริงสูงสุด | — | **ทันที** |
| R5 | batch คืนล้ม (ไม่ใช่ metric) | ล้ม 1 คืน → ใช้พยากรณ์เมื่อวาน | ล้ม **2 คืนติด** |

ทำไมเลขนี้:
- 22% = เกณฑ์ TOR ลูกค้า (≤ 20%) + เผื่อความผันผวนรายสัปดาห์ 2 จุด · 2 สัปดาห์ติดกันไม่ให้ถอยเพราะสัปดาห์แปลก ๆ สัปดาห์เดียว
- R3 เข้มกว่าเพราะพยากรณ์ต่ำ = สาขาจัดคนไม่พอ ลูกค้ารอนาน (เจ็บกว่าพยากรณ์เกิน)
- MAPE ข้ามชั่วโมงที่คนมา 0 คน (หารศูนย์ไม่ได้) — ถ้าสาขาเล็กมี 0 บ่อย ให้ดู MAE ประกอบ

## วิธีถอย (เรียงจากเร็วสุด)

1. สลับ flag ตัวเลือกโมเดล (`forecast_model_active`) กลับเป็นตัวเดิม — ตัวเดิมต้องรันคู่ขนานทุกคืนตลอดช่วงเฝ้า จึงมีตัวเลขพร้อมเสมอ
2. ถ้า flag ใช้ไม่ได้ → deploy image/model version เดิมที่จดไว้ (ตาม `deploy-rules.md`)
3. แจ้งลูกค้าภายใน 30 นาทีหลังถอย (ใครเป็น Comms) · ROLLBACK ทุกครั้งเขียน postmortem ภายใน 3 วันทำการ (skill `postmortem`)

ใครตัดสิน: เจ้าของ release (ML) ตัดสิน WATCH · ROLLBACK ตาม R4/R5 กดได้ทันทีโดย on-call · ROLLBACK ตาม R1–R3 เจ้าของ release + MLOps lead ตกลงกัน (ภายในวันทำการเดียว)

## ใช้สคริปต์

```bash
python scripts/check_rollback.py weekly.csv            # ค่าเริ่มต้น
python scripts/check_rollback.py weekly.csv --mape-max 25 --lunch-rollback -35
```

CSV: `date,hour,branch_id,zone,actual,pred_new,pred_base` (zone = `office` สำหรับสาขาย่านออฟฟิศ) · exit 0 OK / 1 WATCH / 2 ROLLBACK / 3 อินพุตผิด
ผลสรุปคือ "แย่สุดในช่วงที่ส่งเข้าไป" → ตอนเฝ้าหลังขึ้นจริง ให้ส่งเฉพาะ 2–3 สัปดาห์ล่าสุด
