# กติกา deploy ที่โมเดลต้องทำตาม (สรุปจาก deploy runbook ของ DevOps)

> ต้นฉบับ: `company-kit/deploy-runbook.md` (ผู้ดูแล `ops-art`, ปรับปรุง 2026-10-01) · ส่วนคืน deploy จริงให้ใช้ skill `deploy-checklist`

## ช่วงเวลา
- deploy ปกติ: **อังคาร–พฤหัส 21:00–23:00**
- ห้าม: วันศุกร์ · ก่อนวันหยุดยาว · **วันที่ 25 – สิ้นเดือน สำหรับลูกค้าธนาคาร** (เงินเดือนออก) — ยกเว้น hotfix Sev 1
- การสลับโมเดลจาก shadow → จริง นับเป็น deploy (ผู้ใช้เห็นตัวเลขเปลี่ยน) ต้องอยู่ในช่วงที่อนุญาต

## ก่อนวัน deploy
- release notes: รุ่นโมเดล, data version, ผลเทียบ, ความเสี่ยง, flag
- **ลูกค้าเซ็นรับ** (อีเมลยืนยันก็ได้) — ไม่มีลายลักษณ์อักษร = ไม่ deploy
- **แจ้งลูกค้าล่วงหน้า ≥ 3 วันทำการ** แม่แบบ `NOTICE-maintenance` ใช้เบอร์ on-call กลาง ห้ามเบอร์มือถือส่วนตัว
- ของเสี่ยงต้องอยู่หลัง feature flag ปิดไว้ก่อน
- จอง on-call 2 ชม. หลัง deploy + เช้าวันถัดไป 08:00–10:00

## 3 บทบาท (คนเดียวห้ามถือเกิน 2)
Deploy lead (กด + ตัดสิน rollback) · Verifier (คนที่ไม่ได้ทำโมเดลนั้น ทำ smoke test) · Comms (คุยลูกค้า + ช่อง `#deploy`)

## วัน deploy
- ก่อนกด: ดู dashboard ระบบปกติไหม · จด version ปัจจุบัน (ใช้ถอย) · **ปิด batch พยากรณ์รอบคืนถ้าชนกับ migration**
- smoke test ภายใน 15 นาที · error rate < 1%
- หลังเสร็จ: เปิด batch คืน · แจ้งลูกค้าเป็นภาษาผู้ใช้ · tag release + CHANGELOG

## ถอยทันทีถ้า (ระดับระบบ)
smoke test ไม่ผ่านแก้ไม่ได้ใน 15 นาที · error rate > 5% นาน 5 นาที · **ข้อมูลผิดแม้รายการเดียว**
ลำดับ: ปิด flag → deploy version เดิม → แจ้งลูกค้าภายใน 30 นาที · เกิดเหตุ → postmortem ภายใน 3 วันทำการ
