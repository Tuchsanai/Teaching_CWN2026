# meeting-minutes — บันทึกการประชุมแบบเดียวกันทั้งบริษัท

ได้ไฟล์ 1–2 ไฟล์: ฉบับภายใน (ครบทุกอย่าง) และ — ถ้าจะส่งให้คนนอก — ฉบับส่งผู้เข้าประชุม (ผ่าน `customer-data-policy` แล้ว)

`SKILL_DIR` = โฟลเดอร์ของ skill นี้ · โครงไฟล์อยู่ใน `references/minutes-template.md`

## ขั้นตอน

1. **อ่านโน้ตทั้งหมด** แล้วดึง: ชื่อประชุม/โครงการ/รหัสดีล, วัน-เวลา-สถานที่, ผู้เข้าประชุม (ฝั่ง + ตำแหน่ง), เรื่องที่คุย, เรื่องที่ตัดสินแล้ว, สิ่งที่ใครรับปาก, ตัวเลข (งบ วันที่ จำนวน)
   - ไม่รู้ข้อไหน ใส่ `[...]` ห้ามเดาชื่อคน วันที่ หรือตัวเลข
2. **แยก 3 อย่างให้ขาด** — *ตัดสินแล้ว* (มีคนมีอำนาจพูดว่าตกลง) / *รับปากว่าจะทำ* (= action item) / *ยังไม่ได้คำตอบ* (= คำถามค้าง) · คำพูดแบบ "น่าจะ", "เดี๋ยวดู" ไม่ใช่การตัดสิน
3. **action item ทุกข้อ** ต้องมี: งาน (ขึ้นต้นด้วยกริยา) · เจ้าของ 1 คน (ชื่อ + user ถ้าเป็นคนโนวาเทค) · วันกำหนดเป็นวันที่จริงพร้อมชื่อวัน (เช็กปฏิทิน) · ที่มา (ข้อไหนในโน้ต)
   - คำมั่นที่เกินหลักฐาน (เช่น "ผ่าน pentest ทุกครั้ง") ให้ติดป้าย ⚠️ ต้องยืนยัน — ห้ามแก้คำให้ดูดีขึ้นเงียบ ๆ
4. **เขียนฉบับภายใน** ตาม `references/minutes-template.md` ที่ `work/<YYYY-MM-DD>-minutes-<เรื่องสั้น>.md`
5. **ถ้าจะส่งคนนอก** (ลูกค้า ผู้ขาย) ทำฉบับ `-external.md` แยก แล้วใช้ `customer-data-policy` ตรวจก่อน
   - ตัด: เบอร์มือถือ (เก็บใน CRM), หัวข้อ "ความเห็นภายใน", ข้อมูลคู่แข่ง, ราคา/ต้นทุนที่ยังไม่ผ่านบัญชี, ⚠️ ที่ยังไม่ยืนยัน
   - น้ำเสียงและรูปแบบตาม `brand-guide` ("เรา"/"ท่าน", ไม่มีอีโมจิ, ประโยคแรก = ข้อสรุป)
6. **ตอบผู้ใช้สั้น ๆ**: สรุป 3 บรรทัด · action item ที่ครบกำหนดภายใน 3 วันทำการ · คำถามค้าง · จุดที่เติม `[...]` ไว้ · skill ถัดไปที่น่าจะใช้ (ลูกค้า → `follow-up-email`, ได้ขอบเขตงาน → `req-to-spec`, ขอราคา → `pricing-calc`)

## ห้าม

- ห้ามส่งไฟล์เอง — ร่างเท่านั้น เจ้าของประชุมเป็นคนส่ง
- ห้ามใส่ความเห็นส่วนตัวของผู้จด (เช่น "ลูกค้าดูไม่จริงจัง") ลงฉบับใด ๆ ถ้าไม่ได้อยู่ในโน้ต และห้ามมีในฉบับภายนอกเสมอ
