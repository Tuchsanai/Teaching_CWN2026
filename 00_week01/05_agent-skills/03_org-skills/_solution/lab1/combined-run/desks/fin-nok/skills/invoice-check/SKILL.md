# invoice-check — ตรวจใบแจ้งหนี้ก่อนส่งลูกค้า

ทำเรื่องเดียว: รับร่างใบแจ้งหนี้ 1 ใบ → บอกว่าส่งได้หรือยัง ผิดตรงไหน ที่ถูกคืออะไร
ไม่คิดราคา/ทำใบเสนอราคา (นั่นคือ `pricing-calc` ของ fin-joy) และไม่อนุมัติแทนหัวหน้า

ความรู้ที่ต้องใช้อยู่ใน `references/` (สรุปจาก company-kit ไม่ต้องเปิดไฟล์ต้นทาง):
- `references/invoicing-rules.md` — งวดมาตรฐาน สูตร ช่องที่ต้องมี ข้อมูลผู้ขาย/บัญชีรับเงินที่ถูกต้อง
- `references/data-rules.md` — ข้อมูลที่ห้ามอยู่ในใบแจ้งหนี้ + วิธีจัดการ

## ขั้นตอน

1. **อ่านร่าง** ดึง: เลขที่, วันที่ออก, วันครบกำหนด, เครดิตเทอม, มูลค่าสัญญาก่อน VAT, งวดที่/สัดส่วน, ยอดก่อน VAT, VAT, รวม, ตัวอักษร, หมายเหตุทั้งหมด
2. **คำนวณใหม่เอง ห้ามเชื่อตัวเลขในร่าง** (ระบบ auto-fill เคยสลับหลัก 51,800 → 51,080)
   ```
   python scripts/check_amounts.py <มูลค่าสัญญาก่อน VAT> <สัดส่วน %> <รวมทั้งสิ้นที่ใบเขียน>
   ```
   สคริปต์ให้ยอดงวด, VAT (ปัด 2 ตำแหน่ง), รวม, จำนวนเงินตัวอักษร และบอกว่ายอดในใบตรงหรือไม่
   ถ้าไม่มี python ให้คิดด้วยมือตามสูตรใน references แล้วเทียบทีละหลัก
   - ตัวอักษรต้องตรงกับ "รวมทั้งสิ้น" ที่ **ถูก** (ตัวอักษรที่ตรงกับยอดผิดก็ยังผิด)
   - ถ้ามีงวดอื่นในหมายเหตุ เช็กว่าผลรวมทุกงวด = มูลค่าสัญญาพอดี
3. **งวด/สัดส่วน/เอกสารแนบ** เทียบตารางงวดมาตรฐาน · ถ้าต่างให้มีเลขข้อสัญญาในหมายเหตุ · เอกสารแนบของงวดนั้นต้องมีจริง
4. **ช่องที่ต้องมีครบ 8 ช่อง** ตาม references · ข้อมูลผู้ขายและบัญชีรับเงินต้องตรงทุกตัวอักษร
5. **ข้อมูลต้องห้าม** ไล่ทุกบรรทัด โดยเฉพาะหมายเหตุและผู้ติดต่อ: เบอร์มือถือ, ชื่อ/ข้อมูลลูกค้าปลายทาง, เลขบัตร, เลขบัญชี/บัตรของบุคคล, รายละเอียดเคสภายใน → ในใบแจ้งหนี้ **ตัดทิ้ง** (ใช้รหัสเคสถ้าจำเป็นต้องอ้าง)
6. **เลขที่และวันที่** รูปแบบ `INV-<ปี>-<4 หลัก>` · วันครบกำหนด = วันที่ออก + เครดิตเทอม
7. **เขียนผล** (ปกติเก็บใน `work/`):
   - `<เลขที่>-review.md` — บรรทัดแรกบอกผลรวม ✅ ส่งได้ / ❌ ต้องแก้ · ตาราง ปัญหา | ระดับ | ที่ผิด | ที่ถูก · เช็กลิสต์ผู้ตรวจพร้อมหลักฐาน (ตัวเลขที่คำนวณ)
   - `<เลขที่>-corrected.md` — ฉบับแก้แล้ว เปลี่ยนเฉพาะจุดที่ผิด ใส่ชื่อผู้ตรวจ สถานะ "ตรวจแล้ว รออนุมัติ"
   - ห้ามคัดลอกข้อมูลต้องห้ามแบบเต็มลงไฟล์ผล ให้อ้างแบบปิดบัง (เช่น `086-XXX-1234`) หรืออธิบายว่า "ชื่อ + เบอร์มือถือลูกค้าปลายทาง"

## ระดับปัญหา
- 🔴 ต้องแก้ก่อนส่ง: ยอดผิด, ตัวอักษรไม่ตรง, งวด/สัดส่วนผิดสัญญา, ไม่มีเอกสารแนบ, มีข้อมูลต้องห้าม, ข้อมูลผู้ขาย/บัญชีรับเงินผิด
- 🟡 เติมให้ครบ: ช่องผู้ตรวจว่าง, ขาดเลขข้อสัญญาในหมายเหตุ
- ⚠️ ยืนยันนอกเอกสาร: เลขที่เรียงต่อจากใบล่าสุด (ดูทะเบียนในระบบบัญชี), ไฟล์แนบตัวจริง, ที่อยู่ผู้ซื้อตาม ภพ.20, เครดิตเทอมในสัญญา — ถ้าเช็กไม่ได้ให้เขียนว่า "ยืนยันไม่ได้" ห้ามเดาว่าผ่าน

## ส่งต่อ
- ผ่านแล้ว → ส่ง `fin-joy` (ผู้อนุมัติ) ไม่ส่งลูกค้าเอง
- เจอข้อมูลส่วนบุคคลในร่างที่ **ส่งออกไปแล้ว** → แจ้ง `plat-may` ภายใน 1 ชั่วโมง (ตาม `customer-data-policy`)
- ไม่แน่ใจว่าข้อมูลไหนใส่ได้ → ใช้ skill `customer-data-policy` หรือถาม plat-may
