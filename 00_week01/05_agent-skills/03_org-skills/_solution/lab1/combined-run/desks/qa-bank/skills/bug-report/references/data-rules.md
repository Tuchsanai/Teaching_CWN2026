# กติกาข้อมูลในรายงานบั๊ก (สรุปจาก company-kit/customer-data-policy.md v1.4 · ผู้ดูแล plat-may)

- ข้อมูลทดสอบต้องเป็นข้อมูลสังเคราะห์ (synthetic) เท่านั้น — ระบุในรายงานว่า user ทดสอบเป็นข้อมูลสังเคราะห์
- log และรายงานบั๊ก **ห้ามมี** เลขบัตรประชาชน / เบอร์มือถือ / เลขบัญชี / เลขบัตร / ชื่อ-นามสกุลของลูกค้าปลายทางจริง
- ถ้าจำเป็นต้องอ้างถึง ให้ปิดบัง:

| ข้อมูล | แบบปิดบัง |
|---|---|
| เบอร์มือถือ | `081-XXX-4567` |
| เลขบัตรประชาชน | `1-XXXX-XXXXX-XX-3` |
| เลขบัญชี | `XXX-X-X6789-X` |
| เลขบัตรเครดิต | `4111 XXXX XXXX 1234` |
| อีเมลส่วนตัว | `s*****@gmail.com` |
| ชื่อลูกค้าปลายทาง | ใช้รหัสเคส เช่น `CASE-2026-0815` |

- ไม่จำเป็นต้องอ้างถึง → ตัดทิ้งดีกว่าปิดบัง · screenshot ที่มีข้อมูลข้างต้นต้องเบลอก่อนแนบ
- เจอข้อมูลจริงใน log → ไม่ลอกลงรายงาน และแจ้ง DevOps ให้ปิดบังที่ระดับ logger
- สงสัยว่าข้อมูลรั่ว → แจ้ง `plat-may` ภายใน 1 ชั่วโมง (`#ask-pdpa`, dpo@novatech.example)
- ชื่อลูกค้าองค์กร (ธนาคาร) ใส่ในรายงานภายในได้
