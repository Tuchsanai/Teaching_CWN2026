# เขียนรายงานบั๊ก (bug-report)

ผลลัพธ์: ไฟล์ Markdown 1 ไฟล์ต่อ 1 บั๊ก ใน `work/` ชื่อ `BUG-<YYYY-MM-DD>-<อาการสั้น-kebab>.md`
แม่แบบและเกณฑ์อยู่ใน `references/` ของ skill นี้ (ไม่ต้องมี company-kit ก็ใช้ได้)

## ขั้นตอน

1. **อ่านแม่แบบ** `references/bug-template.md` และกติกาข้อมูล `references/data-rules.md` ก่อนเริ่ม
2. **อ่าน log ทั้งหมดที่ได้รับ** แล้วดึงข้อมูลลงช่องของแม่แบบ:
   - หัว log → repo · branch · commit · CI run · env/URL · browser/project · **TZ ของ runner**
   - test ที่ล้ม → ชื่อ test, ไฟล์:บรรทัด, ค่าที่ใช้ในโค้ด test (user, path, ค่าที่กรอก, ปุ่มที่กด) → แปลงเป็น "ขั้นตอนทำซ้ำ" ภาษาคน ใส่ค่าจริงทุกขั้น
   - `Expected` / `Received` → ผลที่คาด / ผลจริง (ลอกข้อความตรงตัว)
   - Network + server log + requestId + path ของ screenshot/trace/video → หลักฐาน (ลอกตรงตัว ห้ามแต่ง)
   - นับ project/รอบที่ล้ม → ความถี่ `x / y` · กรณีที่ผ่าน → "ไม่เกิดเมื่อ"
   - โน้ตทดสอบมือ → เงื่อนไขที่เกิด/ไม่เกิด, commit น่าสงสัย, deadline ลูกค้า
3. **ตั้งชื่อ** `[BUG] <สิ่งที่พัง> เมื่อ/บน <เงื่อนไข>` ไม่เกิน 80 ตัวอักษร (นับด้วยสคริปต์ถ้าไม่แน่ใจ)
4. **ให้ Severity/Priority** ตามตารางใน `references/bug-template.md` และเขียนเหตุผลสั้น ๆ ต่อท้าย
5. **ข้อสังเกตของ QA** = สิ่งที่ต่างระหว่างกรณีผ่าน/ไม่ผ่าน และสิ่งที่ตัวเลขไม่ตรงกัน เขียนเป็นข้อเท็จจริง ไม่ฟันธงสาเหตุ
   ถ้ามีข้อมูลที่ขัดกับสมมติฐานที่ดูชัด ให้เขียนไว้เป็น "จุดที่ยังอธิบายไม่ได้" ด้วย
6. **ตรวจก่อนส่ง** (checklist ด้านล่าง) แล้วบันทึกไฟล์

## Checklist ก่อนส่ง
- [ ] Dev ทำตามขั้นตอนได้โดยไม่ต้องถาม QA (มี URL, user ทดสอบ, สาขา, วันที่, เวลา, ค่าที่เลือกครบ)
- [ ] ผลที่คาด/ผลจริงลอกข้อความจริง ไม่ใช่สรุปเอง
- [ ] มี requestId, status code, path ของหลักฐาน
- [ ] ความถี่เป็นตัวเลข + เงื่อนไขที่เกิด/ไม่เกิด
- [ ] Severity/Priority มีเหตุผลตามเกณฑ์
- [ ] ไม่มีข้อมูลส่วนบุคคลจริง (ดู `references/data-rules.md`) — user ทดสอบระบุว่าเป็นข้อมูลสังเคราะห์
- [ ] ข้อมูลที่ไม่มีใน log (เช่น hash commit, จำนวนครั้งที่ลองมือ) เขียนว่า "ยังไม่มี" ห้ามเดา

## ห้าม
- ห้ามเดาสาเหตุเป็นข้อสรุป · ห้ามเติมตัวเลข/หลักฐานที่ไม่มีใน log
- ห้ามแก้ test ให้ผ่าน — งานนี้คือรายงาน ไม่ใช่แก้
