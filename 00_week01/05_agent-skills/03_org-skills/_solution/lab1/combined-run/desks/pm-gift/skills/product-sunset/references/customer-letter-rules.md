## PDPA

- ห้ามใส่แบบเต็มในเอกสารถึงลูกค้า: เลขบัตรประชาชน, **เบอร์มือถือส่วนตัว** (ทั้งลูกค้าปลายทางและพนักงานลูกค้า — ใช้เบอร์สำนักงาน/อีเมลบริษัท), เลขบัญชี/เลขบัตร, **ชื่อ-นามสกุลลูกค้าปลายทาง** (ใช้รหัสเคส)
- ถ้าไม่จำเป็นต้องอ้างถึง ให้ตัดทิ้งดีกว่าปิดบัง · ปิดบังแบบ `081-XXX-4567`
- **ข้อมูลอ่อนไหว (ม.26)**: ศาสนา สุขภาพ ประวัติอาชญากรรม ข้อมูลชีวภาพ — ห้ามเก็บถ้าไม่จำเป็น · ในงาน sunset: เสนอไม่ย้ายช่องที่มีข้อมูลอ่อนไหว, ส่งไฟล์ส่งออกผ่านช่องทางเข้ารหัส, การลบต้องครอบคลุม backup/log
- ชื่อผู้ติดต่อ/ที่อยู่ลูกค้าองค์กรดึงจาก CRM ตอนส่ง ไม่คัดลอกลงร่าง
- ข้อมูลรั่ว (ส่งผิดคน) → แจ้ง `plat-may` ภายใน 1 ชั่วโมง · ถาม PDPA: `#ask-pdpa` หรือ dpo@novatech.example

## น้ำเสียงและรูปแบบ (แบรนด์)

- ประโยคแรกของทุกหัวข้อ = ข้อสรุป (หัวข้อแรกของหนังสือบอกวันปิดและข้อเสนอทันที)
- ใช้ "เรา" แทนโนวาเทค, "ท่าน" หรือ "ธนาคาร" แทนลูกค้า · ไม่มีอีโมจิ · ไม่ใช้ภาษาวัยรุ่น
- ห้าม "ดีที่สุด", "อันดับหนึ่ง", "100%" — ใช้หลักฐานแทน
- คำเทคนิคเขียนอังกฤษได้ ครั้งแรกอธิบายไทยในวงเล็บ
- เงิน: มีคอมมา หน่วย "บาท" และระบุ "ไม่รวม VAT" หรือ "รวม VAT 7%"
- เลขที่เอกสาร `NVT-<ประเภท>-<ปี>-<ลำดับ>` · วันที่ พ.ศ./ค.ศ. ตามลูกค้า · หัวข้อมีเลข ไม่เกิน 3 ระดับ
- ท้ายกระดาษ "โนวาเทค · ข้อมูลลับเฉพาะลูกค้า" + เลขหน้า
- ชื่อบริษัท "โนวาเทค" / "Novatech" (ห้าม NovaTech, Nova Tech) · ห้าม TH Sarabun ยกเว้นหนังสือราชการที่ลูกค้าบังคับ

## Checklist ก่อนส่งมอบร่าง

- [ ] แผนผ่านตารางตรวจนโยบายครบ 6 ขั้น + ข้อห้าม 2 ข้อ
- [ ] วันประกาศ → วันปิด ≥ 180 วัน · เปิดส่งออก ≥ 90 วันก่อนปิด · ลบ ≤ 30 วันหลังปิด
- [ ] วันปิด ≥ วันหมด MA ของทุกรายที่ยังไม่ย้าย (หรือระบุว่าต้องได้หนังสือยินยอม)
- [ ] ระบุชัดว่าต้องให้ MD อนุมัติหรือไม่ และหนังสือติดป้าย "ร่าง ห้ามส่ง" จนกว่าจะอนุมัติ
- [ ] หนังสือส่งทุกรายวันเดียวกัน เนื้อหาหลักเหมือนกัน
- [ ] ไม่มีเบอร์มือถือ/ชื่อลูกค้าปลายทาง/ข้อมูลอ่อนไหวจริงในเอกสาร
- [ ] ไม่มีคำว่า "ลบแล้ว" · ไม่มีราคาที่แต่งขึ้น
- [ ] มีตาราง "เรื่องที่ต้องตัดสินใจ" ระบุผู้ตัดสิน
