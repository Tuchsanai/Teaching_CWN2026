# product-sunset

ทำแผนเลิกให้บริการ 1 เวอร์ชัน/ฟีเจอร์ + ร่างหนังสือประกาศ จากไฟล์รายชื่อลูกค้า (CSV) — เรื่องเดียว ไม่เขียน PRD ไม่ทำ checklist ปิดเครื่อง

## ข้อมูลเข้า

- CSV ลูกค้าที่ยังใช้เวอร์ชันเก่า คอลัมน์ขั้นต่ำ `customer,type,branches,ma_end_date,ma_baht_per_year` (เสริม: `active_branches_last_30d,queues_last_30d,interested_in_v2,note`) — ในโนวาเทคคือ `company-kit/product/novaqueue-v1-customers.csv`
- ถ้าไม่มี CSV ให้ถามผู้ใช้ ห้ามเดาจำนวนลูกค้าหรือวันหมด MA

## ขั้นตอน

1. **อ่านกติกา** `references/sunset-policy.md` (สรุปนโยบายบริษัท) และ `references/customer-letter-rules.md` (PDPA + น้ำเสียงหนังสือ) ถ้ามี `company-kit/product/product-lifecycle-policy.md` ในเครื่อง ให้เทียบเลขเวอร์ชันนโยบาย — ถ้าใหม่กว่า v2026.2 ใช้ไฟล์ต้นทางและแจ้งผู้ใช้ว่า references ต้องอัปเดต
2. **สรุปลูกค้าและวันสำคัญ** ด้วยสคริปต์ (Python stdlib)
   `python -I scripts/sunset_dates.py <customers.csv> --announce YYYY-MM-DD [--eol YYYY-MM-DD]`
   ได้: จำนวนราย/สาขา/คิว, MA รวม, ต้องให้ MD อนุมัติไหม, วันประกาศ/ส่งออก/ลบล่าสุด, รายที่ปิดก่อน MA หมด
   ถ้าผู้ใช้ถามแค่ "ลูกค้ายังใช้ v1 อยู่กี่ราย" ตอบจากขั้นนี้แล้วจบ
3. **เลือกวันปิด (เสนอ ไม่ตัดสินแทน)** ค่าเริ่มต้น = วันหมด MA ล่าสุด (ไม่ต้องขอหนังสือยินยอม) เสนอทางเลือกอื่นพร้อมผลที่ตามมา วันประกาศ = หลังวันที่คาดว่า MD อนุมัติ
4. **อ่านคอลัมน์ `type` และ `note` ทีละราย** หาเรื่องพิเศษ: ธนาคาร (DPA, MD อนุมัติ), ราชการ (จัดซื้อนาน), ข้อมูลอ่อนไหว (สุขภาพ ฯลฯ), ใช้งานลดลง, ติดต่อไม่ได้, MA หมดก่อนวันปิด
5. **เขียนแผน** ตาม `references/plan-and-letter-template.md` ส่วน A — ต้องมี: สรุป 3 บรรทัด, ตารางลูกค้า, ตารางตรวจนโยบายครบ 6 ขั้น + ข้อห้าม 2 ข้อ, ไทม์ไลน์, แผนรายลูกค้า, ผลกระทบรายได้, ความเสี่ยง, **ตารางเรื่องที่ต้องตัดสินใจ (ใคร ตัดสิน)**, ข้อมูลที่ยังขาด
6. **ร่างหนังสือประกาศ** ตามส่วน B — ฉบับเดียวส่งทุกราย + ภาคผนวกภายในว่าปรับอะไรรายลูกค้า ติดป้าย "ร่าง ห้ามส่งจนกว่า MD อนุมัติ" ถ้าต้องอนุมัติ
7. **ตรวจก่อนส่งมอบ** ด้วย checklist ท้าย `references/customer-letter-rules.md`
8. บันทึกไฟล์ใน `work/` ของผู้ใช้: `<product>-sunset-plan.md` และ `<product>-eol-announcement-draft.md` แล้วสรุปให้ผู้ใช้: วันที่เสนอ, ต้องอนุมัติโดยใคร, เรื่องที่ต้องตัดสินใจ

## ห้าม

- ห้ามเสนอวันปิดที่น้อยกว่า 180 วันจากวันประกาศ หรือก่อนวันหมด MA ของรายที่ยังไม่ย้าย โดยไม่เขียนว่าต้องได้หนังสือยินยอม
- ห้ามเขียนในหนังสือว่า "ลบข้อมูลแล้ว" — เขียนได้แค่ "จะลบภายใน..." (ยืนยันการลบได้หลัง DevOps ยืนยันครบ backup+log เท่านั้น)
- ห้ามใส่เบอร์มือถือ/ชื่อลูกค้าปลายทางในเอกสาร ห้ามคัดลอกข้อมูลสุขภาพหรือข้อมูลอ่อนไหวจาก note ลงหนังสือ (พูดถึงประเภทข้อมูลได้)
- ห้ามแต่งราคา v2 ที่ไม่มีในข้อมูล — เขียนเป็นข้อมูลที่ยังขาด

## ส่งต่อ

- ก่อนส่งหนังสือ: ใช้ `customer-data-policy` ตรวจ PDPA ถ้าติดตั้งไว้
- หลัง MD อนุมัติ: ส่งไทม์ไลน์ปิดระบบ/ลบข้อมูลให้ DevOps (`deploy-checklist`)
