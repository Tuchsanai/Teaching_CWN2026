## 1. เป้าหมายและตัวชี้วัดรับงาน

| รหัส | เป้าหมาย | วัดอย่างไร | ที่มา |
|---|---|---|---|
| G-1 | ลดเวลารอเฉลี่ยที่สาขา 30% ภายใน 6 เดือนหลังเปิดใช้ (ฐาน 38 นาที → ≤ 26.6 นาที) | เวลารอ = เวลาเรียกคิว − เวลามาถึง/เช็กอิน จากระบบสาขา เทียบฐานที่ตกลงร่วมกัน | [TOR 1, 2.1] · นิยามฐานเป็น [สมมติฐาน] Q-01 |
| G-2 | ลูกค้าจองผ่านเว็บและ LINE OA ได้ | FR-BK ทั้งหมดผ่าน UAT | [TOR 2.2] |
| G-3 | พยากรณ์ลูกค้าต่อสาขาต่อชั่วโมง ล่วงหน้า 7 วัน MAPE ≤ 20% | backtest 3 เดือนล่าสุด | [TOR 2.3, 3.3] |

> G-1 เป็นผลทางธุรกิจที่ขึ้นกับการจัดคนของสาขาด้วย — เสนอให้เป็น **KPI ติดตาม** ไม่ใช่เงื่อนไขรับมอบงาน (Q-01)

## 8. ความเสี่ยงและข้อสังเกตจาก TOR

1. **ลูกค้าใหม่ไม่มี CIF** แต่ TOR ให้ยืนยันตัวตนผ่าน core banking เท่านั้น ขณะที่บริการ "เปิดบัญชี" มักเป็นคนที่ยังไม่เป็นลูกค้า → ขัดกันในตัว (Q-02)
2. **MAPE ≤ 20% "ภาพรวม"** ถ้าวัดรายสาขา-รายชั่วโมง สาขาเล็ก/ชั่วโมงที่คนน้อยทำให้ MAPE พุ่ง; ต้นแบบภายในของเรา (ข้อมูลโครงการก่อนหน้า — ห้ามระบุชื่อลูกค้าในเอกสารที่ส่งออก) ได้ 15–20% แบบเฉียด และพยากรณ์ต่ำช่วงเที่ยง −20 ถึง −30% ในสาขาย่านออฟฟิศ → ต้องล็อกนิยามก่อนยื่นราคา
3. **ข้อมูลย้อนหลังได้หลังเซ็นสัญญา** — ไม่มีทางยืนยัน MAPE ล่วงหน้า; ควรเขียนเงื่อนไขว่า MAPE ผูกกับคุณภาพข้อมูลที่ได้รับ
4. G-1 (ลดเวลารอ 30%) ขึ้นกับการจัดคนของธนาคาร ไม่ใช่ระบบอย่างเดียว
5. งบ 4.8M รวม hosting ปีแรก + MA ปีแรก + (อาจ) pen test — ส่งให้ `pricing-calc` ตรวจ margin
6. นำร่องเดือน 5 / ครบเดือน 6 ตึงมาก ถ้า pen test ไม่ผ่านรอบแรก
