# โครงแผนทดสอบ (คัดลอกแล้วเติม)

ตาราง test case ต้องมีคอลัมน์ **รหัส** และ **ผลที่คาดหวัง** (ชื่อคอลัมน์ตามนี้) และรหัสรูปแบบ `XX-NN` เพื่อให้ QA ใช้ `test-from-plan` อ่านได้ตรง ๆ
ห้ามใส่ URL ตัวอย่าง — `test-from-plan` หยิบ URL แรกในแผนเป็นเว็บที่ทดสอบ ใส่ `_รอกำหนด_` จนกว่าจะมี env `uat`

```markdown
# แผนทดสอบ: <ชื่อโครงการ> (<deal-id>)

> คู่กับ <deal>-spec.md v0.1 · จัดทำ <user> <วันที่>
> URL ระบบ UAT: _รอกำหนด_ · health: `/healthz` · readiness: `/readyz`

## 1. ขอบเขตและระดับการทดสอบ
| ระดับ | ใครทำ | ครอบคลุม | เครื่องมือ/สภาพแวดล้อม |
(Unit, Integration, E2E, Performance, Security/pen test, ML backtest ถ้ามี, UAT, Pilot)

## 2. ข้อมูลทดสอบ
synthetic เท่านั้น · test account ที่ต้องขอจากลูกค้า · กรณีขอบ (ไม่พบ, timeout, error)

## 3. Test Cases  (หัวข้อย่อยตามโมดูล)
| ลำดับ | รหัส | โมดูล | สิ่งที่ทดสอบ | ระดับ | ผลที่คาดหวัง | spec |
ระดับ: P1 = Must ที่กระทบเงิน/ข้อมูลลูกค้า/ความปลอดภัย/ข้อสัญญา · P2 = Must อื่น + Should · P3 = Could

## 4. เกณฑ์เริ่มทดสอบ (entry)
env พร้อม, test account ครบ, คำถาม Q-NN ที่กระทบผลที่คาดหวังของ P1 ได้คำตอบแล้ว

## 5. เกณฑ์ผ่าน (exit)
- P1 ผ่านทั้งหมด
- อัตราผ่านรวม ≥ 95%
- ไม่มีบั๊ก Sev 1 / Sev 2 ค้าง
- (เกณฑ์เฉพาะโครงการ เช่น pen test, MAPE)

## 6. ลำดับเวลา (ผูกกับแผนส่งมอบใน spec)
```

ตรวจก่อนส่ง: requirement Must ทุกข้อใน spec ต้องปรากฏในคอลัมน์ `spec` อย่างน้อย 1 ครั้ง
