# หัวข้อที่ลูกค้ามักไม่เขียนใน TOR แต่จะถามทีหลัง

ไล่ทุกข้อ ข้อที่ TOR ไม่พูดถึง → ใส่สมมติฐาน + คำถาม `Q-NN` (ข้อที่มี ★ = กระทบราคาหรือเกณฑ์รับงาน ต้องถามก่อนยื่นราคา)

## ผู้ใช้และตัวตน
- ★ ผู้ใช้กลุ่มที่ไม่เข้าเงื่อนไขการยืนยันตัวตนที่ TOR บังคับ (เช่น คนที่ยังไม่เป็นลูกค้า แต่มาใช้บริการ "เปิดบัญชี")
- OTP: ช่องทาง, ใครจัดหา/จ่ายค่า SMS, อายุ OTP, ลองผิดกี่ครั้ง, rate limit
- โครงสร้างสิทธิ์ (สาขา/ภาค/สำนักงานใหญ่/admin) และกลุ่มใน SSO
- ใครดูแลข้อมูลหลัก (สาขา เวลาทำการ วันหยุด ประเภทบริการ)

## กติกาธุรกิจ
- ★ นิยามตัวชี้วัดใน TOR (เวลารอวัดจากไหนถึงไหน, no-show คืออะไร, ฐานเปรียบเทียบ)
- จำกัดต่อคน, จองล่วงหน้าได้กี่วัน, ปิดจองก่อนกี่นาที, ช่วงผ่อนผันมาสาย
- ลำดับความสำคัญระหว่างช่องทาง (จองล่วงหน้า vs walk-in)
- ลดความจุหลังมีคนจองแล้วทำอย่างไร
- ★ เป้าหมายธุรกิจที่ขึ้นกับลูกค้าด้วย (เช่น ลดเวลารอ %) → KPI ติดตาม หรือเงื่อนไขรับงาน?

## ระบบภายนอก
- ★ เอกสาร API, เวอร์ชัน, sandbox/เครื่องทดสอบ, test account ของทุกระบบที่ต้องต่อ (ระบบเก่ามักไม่มี)
- ใครเป็นเจ้าของ channel (LINE OA, SMS sender) และจ่ายค่าข้อความ
- ใบรับรอง mTLS: ใครออก, อายุ, ขั้นตอนต่ออายุ
- ระบบภายนอกล่ม → ระบบเราต้องทำอะไร (fallback, โหมดออฟไลน์ที่หน้างาน)

## ML / ข้อมูล
- ★ เกณฑ์ความแม่นยำวัดระดับไหน (รวม/รายหน่วย/รายชั่วโมง), ช่วงข้อมูลทดสอบ, ค่าศูนย์ (MAPE หารศูนย์)
- ★ ข้อมูลฝึกได้เมื่อไร รูปแบบไหน คุณภาพไม่พอแล้วเกณฑ์ยังผูกไหม
- เกณฑ์ถอยกลับรุ่นโมเดล, shadow mode ก่อนใช้จริง, หน่วยใหม่ที่ไม่มีประวัติ

## Non-functional
- ★ ปริมาณผู้ใช้ peak, จำนวนธุรกรรมต่อวัน
- ★ RPO/RTO, DR site
- ★ SLA support: 24×7 หรือเวลาทำการ, นิยาม Sev 1–4
- ภาษา (อังกฤษ?), accessibility, อุปกรณ์/เบราว์เซอร์ที่รองรับ
- Retention ข้อมูลธุรกรรม และสิทธิ์ลบตาม PDPA, ข้อความ consent ใครร่าง
- ไฟล์ส่งออก (Excel) มีข้อมูลส่วนบุคคลได้ไหม

## สัญญาและการส่งมอบ
- ★ ค่า pen test / audit ภายนอก และรอบ retest ใครจ่าย, จองคิวผู้ทดสอบเมื่อไร
- ★ งบรวม hosting / MA / license อะไรบ้าง (ส่ง `pricing-calc`)
- นำร่อง → ขยายเต็ม: เวลาพอไหม, ใครอบรม/ติดตั้งหน้างาน
- อะไรอยู่นอกขอบเขต (เขียนให้ชัดในข้อเสนอ)
