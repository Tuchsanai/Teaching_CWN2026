# เกณฑ์ตัดสินดีล (สรุปจาก company-kit ของโนวาเทค ณ พ.ย. 2026)

> ที่มา: สรุปดีล `deal-summaries/DS-*.md`, `monthly-kpi.csv`, `product/product-lifecycle-policy.md`
> ถ้าบริษัทออกเกณฑ์ใหม่ (เช่น `margin-rules.md` ฉบับใหม่) ให้ใช้ฉบับใหม่และแก้ไฟล์นี้

## 1. เกณฑ์ตัวเลขที่ต้องเช็กทุกดีล

| มุม | ผ่าน (ปกติ) | ธงเหลือง | ธงแดง / ต้อง MD |
|---|---|---|---|
| Gross margin (ราคาขายไม่รวม VAT) | ≥ 30% (เป้าบริษัท) | 25–30% | **< 25% → ต้อง MD อนุมัติ** |
| ส่วนลดพิเศษ (% ของค่าพัฒนา) | ≤ 10% หัวหน้าทีมขายอนุมัติได้ | – | **> 10% → MD เท่านั้น** |
| Buffer ใน man-day | มี 10% | < 10% | ไม่มี buffer |
| ระยะเวลาเทียบงานลักษณะเดียวกัน | ตามปกติ | สั้นกว่า ≤ 20% | สั้นกว่ามาก (เช่น 3 เดือน vs ปกติ 5–6) |
| UAT | ≥ 3 สัปดาห์ | 2 สัปดาห์ | < 2 สัปดาห์ |
| QA man-day | ตามประมาณการ SA | – | ถูกตัด "เพื่อให้ราคาลง" |
| ค่าปรับล่าช้า | มีเพดาน ≤ 5% ของมูลค่าสัญญา | เพดานสูงกว่า 5% | **ไม่มีเพดาน** |
| งวดจ่าย | ใกล้ 30 / 40 / 30 (เซ็น / UAT / go-live) เครดิต 30 วัน | งวดสุดท้าย > 40% | ก้อนใหญ่หลัง go-live หลายเดือน / เครดิต 90 วัน |
| การเชื่อมต่อระบบภายนอก | มีเอกสาร API แล้ว | มีแต่ข้อจำกัด (rate limit ฯลฯ) มีทางแก้ | **ยังไม่เห็น API** |
| ข้อมูลส่วนบุคคล | ไม่มี / ใช้รหัสแทน | ข้อมูลส่วนบุคคลทั่วไป + DPA | ข้อมูลอ่อนไหว (สุขภาพ PDPA ม.26, บัตร PCI DSS) แต่ยังไม่มี DPA / แผน PCI |
| กำลังคน | ทีมว่างช่วงนั้น | ต้องรับคนเพิ่มที่เปิดรับอยู่แล้ว | tech lead ถือ ≥ 3 โปรเจกต์พร้อมกัน / ตำแหน่งสำคัญยังว่าง |

TOR ที่ยังไม่คิดราคา: วงเงินใน TOR มักรวม **ค่าพัฒนา + hosting ปีแรก + MA ปีแรก** → ถือเป็นเพดาน ต้องให้บัญชีคิดราคาว่า GM ≥ 25% ได้ใต้เพดานนี้หรือไม่ก่อนเร่ง

## 2. ตาราง 4 ทาง

| คำตัดสิน | ใช้เมื่อ | ต้องเขียน |
|---|---|---|
| 🟢 **เร่ง** | ตัวเลขผ่าน ความเสี่ยงมีทางแก้ กำหนดใกล้ หรือเข้ากับผลิตภัณฑ์/กลยุทธ์ชัด | อะไรขวางอยู่ + ปิดภายในวันไหน |
| ➡️ **ส่งต่อ** | ตัดสินเองไม่ได้ ต้องให้คนอื่นทำก่อน (คิดราคา, spec, roadmap, อนุมัติ MD, คน) | ส่งใคร (user) ด้วย skill อะไร ต้องได้อะไรกลับ ภายในวันไหน |
| 🟡 **ประคอง** | ยังไม่รู้ว่าคุ้มไหม มีเวลาอยู่ ไม่อยากทิ้งแต่ยังไม่ลงแรงเต็ม | ข้อมูลที่ต้องได้ + **วันตัดสิน bid / no-bid** + เงื่อนไขที่จะปล่อย |
| 🔴 **ตีกลับ** | ร่างมีธงแดง ≥ 2 ข้อ หรือธงแดงที่แก้ไม่ได้ด้วยการอนุมัติ (ไม่มีเพดานค่าปรับ, ไม่มี DPA กับข้อมูลอ่อนไหว, timeline เป็นไปไม่ได้) | ธงแดงทุกข้อเป็นตัวเลข + **ร่างใหม่ต้องเปลี่ยนอะไร** (เช่น แบ่งเฟส, ใช้ผลิตภัณฑ์ที่มี, คืน QA/buffer, ใส่เพดานค่าปรับ) |

เร่ง + ส่งต่อ ใช้คู่กันได้ (เช่น ดีลดีแต่ต้องให้ SA/บัญชีทำของก่อนยื่น)

## 3. ข้อสังเกตที่ทำให้ตัดสินเปลี่ยน

- เดือนที่ **GM บริษัทต่ำกว่าเป้า** → ยิ่งต้องเข้มกับดีล GM < 25% แม้เซลส์อ้าง "ได้ลูกค้าต่อ" ให้ขอเป็นตัวเลข
- เดือนที่ **win rate ต่ำเพราะแพ้ราคา** → อย่าแก้ด้วยส่วนลด ให้หาทางลดขอบเขต / ใช้ผลิตภัณฑ์ที่มี
- **ลูกค้าเดิม** (มี MA อยู่) + ทีมเดิมรู้ระบบ = ความเสี่ยงต่ำกว่า
- ดีลที่ **ขอฟีเจอร์ตรงกับ feedback ลูกค้าผลิตภัณฑ์** = ชนะสองทาง → ดึง Product เข้ามาเร็ว
- ดีลหลายตัว **เริ่มเดือนเดียวกัน** → เช็ก tech lead / SA / ตำแหน่งว่าง ก่อนเร่งทุกตัว
