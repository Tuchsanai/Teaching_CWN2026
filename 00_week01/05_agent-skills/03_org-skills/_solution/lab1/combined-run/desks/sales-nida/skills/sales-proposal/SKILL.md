# sales-proposal

แปลง TOR ของลูกค้าเป็น **proposal ฉบับลูกค้า + ใบคิดราคาภายใน** ในสไตล์ที่ชนะดีลธนาคารมาแล้ว
ธนาคารให้น้ำหนักกับ **ความปลอดภัย** และ **SLA** มากที่สุด — ทุกฉบับต้องตอบสองเรื่องนี้ให้ชัด

## ข้อมูลที่ใช้

| ต้องมี | ที่มา |
|---|---|
| TOR ของลูกค้า | ผู้ใช้ให้มา (ไฟล์หรือข้อความ) |
| ราคา + ต้นทุน, กฎ margin/ส่วนลด/VAT | `references/pricing-rules.md` (สำเนาย่อจาก company-kit) |
| โครง proposal, แบรนด์, น้ำเสียง | `references/proposal-structure.md` |
| สิ่งที่ธนาคารตรวจ + ข้อห้ามข้อมูลส่วนบุคคล | `references/bank-checklist.md` |

ถ้าเครื่องนี้มี `company-kit/price-list.csv`, `margin-rules.md`, `brand-guide.md`, `customer-data-policy.md`, `won-proposals/` ให้ **ใช้ไฟล์ต้นฉบับก่อน** และถ้าเวอร์ชันไม่ตรงกับ references ให้แจ้งผู้ใช้

## ขั้นตอน

1. **อ่าน TOR แล้วดึง:** ลูกค้า, เลขที่ TOR, กำหนดยื่น, วัตถุประสงค์ (ตัวเลขเป้า), ขอบเขตแต่ละข้อ, ความปลอดภัย, ระยะเวลา/นำร่อง, SLA/MA, **วงเงิน (รวม/ไม่รวม VAT และรวมอะไรบ้าง)**, เอกสารที่ต้องยื่น, ผู้ประสานงาน
2. **ทำตารางเทียบ TOR** ทุกข้อ → วิธีที่เราตอบ → หัวข้อในข้อเสนอ ห้ามมีข้อที่ไม่มีคำตอบ
3. **ประเมิน man-day** ต่อบทบาทจากขอบเขต เทียบ benchmark ใน `references/pricing-rules.md` ข้อ 4 แล้ว **บวก buffer 10% ไว้ในจำนวนวัน** (ปัดขึ้น ไม่แสดงบรรทัด buffer ให้ลูกค้า) เพิ่ม hosting / license / MA ตามที่ TOR บังคับ
4. **คิดราคา** — ถ้ามี skill `pricing-calc` ให้ใช้ ถ้าไม่มีให้คิดตามสูตรใน `references/pricing-rules.md` ด้วยสคริปต์หรือคำนวณซ้ำ 2 รอบ แล้วตรวจ:
   - ราคาขาย ≤ วงเงิน TOR (เทียบฐานเดียวกัน ไม่รวม VAT)
   - margin หลังส่วนลด: ≥ 25% ผ่าน · 15–<25% ต้องส่ง MD (`deal-approval`) · < 15% ห้ามส่ง
   - ห้ามลด MA/hosting, ส่วนลดเป็นบรรทัดแยก, ระดับผู้อนุมัติส่วนลดถูกต้อง
   - ถ้าเกินงบ: ทำฉากทางเลือก (ตัดขอบเขต / ลด man-day / option แยก) อย่าแอบลดราคาต่อหน่วย
5. **เขียน proposal ฉบับลูกค้า** ตามโครง 9 หัวข้อใน `references/proposal-structure.md` ราคาแสดง 3 บรรทัด `รวมก่อน VAT → VAT 7% → รวมทั้งสิ้น` **ไม่มีต้นทุนหรือ margin**
6. **เขียนใบคิดราคาภายใน** แยกไฟล์: man-day ฐาน/+10%/เสนอ, ราคา, ต้นทุน, margin, ผู้อนุมัติ, ฉากทางเลือก, จุดที่ต้องตัดสินใจ, skill ถัดไป
7. **ตรวจก่อนส่ง** ด้วย checklist ใน `references/bank-checklist.md` (PDPA, น้ำเสียง, แบรนด์, ครบ TOR)

## ผลลัพธ์

เก็บใน `work/` ของโต๊ะผู้ใช้ (หรือที่ผู้ใช้กำหนด)
- `<deal>-proposal-<ลูกค้า>.md` — ฉบับลูกค้า สถานะ "ร่าง"
- `<deal>-pricing-internal.md` — ภายในเท่านั้น หัวไฟล์เขียนว่า "ห้ามส่งลูกค้า"

ตอบผู้ใช้สั้น ๆ: ราคารวม, margin, อยู่ในงบไหม, ใครอนุมัติ, และ **รายการจุดที่ต้องตัดสินใจเอง**

## ห้าม

- ห้ามแต่งราคาที่ไม่อยู่ใน price list (ของนอกตาราง = ต้นทุนจริง + ≥ 20% พร้อมหมายเหตุ)
- ห้ามใส่เบอร์มือถือ / เลขบัตร / ชื่อลูกค้าปลายทางในฉบับลูกค้า แม้ TOR จะให้มา
- ห้ามคำโอ้อวด ("ดีที่สุด", "อันดับหนึ่ง", "100%") — ใช้ตัวเลขหลักฐานแทน
- ห้ามสัญญาสิ่งที่ MA ที่เลือกไม่ครอบคลุม (เช่น ตอบรับ 24x7 กับ MA 8x5)

## ส่งต่อ

- margin 15–<25% หรือส่วนลด > 10% → `deal-approval` (MD)
- ยื่นแล้ว → `follow-up-email` ติดตามลูกค้า
