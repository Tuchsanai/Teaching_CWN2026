## 1. ปัญหาของลูกค้า และหลักฐาน

ลูกค้าปลายทาง **ไม่รู้ว่าใกล้ถึงคิวเมื่อไร** จึงต้องมานั่งรอที่สาขา หรือไม่มาเลยโดยไม่ยกเลิก ส่วนช่องทางเตือนที่มีอยู่ (SMS) ถูกมองว่าเป็นสแปมและเปิดลิงก์ไม่ได้บนมือถือรุ่นเก่า

| หลักฐาน | ค่า |
|---|---|
| F-01 "อยากให้เตือนก่อนถึงคิว จะได้ไม่ต้องนั่งรอหน้าสาขา" | 412 ครั้ง |
| F-03 "ขอเตือนผ่าน LINE ได้ไหม SMS ชอบโดนมองว่าเป็นสแปม" | 288 ครั้ง |
| F-06 "อยากเห็นว่าตอนนี้เรียกถึงคิวไหนแล้ว" | 201 ครั้ง |
| F-08 ลิงก์ใน SMS เตือนเปิดไม่ได้บนมือถือรุ่นเก่า | 64 ครั้ง |
| F-02 ผู้จัดการสาขา: คนไม่มาตามนัดเยอะ ช่วงบ่ายสาขาว่างแต่คิวเต็มในระบบ | 37 ครั้ง |
| F-11 ฝ่ายขาย: ลูกค้าธนาคาร 2 รายจะเพิ่ม **60 สาขา** ถ้ามีเตือนผ่าน LINE | 2 ราย |
| no-show (ก.ค. → ก.ย.) | 13.2% → **14.6%** (~34,800 คิว ในเดือน ก.ย.) |
| ลูกค้ามาแล้วรอเกิน 20 นาที | 9% → **12%** |
| ยกเลิกเองในแอป (% ของคิวที่ไม่มา) | 21% → **19%** (คนไม่มาโดยไม่บอกเพิ่มขึ้น) |
| ค่า SMS ยืนยันนัด (฿0.35/ข้อความ) | **฿83,335** ในเดือน ก.ย. · รวม Q3 ฿241,640 |

## 3. ขอบเขต

### ทำในรอบนี้
1. ลูกค้าปลายทางผูกการจองกับ LINE ได้ (ตอนจอง หรือจากลิงก์ในข้อความยืนยัน) พร้อมขอความยินยอมรับข้อความ
2. ข้อความ **ยืนยันนัด** ส่งทาง LINE ถ้าผูกแล้ว · ไม่ผูกให้ส่ง SMS เหมือนเดิม (ไม่ส่งซ้ำทั้ง 2 ช่องทาง)
3. ข้อความ **เตือนล่วงหน้า 1 วัน** มีปุ่ม "ยืนยันว่าจะไป" และ "ยกเลิกคิว"
4. ข้อความ **ใกล้ถึงคิว** เมื่อเหลือคิวก่อนหน้า N คิว (สาขาตั้งค่า N ได้ ค่าเริ่มต้น 5)
5. **หน้าสถานะคิวสด**: คิวที่กำลังเรียก, จำนวนคิวก่อนหน้า, เวลารอโดยประมาณ — เป็นหน้าเว็บเบา เปิดได้บนเบราว์เซอร์มือถือรุ่นเก่า (แก้ F-08) และเปิดจาก LINE ได้
6. แก้ลิงก์ใน SMS ให้ชี้ไปหน้าสถานะคิวเดียวกัน
7. แอดมินลูกค้าองค์กรตั้งค่าบัญชี LINE OA ของตัวเอง (channel) และเปิด/ปิดช่องทางรายสาขาได้
8. รายงานในหลังบ้าน: จำนวนข้อความต่อช่องทาง, no-show, % ยกเลิกล่วงหน้า แยกรายสาขา
9. ข้อความทุกแบบมีภาษาไทยและอังกฤษ

### ไม่ทำในรอบนี้
- เลื่อนนัดเองในแอป (F-04) → PRD ฉบับถัดไป (ปุ่ม "ยกเลิก" ในรอบนี้จะเปลี่ยนเป็น "เลื่อนนัด" ภายหลัง)
- จองคิวผ่าน LINE (LIFF) เต็มรูปแบบ — รอบนี้แค่รับข้อความและดูสถานะ
- VIP ข้ามคิว (F-09) — ไม่รับ ส่ง MD ตัดสิน
- log การเข้าถึงข้อมูลเก็บในไทย 1 ปี (F-05) — แยกให้ Tech ประเมิน
- รายงาน Excel (F-07), จองแทนพ่อแม่ (F-12)
- NovaQueue v1 ทุกกรณี

## 4. User story และเกณฑ์ตรวจรับ

**US-1 ผูก LINE** — ในฐานะลูกค้าปลายทาง ฉันอยากรับการแจ้งเตือนทาง LINE แทน SMS เพื่อไม่พลาดข้อความ
- AC-1.1 Given ลูกค้าจองคิวสำเร็จที่สาขาที่เปิด LINE · When กด "รับแจ้งเตือนทาง LINE" และกดยินยอม · Then การจองนั้นถูกผูกกับ LINE และได้ข้อความยืนยันทาง LINE ภายใน 60 วินาที
- AC-1.2 Given ลูกค้าไม่กดยินยอม · Then ไม่บันทึก LINE user ID และใช้ SMS ตามเดิม
- AC-1.3 Given การจองผูก LINE แล้ว · Then ไม่ส่ง SMS ยืนยันนัดของการจองนั้น (ตรวจจาก log การส่ง: 1 การจอง = 1 ข้อความยืนยัน)
- AC-1.4 Given สาขาปิดช่องทาง LINE · Then ไม่แสดงตัวเลือกผูก LINE

**US-2 เตือนล่วงหน้า 1 วัน** — ในฐานะลูกค้าปลายทาง ฉันอยากได้เตือนก่อนวันนัดพร้อมปุ่มยกเลิก เพื่อคืนคิวถ้าไปไม่ได้
- AC-2.1 Given นัดวันพรุ่งนี้ · When ถึงเวลา 18:00 ของวันก่อนนัด (ตั้งค่าได้รายสาขา) · Then ส่งข้อความเตือน 1 ครั้งต่อการจอง ผ่านช่องทางที่ผูกไว้
- AC-2.2 When กด "ยกเลิกคิว" · Then สถานะการจองเป็น "ยกเลิกโดยลูกค้า" และ slot ว่างให้คนอื่นจองได้ภายใน 1 นาที
- AC-2.3 When กด "ยืนยันว่าจะไป" · Then บันทึกสถานะ "ยืนยันแล้ว" ให้สาขาเห็นในหลังบ้าน
- AC-2.4 Given การจองถูกยกเลิกไปแล้ว · Then ไม่ส่งข้อความเตือน

**US-3 เตือนใกล้ถึงคิว** — ในฐานะลูกค้าปลายทาง ฉันอยากได้เตือนเมื่อใกล้ถึงคิว เพื่อไม่ต้องนั่งรอหน้าสาขา
- AC-3.1 Given สาขาตั้ง N = 5 · When คิวก่อนหน้าลูกค้าเหลือ 5 คิว · Then ส่งข้อความ "ใกล้ถึงคิว" 1 ครั้ง พร้อมลิงก์หน้าสถานะคิว
- AC-3.2 Given คิวก่อนหน้าน้อยกว่า N ตั้งแต่ตอนเช็กอิน · Then ส่งข้อความทันทีหลังเช็กอิน 1 ครั้ง
- AC-3.3 ข้อความใกล้ถึงคิวต้องถึงผู้รับภายใน 60 วินาทีหลังเงื่อนไขเป็นจริง (p95)
- AC-3.4 Given ส่งทาง LINE ล้มเหลวครบ 5 ครั้ง (retry แบบ exponential backoff) · Then ส่ง SMS แทน 1 ครั้ง และบันทึกเหตุใน log

**US-4 หน้าสถานะคิวสด** — ในฐานะลูกค้าปลายทาง ฉันอยากเห็นว่าเรียกถึงคิวไหนแล้ว เพื่อกะเวลาเดินทาง
- AC-4.1 หน้าแสดง: หมายเลขคิวที่กำลังเรียก, จำนวนคิวก่อนหน้าฉัน, เวลารอโดยประมาณ (นาที) และอัปเดตอย่างน้อยทุก 30 วินาที
- AC-4.2 หน้าทำงานได้โดยไม่ต้องเปิด JavaScript ขั้นสูง (เปิดได้บน Android 8 / iOS 12 ด้วยเบราว์เซอร์เริ่มต้น) และขนาดหน้าแรก ≤ 100 KB
- AC-4.3 ลิงก์เป็น token สุ่มต่อการจอง หมดอายุสิ้นวันนัด และหน้าไม่แสดงชื่อหรือเบอร์โทรของลูกค้า
- AC-4.4 เปิดลิงก์เดียวกันได้ทั้งจาก SMS และ LINE

**US-5 ตั้งค่าโดยลูกค้าองค์กร** — ในฐานะแอดมินของลูกค้าองค์กร ฉันอยากใช้ LINE OA ของธนาคารเอง เพื่อให้ลูกค้าเชื่อถือข้อความ
- AC-5.1 แอดมินกรอก channel ID / secret / access token ของ LINE OA ได้ ระบบทดสอบการเชื่อมต่อและแจ้งผลสำเร็จ/ล้มเหลว
- AC-5.2 ค่า secret และ token ถูกเข้ารหัสเมื่อเก็บ และไม่แสดงกลับบนหน้าจอหลังบันทึก
- AC-5.3 เปิด/ปิด LINE และตั้งค่า N และเวลาเตือนล่วงหน้า แยกรายสาขาได้

**US-6 รายงาน** — ในฐานะผู้จัดการสาขา ฉันอยากเห็นผลของการเตือน เพื่อรู้ว่า no-show ลดลงจริง
- AC-6.1 หลังบ้านแสดงรายวัน/รายสัปดาห์ แยกสาขา: ข้อความที่ส่ง (LINE/SMS), ส่งล้มเหลว, no-show %, % ยกเลิกล่วงหน้า, % รอเกิน 20 นาที
- AC-6.2 ตัวเลขข้อความที่ส่งในรายงานตรงกับจำนวนใน log การส่งข้อความของช่วงเวลาเดียวกันทุกตัว

**ข้อกำหนดที่ไม่ใช่ฟังก์ชัน**
- งานส่งข้อความทั้งหมดผ่านคิว (BullMQ บน Redis) · job idempotent · retry exponential backoff สูงสุด 5 ครั้ง · ล้มครบไป dead-letter queue + แจ้งเตือน (ตาม `arch-standards.md`)
- ข้อมูลทั้งหมดอยู่ใน cloud ภูมิภาคไทย · LINE user ID ถือเป็นข้อมูลส่วนบุคคล เก็บพร้อมหลักฐานความยินยอม และลบเมื่อลูกค้าถอนความยินยอม
- ข้อมูลทดสอบเป็นข้อมูลสังเคราะห์เท่านั้น

## 5. ผลกระทบต่อเวอร์ชันอื่น

- **NovaQueue v1 (on-prem): ไม่ทำ** — v1 อยู่ในขั้น "ดูแลอย่างเดียว" ไม่เพิ่มฟีเจอร์
- ลูกค้า v1 ที่อยากได้ฟีเจอร์นี้ต้องย้ายไป v2 → ใช้เป็นเหตุผลประกอบแผนย้ายเวอร์ชันของ `pm-gift` (`product-sunset`) โดยเฉพาะ ออมทรัพย์เกษตรไทย (สนใจ v2 และขอทดสอบ 5 สาขา)
- Sales: ห้ามสัญญาฟีเจอร์นี้กับลูกค้า v1 และห้ามสัญญาวัน GA จนกว่า MD อนุมัติ GA
