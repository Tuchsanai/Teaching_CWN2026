## 1. PRD ทุกฉบับต้องมี 5 อย่าง

1. **ปัญหาของลูกค้า พร้อมหลักฐาน** (ตัวเลข หรือจำนวนครั้งที่ถูกพูดถึง) — ห้ามมีข้อมูลส่วนบุคคลของลูกค้าปลายทาง
2. **ตัวชี้วัดความสำเร็จที่วัดได้** และ **ค่าปัจจุบันก่อนทำ**
3. **ขอบเขต**: ทำ / ไม่ทำในรอบนี้
4. **user story + เกณฑ์ตรวจรับ (acceptance criteria)** ที่ QA เขียน test ได้
5. **ผลกระทบต่อเวอร์ชันอื่น** (ฟีเจอร์ใหม่ทำบน v2 เท่านั้น)

## 2. ข้อมูลส่วนบุคคลใน PRD

- ข้อมูลส่วนบุคคล: ชื่อ-นามสกุล, เลขบัตรประชาชน, เบอร์มือถือ, อีเมลส่วนตัว, ที่อยู่, เลขบัญชี/บัตร, CIF, IP, GPS, ประวัติธุรกรรม, ใบหน้า
- ข้อมูลอ่อนไหว (สุขภาพ ศาสนา ประวัติอาชญากรรม ชีวภาพ) — ห้ามเก็บถ้าไม่จำเป็นจริง
- **ใน PRD: อ้าง ticket ด้วยรหัส (F-xx, CASE-xxxx) แทนชื่อลูกค้าปลายทาง · ไม่ต้องอ้างเบอร์เลย ตัดทิ้งดีกว่าปิดบัง**
- ถ้าจำเป็นต้องแสดงจริง ใช้รูปแบบปิดบัง: เบอร์ `081-XXX-4567` · บัตรประชาชน `1-XXXX-XXXXX-XX-3` · บัญชี `XXX-X-X6789-X` · บัตรเครดิต `4111 XXXX XXXX 1234` · อีเมล `s*****@gmail.com`
- ฟีเจอร์ที่เก็บตัวระบุใหม่ (เช่น LINE user ID) ต้องมีข้อกำหนด: ขอความยินยอม, เก็บในไทย, ลบเมื่อถอนความยินยอม
- ข้อมูลทดสอบต้องเป็นข้อมูลสังเคราะห์เท่านั้น
- เจอข้อมูลส่วนบุคคลในไฟล์ต้นทาง → ไม่คัดลอก และแจ้ง `plat-may` (#ask-pdpa, dpo@novatech.example) · สงสัยว่ารั่ว แจ้งภายใน 1 ชั่วโมง

## 3. มาตรฐานเทคนิคที่ PRD ควรอ้าง (จาก `company-kit/arch-standards.md`)

- งาน async (ส่ง SMS/LINE, รายงาน, sync) ต้องผ่านคิว · job idempotent · retry exponential backoff สูงสุด 5 ครั้ง · ล้มครบไป dead-letter queue + แจ้งเตือน
- ระบบลูกค้าธนาคาร: deploy บน cloud ภูมิภาคไทยเท่านั้น · ข้อมูลอ่อนไหวเข้ารหัสระดับคอลัมน์
