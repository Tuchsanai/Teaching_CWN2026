## 1. เตรียมล่วงหน้า (T−3 ถึง T−1 วัน · ภายใน จ. 9 พ.ย.)

- [ ] **ส่งประกาศแจ้งลูกค้าภายในวันนี้ (พ. 4 พ.ย.)** ด้วยแม่แบบ `NOTICE-maintenance`: วัน เวลา ผลกระทบ (downtime กี่นาที) ช่องทางติดต่อ — ใช้เบอร์ on-call กลางเท่านั้น ห้ามเบอร์มือถือส่วนตัวของใคร (ทั้งของเราและของลูกค้า)
- [ ] Release notes 2026.11 เสร็จ: รายการ ticket · migration · feature flag · ความเสี่ยง
- [ ] UAT ผ่าน + **ลูกค้าเซ็นรับเป็นลายลักษณ์อักษร** (อีเมลก็ได้) → ไม่มี = ไม่ deploy
- [ ] Migration ทุกตัว dry-run บน staging (โครงสร้าง+ขนาดใกล้ production, ข้อมูลปิดบังแล้ว) · จดเวลา: `[ ___ ]` นาที
  - เกิน 5 นาที หรือ lock ตารางใหญ่ → แยกรอบ / ทำแบบ online
- [ ] Migration ย้อนกลับได้ หรือเป็นแบบ expand (เพิ่มอย่างเดียว) · ถ้ามีลบ/เปลี่ยนชื่อคอลัมน์ ต้องแยก expand (รอบนี้) → contract (รอบหน้า)
- [ ] ฟีเจอร์เสี่ยงอยู่หลัง feature flag และ **ปิดไว้** · รายชื่อ flag: `[ ___ ]`
- [ ] **TLS cert ทุกโดเมนที่เกี่ยวข้อง เหลือ > 21 วัน — รวมโดเมนย่อย api / webhook / payment proxy** ไม่ใช่แค่ www
  - [ ] ⚠️ ไล่ cert ที่ upload มือ 4 ตัว (ShopDee 1 + ลูกค้าอื่น 3) — ตัว **BaanRai หมด 2026-11-02 (ผ่านไปแล้ว)** ใน ticket OPS-2291 ยังไม่มีใครยืนยันว่าต่อแล้ว → เช็กทันที

- [ ] login / logout / refresh token

## 5. แผน rollback ถ้าพัง

**Rollback ทันทีถ้า:** smoke test ข้อใดไม่ผ่านและแก้ไม่ได้ใน 15 นาที · error rate > 5% นาน 5 นาที · ข้อมูลผิดแม้รายการเดียว (เช่น ยอดเงินเพี้ยน)

1. [ ] ปิด feature flag ที่เพิ่งเปิด (เร็วสุด ลองก่อน)
2. [ ] deploy image tag เดิมที่จดในข้อ 2
3. [ ] migration ทำให้โค้ดเก่าใช้ไม่ได้ → restore snapshot ข้อ 2 — **ต้อง deploy lead + หัวหน้าทีม dev (`dev-pond`) ตกลงร่วมกัน** (ข้อมูลหลัง snapshot หาย)
4. [ ] Comms แจ้งลูกค้าภายใน 30 นาทีว่าถอยกลับแล้ว + ผลกระทบ

## 6. หลัง deploy

- [ ] เปิด cron/batch ที่ปิดไว้ในข้อ 2 กลับ
