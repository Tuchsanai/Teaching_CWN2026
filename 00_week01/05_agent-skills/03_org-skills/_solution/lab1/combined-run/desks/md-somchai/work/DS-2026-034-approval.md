> ใช้ภายในเท่านั้น (มีต้นทุนและ margin — ห้ามส่งลูกค้า) · ตามกติกา `notes/deal-rules.md` v2026.3 + `margin-rules.md` v2026.1

**เหตุผล (≤ 5 บรรทัด)**
1. ข้อ 1 กำไร: 18% อยู่ช่วง 15–25% แต่ตัวเลขยังไม่ได้ใส่ risk buffer 10% ที่ margin-rules บังคับ และตัด QA 35→23 วัน คิดตามกฎจริง margin เหลือ ~9.5% (< 15% = ต้องปฏิเสธ)
2. ข้อ 2 แผนงาน: ไม่มี buffer 10%, UAT 1.5 สัปดาห์ (< 3), go-live 3 เดือนกับงานปกติ 5–6 เดือน, API ของ HIS ยังไม่มี
3. ข้อ 3 ชำระเงิน: 10/30/60 (งวดสุดท้าย 60% > 40% และจ่ายหลัง go-live 90 วัน) + เครดิต 90 วัน (> 60)
4. ข้อ 4 สัญญา: ค่าปรับ 0.2%/วันไม่มีเพดาน (ชนเพดาน 10% ใน 50 วัน), scope HIS ยังตรวจรับไม่ได้ · ข้อ 6 ทีม: tech lead ปอนด์ถือ 3 โปรเจกต์ (> 2)
5. เหตุผลเชิงกลยุทธ์ (ลูกค้าใหม่ + อีก 3 รพ.ในเครือ) มีน้ำหนัก แต่ไม่พอชดเชย 5 ข้อที่ไม่ผ่าน และยังไม่มีหนังสือ/LOI ยืนยัน

ผู้พิจารณา: สมชาย วงศ์ประเสริฐ (`md-somchai`) MD · 3 พ.ย. 2026 (ก่อนกำหนดที่เซลส์ขอ 4 พ.ย.)

## รายละเอียดการตรวจ (ตามลำดับตารางข้อ 2 ใน deal-rules)

### 0. ต้องผ่าน MD ไหม
ใช่ — มูลค่า 3.3M ≥ 1M, margin < 25%, ส่วนลด > 10% (ส่วนลดระดับนี้ MD อนุมัติได้คนเดียว)

### 1. กำไร — ❌ ไม่ผ่าน

ตรวจตัวเลขกับ `price-list.csv` แล้ว **ตรงทุกบรรทัด**:

| รายการ | จำนวน | ราคาขาย | ต้นทุน |
|---|---|---|---|
| SA | 15 | 270,000 | 165,000 |
| PM | 30 | 480,000 | 300,000 |
| Dev-Sr | 45 | 675,000 | 427,500 |
| Dev | 110 | 1,210,000 | 770,000 |
| UX | 20 | 240,000 | 150,000 |
| QA | 23 | 207,000 | 133,400 |
| DevOps | 12 | 168,000 | 108,000 |
| **ค่าพัฒนา** | 255 | **3,250,000** | **2,053,900** |
| CL-M × 12 | | 540,000 | 384,000 |
| LIC-LINE × 12 | | 72,000 | 54,000 |
| MA-STD × 1 | | 360,000 | 220,000 |
| ส่วนลดพิเศษ | | −915,000 | — |
| **รวม** | | **3,307,000** | **2,711,900** |

- กำไรขั้นต้น 595,100 · margin 18.0% ✔ (คำนวณถูก)
- ส่วนลด 915,000 = 28.2% ของค่าพัฒนา (21.7% ของราคาตาม price-list ทั้งดีล 4,222,000) → > 10% MD เท่านั้น, ไม่ได้ลด MA/cloud ✔
- **ปัญหา:** งาน fixed-price ต้องบวก risk buffer 10% ของ man-day ทุกบทบาท (margin-rules ข้อ 2) — ดีลนี้ไม่มี
  - buffer 10% = ต้นทุนเพิ่ม 205,390 บาท → margin 11.8%
  - คืน QA เป็น 35 วัน (+12 วัน, +buffer = 13.2 วัน × 5,800) = ต้นทุนเพิ่ม 76,560 บาท → margin **~9.5%**
  - ถ้าราคาขายคงเดิม ดีลนี้อยู่ในโซน "< 15% ปฏิเสธ ห้ามขอยกเว้น"
- การตัด QA "เพื่อให้ราคาลง" กับงานที่มีข้อมูลสุขภาพ + เวลาเร่ง = เพิ่มความเสี่ยงคุณภาพ ไม่ใช่ลดต้นทุนจริง

### 2. ความสมจริงของแผนงาน — ❌ ไม่ผ่าน
- ใช้กำลัง 255 ÷ (6 × 60) = 71% ✔ (≤ 85%) — แต่ถ้าใส่ buffer 10% + คืน QA = ~294 วัน → 82% ยังผ่านเส้น 85% แต่เฉียด แต่ไม่เหลือที่ให้ HIS ล่าช้า
- buffer ≥ 10% ❌ ไม่มี
- UAT ≥ 3 สัปดาห์ ❌ เหลือ 1.5 สัปดาห์
- กรอบเวลา 3 เดือน vs ปกติ 5–6 เดือน + integration HIS ที่ยังไม่เห็น API = ความเสี่ยงสูงสุดของดีล

### 3. เงื่อนไขชำระเงิน — ❌ ไม่ผ่าน
- ขอ 10/30/60 vs มาตรฐาน 30/40/30 · งวดสุดท้าย 60% (เกิน 40%) และจ่ายหลัง go-live 90 วัน
- เครดิตเทอม 90 วัน (เกิน 60)
- MA ต้องเก็บล่วงหน้ารายปี — ให้ระบุให้ชัดในสัญญา

### 4. ความเสี่ยงสัญญา — ❌ ไม่ผ่าน
- ค่าปรับ 0.2%/วันไม่มีเพดาน → ล่าช้า 50 วันก็ชนเพดาน 10% แล้ว (≈ 330,700 บาท) และเกินต่อไม่จำกัด เท่ากับ unlimited liability
- scope "เชื่อม HIS" ยังเขียนเป็นรายการตรวจรับไม่ได้ เพราะไม่มีเอกสาร API

### 5. ภาคผนวก PDPA — ไม่บังคับ (ไม่ใช่ธนาคาร/สถาบันการเงิน)
- แต่ข้อมูลสุขภาพเป็นข้อมูลอ่อนไหว (PDPA ม.26) และร่างสัญญายังไม่มี DPA → **ให้ใส่ DPA + data residency ในไทย (CL-M เป็น Thailand region อยู่แล้ว) + breach notification 72 ชม. เป็นเงื่อนไข** (ดุลยพินิจ MD ไม่ใช่กฎบังคับ)

### 6. ทีมว่างจริง — ❌ ไม่ผ่าน
- tech lead ปอนด์ถือ 3 โปรเจกต์ ม.ค.–ก.พ. 2027 (เกิน 2) รวมโปรเจกต์จองคิวธนาคาร (deal-001) ถ้าได้

### 7. ข้อมูลลูกค้าในเอกสาร — ✔ ไม่พบปัญหา
- สรุปดีลไม่มีเลขบัตร/เบอร์มือถือ/ข้อมูลผู้ป่วย · ย้ำ: proposal ที่ส่ง รพ. ห้ามแสดงต้นทุนและ margin
