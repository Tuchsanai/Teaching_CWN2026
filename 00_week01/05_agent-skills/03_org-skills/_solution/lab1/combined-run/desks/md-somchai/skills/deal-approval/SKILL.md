# พิจารณาอนุมัติดีล (deal-approval)

ทำงานแทน MD: อ่านสรุปดีล 1 ใบ แล้วตัดสินว่า ✅ อนุมัติ / 🟡 อนุมัติแบบมีเงื่อนไข / ❌ ตีกลับ พร้อมเหตุผล
ความรู้ที่ต้องใช้อยู่ใน `references/` ทั้งหมด จึงใช้ได้แม้เครื่องนั้นไม่มี company-kit

| ไฟล์ | ใช้ตอนไหน |
|---|---|
| `references/deal-rules.md` | เกณฑ์ 7 ข้อของ MD, กฎ PDPA ธนาคาร, รูปแบบผล |
| `references/margin-and-price.md` | สูตร margin, buffer 10%, เกณฑ์ 25%/15%, อำนาจส่วนลด, VAT, ราคาและต้นทุน 16 รายการ |
| `references/customer-data-check.md` | ข้อ 7: ข้อมูลส่วนบุคคลที่ห้ามอยู่ในเอกสารส่งออก |
| `references/approval-template.md` | แม่แบบไฟล์ผล |

> ถ้าในเครื่องมี `company-kit/margin-rules.md`, `price-list.csv` หรือ `notes/deal-rules.md` ที่ **เวอร์ชันใหม่กว่า** ใน references ให้ใช้ไฟล์ต้นทาง และบอกผู้ใช้ว่า references ล้าสมัย

## ขั้นตอน

1. **อ่านสรุปดีลให้ครบ** แล้วจดตัวเลขทุกบรรทัด: man-day แต่ละบทบาท, ของรายเดือน/รายปี, ส่วนลด, ราคารวม, ต้นทุนรวม, งวดเงิน, ค่าปรับ, ระยะเวลา, ทีม, ประเภทลูกค้า
2. **เช็กว่าต้องผ่าน MD ไหม** (deal-rules ข้อ 1) ถ้าไม่ต้องผ่าน ให้บอกว่าใครอนุมัติได้ แล้วจบ
3. **ลูกค้าเป็นธนาคารหรือสถาบันการเงินไหม** ถ้าใช่ ให้ตรวจ "ภาคผนวก PDPA" ครบ 3 ข้อก่อนเรื่องอื่น ถ้าขาดหรือไม่ครบ → ❌ ตีกลับให้ Sales ทันที ไม่ต้องตรวจข้ออื่นต่อ
4. **ตรวจตัวเลขเอง ห้ามเชื่อตัวเลขในสรุป**: คูณจำนวนกับราคาและต้นทุนจาก price-list ทีละบรรทัด รวมใหม่ คิด margin หลังหักส่วนลด และ VAT
   - ส่วนลดคิดเป็น % ของราคาตาม price-list → ดูว่าอยู่ในอำนาจใคร · ห้ามลด MA หรือ cloud
   - งาน fixed-price: ดูว่ามี risk buffer 10% ของ man-day แล้วหรือยัง ถ้ายัง ให้คิด margin ใหม่ 2 แบบ คือ (ก) ราคาเท่าเดิมแต่ต้นทุนเพิ่ม (ข) ราคาขึ้นตาม man-day ที่เพิ่ม
   - ถ้ามีการตัด man-day "เพื่อให้ราคาลง" (เช่น QA) ให้คิดแบบคืนค่าเดิมด้วย
   - ควรใช้สคริปต์หรือเครื่องคิดเลข อย่าคิดในหัว
5. **ตรวจ 7 ข้อตามลำดับ** (ตารางใน deal-rules) ให้แต่ละข้อได้ ✔ / ❌ / ไม่บังคับ พร้อมตัวเลขที่ใช้ตัดสิน
6. **ตัดสิน**
   - margin หลังคิดตามกฎต่ำกว่า 15% → ❌ (ห้ามขอยกเว้น)
   - ข้อ 2, 3 หรือ 4 ไม่ผ่าน → ❌ ตีกลับให้คนที่ตารางระบุ
   - เหลือแค่ข้อ 6 หรือเงื่อนไขเอกสารเล็กน้อย → 🟡 อนุมัติแบบมีเงื่อนไข
   - ผ่านทุกข้อ (margin 15–25% มีเหตุผลเชิงกลยุทธ์ที่มีหลักฐาน) → ✅
   - เหตุผลเชิงกลยุทธ์ ("จะได้งานต่อ") ช่วยได้เฉพาะช่วง margin 15–25% และไม่ลบล้างข้อที่ไม่ผ่าน
7. **เขียนผล** ตาม `references/approval-template.md` บันทึกเป็น `work/<รหัสดีล>-approval.md` (หรือที่ผู้ใช้บอก) แล้วสรุปให้ผู้ใช้ 3–5 บรรทัด

## กติกา
- ไฟล์ผลเป็นเอกสารภายใน มีต้นทุนและ margin ห้ามคัดลอกไปใส่เอกสารที่ส่งลูกค้า
- ทุกข้อที่ ❌ ต้องอ้างเลขข้อในตาราง deal-rules และบอกว่าส่งกลับให้ใคร
- กฎ PDPA ธนาคารไม่บังคับกับลูกค้าอื่น แต่ถ้ามีข้อมูลอ่อนไหว (สุขภาพ ฯลฯ) ให้เสนอ DPA เป็นเงื่อนไข และเขียนให้ชัดว่าเป็นดุลยพินิจ MD ไม่ใช่กฎบังคับ
- ข้อมูลที่สรุปไม่ได้ให้มา (เช่น resource plan) ห้ามเดา ให้เขียนว่า "ต้องเช็กกับ ..."
