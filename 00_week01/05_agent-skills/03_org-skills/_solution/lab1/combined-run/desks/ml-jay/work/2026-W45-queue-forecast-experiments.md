## สรุปสั้น

1. **r03 (LightGBM + feature วันหยุด/เงินเดือนออก) ดีที่สุด** MAPE 15.2% และดีขึ้นมากตรงจุดที่สาขาบ่น (payday 44.2 → 17.4, สัปดาห์มีวันหยุด 52.8 → 19.6)
2. **แต่การเทียบ r03 กับ r02 ยังไม่แฟร์** r03 ใช้ข้อมูล qdata-v4 (ตัดแถวซ้ำ ~1.2% และตัดสาขา 017/033 ที่ปิดปรับปรุงในช่วงทดสอบ) ส่วน r02 ใช้ v3 กับ 40 สาขา จึงยังแยกไม่ได้ว่า −4.6 จุดมาจาก feature หรือจากข้อมูลที่สะอาดขึ้น → **ต้องรัน r04 = r02 บน v4 ก่อน**
3. เทียบกับ TOR นครหลวงพัฒนา (MAPE ≤ 20%): r02 ผ่านแบบเฉียด (19.8) ส่วน r03 ผ่านโดยมีที่เหลือ 4.8 จุด แต่**ทั้งหมดวัดกับข้อมูลเกษตรไทย 38–40 สาขา ไม่ใช่ข้อมูลจริงของนครหลวงฯ 120 สาขา** จึงใช้เป็นหลักฐานความเป็นไปได้ได้ แต่ยังรับประกันตัวเลขไม่ได้
4. ทำซ้ำไม่ได้: seed ไม่ได้ fix, ผลจูน num_leaves ไม่ได้จด, โมเดลอยู่บน laptop/drive ไม่ได้ลง MLflow

ข้อสังเกตเรื่องความแฟร์ที่ต้องระวัง
- test period (ก.ค.–ก.ย.) ทับช่วงที่สาขา 017/033 ปิดปรับปรุง (ส.ค.–ก.ย.) ใน v3 สองสาขานี้น่าจะมีค่าจริงใกล้ 0 ซึ่ง**ทำให้ MAPE ของ r01/r02 สูงเกินจริง** (MAPE หารด้วยค่าจริง) ดังนั้นช่องว่างระหว่าง r02 กับ r03 บางส่วนอาจมาจากตรงนี้
- MAPE กับค่าจริงที่น้อย (สาขาเล็ก ชั่วโมงเงียบ) แกว่งง่าย ควรรายงาน MAE/RMSE คู่กันเสมอ (ซึ่ง r03 ก็ดีขึ้นทุกตัว: MAE 3.1→2.6)
- r02 กับ r03 ไม่ได้ fix seed ส่วนต่างระดับ ±0.5 จุดอาจเป็น noise ได้

## 4. ความเสี่ยงที่ MAPE รวมไม่บอก

- **พยากรณ์ต่ำกว่าจริง 20–30% ช่วง 11:00–13:00 ในสาขาย่านออฟฟิศ** อันตรายกว่าพยากรณ์เกินเพราะสาขาจัดคนไม่พอ แต่ CSV ไม่มี metric นี้ → ต้องเพิ่ม `bias_midday_office_pct` (ค่าเฉลี่ย (pred−actual)/actual ช่วงเที่ยง) ทุกรอบต่อจากนี้
- สาขาเปิดใหม่ (< 8 สัปดาห์) ไม่มี lag ใช้ fallback ค่าเฉลี่ยสาขาขนาดเดียวกัน · ไม่มี metric แยกกลุ่มนี้ (นครหลวงฯ 120 สาขา น่าจะมีกรณีนี้)
- ความรู้ทั้งหมดอยู่กับ DS สัญญาจ้างคนเดียว (notebook บนเครื่องส่วนตัว)

## 7. ข้อเสนอการตัดสินใจ (ให้หัวหน้าเลือก)

- **ข้อเสนอ:** ตั้ง r03 เป็น candidate สำหรับแทน v1 ที่เกษตรไทย **หลังจาก** r04 ยืนยันว่า feature ช่วยจริง (r03 ยังดีกว่า r04 ชัดเจน) แล้วส่ง `ml-pim` ทำ release แบบ shadow mode ก่อน
- ไม่ควรใช้ตัวเลข 15.2% เป็นคำสัญญาในข้อเสนอนครหลวงฯ (ยื่น 13 พ.ย.) ให้เขียนว่า "ต้นแบบบนข้อมูลธนาคารลูกค้าเดิมได้ MAPE ~15% ภายใต้เกณฑ์ 20%" พร้อมเงื่อนไขว่าจะวัดใหม่บนข้อมูลจริง
- เกณฑ์ถอยกลับที่ต้าเสนอ (MAPE รายสัปดาห์ > 22% สองสัปดาห์ติด หรือ under-forecast ช่วงเที่ยง > 30%) ส่งให้ `ml-pim` ตัดสินใน model-release ไม่ตัดสินในรายงานนี้
