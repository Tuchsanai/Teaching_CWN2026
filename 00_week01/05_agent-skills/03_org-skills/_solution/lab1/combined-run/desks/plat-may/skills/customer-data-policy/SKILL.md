# ตรวจข้อมูลลูกค้าในเอกสาร (customer-data-policy)

โฟกัสเรื่องเดียว: **เอกสารนี้มีข้อมูลลูกค้าที่ห้ามเปิดเผยไหม และต้องแก้อย่างไร**
ไม่ตรวจตัวเลขเงิน ไม่จัดหน้าแบรนด์ (เจอปัญหานอกขอบเขตให้จดไว้ท้ายรายงานแล้วส่งต่อ skill เจ้าของ)

ความรู้ที่ต้องใช้อยู่ใน `references/` ของ skill นี้ (ไม่ต้องมี company-kit ก็ใช้ได้)
- `references/policy-summary.md` — อะไรห้าม อะไรได้ วิธี mask การเก็บรักษา ช่องทางแจ้งเหตุ
- `references/doc-type-rules.md` — กติกาเพิ่มตามประเภทเอกสาร (ใบแจ้งหนี้ อีเมล สไลด์ บั๊ก) และข้อมูลที่ "ดูเหมือนแต่ไม่ผิด"

## ขั้นตอน

1. **ระบุบริบท** — เอกสารอะไร ส่งให้ใคร (ภายใน/ภายนอก) ลูกค้าองค์กรคือใคร ลูกค้าปลายทางคือใคร
   ไม่แน่ใจว่าส่งออกนอกบริษัทไหม → ถือว่าส่งออก (เข้มไว้ก่อน)
2. **อ่านทุกบรรทัด รวมหมายเหตุและท้ายเอกสาร** — จุดที่หลุดบ่อยคือหมายเหตุที่ระบบ auto-fill ดึงมาจาก ticket
3. **ไล่หาข้อมูลส่วนบุคคล** ตาม `policy-summary.md` ข้อ 1 แล้วจัดแต่ละชิ้นเป็นของ *ใคร*:
   ลูกค้าปลายทาง / พนักงานลูกค้าองค์กร / นิติบุคคล / โนวาเทคเอง — การตัดสินขึ้นกับเจ้าของข้อมูล
4. **ตัดสินทีละชิ้น** เป็น 3 ระดับ
   - **ต้องแก้ (ห้ามส่ง)** — ผิดข้อห้ามเด็ดขาด
   - **ควรแก้** — ไม่ผิด PDPA ตรง ๆ แต่เสี่ยง หรือขาดท้ายกระดาษ "ข้อมูลลับเฉพาะลูกค้า"
   - **ผ่าน** — เขียนเหตุผลด้วย (เช่น "บัญชีของบริษัทเราเอง") เพื่อให้ผู้อ่านไม่ต้องถามซ้ำ
5. **เลือกวิธีแก้**: ถ้าเอกสารไม่จำเป็นต้องอ้างถึง → **ตัดทิ้ง** ดีกว่า mask · ถ้าจำเป็น → ใช้รหัสเคส หรือ mask ตามตาราง
6. **เขียนผล** ลง `work/` ของผู้ใช้
   - `work/<เลขเอกสาร>-pdpa-review.md` — ประโยคแรกตอบเลยว่า "ส่งได้ / ยังส่งไม่ได้"
     หัวข้อ: สรุป (+ตารางนับ 3 ระดับ) → 1 ต้องแก้ → 2 ควรแก้ → 3 ผ่าน (พร้อมเหตุผล) → 4 นอกขอบเขต (ส่งต่อใคร) → 5 การเก็บรักษา/ต้องแจ้งเหตุไหม
     ตารางจุดที่พบ: `# | ตำแหน่ง | สิ่งที่พบ | ผิดข้อ | วิธีแก้` และใส่ข้อความที่แนะนำแทน
   - `work/<เลขเอกสาร>-redacted.md` — สำเนาที่แก้เฉพาะข้อมูลลูกค้า ห้ามแก้เนื้อหาอื่นเงียบ ๆ
     ปัญหานอกขอบเขต (เช่นตัวเลขผิด) ให้ทำเครื่องหมาย `[รอ <เจ้าของ> แก้: ...]` ไว้ ไม่แก้เอง
   - ห้ามแก้ไฟล์ต้นฉบับใน company-kit
7. **ถ้าเอกสารที่มีข้อมูลต้องห้ามเคยถูกส่งออกไปแล้ว** → บอกผู้ใช้ให้แจ้ง `plat-may` ภายใน 1 ชั่วโมง (ห้ามแก้เงียบ)
8. **ส่งต่อ** — ใบแจ้งหนี้: ส่ง `invoice-check` (`fin-nok`) ตรวจยอดต่อ · เอกสารอื่น: แจ้งเจ้าของ skill ที่สร้างเอกสาร

## ข้อควรระวัง

- อย่าคัดลอกข้อมูลต้องห้ามแบบเต็มลงรายงาน ถ้าต้องชี้ตำแหน่ง ให้ชี้บรรทัด/หัวข้อ หรือ mask ก่อน
  (ข้อยกเว้น: รายงานภายในที่ผู้ตรวจต้องเห็นว่าลบอะไร — ระบุว่าเป็นเอกสารภายในห้ามส่งต่อ)
- เลข 13 หลักไม่ใช่เลขบัตรประชาชนเสมอไป เลขผู้เสียภาษีนิติบุคคลแสดงได้
- ไม่แน่ใจ → จัดเป็น "ควรแก้" แล้วเขียนคำถามให้ผู้ใช้ตัดสิน ห้ามปล่อยผ่านเงียบ
