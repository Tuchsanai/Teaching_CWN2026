# กติกาเพิ่มตามประเภทเอกสาร

> สรุปจาก `company-kit/invoices/invoicing-rules.md` v2026.2 ข้อ 4–5 และ `company-kit/brand-guide.md` v3.2 ข้อ 3, 5 (เฉพาะส่วนที่เกี่ยวกับข้อมูลลูกค้า)

## ใบแจ้งหนี้

ใส่ได้ / ต้องมี
- ผู้ติดต่อฝั่งลูกค้า: **ชื่อ + ตำแหน่ง + อีเมลบริษัทเท่านั้น** (ห้ามเบอร์มือถือ)
- ผู้ซื้อ: ชื่อนิติบุคคล สาขา เลขผู้เสียภาษี ที่อยู่ตาม ภพ.20
- บัญชีรับเงินของโนวาเทค (ธนาคารสยามรุ่งเรือง สาขาพระราม 9 เลขที่ 714-2-08835-1) — บัญชีบริษัท แสดงได้

ห้ามมี
- เบอร์มือถือส่วนตัวของใครก็ตาม
- ชื่อหรือข้อมูลของลูกค้าปลายทาง
- เลขบัตรประชาชน
- รายละเอียดเคสภายในของลูกค้า — จำเป็นต้องอ้าง ใช้รหัสเคส/ticket

จุดที่หลุดบ่อย: **หมายเหตุ** ที่ระบบบัญชี auto-fill (เช่น เล่าเคสจาก call center พร้อมชื่อและเบอร์ลูกค้าธนาคาร)
หลังตรวจข้อมูลลูกค้าแล้ว ส่งต่อ `invoice-check` (`fin-nok`) ให้ตรวจยอด/VAT/งวด

## อีเมล / follow-up ถึงลูกค้า

- บันทึกประชุมมักมีเบอร์มือถือผู้เข้าประชุม → ห้ามคัดลอกลงอีเมล ใช้อีเมลบริษัท/เบอร์สำนักงาน
- ห้ามแนบไฟล์ที่มีข้อมูลลูกค้าปลายทาง

## สไลด์ / proposal / รายงาน

- ตัวอย่างเคส ใช้รหัสเคส ไม่ใช้ชื่อจริง · ตัวเลขสถิติรวมได้
- screenshot ระบบต้องเบลอข้อมูลส่วนบุคคล
- ท้ายกระดาษทุกหน้า: "โนวาเทค · ข้อมูลลับเฉพาะลูกค้า" + เลขหน้า (แบรนด์ข้อ 5) — ขาดให้จัดเป็น "ควรแก้"
- เอกสารภายนอกไม่ใช้อีโมจิ (แบรนด์ข้อ 3)

## รายงานบั๊ก / log / ข้อมูลทดสอบ

- ห้ามเลขบัตร/เบอร์/เลขบัญชีจริง · ข้อมูลทดสอบต้อง synthetic
- เจอข้อมูลจริงใน log → แจ้ง DevOps ให้ mask ที่ระดับ logger

## ข้อมูลที่ "ดูเหมือน แต่ไม่ผิด"

| ข้อมูล | ทำไมผ่าน |
|---|---|
| เลขผู้เสียภาษีนิติบุคคล 13 หลัก (เช่น 0105561012345) | เป็นของบริษัท ไม่ใช่เลขบัตรประชาชนบุคคล |
| ที่อยู่สำนักงาน/สาขา | ไม่ใช่ที่อยู่บ้าน |
| บัญชีรับเงินของโนวาเทค | ไม่ใช่บัญชีลูกค้าปลายทาง |
| ชื่อ + ตำแหน่ง + อีเมลบริษัทของพนักงานลูกค้าองค์กร | นโยบายห้ามแค่เบอร์มือถือส่วนตัวของพนักงานลูกค้าองค์กร |
| ชื่อพนักงานโนวาเทค (ผู้จัดทำ ผู้ตรวจ ผู้อนุมัติ) | ผู้ลงนามในนามบริษัท |
