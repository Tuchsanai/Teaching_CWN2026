# 6 มุมความเสี่ยง + เกณฑ์คะแนน

## คะแนน

| | 1 | 2 | 3 |
|---|---|---|---|
| **โอกาส** | ไม่เคยเกิด มีกลไกกันแล้ว | เป็นไปได้ ยังไม่มีกลไกกัน | เกิดอยู่แล้ว / เคยเกิดกับเรา / เงื่อนไขซ้ำกับ known-failures |
| **ผลกระทบ** | เสียเวลาไม่กี่วัน แก้ภายในได้ | เลื่อน milestone, เกินงบ man-day, ลูกค้าไม่พอใจ | ผิด SLA/สัญญา/กฎหมาย, ระบบล่มในมือลูกค้า, เสียชื่อ reference |

ระดับ = โอกาส × ผลกระทบ → 🔴 ≥ 6 · 🟡 3–4 · 🟢 1–2

## คำตัดสิน

| คำตัดสิน | เมื่อไร |
|---|---|
| 🟢 รับได้ / ปล่อยได้ | ไม่มี 🔴 และ 🟡 ทุกข้อมีเจ้าของ |
| 🟡 รับแบบมีเงื่อนไข / ปล่อยเมื่อทำ X เสร็จ | มี 🔴 แต่ลดได้ด้วยการกระทำที่ตรวจได้ก่อนเส้นตาย (เขียนเป็นข้อ ๆ: ทำอะไร ใคร ก่อนวันไหน) |
| 🔴 ไม่ควรรับ / ไม่ปล่อย | มี 🔴 ที่ไม่มีทางลดก่อนเส้นตาย หรือผูกกับสิ่งที่ลูกค้าคุมและไม่ยอมเปลี่ยน |

## มุมที่ 1 · สถาปัตยกรรมและการเชื่อมต่อ
- แปลงเป็นชิ้นงานตามมาตรฐานแล้วมีกี่ตัวที่ต้อง deploy? อะไรต้องแยก service ตามเกณฑ์?
- ระบบภายนอกกี่ระบบ แต่ละระบบมี test env/สเปก/SLA ไหม ใครเป็นเจ้าของ?
- มี cert/secret ที่ต้องต่ออายุมือไหม (mTLS client cert, OV cert ของลูกค้า) — ใครรับผิดชอบ?
- ระบบลูกค้าที่เป็นธนาคาร → region ไทย, แยกเครือข่ายตัวเชื่อม core banking

## มุมที่ 2 · คุณภาพ / โค้ดที่จะนำมาใช้ซ้ำ
- จะใช้โค้ดของโปรเจกต์เดิมไหม โค้ดนั้นมี test ล้ม/บั๊กค้างอยู่ไหม?
- ใช้ test ที่รันในสภาพแวดล้อมเหมือน production ไหม (timezone, ข้อมูลขนาดจริง)
- มีแผนทดสอบ (TEST-PLAN) และคนตรวจที่ไม่ใช่คนเขียนไหม

## มุมที่ 3 · ML (ถ้ามี)
- ตัวเลขความแม่นยำที่อ้างมาจากข้อมูลของใคร เวอร์ชันไหน เทียบกันได้จริงไหม (data version, จำนวนสาขา, seed)
- ผิดทิศไหนอันตรายกว่า (พยากรณ์ต่ำ → จัดคนไม่พอ) และเกิดช่วงไหน
- โมเดลอยู่ที่ไหน (notebook ส่วนตัว = เสี่ยง) ลง MLflow ไหม มี monitoring, เกณฑ์ถอยกลับ, shadow mode ไหม
- ได้ข้อมูลจริงเมื่อไร (ก่อนหรือหลังเซ็นสัญญา) — สัญญาจะผูก metric ก่อนเห็นข้อมูลไหม

## มุมที่ 4 · ปฏิบัติการและการขึ้นระบบ
- SLA/uptime/เวลาตอบรับ Sev1 ที่สัญญาผูก เรามี alert ที่รู้ก่อนลูกค้าไหม (synthetic check, cert < 21 วัน)
- ช่วงเวลา deploy ที่ใช้ได้จริงตาม runbook (ตัดวันศุกร์ ก่อนวันหยุดยาว วันที่ 25–สิ้นเดือนสำหรับธนาคาร) พอกับแผนนำร่อง/ขยายไหม
- migration, backup, rollback, feature flag, on-call พร้อมไหม

## มุมที่ 5 · ความปลอดภัยและกฎระเบียบ
- pentest โดยใคร ต้องจองล่วงหน้าเท่าไร เผื่อรอบแก้ไหม
- ข้อมูลอ่อนไหว (เลขบัตร, เบอร์โทร) เก็บแบบไหน audit log เก็บกี่ปี NDA
- กฎ ธปท. / PDPA ที่ผูกอยู่

## มุมที่ 6 · กำลังคน ("ทีมรับไหวไหม")
- ต้องใช้ทักษะอะไร คนที่มีอยู่ว่างไหม (โปรเจกต์ active, ตรงเวลากี่ตัว, เกินแผนที่ไหน)
- ตำแหน่งที่ยังว่างซึ่งงานนี้พึ่งอยู่ จ้างทันไหม แผนสำรองคืออะไร
- มีคนสำคัญคนเดียว (สัญญาจ้าง, คนเดียวที่รู้ระบบ) ไหม
