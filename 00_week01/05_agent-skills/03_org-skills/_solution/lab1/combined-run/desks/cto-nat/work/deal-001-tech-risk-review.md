## คำตัดสิน (TL;DR)

**🟡 รับได้แบบมีเงื่อนไข** — ทำได้ในทางเทคนิคและเราเคยทำระบบนัดหมายสาขาธนาคารมาแล้ว แต่ยังยื่นตามที่ TOR เขียนตรง ๆ ไม่ได้ ถ้ายังไม่ได้ทำเงื่อนไข 5 ข้อนี้

1. **แก้บั๊ก timezone ของช่วงเวลาที่จองได้ (slot)** ใน `kaset-appointment-web` release/2026.11 ให้เสร็จและพิสูจน์ได้ ก่อนเกษตรไทย deploy วันที่ 10 พ.ย. และก่อนนำโค้ดจองคิวมาใช้กับ deal-001 (ความเสี่ยง R1)
2. **ไม่ยืนยัน MAPE ≤ 20% แบบไม่มีเงื่อนไข** ในข้อเสนอ: ผลที่มีตอนนี้มาจากข้อมูลของธนาคารอื่น และยังเทียบกันแบบแฟร์ไม่ได้ ให้เขียนว่า "วัดบนข้อมูลของธนาคาร 3 เดือนล่าสุด หลัง shadow mode" (R2)
3. **ถามธนาคารก่อนยื่น** เรื่อง core banking (test env + ใครต่ออายุ cert mTLS), สเปก API ของ Q-Matic, รอบ pentest และ OTP (R3, R6)
4. **มีชื่อคนในทีมครบก่อนเซ็นสัญญา**: Senior Full-stack (NVT-JOB-2026-021) + ML Engineer ยังเป็นตำแหน่งว่าง ถ้าจ้างไม่ทัน 4 ม.ค. 2027 ต้องกำหนดแผนสำรอง (R4)
5. **ใส่ monitoring/alert ตามบทเรียน incident 2026-09 ไว้ในขอบเขตและราคาตั้งแต่วันแรก** เพราะ SLA 99.5% + Sev1 ตอบรับใน 30 นาที (R5)

## 3. คำตอบสามคำถามที่ผมถามเสมอ

**งานนี้เสี่ยงทางเทคนิคตรงไหน** — 3 จุดหลัก: (1) โค้ดจองคิวที่เรามีอยู่ **ตอนนี้มีบั๊ก timezone** (R1) (2) ML ยังไม่มีหลักฐานที่เทียบกันได้และไม่มี MLOps รองรับตามที่ TOR บังคับ (R2) (3) ระบบภายนอก 3 ระบบที่เราคุมไม่ได้ + cert mTLS ซึ่งเป็นแบบเดียวกับที่ทำให้ระบบล่มเมื่อ ก.ย. (R3, R5)

**ปล่อยขึ้นระบบได้ไหม** (ตอนนำร่องเดือนที่ 5) — ได้ถ้า: ผ่าน pentest ของธนาคาร, มี alert cert/synthetic check, โมเดลผ่าน shadow mode และมีเกณฑ์ถอยกลับไป baseline, ปฏิทิน deploy ไม่ชนช่วง 25–สิ้นเดือน · **ส่วน release/2026.11 ของเกษตรไทย (10 พ.ย.) ตอนนี้ยังปล่อยไม่ได้** จนกว่าจะแก้ R1

**ทีมรับงานนี้ไหวไหม** — ไหวแบบตึง ถ้าจ้าง Senior Full-stack และ ML Engineer ได้ทัน 4 ม.ค. 2027 ถ้าไม่ได้ ต้องลดงานอื่นของ `dev-mew`/`ml-pim` หรือขอ timeline 7 เดือน (นำร่องเดือนที่ 5–6, ขยายเดือนที่ 7)

## 4. คำถามที่ต้องส่งธนาคารก่อนยื่น (ผ่าน `sa-ton`/`sales-nida`)

1. Core banking Customer Lookup API: มี sandbox/UAT ไหม เปิดให้ใช้ได้ตั้งแต่เดือนไหน ใครออกและต่ออายุ client certificate ของ mTLS อายุกี่ปี
2. Q-Matic: รุ่น/เวอร์ชัน, เอกสาร API, ทุกสาขาใช้รุ่นเดียวกันไหม, ใครเป็นผู้ประสานกับผู้ผลิต
3. Pentest: ผู้ทดสอบที่ธนาคารกำหนดต้องจองล่วงหน้ากี่สัปดาห์ ใครจ่าย ทดสอบซ้ำหลังแก้ได้กี่รอบ
4. OTP: ใช้บริการ OTP/SMS ของธนาคารหรือให้เราจัดหา (ผลต่อค่าใช้จ่ายและความปลอดภัย)
5. MAPE ≤ 20%: วัดบนข้อมูลชุดไหน วัดตอนไหน (หลังได้ข้อมูล 24 เดือน + shadow mode ได้ไหม) และยอมให้ใช้โมเดล baseline ได้ไหมช่วงสาขาที่ยังไม่มีข้อมูลพอ
6. แผนขยาย 120 สาขา: ยอมให้ขยายเป็นระลอกต่อภาคได้ไหม
