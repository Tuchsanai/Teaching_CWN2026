# ทบทวน pipeline สายธุรกิจ (pipeline-review)

ผลลัพธ์: `work/<YYYY-MM-DD ของวันจันทร์>-pipeline-review.md` ไฟล์เดียว อ่านจบใน 5 นาที
ความรู้บริษัทที่ต้องใช้สรุปไว้ใน `references/` แล้ว — ใช้ได้แม้เครื่องไม่มี `company-kit/` (ถ้ามี ให้ใช้ตัวเลขจากต้นฉบับที่ใหม่กว่าเสมอ)

## ขั้นตอน

1. **หา input** ตาม `references/sources.md` — KPI เดือนล่าสุด, สรุปดีล, TOR, บันทึกประชุม, feedback/ลำดับฟีเจอร์ของ Product, รายชื่อลูกค้าผลิตภัณฑ์ · ไม่มีข้อมูล → ถาม **อย่าแต่งตัวเลขหรือดีล**
2. **ตรวจเลขของคนอื่นก่อนเชื่อ** — คำนวณราคา/ต้นทุน/margin/ส่วนลด/man-day ของทุกสรุปดีลซ้ำตาม skill `core:pricing-rules` และ `references/deal-rules.md` เจอเลขไม่ตรงหรือผิดกติกา → ใส่ในเหตุผล
3. **จัดสถานะดีลทีละใบ** ตาม `references/review-rules.md` (🚀 เร่ง / 🟡 ประคอง / 🔴 ตีกลับ / ⚫ ปล่อย) ทุกใบต้องมีเส้นตายและเหตุผลหลักบรรทัดเดียว
4. **ไขว้ข้อมูลข้ามแผนก** — นี่คือหัวใจของ skill: ชื่อลูกค้าในดีลซ้ำกับลูกค้าผลิตภัณฑ์ไหม, TOR ขอฟีเจอร์ที่ backlog ของ Product จัดไว้ท้ายไหม, คน/ทีมชนกันข้ามดีลไหม, เซลส์รับปากอะไรที่ยังไม่มีหลักฐาน (เช็กลิสต์ใน `references/review-rules.md` ข้อ 3)
5. **เขียนรายงาน** ตาม `references/report-template.md` — 6 หัวข้อ เรียงจากภาพรวม → ดีล → เรื่องที่ Sales × Product ต้องคุย → ปฏิทิน → สิ่งที่ต้องตัดสินเอง
6. **ตรวจ PDPA ก่อนบันทึก** ตาม skill `core:customer-data-policy` — `grep -nE "0[689][0-9]-?[0-9]{3}-?[0-9]{4}" work/*-pipeline-review.md` ต้องไม่เจอ · ไม่ใส่ชื่อ/เบอร์ลูกค้าปลายทาง (TOR และบันทึกประชุมมักมีเบอร์มือถือ อย่าคัดลอก)
7. **สรุปให้ผู้ใช้**: ดีลที่ต้องตัดสินวันนี้, เรื่อง Sales × Product, และใครทำต่อ (`next`)

## กติกาที่ห้ามข้าม

- รายงานนี้เป็น **เอกสารภายใน** (มีต้นทุน/margin) ห้ามส่งลูกค้า และไม่ commit เว้นแต่ผู้ใช้สั่ง
- skill นี้ **เสนอ** ไม่อนุมัติ — margin < 25% หรือส่วนลด > 10% ต้องไป `md-somchai` (`deal-approval`) · < 15% ตีกลับเสมอ
- ห้ามแนะนำให้ "ชนะด้วยการลดราคา/ตัด QA/ตัด buffer" — ทางเลือกที่เสนอได้คือแบ่งระยะ, ลดขอบเขต, หรือปล่อย
- ตัวเลขความแม่นยำ ML / ความพร้อมทางเทคนิค ห้ามรับรองเอง → ส่ง `cto-nat` (`tech-risk-review`)
- ฟีเจอร์ที่ขัดหลักความเป็นธรรมของธนาคาร (เช่น VIP ข้ามคิว) → เขียนว่า "ห้ามขาย รอ MD"
- ดีลที่มีในตัวเลข pipeline แต่ไม่มีเอกสาร → บอกมูลค่าที่มองไม่เห็นและขอรายการจาก `sales-nida` อย่าเดาสถานะ
