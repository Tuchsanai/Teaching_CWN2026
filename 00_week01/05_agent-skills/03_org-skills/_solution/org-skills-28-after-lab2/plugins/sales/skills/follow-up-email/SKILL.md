# อีเมลติดตามลูกค้า (follow-up-email)

เป้าหมาย: ลูกค้าอ่านจบใน 30 วินาทีและ**ตอบกลับได้ทันที** เพราะรู้ว่าต้องทำอะไร 1 อย่าง ภายในวันไหน

## ขั้นตอน

1. **หาวัตถุดิบ** — บันทึกประชุม / TOR / อีเมลก่อนหน้า ถ้าไม่มี ให้ถามผู้ใช้แค่: ลูกค้าคือใคร คุยอะไรไว้ ต้องการให้เขาทำอะไรต่อ
   ดึงออกมา 4 อย่าง: ผู้รับ (ใครตัดสินใจ ใครใช้งาน ใครดูความปลอดภัย), สิ่งที่**เรา**รับปาก + วันกำหนด, สิ่งที่**ลูกค้า**ต้องทำ, ช่องทางที่ลูกค้าขอ
2. **เลือกแบบ** ตาม `references/email-patterns.md` — หลังประชุม / ลูกค้าเงียบ / สรุปนัดถัดไป
3. **แยกฉบับตามผู้รับ** ถ้าลูกค้าขอช่องทางเฉพาะ (เช่น "เรื่อง security ทางอีเมลเท่านั้น") หรือเรื่องไม่เกี่ยวกัน → 1 ฉบับ = 1 ขั้นต่อไป
4. **เขียน** ตาม `references/tone-and-format.md` — ประโยคแรกหลังคำทักทายบอกสิ่งที่ขอ ตัวหนา มีวันกำหนด
5. **ตรวจข้อมูลลูกค้า** ตาม `references/customer-data-rules.md` — ตัดเบอร์มือถือ, ไม่มีราคา/คู่แข่ง/ความรู้สึกภายใน
6. **ตรวจคำมั่น** — ทุกข้อที่บอกว่า "เราจะส่ง/เราเคยทำ" ต้องมีหลักฐานในเอกสารบริษัท ถ้าไม่มีหรือเกินหลักฐาน (เช่น "ผ่านทุกครั้ง") ให้เขียนแบบไม่ผูกมัดและยกไปเป็นข้อ "ต้องตัดสินใจ"
7. **ส่งผลงาน** เป็นไฟล์ `work/<YYYY-MM-DD>-followup-<ลูกค้า>.md` ประกอบด้วย:
   - อีเมลแต่ละฉบับ (ถึง / สำเนา / เรื่อง / เนื้อความ)
   - **ต้องตัดสินใจก่อนส่ง** — สิ่งที่ AI ยืนยันเองไม่ได้ (ตารางคนในทีม, หลักฐานที่ส่งได้จริง, ความยินยอมใช้ชื่อลูกค้าเดิม)
   - **เช็กก่อนส่ง** — checklist ท้าย `references/tone-and-format.md` ติ๊กครบ

**ห้ามส่งอีเมลเอง** — ร่างเท่านั้น เจ้าของงานเป็นคนกดส่ง

## จุดที่มักพลาด

- คัดลอกเบอร์มือถือจากบันทึกประชุม/TOR ลงอีเมล (แม้ลูกค้าบอกให้โทรได้ ก็เก็บใน CRM เท่านั้น)
- ใส่หลายคำขอในฉบับเดียว ลูกค้าตอบแค่ข้อแรก
- สัญญาสิ่งที่คนอื่นในทีมพูดในที่ประชุมโดยไม่มีหลักฐาน หรือสัญญาว่าเคยเชื่อมระบบที่ยังไม่ได้ยืนยัน
- เล่าผลลัพธ์ผลงานอ้างอิงจาก "เป้าหมาย" ใน proposal เดิม (เป้าหมาย ≠ ผลจริง) หรือเผยราคาของลูกค้าเดิม
- วันในสัปดาห์ไม่ตรงกับวันที่ — คำนวณให้ถูกก่อนเขียน "อังคาร 17 พ.ย."

## ต่อจากนี้

- ลูกค้าตอบรับ / ได้ข้อมูลครบ → `sales-proposal` (นิดา)
- ต้องส่งราคาแบบช่วง → `pricing-calc` (จอย) ห้ามเดาราคาในอีเมล
- ไม่แน่ใจเรื่องข้อมูลส่วนบุคคล → `customer-data-policy` (เมย์)
