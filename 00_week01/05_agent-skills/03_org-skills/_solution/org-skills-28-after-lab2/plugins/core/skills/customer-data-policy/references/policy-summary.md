# สรุปนโยบายข้อมูลลูกค้า (Customer Data Policy) v1.4

> สรุปจาก `company-kit/customer-data-policy.md` (ผู้ดูแล `plat-may`, ปรับปรุง 2026-03-10) อ้างอิง PDPA พ.ศ. 2562
> ถ้านโยบายต้นฉบับมีเวอร์ชันใหม่กว่า v1.4 ให้ยึดต้นฉบับ แล้วแจ้ง `plat-may` ให้อัปเดตไฟล์นี้

## 1. ข้อมูลส่วนบุคคล = ระบุตัวคนได้ ทั้งตรงและอ้อม

ชื่อ-นามสกุล · เลขบัตรประชาชน · เลขพาสปอร์ต · เบอร์มือถือส่วนตัว · อีเมลส่วนตัว · ที่อยู่บ้าน · เลขบัญชี · เลขบัตรเครดิต/เดบิต · เลขสัญญาสินเชื่อ · CIF · ภาพใบหน้า · IP · GPS · ประวัติธุรกรรม

**ข้อมูลอ่อนไหว (ม.26):** ศาสนา สุขภาพ ประวัติอาชญากรรม ข้อมูลชีวภาพ ห้ามเก็บถ้าไม่จำเป็นจริง (เจอเมื่อไรให้ส่งคนตัดสิน)

**ไม่ใช่ข้อมูลส่วนบุคคล (ใช้ได้):** ชื่อ/ที่อยู่/เลขผู้เสียภาษีของ **นิติบุคคล** (13 หลักขึ้นต้น 0) · บัญชีรับเงินของ **บริษัทเราเอง** · เบอร์สำนักงาน/เบอร์ on-call กลาง

## 2. ลูกค้า 2 ระดับ

| ระดับ | คือใคร | ในเอกสารภายนอกใช้ได้แค่ |
|---|---|---|
| ลูกค้าองค์กร | บริษัท/ธนาคารที่จ้างเรา + พนักงานของเขาที่ติดต่อเรา | ชื่อ + ตำแหน่ง + อีเมลบริษัท + เบอร์สำนักงาน |
| ลูกค้าปลายทาง | ประชาชนที่ใช้ระบบที่เราสร้าง (เช่น ลูกค้าของธนาคาร) | **รหัสเคส** เช่น `CASE-2026-0815` เท่านั้น |

## 3. ห้ามเด็ดขาดในเอกสารที่ส่งออกนอกบริษัท (แบบเต็ม)

proposal, ใบแจ้งหนี้, อีเมลถึงลูกค้า, สไลด์, รายงาน, ประกาศ, ไฟล์ที่แชร์คนนอก

1. **เลขบัตรประชาชน** ของใครก็ตาม
2. **เบอร์มือถือส่วนตัว** ของบุคคล ทั้งลูกค้าปลายทางและพนักงานลูกค้าองค์กร (ใช้เบอร์สำนักงาน/อีเมลบริษัทแทน)
3. **เลขบัญชี / เลขบัตร** ของลูกค้าปลายทาง
4. **ชื่อ-นามสกุลของลูกค้าปลายทาง** (ใช้รหัสเคส)

เบอร์มือถือที่ลูกค้าให้ในที่ประชุมหรือใน TOR ให้เก็บใน CRM ภายในเท่านั้น **ไม่คัดลอกลงเอกสาร** (แม้ลูกค้าจะบอกว่า "โทรมือถือผมได้เลย")

## 4. วิธีปิดบัง (masking): ไม่จำเป็นต้องอ้างถึงเลย ให้ **ตัดทิ้ง** ดีกว่า mask

| ข้อมูล | เต็ม (ห้าม) | ปิดบัง (ใช้ได้) |
|---|---|---|
| เบอร์มือถือ | 081-234-4567 | `081-XXX-4567` |
| เลขบัตรประชาชน | 1-1037-01234-56-3 | `1-XXXX-XXXXX-XX-3` |
| เลขบัญชี | 123-4-56789-0 | `XXX-X-X6789-X` |
| เลขบัตรเครดิต | 4111 1111 1111 1234 | `4111 XXXX XXXX 1234` |
| อีเมลส่วนตัว | somying.jai@gmail.com | `s*****@gmail.com` |

## 5. ข้อมูลทดสอบ / log / production

- ข้อมูลทดสอบ = synthetic เท่านั้น ห้ามคัดลอกฐานข้อมูลจริงลงเครื่อง
- log และรายงานบั๊กห้ามมีเลขบัตร/เบอร์/เลขบัญชีจริง ถ้าเจอใน log ให้แจ้ง DevOps ปิดบังที่ระดับ logger
- เข้าถึงข้อมูลจริงใน production ต้องขอผ่าน ticket และมีผู้อนุมัติฝั่งลูกค้า

## 6. การเก็บรักษา

| ข้อมูล | เก็บนาน | ที่ไหน |
|---|---|---|
| TOR, proposal, สัญญา | 5 ปีหลังจบสัญญา | ไดรฟ์ฝ่ายขาย (Sales + MD) |
| ข้อมูลติดต่อลูกค้าองค์กร | ช่วงมีความสัมพันธ์ + 2 ปี | CRM |
| สำเนาข้อมูลลูกค้าปลายทางระหว่างโครงการ | ลบภายใน 90 วันหลังส่งมอบ | — |
| ใบแจ้งหนี้, เอกสารบัญชี | 5 ปี | ระบบบัญชี |
