# รูปแบบผลรีวิว

บันทึกเป็น `review-<PR หรือชื่อ branch>.md` (ถ้าผู้ใช้ไม่บอกที่เก็บ ตอบในแชตได้)

## 1. กล่องคะแนน (รูปแบบเดิมของทีม — ห้ามเปลี่ยน)

```
coding-rules: 8/10  ✅ merge ได้
- ❌ ข้อ 5: ไม่มี .env.example
- ❌ ข้อ 9: access token ตั้ง 60 นาที และ refresh ไม่หมุน
```
- บรรทัดแรก: `coding-rules: N/10` + `✅ merge ได้` (≥ 8) หรือ `❌ ห้าม merge (ต่ำกว่า 8)`
- ถ้าคะแนนเต็ม/เกือบเต็ม แสดงเฉพาะข้อที่ ❌/❓ · ถ้าตกเยอะ แสดงครบ 10 ข้อ

## 2. ตารางรายจุด

| # | ไฟล์:บรรทัด | ข้อ | ปัญหา | แก้แบบมาตรฐานทีม |

เรียง: ความปลอดภัย/เงิน (ข้อ 9, 10, 5) → ความถูกต้อง (4, 7, 3, 6) → โครงสร้าง/สไตล์ (1, 8, 2)
"แก้แบบมาตรฐานทีม" ต้องเป็นของจริงที่ทำตามได้ (ชื่อฟังก์ชัน, คำสั่ง, path) ไม่ใช่ "ควรปรับปรุง"

## 3. ข้อความตอบใน PR

2–4 ประโยค สุภาพ: คะแนน → 3 เรื่องที่ต้องแก้ก่อน (บอกเหตุผลสั้น ๆ ว่าทีมเคยเจ็บอะไร) → ชี้ไปที่ตาราง
