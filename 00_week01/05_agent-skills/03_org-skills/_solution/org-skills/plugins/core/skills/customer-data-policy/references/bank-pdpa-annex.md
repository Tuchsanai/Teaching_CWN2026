# ภาคผนวก PDPA — ลูกค้าธนาคาร / สถาบันการเงิน

> **ที่เดียวของคลัง** สำหรับข้อความภาคผนวกนี้ — `sales-proposal` อ้างไฟล์นี้ (`deal-approval` จะเปลี่ยนมาอ้างเมื่อ PR แยกของ `exec-ploy` merge) skill อื่นให้อ้างไฟล์นี้ **ห้ามคัดลอกไปเก็บเอง**
> ที่มาของเกณฑ์: `notes/deal-rules.md` v2026.3 (MD สมชาย, มีผล 2026-07-01) → `deal-approval` เกณฑ์ข้อ 5
> เจ้าของเกณฑ์ = MD (`md-somchai`) · ผู้ดูแลถ้อยคำด้าน PDPA = `plat-may` · ถ้าเกณฑ์ MD มีเวอร์ชันใหม่กว่า ให้ยึดต้นฉบับ แล้วแจ้ง `plat-may` ให้อัปเดตไฟล์นี้

## ใช้เมื่อไร
- **proposal** ถึงลูกค้าที่เป็น **ธนาคาร / สถาบันการเงิน** (ทุกมูลค่า) → ต้องมีหัวข้อชื่อ **"ภาคผนวก PDPA"** ตรงตัว (ตาม deal-rules v2026.3 ข้อ 3) · เอกสารประเภทอื่นถึงธนาคาร (ใบแจ้งหนี้ อีเมล minutes ฯลฯ) ไม่ต้องมี
- มี **3 ข้อพอดี** ไม่เพิ่ม ไม่ตัด ไม่รวมข้อ · ไม่มี / ไม่ครบ = MD ตีกลับทันที (`deal-approval` ข้อ 5)
- MD บังคับ 3 **เรื่อง** ไม่ได้บังคับถ้อยคำ · ตอนเขียนให้ใช้แบบข้อความด้านล่างตรงตัว · ตอนตรวจ: เนื้อหาครบแต่ถ้อยคำต่าง = 🟡 (ให้ใช้ถ้อยคำมาตรฐาน) · เนื้อหาขาดหรือขัดกับแบบ (เช่น backup/log อยู่นอกประเทศ, แจ้งช้ากว่า 72 ชม.) = 🔴
- ลูกค้าไม่ใช่ธนาคาร แต่ระบบมีข้อมูลอ่อนไหว ม.26 (สุขภาพ ศาสนา ชีวภาพ ฯลฯ) → ไม่บังคับภาคผนวกนี้ (ต้นฉบับ deal-rules ไม่ได้กำหนดเรื่องนี้) · ต้องส่งให้ `plat-may` ดูก่อนส่งเอกสาร ตามนโยบายของ skill นี้ (`doc-type-rules.md` แถว "สรุปดีล / ข้อมูลโครงการที่มีข้อมูลสุขภาพ") · **ควร**มี DPA ในสัญญา ตามสรุปใน `deal-approval/references/approval-rules.md` (นับในข้อ 4)
- ตำแหน่งในเอกสารและกติกาเฉพาะของ proposal (ต่อท้ายหัวข้อ 9, ใน 4.2 อย่างเดียวไม่นับ ฯลฯ) เป็นของ `sales-proposal` ไม่ได้อยู่ที่นี่

## 3 ข้อที่ต้องมี (เกณฑ์ MD)

| # | เรื่อง | ต้องระบุ |
|---|---|---|
| 1 | **DPA** | โนวาเทคเป็นผู้ประมวลผลข้อมูล ลูกค้าเป็นผู้ควบคุมข้อมูล ประมวลผลตามคำสั่งลูกค้าเท่านั้น |
| 2 | **Data residency** | ข้อมูลส่วนบุคคลทั้งหมดเก็บใน data center ในประเทศไทยเท่านั้น **รวม backup และ log** |
| 3 | **Breach notification** | แจ้งลูกค้าภายใน **72 ชั่วโมง** นับจากที่ทราบเหตุ |

## แบบข้อความ (ใช้ตรงตัว แทนแค่ `<ชื่อลูกค้า>`)

```markdown
## ภาคผนวก PDPA

1. **ข้อตกลงการประมวลผลข้อมูลส่วนบุคคล (DPA)** — โนวาเทคเป็นผู้ประมวลผลข้อมูลส่วนบุคคล และ <ชื่อลูกค้า> เป็นผู้ควบคุมข้อมูลส่วนบุคคล โนวาเทคประมวลผลข้อมูลส่วนบุคคลตามคำสั่งของ <ชื่อลูกค้า> เท่านั้น
2. **การเก็บข้อมูลในประเทศไทย (Data residency)** — ข้อมูลส่วนบุคคลทั้งหมดจัดเก็บใน data center ในประเทศไทยเท่านั้น รวมถึงข้อมูลสำรอง (backup) และ log
3. **การแจ้งเหตุละเมิดข้อมูลส่วนบุคคล (Breach notification)** — โนวาเทคจะแจ้ง <ชื่อลูกค้า> ภายใน 72 ชั่วโมง นับจากที่ทราบเหตุ
```

`<ชื่อลูกค้า>` = ชื่อนิติบุคคลของลูกค้าองค์กร (ใช้ได้ ไม่ใช่ข้อมูลส่วนบุคคล) · ห้ามใส่ชื่อ/เบอร์ของบุคคลในภาคผนวก

## ก่อนให้คำมั่นตามภาคผนวก (เรื่องภายใน ไม่ใส่ในเอกสารลูกค้า)
- **ข้อ 2 รวม log**: ถ้าดีลมีบริการที่เก็บ log/monitoring (เช่น `LIC-APM`) ต้องยืนยันกับ DevOps (`ops-art`) ว่าเก็บใน region ไทยก่อนเซ็นสัญญา ถ้าไม่ใช่ ข้อ 2 จะเป็นคำสัญญาที่ทำไม่ได้ → ส่ง `plat-may` + เจ้าของดีลตัดสิน ห้ามแก้ถ้อยคำเอง
- **ข้อ 3 กับขั้นตอนภายใน**: เริ่มนับ 72 ชม. ตั้งแต่**พนักงานโนวาเทคคนแรกพบเหตุ** (ลูกค้าตีความ "ทราบเหตุ" แบบนี้) · ผู้พบต้องแจ้ง `plat-may` ภายใน 1 ชั่วโมง (`policy-summary.md` ข้อ 7) — การแจ้งนี้อยู่**ในช่วง** 72 ชม. นั้น ไม่ใช่จุดเริ่มนับ
- **72 ชม.** อยู่ระหว่าง `plat-may` เสนอ MD ปรับ (ธนาคารในฐานะผู้ควบคุมต้องแจ้ง สคส. ภายใน 72 ชม. ตาม PDPA ม.37(4) จึงอาจต้องการให้เราแจ้งเร็วกว่านั้น) · จนกว่า MD จะแก้ deal-rules **ใช้ 72 ชม. ตามข้างบน** ห้ามแก้เองใน skill หรือในเอกสาร · ลูกค้าขอสั้นกว่านี้ในสัญญา → ส่ง `plat-may` + เจ้าของดีล
