## 3. ขอบเขต

**ทำในรอบนี้**
1. ผูกบัญชี LINE กับการจองคิว (ผ่าน LINE OA ของลูกค้าองค์กร + LIFF) พร้อมขอความยินยอมรับข้อความ
2. ข้อความ LINE: ยืนยันการจอง, เตือนล่วงหน้า 1 วัน, เตือน 30 นาที, เตือน "ใกล้ถึงคิว" เมื่อเหลือ N คิว (ค่าเริ่มต้น 3 สาขาตั้งได้ 1–10)
3. หน้าสถานะคิวสด: คิวที่กำลังเรียก, จำนวนคิวก่อนหน้าเรา, เวลารอโดยประมาณ — เปิดได้จาก LINE และเว็บ (หน้าเบา รองรับมือถือรุ่นเก่า แก้ F-08)
4. fallback เป็น SMS อัตโนมัติ เมื่อผู้ใช้ไม่ได้ผูก LINE หรือส่ง LINE ล้มครบ retry
5. ผู้ดูแลสาขาตั้งค่าได้: เปิด/ปิดฟีเจอร์ต่อสาขา, ค่า N, ข้อความเทมเพลต
6. รายงานในแดชบอร์ด: อัตราผูก LINE, ส่งสำเร็จ/ล้ม ต่อช่องทาง, no-show ต่อสาขา

**ไม่ทำในรอบนี้**
- เลื่อนนัดผ่าน LINE (F-04) → PRD ถัดไป
- จองคิวใหม่ผ่าน LINE (มีอยู่บนเว็บ) / chatbot ตอบคำถาม
- VIP ข้ามคิว (F-09) — ขัดหลักความเป็นธรรมที่ธนาคารสัญญากับ ธปท. รอ MD ตัดสิน
- ภาษาอังกฤษครบทั้งแอป (F-10) — ทำเฉพาะเทมเพลตข้อความ LINE ไทย/อังกฤษ
- NovaQueue v1 ทุกกรณี

## 4. User story + เกณฑ์ตรวจรับ

**US-01** ในฐานะลูกค้าปลายทาง ฉันอยากผูก LINE ตอนจองคิว เพื่อรับเตือนทาง LINE แทน SMS
- AC-01.1 Given จองคิวสำเร็จบนเว็บ When กด "รับแจ้งเตือนทาง LINE" Then เปิด LIFF ของ LINE OA ของลูกค้าองค์กรนั้น แสดงข้อความขอความยินยอม และผูกได้ภายใน 3 ขั้นตอน
- AC-01.2 Given ผู้ใช้ไม่กดยินยอม Then ไม่ผูก LINE และคิวนั้นยังได้ SMS ตามเดิม
- AC-01.3 Given ผูกแล้ว When ได้รับข้อความยืนยันการจองทาง LINE Then **ไม่ส่ง SMS ยืนยันซ้ำ** สำหรับคิวนั้น
- AC-01.4 Given ผู้ใช้ unfollow/บล็อก LINE OA Then ข้อความถัดไปของคิวนั้นส่งเป็น SMS แทน ภายใน 1 นาที

**US-02** ในฐานะลูกค้าปลายทาง ฉันอยากได้เตือนก่อนถึงคิว เพื่อไม่ต้องนั่งรอหน้าสาขา
- AC-02.1 Given คิวที่ผูก LINE When เหลือ 24 ชม. ก่อนเวลานัด (±5 นาที) Then ได้ข้อความเตือน 1 วัน
- AC-02.2 When เหลือ 30 นาทีก่อนเวลานัด (±2 นาที) Then ได้ข้อความเตือน 30 นาที
- AC-02.3 Given สาขาตั้ง N = 3 When คิวก่อนหน้าเหลือ 3 คิว Then ได้ข้อความ "ใกล้ถึงคิว" **ครั้งเดียว** ภายใน 30 วินาที
- AC-02.4 Given จองน้อยกว่า 30 นาทีก่อนเวลานัด Then ไม่ส่งเตือน 1 วันและ 30 นาที แต่ยังส่ง "ใกล้ถึงคิว"
- AC-02.5 Given คิวถูกยกเลิก Then ไม่มีเตือนใด ๆ ของคิวนั้นถูกส่งหลังยกเลิก
- AC-02.6 ทุกข้อความมีปุ่ม "ดูสถานะคิว" และ "ยกเลิกคิว"

**US-03** ในฐานะลูกค้าปลายทาง ฉันอยากเห็นว่าตอนนี้เรียกถึงคิวไหนแล้ว
- AC-03.1 หน้าสถานะแสดง: หมายเลขคิวที่กำลังเรียก, จำนวนคิวก่อนเรา, เวลารอโดยประมาณ (นาที)
- AC-03.2 ข้อมูลบนหน้าสดไม่ช้ากว่าระบบเรียกคิว 15 วินาที
- AC-03.3 หน้าเปิดได้บน Android 8 / iOS 12 ขึ้นไป และขนาดหน้ารวม ≤ 300 KB
- AC-03.4 ลิงก์สถานะคิวใช้ token สุ่มเฉพาะคิว ไม่มีเบอร์โทร/ชื่อใน URL และหมดอายุ 2 ชม. หลังเวลานัด

**US-04** ในฐานะผู้ดูแลสาขา ฉันอยากตั้งค่าการเตือนของสาขาเอง
- AC-04.1 เปิด/ปิดฟีเจอร์ต่อสาขาได้ มีผลกับคิวที่จองหลังบันทึก
- AC-04.2 ตั้ง N ได้ 1–10 ค่านอกช่วงบันทึกไม่ได้และแสดงข้อความผิดพลาด
- AC-04.3 แก้เทมเพลตข้อความได้ ไทย/อังกฤษ มีตัวอย่างก่อนบันทึก

**US-05** ในฐานะผู้จัดการสาขา ฉันอยากรู้ว่าการเตือนช่วยลด no-show ได้จริงไหม
- AC-05.1 แดชบอร์ดแสดงรายวัน: % คิวที่ผูก LINE, ส่งสำเร็จ/ล้มต่อช่องทาง, no-show
- AC-05.2 ตัวเลขในแดชบอร์ดตรงกับ log การส่งข้อความ (ต่างกันได้ไม่เกิน 0.5%)

**ข้อกำหนดที่ไม่ใช่ฟังก์ชัน (ให้ SA ลงรายละเอียด)**
- ส่งข้อความผ่านคิว `notification` (BullMQ) idempotent, retry exponential สูงสุด 5 ครั้ง → dead-letter + แจ้งเตือน → fallback SMS
- event ตั้งชื่อ `<domain>.<event>` เช่น `booking.created`, `queue.position_changed`, `notification.sent`, `notification.failed`
- LINE userId เป็นข้อมูลส่วนบุคคล เข้ารหัสระดับคอลัมน์, เก็บบน cloud ภูมิภาคไทย
- ไม่มีชื่อ-นามสกุล/เบอร์โทรของลูกค้าปลายทางในข้อความ LINE, URL และ log (ใช้รหัสคิวแทน)

## 5. ผลกระทบต่อเวอร์ชันอื่น

- **v2:** เพิ่มโมดูล `notification` ช่องทาง LINE + หน้าสถานะคิว, ระบบ SMS เดิมยังอยู่เป็น fallback
- **v1:** ไม่กระทบ ไม่ทำบน v1 (ดูแลอย่างเดียว) — ถ้าลูกค้า v1 ขอ ให้เสนอย้ายไป v2 ตามข้อเสนอมาตรฐาน (ค่าย้ายฟรีถ้าเซ็นภายใน 90 วัน, ปีแรกลด 20%)
- **deal-001 นครหลวงพัฒนา:** ฟีเจอร์นี้ครอบคลุม TOR ข้อ 27 และส่วนแจ้งเตือนของข้อ 18/44 · ข้อ 55 (audit log ≥ 2 ปี) อยู่นอก PRD นี้

## 7. คำถามเปิด (ต้องตัดสินก่อน GA)

1. ใช้ **LINE OA ของลูกค้าองค์กร** (TOR deal-001 ต้องการแบบนี้) หรือ OA กลางของโนวาเทค และใครจ่ายค่าโควตาข้อความ — ร่างนี้เลือก OA ของลูกค้า
2. เป้าตัวชี้วัดในข้อ 2 เป็นข้อเสนอของ Product ยังไม่มีข้อมูลเบต้า — ปรับหลังเบต้า 30 วัน
3. ลูกค้าเบต้า 1–3 ราย: เสนอ ออมทรัพย์เกษตรไทย (F-02) + ลูกค้าธนาคาร 2 รายจาก F-11 — ให้ Sales (`sales-nida`) ยืนยัน
4. ความยินยอมรับข้อความ LINE ใช้ข้อความแบบไหน — ให้ `plat-may` (`customer-data-policy`) รีวิว
