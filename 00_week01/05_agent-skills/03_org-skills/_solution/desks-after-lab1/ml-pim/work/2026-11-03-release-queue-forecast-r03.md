## 1. สรุปหนึ่งย่อหน้า

r03 (LightGBM + feature วันหยุด/เงินเดือนออก) ทำ MAPE ได้ 15.2% เทียบ v1 ที่ใช้อยู่ 31.5% และดีขึ้นมากตรงที่ผู้จัดการสาขาบ่น (วันเงินเดือนออก 44.2 → 17.4%) **แต่ตัวเลขนี้ยังเทียบไม่แฟร์**: r03 เทรน/ทดสอบบน qdata-v4 (38 สาขา ข้อมูลสะอาดขึ้น) ส่วน r01/r02 บน qdata-v3 (40 สาขา) จึงยังไม่รู้ว่าดีขึ้นเพราะ feature หรือเพราะข้อมูล · โมเดลยังทำซ้ำไม่ได้ (ไม่ fix seed, artifact อยู่ใน drive) · สาขา 017/033 ที่ถูกตัดออกจากชุดทดสอบยังต้องได้พยากรณ์ในระบบจริง · ยังพยากรณ์ต่ำกว่าจริงช่วงเที่ยงในสาขาย่านออฟฟิศ −20 ถึง −30% แผนคือ ปิดด่านที่ค้างในสัปดาห์นี้ → รัน shadow 3 สัปดาห์ (10–30 พ.ย.) ให้ครอบวันเงินเดือนออก 25 พ.ย. และสิ้นเดือน 30 พ.ย. → ประชุม Go/No-go 1 ธ.ค. → สลับจริง 2 ธ.ค. โดยให้ v1 รันคู่ขนานไว้ตลอด 4 สัปดาห์ สลับกลับด้วย flag ได้ทันที

## 9. เรื่องที่ต้องให้คนตัดสิน

1. **เกณฑ์ R1 = 22% และ R3 = −30%** มาจากข้อเสนอของต้า ยังไม่มีข้อมูลรองรับ — ยอมรับไหม หรือจะตั้ง R3 เทียบกับ v1 แทนตัวเลขตายตัว
2. **shadow 3 สัปดาห์** (ไม่ใช่ 1–2 ตามที่ต้าเสนอ) เพื่อให้ครอบวันเงินเดือนออก 25–30 พ.ย. — แลกกับการขึ้นจริงช้าลง
3. **วันสลับ 2 ธ.ค.** ห่าง long weekend วันพ่อแค่ 2 วันทำการ — runbook ห้าม deploy "ก่อนวันหยุดยาว" ตีความว่าแค่วันศุกร์ก่อนหยุด หรือทั้งสัปดาห์? ถ้าทั้งสัปดาห์ วันถัดไปที่ได้คือ อ. 15 ธ.ค.
4. ถ้า G1 ออกมาว่า r02-v4 ≈ r03 จะปล่อย r03 ต่อ (ดีกว่ากลุ่มวันหยุด) หรือเลือก r02 ที่ง่ายกว่า
5. ใครเป็น **Comms** ฝั่งเกษตรไทย และใครเป็น **Verifier** (ต้องไม่ใช่คนทีม ML)
