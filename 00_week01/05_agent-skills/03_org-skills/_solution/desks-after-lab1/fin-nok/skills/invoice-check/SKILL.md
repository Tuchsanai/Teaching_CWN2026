# invoice-check — ตรวจ/ออกใบแจ้งหนี้ก่อนส่งลูกค้า

กติกาที่ต้องใช้สรุปไว้ใน `references/invoicing-rules.md` (งวด สูตร ช่องบังคับ ข้อห้าม)
และ `references/pdpa-for-invoices.md` (ข้อมูลส่วนบุคคลที่ห้าม + วิธี mask) — อ่านสองไฟล์นี้ก่อนเสมอ
ถ้าในเครื่องมี `company-kit/invoices/invoicing-rules.md` ฉบับใหม่กว่า (ดูเลข version หัวไฟล์) ให้ยึดฉบับนั้น

## โหมด

- **ตรวจ** ("ตรวจใบแจ้งหนี้นี้", "ยอดถูกไหม") → ขั้น 1–5
- **ออก** ("ออกใบแจ้งหนี้งวดแรก") → ขอข้อมูลที่ขาด (มูลค่าสัญญาก่อน VAT, งวด/สัดส่วนตามสัญญา + เลขข้อ, ผู้ซื้อตาม ภ.พ.20, เลขสัญญา/PO, ผู้ติดต่อ, เครดิตเทอม, เลขที่ล่าสุด, เอกสารแนบมีแล้วหรือยัง) — ห้ามเดาตัวเลขหรือเลขที่ → ร่างตามโครง `references/invoice-template.md` → แล้วรันขั้น 1–5 กับร่างของตัวเอง
  - ถ้ายังไม่มีเอกสารแนบของงวด (สัญญาลงนาม / ใบตรวจรับ UAT / ใบตรวจรับ go-live) → **ยังออกไม่ได้** บอกผู้ใช้ตรง ๆ

## ขั้นตอนตรวจ

1. **รันสคริปต์ตัวเลข** (Python 3 ไม่ต้องลงอะไรเพิ่ม):
   `python scripts/check_invoice.py <ใบ.md> [--contract 1850000 --share 40]`
   ได้: ยอดงวด/VAT/รวม ที่ถูก, ตัวอักษรไทยที่ถูก, เบอร์มือถือ/เลขบัตรประชาชนที่เจอ
   คิดเร็ว ๆ: `python scripts/check_invoice.py --calc <มูลค่าสัญญา> <สัดส่วน%>`
   ถ้ารันไม่ได้ ให้คิดมือ: ยอดงวด = มูลค่า × สัดส่วน, VAT = ยอดงวด × 0.07 ปัด 2 ตำแหน่ง
2. **งวด** — งวด/สัดส่วน/เงื่อนไขตรงสัญญา (ต่างจากมาตรฐานได้ถ้ามีเลขข้อสัญญาในหมายเหตุ), มีเอกสารแนบครบ, ผลรวมทุกงวด = มูลค่าสัญญาพอดี (งวดสุดท้ายรับเศษ)
3. **ช่องบังคับ** — ไล่ 8 ช่องใน references ข้อ 4 ทีละช่อง, เลขที่รูปแบบ `INV-ปปปป-นนนน`, วันครบกำหนด = วันออก + เครดิตเทอม
4. **ข้อมูลต้องห้าม (อ่านเอง สคริปต์จับไม่ได้หมด)** — เบอร์มือถือใคร ๆ, ชื่อ/ข้อมูลลูกค้าปลายทาง (ประชาชน/ลูกค้าของลูกค้า), เลขบัตร/เลขบัญชีบุคคล, เรื่องเล่าเคสภายใน → ในใบแจ้งหนี้ให้ **ตัดทิ้ง** มากกว่า mask; ถ้าจำเป็นต้องอ้างใช้รหัสเคส/ticket
   - ที่แสดงได้: เลขผู้เสียภาษีนิติบุคคล (ขึ้นต้น 0), บัญชีรับเงินของบริษัท, ชื่อ+ตำแหน่ง+อีเมลบริษัทของผู้ติดต่อ
5. **ส่งผล** — เขียน 2 ไฟล์ใน `work/` (หรือที่ผู้ใช้บอก):
   - `<เลขที่>-check.md` : หัวผล ✅ ส่งได้ / ❌ ต้องแก้ → ตารางจุดผิด (ระดับ · จุด · ในร่าง · ที่ถูก · อ้างข้อกติกา) → checklist ผู้ตรวจ 5 ข้อ → สิ่งที่ยังยืนยันไม่ได้
   - `<เลขที่>-corrected.md` : ฉบับแก้ (ห้ามแก้ต้นฉบับ) แล้วรันสคริปต์ซ้ำให้ผ่าน
   ห้ามแสดงต้นทุน/margin ในใบที่ส่งลูกค้า

## กฎสำคัญ

- **ไม่เปลี่ยนตัวเลขสัญญาเอง** — ถ้ามูลค่า/สัดส่วนในใบไม่ตรงกับที่ผู้ใช้ให้ ให้ถาม ไม่ "ปรับให้ตรง"
- ตัวอักษรต้องตรงกับ "รวมทั้งสิ้นที่ถูก" ไม่ใช่ตัวเลขในร่าง (ร่างผิดมักผิดคู่กัน)
- ลำดับเลขที่และเอกสารแนบ เช็กจากไฟล์ไม่ได้ → เขียนเป็น "ต้องยืนยันในระบบบัญชี" อย่าติ๊กผ่านเอง
- ถ้าใบที่ **ส่งออกไปแล้ว** มีข้อมูลต้องห้าม → แจ้ง `plat-may` / dpo@novatech.example ภายใน 1 ชม. ห้ามแก้เงียบ (ใบที่ยังเป็นร่างไม่ต้อง)
- ผู้อนุมัติขั้นสุดท้ายคือหัวหน้าบัญชี (`fin-joy`) — skill นี้ตรวจและเตรียม ไม่อนุมัติแทน
