## 5. แผน rollback ถ้าพัง

**ต้อง rollback ทันทีถ้า** เจออย่างใดอย่างหนึ่ง:
- smoke test ข้อไหนไม่ผ่าน และแก้ไม่ได้ใน 15 นาที
- error rate > 5% ต่อเนื่อง 5 นาที
- **ข้อมูลผิดแม้แค่รายการเดียว** (รอบนี้หมายถึง: เวลานัดที่บันทึกหรือแสดงผลเลื่อนจากที่ลูกค้าเลือก, slot เต็มทั้งที่ยังว่าง, จำนวนที่ว่างไม่ตรงกับความจริง)

ทำตามลำดับ:
1. [ ] 5.1 ปิด feature flag ที่เพิ่งเปิด (ลองวิธีนี้ก่อน เพราะเร็วที่สุด)
2. [ ] 5.2 deploy image tag เดิมที่จดไว้ในข้อ 2.4 แล้วรัน smoke test 4.2 ซ้ำ
3. [ ] 5.3 ถ้า migration ทำให้โค้ดเก่าใช้ไม่ได้ → restore snapshot จากข้อ 2.3 · **ต้องให้อาร์ตและปอนด์ตกลงร่วมกันก่อน** เพราะข้อมูลหลังเวลา snapshot จะหาย
   - ก่อน restore ต้อง export นัดที่สร้างหลัง snapshot ทั้งหมดก่อน (`created_at > เวลา snapshot`) เพื่อจองคืนให้ลูกค้า หรือแจ้งลูกค้ารายคนผ่าน LINE (ห้ามคัดลอกเบอร์โทรหรือชื่อลูกค้าลงช่องแชต ให้ใช้รหัสนัดแทน)
4. [ ] 5.4 Comms แจ้งลูกค้าภายใน 30 นาทีว่าย้อนกลับแล้ว และผลกระทบคืออะไร
5. [ ] เปิด job ที่ปิดไว้ในข้อ 2.5 คืน · ถ้าเกิดผลกระทบกับลูกค้า ให้เปิดงาน postmortem (ฝน, skill `postmortem`)
