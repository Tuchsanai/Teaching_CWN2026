## สรุป 4 บรรทัด
1. **r03 (LightGBM + feature วันหยุด/payday) ดีที่สุดทุก metric** — MAPE 15.2% ผ่านเกณฑ์ TOR นครหลวงฯ (≤ 20%) และแก้จุดที่สาขาบ่น (payday 44→17%, สัปดาห์มีวันหยุด 53→20%)
2. **แต่ตอนนี้ยังเทียบ r03 กับ r02 แบบแฟร์ไม่ได้** เพราะ r03 ใช้ข้อมูล qdata-v4 (38 สาขา, ลบแถวซ้ำ) ส่วน r01/r02 ใช้ข้อมูล v3 (40 สาขา) จึงยังแยกไม่ได้ว่าที่ดีขึ้นมาจาก feature หรือจากข้อมูลที่สะอาดขึ้น
3. r02/r03 ไม่ได้ fix seed และยังไม่มี run ไหนลง MLflow → ยังรันซ้ำให้ได้ผลเดิมไม่ได้ (ตรงกับงานวันแรกของคนใหม่ใน onboarding พอดี)
4. **สถานะ: r03 = candidate** จะส่งต่อให้ `model-release` (พิมพ์) ได้เมื่อ r02b + r03b ในหัวข้อ "แผนสัปดาห์หน้า" เสร็จ

## ข้อสังเกตที่ต้องระวัง
- **การเทียบไม่แฟร์ (สำคัญสุด):** มีการเปลี่ยน r02→r03 พร้อมกัน 3 อย่าง คือ feature, n_estimators 600→800 และข้อมูล v3→v4 การตัด 2 สาขาที่ปิดปรับปรุง (ช่วงที่ค่าผิดปกติ) อาจทำให้ MAPE ลดลงได้เองโดยไม่เกี่ยวกับ feature
- **ข้อมูลเป็นของเกษตรไทย ไม่ใช่นครหลวงฯ:** การ "ผ่าน TOR" ตอนนี้เป็นแค่ตัวชี้นำ ต้องวัดใหม่กับข้อมูลย้อนหลัง 24 เดือนที่นครหลวงฯ จะส่งมาหลังเซ็นสัญญา
- **TOR กำหนดให้ "ทดสอบกับข้อมูล 3 เดือนล่าสุด":** test ตอนนี้คือ ก.ค.–ก.ย. ถ้าได้ข้อมูล ต.ค. ครบแล้วควรเลื่อนเป็น ส.ค.–ต.ค.
- **พยากรณ์ต่ำกว่าจริงช่วง 11:00–13:00 ประมาณ −20 ถึง −30% ในสาขาย่านออฟฟิศ:** MAPE ภาพรวมไม่สะท้อนปัญหานี้ ต้องเพิ่ม metric แยกช่วงเที่ยงและแยกทิศทาง (under-forecast)
- ยังไม่ได้วัดสาขาเปิดใหม่ (< 8 สัปดาห์) ที่ใช้ fallback ค่าเฉลี่ยสาขาขนาดเดียวกัน แยกต่างหาก
