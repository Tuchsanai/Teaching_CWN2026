# โครง proposal (สรุปจาก brand-guide §5 + won-proposals ของโนวาเทค)

## หัวเอกสาร
```
# ข้อเสนอโครงการ: <ชื่อระบบไทย> (<ชื่ออังกฤษ>)
**เสนอต่อ:** <ชื่อธนาคารเต็ม> — <ฝ่าย>
**อ้างอิง TOR:** <เลข TOR>
**เลขที่เอกสาร:** NVT-PRP-<ปี>-<ลำดับ 3 หลัก> · **วันที่:** <วัน เดือน ปี — ปี ค.ศ./พ.ศ. ให้ตรงกับลูกค้า>
**จัดทำโดย:** <เซลส์> · <SA>
```
ท้ายเอกสารทุกหน้า: `โนวาเทค · ข้อมูลลับเฉพาะลูกค้า` + เลขหน้า

## 9 หัวข้อ (ลำดับนี้เสมอ)
1. **บทสรุปผู้บริหาร** — ประโยคแรก = ข้อเสนอ + เป้าหมายเป็นตัวเลข · ปัญหาของลูกค้าด้วยตัวเลขจาก TOR · ระยะเวลา + มูลค่า (ไม่รวม VAT)
2. **ความเข้าใจความต้องการ** — ตาราง ข้อ TOR | ความต้องการ | สิ่งที่เราส่งมอบ + "สิ่งที่ขอยืนยันก่อนเริ่มงาน"
3. **โซลูชันที่เสนอ** — ตาราง ส่วน | รายละเอียด
4. **ภาพรวมสถาปัตยกรรม** — 4.1 โครงสร้าง (modular monolith Next.js + Node.js/TS, PostgreSQL + Redis, queue แยก, cloud ภูมิภาคไทย) · 4.2 ความปลอดภัย (ตอบ TOR ทีละข้อ) · 4.x เรื่องเฉพาะ เช่น ดูแลโมเดล ML
5. **ทีมงาน** — ตาราง บทบาท | จำนวน | หน้าที่
6. **แผนงาน** — ตารางรายเดือน, มี pentest ก่อน UAT, UAT ~3 สัปดาห์, hypercare 2 สัปดาห์
7. **ราคา** — ตารางจาก price.py + งวดชำระ 30/40/30 (เซ็นสัญญา/UAT/go-live), MA-hosting-license เก็บล่วงหน้ารายปี + สิ่งที่ไม่รวม + ตัวเลือกเสริม
8. **SLA** — Sev 1: ตอบรับ 30 นาที / แก้ 4 ชม. · Sev 2: 2 ชม. / 1 วันทำการ · Sev 3: 1 วันทำการ / 5 วันทำการ · uptime ≥ 99.5%/เดือน ไม่รวม maintenance แจ้งล่วงหน้า 3 วัน · **ระบุชั่วโมงที่ครอบคลุม** (MA-STD = 8x5, MA-PREM = 24x7)
9. **ทำไมต้องโนวาเทค** — หลักฐาน ไม่ใช่คำโอ้อวด: ผลงานอ้างอิง, สิ่งที่ทำได้จริงแล้ว, ทีมชุดเดียว, รายงานทุกสัปดาห์

## รูปแบบ (brand-guide)
- ฟอนต์ IBM Plex Sans Thai (หัวเรื่อง SemiBold 20pt / เนื้อหา 11pt), ตัวเลขตาราง IBM Plex Mono
- หัวตารางพื้น Navy `#0B2545` ตัวขาว, แถวสลับ Cloud Gray `#F4F6F8` · ห้ามแดงสด / gradient
- หัวข้อมีเลข (1, 1.1) ไม่เกิน 3 ระดับ · โลโก้ Navy บนพื้นขาว ชื่อ "โนวาเทค"/"Novatech" เท่านั้น
