# กติกาโนวาเทคที่ postmortem ต้องใช้ (สรุปจาก company-kit, 2026-11-03)

> สรุปไว้ให้ skill ใช้ได้โดยไม่ต้องมี company-kit ในเครื่อง · ต้นฉบับ: `deploy-runbook.md` (ops-art), `arch-standards.md`, `customer-data-policy.md` v1.4 (plat-may), `brand-guide.md` v3.2 (plat-may), `incident-2026-09.md`

## 1. เมื่อไรต้องเขียน
- เกิดเหตุหลัง deploy หรือระบบ production ล่ม → เขียน postmortem **ภายใน 3 วันทำการ** (runbook ข้อ 6.3)
- เหตุ Sev 1 ถูกนับใน KPI `incidents_sev1` (เป้า 0/เดือน) และขึ้นสไลด์ผู้บริหารหัวข้อ "การส่งมอบโปรเจกต์และเหตุขัดข้อง" → skill ถัดไปคือ `exec-deck`

## 2. Sev / SLA ที่เคยใช้
- Sev 1 = ฟังก์ชันหลักใช้ไม่ได้ (เช่น จ่ายเงินไม่ได้) · SLA ตัวอย่าง (ช้อปดีมาร์ท): **ตอบรับภายใน 30 นาที**
- วัดแยก: เวลาตอบรับ (ผ่าน SLA ไหม) กับ **ใครรู้ก่อน** — ถ้าลูกค้ารู้ก่อนเรา ถือเป็นช่องว่างการเฝ้าระวัง ต้องมี action item
- rollback ตัดสินทันทีถ้า: smoke test ไม่ผ่านและแก้ไม่ได้ใน 15 นาที · error rate > 5% นาน 5 นาที · ข้อมูลผิดแม้รายการเดียว · แจ้งลูกค้าภายใน 30 นาทีหลังถอย

## 3. มาตรฐานการเฝ้าระวัง (ใช้เทียบว่า "ทำไมไม่รู้ตัว")
- Alert ขั้นต่ำ: error rate > 2% 5 นาที · p95 > 2 วินาที · queue ค้าง > 1,000 job · **ใบรับรอง TLS หมดอายุภายใน 21 วัน ทุกโดเมนรวมโดเมนย่อย**
- Health check: `/healthz` (process), `/readyz` (DB + Redis + คิว)
- Metric มาตรฐาน: request rate, error rate, latency p95, queue depth, DB connections · tracing OpenTelemetry
- runbook ข้อ 1.7: ก่อน deploy เช็ก cert ทุกโดเมนที่เกี่ยวข้อง > 21 วัน
- แนวที่ทีมตกลง: uptime check ต้องยิง flow ที่ลูกค้าใช้จริง (synthetic transaction ทุก 5 นาที) · ข้อยกเว้นจาก automation (เช่น cert upload มือ) ต้องอยู่ในทะเบียนกลาง ไม่ใช่ปฏิทินส่วนตัว

## 4. PDPA (customer-data-policy v1.4) — สำคัญกับฉบับลูกค้า
ห้ามใส่แบบเต็มในเอกสารออกนอกบริษัท:
1. เลขบัตรประชาชน
2. เบอร์มือถือส่วนตัว (ทั้งลูกค้าปลายทางและพนักงานลูกค้า) — ใช้เบอร์ on-call กลาง/อีเมลบริษัท
3. เลขบัญชี / เลขบัตรของลูกค้าปลายทาง
4. ชื่อ-นามสกุลลูกค้าปลายทาง — ใช้รหัสเคส เช่น `CASE-2026-0815`

ถ้าจำเป็นต้องอ้าง ให้ mask: มือถือ `081-XXX-4567` · บัตรเครดิต `4111 XXXX XXXX 1234` · บัญชี `XXX-X-X6789-X` · ถ้าไม่จำเป็น **ตัดทิ้งดีกว่า**
- log ที่แนบต้องไม่มีข้อมูลข้างบน ถ้าเจอใน log ให้แจ้ง DevOps ปิดที่ระดับ logger
- สงสัยข้อมูลรั่ว → แจ้ง `plat-may` (#ask-pdpa, dpo@novatech.example) ภายใน 1 ชั่วโมง — ถ้าเหตุมีข้อมูลรั่ว ต้องเขียนในสรุปและแจ้งด้วย
- เพิ่มเติมสำหรับ postmortem: ฉบับลูกค้า **ห้ามมีชื่อลูกค้ารายอื่น** และรายละเอียดภายในเรื่องพนักงาน

## 5. น้ำเสียงและรูปเอกสาร (brand-guide v3.2)
- ประโยคแรกของทุกหัวข้อ = ข้อสรุป · ตรง ชัด สั้น
- ใช้ "เรา" แทนโนวาเทค, "ท่าน" แทนลูกค้า · ไม่มีอีโมจิในเอกสารภายนอก · ห้าม "ดีที่สุด", "100%"
- คำเทคนิคเขียนอังกฤษได้ แต่ครั้งแรกอธิบายไทยในวงเล็บ (ฉบับลูกค้า)
- เลขที่เอกสาร `NVT-<ประเภท>-<ปี>-<ลำดับ>` · ท้ายเอกสารลูกค้า "โนวาเทค · ข้อมูลลับเฉพาะลูกค้า"
- เขียน "โนวาเทค" / "Novatech" เท่านั้น (ไม่ใช่ NovaTech)
