# Checklist ความเสี่ยงรายด้าน

ไล่ทุกด้าน ด้านไหนไม่เกี่ยวกับงานให้เขียน 🟢 พร้อมเหตุผล 1 บรรทัด

## A. ใช้ทั้งงานรับใหม่และงานขึ้นระบบ

| ด้าน | คำถามหลัก | ขึ้น 🔴 เมื่อ |
|---|---|---|
| 1. คน / ความจุทีม | ใครทำ ได้ตัวคนแล้วหรือยัง มีจุดที่รู้อยู่คนเดียวไหม ทีมติดโปรเจกต์อื่นอยู่เท่าไร | คนในตำแหน่งหลักยังไม่ได้ตัว / งานสำคัญรู้อยู่คนเดียว (โดยเฉพาะพนักงานสัญญาจ้าง) |
| 2. Integration ภายนอก | มีเอกสาร sandbox หรือ cert ไหม เราคุมได้แค่ไหน ถ้าปลายทางล่มจะ fallback อย่างไร | ยังไม่เคยเห็นเอกสาร API / ไม่มี fallback ใน flow หลัก |
| 3. ใบรับรอง / ความลับ | cert ต่ออายุอัตโนมัติหรือทำมือ มี alert < 21 วันไหม เจ้าของคือใคร | มี cert มือที่ไม่มี alert หรือไม่มีเจ้าของ |
| 4. ข้อมูล / ความปลอดภัย | ข้อมูลส่วนบุคคล การเข้ารหัส audit log pen test ข้อกำหนด ธปท./PDPA | ต้องผ่าน pen test ภายนอกแต่ไม่มีวันในแผน / เก็บเลขบัตรเป็นข้อความธรรมดา |
| 5. ความถูกต้องของ logic หลัก | เวลา/timezone, concurrency (slot, ยอดเงิน), idempotency | มีบั๊กที่เปิดอยู่ใน flow หลัก / ไม่มี test ที่รันด้วย TZ=UTC |
| 6. ML (ถ้ามี) | วัดบนข้อมูลจริงของลูกค้าหรือยัง การเทียบแฟร์ไหม (data version เดียวกัน) seed / MLflow / monitoring / เกณฑ์ถอยกลับ | เกณฑ์ในสัญญาวัดบนข้อมูลที่ยังไม่เคยเห็น / ไม่มีวิธีถอยกลับ |
| 7. Ops / SLA | uptime และเวลาตอบ Sev1 ตามสัญญา, on-call, alert, synthetic check ของ flow หลัก | SLA 24×7 แต่ไม่มี on-call / ไม่มี check ที่ flow หลัก |

## B. เฉพาะงานรับใหม่

| ด้าน | คำถามหลัก | ขึ้น 🔴 เมื่อ |
|---|---|---|
| 8. Timeline / หน้าต่าง deploy | วาง milestone ลงปฏิทินจริง ชนช่วงห้าม deploy หรือวันหยุดยาวไหม มีเวลาเผื่อไหม | go-live ชนช่วงห้าม deploy / ไม่มีเวลาเผื่อ pen test หรือ UAT |
| 9. งบเทียบกับ effort | หักค่า hosting, license และ MA ออกก่อน แล้วเหลือเท่าไรให้ค่าพัฒนา | ค่าพัฒนาที่เหลือ < effort ที่ประเมิน และตัดขอบเขตไม่ได้ |

## C. เฉพาะงานขึ้นระบบ (ผ่าน gate ตาม runbook — ละเอียดกว่านี้ส่งต่อ `deploy-checklist`)

| gate | ต้องเป็นแบบนี้ |
|---|---|
| UAT | ลูกค้าเซ็นรับเป็นลายลักษณ์อักษร |
| E2E | flow หลักผ่านทุก project (chromium + mobile) และรันด้วย TZ=UTC ด้วย |
| Migration | dry-run บน staging ใช้เวลาไม่เกิน 5 นาที, ย้อนกลับได้หรือเป็นแบบ expand |
| Rollback | จด image tag เดิม + มี snapshot + มี feature flag สำหรับของเสี่ยง |
| Cert | ทุกโดเมนที่เกี่ยวข้อง (รวม api ย่อย และ mTLS) เหลือ > 21 วัน |
| วัน | อังคาร–พฤหัส 21:00–23:00 ไม่ใช่วันศุกร์หรือก่อนวันหยุดยาว ลูกค้าธนาคารต้องไม่ใช่วันที่ 25–สิ้นเดือน |
| แจ้งลูกค้า | ล่วงหน้า ≥ 3 วันทำการ |

## ระดับ
🔴 สูง = พังแล้วกระทบลูกค้าหรือสัญญา และยังไม่มีทางกัน · 🟠 กลาง = มีทางกันแต่ยังไม่ได้ทำ หรือเป็นรูปแบบที่เคยพัง · 🟡 ต่ำ = ทีมเคยทำแล้วและมีทางกัน · 🟢 = ไม่เกี่ยวกับงานนี้หรือปิดแล้ว
