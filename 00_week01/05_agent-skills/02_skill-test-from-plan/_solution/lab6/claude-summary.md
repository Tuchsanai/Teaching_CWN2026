## ข้อที่ต้องถามผู้ใช้ (13 ข้อ)

คำตอบของคำถามเหล่านี้ไม่พลิกคำตัดสิน เพราะ TC-CPN-01 ล้มไม่ว่าจะตีความแบบไหน แต่จำนวนข้อที่ผ่านจะเปลี่ยนได้

1. **TC-CHK-02** ตั้งใจให้ทดสอบเบอร์ 9 หลักใช่ไหม รอบนี้ใช้ 9 หลักตามตัวอย่างในหัวข้อ 3 ของแผน ผลคือล้ม ถ้าใช้เบอร์ว่างแทนจะผ่าน
2. **TC-WISH-02** "ทันที" หมายถึงไม่ต้องรีโหลดใช่ไหม และ "ตัวเลข" คือตัวเลข ♥ ที่หัวเว็บใช่ไหม รอบนี้ตีความแบบนั้น ผลคือล้ม ถ้ายอมให้รีโหลด หรือนับจำนวนรายการในหน้าแทน จะผ่าน
3. **TC-WISH-03** "หายจากรายการโปรด" รวมตัวเลข ♥ ที่หัวเว็บด้วยไหม รอบนี้นับรวม ผลคือล้ม ถ้าดูแค่ว่ารายการหายจากหน้า จะผ่าน
4. **TC-AUTH-03** ทุกกรณีต้องขึ้น error ทั้งสองช่องไหม รอบนี้ตรวจแยกช่องตามกรณี ผลคือผ่าน ถ้าต้องขึ้นทั้งสองช่องทุกกรณีจะล้ม
5. **TC-AUTH-06** ลิงก์ที่หน้าตาเหมือนปุ่มนับเป็น "ปุ่มเข้าสู่ระบบ" ได้ไหม รอบนี้นับได้ ผลคือผ่าน ถ้าต้องเป็นปุ่มจริงจะล้ม
6. **TC-HOME-01** 8 รายการหมายถึงเฉพาะส่วนสินค้ายอดนิยมใช่ไหม รอบนี้นับเฉพาะส่วนนั้น ผลคือผ่าน ถ้านับการ์ดทั้งหน้าจะได้ 12 และล้ม
7. **TC-REC-01** ผลทุกรายการต้องเป็นสินค้าลูกแมวไหม รอบนี้บังคับแค่อันดับ 1 ผลคือผ่าน ถ้าบังคับทุกรายการจะล้ม (อันดับ 2–4 เป็นแมวโต)
8. **TC-REC-02** ผลทุกรายการต้องเป็นหมาสูงวัยไหม รอบนี้บังคับแค่อันดับ 1 ผลคือผ่าน ถ้าบังคับทุกรายการจะล้ม (อันดับ 2 เป็ดอบแห้งเป็นของหมาโต)
9. **TC-REC-03** "ที่เคยดู" ต้องเป็นอาหารแมว หรือสินค้าแมวอะไรก็ได้ รอบนี้เปิดดูอาหารแมว ผลคือผ่าน ถ้าเปิดดูของเล่นหรืออุปกรณ์แมวแทน จะมีน้ำพุแมวโผล่มาและล้ม
10. **TC-REC-04** ตั้งใจให้ใช้สินค้า "ลูกแมว สูตรแซลมอน" ใช่ไหม ผลคือผ่าน สินค้านี้เป็นตัวเดียวที่ชุดซื้อคู่กันมี 3 รายการ ถ้าใช้สินค้าอื่นจะล้ม
11. **TC-API-01** "สินค้าหมา" คือทุกชนิด 14 รายการใช่ไหม รอบนี้นับทุกชนิด ผลคือผ่าน ถ้านับเฉพาะอาหารจะได้ 10 และล้ม
12. **TC-CAT-04** 9 รายการนับจากสินค้าทั้งหมดใช่ไหม รอบนี้นับจากทั้งหมด ผลคือผ่าน ถ้ากรองสัตว์ด้วยจะได้แมว 5 กับหมา 4
13. **TC-CPN-03** "ไม่มีอาหารแมว" หมายถึงตะกร้าที่มีแต่ของหมาใช่ไหม รอบนี้ใช้ตะกร้าของหมา ผลคือผ่าน ลองแบบตะกร้าว่างไม่ได้ เพราะหน้าตะกร้าว่างไม่มีช่องกรอกคูปอง

นอกจากนี้ ข้อ TC-CAT-02 และ TC-CHK-03 ลองอีกแบบแล้วผลไม่เปลี่ยน

**คำตอบเดิมของเจ้าของแผน:** ใช้ 11 ข้อจาก `pawpantry.json` (ตีความ 8 ข้อ และข้อสังเกต 3 ข้อ) ไม่มีข้อไหนหมดอายุ ข้อสังเกตทั้ง 3 ข้อตรวจกับเว็บรอบนี้แล้ว ยังพบทุกข้อ:
- 💰 กรอกโค้ดผิดทับ PAW10 แล้ว PAW10 หลุด ยอดเปลี่ยนจาก ฿833 เป็น ฿840
- ปุ่ม + ยังกดได้เมื่อจำนวนถึงสต็อก 3 แต่จำนวนค้างที่ 3
- กดล้างตัวกรองแล้ว ช่องค้นหายังค้างคำค้นเดิม

## ส่วนที่ต้องตัดสินใจเอง และการปฏิบัติตามกติกา
- **การเปิดโหมดบั๊ก:** ไม่ได้เปิดไฟล์ compose แต่เช็กด้วย `docker compose config` ว่าค่า `BUG_MODE` ตั้งผ่าน environment variable ได้ แล้วเปิดด้วย `BUG_MODE=1` ตอนเสร็จสั่ง `docker compose up -d --build` แบบไม่ใส่ตัวแปร จึงกลับเป็น 0
- **ชื่อ container ไม่ตรงแผน:** แผนเขียนว่า `petshop` แต่ container จริงชื่อ `petshop-skill05`
- **การกันข้อมูลชนกัน:**
  - agent รันของตัวเองด้วย `SKIP_RESET=1` และแยกโฟลเดอร์ output
  - เฉพาะ agent โมดูลสั่งซื้อที่สั่งซื้อจริงได้ และจำกัดไว้ 3 สินค้า (เชือกกัด, สตูว์เนื้อกระป๋อง, ชามกินช้า)
  - test มือถือใช้ Pixel 7 บน Chromium
- **ข้อมูลที่ test ทิ้งไว้ในเว็บ:** มีคำสั่งซื้อในบัญชี demo (PP-100001 เป็นต้นไป) และสต็อกเชือกกัดกับสตูว์เนื้อกระป๋องที่ลดลง การ reset รอบถัดไปจะล้างให้
- **การละเมิดกติกา:** ไม่พบ ไม่มีใครเปิดโค้ดเว็บหรือหัวข้อเฉลย (grep ใน tests และ scratch ว่าง และ agent ทุกตัวยืนยัน) ผมแก้คำตัดสินใน TEST-REPORT.md ด้วยมือ 1 จุด สคริปต์เขียนว่า "ยังไม่เด็ดขาด" แต่จริง ๆ เด็ดขาด เพราะ TC-CPN-01 ล้มไม่ว่าจะตีความแบบไหน
