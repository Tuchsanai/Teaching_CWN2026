- **agent อ่านไฟล์ด้วย Git Bash ได้** กติกา "ใช้ PowerShell" มีไว้สำหรับคำสั่งในพรอมต์ (docker · REA · npm · npx) การอ่าน/ค้นไฟล์ใช้ shell ไหนก็ได้

👀 **สังเกต**
- **"ยืนยันจาก" คือสิ่งที่เราตรวจ ไม่ใช่ความยาวของแผนที่** สุ่มเปิด 2–3 แถวดูว่าไฟล์:บรรทัดนั้นพูดเรื่องนั้นจริงไหม · แถวที่เขียน "เดา" มีประโยชน์กว่าแถวที่เดาแต่ไม่บอก

- **`permissions.deny Edit(...)` กันแค่เครื่องมือแก้ไฟล์ ไม่กันคำสั่ง shell** (`Set-Content`, `>`) → จึงต้องเขียนกติกาใน `CLAUDE.md` ด้วย และเราต้องตรวจ diff เอง
- **`CLAUDE.md` อ้าง `CODEBASE-MAP.md` เป็นชื่อไฟล์ธรรมดา** ถ้าใช้ `@` แผนที่ทั้งไฟล์จะถูกโหลดเข้าทุกเซสชัน แล้วขั้น black-box ใน LAB หลังจะไม่ black-box จริง
- งานในไฟล์นี้ยังเป็นแค่ **"ดู"** (redocumentation / design recovery) ยังไม่ได้แก้อะไร → ยังไม่ใช่ re-engineering

👀 **สังเกต**
- **หาไม่เจอ ≠ ไม่มี** API ที่ static ไม่เจอเกิดได้หลายเหตุผล (URL ประกอบตอนรัน · อยู่ฝั่ง server · ไม่มีหน้าไหนเรียก) → ต้องเป็น ❓ พร้อมเหตุผล ห้ามเขียนว่า "ไม่มี" · แม้แต่ตัวนับ node ของ REA เองก็อาจขาด endpoint หรือ storage บางตัว เพราะ REA ชนเพดานผลของ chunk ใหญ่แล้วเก็บไว้ที่ node ของไฟล์ · ตัวย่อรวมมาให้แล้วในแถวที่คอลัมน์ "ที่มา" เป็น `file node`
- **ชื่อที่ถูกย่อ (minify) และป้ายแปลก ๆ คือ inference ไม่ใช่ข้อเท็จจริง** เช่น endpoint ชื่อตัวอักษรเดียว หรือป้ายชนิดแอปที่ไม่ตรงกับสิ่งที่เรารู้ (`electron-renderer` ชี้ไปที่ไฟล์ HTML ของ Next.js ไม่ใช่แอป Electron) → ต้องอธิบายก่อนเชื่อ
- **คอลัมน์ method ในตัวย่อไม่ใช่ผลของ REA** REA ไม่บันทึก HTTP method · ตัวย่ออ่านจาก bundle ตรงตำแหน่งที่ REA ชี้ให้ (`fetch` ที่ไม่ระบุ method = GET)
- **ของจริงใหญ่มาก ให้ AI อ่านผ่านตัวย่อเท่านั้น** ไฟล์ผล REA หลายสิบ MB ถ้าเปิดตรง ๆ context ล้นและสรุปผิด
- **`out\v1` คือหลักฐานของ "ก่อนแก้"** ถ้าแก้หรือ build ทับ จะพิสูจน์ "แก้แค่ที่ตั้งใจ" ตอนท้ายบทไม่ได้
- **มี source ครบแล้ว อ่าน repo ตรงกว่า** REA มีค่าตอนที่เราต้องดู "ของที่ส่งมอบ" เช่น bundle ที่ build แล้ว หรือยืนยันว่าของที่รันตรงกับ source

👀 **สังเกต**
- **ถามก่อนสร้าง และถามเป็นตัวเลข** คำถามที่ดีบอกว่าตีความ 2 แบบแล้วตะกร้าเดียวกันได้ยอดต่างกันเท่าไร ร้านตอบง่ายกว่าคำถามลอย ๆ
- **impact ต้องมาจากการค้นโค้ด ไม่ใช่เดาจากชื่อไฟล์** และต้องครอบทั้งจุดที่ **คำนวณ** และจุดที่ **แสดง** เงิน ระบบเก่ามักมีหน้าที่เขียนสรุปเงินเองแยกจากที่อื่น
- **"ไฟล์ที่ไม่ต้องแตะ แต่ตรวจแล้ว" มีค่าเท่ากับไฟล์ที่ต้องแตะ** เพราะบอกได้ว่าเราตรวจแล้ว ไม่ใช่ลืม
- **แดงก่อนต้องแดงด้วยเหตุผลที่ถูก** "ยังไม่มีฟีเจอร์" = ถูก · หา element ผิดหรือคำนวณผลที่คาดหวังผิด = test เขียนผิด
- **ข้อที่เขียวตั้งแต่ก่อนมีฟีเจอร์ไม่ได้แปลว่าเสีย** อาจเป็น guard ที่ถูก (เช่นค่าผิดชนิดต้องถือว่าไม่ห่อ) ต้องอธิบายว่าเป็นแบบไหน · ถ้าตรวจทั้งยอดและ field `giftWrap`/`giftWrapFee` ข้อนี้จะแดงจนกว่าจะมีฟีเจอร์ (ตรวจแค่ยอด = guard)
- **ออกแบบตะกร้าโดยคิดถึงสต็อก** test ใหม่ทั้งไฟล์ซื้อของจริง × 3 เบราว์เซอร์ต้องไม่เกินสต็อกหลัง reset · ตะกร้าที่ใช้ซ้ำหลายข้อให้ใช้สินค้าสต็อกมาก ไม่งั้น LAB 8 จะเจอ 409 "สินค้าไม่พอ" ทั้งที่โค้ดถูก

- **regression 3 เบราว์เซอร์ต้องรันทั้งชุด ไม่ใช่เฉพาะ test ใหม่** AC6 ของใบ CR คือ "test เดิมที่ผ่านอยู่ต้องยังผ่าน"
- ⚠️ **ชุดเดิมแดงหลังแก้ ≠ เราแก้พังเสมอ** อ่านข้อความ error ก่อน: ถ้าเป็น `409 สินค้าไม่พอ` หรือปุ่ม `qty-plus` กดไม่ได้ = **ข้อมูลทดสอบหมด** (`npm run test:all` reset ครั้งเดียวแต่ 3 เบราว์เซอร์ใช้สต็อกก้อนเดียวกัน และ test ใหม่ซื้อของเพิ่ม) → รันทีละเบราว์เซอร์ `npx playwright test --project=<ชื่อ>` (reset ทุกรอบ) · ห้ามแก้ตะกร้าใน test เพื่อเลี่ยง
- **test data isolation** test ที่เขียนข้อมูลจริง (สั่งซื้อ ตัดสต็อก) ต้องไม่แย่งทรัพยากรกัน: ชิ้นต่อ test × จำนวนเบราว์เซอร์ ≤ สต็อก หรือแยกข้อมูล/reset ต่อชุด · เป็นเรื่องที่ทีมต้องตัดสินแก้ถาวร จดไว้ใน `CR-01.md`

👀 **สังเกต**
- **hash เท่ากัน = bytes เดียวกัน ไม่ได้แปลว่าถูก** และ **hash ต่างไม่ได้แปลว่าเราแก้** ไฟล์บางไฟล์ถูกเครื่องมือ build เขียนให้เอง ต้องหาที่มาของทุกไฟล์ที่ต่าง
- ⚠️ **เครื่องมือที่ล้มแบบเงียบอันตรายที่สุด** `Get-FileHash` กับ path ที่มี `[id]` ถ้าไม่ใส่ `-LiteralPath` จะได้ค่าว่างโดยไม่ error → ไฟล์ที่แก้หายจากตาราง · ตัวนับสำคัญต้องเทียบกับแหล่งที่สอง (`git status --short petshop`)แต่ไม่ได้ตั้งใจแก้
- **`unknown` ≠ ไฟล์หาย** แปลว่า REA หา digest ของไฟล์นั้นใน bundle ไม่เจอ · อย่ารอคำว่า `modified` ให้ดูตัวนับจริงครบ 7 คลาส และอ่านคู่กับ SHA-256 ของ source
- **คู่เวอร์ชันเดียวกันคือเส้นฐาน** ไฟล์ที่ไม่ตรงตั้งแต่คู่ v1src→v1build ไม่ได้เกิดจากการแก้ของเรา ต้องหักออกก่อนตีความคู่ข้ามเวอร์ชัน
- **obligation ที่ไม่มีหลักฐาน = ⚪ ไม่ใช่ ✅** "น่าจะยังได้" ไม่ใช่หลักฐาน · ⚪ คือรายการที่ต้องเขียน test เพิ่ม
- **เครื่องมือเทียบเวอร์ชันทั้งแอปอ่านยาก** เมื่อชื่อ chunk เปลี่ยนทั้งชุดและ coverage ไม่ครบ ตัวเลข changed/unknown จะเยอะจนบอกอะไรไม่ได้ → ตาราง 4 ทิศเจาะรายไฟล์ตรงกว่า
- ⚠️ **"สิ่งที่หลักฐานยังพิสูจน์ไม่ได้" เป็นหัวข้อบังคับ** รายงานที่บอกว่าพิสูจน์ได้ทุกอย่างคือรายงานที่ยังไม่ได้คิดเรื่องข้อจำกัด

✔️ **ไปต่อได้เมื่อ:** `CHANGE-PROOF.md` ตาราง 3 รายการไม่มี ⚠️ ที่อธิบายไม่ได้ · `CHANGE-REPORT.md` ทุกช่องมีไฟล์อ้างอิง

## 📖 คำศัพท์

| คำ | ความหมายง่าย ๆ |
|---|---|
| **Reverse engineering (RE)** | ศึกษาระบบที่มีอยู่เพื่อเข้าใจว่าทำอะไร โดยยังไม่เปลี่ยนระบบ |
| **Forward engineering** | ทางปกติ: จากความต้องการ → ออกแบบ → เขียนโค้ด → build |
| **Re-engineering** | RE ให้เข้าใจก่อน แล้วแก้หรือสร้างใหม่ (เปลี่ยนพฤติกรรม/เพิ่มความสามารถ) |
| **Restructuring** | เปลี่ยนโครงสร้างโค้ด โดยพฤติกรรมภายนอกเหมือนเดิม |
| **Redocumentation / Design recovery** | เขียนสิ่งที่โค้ดทำใหม่ในระดับเดียวกัน / ประกอบขึ้นเป็นความเข้าใจระดับสูง เช่นกฎธุรกิจ |
| **Legacy code** | โค้ดที่ไม่มี test คุม แก้แล้วไม่รู้ว่าอะไรพัง |
| **Static analysis** | ดูของโดยไม่รัน เช่นอ่าน bundle ที่ build แล้ว |
| **Runtime observation (dynamic)** | ดูตอนระบบรันจริง เช่น HAR หรือขับเบราว์เซอร์ |
| **Black / White / Grey-box** | ดูจากภายนอก (เดินเว็บ · Playwright · HAR) / อ่านโค้ด / ส่องของที่ส่งมอบหรือรันอยู่ด้วย REA แต่ยังทดสอบจากข้างนอก |
| **Triangulation** | ยืนยันเรื่องเดียวกันด้วย 2 มุมขึ้นไป ตรงกัน = มั่นใจขึ้น |
| **REA** | Reverse Engineer Anything · เครื่องมือ MCP + CLI ส่องของที่ส่งมอบหรือรันอยู่ แล้วตอบเป็นหลักฐาน |
| **Evidence** | ผลของ REA ที่บอกที่มา ความน่าเชื่อ ขอบเขต และข้อจำกัด |
| **Authority 🔵🟢🟡⚪** | ป้ายว่าหลักฐานมาจาก static · runtime · การอนุมาน · ยังไม่รู้ |
| **Coverage `partial`** | ตรวจได้ไม่ครบทุกส่วน เป็นเรื่องปกติของการวิเคราะห์แบบนี้ |
| **หาไม่เจอ ≠ ไม่มี** | ไม่เจอในหลักฐาน แปลว่ายังไม่พบ ไม่ใช่พิสูจน์ว่าไม่มี |
| **Content digest / SHA-256** | ลายนิ้วมือของไฟล์ hash เท่ากัน = bytes เดียวกัน (ไม่ได้แปลว่าถูก) |
| **Application graph (node / edge)** | แผนที่ของแอป: ชิ้นส่วน (node) และเส้นที่บอกว่าใครใช้ใคร (edge) |
| **Feature trace / seed** | ตามรอยฟีเจอร์บนแผนที่ โดยเริ่มจากจุดตั้งต้น (seed) เช่นข้อความ `coupons/validate` |
| **HAR** | ไฟล์บันทึก request/response ของเบราว์เซอร์ ⚠️ มีรหัสผ่านและ cookie จริง |
| **Scenario capture** | ให้ REA ขับเบราว์เซอร์ตามสคริปต์แล้วเก็บหลักฐาน (มีผลข้างเคียงได้) |
| **Source-to-bundle** | เทียบ source กับของที่ build ว่าไฟล์ไหนอยู่ในของที่ส่งมอบ |
| **Characterization test / Golden master** | test ที่ล็อก "สิ่งที่ระบบทำอยู่" ไว้ก่อนแก้ / ผลจริงที่เก็บไว้เทียบ |
| **ป้าย [E]** | ผลที่คาดหวังจากหลักฐานระบบ เชื่อได้ว่าระบบ *ทำ* ไม่ใช่ว่า *ควร* · [E] ขัด [D] = ผู้ต้องสงสัยบั๊ก |
| **`test.fail()` / KNOWN-ISSUE** | test ที่ตั้งใจให้ล้มเพราะรู้ว่ามีบั๊กอยู่ ถ้าวันหนึ่งผ่าน = บั๊กถูกแก้แล้ว |
| **legacy-quirk** | test ที่ล็อกพฤติกรรมแปลก ๆ ของระบบเดิมไว้ (ไม่ได้แปลว่าถูก) |
| **Obligation ledger** | รายการ "ของเดิมที่ของใหม่ต้องยังทำได้" พร้อมหลักฐานทีละข้อ |
| **Impact analysis** | หาว่าแก้ตรงนี้แล้วกระทบไฟล์ หน้า API และ test ไหนบ้าง ก่อนลงมือ |
| **ต้นเหตุ vs ปลายเหตุ** | แก้ที่สาเหตุจริง vs แก้แค่ให้อาการหาย |
| **Regression** | รัน test เดิมซ้ำเพื่อดูว่าของที่เคยใช้ได้ยังใช้ได้ |
| **Change Request (CR) / AC** | ใบขอเปลี่ยนแปลงจากร้าน / เกณฑ์ยอมรับที่ตรวจได้ |
| **CHANGE-REPORT** | รายงานส่งมอบ: แก้อะไร ทำไม หลักฐาน ความเสี่ยง วิธี rollback |
| **CODEBASE-MAP / CLAUDE.md** | แผนที่ repo ที่ AI เขียนให้เราตรวจ / คู่มือที่ Claude อ่านทุกเซสชัน |
| **permissions deny** | กติกาใน `.claude/settings.json` ห้าม Claude แก้ไฟล์ที่ระบุ (ไม่กันคำสั่ง shell) |
| **Excluded port range (WinNAT)** | ช่วงพอร์ตที่ Windows จองไว้ โปรแกรมอื่นและ Docker ใช้ไม่ได้ |
| **docker network** | เครือข่ายภายในของ container ให้ REA เรียกเว็บด้วยชื่อ service (`petshop:3000`) |
| **ExecutionPolicy** | กติกาของ Windows ว่ารันไฟล์ `.ps1` ได้ไหม · เลี่ยงรายครั้งด้วย `-ExecutionPolicy Bypass` |
| **MCP** | ช่องทางให้ Agent เรียกเครื่องมือภายนอก (เช่น REA) ได้เอง |
