## 👀 สังเกต (สำหรับ README)

- **เขียนผลที่คาดหวังก่อนเปิดเว็บได้จริง** — ทุกยอดเงินคำนวณจาก [D]+[R] ตรงกับเว็บทุกข้อ (25 ข้อที่มีตัวเลขเงิน รวม TC-CART-05 ที่ยอด ฿1,560 ถูก แต่ล้มเพราะข้อความ) ไม่ต้องลอกจากจอเลย
- **TC-COUP-03 (฿799 → −฿79) "ผ่าน" แต่ไม่ได้แปลว่าถูก** — เป็น [O-ยังไม่ยืนยัน] ผลที่คาดหวังมาจากที่เห็นตอนสำรวจ ถ้าทีมตอบ E1 ว่าปัดปกติ (฿80) ข้อนี้คือบั๊กที่ "อบ" อยู่ในแผน → ตัวอย่างดีสำหรับสอนเรื่อง oracle
- **TC-SRCH-01 ไม่ตรง ไม่ใช่เพราะเว็บผิดเสมอไป** — ผลที่คาดหวังแคบเกิน (คิดว่าค้นแค่ชื่อ) เป็นตัวอย่างดีของ "แผนเข้าใจผิด vs บั๊ก" → ทางออกคือถามทีม ไม่ใช่แก้ตามเว็บเงียบ ๆ
- **TC-CART-05** = ⚠️ R42 จาก LAB 3 กลายเป็น test ที่ล้มจริง — แสดงว่าคำถามใน LAB 3 ถูกนำมาเป็น test case
- **ขอบ NEWCAT50 ฿500 พอดีทำไม่ได้ด้วยอาหารแมวล้วน** (ราคาในร้านรวมไม่ลงตัว) จึงใช้ ฿499 / ฿534 — ถ้าผู้เรียนใช้ขนมแมวรวมให้ได้ ฿500 จะชนคำถาม E4
- จำนวน 47 ข้อ **เกินเป้า 25–35** เพราะคูปอง 4 ตัว × ขอบ/กลุ่ม (10 ข้อ) + ฟอร์มที่อยู่ (4 ข้อ) — ถ้าอยากให้ได้ ~35 ข้อ ให้รวม COUP-08/09 · CHK-03/04/05 · CART-03/04 เป็นข้อเดียวกัน
- สคริปต์ยืนยันพลาดเองครั้งแรก 1 ข้อ (TC-FIND-01: ปุ่มสุดท้ายของ finder คือ `finder-submit` "✨ ดูผลลัพธ์" ไม่ใช่ `finder-next` และการ์ดผลใช้ `finder-result` ไม่ใช่ `product-card`) — แก้สคริปต์ ไม่ได้แก้ผลที่คาดหวัง → **ก่อนสรุปว่า "ไม่ตรง" ต้องเช็กว่าไม่ใช่ปัญหาของวิธีทดสอบ** (เป็นจุดสอนดี)
- ใช้สคริปต์ headless แทนการคลิกทีละข้อผ่าน MCP เพราะ 47 ข้อ × หลายขั้น MCP จะช้ามาก (~1–2 ชม.) · สคริปต์รันทั้งชุด 108 วินาที
- `pp-cart` ใน localStorage เก็บแค่ `{slug, size, qty}` ไม่มีราคา — การใส่ `price: 1` จึงไม่มีผล (ระบบคิดราคาจริงอยู่แล้ว) ✅ TC-SEC-03
- หน้าคำสั่งซื้อแสดงทั้ง PromptPay และ "ส่งด่วน" (TC-CHK-06) · ผู้ใช้อื่นเปิด `/orders/PP-100001` ได้ HTTP 404 จริง (TC-SEC-01)
