### เช็กลิสต์สิ่งที่ต้องตรวจ — 5.1
- [ ] เรียก `POST /api/test/reset` ได้ HTTP 200 `{"ok":true}` ก่อนทุก test และเริ่มด้วย localStorage ว่าง (`pp-cart` `pp-coupon` `pp-wishlist` `pp-recent` ไม่มี)
- [ ] ทุกหน้ารายการ: "พบ N รายการ" = จำนวน `<article>` การ์ดในหน้า = จำนวนสินค้าที่ตรงเงื่อนไขจาก `GET /api/products`
- [ ] ตัวเลขหน้าแรก (ทั้งหมด/แมว/หมา/ของเล่น) = "พบ N" ของหน้าหมวดนั้น และแมว + หมา = ทั้งหมด
- [ ] ปุ่มสัตว์มี `aria-pressed="true"` ใบเดียวพอดีและตรงกับ `pet` ใน URL · select ประเภท/ช่วงวัย/เรียง และ checkbox เกรนฟรีตรงกับ URL ทุกครั้งหลังเข้าตรง ๆ, back และ reload
- [ ] การเปลี่ยนตัวกรอง/การเรียงไม่ทิ้งพารามิเตอร์อื่น (รวม `q`) ยกเว้นการค้นจากหัวเว็บ (Q5)
- [ ] `h1` และ `document.title` ของหน้าหมวด/ค้นหา: title = H1 + " · PawPantry" ทั้งในเบราว์เซอร์และใน `<title>` จาก `curl`
- [ ] HTML จาก server (`curl`) มี H1, "พบ N" และจำนวน `<article>` เท่ากับในเบราว์เซอร์ · ไม่มี console error/hydration warning
- [ ] HTTP status: query แปลก/พารามิเตอร์ซ้ำ/ค่ายาว 15,000 ตัว = 200 · ค่ายาว 20,000 ตัว = 4xx ไม่ใช่ 5xx · `/` ท้าย = 301/308 ไป URL ที่ตัด `/` (query ยังอยู่) · path/slug ตัวพิมพ์ใหญ่ = 404
- [ ] XSS: หลังเปิดทุก payload `window.__xss` ต้องเป็น `undefined`, `img[src="x"]` และ `svg[onload]` = 0, ไม่มี dialog, HTML จาก curl มีแต่ `&lt;` ไม่มีแท็กดิบ · ช่องค้นหา `.value` = payload ตรงตัว
- [ ] ช่องค้นหาหัวเว็บ `.value` = ค่า `q` ใน URL หลังเปิดตรง ๆ/reload/กดตัวกรอง และมีปุ่มล้างคำค้นที่มองเห็นและมี accessible name เมื่อผล > 0
