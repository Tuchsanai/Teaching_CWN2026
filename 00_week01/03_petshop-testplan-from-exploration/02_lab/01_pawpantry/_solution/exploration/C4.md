## A. หน้า/สถานะที่เจอ
- **`/account` ก่อนสั่ง**: การ์ดโปรไฟล์ (ชื่อ "สมใจ ใจดี", อีเมล, "ทาสแมว 🐱"), ตัวนับ "คำสั่งซื้อ 0", "ยอดซื้อสะสม ฿0", "📜 ประวัติการสั่งซื้อ" + "ยังไม่มีคำสั่งซื้อ" + ปุ่ม "เริ่มช้อปเลย" (01-account-before-orders.png)
- **`/account` หลังสั่ง**: แต่ละแถวเป็นลิงก์ไป `/orders/<id>` แสดงแค่ เลขคำสั่ง · จำนวนชิ้น · สถานะ "รับคำสั่งซื้อ" · ยอดสุทธิ · › เรียงใหม่→เก่า (ไม่มีวันที่, ไม่มีวิธีจ่าย/ค่าส่ง/ส่วนลดในแถว) (05-account-after-order1.png, 12-account-after-11-orders.png)
- **`/checkout`** (ล็อกอินแล้ว): stepper 3 ขั้น (✓ตะกร้า › 2 ที่อยู่และชำระเงิน › 3 สำเร็จ), 📦 ที่อยู่จัดส่ง (ชื่อผู้รับ, เบอร์โทร, รหัสไปรษณีย์, ที่อยู่ textarea, จังหวัด dropdown 10 จังหวัด), 🚚 วิธีจัดส่ง (ธรรมดา 2–3 วัน ฿50 / ด่วน 24 ชม. ฿120), 💳 วิธีชำระเงิน (เก็บเงินปลายทาง / PromptPay), สรุปคำสั่งซื้อ, ปุ่ม "ยืนยันสั่งซื้อ ฿<ยอด>" (02-checkout-order1-PAW10.png)
- **`/checkout` + PromptPay**: โผล่กล่อง "สแกนเพื่อชำระ ฿590" + "QR นี้เป็นตัวอย่างสำหรับการทดสอบเท่านั้น ไม่มีการตัดเงินจริง" (07-checkout-order2-promptpay-express.png)
- **`/checkout` ตอน error ฟอร์ม**: ข้อความแดงใต้แต่ละช่อง (03-checkout-empty-submit.png)
- **`/checkout` ตอนสต็อกไม่พอ**: ข้อความ "สินค้าไม่พอ: <ชื่อสินค้า>" เหนือปุ่มยืนยัน (API ตอบ 409) ตะกร้าไม่ถูกล้าง (09-tabA-stale-confirm-rejected.png, 11-injected-soldout-cart-rejected-409.png)
- **`/checkout` ตอนตะกร้าว่าง** (เช่น กด back หลังสั่ง): redirect ไป `/cart` "ตะกร้าของคุณยังว่างอยู่"
- **หน้ายืนยัน `/orders/PP-1000NN`** (title "สั่งซื้อสำเร็จ · PawPantry"): "สั่งซื้อสำเร็จ!", "ขอบคุณ <ชื่อผู้รับ> เลขที่คำสั่งซื้อของคุณคือ PP-…", "ชำระเงินแบบ… · จัดส่งแบบ… ไปที่ <จังหวัด> <รหัสไปรษณีย์>", timeline 4 ขั้น (รับคำสั่งซื้อ › แพ็คสินค้า › จัดส่ง › ถึงแล้ว), รายการสินค้า, สรุปยอด, ปุ่ม "ดูประวัติการสั่งซื้อ" / "ช้อปต่อ" (04-order1-PP-100001-confirm.png) — หน้าเดียวกับที่คลิกจาก `/account`; reload ได้ ไม่สร้างคำสั่งใหม่
- **`/orders/<id>` ตอนไม่ล็อกอิน**: redirect `/login?next=/orders/PP-100001`; `GET /api/orders/PP-100001` = 401
- **สินค้าหมด (สต็อก 0)**: หน้ารายละเอียดมีป้าย "หมด" ×3, ปุ่ม −/+ และ "สินค้าหมด" ถูก disabled; การ์ดในหน้ารวมขึ้น "หมด" + "สินค้าหมด" (10-hairball-detail-stock0.png)

## B. ฟีเจอร์
- สั่งซื้อจริงผ่าน `POST /api/orders` body = `{items:[{slug,size,qty}], coupon, shipping, payment, address:{name,phone,address,province,postcode}}` — **ไม่ส่งราคาไปจากหน้าเว็บ** เซิร์ฟเวอร์คิดราคาเอง (ดีต่อการกันแก้ราคา)
- ตะกร้าเก็บใน localStorage `pp-cart` (`[{slug,size,qty}]`) ไม่ผูกกับเซิร์ฟเวอร์ → ตะกร้าแชร์กันทุกแท็บของเบราว์เซอร์เดียว
- เลขคำสั่งซื้อเรียงต่อกัน `PP-100001`, `PP-100002`, … (เดาเลขคำสั่งของคนอื่นได้ง่าย แต่ต้องล็อกอิน)
- คูปองตรวจผ่าน `POST /api/coupons/validate` ในตะกร้า แล้วติดไปถึง checkout
- หลังสั่งสำเร็จ: ตะกร้าถูกล้าง (🛒 0, `/cart` ว่าง) และคูปองที่ใช้ไม่ติดไปตะกร้าใหม่
- ยอดซื้อสะสมใน `/account` = ผลรวมยอดสุทธิทุกคำสั่ง (ตรวจแล้วตรงทุกครั้ง: 561 → 1,151 → 1,721 → 3,193)
- สต็อกเป็นของ "สินค้า" ไม่ใช่ของ "ขนาด" (ลูกแมวแซลมอน 400 g และ 1.5 kg ลดพร้อมกัน 25→22)
- กันสั่งเกินสต็อกที่เซิร์ฟเวอร์ (409) ทั้งกรณีแท็บค้าง, แก้ localStorage, และยิง 2 คำสั่งพร้อมกัน

## D. ความเสี่ยง
0. **(P1) คำสั่งซื้อซ้ำได้เมื่อคลิกยืนยันหลายครั้งในเฟรมเดียว** — PP-100014/15/16 เกิดจากคลิกเดียวกัน 3 ครั้ง (ลูกค้าโดนเก็บเงิน 3 เท่า สต็อกหาย 3 ชิ้น คูปองถูกใช้ 3 ครั้ง) ปุ่มมี disabled แต่มาหลัง re-render; เซิร์ฟเวอร์รับคำสั่งเหมือนกันทุกอย่างที่ห่างกัน 2 ms โดยไม่กันซ้ำ บนเน็ตช้า/เครื่องช้าหรือกด Enter+คลิกพร้อมกันมีโอกาสเกิดจริง (dblclick ปกติและคลิกห่าง 100 ms ไม่ซ้ำ)
1. **(P1) API สั่งซื้อ "แก้ค่าให้เงียบ ๆ" แทนการปฏิเสธ** — คูปองหมดอายุ/ไม่มีจริงถูกทิ้งแล้วเก็บเงินเต็ม, จังหวัดที่ไม่มีในระบบถูกเปลี่ยนเป็นกรุงเทพมหานคร, shipping/payment ผิดถูกเปลี่ยนเป็น standard/cod, qty 1.5 ถูกปัดเป็น 1 (PP-100005..PP-100011) ถ้าหน้าเว็บส่งค่าผิด (บั๊ก UI หรือคนแก้ request) ลูกค้าจะได้คำสั่งที่ราคา/ที่อยู่/วิธีจ่ายไม่ตรงกับที่เห็นโดยไม่มีใครรู้
2. **(P1) การปัดเศษส่วนลด PAW10 ปัดลงเสมอ** (56.70 → 56) ลูกค้าได้ส่วนลดน้อยกว่า 10% ทุกครั้งที่ยอดไม่ลงตัว — ต้องยืนยันว่าตั้งใจหรือไม่ (ยอดใน checkout / หน้ายืนยัน / `/account` / API ตรงกันหมด จึงเป็นเรื่องกฎ ไม่ใช่ข้อมูลเพี้ยน)
3. **(P1) PromptPay ไม่มีขั้นยืนยันการชำระ** — กดยืนยันแล้วได้สถานะ "รับคำสั่งซื้อ" ทันทีเหมือนเก็บปลายทาง และตัดสต็อกทันที ทั้งที่ยังไม่ได้จ่าย (หน้าเว็บบอกว่า QR เป็นตัวอย่าง) ถ้าเป็นระบบจริงจะมีคำสั่งค้างจ่ายกินสต็อก
4. **(P2) ตะกร้าไม่เตือนสินค้าที่หมดแล้ว** — ลูกค้าเห็นยอด/ส่งฟรีที่รวมของที่ซื้อไม่ได้ แล้วโดน 409 ตอนกดยืนยัน ทั้งคำสั่งถูกปฏิเสธ (ไม่ตัดเฉพาะชิ้นที่หมด) และข้อความ "สินค้าไม่พอ" ไม่บอกว่าเหลือเท่าไร
5. **(P2) ที่อยู่ไม่ถูกแสดงให้ตรวจหลังสั่ง** หน้ายืนยัน/ประวัติโชว์แค่จังหวัด+รหัสไปรษณีย์ และไม่ตรวจรหัสไปรษณีย์กับจังหวัด (กรุงเทพฯ + 50200 ผ่าน) + มีให้เลือกแค่ 10 จังหวัด
6. **(P3) ไม่มีเพดานความยาวช่องข้อมูลผู้รับ** ชื่อยาวทำหน้ายืนยันล้นแนวนอน (scrollWidth 2035 / 1280)
7. **(P3) เลขคำสั่งซื้อเรียงต่อกันเดาได้** (PP-100001, …) ปลอดภัยเมื่อไม่ล็อกอิน (401) แต่ยังไม่ได้ลองว่าบัญชีอื่นเปิดคำสั่งของ demo ได้ไหม (IDOR) → ส่งต่อ C5
