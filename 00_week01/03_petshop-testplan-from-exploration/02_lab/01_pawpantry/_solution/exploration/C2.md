## A. หน้า/สถานะที่เจอ

- ตะกร้ามีของ: รายการ (ชื่อ · ขนาด · ชิ้นละ ฿ · −/ช่อง/+ · ยอดบรรทัด · ✕), แถบ "ซื้อเพิ่มอีก ฿X เพื่อส่งฟรี"/"ได้ส่งฟรีแล้ว!", สรุปยอด, "มักซื้อคู่กับสินค้าในตะกร้า"

## B. ฟีเจอร์
- ตัวเลือกขนาด (ปุ่ม `data-testid=size-option` + `aria-pressed`) ราคาบนปุ่ม และราคาใหญ่ "฿X / ขนาด" ใต้ชื่อ (ไม่มีราคา "/ หน่วย" แบบต่อกรัม/ต่อชิ้นให้เห็น)
- ช่องจำนวน type=number บีบค่าทันทีทุกครั้งที่พิมพ์ (clamp ระหว่าง 1..สต็อก)
- toast ✅ "เพิ่ม <ชื่อ> (<ขนาด>) ลงตะกร้าแล้ว 🛒" / ⚠️ "ไม่สามารถเพิ่ม <ชื่อ> ได้ สินค้าในสต็อกไม่พอ"

## D. ความเสี่ยง
1. **P1 ตะกร้าไม่ตรวจสต็อกซ้ำ** — ข้อ 14, 36, 37: การตรวจสต็อกทำในเบราว์เซอร์ด้วยตัวเลขตอนโหลดหน้า และตะกร้า (localStorage `pp-cart`) แสดงจำนวนเกินสต็อกหรือสินค้าหมดได้โดยไม่เตือน ปุ่ม checkout ยังกดได้ ถ้า `/checkout` / `POST /api/orders` ไม่ตรวจซ้ำ จะขายเกินสต็อกหรือขายของหมดได้ (ส่งต่อ C4 ให้ยืนยันฝั่ง server) สถานการณ์จริง: ลูกค้าใส่สูตรลดก้อนขน 3 ชิ้นไว้ แล้วคนอื่นซื้อหมด ตะกร้าก็ยังโชว์ 3 ชิ้น
2. **P1 พิมพ์จำนวนแล้วได้ค่าผิด** — ข้อ 7: ล้างช่องแล้วพิมพ์ "05" ได้ 15, "003" ได้สต็อกเต็ม เพราะช่องเด้ง 0 → 1 ทันทีระหว่างพิมพ์ ลูกค้าอาจซื้อเกินที่ตั้งใจโดยไม่รู้ตัว (ยอดเงินเพิ่ม 3 เท่า) และเกิดในช่องจำนวนของหน้าตะกร้าด้วย (ข้อ 43)
3. **P2 toast บอกสำเร็จแม้ถูกตัดจำนวน** — ข้อ 5, 12, 23: ใส่เกินสต็อกรวมในตะกร้า ระบบบีบให้เหลือเท่าสต็อกเงียบ ๆ แต่ขึ้น "✅ เพิ่ม...ลงตะกร้าแล้ว" ลูกค้าไม่รู้ว่าได้น้อยกว่าที่กด
4. **P2 ช่องจำนวนไม่หักของที่อยู่ในตะกร้าแล้ว** — max ของช่องเท่ากับสต็อกทั้งหมดเสมอ (ตะกร้ามี 25 แล้วช่องยังให้เลือก 25) ผูกกับข้อ 3
5. **P2 สต็อกรวมทุกขนาด** — ข้อ 22: ถ้าจริง ๆ แต่ละขนาดเป็นคนละ SKU ตัวเลข "มีสินค้า N ชิ้น" จะผิดสำหรับทุกขนาด
6. **P3** ไม่มีราคาต่อหน่วยให้เทียบ, ชุด "คุ้มกว่า" ไม่มีส่วนลด, slug ตัวใหญ่ 404, ปุ่ม −/+ ไม่ disabled ที่ขอบ

## E. คำถามถึงทีม
1. ตะกร้า/checkout ควรตรวจสต็อกซ้ำกับ server ไหม? ตอนนี้ตะกร้าแสดง 25 ชิ้นทั้งที่สต็อก 22 และแสดงสินค้าหมดโดยไม่เตือน (ข้อ 14, 36)
2. ใส่ตะกร้าเกินสต็อกรวม ควรแจ้งว่า "เพิ่มได้แค่ X ชิ้น" แทน toast สำเร็จไหม? (ข้อ 5, 23)
3. ช่องจำนวนควรรอให้พิมพ์เสร็จ (blur) ค่อยบีบค่า แทนที่จะบีบทุกตัวอักษร (พิมพ์ 05 ได้ 15)? (ข้อ 7)
4. สต็อกเป็นต่อสินค้าหรือต่อขนาด (SKU)? ตอนนี้ 400 g กับ 1.5 kg ใช้ก้อนเดียวกัน (ข้อ 22)
5. เกณฑ์ที่ข้อความเปลี่ยนจาก "มีสินค้า N ชิ้น" เป็น "เหลือ N ชิ้น" คือเท่าไร? (เห็น 6 = มีสินค้า, 3 = เหลือ)
6. ชุด "ซื้อคู่กันคุ้มกว่า" ตั้งใจให้มีส่วนลดไหม? ตอนนี้ราคาชุด = ผลรวมพอดี (ข้อ 28) และชุดที่เหลือ 1 รายการยังควรเรียกว่า "ชุด" ไหม (ข้อ 17)
7. ควรแสดงราคาต่อหน่วย (฿/kg, ฿/ซอง) ไหม? (ข้อ 21)
8. slug ตัวพิมพ์ใหญ่ควร redirect ไปตัวเล็กไหม? (ข้อ 30)
9. `[ส่งต่อ C4]` ยืนยันว่า `/checkout` + `POST /api/orders` ปฏิเสธจำนวนเกินสต็อก/สินค้าหมด เมื่อ `pp-cart` ใน localStorage ถูกแก้เป็น สูตรลดก้อนขน ×10 หรือ ไก่ฟรีซดราย ×2 หรือมาจากหน้าที่เปิดค้างไว้ (ข้อ 14, 36) — C2 ไม่ได้ไป checkout
10. `[ส่งต่อ C3]` ตะกร้าที่มีของเกินสต็อกยังคิด "ได้ส่งฟรีแล้ว!" จากยอดที่ซื้อจริงไม่ได้ (เช่น ฿5,518 จากของหมด) — ถ้ายอดถูกบีบตอน checkout ส่งฟรี/คูปองจะคำนวณใหม่ถูกไหม และปุ่ม + ในตะกร้าทำให้จำนวนลดลง (ข้อ 37)
11. `[ส่งต่อ C1]` breadcrumb "ของเล่นแมว" / "ของใช้สุนัข" พาไป `?pet=cat&type=toy` ซึ่ง H1 ยังเขียน "อาหารแมว"/"อาหารสุนัข" (ข้อ 32)
12. `[ส่งต่อ C6]` "สินค้าที่คล้ายกัน" ของขนมแมวเลียมีแค่ไก่ฟรีซดราย (หมด) ชิ้นเดียว — ถ้า "แนะนำสำหรับคุณ"/Finder ใช้ตรรกะเดียวกันอาจแนะนำของหมด (ข้อ 33)
13. `[ส่งต่อ C3]` ช่องจำนวนในหน้าตะกร้ามีบั๊กพิมพ์ทีละตัวแบบเดียวกัน (ข้อ 43: พิมพ์ "05" ได้ 7 = สต็อกเต็ม) — ยอดเงินในตะกร้าเปลี่ยนตามทันที ควรรวมในการทดสอบตะกร้า
