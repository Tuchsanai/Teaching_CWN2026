## 2. Charters (7 ข้อ ไม่ทับกัน)

ระดับความเสี่ยง: **P1** = กระทบเงินหรือคำสั่งซื้อโดยตรง · **P2** = กระทบการเลือกซื้อหรือการใช้งานหลัก · **P3** = ความสวยงาม ความสม่ำเสมอ การเข้าถึง

### C1 · แคตตาล็อกและตัวกรอง — P2 · 45 นาที
**สำรวจ** หน้า `/products` ทุกแบบ (ปุ่มสัตว์, dropdown ประเภท/ช่วงวัย, เกรนฟรี, การเรียง, query string) **ด้วย** ลิงก์จากเมนู, URL ที่แก้เอง, ตัวเลข 28/14/14/4 จากหน้าแรก **เพื่อหา** กฎการกรอง/เรียงที่ผิด, จำนวน "พบ N รายการ" ไม่ตรงกับการ์ดที่เห็น, UI ไม่ตรงกับ URL
สิ่งที่ต้องลองอย่างน้อย:
1. นับการ์ดจริงเทียบกับ "พบ N รายการ" ในทุกตัวกรอง และเทียบกับตัวเลขบนหน้าแรก (28 / 14 / 14 / 4)
2. เรียงราคาต่ำ→สูงและสูง→ต่ำ แล้วดูว่าใช้ราคา "เริ่มต้น" ถูกไหม ถ้าราคาเท่ากันเรียงยังไง สินค้าหมดไปอยู่ตรงไหน
3. ใช้ตัวกรองหลายตัวพร้อมกัน (แมว + ขนม + เกรนฟรี + สูงวัย) ไปจนถึงชุดที่ไม่มีผลลัพธ์เลย ดูว่ามีข้อความบอกตอนว่างไหม
4. เข้า `?type=toy` / `?pet=cat&type=treat` ตรง ๆ แล้วดูว่า dropdown, ปุ่มสัตว์ และ H1 ตรงกับ URL ไหม รวมถึงกด reload และกด back
5. ใส่ query ผิด ๆ เช่น `?pet=fish`, `?type=`, `?type=TOY`, `?pet=cat&pet=dog`, ค่ายาวมาก หรือมีอักขระพิเศษ/สคริปต์
6. ป้ายบนการ์ด (ช่วงวัย, เกรนฟรี, ★) ต้องตรงกับหน้ารายละเอียดของสินค้าตัวนั้น
- ❌ ห้ามกด "ใส่ตะกร้า" (เป็นงานของ C3)

### C2 · หน้ารายละเอียดสินค้าและกฎสต็อก — P1 · 60 นาที
**สำรวจ** หน้า `/products/<slug>` (ขนาด, ราคา, ช่องจำนวน, ข้อความ "มีสินค้า N ชิ้น", สินค้าหมด, ชุด "มักซื้อคู่กัน", "สินค้าที่คล้ายกัน") **ด้วย** สินค้าหมด/ใกล้หมดจาก TEST-DATA (ไก่ฟรีซดราย 0, สูตรลดก้อนขน 3) และค่าขอบเขตของจำนวน **เพื่อหา** ช่องโหว่ที่ทำให้ใส่ตะกร้าเกินสต็อก ราคาที่ไม่ตรงตามขนาด และราคาชุดที่คำนวณผิด
สิ่งที่ต้องลองอย่างน้อย:
1. ใส่จำนวน 0, −1, 1.5, ว่าง, 99999, e, เลขนำหน้าด้วย 0 ทั้งการพิมพ์และการกด −/+ จนถึงขอบ (เทียบกับ "มีสินค้า N ชิ้น")
2. สูตรลดก้อนขน (เหลือ 3): ใส่ 3, 4 และใส่ซ้ำ 2 ครั้ง ครั้งละ 2 ดูว่ายอดรวมเกินสต็อกได้ไหม (ทำในตะกร้าของ session ตัวเองเท่านั้น)
3. ไก่ฟรีซดราย (หมด): พยายามใส่ตะกร้าทุกทางที่หาได้ ทั้งการ์ด หน้ารายละเอียด ชุด "มักซื้อคู่กัน" ที่มีสินค้านี้อยู่ และพิมพ์จำนวนเองหรือกด Enter
4. สลับขนาดแล้วดูว่าราคา, ราคา "/ หน่วย", สต็อก และขนาดที่ลงตะกร้าเปลี่ยนตามถูกไหม
5. "เพิ่มทั้งชุดลงตะกร้า": ฿297 ต้องเท่ากับผลรวมราคาขนาดเล็กสุดของทุกชิ้น และถ้าในชุดมีชิ้นที่หมดจะทำยังไง
6. slug ที่ไม่มีอยู่จริง, slug ตัวพิมพ์ใหญ่ และ breadcrumb ต้องพากลับไปหมวดที่ถูก
- ⚠️ **ทำก่อนอย่างอื่น:** หลังใส่ตะกร้า ให้เปิดสินค้าเดียวกันอีก session แล้วดูว่า "มีสินค้า N ชิ้น" ลดลงไหม ถ้าลด (แปลว่าการใส่ตะกร้าไปจองสต็อก) ให้หยุดลองข้อ 2–3 แล้วแจ้งเจ้าของ C4 เพราะสต็อกกลางเป็นของ C4
- ❌ ห้ามไปหน้า checkout หรือสั่งซื้อ

### C3 · ตะกร้า คูปอง และค่าส่ง (ก่อนกดยืนยันคำสั่งซื้อ) — P1 · 60 นาที
**สำรวจ** `/cart` และหน้าสรุปยอดใน `/checkout` ไปจนถึงก่อนกดยืนยันสั่งซื้อ **ด้วย** คูปองทั้ง 4 ตัว (`PAW10`, `FREESHIP`, `NEWCAT50`, `SUMMER20`), ยอดรอบ ๆ ฿999 และ ฿500, ส่งปกติ ฿50 / ด่วน ฿120 และบัญชีที่สมัครเอง **เพื่อหา** ยอดรวม ส่วนลด หรือค่าส่งที่คำนวณผิด, เงื่อนไขคูปองที่บังคับใช้ไม่ครบ, ยอดติดลบหรือการปัดเศษผิด
สิ่งที่ต้องลองอย่างน้อย:
1. ยอดเท่ากับ ฿998 / ฿999 / ฿1000 ทั้งก่อนและหลังลด `PAW10` ดูว่าส่งฟรีคิดจากยอดก่อนหรือหลังส่วนลด
2. `NEWCAT50`: อาหารแมว ฿499 กับ ฿500, ยอด ฿500 ที่มีของเล่นแมวปน, ยอด ฿500 ที่มีของหมาปน และกรณีลดราคาแล้วต่ำกว่า ฿500
3. ใช้คูปองซ้อนกัน (PAW10 + FREESHIP), ใส่ซ้ำ, พิมพ์เล็ก/เว้นวรรค (` paw10 `), `SUMMER20` ที่หมดอายุ และโค้ดมั่ว ดูว่าข้อความ error ถูกไหม
4. ใส่คูปองแล้วค่อยแก้ตะกร้า (ลดจำนวน ลบสินค้า) ดูว่าส่วนลดยังค้างอยู่ทั้งที่ไม่ผ่านเงื่อนไขแล้วหรือไม่
5. ส่งด่วน ฿120 + FREESHIP + ยอด ≥ ฿999 ดูว่าส่งด่วนฟรีด้วยไหม และตรวจราคาต่อชิ้น × จำนวน = ยอดรวมย่อย ปัดเศษ 10% ถูกไหม
6. ตัวนับ 🛒 บนหัวเว็บตรงกับตะกร้าไหม ตะกร้ายังอยู่ไหมหลัง reload / ปิดแท็บ / ล็อกอินหรือล็อกเอาต์ ถ้าเปิดสองแท็บแก้พร้อมกันจะเป็นยังไง
7. "ใส่ตะกร้า" จากการ์ดหน้าแรกหรือหน้ารวมสินค้าใส่ขนาดไหนลงไป
- ❌ **ห้ามกดยืนยันคำสั่งซื้อ** · ห้ามใช้บัญชี demo · ใช้บัญชีของตัวเอง `qa-c3-<เวลา>@pawpantry.test`

### C4 · สั่งซื้อจริง ประวัติคำสั่งซื้อ และสต็อกที่ลดลง (เจ้าของข้อมูลกลาง) — P1 · 60 นาที
**สำรวจ** การกดยืนยันใน `/checkout`, หน้ายืนยันคำสั่งซื้อ และ `/account` (ประวัติการสั่งซื้อ) **ด้วย** บัญชี `demo@pawpantry.test` (มีสิทธิ์ใช้คนเดียว), สินค้าใกล้หมด, คูปอง และวิธีชำระเงิน (ปลายทาง/PromptPay) **เพื่อหา** คำสั่งซื้อซ้ำ, สต็อกที่ไม่ลดหรือติดลบ, ยอดในประวัติไม่ตรงกับตอนจ่าย และการสั่งของที่หมดได้
สิ่งที่ต้องลองอย่างน้อย:
1. สั่งหนึ่งคำสั่งแบบปกติ แล้วเทียบยอด ส่วนลด ค่าส่ง และรายการในหน้ายืนยันกับใน `/account` ทุกบรรทัด

4. เตรียมตะกร้าที่มีของใกล้หมดไว้ในแท็บ A แล้วแท็บ B (บัญชีเดียวกัน) สั่งของนั้นจนหมดไปก่อน จากนั้นกลับมายืนยันในแท็บ A

### C5 · สมัคร เข้าสู่ระบบ และหน้าที่ต้องล็อกอิน — P2 · 45 นาที
**สำรวจ** `/register`, `/login`, `?next=`, การออกจากระบบ และการกันหน้า `/account` `/checkout` **ด้วย** อีเมลและรหัสผ่านทั้งแบบถูกและผิด, ค่าขอบเขตของกฎ "8 ตัว + มีตัวเลข", URL ที่แก้ `next` เอง **เพื่อหา** การตรวจข้อมูลที่หลุด, ข้อความ error ที่ผิดหรือเปิดเผยข้อมูลเกินจำเป็น, open redirect และสิทธิ์ที่ค้างหลังออกจากระบบ
สิ่งที่ต้องลองอย่างน้อย:
1. รหัสผ่านยาว 7/8 ตัว, ไม่มีตัวเลข, มีแต่ตัวเลข, เว้นวรรค, ยืนยันรหัสไม่ตรง, ไม่ติ๊กยอมรับเงื่อนไข, ไม่เลือกสัตว์เลี้ยง
2. อีเมลซ้ำ (ลองสมัครด้วย `demo@pawpantry.test` ซึ่งแค่ส่งฟอร์มสมัคร ไม่ได้ล็อกอิน), อีเมลตัวพิมพ์ใหญ่หรือมีช่องว่าง, อีเมลผิดรูปแบบ ทั้งตอนสมัครและตอนล็อกอิน
3. ล็อกอินผิดด้วย "บัญชีที่สมัครเอง" ดูว่าข้อความ error บอกว่าอีเมลไม่มีอยู่หรือรหัสผิดแยกกันไหม และมีล็อกบัญชีหรือจำกัดจำนวนครั้งไหม
4. `?next=` ปกติ (`/account`, `/checkout`), `next=https://evil.example`, `next=//evil.example`, `next=/nope` และส่ง next ต่อผ่านลิงก์ไปหน้าสมัคร
5. ออกจากระบบแล้วกด back หรือเข้า `/account` `/checkout` ตรง ๆ, ล็อกอินค้างอยู่แล้วเปิดหน้า `/login` `/register` ซ้ำ และดูว่าหัวเว็บแสดงชื่อผู้ใช้ถูกต้อง
6. ปุ่ม 👁️ แสดง/ซ่อนรหัส, กด Enter เพื่อส่งฟอร์ม, กด Tab ไล่ช่อง, ดูว่ามี label ครบทุกช่อง
- ❌ **ห้ามกรอกรหัสผิดกับบัญชี demo** (อาจทำให้บัญชีของ C4 ถูกล็อก) · ห้ามเปลี่ยนข้อมูลหรือรหัสผ่านของบัญชี demo

### C6 · ตัวช่วยเลือกอาหาร, แนะนำสำหรับคุณ และรายการโปรด — P2 · 45 นาที
**สำรวจ** `/finder` (3 ขั้น), กล่อง "แนะนำสำหรับคุณ" บนหน้าแรก และ `/wishlist` (ปุ่ม ♥ บนสินค้า + ตัวนับบนหัวเว็บ) **ด้วย** ทุกชุดคำตอบที่เป็นไปได้ (แมว/หมา × ช่วงวัย × ความต้องการพิเศษ), ประวัติการดูสินค้า และบัญชีที่สมัครเอง **เพื่อหา** ผลแนะนำที่ขัดกับคำตอบ (เช่น แนะนำของหมาให้แมว หรือแนะนำสินค้าหมด) และรายการโปรดที่หายหรือซ้ำ
สิ่งที่ต้องลองอย่างน้อย:
1. ตอบ Finder ครบทุกชุดคำตอบหลัก แล้วดูว่าผลตรงกับสัตว์ ช่วงวัย และความต้องการ (เช่น ทางเดินปัสสาวะ, ก้อนขน, เกรนฟรี) ไหม และมีสินค้าหมดโผล่มาไหม
2. ใน Finder: กด "ถัดไป" โดยยังไม่เลือก, ย้อนกลับไปเปลี่ยนคำตอบ, reload ระหว่างทาง, กด back ของเบราว์เซอร์
3. "แนะนำสำหรับคุณ": ดูสินค้าแมว 3–4 ชิ้นแล้วกลับหน้าแรก ดูว่าคำแนะนำเปลี่ยนตามไหม และมีสินค้าที่เพิ่งดูหรือสินค้าหมดปนมาไหม
4. ♥ เพิ่มแล้วเอาออก, กดรัว ๆ, เพิ่มสินค้าหมด ดูว่าตัวนับ ♥ ตรงกับหน้า `/wishlist` ไหม
5. รายการโปรดหลัง reload, หลังล็อกอินหรือล็อกเอาต์ และเปิดสองแท็บ ข้อมูลรวมกันหรือหาย
6. ปุ่มใส่ตะกร้าจากในหน้ารายการโปรดหรือผล Finder (ถ้ามี) ดูแค่ว่าตัวนับ 🛒 เพิ่มขึ้น ไม่ต้องทดสอบราคา (เป็นงานของ C3)
- ❌ ห้ามสั่งซื้อ · ใช้บัญชีของตัวเอง `qa-c6-<เวลา>@pawpantry.test`

### C7 · โครงเว็บร่วม หัว/ท้าย 404 มือถือ และการเข้าถึง — P3 · 30 นาที
**สำรวจ** หัวเว็บ ท้ายเว็บ เมนูมือถือ (ปุ่ม "เปิดเมนู") หน้า 404 และฟอร์มรับข่าวสาร **ด้วย** การย่อจอ (`playwright-cli resize 375 812`), คีย์บอร์ด, dark mode / forced-colors, console และ network **เพื่อหา** ลิงก์เสีย ปัญหา layout บนมือถือ ปัญหาการเข้าถึง (a11y) และ error ที่เกิดซ้ำทุกหน้า
สิ่งที่ต้องลองอย่างน้อย:
1. คลิกลิงก์ทั้ง 8 อันบนหัวเว็บและ 9 อันท้ายเว็บ ทั้งบนเดสก์ท็อปและมือถือ แล้วดูว่า active state ของเมนูถูกหน้าไหม
2. จอกว้าง 375px: เปิด/ปิดเมนู, กด Esc, กด Tab ไล่ไป ดูว่ามีจุดที่โฟกัสติดอยู่ หรือหน้าเลื่อนแนวนอนไหม
3. ฟอร์มรับข่าวสาร: ช่องว่าง, อีเมลผิดรูปแบบ, กดส่งซ้ำ, ข้อความยาว ดูว่าข้อความตอบกลับเป็นอย่างไร
4. หน้า 404: URL ภาษาไทย, path ลึก ๆ, มี `/` ต่อท้าย ดูว่า title และสถานะ HTTP ถูกไหม (ตอนนี้ title ยังเป็นชื่อหน้าแรก)
5. เก็บ console error และ request ที่ตอบ 4xx/5xx ทุกหน้า (ตอนนี้เห็น favicon 404), ลิงก์ "ข้ามไปเนื้อหา" (`#main`), alt ของรูป, ปุ่มที่เป็นไอคอนล้วนต้องมี aria-label
6. ตัวเลขสถิติบนหน้าแรก (28 สินค้า, 14/14/4) ต้องตรงกับแคตตาล็อก (แค่ดูตัวเลข ไม่ต้องลองตัวกรอง เพราะเป็นงานของ C1)
- ❌ ไม่ต้องล็อกอิน ไม่ใส่ตะกร้า

### 3.2 กติกาแยกพื้นที่ทำงาน
1. **session แยกกัน:** แต่ละ agent ใช้ `playwright-cli -s=c<N> open ...` (เช่น `-s=c3`) ห้ามใช้ session `default` ร่วมกัน เพื่อไม่ให้ cookie, localStorage, ตะกร้า หรือรายการโปรดปนกัน
2. **บัญชีแยกกัน:** ถ้าต้องล็อกอินให้สมัครบัญชีของตัวเอง ใช้อีเมล `qa-c<N>-<yyyymmddhhmm>@pawpantry.test` และรหัส `Paw12345` แล้วจดไว้ในรายงาน
3. **ไม่ต้องรอใคร:** ไม่มี charter ไหนต้องรอให้อีก charter เสร็จก่อน ยกเว้น C4 ซึ่งควรเริ่ม**หลัง** C2 ได้คำตอบเรื่อง "ใส่ตะกร้าแล้วจองสต็อกไหม" แล้ว (ประมาณ 10 นาทีแรก)
4. **เห็นข้อมูลเปลี่ยนเอง:** ถ้าเห็นสต็อกหรือข้อมูลเปลี่ยนโดยที่ตัวเองไม่ได้ทำ ให้ถือว่าเป็นผลจาก C4 ก่อน อย่าเพิ่งรายงานเป็นบั๊ก ให้เทียบกับบันทึกของ C4
5. **ต้องการ reset:** ถ้าต้องการสภาพเริ่มต้นใหม่ ให้ขอผู้ประสานงานแทนการเรียก reset เอง ผู้ประสานงานจะประกาศก่อน reset ทุกครั้ง
6. **ทับเขตกัน:** ถ้าเจอประเด็นที่เป็นของ charter อื่น ให้จดไว้ในหัวข้อ "ส่งต่อ" ของรายงาน แล้วไม่ต้องลงไปลองเอง
