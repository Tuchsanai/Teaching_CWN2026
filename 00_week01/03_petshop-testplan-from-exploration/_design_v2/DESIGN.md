## 5.1 ร่างพรอมต์ PawPantry LAB 0–2 (ปรับต่อหลังเห็นผลจริงทีละ LAB)

**LAB 0**
```text
เตรียมเครื่องมือสำรวจแบบขนาน แล้วเปิดเว็บ PawPantry (ห้ามเปิดอ่านโค้ดในโฟลเดอร์ petshop)
1. ติดตั้ง playwright-cli: npm install -g @playwright/cli@latest แล้วรัน playwright-cli install --skills ในโฟลเดอร์นี้
2. ลองเปิดเบราว์เซอร์ 2 ตัวพร้อมกัน ชื่อ a และ b (playwright-cli -s=a open https://example.com) แล้ว playwright-cli list ต้องเห็น 2 ตัว จากนั้นปิดทั้งหมด
3. ในโฟลเดอร์ petshop รัน docker compose up -d --build รอจน healthy แล้วเช็กว่า http://localhost:3000/api/health ตอบอะไร
สรุปเป็นตาราง ขั้น | ผล
```

**LAB 1 · แบบ A (มีความรู้เดิม) / แบบ B (ไม่มี)**
```text
วางแผนการสำรวจเว็บ http://localhost:3000 ก่อนลงมือ (ห้ามเปิดอ่านโค้ดใน petshop และห้ามเปิดโฟลเดอร์ _solution)
[A] ใช้ความรู้ที่มี: TEST-DATA.md + ความรู้ทั่วไปว่าร้านขายของออนไลน์มักมีฟีเจอร์อะไร
[B] ไม่ใช้ความรู้เดิม: ใช้ playwright-cli เดินทุกเมนูและลิงก์ 1 รอบเร็ว ๆ (ไม่กรอกฟอร์ม) ทำแผนผังหน้าก่อน
แล้วเขียน CHARTERS.md:
1. รายการฟีเจอร์ที่คิดว่ามี | อยู่หน้าไหน | ที่มาของข้อมูล (เห็นจริง / เดาจากความรู้)
2. แบ่งเป็น charter 5–7 ข้อ ไม่ทับกัน รูปแบบ "สำรวจ <ส่วนไหน> ด้วย <ข้อมูล/เครื่องมือ> เพื่อหา <กฎ ความเสี่ยง>" พร้อมระดับความเสี่ยงที่เดาไว้ P1/P2/P3 และเวลาที่ให้ (นาที)
3. กติกากันชนกัน: charter ไหนเปลี่ยนข้อมูลกลาง (สั่งซื้อ ลดสต็อก reset) ให้มีเจ้าของคนเดียว
```

**LAB 2 · สำรวจขนาน**
```text
อ่าน CHARTERS.md แล้วแบ่ง subagent 1 ตัวต่อ 1 charter ทำงานพร้อมกัน
แต่ละตัวใช้ playwright-cli ด้วย session ของตัวเอง (playwright-cli -s=<ชื่อ charter>) ห้ามใช้ session ร่วมกัน
ห้ามเรียก /api/test/reset ระหว่างที่ตัวอื่นยังทำงาน · ห้ามเปิดอ่านโค้ดใน petshop และโฟลเดอร์ _solution
แต่ละตัวเขียน exploration/<ชื่อ charter>.md: หน้า/สถานะที่เจอ | ฟีเจอร์ | กฎ (ตัวอย่างที่ลอง ผลที่เห็น ที่มา [D]/[R]/[O]) | ความเสี่ยง | คำถามถึงทีม | ภาพหลักฐานใน exploration/<ชื่อ charter>/
ผลที่เห็นขัดกับ TEST-DATA หรือกฎทั่วไป ให้ทำเครื่องหมาย ⚠️ ห้ามตัดสินว่าหน้าจอถูกเสมอ
เสร็จแล้วสรุปตาราง charter | เวลา | จำนวนกฎ | ⚠️ | คำถาม
```
