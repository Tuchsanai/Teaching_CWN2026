# Scenarios ลูกค้า — fixture v3

**Fixture สมมติที่สร้างใหม่ ไม่ใช่ scenarios ต้นฉบับ และห้ามส่งกลับเป็นต้นฉบับ.**
สถานะทุกกรณี: **NOT_RUN**; ช่องผลจริง/หลักฐานยังไม่มีข้อมูล. baseline JSON มีเพียง pointer ไปยังสามไฟล์ที่ไม่พบ จึงไม่ทราบรหัส scenario เดิม; รหัส CHG- ในไฟล์นี้เป็นรหัสใหม่ของการทดลอง ไม่ใช่การเปลี่ยนชื่อรหัสเดิม.

UI เป้าหมาย `../ui-mockup-v3.html`; FR authority `../fr-nfr-v3.md`; Flow `../flow-v3.md`. JSON manifest resolve paths จาก directory ที่เก็บ JSON. ทุก expected ต่อไปนี้คือเกณฑ์ตรวจภายหลัง ไม่ใช่ผลที่สังเกตแล้ว.

เริ่มแต่ละกรณีด้วย browser context ใหม่ เปิด UI แล้วกด `btn-reset`; ข้อมูลจำลองเวลา 2026-01-01T12:00:00+07:00, ช่วง 11:30–13:30, N=3, X=10, คิวว่าง. หนึ่ง context ใช้แท็บเดียวแชร์ state ระหว่างบทบาท; ไม่ reload กลางกรณี. บทบาทลูกค้าไม่ล็อกอิน; พนักงาน/ผู้จัดการเลือก role แล้วเลือก `staff-user`, กรอก `staff-pin` เป็น 0000 และกด `btn-login` ทุกครั้งที่สลับเข้าใหม่. บัญชี demokitchen/demofront/demomanager เป็น placeholder สาธารณะทั้งหมด.

Helper “ส่งหนึ่งใบ”: ลูกค้าเลือก `table-select=01`, `btn-open-menu`, `menu-item-m01`, `btn-add-item`, `btn-submit-order` (ถ้าเปิดโต๊ะอยู่แล้วไม่ต้องเปิดซ้ำ). หนึ่งใบเพิ่มเลข `order-id` หนึ่งและล้าง `cart-count`; หลายจานต้องกดเพิ่มหลายครั้งก่อน submit เดียว. สลับโต๊ะแล้วต้องกด `btn-open-menu` จึงเปลี่ยน active session. ในตัวตรวจใช้ `[data-testid="ชื่อ"]`; scope ใบครัว/หน้าร้านด้วย `data-order-id` และรายการด้วย `item-resolution[data-item-id]` ไม่ใช้ locator ของรายการซ้ำทั่วหน้า.

ผู้ทดลองเก็บ case ID, context/รอบ, seed/ค่าตั้ง, sim-clock, steps, expected เทียบ actual, screenshot ก่อน/หลังและ trace/console error. แยกผล smoke ใน mock กับ AC ระบบจริงและจำนวนตัวอย่างตาม FR. ห้ามนับภาพหลายภาพแทนรอบหรือใช้เวลาจำลองเป็นเวลา LAN. ใน pre-run นี้ไม่มีการรัน browser หรือ UI tests.

## CHG-C01 — QR/โต๊ะ/ตัวเลือกและการสั่ง (US-01/02/04)

1. เปิดโต๊ะ 01 โดยไม่ล็อกอิน; ตรวจ `active-table`, `session-id`, `menu-list`.
2. เลือก m01, ติ๊ก `option-extra-egg`; `item-total` ต้อง 60 บาท; เพิ่มแล้ว `cart-total=60`, `cart-count=1` ก่อนยืนยัน. ส่งออเดอร์และบันทึก order ID.
3. สลับเข้าครัวและหน้าร้านตามสิทธิ์; ใบของ ID เดียวกันต้องมีโต๊ะ 01, m01 และไข่เพิ่ม, ยอด 60. เปิดโต๊ะ 02 แล้วต้องแยก session/รายการจากโต๊ะ 01.
4. กลับโต๊ะ 01 โดยไม่ reset; ประวัติเดิมยังอยู่. QR ที่นี่เป็น fixture select ไม่ใช่การสแกนจริง.

เกณฑ์จริงคง US-01 3 วินาทีบน Wi-Fi ≥18/20, US-02 table_id ตรง ≥19/20 จาก 20 โต๊ะ, US-04 ตัวเลือกครบ ราคาเพิ่มก่อนยืนยันและใบครัว ≥19/20. Fixture มีเพียงสามโต๊ะ จึงยังไม่พิสูจน์ชุด 20 โต๊ะ.

## CHG-C02 — สั่งกลับบ้าน (US-03/15)

เลือก `order-mode=takeaway` ณ 12:00; `pickup-slot` แรกต้องเป็น 12:30-12:45 (เริ่มอย่างน้อย 20 นาที ช่วงละ 15 นาที). ส่ง m02 สองใบแยกกัน; `takeaway-id` เป็น T-001/T-002. ใบครัวและหน้าร้านแสดง “สั่งกลับบ้าน” พร้อมช่วงรับตรงกัน. สลับบทบาทแล้วเลขไม่ reset. กด `[data-action="advance"][data-minutes="1440"]` แล้วเลือกช่วงใหม่/ส่งอีกใบ เลขเป็น T-001 ของวันใหม่ใน fixture. การเปลี่ยน N ไม่เปลี่ยน pickup slot หรือขั้นต่ำ 20 นาที.

เกณฑ์จริง US-03 ป้ายและช่วงรับครบ 10/10; US-15 โต๊ะ/หมายเลขรับและสถานะ/log 20/20. Midnight ระบบจริงยังต้องตรวจภายนอก.

## CHG-C03 — เมนูหมดและตะกร้าค้าง (US-06/12/13/20)

เพิ่ม m01+ไข่ในตะกร้า ยังไม่ส่ง. ครัวเลือก `ingredient-select=egg`, กด `btn-out-of-stock`; ลูกค้าต้องเห็น extra-egg disabled, m01 หลักยังขายได้, m03 ทั้งจานหมด. ส่งตะกร้าเดิม: `order-message` มี “หมด”, ไม่เพิ่มใบครัว/เลขออเดอร์หรือจำนวนความจุ. กดกลับมามีแล้วสั่งได้อีก. ทำซ้ำ chicken: m01 ทั้งจาน disabled. ถ้า egg ยังหมดแล้วคืน chicken, m01 เปิดได้แต่ไข่ยัง disabled. การปฏิเสธจากวัตถุดิบคงอยู่แม้ N=3; ไม่ใช่กฎปฏิเสธจากครัวเต็ม.

เกณฑ์จริง US-06/13 ภายใน 10 วินาทีบน LAN ≥9/10; แมป US-12 วัตถุดิบ 5 ชนิด 5/5, US-20 5 เมนู 5/5 ตาม AC; smoke นี้ไม่ครบจำนวนตัวอย่าง.

## CHG-C04 — ETA แยกจากคำเตือนความจุ (US-07/21)

เปิดตะกร้าก่อนและหลังมีสามออเดอร์ยืนยันในหน้าต่างเดียวกัน. ข้อความ US-07 ยังคง “ยังประมาณไม่ได้” เพราะ fixture ไม่มีค่าเฉลี่ย 7 วัน/ต่อเมนู; X=10 ต้องมีป้าย “X เป็นค่าจำลอง ยังไม่ยืนยันสูตร” และไม่แทน ETA. การตรวจ threshold สามรอบใช้ CHG-21-R1/R2/R3 ใน manager.md.

AC US-07 คงสูตร (คิวที่ยังไม่พร้อมเสิร์ฟ × เวลาเฉลี่ยต่อออเดอร์ 7 วันล่าสุด) + เวลาเฉลี่ยต่อเมนูที่นานที่สุด; วัดจริงยืนยันสั่ง→ครัวพร้อมเสิร์ฟจาก server log, ช่วง 11:30–13:00 และ 17:30–19:30 ของหนึ่งวัน, คลาดเคลื่อนไม่เกิน 10 นาที ≥80%. ชุดนี้ไม่พิสูจน์ความแม่นยำ ETA; NOT_TESTED.

## CHG-C05 — เงินสดและ PromptPay สามกรณี (US-08/15)

ใช้ context ใหม่แยกแต่ละกรณี ส่ง m01+ไข่ 60 บาท แล้วเทียบยอดลูกค้า/หน้าร้านก่อนยืนยันเงิน:

| กรณี | การกระทำ | Expected fixture |
|---|---|---|
| ปกติ | ลูกค้า `pay-promptpay`, หน้าร้าน `btn-confirm-slip` ในใบเดียวกัน | ค้างจ่ายจนหน้าร้านยืนยัน แล้วจ่ายแล้ว; payment-log มีผู้ใช้จำลอง/เวลา/ID |
| ปิดใช้งาน | ผู้จัดการปิด `toggle-promptpay`, ลูกค้าเปิดหน้าจ่าย เลือกเงินสด และหน้าร้าน `btn-receive-cash` | ข้อความเงินสด; เลือกเงินสดอย่างเดียวยังไม่จ่าย; หน้าร้านยืนยันจึงจ่ายแล้ว |
| สลิปยังไม่ยืนยัน | ลูกค้าเลือก PromptPay แล้ว `btn-advance-10m` และ +1 นาที ก่อนเข้าหน้าร้านรับเงินสด | แสดงทางออกเงินสดทั้งที่ถึงและเกิน 10 นาที; ไม่ยืนยันจ่ายเอง; log หลังการกดจริงใน fixture |

ต้องยังมีตัวเลือกจ่ายสองแบบตาม AC; ข้อค้างความหมายขณะปิด PromptPay คงเดิม. AC ยอดตรง ≥19/20 และ fallback 3/3; log และสถานะ US-15 20/20. ไม่เรียกบริการชำระเงินจริง.

## CHG-C06 — ครัวทำไม่ได้/คืน/เปลี่ยน (US-09/14/08/19)

คู่กับ CHG-K03 ใน kitchen-front.md. สร้างใบ 115 บาท (m01+ไข่=60 และ m02=55). ครัวกดทำไม่ได้เฉพาะจาน 60; ลูกค้าเห็น `customer-unavailable-alert` ใน `customer-resolution-order` ของ ID นั้น แม้ไม่ใช่ใบล่าสุด. ต้องเห็นสองปุ่มและสถานะรอลูกค้าตัดสินใจ. แต่ละทางเลือกเริ่มข้อมูลใหม่: คืนแล้ว adjusted total=55; เลือก m02 ดู preview แล้วกดเปลี่ยน ยอด=110. ทั้งสองคง snapshot 115, ไม่เพิ่ม order ID/จำนวนความจุ, ไม่ประกาศโอนคืนเงินสำเร็จ. ไม่เลือกเมนูหรือเลือกเมนูที่หมดต้องคง pending ตาม fixture.

เกณฑ์จริงแจ้งถึงลูกค้า ≤10 วินาทีบน LAN 5/5 และผลจากลูกค้าถึงครัว ≤10 วินาที 5/5 แยกชุด/ทิศทาง. ใช้ห้ากรณีและบันทึกทั้งสองทิศทางตาม CHG-K03; ไม่ใช้จำนวนภาพแทน 5 กรณี.

## CHG-C07 — ขนาดจอและการเข้าถึงคำเตือน

ผู้ทดลองตรวจ desktop และ mobile ด้วยสคริปต์เดียวกันทั้งสองวิธี; viewport เป็น fixture ให้บันทึกค่าจริง. ที่ count=3 ใช้ Tab เข้าปุ่ม submit, ตรวจข้อความเต็มและป้าย X มองเห็น ไม่ถูกตัด/ทับ และลำดับ DOM ก่อนปุ่ม. ตรวจ keyboard/select/native buttons เดิมและ console. เกณฑ์ viewport เป็นการตรวจ mock เพิ่ม ไม่ใช่ AC ร้านใหม่.
