# ผลรันจริงของชุดสาธิตเกณฑ์ E1

ชุดนี้เป็นการสาธิตแยก ไม่ใช่ผลของลูปหลัก และไฟล์ส่งต่อไป LAB 003 ยังคงเป็น final/fr-nfr-input.md (v1)

ในหลักฐานของ LAB ไฟล์ส่งต่อดังกล่าวคือ [reference/final/fr-nfr-input.md](../final/fr-nfr-input.md) ซึ่งตรงกับ [v1 เดิม](../step-01/round-1/fr-nfr-v1.md) ทุกไบต์ ชุด E1 ใช้ v1 เดิมเป็น Input โดยไม่ได้เรียก generator ใหม่ ไม่ใช่การรันทั้งชุดจาก v0 ซ้ำ ผล [ลูปหลัก](../loop-log.json) ยังเป็น PASS 90/90 ตั้งแต่ checker รอบแรกและไม่มีการเรียก fixer ในลูปหลัก

## เกณฑ์และสมมติฐานที่ตรึงก่อนรัน

เพิ่มเกณฑ์ตามขั้น 05 ผ่าน prompt-used.md ของแต่ละรอบ ไม่แก้ prompts/ หรือ input/:

> เกณฑ์เพิ่ม: E1 | AC แต่ละข้อมีรหัสไม่ซ้ำและวิธีตรวจอ้างรหัสนั้นตรงกันทุกข้อ

ตีความ “AC แต่ละข้อ” ให้ครอบคลุม FR และ NFR ที่เกี่ยวข้องกับ US นั้น รหัสประกอบ FR/NFR ID ใช้ได้ถ้าตามรอยชัดเจน ไม่บังคับรูปแบบรหัสเฉพาะ และไม่เพิ่มกฎธุรกิจหรือค่าบังคับจากที่อื่น คง F/B/A/V/N เดิมและเพิ่ม E1 ให้ทั้ง 18 US รวม 108 คู่ตลอดชุด Checker รอบแรกไม่มีผลก่อนหน้าในชุด E1; รอบถัดไปใช้ผลตรวจก่อนหน้าทุกฉบับในชุดนี้ เพดาน checker 3 รอบและหยุดทันทีเมื่อ PASS

เรียก CLI ตรงทีละรอบ เริ่ม session ใหม่ทุกครั้ง ใช้ Codex CLI 0.154.0, gpt-6-astra (ตาม flag ที่สั่ง CLI ไม่ยืนยันกลับ), effort high โดยให้ CLI บันทึกคำตอบสุดท้าย ไม่มีการแก้ผลตอบด้วยมือ

## ข้อจำกัด

ผลนี้ตรวจคุณภาพเอกสาร ไม่ใช่ผลทดสอบระบบร้านจริง ไม่ได้วัดประสิทธิภาพ runtime หรือยืนยันข้อมูลหมายเหตุที่ต้นฉบับไม่ได้ให้ การทดลองหนึ่งชุดยังไม่พิสูจน์เหตุ–ผลของเกณฑ์ E1 เพราะคำตอบ AI แปรผันได้ และเวลาในชุดนี้ไม่รวม generator เดิม

ลูปหลักได้ 90/90 ตามเกณฑ์ 5 ข้อ ส่วนชุดนี้ใช้ 108 คะแนนเต็ม จึงต้องเทียบคะแนนพร้อมตัวหาร ไม่เทียบคะแนนดิบอย่างเดียว ร่างหลังแก้ของชุดสาธิตเก็บเพื่อศึกษาการแก้ตาม Feedback; ไฟล์ส่งต่อไป LAB 003 ยังคงเป็น v1 เดิม
