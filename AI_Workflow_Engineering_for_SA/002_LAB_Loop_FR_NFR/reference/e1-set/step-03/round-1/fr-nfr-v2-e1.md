ที่มา baseline ที่ร่าง v1 บันทึกไว้: **ใช้ผลอ้างอิงจาก LAB 001** ตาม `work/baseline-source.txt` โดยใช้สำเนา `work/fr-nfr-v0.md` ต้นทาง `../001_LAB_Single_Prompt_Baseline/reference/step-02/round-1/fr-nfr-v0.md` วันที่ผล 2026-09-14 เวลา 10:28:10–10:31:52 UTC ข้อความนี้สืบทอดจาก v1 โดยไม่ได้เปิดไฟล์เหล่านั้นเพิ่มเติม และไม่ใช้เป็นหลักฐานว่าเคยผ่านการตรวจในชุด E1

ยึด US ต้นฉบับเป็นหลัก ใช้ `prompts/checker-criteria.md` ฉบับเดิมครบถ้วนร่วมกับเกณฑ์เพิ่มที่ตรึงไว้: **E1 — AC แต่ละข้อมีรหัสไม่ซ้ำและวิธีตรวจอ้างรหัสนั้นตรงกันทุกข้อ** ครอบคลุม AC ใน FR และ NFR ที่เกี่ยวข้องกับแต่ละ US รวม 18 US × 6 เกณฑ์ = 108 คู่ เกณฑ์ F/B/A/V/N คงเดิม การให้ PASS=1 หรือ FAIL=0 ไม่มีคะแนนบางส่วนเป็นหน้าที่ checker เอกสารนี้ไม่กำหนดผลล่วงหน้า

แก้ตาม FAIL ของ E1 จำนวน 16 คู่ โดยเพิ่มรหัส AC แยกข้อความรวมตามกฎเดิม และระบุรหัสในวิธีตรวจ คง FR/NFR ID เดิมทั้งหมด รวมทั้งกฎ ตัวเลข หน่วย สูตร สัดส่วน จุดเริ่ม–จบเวลา และเครือข่าย ตาราง regression ท้ายเอกสารครอบคลุม 92 คู่ที่เคย PASS ในผลตรวจที่ระบุ

สภาพแวดล้อมตามต้นฉบับคือ Ubuntu เครื่องเดียวในร้านและ LAN/Wi-Fi ร้าน การใช้งานออฟไลน์หมายถึงอินเทอร์เน็ตภายนอกขาด แต่เครื่อง Ubuntu และเครือข่ายภายในยังทำงาน จำนวนเงินงบประมาณ **ไม่มีข้อมูลในต้นฉบับ**

**ตาราง FR**

เลขข้อภายใน AC ใช้จับคู่กับวิธีตรวจของ FR แถวนั้น โดยรหัสเต็มคือ `FR-ID/เลขข้อ` เช่น `FR-03/1` และ `FR-03/2` เลข `1)` ในวิธีตรวจของแถว FR-03 จึงอ้าง AC `FR-03/1` โดยตรง การอ้างช่วง เช่น `2–4)` หมายถึงตรวจ AC เลข 2, 3 และ 4 ของ FR แถวนั้นครบทุกข้อ กติกานี้คงการจับคู่เดิม โดยเฉพาะ FR-03 และ FR-04 ซึ่งเคย PASS E1 ไม่เปลี่ยนเลขข้อเดิม สำหรับ FR ที่เดิมไม่มีเลขข้อ เพิ่มเลขและรหัสเต็มกำกับในวิธีตรวจให้ชัดเจน

การเตรียมข้อมูลและการทดลองค่าขอบเขตเป็นวิธีตรวจที่เสนอ ไม่ใช่ข้อกำหนดธุรกิจเพิ่มเติม สำหรับการวัดเวลาข้ามอุปกรณ์ ให้บันทึกเหตุการณ์ต้นทางและปลายทางด้วยหลักฐานเวลาที่เทียบกันได้ พร้อมระบุอุปกรณ์และสภาพเครือข่ายที่ใช้จริง ตัวเลขใน AC เป็นเกณฑ์สำหรับการตรวจในอนาคต

**ตาราง NFR — ประสิทธิภาพ/เวลาตอบสนอง**

คง NFR ID ที่เกี่ยวข้องจาก v1 ซึ่งสืบทอดจาก v0 การแยก NFR ไม่ตัดกฎธุรกิจออกจาก FR เกณฑ์เวลาที่ไม่มีสภาพเครือข่ายหรือสัดส่วนกำหนดเฉพาะในแถวต้นฉบับจะไม่ถูกเพิ่มขึ้นเอง

**ประวัติรายการเปลี่ยนจาก v0 ที่สืบทอดจาก v1**

รายการนี้เป็นประวัติที่บันทึกในร่างเดิม ไม่ใช่การดำเนินการใหม่ในชุด E1 และไม่ใช้แทนผลตรวจรอบก่อนหน้า

1. จำกัดเอกสารจาก baseline 26 US เหลือ 18 แถวตาม Input ของ LAB 002 โดยไม่แก้ baseline และไม่เพิ่มขอบเขตจากรหัสอ้างในเซลล์
2. คง FR ID เดิมทั้งหมดที่อยู่ในขอบเขต ได้แก่ FR-01–FR-08, FR-10–FR-13, FR-15–FR-16, FR-19–FR-20 และ FR-25–FR-26 จึงเทียบ ID ระหว่าง v0 กับ v1 ได้โดยตรง เลขที่เว้นไว้ไม่ถูกนำมาใช้กับข้ออื่น
3. คง NFR ID ที่เกี่ยวข้อง 15 ข้อ ได้แก่ NFR-01–NFR-04, NFR-06–NFR-08, NFR-11–NFR-12, NFR-16–NFR-19, NFR-21–NFR-22 และเพิ่มคอลัมน์หมวดให้ชัด แยกความแม่นยำเวลารอ การตรวจสอบย้อนหลัง และการติดตั้งออกจากหมวดอื่น
4. ขยายวิธีตรวจให้ระบุข้อมูลเตรียม การกระทำ หลักฐานและการตัดสินรายกฎ โดยเฉพาะคำสั่งเมนูที่ปิดแล้ว การเรียงพร้อมกันจากสองมือถือ การรีเซ็ตเลขรับข้ามวัน การตรวจ session เดิม และการตรวจ URL โดยตรง
5. แยกการนับผลที่มีสัดส่วนออกจากกฎที่ต้องครบ เช่น ความตรงของชุดเปิดคืนไม่ถูกลดเหลือเพียงเกณฑ์เวลา 9 จาก 10 และความครบของตัวเลือก/ราคาเพิ่มไม่ถูกแทนด้วยสัดส่วนใบครัว 19 จาก 20
6. ทำ traceability ใหม่ให้มี 18 แถว พร้อมเหตุผลสำหรับ US ที่ไม่มีหมวด NFR บังคับ และคงกฎไว้ใน FR ทุกข้อ
7. รวมคำถามที่เกี่ยวข้องไว้ในเอกสารนี้ ไม่ต้องอาศัยรหัสประเด็นจากเอกสาร LAB 001 เพื่อเข้าใจสิ่งที่ยังขาด คงหมายเหตุ ก./ค./ช. เป็นข้อมูลขาด และคง US-14 ใน FR-20 อย่างเปิดเผย
8. ไม่ยกระดับข้อเสนอเดิมเรื่องการแมปสถานะ การแก้ dependency หรือการจำลองระบบให้เป็นข้อกำหนดที่ยืนยันแล้ว ไม่มีผลทดสอบหรือสถิติการรันใหม่แนบมากับ v1

**ข้อมูลขาด ข้อขัดแย้ง และคำถามรอยืนยัน**
