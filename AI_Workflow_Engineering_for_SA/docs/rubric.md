# Rubric และตารางบันทึกผลต่อ LAB

เกณฑ์ฉบับร่างนี้ใช้ 5 มิติ ระดับ 0–3 สำหรับการสอนกรณีศึกษาใน [ต้นฉบับ](../../appendix-a-restaurant.md) ไม่ใช่ผลประเมินที่รันแล้ว

ประเมินด้วย Input ขอบเขต US เกณฑ์ และเงื่อนไขทดลองเดียวกันเมื่อเปรียบเทียบ workflow บันทึกเครื่องมือ รุ่น/โมเดลที่ตรวจสอบได้ เพดานรอบ เวลา งบ และชิ้นงานเวอร์ชันที่ใช้ในหลักฐาน ขอบเขต LAB ต่างกันจึงไม่ควรเทียบคะแนนดิบโดยไม่ระบุขอบเขตร่วม

**ไม่มีข้อมูล** หมายถึงยังไม่ได้วัด/ยังไม่มีหลักฐาน ไม่เท่ากับคะแนน 0 ให้คะแนน 0 ได้เมื่อมีหลักฐานว่าผลงานอยู่ในระดับนั้น มิติที่ยังไม่เกี่ยวกับชิ้นงานของ LAB เช่น UI ใน LAB แรก ให้คง “ไม่มีข้อมูล” พร้อมเหตุผลและไม่รวมในคะแนนรวม

## เกณฑ์ 5 มิติ ระดับคะแนน 0–3

| มิติ | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| M1 ความครบถ้วนบทบาท/กฎธุรกิจ/FR-NFR/AC ทดสอบได้ | ตรวจแล้วไม่มีการวิเคราะห์ที่ใช้ได้ตามขอบเขต บทบาทและกฎหลักขาด และ AC ใช้ทดสอบไม่ได้ | มีบางบทบาทหรือ FR แต่ตกหล่นกฎ/ตัวเลขสำคัญ NFR หรือ AC ยังคลุมเครือ | ครบทุกบทบาทในขอบเขต มีกฎ FR/NFR และ AC ที่วัดได้เป็นส่วนใหญ่ เหลือช่องว่างที่ระบุชัด | ครบ US และบทบาทในขอบเขต รักษากฎ/ตัวเลขเดิม แยก FR/NFR และมีวิธีตรวจ AC ทุกข้อ รวมข้อจำกัดที่ต้องตรวจในระบบจริง |
| M2 ความสอดคล้องและตรวจย้อนกลับ | ตรวจแล้วชิ้นงานหลักขัดกันและหา US ต้นทางไม่ได้ | มีรหัสอ้างอิงบางส่วน แต่ลิงก์ข้ามชิ้นงานขาดหรือไม่ตรง | ตรวจย้อนกลับได้เป็นส่วนใหญ่ ความขัดแย้งมีทะเบียนและผู้รับผิดชอบแก้ แต่ยังมีจุดเชื่อมขาด | ทุกชิ้นงานที่กำหนดใน LAB เชื่อม US→FR/NFR→Flow/โครงสร้าง→UI→Test ตามขั้นที่มี ตรวจพบต้นทางและผลกระทบได้ ไม่มีข้อขัดแย้งที่ซ่อนไว้ |
| M3 ความสำเร็จ UI ตาม Test Scenarios | รันทดสอบแล้วเส้นทางหลักทำไม่สำเร็จหรือเปิด UI ไม่ได้ตามวิธีในคู่มือ | เส้นทางหลักผ่านเพียงบางส่วน ยังมีขั้นต่อเนื่องหรือบทบาทที่ใช้ไม่ได้ | เส้นทางหลักในขอบเขตผ่าน แต่บางทางเลือก/ข้อผิดพลาด/ข้อยกเว้นยังตก มีหลักฐานระบุชัด | ทุก Test Scenario ของ UI ในขอบเขตผ่านทั้งเส้นทางหลัก ทางเลือก ข้อผิดพลาด และข้อยกเว้น มีขั้นทำซ้ำและหลักฐาน แยกการจำลองออกจาก NFR ระบบจริง |
| M4 ข้อขัดแย้ง/ตกหล่น/สมมติฐาน/รับมือข้อกำหนดเปลี่ยน | ตรวจแล้วพบการละเลยข้อขัดแย้งหรือแต่งข้อมูลแทนส่วนที่ขาด และเปลี่ยนงานโดยไม่ตรวจผลกระทบ | ระบุปัญหาบางข้อแต่ไม่แยกสมมติฐานหรือไม่บันทึกผลกระทบจากข้อมูลเพิ่ม | มีทะเบียนปัญหา/สมมติฐานและปรับแผนตามข้อมูลเพิ่ม แต่เหตุผล dependency หรือการตรวจซ้ำส่วนใช้ซ้ำยังไม่ครบ | แยกข้อเท็จจริง/ข้อสงสัย/สมมติฐานชัด แสดงแผนก่อน–หลัง เหตุผล งานและ dependency ที่เปลี่ยน ชิ้นงานกระทบ ส่วนใช้ซ้ำ/ตรวจใหม่ และสถานะข้อที่ยังรอยืนยันครบ |
| M5 เวลา/รอบ/จำนวนเรียก/ต้นทุนที่วัดได้ | ตรวจหลักฐานแล้วตัวเลขไม่ตรวจย้อนกลับหรือเงื่อนไขทดลองไม่พอให้ประเมินการใช้ทรัพยากร | มีค่าจริงบางส่วน แต่ขาด log นิยามการนับ หรือข้อมูลที่จำเป็นต่อการเทียบ | มีเวลา รอบ จำนวนเรียก และโทเคนจาก log พร้อมเพดานทดลอง แต่เงื่อนไขเทียบหรือการคำนวณต้นทุนยังอธิบายไม่ครบ | มี log และวิธีนับตรวจซ้ำได้ เทียบขอบเขต/เงื่อนไขเดียวกัน อธิบายคุณภาพเทียบทรัพยากร แยกต้นทุนจริง/ประมาณพร้อมที่มา หรือระบุไม่มีข้อมูลพร้อมเหตุผลเมื่อคำนวณไม่ได้ |

M5 ประเมินความครบถ้วนและความน่าเชื่อถือของการวัด ไม่ให้คะแนนสูงเพียงเพราะใช้เวลาสั้นหรือเรียกน้อย และไม่ลงโทษการเปิดเผยอย่างถูกต้องว่าต้นทุนเงินยังไม่มีข้อมูล

## วิธีบันทึกเมื่อมีผลจริง

- เวลาใช้เวลาที่วัดจริงของช่วงทดลอง ระบุจุดเริ่ม/จบและวิธีวัด แยกเวลารวมออกจากเวลาแต่ละเรียก
- รอบคือรอบสร้าง–ตรวจ–แก้ตาม workflow; จำนวนเรียกนับการเรียก AI จริง รวมครั้งที่แก้และล้มเหลว โดยระบุวิธีนับในหลักฐาน
- โทเคน in/out อ่านจาก usage ใน log จริง เช่น `turn.completed.usage` ของ Codex CLI; ถ้าเครื่องมือไม่ส่งค่า ให้บันทึก “ไม่มีข้อมูล” พร้อมเหตุผล ตรวจสถานะล้มเหลวก่อนใช้ผล
- ต้นทุนเงินจริงต้องมีข้อมูลค่าใช้จ่ายที่ตรวจสอบได้ หากประมาณจากโทเคน ให้ระบุว่า “ค่าประมาณ” พร้อมราคา รุ่น วันที่ แหล่งราคา และวิธีคำนวณ ถ้าไม่มีข้อมูลเพียงพอให้คง “ไม่มีข้อมูล” ไม่ใช้ 0 แทน
- หลักฐานระบุ Input, Prompt, Output, log, ผลตรวจ และเวอร์ชันชิ้นงานที่ใช้จริง เพิ่มลิงก์เมื่อไฟล์นั้นมีอยู่แล้ว ผลอ้างอิงที่นำมาใช้เรียนต่อให้ระบุว่าเป็นผลอ้างอิง ไม่ใช่ผลที่นักศึกษารันเอง
- ประเมินแต่ละมิติจากหลักฐาน เก็บเหตุผล ข้อที่ตก การแก้ และผลตรวจซ้ำก่อนส่งต่อ LAB ถัดไป ไม่เขียนทับหลักฐานรอบก่อน

ตารางนี้เป็นแบบฟอร์มก่อนรัน จึงยังไม่มีคะแนนและค่าทรัพยากร; ผลที่ตรวจแล้วดู [รายงานทดสอบ](test-report.md)
