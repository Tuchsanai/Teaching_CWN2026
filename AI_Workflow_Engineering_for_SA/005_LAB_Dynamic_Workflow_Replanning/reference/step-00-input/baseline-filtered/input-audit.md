## ขอบเขต US และข้อมูลที่หลุด

อ่าน US ตั้งต้นเพียง 18 แถว: US-01–US-08, US-10–US-13, US-15–US-16, US-19–US-20 และ US-25–US-26 ไม่เปิดแถวอื่นจากการอ้างรหัสในเซลล์ ไม่แก้ข้อความ US/AC ตัวเลข หน่วย หรือสัดส่วนทดสอบ

จุดที่ทำให้ BLOCKED คือ state-machine.md:271 และ structure.md:201 ในแถว DI-04 ซึ่งยังอธิบายสาระของ US-14 จากเอกสารประกอบเดิม ไม่ใช่เพียงข้อความอ้างรหัสที่อนุญาตให้คงใน US-20 บันทึกเฉพาะตำแหน่งเพื่อไม่ส่งต่อเนื้อหาที่หลุดซ้ำ หยุดการผลิตงานและ plan-v1 ณ ขั้นนี้ ไม่แก้ชุดกรองหรือสร้างชุดทดแทนเอง

## ความสอดคล้องของรุ่นและข้อจำกัดหลักฐาน

FR มีชื่อภายใน v1 แม้ต้นทางถูกจัดไว้ใน final; เลือกตาม provenance และหลักฐานตรวจ ไม่อนุมานว่าฉบับเลขสูงสุดผ่าน Flow อ้าง hash FR ตรงกับ fr-nfr.md ที่คัดมา และอ้างเอกสารประกอบจาก node ที่ provenance ระบุไว้ UI ใช้สัญญา mock ของ LAB 004 และแสดงข้อค้างสถานะ/การชำระ/dependency เดียวกับ Flow จึงสอดคล้องในระดับสายที่มาและขอบเขตที่อ้าง ไม่ใช่หลักฐานว่าทั้งสามผ่าน AC ธุรกิจครบ

hash ต้นทางก่อนกรองตาม parent/provenance.md คือ flow.md = 11a2bd2c3d5b3f13f0ab596618de6f011a1737be621b3bc7271471948235a449; state-machine.md = 01182925516cfd21bf24ab1b00291ecf952eb3371179a1714340903b27b9d57c; structure.md = a6963600ae6fcf76a9726457cad0a38f2ac6f34f8c5ecb565ad1edafbce50cc7 ทั้งสามต่างจากชุดกรองตามตาราง เป็นความเปลี่ยนแปลงที่บันทึกไว้ ไม่ใช่การเลือก Flow ต่างรุ่นเงียบ ๆ ค่า hash เก่าที่ฝังใน Flow เป็นประวัติต้นทาง ไม่ใช่ hash สำเนาปัจจุบัน ไม่ได้เปิดต้นฉบับ parent เพื่อตรวจซ้ำหรือรัน upstream บนชุดกรอง

ผล upstream มีครบ จึงไม่มีชิ้นงานหลักที่ต้องระบุว่า “ยังไม่ตรวจ” เพราะขาดรายงานเดิม อย่างไรก็ดี การรันตรวจ upstream ซ้ำบนชุดกรองยังไม่ตรวจ และหลักฐาน FR/UI ไม่ได้ผูก hash ชิ้นงานไว้ใน JSON โดยตรง การรับสายที่มาจึงอาศัย provenance ตามที่ผู้ใช้ให้ใช้ผลอ้างอิง

## ข้อค้างธุรกิจ แยกจากไฟล์หาย

ข้อค้างธุรกิจยังคงเดิม: ความสัมพันธ์ “เสร็จแล้ว/พร้อมเสิร์ฟ”, จุดเริ่ม 10 นาทีและพฤติกรรมเมื่อปิด PromptPay, รหัสอ้างใน US-20, หมายเหตุ ก./ค./ช., ค่าเฉลี่ย ETA, การเปิดคืนหลายวัตถุดิบ, เงื่อนไขปิดโต๊ะ, เขตเวลาและขอบเขตเลขออเดอร์ รวมคำถามใน FR ไม่เติมคำตอบหรือเปลี่ยนเป็น AC ข้อค้างเหล่านี้จำกัดงานที่ต้องตัดสินกฎ แต่ไม่ใช่เหตุให้ห้ามวิเคราะห์เอกสาร/mock ทุกชนิดโดยลำพัง เหตุหยุดชุดนี้คือข้อมูลที่กันไว้หลุด

ด้านไฟล์: input-source.md ไม่อยู่ใน baseline-filtered; provenance ทำหน้าที่บันทึกที่มาชิ้นงานหลักตามข้อกำหนดเฉพาะการรัน ส่วน state-machine.md:9 อ้าง flow-state-machine.md และ flow-state-machine.json; structure.md:11 อ้าง flow-structure.md และ flow-structure.json ซึ่งไม่มีสำเนาในชุดนี้ จึงยังยืนยันความครบของเอกสารตามลิงก์ทั้งหมดไม่ได้ ไม่ตามลิงก์ไปอ่านนอก input และไม่สร้างไฟล์แทน เอกสาร audit/schema/source ที่อยู่ในตารางประวัติของ Flow ไม่ถูกถือเป็น input ใหม่ที่ได้รับอนุญาตโดยอัตโนมัติ
