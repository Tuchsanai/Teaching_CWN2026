## State และความสัมพันธ์

ใช้ state กลางในหน่วยความจำของแท็บ ไม่มี localStorage และไม่มีฐานข้อมูล รีเฟรชไฟล์หรือกดรีเซ็ตเริ่มจาก seed อีกครั้ง

- `tables` เป็นโต๊ะถาวรจาก seed; `sessions` เก็บ id, table_id, state, opened_at, closed_at และตะกร้าแยกต่อรอบโต๊ะ ไม่ใช้เลขโต๊ะแทน session
- `orders` เก็บ id เพิ่มทีละ 1, channel, table_id, session_id, เวลารับ/ยืนยัน, สถานะครัว, ยอด และข้อมูลช่วงรับ/เลขกลับบ้าน การสั่งกลับบ้านไม่ผูก session โต๊ะ
- `items` แยกจาก orders เชื่อมด้วย order_id เก็บชื่อ ราคา และตัวเลือกที่เลือกเป็นสำเนา ณ เวลาส่ง ไม่อ่านยอดออเดอร์เดิมจาก catalog ปัจจุบัน
- `payments` แยกต่อ order_id; `paymentEvents` เก็บออเดอร์ใหม่ การเลือกวิธี และการยืนยันโดยหน้าร้าน พร้อมผู้กระทำ เวลา ISO และเลขออเดอร์; `statusEvents` แยกเหตุการณ์ครัวจากเงิน
- `menus/options`, `ingredients` และ `mappings` เป็นข้อมูล catalog และความพร้อมขาย แยก `available` ที่ผู้จัดการกำหนดจากผลวัตถุดิบ คำนวณผล whole/option จากแมปปัจจุบัน
- ตรวจตะกร้าทั้งชุดก่อนเพิ่ม order/items/payment หรือเลขคิว หาก stock ไม่พอ ถูกปิดขาย หรือเมนู/ตัวเลือกถูกลบ จะปฏิเสธทั้งชุดและไม่เพิ่มใบครัว
- สลับบทบาทหรือเปิดโต๊ะ active เดิมไม่ล้างตะกร้า/สถานะ ปิดโต๊ะล้างตะกร้าที่ยังไม่ส่งของรอบนั้นและห้ามใช้รอบเดิมอีก ออเดอร์และการจ่ายเก่ายังอยู่ในประวัติหน้าร้าน มีป้ายรอบที่ปิดแล้ว ไม่แสดงใน session ลูกค้าใหม่
- รายการออเดอร์เก่าของลูกค้าในรอบเดียวกันอยู่ในส่วน “ออเดอร์ทั้งหมดในรอบนี้”; ไม่รวมบิล US-17 ลูกค้าเลือกวิธีจ่ายต่อออเดอร์ได้ หน้าร้านยืนยันแต่ละใบ

## สมมติฐานและข้อค้างที่ยังคงไว้

1. **A-02 / MC-02:** ไม่ทราบนิยามหมายเหตุ ก./ค./ช. ไม่เติมนิยามเอง PromptPay ใน mock นับ 10 นาทีจากการเลือกครั้งแรกของออเดอร์ ตาม contract; จุดเริ่มจริง Q-08 ยังไม่ยืนยัน กด PromptPay ซ้ำไม่รีเซ็ตนาฬิกานี้ การปิดบริการและ timeout แสดงเงินสด แต่ไม่ยืนยันเงินอัตโนมัติ
2. **DI-07 / A-05 / MC-01:** ใช้ชื่อ รับออเดอร์ → กำลังทำ → เสร็จแล้ว เฉพาะ fixture ไม่แมป “เสร็จแล้ว” เป็น “พร้อมเสิร์ฟ” ไม่สร้างสถานะรายการ “รอลูกค้าตัดสินใจ” หรืออ้าง ETA ข้อมูลเฉลี่ยตาม FR-07 ไม่มี จึงแสดงข้อจำกัดก่อนส่งแทนตัวเลขสมมติ
3. **DI-04 / A-03 / MC-03:** คงข้อความ US-20 ว่า “กฎปิด/เปิดเมนูอัตโนมัติ (US-14)” การเชื่อม US-12/US-13 ยังเป็นข้อเสนอไม่ยืนยัน การเล่น whole/option ตาม seed/contract ไม่ได้แก้ DI-04 หรือเพิ่ม FR-14
4. เวลาจำลองเริ่ม `2026-01-01T12:00:00+07:00` คง timezone +07:00 ตาม seed ไม่ใช่กฎ timezone ร้านจริง คิวใช้เวลา ISO ปัดลงวินาทีแล้วเลขออเดอร์; ไม่มี server clock หรือ concurrency หลายเครื่อง
5. ช่วงรับเริ่มที่ขอบ 15 นาทีหลังขั้นต่ำ 20 นาที แรกคือ 12:30–12:45 แสดง 8 ช่วงถัดไปพร้อมวันใน label ค่า select เป็น HH:MM-HH:MM จัดเก็บวันแยกเพื่อรองรับเที่ยงคืน เมื่อเลื่อนนาฬิกา ช่วงที่ใช้ไม่ได้จะเปลี่ยนเป็นช่วงแรกที่ใช้ได้ตามแบบจำลองนี้
6. เลข T เพิ่มเมื่อส่งกลับบ้านสำเร็จและเริ่ม T-001 เมื่อวันจำลองเปลี่ยน เลข order_id ไม่รีเซ็ตตอนเปลี่ยนวันและยังแยกจากเลข T เก็บวันเพื่อแยกเลขรับซ้ำคนละวัน
7. PIN ผิดติดกันนับแยกบัญชี ล็อกจนเวลาจำลองครบ 5 นาที การสลับแท็บไม่ล้างตัวนับล็อก แต่ล้างสิทธิ์ผู้ใช้ก่อนเสมอ; เข้าผู้จัดการต้องใช้ role manager การตรวจ route และ action อยู่ใน JavaScript จึงไม่ใช่ authentication/security จริง
8. ชื่อบัญชีใน mock รับ Unicode letter/number 3–20 code points, PIN ASCII 4–6 หลัก ปฏิเสธชื่อซ้ำโดยเทียบตัวพิมพ์เล็ก เป็นรายละเอียดจำลองเพื่อให้แบบฟอร์มใช้งานได้ ชุดอักขระ นโยบายชื่อซ้ำ และขอบเขตล็อกของระบบจริงยังอยู่ใน Q-25
9. รูปจำลองตีความ 2 MB เป็น **2,000,000 ไบต์** ตามหน่วยทศนิยม ตรวจนามสกุล MIME signature และให้ browser ถอดรหัสรูปก่อนใช้ data URI; Q-19 ยังไม่ยืนยันนิยาม MB จริง ไม่มี URL รูปภายนอก เมื่อไฟล์ไม่ถูกต้องหยุดบันทึกและให้เลือกใหม่
10. ราคาใช้บาท/สตางค์และปัดสองตำแหน่งใน mock; จำนวนหนึ่งรายการในตะกร้าคือหนึ่งจาน กดเพิ่มซ้ำได้ ตะกร้าที่ยังไม่ส่งและ catalog เปลี่ยนจะปรับรายละเอียด/ราคาให้ตรวจแล้วกดส่งอีกครั้ง เป็นนโยบาย UI จำลองของ Q-04/Q-19 ไม่กระทบ snapshot ที่ส่งแล้ว
11. ตัวเลือกเพิ่มใน mock เป็น checkbox เลือกแยกกัน ลบตัวเลือกที่มีแมปแล้วต้องยืนยันลบแมปของตัวเลือกนั้นด้วยเพื่อไม่ทิ้งความสัมพันธ์กับสิ่งที่ไม่มี ส่วนเมนู/ตัวเลือกในออเดอร์เก่ายังคง snapshot ไม่มี flow ยกเลิก/คืนเงิน
12. วัตถุดิบกลับมามีเปิดเฉพาะสิ่งที่ไม่มีวัตถุดิบอื่นหมดค้างและผู้จัดการไม่ได้ปิดขาย ตาม contract ของ LAB นี้ ไม่ถือว่า Q-12/Q-13/Q-20 ของธุรกิจได้รับคำตอบ
13. กดรับเงินสดหรือยืนยันสลิปจำลองแล้วเป็นจ่ายแล้ว ปุ่มยืนยันถูกปิดหลังจ่ายเพื่อไม่สร้างผลซ้ำใน mock; ต้องเคยเลือก PromptPay จึงกดยืนยันสลิปได้ และยังยืนยันได้หลัง fallback ไม่มีการตรวจยอดโอนจริงหรือแนบสลิปจริง การเลือกเงินสดไม่ใช่การรับเงิน
14. ปิดโต๊ะไม่เพิ่มเงื่อนไขต้องจ่ายครบหรือครัวเสร็จก่อนปิด เพราะ Q-16 ยังเปิดอยู่ ออเดอร์ที่รับแล้วไม่ถูกยกเลิกจากการปิดโต๊ะ

## วิธีเปิดและตรวจโดยผู้เรียน

เปิด `work/ui-mockup.html` โดยตรงใน browser ผ่าน `file://` คำแนะนำบนหน้าระบุบทบาท บัญชี seed และลำดับเล่นแล้ว ใช้ `demokitchen`, `demofront`, `demomanager` กับ PIN จำลอง `0000` ปุ่ม +1/+5/+10 นาทีและ +1 วันเดินเวลาจำลอง; รีเซ็ตคืน seed/เวลา/บัญชี/แมป/คิว/ประวัติและออกจากระบบ

ใช้ native button/select/input, ป้ายกำกับฟอร์ม, focus ring, skip link และ CSS จอเล็ก แยก controls ที่ซ้ำใน kitchen-order/front-order ตาม contract การค้นหา selector ใน source รวมแม่แบบ menu-item-<id> และ option-<id> ไม่ใช่ผลคลิกจริง

การตรวจระหว่างสร้างจำกัดที่ `node --check` ของ JavaScript, เทียบ embedded JSON กับ seed, สำรวจชื่อ controls ใน source และตรวจว่าไม่มี URL ทรัพยากรออนไลน์ ไม่ได้รัน `tests/ui-check.py`, ไม่ได้เปิด browser ตรวจ UI, ไม่ได้สร้าง JSON ผลทดสอบหรือ screenshot จึงยังไม่มีผลยืนยันพฤติกรรมหรือ responsive จากการรันจริง

ให้ผู้เรียนรันจากโฟลเดอร์ LAB 004 โดยใช้ตำแหน่งผลใหม่ตามแผน round-1:

```bash
python tests/ui-check.py --html work/ui-mockup.html --out work/ui-check-round-1.json --shots work/shots/round-1
```

หากตำแหน่งหลักฐานนี้มีอยู่แล้ว ให้เก็บชุดเดิมและใช้ชื่อรอบที่ถูกต้องตาม session-plan ไม่เขียนทับผลเดิม ก่อนแก้รอบถัดไป ผู้เรียนต้องตรวจ JSON/screenshot จริงและ snapshot HTML/notes ชุดนี้ก่อน ผล smoke checks ไม่ทดแทนจำนวนตัวอย่างหรือเกณฑ์ US/NFR จริง ไม่รับรอง LAN, หลายเครื่อง, load, authentication, การติดตั้ง Ubuntu หรือเกณฑ์เวลา/ความแม่น ETA

การตรวจเพิ่มเติมหลังมีหลักฐาน smoke: รูป JPG/PNG ขอบ 2 MB/เกิน/ข้อมูลเสีย, ตัวเลือก 0/10/11 และแก้/ลบตัวเลือก, ยกเลิก/ยืนยันการลบเมนูที่มีแมป, ยอดเก่าหลังลบ/แก้, วัตถุดิบหมดซ้อนหลายชนิด, ปิดขายโดยผู้จัดการแล้ว restock, ข้ามเที่ยงคืนและเลข T, ปลดล็อกก่อน/ตรง 5 นาที, ล้างสิทธิ์เมื่อสลับบทบาท, กดจากคีย์บอร์ด และจอมือถือ
