# ผลตรวจ coverage — round-1

**ผล: GAPS — เข้าเกณฑ์ขั้นต่ำที่มีวิธีตรวจและ expected 19 จาก 26 US; อีก 7 US ยังไม่เข้าเกณฑ์** ได้แก่ US-04, US-05, US-07, US-11, US-17, US-22 และ US-24. ทั้ง 26 US มีแบบสำเร็จที่ตรวจผลได้เชิงออกแบบ แต่การมีชื่อประเภทผิดพลาด/ข้อยกเว้นครบทุก US ยังไม่พอให้ผ่าน. US-13 นับเฉพาะกรณี A ของ TS-US-13-4 ซึ่งมี expected แบบ fixture เสนอไว้อย่างชัดเจน; ไม่ได้นับกรณี B ที่ยังไม่มี oracle และไม่รับรองนโยบายร้าน

นี่คือ **การตรวจตั้งต้นครั้งแรก**: ชื่อโฟลเดอร์และ Output ใช้ round-1 แต่ตรงกับ round-0 ใน loop บทเรียน; จำนวนรอบแก้ coverage ที่ใช้แล้ว = 0 จากที่อนุญาต 2 รอบ. ยังไม่มีชุด gap จากการตรวจครั้งก่อนให้เปรียบเทียบ จึงไม่อ้างว่าช่องว่างเดิมไม่ลดและยังไม่ใช้ STOP_WITH_GAPS. ข้อแก้ด้าน scenario ทำต่อได้โดยแยกคำถามธุรกิจและข้อจำกัดระบบออกตามทะเบียนด้านล่าง

การนับนี้เป็น **coverage การออกแบบ ไม่ใช่ผลทดสอบผ่าน**. mock-not-testable ที่มีข้อมูลทดสอบ ขั้นตอน จุดสังเกต และ expected อ้าง AC หรือสมมติฐาน fixture ที่เปิดเผย นับการออกแบบได้แม้ยังรันไม่ได้. กรณีที่ expected ระบุเพียงรอคำตอบ/ไม่มีข้อมูล ไม่นับปิดช่องขั้นต่ำของเหตุผิดพลาดนั้น. การมีคำตอบธุรกิจที่ยังขาดไม่บังคับให้หยุดทุก US ถ้าส่วนที่ชัดยังออกแบบต่อได้

## ผลตรวจโครงสร้าง ข้อความ และ mapping

พบ 107 นิยาม TestID: C 32, K 40, M 35. แบ่งตามประเภทที่ผู้เขียนระบุเป็นสำเร็จ 49, ทางเลือก 14, ผิดพลาด 21, ข้อยกเว้น 23. ตัวเลขนี้ใช้ตรวจบัญชีรายการเท่านั้น ไม่ใช้แทน coverage. automation ตามไฟล์คือ auto 51, manual 6, mock-not-testable 50; Status เป็น NOT_RUN 57 และ NOT_TESTABLE 50. ทุก scenario มีช่อง template รวมขั้นตอน/expected/เหตุผล automation แต่บาง expected ยังตัดสินผลไม่ได้ตาม D01–D07

ตรวจเทียบข้อความ AC เต็มของทั้ง 107 รายการกับแถว US ต้นฉบับด้วยข้อความตรงตัว: **ตรง 107 จาก 107**; แถว US ต้นฉบับในไฟล์ทั้งสามตรงครบ 26 แถว. ไม่พบการแก้ตัวเลข หน่วย สูตร จำนวนตัวอย่าง หรือสัดส่วนใน AC เต็ม. ชุด fixture ย่อย เช่น 3 โต๊ะ, 1 ออเดอร์, ราคา 50/55/60, X=10, +07:00 และขอบ MB ถูกแยกเป็นข้อมูลจำลอง ไม่ใช้แทนประชากรหรือกฎร้าน. ตรวจ expected และขั้นตอนแยกจากการคัด AC เพื่อไม่ให้ข้อความต้นฉบับที่แนบเฉย ๆ ทำให้ผ่าน

นิยามใหม่ทั้งหมดใช้ TS-US-<เลข US>-<n> โดย n ต่ำกว่า 101; ไม่มี ID ซ้ำในสามไฟล์ และไม่มี ID ชน fixture. JSON มี fixture 14 ID ไม่ซ้ำ ครอบคลุม 13 US; เป็น smoke เท่านั้น. TS-US-08-102 อ้างเป็นทางเลือกเงินสดโดยใช้ steps/expected ที่มีจริงใน JSON ไม่สร้างนิยามซ้ำและไม่เพิ่มเข้าจำนวน 107

FR/Flow มี mapping active **21 จาก 26 US** ตามตาราง Traceability และ Coverage ในไฟล์จริง. รหัสที่ scenario อ้างสำหรับ 21 US พบในทะเบียน FR/NFR และ MRG/SCR; การอ้างทะเบียน reuse ไม่รับรองรายละเอียด baseline หรือ implementation ที่ไม่ได้ตรวจ. US-17, US-18, US-22, US-23, US-24 ไม่มี mapping active จึงคง MISSING ตาม U17/U18/U22/U23/U24. US-26 มี FR-26/NFR-16/NFR-22 และ MRG-29/30 แม้ไม่มีหน้าติดตั้งใน mock; ไม่นับการไม่มีหน้าจอนี้เป็นข้อขาดการออกแบบ. FR v2 ปิดข้อความ “เพื่อ” ของ US-12 อยู่เดิม แต่ scenario ใช้ข้อความต้นฉบับถูกต้อง ไม่ใช่ข้อผิดใหม่ของผู้เขียน scenario

## ผลรอบนี้และเงื่อนไขตรวจถัดไป

**GAPS.** ขั้นต่ำสำเร็จ ≥1 และผิดพลาดหรือข้อยกเว้น ≥1 ที่มีวิธีตรวจ/expected เข้าเกณฑ์ 19/26 US ตามตาราง. ทั้ง 26 มีสำเร็จเชิงออกแบบ; 7 ขาดช่องขั้นต่ำ D01–D07; mapping active มี 21/26 และขาด 5 US ตาม U17/U18/U22/U23/U24. สองกลุ่มนี้ซ้อนกันที่ US-17/22/24 จึงไม่บวกเป็นจำนวน US ที่ขาด 12. ไม่ประกาศ COVERED ทั้งชุดจากจำนวน 107 หรือจากการคัด AC ตรงทั้งหมด

ส่งแก้ D01–D07 พร้อมคงข้อค้าง U/B และจัดการ fixture F01/F02 ในงานที่ได้รับขอบเขตแก้ไฟล์นั้น. หลังแก้ให้ผู้ตรวจอ่าน manifest และไฟล์รุ่นเดียวกันใหม่ เทียบ gap ตาม ID/clause/เหตุผล ไม่เทียบจำนวน scenario รวม. หากตรวจหลังแก้แล้วชุดช่องว่างเดิมไม่ลด หรือครบแก้ 2 รอบยังเหลือ gap ให้ STOP_WITH_GAPS; หากเหลือเฉพาะข้อมูลธุรกิจจำเป็นที่ไม่สามารถวาง oracle แบบมีเงื่อนไขหรือออกแบบต่อได้ ให้หยุดพร้อมข้อค้างตามเกณฑ์. ไม่มีประวัติแก้ coverage ในรอบตั้งต้นนี้ที่จะใช้ตัดสินเงื่อนไขดังกล่าว

**ไฟล์ที่สร้างจริง:** coverage-round-1.md เพียงไฟล์เดียวในโฟลเดอร์ขั้นนี้ สร้างเมื่อยังไม่มีไฟล์ด้วยโหมดไม่เขียนทับ. ไม่แก้ input, manifest, scenario หรือหลักฐานเก่า ไม่สร้าง work/ หรือไฟล์ผลรัน

**ข้อบกพร่อง/ข้อค้าง:** 7 ช่องขั้นต่ำที่ยังไม่มี oracle ตัดสินเหตุผิดพลาด, mapping upstream ขาด 5 US, fixture selector/ทางเข้าไม่ตรง 2 รายการ, ฐาน path manifest คลาดเคลื่อนที่แก้การตีความเฉพาะรอบนี้แล้ว และคำถามธุรกิจตามทะเบียน. ไม่มี runtime failure ใหม่ที่ยืนยันได้จากรอบนี้
