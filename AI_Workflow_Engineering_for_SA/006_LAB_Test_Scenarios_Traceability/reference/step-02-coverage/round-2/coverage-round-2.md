# ผลตรวจความครอบคลุม — ROUND 2

**ผล: GAPS — STOP_WITH_GAPS สำหรับวงแก้ scenario ด้วย Input ชุดปัจจุบัน**

- **ผ่านเกณฑ์ขั้นต่ำการออกแบบ 26/26 US**: ทุก US มีสำเร็จอย่างน้อยหนึ่งกรณี และผิดพลาดหรือข้อยกเว้นอย่างน้อยหนึ่งกรณีที่มีวิธีกระตุ้น/สังเกตและ expected ตรวจเทียบได้ จากเดิม 19/26 เพิ่ม 7 US ได้แก่ US-04, US-05, US-07, US-11, US-17, US-22 และ US-24
- **ครบ mapping ทุกมิติที่จำเป็นในทะเบียนออกแบบ 21/26 US**: US-01–US-16, US-19–US-21 และ US-25–US-26; อีก 5 US ขาด FR/Flow/Screen active ตาม U17/U18/U22/U23/U24. จำนวนนี้หมายถึงการอ้าง US → FR/NFR ที่เกี่ยวข้อง → Flow → Screen หรือ N/A ที่มีเหตุผล ไม่ได้หมายถึงครบ oracle ธุรกิจทุกข้อ มี implementation ทุกหน้า หรือผ่านระบบจริง
- **ผลการรัน: ไม่มีข้อมูล / NOT_TESTED** ทั้งแบบจำลองและระบบจริง ไม่มีจำนวน passed/failed/skipped ที่เกิดจากการรันให้รายงาน

นี่คือการตรวจครั้งที่ 2 หลังแก้ครั้งที่ 1; ใช้รอบแก้แล้ว **1/2** และยังเหลือสิทธิ์แก้ **1 รอบ**. ไม่ใช้ชื่อโฟลเดอร์ round-2 เป็นหลักฐานว่าหมดเพดาน. ช่องขั้นต่ำ D01–D07 ลดจาก 7 เหลือ 0 และ P01 ฐาน manifest แก้แล้ว จึงไม่หยุดด้วยเหตุ “ชุดช่องว่างเดิมไม่ลด”. หยุดเพราะสิ่งที่ขวาง COVERED ต่อจากนี้เป็น mapping/นิยามธุรกิจและ fixture Input ต้นทางที่ผู้แก้ scenario เปลี่ยนไม่ได้ รวมความพร้อมระบบสำหรับรัน; การเพิ่ม scenario โดยเดาคำตอบไม่ปิดข้อค้างเหล่านี้

## ผลตรวจเอกสารและการนับ

พบ 114 นิยาม TestID: C 35, K 42, M 37; ประเภทตามผู้เขียนคือสำเร็จ 49 ทางเลือก 14 ผิดพลาด 25 ข้อยกเว้น 26. จำนวนเหล่านี้ใช้ตรวจบัญชีรายการเท่านั้น ไม่ใช้แทน coverage ราย US/ราย clause

ตรวจ AC เต็มตรงตัวกับต้นฉบับ **114/114** และแถว US ต้นฉบับทั้ง **26/26** ตรงกัน; ไม่พบการเปลี่ยนตัวเลข หน่วย สูตร จำนวนตัวอย่างหรือสัดส่วนใน AC. ตรวจขั้นตอน/expected แยกจากข้อความ AC แล้วตามตารางด้านล่าง. นิยามเดิม **107/107** ตรงกับไฟล์ก่อนแก้แบบข้อความตรงตัว; เพิ่ม 7 นิยามที่มี ID ใหม่ ไม่เปลี่ยนความหมาย ID เดิม. ID ทั้ง 114 ไม่ซ้ำ รูปแบบ TS-US-<เลข US>-<n> และ n ต่ำกว่า 101; ไม่ชน fixture 14 ID ซึ่งไม่ซ้ำและครอบคลุมเพียง 13 US

Automation ตามไฟล์: **auto 51 / manual 6 / mock-not-testable 57**. Status เป็น NOT_RUN 57, NOT_TESTABLE 50 และ MOCK_NOT_TESTABLE 7; สองชื่อหลังเก็บต่างกันตามรุ่นเอกสาร แต่ทั้งคู่ไม่ใช่ผลผ่าน. ทุก Actual/หลักฐานยังไม่มีข้อมูล. รหัส FR/NFR/MRG/SCR ที่อ้างในช่อง mapping พบในทะเบียนต้นทาง; การพบรหัส reuse ไม่ยืนยัน implementation หรือรายละเอียด baseline ที่ไม่ได้เปิด

mock-not-testable ที่ระบุข้อมูล ขั้นตอน จุดสังเกต และ oracle จาก AC หรือ fixture ที่เปิดเผย นับขั้นต่ำการออกแบบได้ แม้ยังไม่มีเครื่องมือรัน. แผนที่บอกเพียงรอคำตอบ/เก็บผลไว้ดู ไม่มี expected ของเหตุผิดปกติ ไม่นับปิดขั้นต่ำ. US-13 ใช้เฉพาะกรณี A ใน TS-US-13-4 ที่เสนอคงปิดเมื่ออีกวัตถุดิบยังหมด; กรณี B ยัง MISSING. A เป็นสมมติฐาน fixture ไม่ใช่กฎร้านที่ยืนยัน

**GAPS / STOP_WITH_GAPS.** ช่องขั้นต่ำเดิมลดจริงครบทั้งเจ็ด; ไม่มีช่องขั้นต่ำที่ต้องส่งแก้ scenario เพิ่มจาก Input นี้. ยังเหลือสิทธิ์แก้อีกหนึ่งรอบตามเพดาน แต่ไม่ต้องใช้รอบนั้นเพื่อเติมข้อกำหนดที่หายด้วยการเดา. ส่วนที่ทำต่อได้คือผู้ดูแล upstream จัด mapping ห้า US/fixture สองรายการและเจ้าของข้อกำหนดตอบ B; ผู้จัดระบบเตรียม R01 สำหรับการรัน. ผู้แก้ scenario อาจเพิ่มตัวอย่าง fixture ได้ แต่ปิด U/F/นโยบายธุรกิจไม่ได้ด้วยตัวอย่างเหล่านั้น
