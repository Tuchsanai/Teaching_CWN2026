# Safe Resume — ทำต่อโดยไม่ทำซ้ำ

คุณคือ ROUTER สำหรับงานที่หยุดกลางทาง ใช้ไฟล์นี้พร้อมสถานะงานและ workspace

## แผนภาพการทำงาน

```text
อ่าน state → ตรวจ session / process เดิม
                 │
                 ├─ ยังรัน → ติดตามงานเดิม ไม่เริ่มซ้ำ
                 ├─ ยืนยันไม่ได้ → blocked
                 └─ หยุดแล้ว → ตรวจผลและ hash
                                  │
                                  ├─ ผ่าน + รุ่นตรง → ใช้ผลเดิม
                                  └─ ยังไม่ครบ / รุ่นเปลี่ยน
                                         │
                                         ▼
                                  จัดงานที่กระทบใหม่
                                  → ตรวจ dependency → ทำต่อ

ก่อน undo → เทียบไฟล์ปัจจุบันกับรุ่นที่ worker เขียน
                 ├─ ตรง + มี checkpoint → คืนเฉพาะงานนั้น
                 └─ มีคนแก้ต่อ → rollback_conflict → รักษาไฟล์ผู้ใช้
```

## ขั้นตอนและกติกา

1. อ่านเป้าหมายและ state ก่อนแก้: `id, status, session, attempt, dependencies, scope, input/output hash, evidence` ถ้าไม่มี state ให้ตรวจสภาพจริงก่อนสรุป

2. `running` ไม่ได้แปลว่าตาย: ตรวจ session/process เดิม ยังทำอยู่ให้ติดตาม จบแล้วให้ตรวจผลก่อน dispatch ใหม่

3. ไม่รู้สถานะให้ตรวจเพิ่ม ถ้ายืนยันไม่ได้ให้ `blocked` พร้อมเหตุผล ห้ามเริ่มซ้ำหรือ undo โดยเดา

4. `passed` ใช้ต่อได้เมื่อ input/output/acceptance ตรงเดิม; ต้นทางเปลี่ยนให้ invalidate เฉพาะ task ที่ได้รับผลและปลายน้ำ

5. JOIN หรือรายงานรวมที่ผ่านแล้วและ hash ไม่เปลี่ยนใช้ผลเดิม ไม่สร้างใหม่เพียงเพราะ resume

6. ก่อนเริ่ม task ที่ค้าง ยืนยัน dependency ผ่าน ไม่มี process เดิม และไม่ชนไฟล์อ่าน/เขียนของงานอื่น; รักษา attempt เดิมไม่รีเซ็ตงบแก้

7. ก่อน undo ต้องมี checkpoint และ hash หลัง worker เขียน เปรียบเทียบกับไฟล์ปัจจุบัน; มีคนแก้ต่อให้รักษาไฟล์นั้นและรายงาน `rollback_conflict` ห้ามทับงานผู้ใช้

8. undo เฉพาะผลของ task; ไม่ reset/clean/stash ทั้ง repo ไม่ลบไฟล์ที่ไม่อยู่ใน manifest ไม่ commit/push เว้นแต่ผู้ใช้สั่ง

9. ROUTER เขียน state คนเดียวแบบ atomic พร้อมรุ่นและหลักฐาน; กลับไปทำ → ตรวจ → บันทึกผล แก้ได้ตามงบเดิม

10. สรุปสิ่งที่ใช้ผลเดิม สิ่งที่ทำต่อ และข้อค้างตามจริง ห้ามแต่งสถานะหรือหลักฐาน

ตัวอย่าง: T1 ยังรัน session เดิม → ติดตาม T1; ผู้ใช้แก้ v2 เป็น v3 → ห้ามเอา checkpoint v1 ทับ
