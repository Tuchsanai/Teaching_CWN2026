# ROLE (บทบาท)
คุณสวมบทบาทที่แยกจากกัน 2 บทบาท:
- GENERATOR: สร้างหรือปรับปรุงผลงาน
- CRITIC: ตรวจผลงานตามเกณฑ์อย่างเคร่งครัดและอ้างหลักฐานจากผลงานจริง

# GOAL (เป้าหมาย)
สร้างผลงานที่ผ่านเกณฑ์ทุกข้อ โดยรักษาข้อกำหนด ข้อมูลต้นทาง และประเด็นที่ยังยืนยันไม่ได้

# INPUT PARAMETERS (พารามิเตอร์นำเข้า)

## REQUIREMENT
ย้ายระบบนัดหมายคลินิกจาก Google Sheet สู่ระบบกลาง (As-Is → To-Be + Migration (การย้ายข้อมูลและระบบ))
บริบท: คลินิกทันตกรรม 3 สาขา ใช้ Google Sheet แยกสาขา ร่วมกับจองผ่าน LINE ต้องการย้ายมาระบบนัดหมายกลาง

ตัวอย่างข้อมูลจาก Google Sheet ของสาขาต่าง ๆ (CSV):
```csv
สาขา,วันที่,เวลา,ชื่อคนไข้,เบอร์,หมอ,บริการ,หมายเหตุ
ลาดกระบัง,03/09/2026,10:00,สมชาย ใจดี,081-234-5678,หมอเอ,ขูดหินปูน,
ลาดกระบัง,2026-09-03,10:00,สมชาย ใจดี,0812345678,หมอเอ,ขูดหินปูน,จองซ้ำทางไลน์
บางนา,3 ก.ย. 69,13:30,คุณมาลี,,หมอบี,จัดฟัน,ไม่มีเบอร์ ติดต่อทางไลน์
บางนา,03/09/2026,13:30,วิชัย ศรีสุข,089-111-2222,หมอบี,อุดฟัน,
อ่อนนุช,09/03/2026,09:00,Somchai Jaidee,081 234 5678,หมอเอ,ตรวจฟัน,หมอเอมาช่วยสาขานี้ทุกวันพุธ
```

งานที่ต้องส่ง: As-Is Process (กระบวนการทำงานปัจจุบัน) (Mermaid flowchart) · Data Quality Findings (ข้อค้นพบปัญหาคุณภาพข้อมูล) (ปัญหา / แถว / ผลกระทบ) · To-Be Process (กระบวนการทำงานที่ต้องการในอนาคต) และ Data Model (แบบจำลองข้อมูล) · Data Mapping (การจับคู่ข้อมูลต้นทางกับปลายทาง) + แผน Migration (การย้ายข้อมูลและระบบ) (รวมวิธีจับคู่ตัวตนคนไข้) · Gap Analysis (การวิเคราะห์สิ่งที่ยังขาดเพื่อไปสู่ระบบใหม่) + Roll-out Plan (แผนทยอยนำระบบไปใช้งาน) · Plan Version Log (บันทึกการเปลี่ยนแปลงแผน)
Output: ส่ง 2 ไฟล์ ได้แก่ output.md สำหรับเอกสารและแผนภาพ Mermaid และ mockup.html สำหรับ Web UI Mockup (แบบจำลองหน้าจอเว็บไซต์) ด้วย HTML/CSS
Mockup เฟสแรกมี 3 หน้าหรือส่วน: (1) ตารางนัดหมายกลาง แสดงสาขา วันที่ เวลา หมอ บริการ และสถานะ (2) ฟอร์มจอง/แก้ไขนัดหมาย พร้อมตัวอย่างคำเตือนเวลาชนกัน (3) ตรวจข้อมูลก่อนย้าย แสดงข้อมูลซ้ำ ข้อมูลขาด วันที่กำกวม และรายการรอคนยืนยัน
ใช้ข้อมูลจำลองพร้อมป้ายกำกับ โดยหน้าจอและชื่อข้อมูลต้องสอดคล้องกับ To-Be, Data Model (แบบจำลองข้อมูล) และ Data Quality Findings (ข้อค้นพบปัญหาคุณภาพข้อมูล) ไม่ตัดสินข้อมูลกำกวมหรือรวมตัวตนเอง ปุ่มเป็นภาพจำลองได้ ไม่ต้องมี backend หรือย้ายข้อมูลจริง
เกณฑ์ตรวจ Mockup: เปิดในเบราว์เซอร์ได้ เห็นครบ 3 ส่วน ข้อมูล/สถานะสอดคล้องกับเอกสาร และแสดงรายการรอยืนยันชัดเจน บันทึกผลตรวจพร้อมภาพหลักฐาน ไม่บังคับทดสอบธุรกรรมจริง

## CRITERIA
C1. ส่ง output.md ครบหกส่วนตามโจทย์ และ mockup.html ครบสามส่วนตามขอบเขต Mockup
C2. Data Quality Findings (ข้อค้นพบปัญหาคุณภาพข้อมูล) ระบุปัญหาที่ต่างประเภทกันอย่างน้อย 5 ประเภท โดยแต่ละประเภทอ้างอิงแถวที่ได้รับผลกระทบอย่างเจาะจงและระบุผลกระทบ ค่าทุกค่าที่ตีความได้มากกว่าหนึ่งแบบต้องระบุว่ากำกวม และการตีความที่เลือกต้องอ้างอิงหลักฐานที่พบในข้อมูล
C3. ส่วน Data Mapping (การจับคู่ข้อมูลต้นทางกับปลายทาง) + Migration (การย้ายข้อมูลและระบบ) มีกลยุทธ์จับคู่ตัวตนคนไข้ที่ระบุวิธีปรับรูปแบบเบอร์โทรศัพท์และชื่อให้เป็นมาตรฐานก่อนจับคู่ พร้อมระบุแถวที่ต้องให้มนุษย์ยืนยัน และทุกบล็อก Mermaid ต้อง render ได้ (ใช้ renderer ที่ติดตั้งในเครื่องหากมี มิฉะนั้นให้ตรวจ syntax อย่างเคร่งครัด พร้อมระบุว่าใช้วิธีใด) รวมถึงเปิด mockup.html ในเบราว์เซอร์ ตรวจความครบทั้งสามส่วน ความสอดคล้องกับเอกสาร ป้ายข้อมูลจำลองและรายการรอยืนยัน พร้อมบันทึกภาพหลักฐาน

# WORKFLOW (ลำดับการทำงาน)
ทำซ้ำตามวงจรต่อไปนี้:
1. ก่อนสร้างงาน เชื่อมแต่ละข้อกำหนดกับส่วนของผลงานและเกณฑ์ที่ใช้ตรวจ
2. GENERATOR สร้างผลงานใน Iteration 1; รอบถัดไปแก้เฉพาะส่วนที่เกี่ยวข้องกับเกณฑ์ที่ไม่ผ่าน
3. CRITIC ตรวจผลงานล่าสุดทีละเกณฑ์ แล้วระบุ PASS หรือ FAIL พร้อมหลักฐานหรือตำแหน่งที่ตรวจได้
4. เกณฑ์ที่มีหลายเงื่อนไขจะ PASS เมื่อครบทุกเงื่อนไข หากไม่มีหลักฐานให้ FAIL และระบุสิ่งที่ขาด
5. หากทุกเกณฑ์ PASS ให้หยุด หากยังมี FAIL ให้ระบุสาเหตุ สิ่งที่ต้องแก้ และเริ่ม Iteration ถัดไป

# CONSTRAINTS (ข้อห้าม)
- ห้ามเปลี่ยนข้อกำหนดหรือเกณฑ์ที่ผู้เรียกส่งมา
- ห้ามแต่งข้อมูลที่ไม่มีในข้อมูลนำเข้า ให้แยกสมมติฐาน ข้อขัดแย้ง และเรื่องที่ต้องยืนยัน
- ห้ามเปลี่ยนส่วนที่ผ่านแล้ว เว้นแต่จำเป็นต่อการแก้ข้อที่ไม่ผ่าน และต้องตรวจผลกระทบซ้ำ
- ใช้วิธีตรวจสำรองได้เฉพาะเมื่อเกณฑ์อนุญาต และต้องระบุข้อจำกัดตามจริง

# STOP CONDITION (เงื่อนไขหยุด)
หยุดเมื่อ:
- ทุกเกณฑ์เป็น PASS หรือ
- ทำครบ 3 Iteration หรือ
- เกณฑ์เดิมไม่ผ่าน 2 ครั้งติดต่อกันโดยไม่ดีขึ้น ให้รายงานสถานะ blocked พร้อมงานค้างและข้อมูลที่ขาด

# OUTPUT FORMAT (รูปแบบผลลัพธ์)
1. ตารางบันทึก Iteration: | Iteration | สิ่งที่เปลี่ยน | ผลตรวจแต่ละเกณฑ์ |
2. ตารางผลตรวจ: | เกณฑ์ | PASS/FAIL | หลักฐาน/ตำแหน่ง | สิ่งที่ต้องแก้ |
3. ผลงานสุดท้ายตาม REQUIREMENT
4. ประเด็นที่ยังเหลือ สมมติฐาน หรือข้อจำกัด (ถ้ามี)
