# บันทึก Loop — โจทย์คลินิกเพิ่ม Mockup

รอบนี้ใช้ Codex ในบทสนทนาเดียวสลับบทบาท ไม่ใช่ผู้ตรวจอิสระ ใช้เอกสารออกแบบเดิมเป็นจุดตั้งต้น แล้วสร้าง Mockup ใหม่และตรวจหลักฐานใหม่ทั้งหมด ไม่คัดลอก PASS หรือภาพจากรอบเดิม

## Requirement → ผลงาน → วิธีตรวจ (ก่อนสร้าง)
- C1: เอกสารหกส่วน + Mockup สามส่วน → output.md, mockup.html → อ่านหัวข้อและเปิดหน้าจอจริง
- C2: ปัญหาอย่างน้อยห้าประเภท พร้อมแถว ผลกระทบ และข้อมูลกำกวม → Findings เก้าประเภท → อ่านเทียบ CSV R1–R5 และตรวจวันด้วย Python
- C3: normalization และคนยืนยัน + Mermaid + Mockup สอดคล้อง → เอกสารและ UI → ตรวจชื่อ/เบอร์ กรณี R1–R5, render ทุกแผนภาพ, เปิดหน้าจอและตรวจภาพ

## Iteration 1 — Generator
คงข้อมูลต้นทางและกติกาที่ยังถูกต้อง เพิ่ม Mockup ตารางนัดหมาย ฟอร์มจอง และคิวตรวจข้อมูล โดยยังไม่เพิ่ม Change Request เฟสสอง รอผล Critic จากการตรวจจริง

## Iteration 1 — Critic
- C1 PASS: เอกสารครบ As-Is, Findings, To-Be/Data Model, Mapping/Migration, Gap/Roll-out, Plan v1 และ Mockup สามส่วน; เปิดจริงทั้งจอ 1440 และ 390
- C2 PASS (อ่านเทียบข้อมูล): Findings เก้าประเภทอ้าง R1–R5 และผลกระทบ; วันที่ทุกแบบที่กำกวมเก็บ candidate; R2 เป็นหลักฐานประกอบ ไม่เหมารูปแบบทุกสาขา; ผล Python ยืนยันวันของ R5 สองแบบไม่ใช่พุธ
- C3 PASS: อ่านตรวจชื่อ NFC/trim/casefold และเบอร์ตัดขีด/ช่องว่าง พร้อมกรณี R1–R5 ให้คนยืนยัน; Mermaid สามบล็อก render จริง; UI เก็บ raw วันที่ แสดงสถานะรอยืนยันและไม่มี auto-merge; ผลเปิดเบราว์เซอร์และภาพใน verification-phase1.json
หยุดเฟสแรกเพราะผ่านครบ ไม่จำเป็นต้องแก้ให้ครบสามรอบ ผลตรวจความหมายเป็นการตรวจโดย Codex ในบทสนทนาเดียว

## เฟสสอง — รับ Change Request หลังตรวจเฟสแรก
เพิ่มความยินยอมและการจองเองผ่าน LINE OA ให้ C1 ครอบคลุมทั้งเอกสารและ Mockup
Critic ตรวจ baseline: C1 FAIL เพราะเฟสแรกยังไม่มีสองส่วนนี้; C2 และ C3 ของขอบเขตเดิมยังผ่าน จึงแก้เฉพาะส่วนที่ได้รับผลกระทบ

## Iteration 2 — Generator
เพิ่มกระบวนการและแบบจำลองความยินยอม/LINE, Impact/Reuse และ Plan v2 พร้อม Mockup สองส่วนใหม่ คงเอกสารและสามหน้าจอเฟสแรก รอตรวจซ้ำทั้งหมด

## Iteration 2 — Critic
- C1 PASS: เอกสารและ Mockup เพิ่มความยินยอมกับ LINE OA ครบ พร้อม Plan v2, Impact และ Reuse; สามส่วนเฟสแรกยังอยู่
- C2 PASS: raw และ Findings เฟสแรกยังคงเดิม ข้อกำหนดใหม่ไม่ลบความกำกวมหรือยืนยันตัวตนแทนคน
- C3 PASS: Mermaid ห้าบล็อก render จริง; Playwright เปิด Mockup ครบห้าส่วนทั้ง 1440 และ 390; ไม่มี console/page error; ไม่มี horizontal overflow ระดับหน้า; ช่องยินยอมไม่ถูกเลือกล่วงหน้า; LINE ติดป้ายจำลอง
- ตรวจภาพหน้าจอทั้งห้าส่วนแล้ว: ตารางและฟอร์มอ่านได้ ไม่มีการทับซ้อนที่เห็นในภาพ; สถานะรอยืนยันไม่ปะปนกับการยืนยันนัดจริง
- อ่านความสอดคล้อง: หน้าจอแรกใช้ SourceRow ก่อนสร้าง Appointment; ฟอร์มเจ้าหน้าที่ใช้ข้อมูล Branch/Doctor/Service; คิวตรวจตรง ReviewIssue; ความยินยอมตรง ConsentRecord; LINE แยก LineIdentity และ BookingRequest ก่อนสร้าง Appointment
หยุดเมื่อผ่านทุกเกณฑ์ ภาพหน้าจอและผลตรวจทั้งหมดมาจากรอบนี้ ไม่มีการทดสอบ API ธุรกรรม หรือการปฏิบัติตามกฎหมายจริง
