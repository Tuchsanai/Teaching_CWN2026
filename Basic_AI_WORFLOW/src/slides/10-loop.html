Loop Engineering

ทำ → ตรวจ → แก้ วนจนผ่านเกณฑ์ (ระดับ: ง่าย) · ร่องรอยที่ได้: Iteration Log

Theory

Loop คืออะไร: Generate → Evaluate → Improve

นักเรียนส่งการบ้าน
ครูตรวจตามเกณฑ์
ไม่ผ่านก็แก้เฉพาะจุด
แล้วส่งใหม่ ไม่เกิน 3 ครั้ง
  1. Generate — สร้างผลงานตาม Requirement
  2. Evaluate — ตรวจทีละเกณฑ์ พร้อมหลักฐาน
  3. Improve — แก้เฉพาะข้อที่ FAIL แล้วตรวจซ้ำ

Requirement → Generate → Evaluate → ผ่าน? ใช่→Result / ไม่→Improve→กลับไป Evaluate

Workflow Diagram: วงจร Loop

เส้นย้อนกลับเข้า Evaluate: ทุกครั้งที่แก้ต้องตรวจใหม่ · คลิกขยายเพื่ออ่านรายละเอียด

Theory

ทำไมต้องแยก GENERATOR กับ CRITIC และเกณฑ์แบบ PASS/FAIL

GENERATOR

สร้างหรือปรับปรุงผลงาน
รอบถัดไปแก้เฉพาะข้อที่ FAIL

CRITIC

ตรวจทีละเกณฑ์: PASS/FAIL + หลักฐาน 1 บรรทัด
ตรวจอย่างเคร่งครัด ไม่ผ่อนปรน

ให้ AI ตรวจงานตัวเองมักตอบว่าดี — จึงต้องแยกบทบาทและระบุวิธีตรวจ
เกณฑ์ไม่ดีเกณฑ์ดี — ตอบ PASS/FAIL ได้
UI ดีไหมมีปุ่มยกเลิกหรือไม่
ครบถ้วนมี 5 ฟีเจอร์ตามรายชื่อ
สวยเข้าถึงทุกฟีเจอร์ภายใน 2 คลิก

หลักออกแบบ Evaluation Criteria ตาม §7.1

Theory

Stop Condition และทางออกเมื่อวนแล้วไม่ดีขึ้น · เหมาะ/ไม่เหมาะ

หยุดเมื่อ

  1. ทุกเกณฑ์เป็น PASS
  2. ครบ 3 Iteration
  3. เกณฑ์เดิม FAIL 2 ครั้งติดโดยไม่ดีขึ้น → รายงาน blocked

ข้อจำกัด

ไม่เห็นภาพรวม แก้ทีละจุด
ต้องมีเกณฑ์ที่ตรวจได้
เมื่อ blocked ให้ระบุข้อที่ยังติดขัด

เหมาะเมื่อ

งานชิ้นเดียว เกณฑ์ชัด ปรับปรุงซ้ำได้ — แนวเลือก Workflow จาก §6 บท 4

Prompt Template

Loop Prompt Template (ฉบับไทย)

บรรทัดที่ขึ้นต้นด้วย "//" คือคำอธิบายสำหรับผู้เรียน ให้ AI ข้ามบรรทัดเหล่านี้

# ROLE (บทบาท)
คุณสวมบทบาทที่แยกจากกัน 2 บทบาท:
- GENERATOR: สร้างหรือปรับปรุงผลงาน
- CRITIC: ตรวจผลงานตามเกณฑ์อย่างเคร่งครัด ผู้ตรวจต้องไม่ผ่อนปรน

# GOAL (เป้าหมาย)
สร้างผลงานที่ผ่านเกณฑ์ทุกข้อด้านล่าง

# INPUT (ข้อมูลนำเข้า)
{{REQUIREMENT}}

# CRITERIA (เกณฑ์ตรวจ — ทุกข้อต้องตอบได้ว่า PASS หรือ FAIL)
C1. มีทุกฟีเจอร์ที่ระบุไว้ในโจทย์
C2. {{CRITERION_2}}
C3. {{CRITERION_3}}
// ตัวอย่าง "คำโปรยสินค้า": C1 มีชื่อสินค้า  C2 มีราคา  C3 ไม่เกิน 30 คำ — ทุกข้อตอบผ่าน/ไม่ผ่านได้

# WORKFLOW (ลำดับการทำงาน)
ทำซ้ำตามวงจรต่อไปนี้:
1. GENERATOR: สร้างผลงาน (Iteration 1) หรือแก้เฉพาะเกณฑ์ที่ไม่ผ่านเท่านั้น (Iteration ถัดไป)
2. CRITIC: ระบุผลแต่ละเกณฑ์เป็น PASS หรือ FAIL พร้อมหลักฐานข้อละหนึ่งบรรทัด
3. หากทุกเกณฑ์เป็น PASS ให้หยุด
4. หากยังไม่ผ่านครบ ให้ระบุเกณฑ์ที่ไม่ผ่านแล้วเริ่ม Iteration ถัดไป
// รอบ 1: "หูฟังเสียงใส ใส่สบาย" → C2 ไม่ผ่าน (ไม่มีราคา)  รอบ 2: เติม "ราคา 990 บาท" → ผ่านครบ

# CONSTRAINTS (ข้อห้าม)
- ห้ามเปลี่ยนส่วนที่ผ่านแล้ว
- ห้ามแต่งข้อมูลที่ไม่มีในข้อมูลนำเข้า ให้ระบุว่าเป็นสมมติฐานแทน

# STOP CONDITION (เงื่อนไขหยุด)
หยุดเมื่อ:
- ทุกเกณฑ์เป็น PASS หรือ
- ทำครบ 3 Iteration หรือ
- เกณฑ์เดิมไม่ผ่าน 2 ครั้งติดต่อกันโดยไม่ดีขึ้น (รายงานว่าติดขัด โดยระบุสถานะ blocked)

# OUTPUT FORMAT (รูปแบบผลลัพธ์)
1. ตารางบันทึก Iteration: | Iteration | สิ่งที่เปลี่ยน | C1 | C2 | C3 |
2. ผลงานสุดท้าย
3. ประเด็นที่ยังเหลือหรือสมมติฐาน (ถ้ามี)

คัดลอกทั้งก้อน · บรรทัด // เป็นคำอธิบายให้ผู้เรียน และสั่ง AI ให้ข้าม
