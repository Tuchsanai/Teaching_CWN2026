ตัวเลขเข้าถึงเป็นจำนวนคลิกนำทางตามขอบเขต N1b ไม่รวมการกรอกข้อมูล ตัวเลขจนเสร็จนับปุ่มนำทางและส่งคำสั่ง โดย Playwright ใช้ fill/select_option ในการกรอก/เลือกข้อมูล จึงไม่อ้างว่าเป็นจำนวนการคลิกทั้งหมดของผู้ใช้ที่เปิดตัวเลือกวันที่หรือเวลา การยกเลิกและอ่านสถานะเตรียมรายการจองผ่าน UI ก่อนเริ่มนับจากหน้าแรก

ตรวจเดสก์ท็อปที่ 1280×900 และมือถือจำลองที่ 360×800 ไม่มี overflow ของหน้าและ controls ที่ตรวจ ภาพหน้าแรกเพิ่มเติมที่ 1440×1000 ผ่านการเปิดดูร่วมกับภาพมือถือ

## การรวมและข้อขัดแย้ง

N5 รับเฉพาะ N2, N3, N4 ที่มีสถานะ DONE และรูปแบบ JSON ครบ ตรวจ static DOM IDs ที่จำเป็น 27 รายการและจุดแทรก script แล้วตรงกัน ไม่มี ID ซ้ำ ไม่มีข้อขัดแย้งของ contract และไม่ต้องแก้จุดเชื่อมต่อ การทดสอบผ่านรอบแรกจึงไม่ใช้ retry

หลักฐาน INPUT: “ระบบต้องสามารถ: แสดงห้องประชุม, ดูเวลาว่าง, จองห้อง, ยกเลิกการจอง, แสดงสถานะการจอง” และ “Output: Web UI Mock-up ที่เปิดและทดลองใช้งานได้” ทดสอบแต่ละฟีเจอร์ผ่านการคลิกจริงครบ ข้อขัดแย้งที่ยังหาข้อสรุปไม่ได้: ไม่มี

ข้อมูลห้อง ความจุ เวลาเริ่มต้น นโยบาย overlap และการเก็บใน localStorage เป็นสมมติฐานสำหรับ mock-up ที่บันทึกไว้ใน nodes/N1b-assumptions.md ไม่ใช่ข้อเท็จจริงหรือนโยบายองค์กรจาก INPUT ระบบนี้เก็บข้อมูลเฉพาะเบราว์เซอร์ ไม่มี backend ร่วมกัน ผลทดสอบไม่ได้อ้างการใช้งานหลายผู้ใช้จริง
