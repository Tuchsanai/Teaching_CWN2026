
# Phase 2 — ตารางการรันซ้ำ (updated: change request)

| Node | รันซ้ำหรือไม่? (yes/no) | เหตุผล |
|---|---|---|
| N1 | yes | INPUT เพิ่มข้อกำหนดความยินยอมตาม PDPA และการจองเองผ่าน LINE OA จึงมี completeness gaps ใหม่ แม้ CSV ไม่เปลี่ยน |
| N1b | yes | ผล N1 เปลี่ยน จึงต้องประเมินข้อกำกวมใหม่; หากข้อสรุปไม่เปลี่ยนให้คงเนื้อหาเดิม |
| N2 | yes | ผล dependency N1 เปลี่ยน; ไม่อนุมานว่า requirement ใหม่เป็น As-Is แล้ว |
| N3 | yes | ผล N1 เปลี่ยน ต้องเพิ่มกระบวนการและ model รองรับ requirement ใหม่ |
| N4 | yes | ผล N1 เปลี่ยน ต้องเพิ่ม mapping/migration และวิธีจัดการข้อมูลใหม่ที่ไม่มีใน legacy |
| N5 | yes | ผล N3/N4 จะเปลี่ยนและผู้ใช้กำหนดให้รวมอีกครั้งหลัง dependencies DONE |

การตัดสิน N2–N4 ขึ้นกับ output N1 ที่เปลี่ยนจริงจากการเพิ่มช่องว่างใหม่ ไม่ใช่รันทุก Node เพียงเพราะได้รับ change request; ตรวจเงื่อนไขก่อนเริ่มแต่ละระดับ ไม่มี Node ที่เข้าเงื่อนไข no ในรอบนี้ ผลที่รันซ้ำแต่ไม่เปลี่ยนเนื้อหายังคงเดิมทุกประการและบันทึกแยกจากการ reuse โดยไม่รัน
