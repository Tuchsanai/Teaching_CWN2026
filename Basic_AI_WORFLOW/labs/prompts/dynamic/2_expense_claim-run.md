Output: ส่ง 2 ไฟล์ร่วมกัน ได้แก่ output.md (เอกสารข้อกำหนดและแผนภาพ Mermaid) และ mockup.html (Web UI Mockup) โดย output.md ประกอบด้วย Actor/Stakeholder · FR-xx และ NFR · BR-xx · Use Case Diagram · ERD · Sequence Diagram "ยื่นเบิก → อนุมัติ → จ่ายเงิน" · State Diagram ของใบเบิก · Traceability Matrix (ประโยคต้นทาง → FR/BR → Use Case → Entity) · Open Issues

สำหรับ mockup.html ให้ใช้ HTML/CSS และข้อมูลตัวอย่างเพื่อสื่อหน้าตาและสถานะตามข้อกำหนดใน output.md ไม่ต้องทำระบบธุรกรรมจริง
มี 3 หน้าหรือ 3 ส่วนที่มองเห็นได้:
1. ยื่นเบิก: ช่องข้อมูลใบเบิก ประเภทค่าใช้จ่าย พื้นที่แนบรูปใบเสร็จจำลอง และข้อความเงื่อนไข 30 วัน; แสดงช่องชื่อลูกค้าและบริษัทสำหรับค่ารับรอง
2. ติดตามใบเบิก: รายการ สถานะ ผู้รับผิดชอบปัจจุบัน และขั้นตอนถัดไป
3. ตรวจและอนุมัติ: รายละเอียดใบเบิก ตัวอย่างจุดแจ้งเตือนใบเสร็จอาจซ้ำ และข้อความรอยืนยันนโยบายวงเงิน 5,000/10,000 รวมถึงวงเงินค่าที่พักที่ยังไม่มีข้อมูล
ไม่ต้องมี backend, ฐานข้อมูล, login, upload/OCR, การตรวจซ้ำ, การอนุมัติ หรือการจ่ายเงินจริง ปุ่มเป็นภาพจำลองได้ ไม่บังคับให้คลิกทำงาน ข้อมูลและสถานะตัวอย่างต้องติดป้ายว่าจำลอง ไม่แต่งนโยบายที่ยังไม่ยืนยัน
ใน output.md เพิ่มตาราง Pain Point → FR/BR → หน้าหรือส่วนของ Mockup พร้อมอธิบายว่าหน้าจอแต่ละส่วนช่วยผู้ใช้อย่างไร

### เกณฑ์ตรวจ C1–C3
C1. ส่ง output.md ที่มีหัวข้อและแผนภาพครบตามรายการ Output พร้อม mockup.html ที่แสดงครบสามส่วน: ยื่นเบิก ติดตามใบเบิก และตรวจ/อนุมัติ โดยเป็นภาพจำลอง ไม่ต้องมีระบบธุรกรรมทำงานจริง
C2. บันทึกสัมภาษณ์ทุกบรรทัดปรากฏใน Traceability Matrix โดยเชื่อมโยงกับ FR-xx หรือ BR-xx อย่างน้อยหนึ่งข้อ หากมีสองบรรทัดที่ให้กติกาต่างกันสำหรับการตัดสินใจเรื่องเดียวกัน ต้องยกทั้งสองบรรทัดไว้ใน Open Issues โดยไม่เลือกข้าง และตัวเลขทุกตัวที่ปรากฏใน FR/BR/Open Issues ต้องตรงตามที่ปรากฏในข้อมูลนำเข้าทุกตัวอักษร
C3. ทุก Entity และ Attribute ที่ระบุชื่อใน Sequence Diagram และ State Diagram ต้องมีอยู่ใน ERD ทุกสถานะใน State Diagram ต้องระบุว่าใบเบิกอยู่กับใครในขณะนั้น และทุกบล็อก Mermaid ต้อง render ได้ (ใช้ renderer ที่ติดตั้งในเครื่องหากมี มิฉะนั้นให้ตรวจ syntax อย่างเคร่งครัด พร้อมระบุว่าใช้วิธีใด) และ mockup.html ต้องเปิดเห็นครบทั้ง 3 หน้าหรือส่วน ข้อความสถานะ ผู้รับผิดชอบ และกติกาต้องสอดคล้องกับเอกสาร มีตารางเชื่อม Pain Point → FR/BR → หน้าจอ แสดงข้อมูลจำลองและนโยบายที่รอยืนยันชัดเจน ตรวจเฉพาะความครบของภาพและความสอดคล้อง ไม่กำหนดให้ปุ่มหรือระบบธุรกรรมทำงานจริง
