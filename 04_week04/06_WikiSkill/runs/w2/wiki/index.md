# Wiki Index

- [missing-input-validation](wiki/patterns/missing-input-validation.md): ยังเกิดอยู่ (ตกทุกงาน) `reject_value`/`reject_type` ตกเพราะ Agent เขียนแต่ happy path ไม่ได้แปลงช่วงค่าและชนิดข้อมูลในโจทย์เป็นการตรวจอินพุต ให้ตรวจช่วงและชนิดแบบเข้ม (ไม่รับ float/bool) ก่อนการคำนวณหรือ early return ทุกครั้ง แล้ว `raise ValueError`
- [missing-cli-entrypoint](wiki/patterns/missing-cli-entrypoint.md): ยังเกิดอยู่ (ตกทุกงาน) `cli_ok`/`cli_error` ตก stdout ว่าง exit 0 เพราะ `solve.py` มีแต่ฟังก์ชัน ไม่มี `__main__` ที่อ่าน JSON จาก stdin ให้เพิ่ม entrypoint ที่พิมพ์ `{"ok": true, "result": ...}` exit 0 และเมื่อ error พิมพ์ `{"ok": false, "error": ...}` exit 2 ไม่มี traceback
- [missing-test-file](wiki/patterns/missing-test-file.md): ยังเกิดอยู่ (ตกทุกงาน) `tests` ตกเพราะโจทย์ไม่ได้สั่ง Agent จึงไม่สร้าง `test_solve.py` ให้สร้างไฟล์เทสข้าง `solve.py` ครอบ happy path ขอบเงื่อนไข ValueError และ CLI แล้วรันให้ผ่านก่อนส่ง (ยังไม่ยืนยันว่าตัวตรวจรันเทสด้วยหรือเช็กแค่ไฟล์)
- [no-self-verification](wiki/patterns/no-self-verification.md): ยังเกิดอยู่ Agent ส่งงานโดยไม่รันเลย (t4) หรือรันแค่ 2–4 ค่าที่เป็นกรณีปกติ จึงไม่เห็นว่าขาดทั้งการตรวจอินพุต CLI และเทส ให้รัน `python solve.py` ผ่าน stdin ทดสอบกรณีผิดและรัน test_solve.py ก่อนส่ง และเทียบทุกกฎในโจทย์กับโค้ดทีละข้อ
- [policy-mismatch-unconfirmed](wiki/patterns/policy-mismatch-unconfirmed.md): ยังไม่ยืนยัน `policy` ตกใน cashback (คาด 300 ได้ 600) และ shipping_fee (คาด 0 ได้ 8000) ทั้งที่อ่านโจทย์ตรงตัว ไม่รู้ว่าเพราะตีความผิดหรือกฎที่ตัวตรวจใช้ไม่ได้เขียนในโจทย์ ให้เขียนตารางตัวอย่างคำนวณมือหลายกรณี จดข้อสมมติ และรอบหน้าดูรายการกรณีที่ตกเพื่อยืนยัน
- [integer-math-half-up-works](wiki/patterns/integer-math-half-up-works.md): วิธีที่ได้ผล (ผ่าน `contract`/`basic`/`half_up`/`no_drift`/`boundary`) เพราะคำนวณเงินเป็นสตางค์ด้วยจำนวนเต็ม/Fraction ไม่ใช้ float แล้วปัดครึ่งขึ้นครั้งเดียวตอนท้าย ให้คงวิธีนี้ไว้ในสกิล
