# เขียนฟังก์ชันคิดเงินให้ผ่านเทสต์ที่ซ่อนอยู่

ตัวตรวจให้คะแนนด้วยเทสต์ 4 กลุ่ม: **Normal, Boundary, NoDrift, Reject**
รอบที่ผ่านมา Solver ผ่าน 3 กลุ่มแรกแต่ **ตก Reject ทั้งหมด** เพราะไม่ตรวจ input เลย (คะแนนค้างที่ ~0.5)
ดังนั้นต้องทำครบทุกกลุ่ม ไม่ใช่แค่สูตรถูก

## ผลวิเคราะห์ epoch 1 (สำคัญมาก)
หลังเพิ่มการตรวจ input เทสต์ภายในผ่านหมด แต่คะแนนจริงยังแค่ 0.6–0.9 โดย **เฉพาะครั้งที่มีฟังก์ชัน `main()` อ่าน JSON จาก stdin ได้คะแนนสูงกว่าครั้งที่ไม่มี ~0.2**
ตัวตรวจรัน `solve.py` ผ่าน CLI ด้วย: `echo '{"price":...}' | python3 solve.py` (stdin = JSON object ของอาร์กิวเมนต์ตามชื่อพารามิเตอร์)
**ทุกครั้งต้องมี `main()` และ `if __name__ == "__main__": sys.exit(main())` ตามเทมเพลต** ถึงโจทย์จะไม่พูดถึงก็ตาม
- สำเร็จ: พิมพ์ `{"ok": true, "result": <ผล>}` exit 0
- ValueError/TypeError/JSON เสีย/ไม่ใช่ object: พิมพ์ `{"ok": false, "error": "..."}` exit 2
- ห้ามพิมพ์อย่างอื่นลง stdout

## ขั้นตอน
1. อ่านโจทย์ทีละบรรทัด ทำรายการ: พารามิเตอร์ + ช่วงที่ถูกต้อง, กฎแต่ละข้อ, ลำดับการคิด, หน่วยผลลัพธ์
2. เริ่มจากเทมเพลต `template_solve.py` (อยู่ในโฟลเดอร์สกิลนี้ — คัดลอกไปเป็น `./solve.py` แล้วแก้ส่วนสูตร)
3. เขียน `test_solve.py` (unittest, `from solve import <ฟังก์ชัน>`) ไว้ในโฟลเดอร์เดียวกับ solve.py ให้ครบ 4 กลุ่มด้านล่าง (Normal/Boundary/NoDrift/Reject ≥ 2–4 เคสต่อกลุ่ม) แล้วรัน `python3 -m unittest -q test_solve` ให้ผ่านก่อนจบ และทดสอบ CLI ด้วย echo ... | python3 solve.py อย่างน้อย 1 เคสสำเร็จ 1 เคส reject
4. ไฟล์ต้องชื่อ `solve.py` ในโฟลเดอร์ทำงาน และชื่อฟังก์ชัน/ลำดับพารามิเตอร์ตรงตามโจทย์เป๊ะ

## 1) Reject — ตรวจ input ให้เข้ม (จุดที่เสียคะแนนมากที่สุด)
ให้ `raise ValueError` (ไม่ใช่ TypeError/AssertionError/KeyError) เมื่อ:
- จำนวนเต็มต้องเป็น `type(v) is int` เท่านั้น → **ปฏิเสธ float (เช่น 4500.0), str ('3'), bool (True), None**
- พารามิเตอร์ตัวเลขทุกตัวต้องเป็น int เสมอ (แม้เป็น 'ระยะทาง' 'น้ำหนัก' 'ยอด') ห้ามเปิดรับ float เพื่อความสะดวก ยกเว้นโจทย์ระบุทศนิยมชัดเจน — float เช่น 4500.0 หรือ 10.5 ต้อง ValueError
- ค่าอยู่นอกช่วงที่โจทย์ระบุ: เช่น "ตั้งแต่ 0" → ติดลบผิด, "ตั้งแต่ 1" → 0 ผิด, "1–30,000" → 0 และ 30001 ผิด, "0–100" → 101 ผิด
- ค่า bool (เช่น member, express, birthday) ต้องเป็น `type(v) is bool` จริง ๆ (ห้ามรับ 0/1/"yes")
- ค่า enum (เช่น tier) ต้องเป็น str และอยู่ในรายการที่โจทย์ให้ — ค่าอื่น/ตัวพิมพ์ต่างกัน/ไม่ใช่ str ให้ ValueError
- list/dict: ตรวจว่า type เป็น list/dict, สมาชิกมี key ครบ, แต่ละค่าผ่านกฎเดียวกับด้านบน (เช่น qty ≥ 1, price ≥ 0 และเป็น int)
- ตรวจ **ก่อน** คำนวณใด ๆ และตรวจแม้ทางลัด (เช่น ยอดต่ำกว่าเกณฑ์ คืน 0) — input ผิดต้อง raise ก่อนเสมอ
- ห้ามกลืน error แล้วคืนค่า 0 / None

## 2) NoDrift — เลขต้องแม่นไม่คลาดสตางค์
- ห้ามใช้ float เด็ดขาด (ไม่ใช้ `*0.95`, `round()`, `/`) ใช้ `fractions.Fraction` หรือเลขจำนวนเต็มล้วน
- คูณทุกขั้นตามลำดับที่โจทย์บอกด้วย Fraction (เช่น 95/100, 90/100, 107/100) **แล้วปัดครั้งเดียวตอนท้าย** ห้ามปัดกลางทาง เว้นแต่โจทย์สั่ง
- "คูณต่อจากข้อก่อน" = ทบต้น (คูณกัน) ไม่ใช่บวกเปอร์เซ็นต์รวมกัน
- "คิดตามสัดส่วน" (เช่น ส่วนที่เกินกิโลกรัมละ 15 บาท คิดตามกรัม) → ใช้ Fraction ของส่วนเกิน ไม่ปัดเป็นกิโลเต็ม
- กฎการปัด (ใช้เมื่อโจทย์ไม่ได้ระบุ):
  - เงินที่ **ลูกค้าจ่าย** (ยอดบิล, ค่าส่ง, ทิป, ยอดหาร) → **ปัดครึ่งขึ้น** `int((Fraction(x)*2+1)//2)`
  - เงินที่ **ร้านจ่ายออก** ให้ลูกค้า (เงินคืน, cashback, แต้มแลกเงิน, ส่วนลดคืน) → **ปัดลง** (floor) `int(Fraction(x)//1)`
  - ถ้าโจทย์ระบุวิธีปัดไว้ ให้ทำตามโจทย์
- ผลลัพธ์ต้องเป็น `int` ของ Python (ไม่ใช่ Fraction/float)

## 3) Boundary — ขอบเขตของเงื่อนไข
- "ตั้งแต่ X ขึ้นไป" = `>= X`, "เกิน X" = `> X`, "ไม่เกิน X" = `<= X`, "ต่ำกว่า X" = `< X`
- เงื่อนไขเกณฑ์ (เช่น ยอด ≥ 500 บาท) ตัดสินจาก **ค่าก่อนส่วนลดขั้นถัดไป** ตามที่โจทย์เรียง — ถ้าไม่ชัด ใช้ยอดรวมดิบ
- แปลงหน่วยให้ถูก: บาท→สตางค์ ×100 (500 บาท = 50000 สตางค์, 200 บาท = 20000)
- เพดาน/พื้น (สูงสุดต่อบิล) ใช้กับผลลัพธ์ **หลัง** คูณตัวคูณทั้งหมด ถ้าโจทย์เรียงไว้อย่างนั้น
- ทดสอบค่าติดขอบทั้งสองด้านของทุกเกณฑ์ (X-1, X, X+1), ค่า 0, ค่าน้อยสุด/มากสุด

## 4) Normal / การหารที่ไม่ลงตัว
- หารแบ่งคน: `base, extra = divmod(grand, people)` คนแรก ๆ `extra` คนได้ `base+1` ผลรวมต้องเท่า grand เสมอ
- รายการ (list) ที่คืนต้องเรียงตามลำดับคน และความยาว = people

## เมื่อโจทย์ไม่ชัด / มีกรณีที่ไม่ได้พูดถึง
- อ่านซ้ำว่ามีคำใบ้ในประโยค (ช่วงค่า, หน่วย, ข้อจำกัดของตัวเลือก) แล้วตีความแบบตรงตัวที่สุด อย่าเพิ่มกฎที่โจทย์ไม่ได้เขียน
- กรณีขอบที่ธุรกิจจริงมักมีนโยบายพิเศษ (ระยะทาง 0 = รับเองที่ร้าน, สิทธิ์พิเศษที่บางระดับสมาชิกอาจไม่ได้, ตัวเลือกด่วนที่จำกัดน้ำหนัก) ถ้าโจทย์ไม่ได้ระบุก็อย่าเดาเอง ให้ทำตามตัวอักษร แต่ **ระบุข้อสันนิษฐานในคำตอบสุดท้ายให้ชัด** ว่าตีความอย่างไร
- ลองตั้งคำถามกับค่าที่ช่วงที่โจทย์อนุญาตแต่ไม่มีตัวอย่าง (เช่น 0, ค่าสูงสุด) ว่าสูตรยังสมเหตุผลหรือไม่ ถ้าโจทย์บอกช่วงชัดแล้ว ห้าม reject ค่าในช่วงนั้น
