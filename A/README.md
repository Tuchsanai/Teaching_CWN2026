## เริ่มอย่างไรโดยไม่เขียนโค้ด

ทุก LAB ใช้วงจรเดียวกันซ้ำทุกขั้น: **อ่านโจทย์ → คัดลอกพรอมท์ → วางใน AI ภายในคอนเทนเนอร์ → ดูผลลัพธ์จริง → เทียบ Expected Output → ทำขั้นถัดไป**

1. ผู้สอนเตรียม container, การเชื่อมต่อ SSH และ AI CLI ที่ล็อกอินพร้อมรับ prompt ตาม [คู่มือผู้สอน](instructor/README.md) แล้วทำ LAB 001 ก่อน
2. แต่ละโฟลเดอร์ LAB มี **README.md เป็นเอกสารผู้เรียนไฟล์เดียว** อ่านจากบนลงล่าง: ก่อนเริ่ม → โจทย์ธุรกิจฉบับเต็ม → ขั้นที่ 1…N → ส่งงาน แต่ละขั้นมี 6 ส่วนเรียงเหมือนกันทุก LAB: 🎯 เป้าหมาย · 📥 ข้อมูลตั้งต้น · 📋 พรอมท์สำหรับคัดลอก · ✅ Expected Output · 🔍 จุดที่ต้องตรวจ · 🔁 ถ้าผลไม่ตรง
3. คัดลอก **ทั้งกรอบ** ในหัวข้อ 📋 แล้ววางในช่องสนทนาของ AI CLI ที่เปิดอยู่ภายใน SSH (ถ้าเห็น `$` หรือ `#` แสดงว่ายังอยู่ใน shell ให้ผู้สอนเปิด wrapper ให้ก่อน) กรอบพรอมท์มีโจทย์และกฎธุรกิจอยู่ครบในตัว AI ไม่ต้องอ่าน README
4. โฟลเดอร์ `prompts/` ของ LAB 002–007 เก็บพรอมท์ย่อยของแต่ละขั้น (`step-01.md`, `step-02.md`, …) เนื้อหาตรงกับกรอบใน README ทุกตัวอักษร ถ้าผู้สอนวางโฟลเดอร์ LAB ไว้ใน container ที่ `/root/workspace/sa-labs/` แล้ว ผู้เรียนวาง "ทางลัด" หนึ่งบรรทัดที่อยู่ใต้กรอบแทนได้ AI จะอ่านไฟล์นั้นเอง
5. AI ทำเฉพาะขั้นนั้น แสดงเนื้อหาไฟล์ที่สร้างบนหน้าจอ แล้วหยุดรอ ผู้เรียนเทียบกับ ✅ Expected Output และติ๊ก 🔍 ก่อนไปขั้นถัดไป ถ้าไม่ตรงให้วางข้อความจากตาราง 🔁 ผลงานทั้งหมดอยู่ใน `/root/workspace/sa-work/001/` ถึง `/root/workspace/sa-work/007/`
6. เมื่อเปลี่ยนผู้ทำหรือผู้ตรวจ ให้เปิด wrapper ของบัญชีที่ระบุในอีกหน้าต่าง ถ้ามี CLI ค่ายเดียวให้ใช้ตัวเดิมและติดป้าย `SIMULATION` ในผลส่งงาน ไม่นับว่าตรวจข้ามค่ายแล้ว

ผู้เรียนไม่ต้องพิมพ์คำสั่งใด ๆ นอกจากชื่อ wrapper (`yolo1`, `cyolo1`, `qyolo1`) เพื่อเปิด AI ทุก LAB มีผังขั้นตอนใน `img/flow.png` และ LAB 002–007 ทำแยกกันได้หลังผ่าน LAB 001

## อ่านผลให้เป็น

- **PASS**: มีหลักฐานตรงเกณฑ์ เช่น กรอกจองครบแล้วจำนวนที่ว่างลดลงจริง
- **FAIL**: ทดสอบแล้วพฤติกรรมผิดจากเกณฑ์ ต้องบอกข้อที่ผิดและส่งกลับแก้
- **SKIP**: ยังไม่ได้ทดสอบ เช่น ไม่มี credential ของเจ้าของบัญชี หรือไม่มีเครื่องมือเรียกผู้ตรวจอีกค่าย
- หัวข้อ Expected ใน README คือแนวคำตอบสำหรับเปรียบเทียบ ไม่ใช่หลักฐานว่า AI ในบัญชีของผู้เรียนรันสำเร็จ คำพูดต่างกันได้ แต่กฎธุรกิจและเกณฑ์ตรวจต้องตรง

การตอบข้อความทดสอบได้พิสูจน์ว่าคำขอไปถึงบริการและได้คำตอบ แต่ไม่พิสูจน์ว่าทุก wrapper เป็นคนละบัญชี เจ้าของต้องตรวจตัวตนในหน้าบัญชีเป็นการส่วนตัวและตรวจ config root ด้วย ห้ามใช้ข้อความที่โมเดลกล่าวถึงตัวเองเป็นหลักฐานตัวตน

## กติกาข้อมูล

ใช้ `<YOUR_EMAIL>`, `<YOUR_NAME>`, `<YOUR_USERNAME>`, `<YOUR_TOKEN>` และชื่อบทบาทสมมติเท่านั้น ไม่ใส่ค่าจริงใน prompt ผลงาน ภาพหน้าจอ หรือรายงาน แชร์ได้เฉพาะไฟล์โจทย์ ข้อกำหนด และผลตรวจในโฟลเดอร์โครงการ Credential/config/session/history/cache เป็นของแต่ละบัญชี

`yolo1`, `cyolo1`, `qyolo1` เป็นชื่อคำสั่งตัวอย่าง ไม่ใช่ชื่อผู้ใช้จริง เลขท้ายคือบัญชี ไม่ใช่ชื่อโมเดล รุ่น ราคา โควตา endpoint และสิทธิ์ต้องตรวจจากระบบจริง อย่าใช้ตัวเลขในบทเรียนเดิมเป็นข้อมูลล่าสุด
