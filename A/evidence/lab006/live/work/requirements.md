# requirements.md — B01–B09 (SIMULATION)

> **ป้ายกำกับ: `SIMULATION`** — เอกสารนี้จัดทำด้วย CLI เดียว (ตัวเดิม) ข้อมูลผู้เรียนเป็นรหัสจำลอง `<LEARNER_A>`–`<LEARNER_D>` ไม่ใช่ข้อมูลจริง
> เวอร์ชัน: 1.1 | วันที่: 2026-09-07 | ผู้จัดทำ: System Analyst (<REDACTED>)

## 1. เป้าหมาย (Goal)

แปลง brief ให้เป็นข้อกำหนดที่ **ตรวจได้** สำหรับหน้าจอจองที่นั่งเวิร์กช็อป **“ออกแบบบริการด้วย AI”** จำนวน **3 ที่นั่ง** ทำงานใน **browser เดียว** เก็บสถานะด้วย `localStorage` ทุกผลลัพธ์ต้องพิสูจน์ได้ด้วย **ตัวเลข** (จำนวนรายการ / ที่นั่งเหลือ) และ **การคลิก/กดปุ่ม** ที่ระบุขั้นตอนชัดเจน

## 2. บทบาท (Roles)

| บทบาท | สิ่งที่ทำได้ |
|---|---|
| ผู้เรียน (Learner) | กรอกรหัสผู้เรียน กดจอง กดยกเลิกรายการ |
| ผู้ตรวจ UAT (Tester) | รัน UAT-01 ถึง UAT-09 บันทึกผ่าน/ไม่ผ่านตามผลคาดหวัง |
| System Analyst | เจ้าของเอกสารนี้ ไม่เพิ่ม/ลดกฎนอกเหนือ B01–B09 |

## 3. ขอบเขต (Scope)

**อยู่ในขอบเขต:** browser เดียว, `localStorage`, หน้าจอกว้าง 375px, keyboard/focus, ข้อความภาษาไทย
**ไม่อยู่ในขอบเขต:** หลาย browser / ซิงก์ข้ามเครื่อง, login, การแจ้งเตือน, การชำระเงิน, การขึ้น production

## 4. กฎ B01–B09 และเกณฑ์ที่ตรวจได้

| รหัส | กฎ | เกณฑ์ที่ตรวจได้ (ตัวเลข / การคลิก) |
|---|---|---|
| **B01** | เวิร์กช็อปชื่อ “ออกแบบบริการด้วย AI” มี 3 ที่นั่ง เริ่มต้นไม่มีการจอง | เปิดหน้าครั้งแรก: ชื่อบนหน้าจอ = “ออกแบบบริการด้วย AI” ตรงตัวอักษร; ที่นั่งทั้งหมด = 3; จำนวนรายการจอง = 0; ที่นั่งเหลือ = 3 |
| **B02** | รับรหัส `<LEARNER_A>`–`<LEARNER_D>` ไม่ใช้ข้อมูลจริง | ช่องกรอกรับรหัสจำลอง 4 ค่า; ไม่มีช่องชื่อ-นามสกุล / อีเมล / เบอร์โทร บนหน้าจอ (นับได้ = 0 ช่อง) |
| **B03** | ช่องว่าง/space ล้วน และรหัสซ้ำ ไม่ผ่าน; จองสำเร็จแล้วเพิ่มรายการ ลดที่นั่งทันที | คลิกจองขณะช่องว่าง (0 ตัวอักษร) หรือ `"   "` (space ล้วน) → รายการคงเดิม ที่นั่งเหลือคงเดิม พร้อมข้อความไทย; คลิกจองรหัสที่มีอยู่แล้ว → รายการคงเดิม พร้อมข้อความไทย; จองสำเร็จ 1 ครั้ง → รายการ +1 และที่นั่งเหลือ −1 ทันทีในคลิกเดียว (ไม่ต้อง refresh) |
| **B04** | ครบ 3 รายการแล้วคนที่ 4 ไม่ผ่าน ต้องแจ้งว่าเต็มและเหลือ 0 | เมื่อรายการ = 3: ที่นั่งเหลือ = 0; คลิกจอง `<LEARNER_D>` → รายการยังคง = 3, ที่นั่งเหลือยังคง = 0, มีข้อความไทยว่าเต็ม และแสดงเลข 0 |
| **B05** | ยกเลิกได้ คืนที่นั่งทันที แล้วคนที่เคยถูกปฏิเสธจองได้ | คลิกยกเลิก 1 รายการ → รายการ −1, ที่นั่งเหลือ +1 ทันที; จากนั้นคลิกจองรหัสที่เคยถูกปฏิเสธ → สำเร็จ, รายการกลับเป็น 3, ที่นั่งเหลือ = 0 |
| **B06** | refresh แล้วข้อมูลคงอยู่ใน browser เดิมด้วย localStorage | มีรายการ N รายการ → กด F5 → จำนวนรายการ = N และที่นั่งเหลือ = 3 − N เท่าเดิม; `localStorage` มีคีย์ของแอปเก็บค่าอยู่ |
| **B07** | “เริ่มใหม่” ล้างข้อมูลจำลองใน browser นี้ | คลิก “เริ่มใหม่” → รายการ = 0, ที่นั่งเหลือ = 3; refresh อีกครั้งยังคง 0 / 3 |
| **B08** | ที่ 375px ไม่เลื่อนแนวนอน ใช้ keyboard ได้ มี focus ชัด | viewport 375px: `document.documentElement.scrollWidth − clientWidth = 0`; กด `Tab` เข้าถึงช่องกรอก → ปุ่มจอง → ปุ่มยกเลิก → ปุ่มเริ่มใหม่ ครบทุกตัวควบคุม; `Enter`/`Space` สั่งงานปุ่มได้; ทุกตำแหน่ง focus มีขอบ/วงแหวนมองเห็นได้ |
| **B09** | ผลจอง/ปฏิเสธ/ยกเลิก มีข้อความไทย ไม่ใช้แค่สี | ทั้ง 3 เหตุการณ์แสดงข้อความไทยอย่างน้อย 1 ประโยค (ยาว > 0 ตัวอักษร) อ่านรู้เรื่องแม้เป็นภาพขาวดำ; ไม่มีกรณีที่สื่อผลลัพธ์ด้วยสีเพียงอย่างเดียว |
