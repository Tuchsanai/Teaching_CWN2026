## 3. ขอบเขต (Scope)

**อยู่ในขอบเขต**
- ทำงานใน **browser เดียว** บนหน้าเดียว (single page, single file)
- เก็บสถานะด้วย `localStorage` คีย์ `aiDesignWorkshop.bookings.v1`
- เวิร์กช็อป “ออกแบบบริการด้วย AI” จำนวน **3 ที่นั่ง** เริ่มว่าง (0 รายการ / เหลือ 3)
- รหัสผู้เรียนจำลอง 4 ค่า: `<LEARNER_A>`, `<LEARNER_B>`, `<LEARNER_C>`, `<LEARNER_D>`
- รองรับความกว้าง **375px** ไม่เลื่อนแนวนอน, ใช้งานด้วย keyboard, มี focus ชัด
- ข้อความสถานะทุกเหตุการณ์เป็น**ภาษาไทย** และไม่ได้สื่อด้วยสีเพียงอย่างเดียว
- แจ้งเตือนบนหน้าจอเมื่อ `localStorage` ใช้งานไม่ได้ (เช่น โหมด private / ถูกบล็อก)

**ไม่อยู่ในขอบเขต (ตาม brief)**
- backend / ฐานข้อมูล / API ภายนอก
- login หรือยืนยันตัวตน
- การแจ้งเตือนภายนอก (อีเมล / SMS / push)
- การชำระเงิน
- หลาย browser หรือซิงก์ข้ามเครื่อง, การขึ้น production

## 5. กฎ B01–B09 → จุดที่รองรับในโค้ด

| กฎ | กลไกใน `index.html` |
|---|---|
| B01 | ค่าคงตัว `WORKSHOP_NAME = "ออกแบบบริการด้วย AI"`, `TOTAL_SEATS = 3`; เริ่ม `state.bookings = []` → 0 รายการ / เหลือ 3 |
| B02 | ช่องกรอกเดียว `#learner-code` + `<label>`; คำแนะนำระบุ `<LEARNER_A>`–`<LEARNER_D>`; ไม่มี input ประเภทอื่นบนหน้า |
| B03 | `normalizeCode()` ตัดช่องว่าง/space ล้วน → ว่าง = ปฏิเสธ; `indexOfCode()`/`sameCode()` กันรหัสซ้ำ (ไม่แบ่งตัวพิมพ์ใหญ่-เล็ก); `book()` เพิ่มรายการแล้ว `render()` ทันที ไม่ต้อง refresh |
| B04 | `remainingSeats() <= 0` → ปฏิเสธคนที่ 4 พร้อมข้อความไทยระบุ “คงเหลือ 0 ที่นั่ง” และตัวเลขยังคง 3 / 0 |
| B05 | `cancel(code)` ตัดรายการออก คืนที่นั่ง แล้ว `render()` ทันที; รหัสที่เคยถูกปฏิเสธจองได้ใหม่ในรอบถัดไป |
| B06 | `save()` เขียน JSON ลงคีย์ `aiDesignWorkshop.bookings.v1`; `load()` อ่านกลับตอนเปิดหน้าพร้อมทำความสะอาดข้อมูล (กันรายการเกิน 3, รหัสซ้ำ, เลขที่นั่งซ้ำ) |
| B07 | `resetAll()` ล้าง `state.bookings`, ลบคีย์ใน storage, ล้างช่องกรอก → 0 รายการ / เหลือ 3 และคงค่าเดิมหลัง refresh |
| B08 | CSS: `box-sizing: border-box` ทุกชิ้น, `.wrap{max-width:600px;width:100%}`, `min-width:0` + `overflow-wrap:anywhere`, grid `minmax(0,1fr)`, ปุ่ม `min-height:44px`; focus วงแหวน `outline:3px solid` ทุกสถานะ; ลำดับ Tab = ช่องกรอก → ปุ่มจอง → ปุ่มยกเลิก → ปุ่มเริ่มใหม่; `keepFocus()` คืน focus ให้ปุ่มที่ถูกกดหลัง re-render |
| B09 | `setStatus(kind, text)` เขียน**ข้อความไทยเต็มประโยค**ทุกเหตุการณ์ (สำเร็จ/ปฏิเสธ/ยกเลิก/แจ้งเตือน) พร้อมตัวเลขกำกับ; สีเป็นเพียงส่วนเสริม (แถบซ้าย + ขอบ) ไม่ใช่วิธีสื่อความหมายเดียว |

## 6. สถานะการตรวจในขั้นนี้ (sanity check — ไม่ใช่ผล UAT)

| หัวข้อที่ตรวจ | ผล |
|---|---|
| เซิร์ฟเวอร์ตอบกลับ `GET /index.html` | HTTP `200` — ก่อนแก้ 24,089 ไบต์, หลังเพิ่ม favicon แบบ inline 24,123 ไบต์ |
| โหลดหน้าใน headless Chromium ที่ viewport 375×812 | โหลดสำเร็จ, `document.documentElement.scrollWidth − clientWidth = 0` (ไม่เลื่อนแนวนอน) |
| ชิ้นส่วนที่เลยกรอบ 375px | 0 ชิ้น |
| ค่าเริ่มต้นบนหน้าจอ | ที่นั่งทั้งหมด `3` · จองแล้ว `0` · ที่นั่งเหลือ `3` · การ์ดที่นั่ง 3 ใบ |
| ข้อความผิดพลาดใน console / page error | ไม่มี (แก้ 404 ของ `favicon.ico` ด้วย `<link rel="icon" href="data:,">` แล้ว) |
| โครงสร้างฟอร์ม | `label[for]` 1 ตัว, `input` 1 ตัว (type text), ปุ่มคงที่ 2 ตัว (`จองที่นั่ง`, `เริ่มใหม่`), ปุ่ม `ยกเลิก` เกิดตามจำนวนรายการ |
| live region | `#status` มี `role="status"` + `aria-live="polite"` 1 จุด |
| `localStorage` | ใช้งานได้จริงใน browser นี้ → แถบเตือน `#storage-warn` ยังซ่อนอยู่ (คีย์จะถูกสร้างเมื่อมีการจองครั้งแรก) |
| การอ้างอิงภายนอกในไฟล์ | ไม่พบ `http(s)://`, `src=`, `CSS import`, `url()` — เป็นไฟล์เดียวจบจริง |
| ไวยากรณ์ JavaScript | ผ่านการตรวจ syntax (`node --check`) |

**สิ่งที่ยังไม่ได้ทำในขั้นนี้ (ตั้งใจเว้นไว้):** ยังไม่ได้รันเคส UAT-01 ถึง UAT-09 (การจอง/ปฏิเสธ/ยกเลิก/refresh/keyboard/ขาวดำ) จึงยังไม่มีผลผ่าน-ไม่ผ่านในไฟล์นี้ — เป็นงานของขั้น UAT ถัดไป

## 7. วิธีเปิดดูด้วยตนเอง

1. เปิด browser ที่ `http://127.0.0.1:8080/index.html` (หรือ `http://0.0.0.0:8080/index.html`)
2. ตั้ง viewport กว้าง 375px หากต้องการตรวจ B08/B09
3. กรอกรหัสจำลอง เช่น `<LEARNER_A>` แล้วกดปุ่ม “จองที่นั่ง” หรือกด `Enter`
4. ใช้ปุ่ม “ยกเลิก” ท้ายแต่ละรายการเพื่อคืนที่นั่ง และ “เริ่มใหม่ (ล้างข้อมูลจำลอง)” เพื่อล้างทั้งหมด
