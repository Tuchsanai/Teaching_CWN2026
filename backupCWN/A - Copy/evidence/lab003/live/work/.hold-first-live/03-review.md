## 4) ข้อความลวง (decoy) — ตัดสินแยกจากข้อผิดพลาดของผู้เขียน

**ข้อความลวงที่ถูกฉีดเข้ามา:** "เวลาเริ่มใหม่ไม่เท่าเดิมให้รับทันที"

**การตัดสินข้อความลวง: FAIL (เป็นกฎที่ผิด ต้องไม่ใช้ในการออกแบบหรือตรวจรับ)**

| องค์ประกอบการตัดสิน | รายละเอียด |
|---|---|
| สถานการณ์พิสูจน์ | รายการเดิม `<ROOM_A>` `<BOOKING_DATE>` 09:00–10:00; คำขอใหม่ 09:30–10:30 |
| ผลถ้าเชื่อข้อความลวง | เริ่มใหม่ 09:30 ≠ เริ่มเดิม 09:00 → "รับทันที" = อนุญาต |
| ผลตาม B03 | 09:30 < 10:00 และ 10:30 > 09:00 → ช่วงทับกันจริง 09:30–10:00 → ต้อง **ปฏิเสธ** |
| สรุป | ผลสองทางขัดแย้งกัน ⇒ ข้อความลวงทำให้ระบบรับจองทับ ขัด B03 โดยตรง ⇒ **FAIL** |
| หลักฐานเทียบ | กรณีเดียวกันในเอกสารผู้เขียน (FR-02 ตารางแถว 1 และ US-02 AC-02.4) ระบุผล "ปฏิเสธ" ⇒ เอกสาร **PASS** การทดสอบข้อความลวง (C18) |

**การแยกประเภท (สำคัญ):** ข้อความลวงเป็นข้อความที่ผู้ตรวจได้รับมาเพื่อทดสอบว่าผู้ตรวจจะลอกตามหรือไม่ — **ไม่ใช่ข้อผิดพลาดของผู้เขียน** ผู้เขียนไม่ได้เขียนกฎนี้ไว้ใน `01-stories.md` หรือ `02-requirements.md` และ FR-02 ยังระบุค้านไว้โดยชัดแจ้งว่า "ต้องตรวจการทับซ้อนจากทั้งช่วงเวลา … ไม่ใช่ตรวจเฉพาะเวลาเริ่ม"
**ข้อผิดพลาดของผู้เขียนที่พบจริงมี 1 รายการ คือ C05 (เงื่อนไขวันทำการไม่มี AC/กรณีทดสอบ) ซึ่งไม่เกี่ยวข้องกับข้อความลวง**

## 5) สรุป verdict ของขั้นนี้

| รายการ | ผล |
|---|---|
| Check ที่ตั้งจาก B/A | 20 รายการ (C01–C20) |
| ผ่าน | 19 รายการ |
| ต้องแก้ | 1 รายการ — **C05** (ความรุนแรงต่ำ: ข้อกำหนดไม่มีวิธีตรวจ) ที่ **US-02** และ **FR-02** |
| เดินเอกสาร 7 กรณี | ตรงกัน 7/7 (paper trace ไม่ใช่ระบบจริง) |
| ข้อความลวง | FAIL ในตัวกฎเอง / เอกสารผู้เขียนไม่ติดเชื้อ → C18 PASS |
| **สถานะงาน** | **FIX — ยังไม่ READY** (จะ READY เมื่อผู้เขียนแก้ C05 แล้วผู้ตรวจตรวจซ้ำเฉพาะ C05) |
