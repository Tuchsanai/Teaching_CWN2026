## 3. ข้อขัดแย้งที่พบและวิธีหาข้อสรุป

| ประเด็น | หลักฐานและข้อสรุป |
|---|---|
| ข้อกำหนดใหม่กับ As-Is | “ต้องเก็บความยินยอม” และ “ต้องจองคิวเองผ่าน LINE OA ได้” เป็นความต้องการอนาคต จึงคง As-Is เดิม |
| ต้องเก็บ consent แต่ไม่มีหลักฐาน | CSV ไม่มีข้อมูลความยินยอม; “จองซ้ำทางไลน์” ไม่ใช่คำยินยอม จึงเก็บ unknown/missing ไม่สร้าง granted หรือ denied |
| เบอร์ร่วมกับสิทธิ์จองเอง | เบอร์แถว 1/2/5 ตรงกัน แต่ไม่มีตัวระบุบัญชีที่ยืนยันแล้ว จึงแยกข้อมูลติดต่อออกจาก authentication, patient linkage และ authorization |
| Mapping กับ ERD | เพิ่มตารางเทียบฟิลด์ หลักฐาน consent และประวัติเหตุการณ์/สิทธิ์ให้รองรับแผน migration โดยคงส่วนแก้ไขจากเฟสแรก |
| Rollback กับการถอนสิทธิ์ | รักษา withdrawal/revoke ที่เกิดหลัง snapshot; ไม่คืน granted หรือ active link จากข้อมูลเก่า |
| กฎที่หลักฐานไม่พอ | INPUT ไม่ระบุฐานประมวลผล retention หรือรายละเอียด LINE integration จึงยังไม่เลือกค่าแทนคลินิก; วันที่ ตัวตน และคิวชนเดิมยังรอมนุษย์ยืนยัน |

รายละเอียดข้อขัดแย้งและหลักฐานรายข้ออยู่ในส่วน 3 ของ `output.md`
