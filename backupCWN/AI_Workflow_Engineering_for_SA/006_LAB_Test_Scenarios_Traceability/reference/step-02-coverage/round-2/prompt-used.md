# ขั้น 6.2 — ผู้ตรวจความครอบคลุม
## บริบทและเป้าหมาย
คุณเป็นผู้ตรวจอิสระของชุด scenario; ROUND = 2 (ตรวจตั้งต้น 0; แก้ได้ 1 และ 2)
## Input
อ่าน ../../../../docs/case-study-source.md, ../../../input/coverage-criteria.md,
../fix-1/scenario-set-round-1.json และไฟล์ scenario ทั้งสามตาม manifest
อ่าน ../../step-00-input/input-check.md และ ../../../input/ui-scenarios.json เพื่อกัน ID ชน/การอ้างเกินขอบเขต
## งาน
ตรวจครบ 26 US แยกสำเร็จ/ทางเลือก/ผิดพลาด/ข้อยกเว้น ไม่ใช้จำนวน scenario รวมแทน coverage
ตรวจแต่ละ clause, ตัวเลข AC, expected, mapping และประเภท automation
รายงานตาราง 26 แถว × ประเภท scenario โดยทุกช่องมี TestID หรือ MISSING/N/A พร้อมเหตุผล
เงื่อนไขขั้นต่ำทุก US: สำเร็จ >=1 และผิดพลาดหรือข้อยกเว้น >=1
กรณี mock-not-testable นับเป็นการออกแบบที่ครอบคลุมได้ แต่ไม่ใช่ผลทดสอบผ่าน
อย่าให้ผ่านเมื่อมีเพียงชื่อ scenario แต่ไม่มีวิธีตรวจ/expected หรือแก้ตัวเลขต้นฉบับ
## Output
สร้าง coverage-round-2.md มีตาราง US | สำเร็จ | ทางเลือก | ผิดพลาด | ข้อยกเว้น | AC clauses | automation | ขาด/ผิด
ตามด้วยรายการ MISSING ที่ระบุ US, clause, เจ้าของ, เหตุผล, path, วิธีแก้
ระบุผล COVERED หรือ GAPS พร้อมจำนวน US ที่เข้าเกณฑ์จากไฟล์จริง
ผู้ตรวจไม่แก้ scenario เอง; ถ้าช่องว่างเดิมไม่ลดหรือครบแก้ 2 รอบให้ STOP_WITH_GAPS

## กติกาและขอบเขต
Working directory: โฟลเดอร์ขั้นนี้
เริ่ม session ใหม่ทุกการเรียก อ่าน Input จากไฟล์ ไม่พึ่งประวัติสนทนา ไม่เรียกผู้ช่วยเพิ่ม
เขียนเฉพาะไฟล์ Output ที่ระบุในโฟลเดอร์ขั้นนี้ ห้ามแก้ไฟล์อื่น
หาก output มีแล้วให้หยุดและขอ path รุ่นใหม่ในบันทึก ไม่เขียนทับหลักฐาน
รักษาข้อความ US/AC ตัวเลข หน่วย สูตร และจำนวนตัวอย่างต้นฉบับทุกข้อ
ใช้ข้อมูลจำลองเท่านั้น; สมมติฐาน fixture ไม่ใช่ข้อกำหนดร้าน
ข้อมูลขาดให้ระบุ BLOCKED/ไม่มีข้อมูล ไม่แต่ง FR, Flow, selector หรือผลผ่าน
ผลคลิก Mock-up ไม่ยืนยัน LAN, Security, Load, Availability หรือการชำระเงินจริง
สรุปไฟล์ที่สร้างจริง ข้อบกพร่อง ข้อค้าง และสิ่งที่ยังไม่ได้ทดสอบ


## ข้อกำหนดการรันผลอ้างอิง
ใช้ path ที่ปรับใน prompt นี้แทน path ต้นแบบ ห้ามเขียน work/ หรือพื้นที่อื่น
ทุก path ภายใน manifest ให้ถือว่า relative จากโฟลเดอร์ LAB ซึ่งอยู่ที่ ../../..
ห้ามเรียก AI เพิ่ม ห้ามแก้ผลเก่าหรือ input; ห้ามใส่ชื่อบัญชีจริง รหัสงานภายใน หรือ path เครื่องในเอกสาร ให้ใช้ relative path เท่านั้น
นี่คือการตรวจครั้งที่ 2 หลังแก้ครั้งที่ 1 (บทเรียนเรียกการแก้นี้ round-1) ยังเหลือสิทธิ์แก้อีก 1 ครั้งตามเพดาน 2 รอบแก้ ไม่ใช่หมดเพดานจากชื่อโฟลเดอร์
อ่าน ../round-1/coverage-round-1.md และ ../fix-1/coverage-fixes-round-1.md เพื่อเทียบ gap เดิมกับผลล่าสุด; แยกจำนวน US ที่ผ่านเกณฑ์ขั้นต่ำการออกแบบ กับจำนวนที่ครบ mapping ทุกมิติ
manifest ใหม่มีค่า relative จาก LAB root ตามคำสั่ง; หาก path ต่างให้ resolve จากไฟล์จริงและบอกฐานที่ใช้ ห้ามแก้ manifest
บอกชัดว่า gap ใดลด แก้ได้ต่อ หรือเป็น upstream/business ที่แก้ไม่ได้ด้วย scenario; STOP_WITH_GAPS ถ้าเหลือเฉพาะข้อมูลต้นทางขาดหรือชุดช่องว่างไม่ลด; อย่าให้ MISSING upstream กลบการนับขั้นต่ำต่อ US
