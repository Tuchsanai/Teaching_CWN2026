# Input ของ LAB 004

## ไฟล์ตั้งต้นและที่มา

อ่านผลจาก `../003_LAB_Static_Graph_Flow_Structure/work/` ของนักศึกษาก่อน
ใช้ `lab004-handoff.md` เป็น manifest เลือก snapshot เดียวกันทั้งชุด ไม่เลือกแต่ละไฟล์จากคนละรอบ
ต้องมี flow-customer.md, flow-kitchen-front.md, flow-manager.md, state-machine.md, structure.md และ flow-merge.md
นำ JSON คู่กันและ merge-report.md มาด้วยเมื่อมี เพื่อดู conflicts, sources และ FR/US ที่ตรวจย้อนกลับได้
ถ้า LAB ก่อนหน้าให้ชื่อ flow-state-machine.md หรือ flow-structure.md ให้ใช้ manifest ยืนยันไฟล์แทน ไม่เดาว่าเหมือนกัน

หากยังไม่มีผลของตนเอง ให้เลือกชุดที่มีอยู่จริงใน `../003_LAB_Static_Graph_Flow_Structure/reference/`
ตรวจชื่อโฟลเดอร์รุ่นและ manifest ก่อนเลือก; คู่มือไม่สมมติว่าผลอ้างอิงถูกสร้างแล้ว
บันทึกข้อความ **ใช้ผลอ้างอิง ไม่ใช่ผลที่นักศึกษารันเอง** ลง `work/input-source.md`
ถ้าทั้ง work/ และ reference/ ยังไม่มีไฟล์ครบ ให้บันทึก MISSING และหยุดก่อนสร้าง UI ห้ามแต่ง flow ทดแทน
ดูวิธีและ Prompt เตรียมชุดใน [คู่มือ LAB](../README.md) และ [Prompt เตรียม Input](../prompts/00-prepare-input.md)

## สมมติฐานที่เปิดเผย

- สามแท็บหลัก = ลูกค้า / ครัวและหน้าร้าน / ผู้จัดการ; kitchen/front เป็นสิทธิ์แยกในแท็บเดียวกันตามบริบท
- หนึ่งแท็บ browser แชร์ state ระหว่างบทบาท; การแจ้งเตือน, PromptPay, นาฬิกา และ login เป็นการจำลอง
- schema, รหัส seed, ราคา และ selectors เป็นข้อตกลงการเรียน ไม่ใช่การเพิ่มเติมกฎธุรกิจของร้าน
- A-02: หมายเหตุ ก./ค./ช. ยังไม่พบนิยาม ไม่เติมความหมายเอง
- DI-04/A-03: US-20 ต้นฉบับอ้าง US-14; การเชื่อมกฎแมปกับ US-12/US-13 เป็นข้อเสนอที่ยังไม่ยืนยัน
- DI-07/A-05: ชื่อสถานะระดับรายการ/ออเดอร์/การจ่ายต้องแยกกัน; การแมป เสร็จแล้ว กับ พร้อมเสิร์ฟ ยังรอยืนยัน
- ผลผ่านตัวตรวจไม่รับรอง LAN, ความปลอดภัย, สัดส่วนสำเร็จหลายรอบ หรือการติดตั้งระบบจริง
