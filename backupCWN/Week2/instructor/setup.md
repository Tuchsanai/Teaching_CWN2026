# เตรียมห้องเรียน — ผู้สอนทำก่อนเริ่มจับเวลาภารกิจ

ใช้เครื่อง Linux ที่มี Python 3, Git (launcher ใช้สร้างพื้นที่ฝึก), cyolo1 และบัญชี ChatGPT ของห้องที่มีสิทธิ์ใช้โมเดลกำหนด ไม่มีการอ่านหรือคัดลอก credential ในแพ็กเกจนี้ ผู้เรียนไม่ต้องเขียนโปรแกรมหรือจัดการ API

## 1. ตรวจเครื่องและเปิดแพ็กเกจ

แตก ZIP เป็น Week2 แล้วเปิด Terminal ที่โฟลเดอร์ Week2 เครื่องที่ใช้พอร์ต 18762 อยู่แล้วให้ผู้สอนจัดสภาพแวดล้อมใหม่ก่อนเรียน ไม่ให้ผู้เรียนแก้ config ระหว่างภารกิจ

```bash
cyolo1 --version
env CODEX_HOME=/root/workspace/.Codex/cyolo1 codex login status
./shop preflight
python3 -m http.server 18761 --bind 127.0.0.1
```

เปิด `http://127.0.0.1:18761/index.html` ใน browser เครื่องเดียวกัน คำสั่ง web server เปิดค้างใน Terminal ผู้สอน เมื่อจบกด Ctrl+C ในหน้าต่างนั้น บริการร้านใช้คนละพอร์ตและเริ่มเฉพาะตามกิจกรรม

ถ้าย้ายเครื่องต้องมี wrapper cyolo1 ที่ผู้สอนจัดไว้เอง path login ด้านบนเป็นเฉพาะเครื่องอ้างอิงนี้ ไม่ต้อง copy บัญชีไปกับ ZIP ไม่ใช้โมเดลอื่นแทนเงียบ ๆ หาก login ไม่ผ่านให้ผู้สอนจัดบัญชีก่อนเริ่มงาน

## 2. Native Skill ที่เตรียมไว้

ต้นฉบับสาม Skill อยู่ที่ `.agents/skills/shop-requirements/SKILL.md`, `shop-recovery/SKILL.md`, `shop-complaints/SKILL.md` ทั้งหมดเป็น text-only และไม่มี scripts ใน Skill

[OpenAI Docs: Build skills](https://learn.chatgpt.com/docs/build-skills) ระบุ `name`/`description`, project discovery ผ่าน `.agents/skills`, เรียกด้วย `$` หรือ `/skills` ใน Codex CLI และโหลด body เมื่อใช้ Skill; ตรวจแหล่ง 2026-09-12 UTC ให้แยก syntax นี้จากหน้า ChatGPT ซึ่งอาจใช้ `@`

ให้เปิดโปรเจกต์ S ใหม่ที่ launcher สร้างก่อนเรียก ไม่เปิด Codex จากโฟลเดอร์รวมที่มีเฉลย ชื่อ/คำอธิบายคือขั้นค้นพบ body คือขั้นใช้จริง ไม่ใช่การฝึกโมเดลใหม่

## 3. เส้นทางผู้เรียนที่ตรวจใช้งานได้ — ready launcher

เตรียมรอบ P:

```bash
./learn prepare lab1 A P
./learn inspect
./learn run start
```

เตรียมรอบ S ในบริบทใหม่:

```bash
./learn close
./learn prepare lab1 B S
./learn inspect
./learn run start
```

`inspect` แสดงโฟลเดอร์และ path native ส่วน `run start` เรียก cyolo1 exec จริงด้วย gpt-6-astra/high, stdin ปิดด้วย /dev/null, JSONL และ -o เป็นไฟล์จริง Deadline 240 วินาที เรียกซ้ำเฉพาะเมื่อผู้สอนอนุมัติและแยก label ไม่ลบงานล้มเหลว

เปลี่ยน lab1 เป็น lab2/lab3 และ A/B/C ตามใบมอบหมายโดยคัดลอกคำสั่งที่ตรงรอบ ไม่แก้สคริปต์ ทุก prepare สร้าง input-only directory ใหม่ ไม่มีเฉลยหรือผลรอบอื่น ผลอยู่ใน `learner-results` แยกจาก input อย่าให้ผลงานเดิมปนในการเปรียบเทียบ

```bash
./learn run analyze
./learn run revise
./learn run verify
./learn run ask
./learn close
```

analyze/revise/verify ส่งข้อความพร้อมร่างก่อนหน้าเฉพาะรอบเดียวกัน นับรวมได้สองครั้งในรอบเปรียบเทียบ; ask ใช้วางข้อความภาษาคนเอง จบข้อความด้วย END หนึ่งบรรทัด ไม่ต้องพิมพ์คำสั่งโปรแกรม

## 4. กิจกรรมให้ AI สร้าง Skill (หลังเก็บร่าง A/B แล้ว)

เปิดพื้นที่ฝึกใหม่ ไม่ใช้รอบเก็บคะแนนหลัก:

```bash
./learn prepare lab3 C S
./learn run ask
```

วางข้อความนี้แล้ว END:

```text
สร้าง Skill ใหม่ชื่อ complaint-desk ใน .agents/skills/complaint-desk/SKILL.md ให้ฉัน โดยคุณเป็นคนเขียนไฟล์ ไม่ให้ฉันเขียนโค้ด Skill เป็นคำแนะนำข้อความล้วน ใช้เมื่อร้านต้องจัดคิวและร่างตอบข้อร้องเรียนจาก input.md และ manual.md ต้องตรวจนโยบายที่มีผลจริง อ้าง ID ทุกเคส แยกข้อมูลขาด จัดคิวอันตรายก่อน ส่งข้อยกเว้นให้คน และไม่อนุมัติ/ส่งข้อความเอง มี name description จุดประสงค์ ข้อมูลเข้า ขั้นตอน รูปแบบผล และรายการตรวจ สรุป path และสิ่งที่สร้างให้ฉันตรวจ
```

ดูคำตอบและไฟล์ที่ AI สร้างด้วยตัวอ่านเอกสาร ไม่แก้ไฟล์เอง จากนั้นเรียก ask อีกครั้ง:

```text
$complaint-desk อ่าน .agents/skills/complaint-desk/SKILL.md ด้วยเครื่องมืออ่านไฟล์เพื่อยืนยันการใช้ แล้วจัดการ input.md ชุด C ตาม manual.md ส่งร่างและสิ่งที่ต้องถาม
```

ให้ผู้สอนตรวจ log ว่ามีการอ่าน path นี้จริง และ frontend name/description ผ่านตัวตรวจ Skill การพูดว่า “ใช้ Skill” อย่างเดียวไม่พอ หาก CLI ไม่พบ ให้เปิด Codex ใหม่ที่ workspace ที่ inspect แสดง หรือใช้ launcher ซึ่งเริ่ม exec ใหม่ทุกครั้ง

## 5. ปรับ Skill ด้วยข้อผิดพลาดอย่างมีหลักฐาน

ตัวอย่าง v1 ที่บกพร่อง **ผู้สอนแต่งเพื่อสอน ไม่ใช่ผลทดลองจริง**: “จำไว้ว่าร้านรับชำรุดแค่ 7 วัน และไม่รับเปลี่ยนใจทุกกรณี” เมื่อใช้กับ C จะปฏิเสธ C101 และ C303 ผิด เพราะ C-P1 v2 เปลี่ยนเป็น 14 วันและอนุญาตเปลี่ยนใจบางกรณี

วางคำสั่งภาษาคนให้ AI ปรับ (เลือกไฟล์ Skill ที่กำลังฝึก):

```text
ตัวอย่าง v1 ที่ใช้กฎ 7 วันและห้ามคืนเปลี่ยนใจทุกกรณีใช้กับ C ไม่ได้ตาม C-P1 v2 ช่วยปรับ complaint-desk ที่คุณสร้าง ให้ตรวจรุ่น วันที่มีผล และขอบเขตจากข้อมูลใหม่ก่อนตัดสินทุกครั้ง อย่า hard-code จำนวนวันไว้ใน Skill คุณเขียนไฟล์ให้เอง คงการอ้าง ID และการไม่อนุมัติข้อยกเว้น สรุปเฉพาะสิ่งที่ปรับกับเหตุผล แล้วฉันจะทำ C ใหม่ในบริบทใหม่
```

เก็บ Skill ก่อน/หลังและเวลาปรับ การทำ C ซ้ำหลังเห็นเฉลยเป็น assisted transfer ไม่ใช่ผลทั่วไปที่ไม่เคยเห็นข้อมูล หากคำตอบแรกดีอยู่แล้ว ให้ใช้ตัวอย่างผิดที่ติดป้ายนี้ ไม่อ้างว่าพบข้อผิดพลาดจริง

## 6. จัดร้านฝึกก่อนภารกิจ

```bash
./shop reset basic-A
./shop preflight
./shop status
```

ต้องได้ STOPPED v1 และ preflight ผ่านก่อนเริ่มเวลา 30 นาที ชุด B ใช้ basic-B; รอบต่อยอดเริ่ม advanced-A/B เป็นเหตุการณ์ใหม่ ทุกคนใช้คู่มือเดียวกัน ผู้เรียนห้ามแก้ runtime ผู้สอนเก็บ state นอก ZIP โดยอัตโนมัติและหยุดด้วย `./shop stop` หลังจบ

การตรวจ browser ในเครื่องนี้ใช้ Playwright CLI 1.58.2 กับ Chromium executable ที่มีจริง ดูคำสั่ง/viewport/URL/ผลใน evidence/browser และ verification.md การติดตั้งเครื่องมือทดสอบเป็นงานผู้สอน ไม่เป็นส่วนของบทเรียนผู้ใช้ทั่วไป

## หลายกลุ่มบนเครื่องเดียว (ผู้สอนเท่านั้น)

แนะนำหนึ่งเครื่องฝึก/VM ต่อกลุ่ม ถ้าแชร์ Linux host ให้ใช้สำเนา Week2 คนละโฟลเดอร์และพอร์ตคนละหมายเลขก่อนเรียน โดยผู้สอนรันในสำเนานั้น:

```bash
python3 instructor/runtime/provision_shop.py --port 18763
./shop preflight
```

สำเนาที่สองเลือกพอร์ตว่างของตน ผู้เรียนใช้ `./shop open` จึงไม่ต้องแก้คำสั่งหรือ config บริการผูกเฉพาะ loopback การส่งออกหน้าเรียนใช้พอร์ตอื่นที่ครูจัดก่อนเรียน รายการจองฝึกอยู่ในหน่วยความจำและหายเมื่อหยุดหรือเปลี่ยนรุ่น ไม่ใช่ระบบรับออเดอร์จริง

ก่อนรอบ advanced ให้ครูแสดงผล known-good v1 ของ runtime ฝึกจาก evidence/browser/pilot-runtime/basic-A.json หรือ basic-B.json และเลขจองที่ตรวจแล้ว ผู้เรียนยังต้องตรวจสถานะปัจจุบันก่อน rollback ไม่ถือว่าเลขเวอร์ชันอย่างเดียวพิสูจน์ว่าใช้งานได้
