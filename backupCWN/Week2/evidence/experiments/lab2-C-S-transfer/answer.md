**หลักฐานที่ให้มา**

ชุด C เป็นสถานการณ์สมมติ ไม่ใช่ผลจากการรันจริง จึงยังใช้ยืนยันสถานะร้านปัจจุบันหรือผลกู้คืนไม่ได้

| ID | สิ่งที่เห็น | ความหมาย |
|---|---|---|
| C-U1 | `RUNNING version=v2` | ตามโจทย์ โปรแกรมร้านกำลังทำงานด้วยรุ่น v2 ไม่ใช่บริการหยุด |
| C-U2 | เปิดหน้าร้านได้ แต่จองไม่สำเร็จ พร้อม `UPDATE_V2_BOOKING_BROKEN` | หน้าเว็บเปิดได้ไม่ได้แปลว่าจองสินค้าได้ |
| C-U3 | v1 เคยตรวจการจองผ่าน; บันทึกมี `UPDATE_APPLIED` และ `BOOKING_ERROR` ไม่มีเหตุอื่น | สนับสนุนว่าปัญหาเกิดจากรุ่นอัปเดต v2 และมี v1 ที่เคยใช้งานได้ |
| C-N1 | ยังไม่มีผลหลังแก้ และให้เริ่มด้วย `./shop reset transfer-C` | ต้องให้คนตั้งรอบฝึกและตรวจหลักฐานสดก่อนเลือกคำสั่งกู้ |

**ข้อสันนิษฐานและความมั่นใจ:** สาเหตุหลักเพียงหนึ่งคือ **รุ่นอัปเดต v2 ทำให้การจองเสีย** ความมั่นใจสูงสำหรับสถานการณ์ที่โจทย์ระบุ [C-U1–C-U3] แต่ยังไม่ยืนยันกับร้านที่รันจริง [C-N1] คำสั่งที่ตรงสาเหตุคือ `rollback` ซึ่งหมายถึงกลับไปใช้รุ่นก่อนหน้าที่ตรวจแล้วว่าดี ส่วน `start` ใช้กับบริการหยุด จึงไม่ตรงกับหลักฐานนี้ [C-U1, C-U3; manual.md]

**สิ่งที่ต้องถามหรือขอเพิ่มจากผู้เรียนเมื่อทำจริง:** หลังตั้งรอบ ขอผล `status`, `logs` (บันทึกเหตุการณ์) และผลกดจองผ่านเบราว์เซอร์ เพื่อยืนยันว่าร้านยังเป็น v2 ที่เปิดได้แต่จองเสียตามโจทย์ [C-U1–C-U3, C-N1] รอบนี้ไม่มีผู้เรียนโต้ตอบ จึงให้แผนแบบมีเงื่อนไขไว้ โดยไม่ถือว่าได้รับหลักฐานแล้ว

**คำแนะนำสำหรับคนทำ ตามลำดับ**

ใช้คำสั่งจากโฟลเดอร์ Week2 ตามคู่มือเท่านั้น ผลในตารางเป็นสิ่งที่คาดหวัง ไม่ใช่ผลที่เกิดขึ้นแล้ว

| คำสั่งตามลำดับ | เมื่อใด | เหตุผล | ผลคาดหวัง |
|---|---|---|---|
| 1. `./shop reset transfer-C` | เริ่มรอบนี้ ตาม C-N1 เท่านั้น | เตรียมสถานการณ์ร้านใหม่ | `RESET transfer-C RUNNING version=v2` |
| 2. `./shop preflight` | ก่อนเริ่มวินิจฉัยสด | ตรวจ Python และพอร์ตที่ร้านใช้รับการเชื่อมต่อ | `PREFLIGHT OK` และ URL; หากขัดข้อง ให้หยุดแจ้งผู้สอน |
| 3. `./shop status` แล้ว `./shop logs` | หลังตั้งรอบ | ตรวจสถานะ รุ่น และเหตุการณ์จริง | หากตรงโจทย์ จะเป็น v2 และมีหลักฐานอัปเดต/การจองผิดพลาด |
| 4. `./shop open` แล้วเปิด URL และกด **จองสินค้า** ด้วยข้อมูลฝึก | เก็บอาการก่อนกู้ | ตรวจการใช้งานจริงผ่านเบราว์เซอร์ | หากตรง C-U2 จะเปิดหน้าได้แต่จองไม่สำเร็จ; เก็บข้อความที่พบ |
| 5. `./shop rollback` | **เฉพาะเมื่อหลักฐานสดยืนยัน v2 เปิดได้แต่จองเสีย และ v1 ก่อนหน้าเคยผ่าน** | กลับรุ่นที่ดีตาม C-U3 | `ROLLED BACK version=v1` |
| 6. `./shop status` | หลัง rollback | ยืนยันสถานะและรุ่นหลังเปลี่ยน | `RUNNING version=v1` |
| 7. `./shop check` | หลังตรวจสถานะ | ตรวจทั้งหน้าเว็บและการจองผ่านจุดรับคำขอจริงของร้าน | `CHECK PASS booking=... version=v1`; จดเลขจริง |
| 8. `./shop open` แล้วเปิด URL และกด **จองสินค้า** | หลัง check ผ่าน | ยืนยันว่าผู้ใช้จองผ่านเบราว์เซอร์ได้ | เห็นเลขจองจริงและรุ่น v1 |
| เมื่อทดสอบไม่ผ่าน: `./shop logs` | หากกู้หรือทดสอบไม่สำเร็จ | เก็บเหตุการณ์เพื่อแจ้งผู้สอน | ส่งบันทึกพร้อมอาการ แล้วหยุดการแก้ต่อ |

หากหลักฐานสดต่างจากโจทย์หรือไม่พอ ให้หยุดก่อน `rollback` และขอ `status`/`logs` เพิ่ม ไม่เปลี่ยนหลายอย่างพร้อมกัน และห้าม reset ระหว่างกู้เพื่อทำให้ผลดูผ่าน [C-N1; manual.md]
