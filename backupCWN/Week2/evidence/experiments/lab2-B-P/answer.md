ร่างนี้ใช้เฉพาะ input.md และ manual.md เป็นการวินิจฉัย **ร้านจำลอง ไม่มีการชำระเงินจริง** ผู้ใช้เป็นผู้เลือกและรันคำสั่งเอง ยังไม่มีหลักฐานหลังแก้ไข ทั้งสองรอบเป็นคนละเหตุการณ์ ไม่ใช่ขั้นตอนต่อเนื่องกัน

**หลักฐานก่อนกู้**

| ID | สิ่งที่เห็น | ความหมาย |
|---|---|---|
| B-S1 | `STOPPED version=v1` | บริการหยุดอยู่ที่รุ่น v1 |
| B-S2 | Browser แสดง `ERR_CONNECTION_REFUSED` | เปิดร้านที่ URL ในหลักฐานไม่ได้ สอดคล้องกับบริการหยุด |
| B-S3 | logs มี `SERVICE_STOPPED` และ `SERVICE_NOT_STARTED` | บันทึกระบุว่าบริการยังไม่ได้เริ่มทำงาน |
| B-U1 | `RUNNING version=v2 bookings=0` | บริการทำงานอยู่ที่ v2; จำนวนจองศูนย์เพียงอย่างเดียวไม่พิสูจน์ว่าระบบเสีย |
| B-U2 | Browser จองไม่สำเร็จ พร้อม `UPDATE_V2_BOOKING_BROKEN` | การจองผ่านหน้าเว็บล้มเหลว โดยระบุปัญหาของ v2 |
| B-U3 | logs มี `STARTED`, `UPDATE_APPLIED` และ `BOOKING_ERROR` พร้อมสาเหตุ `UPDATE_V2_BOOKING_BROKEN` | บริการเริ่มแล้ว แต่รุ่นอัปเดตมีปัญหาการจอง |

**สาเหตุ ข้อสันนิษฐาน และสิ่งที่ต้องตรวจเพิ่ม**

- **รอบ basic — สาเหตุหลักหนึ่งข้อ:** บริการยังไม่ได้เริ่มทำงาน ความมั่นใจสูง จาก B-S1–B-S3 จึงเข้าเงื่อนไขเลือก `start`
- **รอบ advanced — สาเหตุหลักหนึ่งข้อ:** รุ่นอัปเดต v2 จองสินค้าไม่ได้ ความมั่นใจสูง จาก B-U1–B-U3 จึงไม่ใช่กรณีใช้ `start` แก้ปัญหา
- **ข้อสันนิษฐานที่ยังไม่ยืนยัน:** basic น่าจะกลับมาใช้งานได้หลังเริ่มบริการ แต่ B-S1–B-S3 ยังไม่พิสูจน์ว่าจองสำเร็จ ส่วน advanced ยังไม่มีหลักฐานว่า v1 ก่อนหน้าตรวจแล้วว่าดีใน B-U1–B-U3
- **สิ่งที่ต้องถามผู้สอนก่อน advanced:** “มี v1 ก่อนหน้าที่ตรวจแล้วว่าจองผ่านหรือไม่ และมีหลักฐานเลขจองกับรุ่นใด?” ต้องยืนยันเงื่อนไขนี้ก่อนเลือก `rollback` ห้ามถือว่า v1 ดีเพียงเพราะ basic แสดงรุ่น v1 (B-S1)
- **สิ่งที่ต้องตรวจเพิ่มทั้งสองรอบ:** สถานะปัจจุบันและผลหลังทำ เพราะ B-S1–B-S3 และ B-U1–B-U3 เป็นภาพก่อนกู้ หากสถานะจริงไม่ตรงหรือหลักฐานไม่พอ ให้ขอ `status` และ `logs` แล้วหยุดก่อนเปลี่ยนแปลง

คำศัพท์: **บริการ** คือโปรแกรมที่รับคำขอจากหน้าเว็บ; **รุ่น** คือชุดพฤติกรรมของโปรแกรม เช่น v1/v2; **logs** คือบันทึกเหตุการณ์; **rollback** คือกลับไปใช้รุ่นก่อนที่ตรวจแล้วว่าดี; **endpoint** คือจุดรับคำขอของโปรแกรมที่ `check` ใช้ทดสอบ

**คำแนะนำสำหรับคนทำ — ใช้แยกตามรอบ**

คำสั่งในคู่มือให้รันจากโฟลเดอร์ Week2 เปลี่ยนเพียงอย่างเดียวตามสาเหตุ แล้วตรวจผล

| ลำดับ / คำสั่ง | เมื่อใด | เหตุผล | ผลคาดหวัง |
|---|---|---|---|
| 1. `./shop preflight` | ก่อนเริ่มแต่ละรอบ | ตรวจ Python และพอร์ตตามคู่มือ | `PREFLIGHT OK` และ URL; หากมีเหตุขัดข้องให้หยุดแจ้งผู้สอน |
| 2. `./shop status` | ก่อนเลือกคำสั่งกู้ | ยืนยันสถานะและจดรุ่นก่อนทำ | basic: `STOPPED version=v1`; advanced: `RUNNING version=v2` |
| 3. `./shop logs` | ก่อนเลือกคำสั่งกู้ | ตรวจเหตุการณ์รอบปัจจุบันให้ตรงกับหลักฐาน | basic สอดคล้อง B-S3; advanced สอดคล้อง B-U3; หากไม่ตรงให้หยุดประเมิน |
| 4ก. `./shop start` | **เฉพาะ basic** เมื่อยังหยุดที่ v1 ตาม B-S1–B-S3 | เริ่มบริการรุ่นปัจจุบัน | `STARTED version=v1` |
| 4ข. `./shop rollback` | **เฉพาะ advanced** เมื่อยืนยันปัญหาตาม B-U1–B-U3 **และมี v1 ที่ตรวจแล้วว่าดี** | กลับจากรุ่นที่จองเสีย | `ROLLED BACK version=v1`; ถ้ายังไม่มีหลักฐาน v1 ที่ดี ให้พักขั้นนี้ |
| 5. `./shop status` | หลังคำสั่งกู้ของรอบนั้น | ตรวจสถานะและรุ่นหลังทำ | `RUNNING version=v1` |
| 6. `./shop check` | หลังสถานะตรงตามคาด | ทดสอบหน้าเว็บและการจองผ่าน endpoint จริง | `CHECK PASS booking=… version=v1`; จดเลขจริง |
| 7. `./shop open` | หลัง check ผ่าน | รับ URL ไปเปิด browser | URL ร้านในเครื่อง เช่น `http://127.0.0.1:18762` โดยใช้ค่าที่คำสั่งพิมพ์จริง |
| 8. กด **จองสินค้า** ใน browser | เปิดหน้าเว็บแล้ว ใช้ข้อมูลฝึก | ยืนยันว่าผู้ใช้ทำรายการได้จริง | จองสำเร็จ เห็นเลขจองจริงและรุ่น v1 |
| หากไม่สำเร็จ: `./shop logs` | ขั้นกู้หรือทดสอบไม่ผ่าน | เก็บเหตุการณ์ให้ผู้สอนตรวจ | บันทึก logs พร้อมข้อผิดพลาด แล้วหยุดทดลองและแจ้งผู้สอน |

หน้าเว็บเปิดได้หรือ HTTP 200 **ยังไม่ยืนยันว่าจองได้** แม้ `check` ผ่านก็ต้องทำรายการผ่าน browser เพิ่ม ห้ามใช้ `reset` เพื่อทำให้ผลดูผ่าน และห้ามแก้ไฟล์ภายใน/ตั้งค่า ติดตั้งแพ็กเกจ ลบข้อมูล เปิดพอร์ตสาธารณะ หรือใช้คำสั่งนอกคู่มือ

**ช่องรอหลักฐานหลังทำ — กรอกผลจริงเท่านั้น**

| รายการบันทึก | basic | advanced |
|---|---|---|
| ผู้ทำ / เวลา / คำสั่งที่ทำจริงตามลำดับ | รอกรอก | รอกรอก |
| หลักฐาน v1 ก่อนหน้าที่ดี | — | รอยืนยันก่อน rollback |
| รุ่นก่อน → หลัง | ภาพก่อน: v1 → รอตรวจ | ภาพก่อน: v2 → รอตรวจ |
| ผล status หลังทำ | รอผล | รอผล |
| ผล check / เลขจองจาก check | รอผล | รอผล |
| ผล browser / เลขจองจาก browser / รุ่นที่แสดง | รอผล | รอผล |
| logs หรือข้อผิดพลาดที่ส่งผู้สอน | รอกรอกถ้ามี | รอกรอกถ้ามี |
| สถานะ: รอทดสอบ / ผ่าน / ไม่ผ่าน | **รอทดสอบ** | **รอทดสอบ** |

ให้ลงว่า **ผ่าน** เมื่อ status เป็น `RUNNING version=v1`, check ผ่าน และ browser จองสำเร็จพร้อมเลขจองและรุ่น v1 ครบเท่านั้น ขณะนี้ยังสรุปว่ากู้คืนสำเร็จไม่ได้
