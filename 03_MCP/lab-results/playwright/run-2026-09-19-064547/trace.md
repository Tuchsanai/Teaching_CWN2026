## ไฟล์หลักฐานในโฟลเดอร์นี้
- `cs2-01-loaded.png` หน้าเว็บหลังเปิด (ขั้น 1–2) · `cs2-02-filled.png` หลังกรอกฟอร์ม (ขั้น 3) · `cs2-03-result.png` หลังกดปุ่มและได้ผล (ขั้น 4–6) · `cs2-04-error-empty.png` กรณีข้อความว่าง (ขั้น 7)
- `snapshot-01-loaded.yml`, `snapshot-03-result.yml`, `snapshot-04-error.yml` = accessibility snapshot ที่ Playwright MCP คืนให้ AI (สิ่งที่ AI "มองเห็น")
- `console.log` = console ของหน้าเว็บ (มีเพียง favicon 404) · `result-audio.wav` = ไฟล์เสียงที่เว็บสร้าง (คัดลอกจาก labs/kokoro-web/audio_out/)

## ข้อสังเกตจากการทดลอง
1. **AI มองเห็นหน้าเว็บผ่าน accessibility snapshot** ไม่ใช่รูปภาพ: ทุก element มี ref (e9, e13, e14 ...) ที่ใช้อ้างในคำสั่งถัดไป การตั้ง `<label>`/`aria-label` ที่ดีในเว็บทำให้ AI เลือก element ได้ถูกต้องตั้งแต่ครั้งแรก
2. **การคลิกล้มเหลว 2 ครั้งด้วยเหตุผลที่ไม่ใช่บั๊กของเว็บ**: แท็บอยู่เบื้องหลัง (`document.visibilityState === "hidden"`) เพราะ Excalidraw MCP ใช้เบราว์เซอร์ตัวเดียวกันก่อนหน้า Playwright จึงรอเงื่อนไข "stable" ไม่ผ่านใน 5 วินาที แก้ด้วย `browser_tabs select` แล้วคลิกผ่านทันที — บทเรียนคือเมื่อ tool ล้มเหลวให้ใช้ tool วินิจฉัย (`browser_evaluate`) หาสาเหตุก่อนแก้
3. screenshot ที่สั่งด้วยชื่อไฟล์แบบ relative ถูกบันทึกที่ working directory ของ process playwright-mcp (โฟลเดอร์ที่เปิด Claude Code) ไม่ใช่ `--output-dir` จึงต้องย้ายไฟล์เข้าโฟลเดอร์หลักฐานเอง
4. ตัวเลขที่ยืนยันได้: เสียงยาว 7 วินาที (ตรงกับ `audio.duration` = 7 และไฟล์ .wav 24000 Hz) เวลาสร้าง 576 ms บน CPU · POST /api/tts ตอบ 200 · เบราว์เซอร์โหลดเสียงแบบ range request (206)
