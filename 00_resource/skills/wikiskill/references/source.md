# ที่มาของแต่ละส่วน · เทียบกับเปเปอร์ WikiSkill

เปเปอร์: Tang et al., *WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution* (arXiv:2608.27454)
อ่านจาก: หน้า HTML ของ arXiv (ข้อ 2, 3, ภาคผนวก A.1, C, D.2) และสรุปภาษาไทยของบท 06 · **ไม่ได้เปิดภาคผนวก E** (prompt ของเปเปอร์) เพื่อให้ prompt ของสกิลนี้เป็นถ้อยคำของตัวเอง

## วงรอบของ WikiSkill ใน 1 หน้า

**3 ชั้น** (เปเปอร์ ข้อ 3.1)

| ชั้น | เก็บอะไร | ตอบคำถาม | กติกา |
|---|---|---|---|
| Raw (`raw/`) | Trace ของ Training ทุกรอบ | เกิดอะไรขึ้นในงานนี้ | เขียนครั้งเดียว ไม่แก้ |
| Wiki (`wiki/`) | pattern · index · log · skill-impact | ทำไมจึงเกิด และเคยลองแก้อย่างไร | สะสมทุกรอบ ไม่ถูกย้อนกลับ |
| Skills (`skills/`) | `SKILL.md` + `PURPOSE.md` ของสกิลที่ใช้งาน | งานถัดไปต้องทำอย่างไร | เปลี่ยนเมื่อผ่าน gate เท่านั้น ย้อนกลับได้ |

**4 ส่วนประกอบ** (เปเปอร์ ข้อ 3.2)

| ส่วนประกอบ | รับเข้า | ส่งออก | เห็นอะไรได้ |
|---|---|---|---|
| Inference Agent | โจทย์ + ชุดสกิล S | ผลงาน + Trace | `skills/` เท่านั้น (ไม่เห็น wiki และ raw) |
| Wiki Maintainer | wiki เดิม + Trace ที่สุ่ม (ไม่ผ่าน ≤ 5 · ผ่าน ≤ 3) | รายการแก้ wiki | wiki ทั้งหมด + Trace ตัวอย่าง |
| Skill Proposer | index + skill-impact + สรุปผล แล้วเปิดไฟล์เอง (ReAct) | ข้อเสนอ 1 ข้อ ต่อสกิล 1 ตัว | wiki · Trace ของรอบนี้ · สกิล (อ่านอย่างเดียว) |
| Gating and Rollback | ชุดสกิลที่เสนอ + โจทย์ Validation | รับ หรือ ย้อนกลับ + บันทึกลง wiki | เป็นโปรแกรม ไม่ใช่โมเดล |

**Algorithm 1** (ภาคผนวก A.1) และคำสั่งที่ตรงกัน

| บรรทัด | เนื้อหา | คำสั่ง |
|---|---|---|
| 2 | S₀ ← ∅ · W₀ ← ∅ | `init` |
| 3 | R_best ← คะแนน Validation ของ S₀ | `baseline` |
| 4–7 | วน k = 1…K · หยุดเมื่อ R_best = 1.0 | `loop` (และ `rollout` ไม่เริ่มรอบใหม่) |
| 8 | Trace_k ← Agent ทำโจทย์ Training ด้วย S_{k−1} | `rollout` |
| 9–10 | สุ่ม Trace แล้ว W′_k ← Maintainer(W_{k−1}, ตัวอย่าง) | `maintain` |
| 11–12 | P_k ← Proposer(W′_k, S_{k−1}, Trace_k) · S′_k ← Apply(S_{k−1}, P_k) | `propose` |
| 13–18 | วัด Validation ของ S′_k · มากกว่า R_best = รับ · ไม่เช่นนั้นย้อนกลับเฉพาะสกิล | `gate` |
| 19 | W_k ← W′_k + บันทึก(ข้อเสนอ, diff, คะแนน, ผล) ทำทั้งสองกรณี | `gate` |
| 21 | ส่งออก S_K และ W_K | `skills/` และ `wiki/` ของ workspace |

สามบรรทัดที่ทำให้ต่างจากวงรอบทั่วไป: 10 (ความรู้เข้า wiki ก่อนรู้ผลของ gate) · 17 (ย้อนกลับเฉพาะสกิล) · 19 (จดผลของข้อเสนอทุกครั้ง)

## ส่วนของสกิล | มาจากข้อไหนของเปเปอร์ | เหมือนหรือต่าง

| ส่วนของสกิล | มาจากข้อไหนของเปเปอร์ | เหมือนหรือต่าง |
|---|---|---|
| workspace 3 โฟลเดอร์ `raw/` `wiki/` `skills/` | ข้อ 3.1 · รูป 2 | **เหมือน** · ต่างเล็กน้อย: ไฟล์บันทึกชื่อ `log.md` (เปเปอร์เรียก `logs.md`) |
| `init` (ชุดสกิลว่าง wiki ว่าง) | Algorithm 1 บรรทัด 2 · ข้อ 2 | **เหมือน** · wiki ตั้งต้นมีหัวไฟล์ 3 ไฟล์แทนโฟลเดอร์ว่างเปล่า |
| `baseline` (R_best เริ่มต้น) | บรรทัด 3 · ข้อ 3.2.4 | **เหมือน** |
| `rollout` → Trace ใน `raw/iter-NN/` | บรรทัด 8 · ข้อ 3.2.1 · ข้อ 3.1 Raw Layer | **ต่าง**: เปเปอร์ใส่เนื้อหาสกิลทั้งหมดใน system prompt ของ Agent · ที่นี่คัดลอกสกิลไปที่ `./skills` ใน sandbox แล้ว Agent เปิดอ่านเอง (รันด้วยคำสั่ง `run` ของ skill-optimizer บท 05) · 1 โจทย์รันหลายรอบ (`--reps`) · Trace เป็น Markdown ที่แปลงจาก stream-json |
| Agent ไม่เห็น wiki | ข้อ 3.2 · ข้อ 5.1 (ให้ Agent อ่าน wiki แล้วสกิลแย่ลง) | **เหมือน** |
| Trace ยาวไม่เกิน 15,000 ตัวอักษร | ภาคผนวก C | **เหมือน** · เพิ่มลำดับการตัด: ย่อคำสั่งและผลของแต่ละขั้นก่อน แล้วจึงตัดท้าย |
| สุ่ม Trace: ไม่ผ่าน ≤ 5 + ผ่าน ≤ 3 | บรรทัด 9 · ภาคผนวก C | **เหมือน** · เพิ่ม: คะแนนต่ำก่อน กระจายทุกโจทย์ก่อนซ้ำ และใช้เลขรอบเป็น seed |
| `maintain` + `prompts/maintainer.md` | บรรทัด 10 · ข้อ 3.2.2 | **เหมือน**: เรียกโมเดล 1 ครั้ง · ได้ wiki ทั้งหมดกับ Trace ตัวอย่าง · สร้างหรือแก้หน้า pattern แบบ patch (append / replace / insert) · เขียน index ใหม่ · ต่อท้าย log · **ต่าง**: โมเดลตอบเป็น JSON แล้วโปรแกรมเป็นผู้เขียนไฟล์ (ไม่มีเครื่องมือ) · ตรวจชื่อไฟล์ · เรียกใหม่ได้ไม่เกิน 3 ครั้ง |
| `wiki/skill-impact.md` เขียนโดยโปรแกรม | ข้อ 3.1 Wiki Layer · ข้อ 3.2.4 · บรรทัด 19 | **เหมือน**: ชื่อสกิล · unified diff · คะแนน Validation · ผล · **ต่าง**: มีผลแบบที่สาม `NO_ACTION` (ไม่ได้วัด) |
