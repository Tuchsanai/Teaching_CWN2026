Lab 1 · System Analysis — จัดข้อตกลงร้านให้ตรงกัน

เปิด README.html เพื่ออ่านแบบมีปุ่มคัดลอกและสารบัญ หรืออ่าน README.md ไฟล์นี้ เนื้อหาทั้งสองฉบับตรงกัน ข้อมูล A/B/C รวมอยู่ในหัวข้อ ชุดข้อมูลพร้อมคัดลอก ภายในไฟล์นี้ ไม่ต้องเปิดไฟล์ข้อมูลแยก

วิธีส่งงานให้ AI: ใช้ ./learn prepare และ ./learn run ตามคู่มือ ผู้ช่วยจะจัดเฉพาะ input.md, คู่มือร่วม และ Prompt/Skill ให้ ไม่แนบ README ทั้งไฟล์ เพราะช่วงท้ายมีเฉลยสำหรับผู้สอน

สารบัญภายใน Lab

เริ่มทำ Lab · ชุดข้อมูลพร้อมคัดลอก · ผลลัพธ์ที่คาดหวัง · คู่มือและคำสั่ง · Prompt พร้อมใช้ · Skill · ใบงาน · คำใบ้สามระดับ · ตัวอย่าง · เฉลยผู้สอน

เริ่มทำ: คัดลอก → วาง → ตรวจผล

เตรียมก่อนจับเวลา: ผู้สอนจัดเครื่องและบัญชีตามคู่มือกลาง เปิด Terminal (หน้าต่างรับคำสั่ง) ที่โฟลเดอร์ Week2; ไฟล์คู่มือสองไฟล์นี้มีเนื้อหาและข้อมูลครบ ส่วนคำสั่ง ./learn และ ./shop ใช้เครื่องมือกลางที่ผู้สอนเตรียมให้

ใน HTML ให้กดปุ่ม คัดลอกข้อความ ใต้กรอบ แล้ววางลงในตำแหน่งที่ระบุ ใน Markdown ให้คัดลอกเฉพาะข้อความในกรอบ ไม่คัดลอกเครื่องหมายกรอบ ไม่ต้องพิมพ์หรือแก้โค้ด

ผลลัพธ์ที่คาดหวัง (Expected output): บรรทัดแรกมี READY lab1 ตามด้วยชุดและวิธีที่เลือก จากนั้นมี WORKSPACE และ RESULTS พร้อมตำแหน่งจริงของรอบนี้ ชื่อตำแหน่งเปลี่ยนได้ทุกครั้ง หากไม่ขึ้น READY ให้ส่งข้อความผิดพลาดให้ผู้สอนก่อนทำต่อ

ขั้นที่ 2 — ตรวจพื้นที่ทำงาน

วางใน Terminal:

./learn inspect

Expected output: เห็น lab เป็น lab1 พร้อม variant และ condition ตรงกับที่เลือก; รอบ S มีชื่อ Skill ใน Native skills ส่วนรอบ P เป็นรายการว่าง ข้อมูลจะถูกดึงจากคู่มือไปยังพื้นที่แยกโดยอัตโนมัติ ไม่ต้องสร้างไฟล์เอง

ขั้นที่ 3 — ส่งงานเริ่มต้นให้ AI

วางใน Terminal:

./learn run start

Expected output: แสดงการเรียก cyolo1 แล้วมีคำตอบภาษาไทยและตำแหน่ง หลักฐาน ของรอบนั้น โครงสร้างคำตอบที่ต้องตรวจคือ: ตารางความต้องการพร้อมสถานะและรหัสแหล่งข้อมูล → คำถามที่ต้องถามเจ้าของร้าน → กติกาที่ยืนยันได้แยกจากเรื่องรอตัดสิน → สถานการณ์ตรวจรับแบบ เมื่อ / ทำ / คาดหวัง ไม่ตัดสินข้อขัดแย้งแทนร้าน

คำตอบ AI อาจใช้ถ้อยคำต่างจากตัวอย่าง จึงตรวจสาระและหลักฐาน ไม่ตรวจว่าข้อความเหมือนเฉลยทุกตัวอักษร เก็บร่างแรกก่อนแก้ทุกครั้ง

ขั้นที่ 4 — วิเคราะห์ แก้ และตรวจร่าง

เลือกคำสั่งตามความจำเป็น ทีละคำสั่ง วางใน Terminal หลัง run start สำเร็จ ไม่ต้องใช้ครบทุกคำสั่งในรอบเปรียบเทียบ

วิเคราะห์จุดที่ยังขาด

./learn run analyze

Expected output: รายการจุดที่ขาด ขัดแย้ง หรือไม่มีหลักฐาน พร้อมรหัสอ้างอิงและสิ่งที่ควรแก้ ไม่อ้างว่าได้ตรวจระบบจริงแทนผู้เรียน

แก้ร่างจากข้อที่พบ

./learn run revise

Expected output: คำตอบฉบับแก้ที่ยังอ้างข้อมูลชุดเดิม แยกเรื่องรอยืนยันและไม่เติมข้อเท็จจริงใหม่ เก็บคู่กับร่างแรกเพื่อตรวจว่าข้อผิดพลาดลดลงหรือไม่

ตรวจคำตอบล่าสุด

./learn run verify

Expected output: รายการตรวจผ่าน/ยังต้องแก้ พร้อมเหตุผลจากข้อมูลจริง คำตอบว่า “ผ่านทั้งหมด” โดยไม่มีหลักฐานไม่เพียงพอ; ใช้เกณฑ์ในใบงานตรวจด้วยตนเองด้วย

เมื่อติดขัดและต้องส่งหลักฐานเพิ่ม

./learn run ask

เมื่อเห็นคำเชิญให้วางข้อความ ให้คัดลอก Prompt จากส่วน Prompt พร้อมใช้ แล้วแนบข้อความผิดพลาดหรือผลตรวจที่พบจริง จากนั้นพิมพ์ END แยกหนึ่งบรรทัดเพื่อส่ง Expected output: AI อธิบายหลักฐานที่เพิ่งส่งและระบุขั้นตอนถัดไปหรือข้อมูลที่ยังขาด

ในรอบเปรียบเทียบใช้การช่วยวิเคราะห์/แก้/ตรวจรวมไม่เกิน 2 ครั้งต่อชุด ตามกติกาเดิม และบันทึกจำนวนครั้งกับคำใบ้ที่เปิด

ขั้นที่ 5 — เก็บงานและจบรอบ

กรอก ใบงาน เก็บร่างแรก ฉบับแก้ และหลักฐานก่อนวางคำสั่งนี้ใน Terminal:

./learn close

Expected output: CLOSED; เก็บ learner-results ไว้ พื้นที่ทำงานชั่วคราวปิดแล้ว แต่หลักฐานใน learner-results ยังอยู่ จากนั้นจึงเริ่มชุดถัดไปตามลำดับที่ผู้สอนจัด

สถานการณ์

ร้านกำลังปรับวิธีรับออเดอร์ แต่ฝ่ายขาย แชต และกติกาไม่ตรงกัน คำว่า System Analysis ในที่นี้คือทำความเข้าใจงานและเงื่อนไขร่วมกัน ไม่ต้องรู้การออกแบบซอฟต์แวร์

เตรียมก่อนเริ่ม

ผู้สอนทำ setup ให้เสร็จ และจัดพื้นที่แยกแต่ละรอบพร้อม input.md, manual.md และเฉพาะ Skill ของรอบ S ห้ามแจกโฟลเดอร์เฉลยหรือผลทดลองเข้า AI

ผู้เรียนต้องเปิดเว็บ อ่านไทย คัดลอก/วางข้อความ และใช้ Terminal ตามคำสั่งได้ เรียนรู้ Terminal ในบทนำ 5 นาทีก่อนจับเวลา ใช้เครื่องฝึกที่ครูเตรียม; Windows/macOS ใช้เครื่อง Linux ฝึกของห้อง ไม่ให้ผู้เรียนตั้งระบบเอง

ข้อมูล A · ข้อมูล B · ข้อมูล C หลังจบรอบหลัก

วิธีทำทีละขั้น

  1. เปิดพื้นที่ใหม่ที่ผู้สอนเตรียมให้ ตรวจชื่อชุด A/B และเงื่อนไข P/S บนใบงาน ไม่เปิด C หรือเฉลยก่อนครบสองรอบ
  2. อ่าน input.md และ manual.md ให้ครบ ในกลุ่มแบ่งคนอ่านหลักฐาน คนวาง Prompt และคนจดเวลา สลับบทบาทรอบถัดไป
  3. เปิด ข้อความพร้อมวาง เริ่มด้วย 1P ทั้งกรอบ หรือ 1S เพียงแบบเดียว เก็บร่างแรกเป็นไฟล์/คัดลอกลงเอกสารที่ผู้สอนให้ ลงเวลารับคำตอบก่อนแก้
  4. ตรวจร่างกับหลักฐานเองหนึ่งรอบ หากต้องการความช่วยเหลือใช้ข้อความ 2/3/4 รวมไม่เกินสองข้อความ และเปิดคำใบ้ได้ไม่เกินสามระดับ จดทุกครั้ง ห้ามแก้คะแนนร่างแรกย้อนหลัง
  5. ปิดบริบทเดิม แล้วเปิดพื้นที่อีกชุดตามตารางสลับลำดับ ทำอีกเงื่อนไขโดยไม่มีคำตอบรอบก่อนติดไป
  6. ส่งทั้งร่างแรกและฉบับแก้ จึงเปิดตัวอย่าง/เฉลยผู้สอน ตรวจคะแนนทีละข้อและระบุบรรทัดรองรับ
  7. ทำกิจกรรมสร้าง Skill ด้วยภาษาคนในคู่มือ setup จากนั้นใช้ C ก่อนแก้ Skill และเก็บผลการใช้ซ้ำ; ปรับ Skill จากข้อผิดพลาด แล้วเริ่มบริบทใหม่ทำ C อีกครั้ง แยกคะแนนก่อน/หลังและเวลาบำรุงรักษา

งานที่ส่ง

ใบงาน + ร่างแรก + ฉบับแก้ + คำสั่ง/ID หลักฐาน + scorecard + ข้อเสนอปรับ Skill หนึ่งข้อพร้อมเหตุผล สำหรับ Lab2 แนบภาพ browser ก่อน/หลังและเลขจองด้วย

ตัวอย่างและเกณฑ์ประเมิน

เปิดหลังส่งร่างทั้งสองชุด: ตัวอย่างดีและตัวอย่างผิดที่ผู้สอนแต่ง · เฉลย/รูบริก 12 ข้อ

เกณฑ์สามระดับ: 10–12 = ทำงานได้และยังต้องตรวจจุดเสี่ยง, 7–9 = ต้องแก้ก่อนใช้, 0–6 = ทบทวนหลักฐานและวิธีทำ คะแนนสูงแต่มีการอนุมัติ/นโยบายแต่ง/ผลกู้คืนแต่งถือว่ายังใช้จริงไม่ได้ ไม่ถือคะแนนรวมลบล้างข้อผิดพลาดสำคัญ

ปัญหาที่พบบ่อย

  • AI ไม่เห็นไฟล์: ใช้พื้นที่ที่ launcher แจ้ง อย่าเปิดจาก Week2 รวม และตรวจว่ามี input.md/manual.md ถ้าเปิดผิด ให้แจ้งครูและเริ่มรอบใหม่ที่บันทึกว่า invalid
  • ไม่เห็นชื่อ Skill: เปิดหน้าต่างใหม่จากพื้นที่ S ใช้ /skills หรือพิมพ์ $ เลือกชื่อ shop-requirements; ถ้ายังไม่มีให้ครูตรวจ path ไม่วาง body แทนแล้วเรียกว่า native
  • AI ตอบมั่นใจแต่ไม่มี ID: วางข้อความตรวจคำตอบ บันทึกเป็น correction และเก็บร่างแรกไว้
  • รุ่นโมเดลหรือบัญชีไม่ตรง/หมดเวลา/เข้าใช้ไม่ได้: หยุดรอบ บันทึกเหตุและเวลาจริง ไม่สลับโมเดลหรือเรียกซ้ำเอง
  • เปิด local link ไม่ได้: ใช้หน้า lab HTML ที่แจกหรือเปิดไฟล์ในโฟลเดอร์ ผู้สอนต้องเปิด web server ถ้าห้องใช้ URL
  • ข้อมูลสองแหล่งขัดกัน: การอ้างรหัสครบยังไม่เท่ากับตัดสินได้ ให้รักษาสถานะรอข้อมูล/รอคนไว้

คำถามอภิปราย

  1. ข้อใดเปลี่ยนเพราะหลักฐานใหม่ และข้อใดเปลี่ยนเพราะรูปแบบคำสั่ง?
  2. Prompt ที่มีขั้นตอนครบยังแพ้หรือชนะ Skill เสมอหรือไม่ ใช้คู่ข้อมูล A/B และคะแนนจริงตอบ
  3. การสร้างและปรับ Skill ใช้เวลาเท่าไร ต้องนำกลับมาใช้กี่ครั้งจึงคุ้มสำหรับทีมของคุณ?
  4. ถ้า AI มี ID ทุกบรรทัดแต่ตีความผิด คุณจะตรวจพบด้วยวิธีใด?

ถ่ายโอน C

ใช้ข้อมูล C ในบริบทใหม่กับ Skill เดิมก่อน แยกผลเป็น reuse ครั้งแรก จากนั้นปรับด้วยคำสั่งภาษาคนและทำซ้ำ C เป็น assisted transfer ไม่รวมกับผล A/B

$shop-requirements อ่าน input.md ชุด C และ manual.md ทั้งหมด ทำงานด้วยวิธีเดิมแต่ยึดข้อมูลและขอบเขตใหม่ ระบุส่วนที่ใช้ซ้ำได้ ส่วนที่ต้องเปลี่ยน และสิ่งที่ยังไม่รู้ ห้ามดูคำตอบรอบก่อน

ชุดข้อมูลพร้อมคัดลอก

เลือกเฉพาะ A หรือ B ที่ได้รับมอบหมาย ใช้ C หลังจบรอบหลัก ปุ่มคัดลอกแต่ละชุดให้เฉพาะข้อมูล ไม่มีเฉลย สำหรับเส้นทาง ./learn prepare เครื่องมือจะนำข้อมูลชุดที่เลือกไปใช้ให้อัตโนมัติ

หากผู้สอนให้วางข้อมูลในช่องสนทนา ให้คัดลอกข้อมูลเพียงชุดเดียว ตามด้วยคู่มือร่วมและ Prompt ของเงื่อนไขที่กำหนด ใช้เครื่องมือและวิธีแนบข้อมูลเดียวกันทั้ง P/S; รอบ S ต้องเปิด Skill จริงในเครื่องมือด้วย การวางคำแนะนำอย่างเดียวไม่นับเป็นการใช้ native Skill ห้ามแนบ README ทั้งไฟล์เพราะมีเฉลยท้ายบท

# ผู้ช่วยตรวจความครบถ้วนและความสอดคล้องของข้อตกลงร้านค้า
## วัตถุประสงค์และเมื่อใช้
ใช้เมื่อแชต บันทึกประชุม และนโยบายร้านพูดกระจัดกระจาย ต้องสรุปเป็นข้อตกลงภาษาคน ไม่ออกแบบระบบหรือเขียนโปรแกรม
## ข้อมูลเข้า
อ่าน input.md และ manual.md ทั้งหมด ใช้เฉพาะข้อมูลที่ให้ รหัสในวงเล็บเหลี่ยมคือแหล่งหลักฐาน หากเอกสารขาดให้บอกขาด ห้ามแต่งข้อมูล
## ขั้นตอน
1. รวบรวมทุกข้อกล่าวอ้าง แยกหมวดส่วนลด การยกเลิก การคืนสินค้า และการรับออเดอร์ รักษารหัสแหล่งข้อมูลไว้
2. แยกสถานะ ยืนยันได้ / ขัดแย้ง / ข้อมูลขาด ทุกข้ออ้างต้องมี ID; ข้อขัดแย้งต้องมี ID ทั้งสองด้าน
3. ห้ามใช้ความใหม่ของข้อความ ตำแหน่งคนพูด หรือคำว่า policy เพื่อตั้งลำดับอำนาจเอง หากมีคำอนุมัติและขอบเขตชัดในข้อมูลจึงใช้ตามนั้น
4. ตั้งคำถามที่ผู้มีอำนาจตอบได้ ระบุสิ่งที่ต้องตัดสินและผลกระทบ อย่าสมมติชื่อผู้อนุมัติที่ข้อมูลไม่ให้
5. เขียนกติกาที่ยืนยันได้แยกจากข้อเสนอหรือกติกาที่ยังรอคำตอบ ไม่คำนวณส่วนลดหรือกำหนดค่าขนส่งที่ไม่มีข้อตกลง
6. เขียนสถานการณ์ตรวจรับด้วย เมื่อ / ทำ / คาดหวัง สำหรับกติกายืนยัน และระบุ รอยืนยัน สำหรับข้อขัดแย้งหรือข้อมูลขาด ไม่ทำให้ความไม่แน่นอนกลายเป็นผลผ่าน

## เกณฑ์รับงาน

คำใบ้สามระดับ — เปิดเมื่อจำเป็นและบันทึกการใช้คำใบ้

คำใบ้ 3 ระดับ — System Analysis — จัดข้อตกลงร้านให้ตรงกัน

เปิดทีละระดับเมื่อจำเป็น จดระดับและ UTC ที่เปิดในใบงาน ห้ามผู้สอนส่งเพิ่มเฉพาะฝ่ายใดโดยไม่บันทึก

ระดับ 1 — ดูหลักฐาน

ทำเครื่องหมายข้ออ้างแต่ละข้อและเขียน ID ไว้ข้าง ๆ ก่อนสรุป

ระดับ 2 — จัดความสัมพันธ์

วางแชตเรื่องส่วนลดข้างกติกาส่วนลด ทำเหมือนกันกับยกเลิกและคืน; คำว่าอยากหรือน่าจะไม่ใช่คำอนุมัติ

ระดับ 3 — แนวทางตัดสิน

มีสามคู่ที่ต้องถาม ไม่ใช่เลือกเอง; รายการชื่อผู้รับ/เบอร์/สินค้าเป็นสิ่งยืนยันได้ ส่วนค่าขนส่งคืนยังขาด

กลับสารบัญ

ตัวอย่างสำหรับอภิปราย — เปิดหลังส่งร่าง A/B

ตัวอย่างสำหรับอภิปรายหลังส่งงาน — ผู้สอนแต่ง ไม่ใช่ผลโมเดลทดลอง

ใช้ชุด A เป็นตัวอย่าง หลังเปิดเฉลยแล้วห้ามเอาไปใส่พื้นที่ทดลอง A/B

ตัวอย่างที่ดี

หมวด ข้อความ สถานะ หลักฐาน
รับออเดอร์ เก็บชื่อผู้รับ เบอร์ และรายการก่อนยืนยัน ยืนยันได้ A-M1
ส่วนลด 10% ร่วมคูปองได้หรือไม่ ขัดแย้ง รอคำตัดสิน A-C1, A-P1
ยกเลิก หลังจ่ายก่อนแพ็กยังยกเลิกได้หรือไม่ ขัดแย้ง รอคำตัดสิน A-C2, A-P2
คืนสินค้า คืนเปลี่ยนใจได้หรือเฉพาะชำรุด ขัดแย้ง รอคำตัดสิน A-M2, A-P3
คืนสินค้า สภาพสำหรับคืนเปลี่ยนใจ และผู้จ่ายค่าขนส่ง ข้อมูลขาด A-M2, A-N1

คำถาม: ใครอนุมัติลำดับกติกาและขอบเขตที่ใช้ [A-N1]? ยืนยันใช้คูปองร่วม 10% ได้ไหม [A-C1,A-P1]? ยกเลิกหลังจ่ายก่อนแพ็กได้ไหม [A-C2,A-P2]? ยอมรับเปลี่ยนใจไหม ถ้าใช่สภาพต้องเป็นอย่างไรและใครจ่ายค่าส่ง [A-M2,A-P3,A-N1]?

กติกาที่ยืนยัน: ก่อนยืนยันออเดอร์ต้องบันทึกข้อมูลสามอย่าง [A-M1] ส่วนลดที่ทั้งสองแหล่งตรงกันคือ 10% แต่การใช้ร่วมคูปองยังรอคำตอบ [A-C1,A-P1] ขอบเขตยกเลิกและคืนยังไม่ประกาศเป็นข้อยุติ ไม่ตั้งลำดับอำนาจเอง [A-N1]

เมื่อ ทำ ผลที่คาดหวัง ที่มา
จะยืนยันออเดอร์ ตรวจข้อมูลชื่อ เบอร์ รายการ ต้องเก็บครบก่อนยืนยัน (เป็นเกณฑ์ ไม่ใช่ผลทดสอบจริง) A-M1
มีคูปองและส่วนลด 10% ขอใช้ร่วม รอยืนยันกติกา A-C1,A-P1
จ่ายแล้วแต่ยังไม่แพ็ก ขอยกเลิก รอยืนยันกติกา A-C2,A-P2
เปลี่ยนใจภายใน 7 วัน ขอคืน รอยืนยันเรื่องสิทธิ์ สภาพ และค่าส่ง A-M2,A-P3,A-N1

ตัวอย่างผิดทั้งงาน — ใช้จับข้อผิดพลาด

“ความต้องการ: ลด 10% ร่วมคูปองได้ ยกเลิกหลังจ่ายได้ และคืนเปลี่ยนใจได้ภายใน 7 วัน ร้านออกค่าส่งทั้งหมด เพราะแชตใหม่กว่าเอกสาร ไม่ต้องถามใคร กติกาทั้งหมดอนุมัติแล้ว สถานการณ์ตรวจรับทุกข้อผ่าน”

ผิดที่เลือก precedence เอง [A-N1], ปิดสามข้อขัดแย้ง, แต่งค่าส่ง, ไม่มีคำถาม/ตารางอ้างหลักฐาน และอ้างผลทดสอบที่ไม่ได้ทำ การแก้ต้องกลับไปผูกสองแหล่ง รักษาสถานะรอยืนยัน และแยกเกณฑ์ออกจากผลจริง

เฉลยและเกณฑ์ประเมิน — สำหรับผู้สอนหลังส่งร่าง

เฉลยและเกณฑ์ให้คะแนน — System Analysis — จัดข้อตกลงร้านให้ตรงกัน

ผู้สอนเปิดหลังส่งร่างทั้ง A/B เท่านั้น ห้ามอยู่ในพื้นที่ AI ทดลอง

วิธีประเมิน

คะแนนข้อ 1–12 ข้อละ 1 เมื่อผ่านเงื่อนไขครบ มิฉะนั้น 0 พร้อมคัดข้อความผิดและ ID ต้นทาง ไม่ให้คะแนนจากคำสำคัญตรงกันอย่างเดียว อ้าง A- หรือ B- นำหน้ารหัสตามชุด ส่วน Lab2 ใช้รหัส S/U ใน snapshot ของชุดนั้น

ผู้ตรวจอ่านร่างดิบที่บันทึกก่อน แล้วตรวจฉบับแก้แยก ทำ blind condition ได้โดยซ่อน P/S ผู้ตรวจใน pilot นี้เป็นผู้จัดทำแพ็กเกจ (AI worker อ่านผลตามรูบริก) ไม่ใช่ผู้ประเมินมนุษย์หรือผู้ประเมินอิสระ

ข้อ สิ่งตรวจ เงื่อนไขและหลักฐานเฉลย คะแนน
1 รวบรวมข้อยืนยัน M1: ชื่อผู้รับ เบอร์ติดต่อ รายการสินค้า ก่อนยืนยัน ครบสามอย่าง 0 / 1
2 ส่วนลดขัดกัน C1 กับ P1: ใช้ร่วมคูปองได้/ไม่ได้ ต้องยังไม่ตัดสิน 0 / 1
3 ยกเลิกขัดกัน C2 กับ P2: หลังจ่ายก่อนแพ็ก/เฉพาะก่อนจ่าย ต้องยังไม่ตัดสิน 0 / 1
4 คืนขัดกัน M2 กับ P3: เปลี่ยนใจ/เฉพาะชำรุด ต้องยังไม่ตัดสิน 0 / 1
5 ค่าขนส่งขาด N1 และ M2: ยังไม่มีข้อตกลงค่าขนส่งคืน 0 / 1
6 สภาพสินค้าขาด M2: สภาพสำหรับคืนเมื่อเปลี่ยนใจยังไม่ระบุ ไม่กำหนดเอง 0 / 1
7 ไม่แต่งลำดับอำนาจ N1: ไม่มี precedence และคำอนุมัติ ไม่ถือเอกสารกติกาชนะอัตโนมัติ 0 / 1
8 คำถามตัดสินได้ มีคำถามส่วนลด ยกเลิก คืน และข้อมูลขาด พร้อม ID 0 / 1
9 กติกาแยกสถานะ M1 ยืนยัน; สามหมวดที่ขัดกันรอคำตอบ ข้อเสนอระบุเป็นข้อเสนอ 0 / 1
10 ตรวจรับข้อยืนยัน กรณีเก็บชื่อ/เบอร์/รายการก่อนยืนยัน ตาม M1 และไม่อ้างผลรันจริง 0 / 1
11 ตรวจรับความไม่แน่นอน มีเหตุการณ์ส่วนลดร่วมคูปอง ยกเลิกหลังจ่าย คืนเปลี่ยนใจ พร้อมรอยืนยันและสอง ID 0 / 1
12 โครงสร้าง/ที่มาครบ ครบตารางความต้องการ คำถาม กติกา สถานการณ์ ทุกข้ออ้างมี ID ที่รองรับ 0 / 1

accuracy เพิ่มเติม = จำนวนข้อกล่าวอ้างที่ต้นทางรองรับ / จำนวนข้อกล่าวอ้างเชิงข้อเท็จจริงที่ผู้ตรวจนับ โดยบันทึกวิธีแบ่งข้ออ้างให้เหมือนกัน; ถ้าไม่นับให้ not-measured ความครบถ้วน = ผ่านกี่ข้อจาก 12; ห้ามเรียกสองค่าทดแทนกัน

เฉลย C และการใช้ซ้ำ

C: ใช้ C-D1/C-D2 เฉพาะแคมเปญใหม่: ลด 12% ไม่ร่วมคูปอง ยกเลิกก่อนแพ็กแม้จ่าย คืนชำรุด 5 วัน ร้านออกค่าส่งเมื่อยืนยันเสีย; C-C1 ไม่ครอบออเดอร์ทุกยุค; C-M1 ยังยืนยัน; C-N1 ขั้นยืนยันเสีย/เวลาคืนเงินจริงยังขาด ออเดอร์เก่าถามเจ้าของ ห้ามนำข้อสรุปใหม่นี้ย้อนใช้กับ A/B

เกณฑ์ transfer 4 ข้อ ข้อละ 1: ยึดขอบเขต/รุ่นใหม่; เปลี่ยนการตัดสินที่ต้องเปลี่ยน; รักษาการขอข้อมูล/ส่งคน; ไม่อ้างสำเร็จโดยไม่มีหลักฐาน เปรียบเทียบ C ก่อนและหลังปรับ Skill แยกจาก A/B

แนวอภิปราย

หากทั้งสองวิธีได้คะแนนเท่ากัน ไม่ต้องบังคับให้ Skill ชนะ พิจารณาค่าเตรียมและเวลาคัดลอกเมื่อใช้ซ้ำด้วย งานเสี่ยงยังต้องตรวจหลักฐานทุกครั้ง แม้ได้ 12/12 ในข้อมูลสั้นนี้
