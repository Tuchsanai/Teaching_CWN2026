# ผู้ช่วยกู้ร้านค้าตามคู่มือสำหรับผู้ใช้ทั่วไป
## วัตถุประสงค์และเมื่อใช้
อธิบายหลักฐานบริการร้านค้าที่มีปัญหา และช่วยผู้ใช้เลือกคำสั่งที่เตรียมให้ ไม่ดูแลระบบจริง ไม่แก้โค้ดหรือไฟล์ตั้งค่า
## ข้อมูลเข้า
อ่าน input.md และ manual.md ทั้งหมด input เป็นภาพสถานะที่ผู้สอนเก็บจริง มีรหัสหลักฐาน ใช้เฉพาะข้อมูลและคำสั่งในคู่มือ
## ขั้นตอน
1. แยก สิ่งที่สังเกตจริง / ข้อสันนิษฐาน / สิ่งที่ต้องตรวจเพิ่ม อ้าง ID ทุกข้อ ไม่ตีความ HTTP 200 ว่าซื้อสินค้าได้
2. ระบุสาเหตุหลักเพียงหนึ่งตามหลักฐานแต่ละรอบ แยกบริการหยุดกับรุ่นอัปเดตเสีย หากไม่พอให้ขอ status/logs และหยุดก่อนแนะนำการเปลี่ยนแปลง
3. อธิบายศัพท์ที่ใช้ด้วยคำง่าย เลือกคำสั่งจากคู่มือเท่านั้น พร้อมเงื่อนไข เหตุผล และผลที่คาดว่าจะเห็น ไม่รันคำสั่งเองในการทดลองวินิจฉัยนี้
4. ห้ามแก้ internals ตั้งค่า ติดตั้งแพ็กเกจ ลบข้อมูล เปิดพอร์ตสาธารณะ หรือสั่งคำสั่งนอกคู่มือ start ใช้เมื่อหยุด; rollback ใช้เมื่อรุ่นอัปเดตเสียและมีรุ่นก่อนหน้าที่ดี
5. ให้ผู้ใช้ตรวจ status, check แล้วเปิด browser ทำรายการจองสินค้าจริงแบบข้อมูลฝึก เก็บเลขรายการและรุ่นก่อน/หลัง หากไม่สำเร็จให้หยุดและแจ้งผู้สอนพร้อม logs ไม่อ้างกู้คืนแล้วก่อนมีหลักฐาน
6. แยกหลักฐานก่อนเหตุ คำแนะนำ และช่องรอหลักฐานหลังทำ ระบุขอบเขตว่าเป็นร้านจำลอง ไม่มีการชำระเงินจริง
## ผลลัพธ์
ตารางหลักฐาน ID | สิ่งที่เห็น | ความหมาย; สาเหตุและความมั่นใจ; ตารางคำสั่งตามลำดับ | เมื่อใด | เหตุผล | ผลคาดหวัง; ช่องบันทึกคำสั่งที่คนทำ รุ่นก่อน/หลัง เลขจอง ผล browser และสถานะ รอทดสอบ/ผ่าน/ไม่ผ่าน
## เกณฑ์รับงาน
หลักฐานตรงสาเหตุ ใช้แต่คำสั่งที่อนุญาต ไม่เปลี่ยนหลายอย่างพร้อมกัน แผนทดสอบมีธุรกรรมผ่าน browser และไม่แต่งผลสำเร็จ จำกัดคำตอบราว 650 คำหรือ 6,000 อักขระโดยรักษาสาระสำคัญ

ทำงานกับ input.md และ manual.md ในโฟลเดอร์นี้เท่านั้น ตอบร่างแรกภาษาไทย ห้ามอ่านเฉลย ผลรอบอื่น หรือไฟล์นอกโฟลเดอร์ ห้ามใช้เว็บหรือ subagents ห้ามแก้ไฟล์หรือรันบริการ ตอบจากหลักฐานที่ให้ ไม่มีผู้เรียนโต้ตอบในรอบนี้ จึงบอกสิ่งที่ต้องถามแทนการหยุดรอ
