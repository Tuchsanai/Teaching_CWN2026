เปิด README.html เพื่ออ่านแบบมีปุ่มคัดลอกและสารบัญ หรืออ่าน README.md ไฟล์นี้ เนื้อหาทั้งสองฉบับตรงกัน ข้อมูล A/B/C รวมอยู่ในหัวข้อ ชุดข้อมูลพร้อมคัดลอก ภายในไฟล์นี้ ไม่ต้องเปิดไฟล์ข้อมูลแยก

สารบัญภายใน Lab

เริ่มทำ Lab · ชุดข้อมูลพร้อมคัดลอก · ผลลัพธ์ที่คาดหวัง · คู่มือและคำสั่ง · Prompt พร้อมใช้ · Skill · ใบงาน · คำใบ้สามระดับ · ตัวอย่าง · เฉลยผู้สอน

เตรียมก่อนจับเวลา: ผู้สอนจัดเครื่องและบัญชีตามคู่มือกลาง เปิด Terminal (หน้าต่างรับคำสั่ง) ที่โฟลเดอร์ Week2; ไฟล์คู่มือสองไฟล์นี้มีเนื้อหาและข้อมูลครบ ส่วนคำสั่ง ./learn และ ./shop ใช้เครื่องมือกลางที่ผู้สอนเตรียมให้

ใน HTML ให้กดปุ่ม คัดลอกข้อความ ใต้กรอบ แล้ววางลงในตำแหน่งที่ระบุ ใน Markdown ให้คัดลอกเฉพาะข้อความในกรอบ ไม่คัดลอกเครื่องหมายกรอบ ไม่ต้องพิมพ์หรือแก้โค้ด

ผลลัพธ์ที่คาดหวัง (Expected output): บรรทัดแรกมี READY lab2 ตามด้วยชุดและวิธีที่เลือก จากนั้นมี WORKSPACE และ RESULTS พร้อมตำแหน่งจริงของรอบนี้ ชื่อตำแหน่งเปลี่ยนได้ทุกครั้ง หากไม่ขึ้น READY ให้ส่งข้อความผิดพลาดให้ผู้สอนก่อนทำต่อ

ขั้นที่ 2 — ตรวจพื้นที่ทำงาน

วางใน Terminal:

./learn inspect

Expected output: เห็น lab เป็น lab2 พร้อม variant และ condition ตรงกับที่เลือก; รอบ S มีชื่อ Skill ใน Native skills ส่วนรอบ P เป็นรายการว่าง ข้อมูลจะถูกดึงจากคู่มือไปยังพื้นที่แยกโดยอัตโนมัติ ไม่ต้องสร้างไฟล์เอง

ขั้นที่ 3 — ส่งงานเริ่มต้นให้ AI

วางใน Terminal:

./learn run start

Expected output: แสดงการเรียก cyolo1 แล้วมีคำตอบภาษาไทยและตำแหน่ง หลักฐาน ของรอบนั้น โครงสร้างคำตอบที่ต้องตรวจคือ: อาการ → หลักฐานและรหัส → สาเหตุที่หลักฐานรองรับ → คำสั่งถัดไปจากคู่มือพร้อมเหตุผล → ผลที่คาดว่าจะเห็นและช่องรอผลตรวจจริง แยกเหตุการณ์ basic กับ advanced; ข้อมูลก่อนกู้ไม่ใช่หลักฐานว่ากู้แล้ว

คำตอบ AI อาจใช้ถ้อยคำต่างจากตัวอย่าง จึงตรวจสาระและหลักฐาน ไม่ตรวจว่าข้อความเหมือนเฉลยทุกตัวอักษร เก็บร่างแรกก่อนแก้ทุกครั้ง

ขั้นที่ 4 — วิเคราะห์ แก้ และตรวจร่าง

เลือกคำสั่งตามความจำเป็น ทีละคำสั่ง วางใน Terminal หลัง run start สำเร็จ ไม่ต้องใช้ครบทุกคำสั่งในรอบเปรียบเทียบ

วิเคราะห์จุดที่ยังขาด

./learn run analyze

Expected output: รายการจุดที่ขาด ขัดแย้ง หรือไม่มีหลักฐาน พร้อมรหัสอ้างอิงและสิ่งที่ควรแก้ ไม่อ้างว่าได้ตรวจระบบจริงแทนผู้เรียน

แก้ร่างจากข้อที่พบ

./learn run revise

Expected output: คำตอบฉบับแก้ที่ยังอ้างข้อมูลชุดเดิม แยกเรื่องรอยืนยันและไม่เติมข้อเท็จจริงใหม่ เก็บคู่กับร่างแรกเพื่อตรวจว่าข้อผิดพลาดลดลงหรือไม่

ตรวจคำตอบล่าสุด

./learn run verify

Expected output: รายการตรวจผ่าน/ยังต้องแก้ พร้อมเหตุผลจากข้อมูลจริง คำตอบว่า “ผ่านทั้งหมด” โดยไม่มีหลักฐานไม่เพียงพอ; ใช้เกณฑ์ในใบงานตรวจด้วยตนเองด้วย

เมื่อติดขัดและต้องส่งหลักฐานเพิ่ม

./learn run ask

เมื่อเห็นคำเชิญให้วางข้อความ ให้คัดลอก Prompt จากส่วน Prompt พร้อมใช้ แล้วแนบข้อความผิดพลาดหรือผลตรวจที่พบจริง จากนั้นพิมพ์ END แยกหนึ่งบรรทัดเพื่อส่ง Expected output: AI อธิบายหลักฐานที่เพิ่งส่งและระบุขั้นตอนถัดไปหรือข้อมูลที่ยังขาด

ในรอบเปรียบเทียบใช้การช่วยวิเคราะห์/แก้/ตรวจรวมไม่เกิน 2 ครั้งต่อชุด ตามกติกาเดิม และบันทึกจำนวนครั้งกับคำใบ้ที่เปิด

ขั้นที่ 5 — เก็บงานและจบรอบ

กรอก ใบงาน เก็บร่างแรก ฉบับแก้ และหลักฐานก่อนวางคำสั่งนี้ใน Terminal:

./learn close

Expected output: CLOSED; เก็บ learner-results ไว้ พื้นที่ทำงานชั่วคราวปิดแล้ว แต่หลักฐานใน learner-results ยังอยู่ จากนั้นจึงเริ่มชุดถัดไปตามลำดับที่ผู้สอนจัด

เป้าหมายและเวลา

เลือกคำสั่งจากหลักฐาน อธิบายสาเหตุเดียวต่อรอบ และพิสูจน์การจองผ่านหน้าเว็บหลังเปิดบริการหรือย้อนรุ่น

ภารกิจ 30 นาทีต่อชุด A หรือ B: สังเกต 5 + ถาม AI 4 + รอบง่าย 6 + รอบต่อยอด 7 + ตรวจหลักฐาน/สรุป 8; การเปรียบเทียบครบสองชุดใช้ 60 นาที และอภิปราย/ปรับ Skill/C อีก 20 นาที ไม่รวมจัดเตรียมเครื่อง บัญชี และบริการ ผู้เรียนใช้เพียงข้อความภาษาคน คำสั่งสำเร็จรูป และ Skill ไม่มีงานเขียนหรือแก้โปรแกรม สคริปต์ หรือ config

สถานการณ์

อีก 30 นาทีร้านฝึกจะเริ่มแคมเปญ หน้าร้านรอบง่ายเปิดไม่ได้ ส่วนรอบต่อยอดเปิดได้แต่จองสินค้าไม่ได้ DevOps ในที่นี้คือการสังเกต ดูแล และตรวจว่าบริการกลับมาใช้งานได้ ไม่ต้องเรียนระบบเครือข่ายมาก่อน

เตรียมก่อนเริ่ม

ผู้สอนทำ setup ให้เสร็จ และจัดพื้นที่แยกแต่ละรอบพร้อม input.md, manual.md และเฉพาะ Skill ของรอบ S ห้ามแจกโฟลเดอร์เฉลยหรือผลทดลองเข้า AI

ผู้เรียนต้องเปิดเว็บ อ่านไทย คัดลอก/วางข้อความ และใช้ Terminal ตามคำสั่งได้ เรียนรู้ Terminal ในบทนำ 5 นาทีก่อนจับเวลา ใช้เครื่องฝึกที่ครูเตรียม; Windows/macOS ใช้เครื่อง Linux ฝึกของห้อง ไม่ให้ผู้เรียนตั้งระบบเอง

ข้อมูล A · ข้อมูล B · ข้อมูล C หลังจบรอบหลัก

วิธีทำทีละขั้น

  1. เปิดพื้นที่ใหม่ที่ผู้สอนเตรียมให้ ตรวจชื่อชุด A/B และเงื่อนไข P/S บนใบงาน ไม่เปิด C หรือเฉลยก่อนครบสองรอบ
  2. อ่าน input.md และ manual.md ให้ครบ ในกลุ่มแบ่งคนอ่านหลักฐาน คนวาง Prompt และคนจดเวลา สลับบทบาทรอบถัดไป
  3. เปิด ข้อความพร้อมวาง เริ่มด้วย 1P ทั้งกรอบ หรือ 1S เพียงแบบเดียว เก็บร่างแรกเป็นไฟล์/คัดลอกลงเอกสารที่ผู้สอนให้ ลงเวลารับคำตอบก่อนแก้
  4. ตรวจร่างกับหลักฐานเองหนึ่งรอบ หากต้องการความช่วยเหลือใช้ข้อความ 2/3/4 รวมไม่เกินสองข้อความ และเปิดคำใบ้ได้ไม่เกินสามระดับ จดทุกครั้ง ห้ามแก้คะแนนร่างแรกย้อนหลัง
  5. ปิดบริบทเดิม แล้วเปิดพื้นที่อีกชุดตามตารางสลับลำดับ ทำอีกเงื่อนไขโดยไม่มีคำตอบรอบก่อนติดไป
  6. ส่งทั้งร่างแรกและฉบับแก้ จึงเปิดตัวอย่าง/เฉลยผู้สอน ตรวจคะแนนทีละข้อและระบุบรรทัดรองรับ
  7. ทำกิจกรรมสร้าง Skill ด้วยภาษาคนในคู่มือ setup จากนั้นใช้ C ก่อนแก้ Skill และเก็บผลการใช้ซ้ำ; ปรับ Skill จากข้อผิดพลาด แล้วเริ่มบริบทใหม่ทำ C อีกครั้ง แยกคะแนนก่อน/หลังและเวลาบำรุงรักษา
  8. ในภารกิจจริงใช้ ./shop reset basic-A (หรือ basic-B) เฉพาะเมื่อเริ่มรอบ เปิด URL จาก ./shop open ให้เห็นปัญหา บันทึก ./shop status และ ./shop logs ถาม AI ด้วยข้อมูลที่เพิ่งได้จริง แล้วเลือกคำสั่งในคู่มือด้วยตนเอง
  9. เมื่อกู้รอบง่ายเสร็จ ให้ผู้สอนเริ่ม ./shop reset advanced-A (หรือ advanced-B) เป็นเหตุการณ์ใหม่ แยกเวลาและหลักฐาน เปิดเว็บและกด จองสินค้า ให้เห็นปัญหา แล้ววินิจฉัยใหม่ ห้ามเอาผลรอบง่ายนับเป็นการกู้รอบยาก
  10. ทุกการกู้ต้องใช้ status/check แล้วเปิด browser กด จองสินค้า จดเลข W2- ที่ได้จริงกับรุ่น บันทึกก่อน/หลังและใช้ ./shop stop เมื่อจบ ค่า HTTP 200 อย่างเดียวไม่พอ

งานที่ส่ง

ใบงาน + ร่างแรก + ฉบับแก้ + คำสั่ง/ID หลักฐาน + scorecard + ข้อเสนอปรับ Skill หนึ่งข้อพร้อมเหตุผล สำหรับ Lab2 แนบภาพ browser ก่อน/หลังและเลขจองด้วย

ตัวอย่างและเกณฑ์ประเมิน

เปิดหลังส่งร่างทั้งสองชุด: ตัวอย่างดีและตัวอย่างผิดที่ผู้สอนแต่ง · เฉลย/รูบริก 12 ข้อ

เกณฑ์สามระดับ: 10–12 = ทำงานได้และยังต้องตรวจจุดเสี่ยง, 7–9 = ต้องแก้ก่อนใช้, 0–6 = ทบทวนหลักฐานและวิธีทำ คะแนนสูงแต่มีการอนุมัติ/นโยบายแต่ง/ผลกู้คืนแต่งถือว่ายังใช้จริงไม่ได้ ไม่ถือคะแนนรวมลบล้างข้อผิดพลาดสำคัญ

ปัญหาที่พบบ่อย

  • AI ไม่เห็นไฟล์: ใช้พื้นที่ที่ launcher แจ้ง อย่าเปิดจาก Week2 รวม และตรวจว่ามี input.md/manual.md ถ้าเปิดผิด ให้แจ้งครูและเริ่มรอบใหม่ที่บันทึกว่า invalid
  • ไม่เห็นชื่อ Skill: เปิดหน้าต่างใหม่จากพื้นที่ S ใช้ /skills หรือพิมพ์ $ เลือกชื่อ shop-recovery; ถ้ายังไม่มีให้ครูตรวจ path ไม่วาง body แทนแล้วเรียกว่า native
  • AI ตอบมั่นใจแต่ไม่มี ID: วางข้อความตรวจคำตอบ บันทึกเป็น correction และเก็บร่างแรกไว้
  • รุ่นโมเดลหรือบัญชีไม่ตรง/หมดเวลา/เข้าใช้ไม่ได้: หยุดรอบ บันทึกเหตุและเวลาจริง ไม่สลับโมเดลหรือเรียกซ้ำเอง
  • เปิด local link ไม่ได้: ใช้หน้า lab HTML ที่แจกหรือเปิดไฟล์ในโฟลเดอร์ ผู้สอนต้องเปิด web server ถ้าห้องใช้ URL
  • PORT BUSY หรือ preflight ไม่ผ่าน: หยุดแจ้งผู้สอน ไม่แก้พอร์ตเอง; check เพิ่มรายการฝึกหนึ่งรายการทุกครั้ง; บริการ stopped ให้เปิดใหม่ตามคู่มือ การกด start ซ้ำไม่แก้ v2

คำถามอภิปราย

  1. ข้อใดเปลี่ยนเพราะหลักฐานใหม่ และข้อใดเปลี่ยนเพราะรูปแบบคำสั่ง?
  2. Prompt ที่มีขั้นตอนครบยังแพ้หรือชนะ Skill เสมอหรือไม่ ใช้คู่ข้อมูล A/B และคะแนนจริงตอบ
  3. การสร้างและปรับ Skill ใช้เวลาเท่าไร ต้องนำกลับมาใช้กี่ครั้งจึงคุ้มสำหรับทีมของคุณ?
  4. ถ้า AI มี ID ทุกบรรทัดแต่ตีความผิด คุณจะตรวจพบด้วยวิธีใด?

ถ่ายโอน C

ใช้ข้อมูล C ในบริบทใหม่กับ Skill เดิมก่อน แยกผลเป็น reuse ครั้งแรก จากนั้นปรับด้วยคำสั่งภาษาคนและทำซ้ำ C เป็น assisted transfer ไม่รวมกับผล A/B

ผลลัพธ์ที่คาดหวังและวิธีตรวจ

เกณฑ์คาดหวัง ไม่ใช่ผลทดลองที่เกิดขึ้นแล้ว: อาการ → หลักฐานและรหัส → สาเหตุที่หลักฐานรองรับ → คำสั่งถัดไปจากคู่มือพร้อมเหตุผล → ผลที่คาดว่าจะเห็นและช่องรอผลตรวจจริง แยกเหตุการณ์ basic กับ advanced; ข้อมูลก่อนกู้ไม่ใช่หลักฐานว่ากู้แล้ว

ช่วงงาน ควรเห็น หากยังไม่ตรง
รับข้อมูล อ้างข้อมูลเพียงชุดที่เลือกและคู่มือครบ ตรวจ variant ด้วย inspect และส่งข้อความผิดพลาดให้ผู้สอน
ร่างแรก โครงสร้างงานครบตามเกณฑ์ด้านบน มีรหัสย้อนตรวจได้ เก็บร่างแรกแล้วใช้ Prompt วิเคราะห์
ฉบับแก้ แก้จุดที่ชี้ได้และรักษาข้อเท็จจริงเดิม ส่งเฉพาะบรรทัดที่ผิดพร้อมรหัสต้นทางให้ AI ตรวจอีกครั้งภายในจำนวนครั้งที่กำหนด
ส่งงาน ใบงานและหลักฐานจริง แยกสิ่งที่ยังไม่รู้และยังไม่ได้ทดสอบ บันทึก not-measured หรือรอยืนยัน ห้ามแต่งค่า

ดู ตัวอย่างผลลัพธ์ที่ครบและตัวอย่างผิด หลังเก็บร่างตามกติกา ตัวอย่างเป็นงานที่ผู้สอนแต่งเพื่ออธิบายรูปแบบ ไม่ใช่คำตอบจากการทดลองรอบใหม่

คู่มือคำสั่งร้านฝึก — ใช้เหมือนกันทั้ง Prompt และ Skill

บริการคือโปรแกรมที่รอรับคำขอจากหน้าเว็บ; รุ่นคือชุดพฤติกรรมของโปรแกรม; rollback คือกลับรุ่นก่อนที่ตรวจแล้วว่าดี; logs คือบันทึกเหตุการณ์ งาน AI ในการทดลองเป็นการวินิจฉัยจากภาพสถานะ ผู้ใช้เป็นคนเลือกและรันคำสั่ง ไม่ใช่ AI ปฏิบัติเอง คำสั่งพร้อมใช้จากโฟลเดอร์ Week2:

คำสั่ง ใช้เมื่อ / ความหมาย ผลที่ควรเห็น
./shop preflight ก่อนเริ่ม ตรวจ Python และพอร์ต PREFLIGHT OK และ URL หรือเหตุขัดข้อง
./shop open ต้องการเปิดเว็บ คัดลอก URL ที่พิมพ์ไป browser URL http://127.0.0.1:พอร์ต
./shop status ดูว่าบริการตอบจริงและรุ่นใด STOPPED หรือ RUNNING version=v1/v2
./shop logs อ่านเหตุการณ์รอบปัจจุบัน EVENT พร้อม UTC, version, booking หรือ error
./shop start บริการหยุดและควรใช้รุ่นปัจจุบัน STARTED version=v1; หากทำซ้ำ ALREADY RUNNING; ไม่แก้ v2
./shop rollback v2 ยังเปิดเว็บได้แต่จองไม่ได้ และมี v1 ที่ดี ROLLED BACK version=v1; บน v1 แจ้ง ALREADY v1
./shop check ตรวจทั้งหน้าเว็บและการจองผ่าน endpoint จริง CHECK PASS booking=... version=v1 หรือ CHECK FAIL; ต้องตรวจ browser เพิ่ม
./shop reset basic-A เริ่มรอบฝึกบริการหยุดชุด A ล้างเฉพาะรายการฝึก RESET basic-A STOPPED version=v1
./shop reset basic-B เริ่มรอบฝึกบริการหยุดชุด B RESET basic-B STOPPED version=v1
./shop reset advanced-A เริ่มรอบอัปเดตเสียชุด A มีสาเหตุเดียวคือ v2 จองไม่ได้ RESET advanced-A RUNNING version=v2
./shop reset advanced-B เริ่มรอบอัปเดตเสียชุด B RESET advanced-B RUNNING version=v2
./shop reset transfer-C เริ่มรอบถ่ายโอน ร้านใหม่แต่สาเหตุ v2 เดิม RESET transfer-C RUNNING version=v2
./shop stop จบงาน หยุดเฉพาะร้านฝึกนี้ STOPPED

ห้าม reset ระหว่างกำลังกู้เพื่อทำให้ผลดูผ่าน ห้ามแก้ไฟล์ภายใน ใช้คำสั่งตามตารางเท่านั้น หลังเลือกคำสั่งกู้: status → check → open → ปุ่ม จองสินค้า → ต้องเห็นเลขจองและรุ่น v1; จดเลขจริง ไม่ใช้ตัวอย่างในคู่มือ หากยังไม่ผ่าน: เก็บ logs หยุดและแจ้งผู้สอน อย่าลองหลายคำสั่งที่ไม่เกี่ยว ข้อมูลสมมติ ไม่มีจ่ายเงินจริง เวลาเครื่อง 240 วินาทีต่อร่าง; ภารกิจกู้คืนของผู้เรียน 30 นาทีแยกจาก setup

# ผู้ช่วยกู้ร้านค้าตามคู่มือสำหรับผู้ใช้ทั่วไป
## วัตถุประสงค์และเมื่อใช้
อธิบายหลักฐานบริการร้านค้าที่มีปัญหา และช่วยผู้ใช้เลือกคำสั่งที่เตรียมให้ ไม่ดูแลระบบจริง ไม่แก้โค้ดหรือไฟล์ตั้งค่า
## ข้อมูลเข้า
อ่าน input.md และ manual.md ทั้งหมด input เป็นภาพสถานะที่ผู้สอนเก็บจริง มีรหัสหลักฐาน ใช้เฉพาะข้อมูลและคำสั่งในคู่มือ
## ขั้นตอน
1. แยก สิ่งที่สังเกตจริง / ข้อสันนิษฐาน / สิ่งที่ต้องตรวจเพิ่ม อ้าง ID ทุกข้อ ไม่ตีความ HTTP 200 ว่าซื้อสินค้าได้
2. ระบุสาเหตุหลักเพียงหนึ่งตามหลักฐานแต่ละรอบ แยกบริการหยุดกับรุ่นอัปเดตเสีย หากไม่พอให้ขอ status/logs และหยุดก่อนแนะนำการเปลี่ยนแปลง
3. อธิบายศัพท์ที่ใช้ด้วยคำง่าย เลือกคำสั่งจากคู่มือเท่านั้น พร้อมเงื่อนไข เหตุผล และผลที่คาดว่าจะเห็น ไม่รันคำสั่งเองในการทดลองวินิจฉัยนี้
4. ห้ามแก้ internals ตั้งค่า ติดตั้งแพ็กเกจ ลบข้อมูล เปิดพอร์ตสาธารณะ หรือสั่งคำสั่งนอกคู่มือ start ใช้เมื่อหยุด; rollback ใช้เมื่อรุ่นอัปเดตเสียและมีรุ่นก่อนหน้าที่ดี
5. ให้ผู้ใช้ตรวจ status, check แล้วเปิด browser ทำรายการจองสินค้าจริงแบบข้อมูลฝึก เก็บเลขรายการและรุ่นก่อน/หลัง หากไม่สำเร็จให้หยุดและแจ้งผู้สอนพร้อม logs ไม่อ้างกู้คืนแล้วก่อนมีหลักฐาน
6. แยกหลักฐานก่อนเหตุ คำแนะนำ และช่องรอหลักฐานหลังทำ ระบุขอบเขตว่าเป็นร้านจำลอง ไม่มีการชำระเงินจริง
## ผลลัพธ์
ตารางหลักฐาน ID | สิ่งที่เห็น | ความหมาย; สาเหตุและความมั่นใจ; ตารางคำสั่งตามลำดับ | เมื่อใด | เหตุผล | ผลคาดหวัง; ช่องบันทึกคำสั่งที่คนทำ รุ่นก่อน/หลัง เลขจอง ผล browser และสถานะ รอทดสอบ/ผ่าน/ไม่ผ่าน
## เกณฑ์รับงาน
หลักฐานตรงสาเหตุ ใช้แต่คำสั่งที่อนุญาต ไม่เปลี่ยนหลายอย่างพร้อมกัน แผนทดสอบมีธุรกรรมผ่าน browser และไม่แต่งผลสำเร็จ จำกัดคำตอบราว 650 คำหรือ 6,000 อักขระโดยรักษาสาระสำคัญ

2 วิเคราะห์

อธิบายหลักฐานแต่ละรอบเป็นคำง่าย แยกบริการหยุดจากรุ่นอัปเดตเสีย ระบุสาเหตุเดียวต่อรอบกับสิ่งที่ยังไม่รู้

3 แก้ไข

ทบทวนคำสั่งให้ตรงคู่มือ ใช้ start เมื่อหยุด และ rollback เมื่อรุ่นเสีย ห้ามแก้ internals แสดงแผนตรวจธุรกรรมและขั้นตอนเมื่อกู้ไม่สำเร็จ

4 ตรวจคำตอบ

ตรวจหลักฐานก่อนและหลังที่ฉันวางต่อไปนี้ แล้วรายงานว่ากู้สำเร็จจริงหรือยัง ถ้ายังไม่มีเลขจองและผล browser ให้บอกว่ายังยืนยันไม่ได้ ไม่แต่งค่า

ก่อนให้ AI ช่วยแก้ เก็บร่างแรกเสมอ การส่งวิเคราะห์/แก้/ตรวจนับเป็นการช่วยเหลือ 1 ครั้งต่อข้อความ ไม่ใช้เกิน 2 ครั้งต่อชุดในรอบเปรียบเทียบ คำใบ้สูงสุด 3 ระดับและจดเวลาเปิด

ขั้นตอน

  1. แยก สิ่งที่สังเกตจริง / ข้อสันนิษฐาน / สิ่งที่ต้องตรวจเพิ่ม อ้าง ID ทุกข้อ ไม่ตีความ HTTP 200 ว่าซื้อสินค้าได้
  2. ระบุสาเหตุหลักเพียงหนึ่งตามหลักฐานแต่ละรอบ แยกบริการหยุดกับรุ่นอัปเดตเสีย หากไม่พอให้ขอ status/logs และหยุดก่อนแนะนำการเปลี่ยนแปลง
  3. อธิบายศัพท์ที่ใช้ด้วยคำง่าย เลือกคำสั่งจากคู่มือเท่านั้น พร้อมเงื่อนไข เหตุผล และผลที่คาดว่าจะเห็น ไม่รันคำสั่งเองในการทดลองวินิจฉัยนี้
  4. ห้ามแก้ internals ตั้งค่า ติดตั้งแพ็กเกจ ลบข้อมูล เปิดพอร์ตสาธารณะ หรือสั่งคำสั่งนอกคู่มือ start ใช้เมื่อหยุด; rollback ใช้เมื่อรุ่นอัปเดตเสียและมีรุ่นก่อนหน้าที่ดี
  5. ให้ผู้ใช้ตรวจ status, check แล้วเปิด browser ทำรายการจองสินค้าจริงแบบข้อมูลฝึก เก็บเลขรายการและรุ่นก่อน/หลัง หากไม่สำเร็จให้หยุดและแจ้งผู้สอนพร้อม logs ไม่อ้างกู้คืนแล้วก่อนมีหลักฐาน
  6. แยกหลักฐานก่อนเหตุ คำแนะนำ และช่องรอหลักฐานหลังทำ ระบุขอบเขตว่าเป็นร้านจำลอง ไม่มีการชำระเงินจริง

คำใบ้ 3 ระดับ — DevOps — กู้ร้านก่อนเริ่มแคมเปญ

เปิดทีละระดับเมื่อจำเป็น จดระดับและ UTC ที่เปิดในใบงาน ห้ามผู้สอนส่งเพิ่มเฉพาะฝ่ายใดโดยไม่บันทึก

ระดับ 1 — ดูหลักฐาน

อ่าน status ก่อนเลือกคำสั่ง อย่าเริ่มจากเดาว่าคอมพิวเตอร์เสีย

ระดับ 2 — จัดความสัมพันธ์

ถ้า STOPPED ดูรอบง่าย; ถ้า RUNNING v2 แต่จองไม่ผ่าน ดูคู่มือเรื่อง rollback อย่า reset เพื่อข้ามปัญหา

ระดับ 3 — แนวทางตัดสิน

รอบง่ายใช้ start แล้ว check/browser; รอบต่อยอดใช้ rollback แล้วตรวจรุ่น v1 และเลขจองจริง เก็บหลักฐานหลังทุกครั้ง

ตัวอย่างผิด

“เว็บตอบ 200 แปลว่าซื้อได้แล้ว ทั้งสองรอบให้ restart ฐานข้อมูล แก้ config และเพิ่มพอร์ต จากนั้น reset ร้านเป็นปกติ ทดสอบผ่าน เลขจอง 12345”

ผิด: basic ไม่มีหลักฐานฐานข้อมูลเสีย; advanced ยังจองล้มเหลวแม้หน้าตอบ; คำสั่งไม่อยู่ในคู่มือ; reset ลบเหตุและไม่พิสูจน์การกู้; แต่งเลขและผลสำเร็จ ต้องกลับไปแยกสองสาเหตุ เลือก start/rollback ให้ตรงหลักฐาน และตรวจรายการจริงผ่าน browser

วิธีประเมิน

คะแนนข้อ 1–12 ข้อละ 1 เมื่อผ่านเงื่อนไขครบ มิฉะนั้น 0 พร้อมคัดข้อความผิดและ ID ต้นทาง ไม่ให้คะแนนจากคำสำคัญตรงกันอย่างเดียว อ้าง A- หรือ B- นำหน้ารหัสตามชุด ส่วน Lab2 ใช้รหัส S/U ใน snapshot ของชุดนั้น

ผู้ตรวจอ่านร่างดิบที่บันทึกก่อน แล้วตรวจฉบับแก้แยก ทำ blind condition ได้โดยซ่อน P/S ผู้ตรวจใน pilot นี้เป็นผู้จัดทำแพ็กเกจ (AI worker อ่านผลตามรูบริก) ไม่ใช่ผู้ประเมินมนุษย์หรือผู้ประเมินอิสระ

ข้อ สิ่งตรวจ เงื่อนไขและหลักฐานเฉลย คะแนน
1 หลักฐานรอบหยุด S1 status STOPPED, S2 browser ERR_CONNECTION_REFUSED อ้าง ID 0 / 1
2 สาเหตุรอบหยุด S3 SERVICE_NOT_STARTED ไม่เดาปัญหา network/ฐานข้อมูลเพิ่ม 0 / 1
3 คำสั่งรอบหยุด เลือก ./shop start ตาม manual สำหรับ basic; ไม่ใช้ rollback แทน 0 / 1
4 หลักฐานรุ่นเสีย U1 RUNNING v2 และ U2 การจองไม่สำเร็จ แยกหน้าเปิดได้จากธุรกรรม 0 / 1
5 สาเหตุรุ่นเสีย U3 UPDATE_V2_BOOKING_BROKEN เพียงหนึ่งสาเหตุใน advanced 0 / 1
6 คำสั่งรุ่นเสีย เลือก ./shop rollback ให้กลับ v1 ตาม manual ไม่คิดว่า start แก้ v2 0 / 1
