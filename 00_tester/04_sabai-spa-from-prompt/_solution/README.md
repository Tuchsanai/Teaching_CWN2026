# 🔑 เฉลยผู้สอน · บท 04 สบายใจ สปา (สร้างเว็บจากพรอมต์ แล้วทดสอบเว็บนั้น)

> ⚠️ **โฟลเดอร์นี้สำหรับผู้สอนเท่านั้น** มีเฉลยบั๊กที่ฝังไว้ ([web/BUGS.md](web/BUGS.md)) แผนทดสอบตัวอย่าง และรายงานโหมดบั๊กฉบับเต็ม
> ถ้าแจกงานให้ผู้เรียน ให้ลบหรือย้าย `_solution/` ออกก่อน (หรืออย่างน้อยห้ามเปิดก่อนจบ LAB 12)

ไฟล์ทั้งหมดในนี้มาจาก **การรันพรอมต์ใน [README.md](../README.md) ของบทจริงครบ LAB 0–12 หนึ่งรอบ** (10 ต.ค. 2026) โดยให้ Claude สวมบทผู้เรียน ทำทีละ LAB ตามพรอมต์ตรงตัว (ไม่อ่าน LAB ถัดไปล่วงหน้า · LAB 7–12 ไม่อ่านโค้ดใน `web/` `db/` และไม่เปิด `web/BUGS.md` จนถึงข้อที่พรอมต์อนุญาต) — กติกาการรันอยู่ใน [_design/RUNNER.md](_design/RUNNER.md)

- **ใช้ Playwright แบบ headless (สคริปต์ node) แทน Playwright MCP** ทุกจุดที่พรอมต์บอก "Playwright MCP" เพราะ MCP บนเครื่องที่ถ่ายทำตั้งเป็นโหมด `--extension` ซึ่งเกาะ Chrome ตัวจริงของผู้ใช้ (cookie และแท็บจริง) ผลที่ได้เทียบเท่ากัน แต่ผู้เรียนที่ใช้ MCP จริงอาจเจอเรื่องต่างไปเล็กน้อย (ดูข้อ 7)
- **บั๊กที่ฝังถูกเลือกโดย Claude เองใน LAB 6** (พรอมต์ BUILD-PROMPT ขั้น 9 สั่งแค่ "3 ตัว: เงิน / การจอง / ตัวเลขหลังทำรายการ") → **แต่ละรอบ (แต่ละผู้เรียน) จะได้บั๊กต่างกัน** ตารางในข้อ 3 จึงเป็นเฉลยของ *รอบนี้* เท่านั้น ผู้สอนต้องเปิด `web/BUGS.md` ของผู้เรียนแต่ละคนเพื่อตรวจ
- ตัวเลขผลจริงทุกตัวในหน้านี้มาจาก `_design/results/LAB*_RESULT.md` และไฟล์ผลจริงในโฟลเดอร์นี้ (ข้อ 8.3 เป็นการตัดไฟล์หลังจบ LAB)

### หมายเหตุรายละเอียดสำคัญ

- **LAB 1–4** — บทสัมภาษณ์ไม่มีราคา/ระยะเวลาบริการ AI จึงตั้งตัวเลขเอง (เช่น นวดไทย 60 นาที ฿1,000) ติด ⚠️ ไว้ · LAB 4 จับข้อขัดแย้งได้เอง: คุณนิดามีคอร์ส ฿15,000 แต่ยอดสะสม ฿12,400 (ขัด A10) → T1
- **LAB 5** — พรอมต์ไม่บอกว่าใครกด "ใช้บริการเสร็จ" Claude จึงเพิ่มบัญชี `owner@sabai.test` + หน้า `/admin` เอง (ถ้าไม่มี BR-09 แต้มหลังใช้บริการทดสอบไม่ได้) และเพิ่มตาราง `hotel`
- **LAB 6** — รันในเซสชันใหม่ ≈ 52 นาที · Claude ตรวจตัวเองด้วย `web/scripts/check-rules.mjs` จากตาราง E01–E90 (ต้อง Node ≥ 22.18 บนเครื่อง) · สมมติฐานที่ตั้งเอง 5 ข้อ (ดู `_design/lab6-final-answer.md`) · ขั้น 11.6 `Start-Process` เปิดเบราว์เซอร์ถูกข้าม
- **LAB 7** — พรอมต์สั่ง "จองคิว → แล้วค่อยเข้าสู่ระบบ" ทำให้การจอง B14 เป็นแบบไม่ล็อกอินและไม่โผล่ในบัญชีคุณนิดา (ไม่ใช่บั๊ก เป็นสมมติฐาน T3) · regex NFR-06 `[฀-๿]` นับ "฿" เป็นอักษรไทย
- **LAB 8** — `dblclick()` ของ Playwright **ไม่เจอ** บั๊กกดซ้ำ ต้องคลิก 2 ครั้งในคำสั่งเดียว (`el.click(); el.click()`) ถึงได้ 2 นัด
- **LAB 9** — สคริปต์รอบแรกได้ 33/40 เพราะสคริปต์อ่าน testid ผิด แก้สคริปต์ (ไม่แก้ผลที่คาดหวัง) → 36/40 · ทั้ง 4 ข้อ ⚠️ ตรงกับที่ LAB 8 เจอ
- **LAB 10** — ตาราง 8.1 ช่วยจับ oracle อ่อน: PRICE-06 เดิมใช้ U08 (Silver 0%) ถ้าส่วนลดหลุดเข้าแพ็กเกจก็ยังผ่าน → เปลี่ยนเป็น U02 (Platinum + เกิด ต.ค.)
- **LAB 11** — **เว็บโหมดปกติก็ไม่ผ่านเกณฑ์อยู่แล้ว** (38/42) เพราะบั๊กจริง 3 ตัว + แผนผิด 1 · `workers: 1` เพราะค่าคาดหวังผูกกับ seed และ CXL-02 เลื่อนนาฬิกาทั้งระบบ · รอบ 1 มี test เขียนผิด 1 ข้อ (I18N-01 บน WebKit นับอักษรไทยก่อนวาดใหม่) แก้แล้ว · รอบ 2 และ 3 ผลเหมือนกัน 100% · **TC-BOOK-05 ใช้ `dblclick()` จึงผ่าน — e2e พลาดบั๊กกดซ้ำที่ LAB 8/9 เจอ** (ดูข้อ 4)
- **LAB 12** — `npm run test:gif` เขียนทับ artifacts ของรอบ 3 เบราว์เซอร์ (outputDir เดียวกัน) → ภาพตอนล้มใน `test-report/artifacts/` เป็นของ Chromium เท่านั้น · TC-BOOK-07 ล้มแบบ timeout 90 วิ (รอปุ่มที่ไม่มี) จึงไม่ได้ตรวจราคา ฿2,520 ต่อ · จบแล้วเปิดกลับโหมดปกติ ยืนยัน 23 รอบ / ฿900 / 108 แต้ม

## 8. เปิดเว็บเฉลยและรัน e2e ซ้ำ

### 8.1 เปิดฐานข้อมูล + เว็บ (PowerShell ที่โฟลเดอร์ `_solution`)

```powershell
cd _solution
docker stop petshop                                    # ถ้ามี container อื่นจับพอร์ต 3000/5433 (stop อย่างเดียว)

# network ร่วม (ครั้งแรกครั้งเดียว)
docker network inspect sabai-net *> $null; if (-not $?) { docker network create sabai-net }

docker compose -f db/compose.yaml up -d                # sabai-db · พอร์ต 5433 · รอ healthy
docker compose -f web/compose.yaml up -d --build       # sabai-web · http://localhost:3000 · build ครั้งแรกหลายนาที
Invoke-RestMethod http://localhost:3000/api/health     # ok=True db=True
```

เปิด/ปิดโหมดบั๊ก:

```powershell
$env:BUG_MODE = "1"; docker compose -f web/compose.yaml up -d --force-recreate   # เปิดโหมดบั๊ก (LAB 12)
$env:BUG_MODE = "0"; docker compose -f web/compose.yaml up -d --force-recreate   # กลับโหมดปกติ
```

เช็กโหมด: ดู `<html data-bug-mode="...">` ในหน้าเว็บ (รายงาน `e2e/index.html` ขึ้นป้ายโหมดให้) · ผู้ใช้ทดสอบทุกคน (รวม `owner@sabai.test`) อยู่ใน [web/SPEC.md](web/SPEC.md) หัวข้อ 7 · ตรวจกฎร้าน: `cd web; node scripts/check-rules.mjs` (Node ≥ 22.18 · ปกติ 90/90 · โหมดบั๊ก 80/90)

> ⚠️ ถ้าเครื่องมี volume `sabai-pgdata` จากรอบก่อน (เช่นของผู้เรียน) seed จะไม่ถูกโหลดใหม่ — ใช้ `POST /api/test/reset` (test ทำให้เองทุกข้อ) หรือ `docker compose -f db/compose.yaml down -v` เพื่อเริ่มใหม่
