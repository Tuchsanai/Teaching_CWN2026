## ข้อเสนอแก้พรอมต์

1. ข้อ 2 "ให้แต่ละเบราว์เซอร์จองคนละวันหรือใช้ผู้ใช้ใหม่" ขัดกับข้อ 3 "ใช้ตัวเลข/ข้อความตามแผนเท่านั้น" เพราะตัวเลขในแผนผูกกับผู้ใช้ seed และวันที่ใน seed (และ CXL-02 เลื่อนนาฬิกาทั้งระบบ) เสนอเขียนตรง ๆ ว่า **"แผนนี้ใช้ผู้ใช้/วันจาก seed → ตั้ง `workers: 1` และ reset ก่อนทุก test"** หรือให้เหตุผลว่าทำไมต้องเลือก
2. ข้อ 2 "POST /api/test/reset … ครั้งเดียว" ขัดกับแผนหัวข้อ 5 "ทุก TC เริ่มจาก reset" เสนอเปลี่ยนเป็น "global-setup reset 1 ครั้ง + reset ก่อนทุก test (fixture)"
3. เพิ่มประโยค: **"ราคาบนหน้าจอมาจาก API แบบไม่พร้อมกัน — รอให้หน้าเว็บคิดเสร็จก่อนอ่าน (ห้ามรอจนได้ค่าที่อยากได้)"** ช่วยตัด "test เขียนผิด" ที่พบบ่อยที่สุดในแล็บนี้
4. "ป้ายโหมดจาก data-bug-mode" ควรบอกว่าให้อ่านตอน global-setup (ไม่ใช่ตอนเปิด index.html ซึ่งเป็น file:// อ่านเว็บไม่ได้)
5. "รันซ้ำอีก 1 รอบเช็กว่าผลนิ่ง" ควรบอกให้บันทึกผลแต่ละรอบ (เช่น `history.json`) ไม่งั้นรอบที่ 2 จะทับรอบแรกจนเทียบไม่ได้
6. ระบุว่าการจำแนก "แผนผิด" **ยังนับเป็นล้ม** จนกว่าแผนจะแก้ (ผู้เรียนอาจอยากแก้ test ให้ผ่านแทน) เช่น TC-SEC-05
7. regex ในแผน `[ก-๛]` ครอบ ฿ ถ้าพรอมต์ให้ "ใช้ข้อความตามแผนเท่านั้น" ผู้เรียนจะลอก regex ผิดมาตรง ๆ เสนอให้แผน (LAB 10) เขียนเป็น `[ก-฾เ-๛]`
