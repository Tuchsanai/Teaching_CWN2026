## ข้อสังเกต 👀 / ปัญหาที่เจอ และวิธีแก้

1. 👀 **Mermaid ไม่มี use case diagram จริง** — ต้องจำลองด้วย `flowchart` (actor = วงรีมน, use case = กล่องใน subgraph "ระบบ", include/extend = เส้นประ) ผู้เรียนควรรู้ว่านี่คือเหตุที่รูปหน้าตาไม่เหมือน UML ในตำรา และรูปยาวมาก (1280×2974) เพราะเส้นโยงเยอะ
2. 👀 **ข้อความ URL บนเส้นเชื่อมพัง**: label `http://localhost:3000` ใน flowchart แสดงเป็น "Unsupported markdown: link" → แก้เป็น "localhost พอร์ต 3000"
3. 👀 **ชื่อ subgraph ยาว/มี `<br/>` ถูกตัด** (เช่น "Docker: sabai-web · พอร์ต" ขาดท้าย) → ย่อชื่อ subgraph ให้สั้นบรรทัดเดียว แล้วย้ายรายละเอียดเข้ากล่องข้างใน
4. 👀 Architecture แบบ `LR` กว้างเกิน อ่านไม่ออกที่ 1280px → เปลี่ยนเป็น `TB`
5. 👀 ERD ของ Mermaid รับชนิดข้อมูลแค่คำเดียว เขียน `NUMERIC(10,2)` ตรงช่อง type ไม่ได้ (มีจุลภาค) → ใส่ `numeric` แล้วระบุ `"NUMERIC(10,2) บาท"` ในช่อง comment — ผู้เรียนต้องเปิดดู comment เพื่อเห็นชนิดเต็ม
6. ปัญหาเครื่องมือ: แก้ไฟล์ด้วย Python บน Windows (text mode) ทำให้ไฟล์กลายเป็น CRLF แล้วสคริปต์ regex หาบล็อก mermaid ไม่เจอ (0/0) → แปลงกลับเป็น LF และเขียนไฟล์ด้วย `newline=''`
7. 👀 การออกแบบจริงเจอเรื่องที่ REQUIREMENTS ขัดกันเอง: FR-14 "ตัดครั้งเมื่อใช้บริการ" vs US-16 Wallet "เหลือ X ครั้ง" — ถ้าตัดตอนใช้ จองล่วงหน้าเกินจำนวนครั้งได้ (D5) นี่คือจุดที่การวาด sequence ช่วยจับได้
8. 👀 คุยกันข้ามโปรเจกต์ compose: ใน network ต้องใช้ `sabai-db:5432` (พอร์ตใน container) ไม่ใช่ 5433 — 5433 ใช้จากเครื่อง host เท่านั้น เขียนไว้ทั้งในรูปและตาราง เป็นจุดที่ผู้เรียนพลาดบ่อยใน LAB ถัด ๆ ไป
9. ตรวจ syntax ด้วยการ render จริง (สคริปต์ `../tools/lab3/render.js` ใช้ playwright headless + `mermaid@11.4.1` ติดตั้งแบบ `--no-save` ใน `../tools`) ไม่ได้ใช้ Playwright MCP ตามกติกา RUNNER

## ข้อเสนอแก้พรอมต์

- ข้อ 2 "Use Case": ควรบอกว่า Mermaid ไม่มี use case diagram ให้ใช้ `flowchart LR` จำลอง (actor เป็นวงรี ระบบเป็น subgraph) ไม่อย่างนั้นแต่ละคนจะได้รูปแบบต่างกันมาก เช่น เสนอ: "Use Case (Mermaid ไม่มีชนิดนี้ ใช้ flowchart LR: actor = `([ ])` ระบบ = subgraph)"
- ข้อ 2 ยังกำกวมว่า "actor ทุกกลุ่ม" = ราย persona (คุณเมย์ ฯลฯ) หรือราย role (ลูกค้า/สมาชิก/นักท่องเที่ยว) — เสนอเติม "ใช้ชื่อบทบาท + ชื่อคนในวงเล็บ"
- ข้อ 1: ควรระบุให้เขียนพอร์ตในเครือข่ายด้วย เช่น "web ต่อ db ด้วย `sabai-db:5432` ผ่าน sabai-net (5433 ใช้จากเครื่องเท่านั้น)" เพราะ AI อาจเขียน 5433 ใน connection string ของ web ผิด
- ข้อ 4: เพิ่มคำใบ้ "ERD ของ Mermaid ใส่ชนิดได้คำเดียว ให้เขียนความยาว เช่น NUMERIC(10,2) ใน comment" และบอกให้ใช้ NUMERIC ไม่ใช่ float สำหรับเงิน
- ท้ายพรอมต์: เพิ่ม "ตรวจว่าแผนภาพทุกรูป render ได้ (เช่น เปิดใน VS Code preview / mermaid.live)" — รอบนี้ syntax ผ่านแต่มี label พัง 1 จุดที่เห็นได้เฉพาะตอน render
- (ถ้าต้องการให้สั้น) ข้อ 3 กำหนด "อย่างน้อย 2 รูป" แล้ว AI มักเพิ่มรูปคำนวณราคาเป็นรูปที่ 3 เอง — ถ้าอยากให้ทุกคนได้ผลเท่ากัน ระบุว่า "2–3 รูป (รูปที่ 3 = คำนวณราคาตาม BR-20 ถ้าต้องการ)"
