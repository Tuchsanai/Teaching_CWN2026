**ถ้าเลื่อนไปทับเวลาเดิมของตัวเอง** (เช่น B02 คู่ 19:00–20:30 → 19:30–21:00)
- โค้ด: `busySlots` เห็น slot T01/T02 ของ B02 เอง → `freeTherapists` บอกว่าคนเดิมไม่ว่าง → 409 `SLOT_TAKEN` ปลอม · `roomBusy` เห็นห้องของ B02 เอง → 409 · `assertNoOverlapForPerson` เห็น B02 → 409 `DUPLICATE_BOOKING` ปลอม → **ทั้ง 3 จุดต้องมีตัวเลือก "ไม่นับนัด id นี้"**
- DB: ถ้า **UPDATE แถวเดิม** ใน transaction เดียว EXCLUDE เทียบกับแถวอื่นเท่านั้น → ไม่ชนตัวเอง · แต่ถ้า "INSERT แถว slot ใหม่ก่อนปิดแถวเก่า" จะชน `booking_slot_no_overlap` → 23P01 → 409 `SLOT_TAKEN` (T11 `web/lib/server/http.ts:42`)

**ทำไม `/api/slots` เดิมใช้หาเวลาเลื่อนไม่ได้** (`availableSlots()` `booking.ts:311-338`)
1. นับนัดของตัวเองเป็น "ไม่ว่าง" (`busySlots` `:325`) → เวลาที่ทับนัดเดิม (19:30 ของ B02) หายไป
2. ตอบ "ว่าง" ถ้านักบำบัด**คนไหนก็ได้**ว่างพอ (`free.length >= people` `:335`) → ไม่ได้ผูกคนเดิม · วัดจริงก่อนแก้: `/api/slots` S01 14 ต.ค. 16:00 = available (T06 ว่าง) แต่ T03 ของ B01 ติด B04 `[E]`
3. ไม่ตรวจกฎเฉพาะการเลื่อน (24 ชม. ของนัดเดิม · เดือนเกิด · วันหมดอายุคอร์ส · เจ้าของนัด)

**ทำไม "ยกเลิกแล้วจองใหม่" ข้างในโค้ดทำให้เพี้ยน** (`cancelBooking()` `booking.ts:497-529` + `createBooking()` `:376-494`)
- **คอร์ส:** ยกเลิกคืน `reserved_sessions - 1` (`:511`) แล้วจองใหม่ผ่าน `buildQuote` ที่ต้อง `canUseCourse(remaining ≥ 1 …)` (`booking.ts:118-139` · `web/lib/rules/course.ts:16-18`) → ถ้าทำนอก transaction เดียวหรือมีคนอื่นแทรก ครั้งอาจหาย/ซ้ำ · และนัดใหม่ได้ `course_purchase_id` ใหม่จาก `ORDER BY expires_on` อาจคนละคอร์ส
- **เดือนเกิด:** ยกเลิกลบ `birthday_use` เฉพาะเมื่อ `yearMonth(today) <= ym` (`:525-526`) แล้วจองใหม่ insert ใหม่ (`:473`) → ถ้าลำดับผิดชน PK `birthday_use_pkey` · และ `buildQuote` คิดส่วนลดใหม่ตามวันนัดใหม่ (`:143-151`) → สิทธิ์เดือนเกิดหาย/ได้ใหม่
- **ราคา/แต้ม/บัตร:** จองใหม่คิดราคาใหม่ทั้งหมด (`calcPrice` + tier ปัจจุบัน + CR-02 ส่วนลดกลุ่มตามวันจอง) ขัด CR ข้อ 2 · แต้ม/บัตรถูกคืน (`:515-524`) แล้วตัดใหม่ · ต้องส่ง `quotedTotal` ใหม่ ไม่งั้น 409 `PRICE_CHANGED` (`:388-390`) · รหัสนัดเปลี่ยน (B05 → B14) และมีนัด cancelled ค้างในประวัติ
- **ช่วงเวลา:** ระหว่างยกเลิกกับจองใหม่ รอบเดิมว่างให้คนอื่นแย่ง (ปัญหาที่ร้านเล่าใน CR)
→ ทางที่เลือก: **UPDATE แถวเดิม** (`booking.start_at/end_at` + `booking_slot.period` ทุกแถว) ใน transaction เดียว ไม่แตะคอลัมน์เงิน/แต้ม/คอร์ส/บัตร/เดือนเกิด
