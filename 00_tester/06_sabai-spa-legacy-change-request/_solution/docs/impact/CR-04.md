## 3. ออกแบบ

- ตาราง `shop_holiday (holiday_date DATE PRIMARY KEY, name_th VARCHAR(100) NOT NULL, name_en VARCHAR(100) NOT NULL, name_zh VARCHAR(100) NOT NULL)` `[D:CR-04] ②`
- `db/migrations/001_shop_holiday.sql`: `BEGIN` · `CREATE TABLE IF NOT EXISTS` · `INSERT … ON CONFLICT (holiday_date) DO NOTHING` 3 แถว · `COMMIT` → รันซ้ำได้ ไม่แตะตารางเดิม
- `db/migrations/001_shop_holiday.down.sql`: `DROP TABLE IF EXISTS shop_holiday` (ข้อมูลที่หาย = แถววันหยุดทั้งหมด รวมที่ร้านเพิ่มเองในอนาคต · นัด/ลูกค้าไม่หาย)
- เครื่องติดตั้งใหม่: เพิ่ม `CREATE TABLE` ใน `db/init/01-schema.sql` (โครงตรงกับ migration) + 3 แถวใน `db/init/02-seed.sql`
- reset: เติม `"shop_holiday"` ใน `TABLES` + แถวใน seed (ข้อ 2) → rebuild image (T4)
- ทุกช่องทางจอง ผ่าน 3 จุดเท่านั้น:
  - `availableSlots()` `web/lib/server/booking.ts:309` (หน้า /book ขั้น 2 ผ่าน `/api/slots` · แชท `freeTimes` `chat.ts:197`)
  - `buildQuote()` `booking.ts:105` (`/api/price` และ `createBooking()` `booking.ts:374` = จองทุกแบบ single/couple/group/package/course)
  - แชทขั้นเลือกวัน `web/lib/bot/chat.ts:211-216` (ต้องตอบเป็นข้อความ ไม่ปล่อย ApiError จาก `freeTimes` หลุดเป็น 422 ของ `/api/chat`)
- ลำดับ error: `SERVICE_INVALID` → จำนวนคน → (slots: `BAD_REQUEST` วันที่) → **`DATE_OUT_OF_RANGE` → `SHOP_CLOSED`** → `SLOT_INVALID` → … `[D:CR-04] ① ข้อ 3`
- error `422 SHOP_CLOSED {date, name}` · `errorBody()` เติม `{name}` ในข้อความ (`web/lib/server/http.ts:26-33`)
- `GET /api/holidays` → `{holidays:[{date,name,nameTh,nameEn,nameZh}]}` เรียงวันที่ `[D:CR-04] ②`
- หน้า /book: ไม่ต้องแก้ component · `BookingWizard.tsx:144-148` แสดง error จาก `/api/slots` ใน `ErrorBox` (`:372`) อยู่แล้ว
