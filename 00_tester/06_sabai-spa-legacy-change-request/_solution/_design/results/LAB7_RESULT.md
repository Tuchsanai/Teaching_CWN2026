## 7. ข้อสังเกต 👀

- **impact พลาดเคส "เจ้าของนัดเดิมจองทับในเทสต์เก่า"**: grep หา "เทสต์พร้อมกันคนละคน" ครบ แต่ไม่ได้ไล่ว่าเทสต์เก่าตัวไหน "จองทับนัด seed ด้วยบัญชีเจ้าของนัด" (TC-BOOK-07 ใช้ U02 ทับ B02 ของ U02) → แดงที่ e2e-legacy รอบแรก · บทเรียนดี: กฎใหม่ที่ "เพิ่มเงื่อนไขปฏิเสธ" ต้องคิดเรื่อง**ลำดับ error** เมื่อเข้าหลายเงื่อนไขพร้อมกัน
- **ภาษาของ error มาจาก cookie ไม่ใช่ `body.lang`**: `bookings/route.ts:11` ใช้ `getLang(body.lang)` สำหรับผลสำเร็จ แต่ `handle()` `http.ts:39` ใช้ `getLang()` (cookie) สำหรับ error → เทสต์ที่ส่ง `lang` ใน body ได้ข้อความสำเร็จภาษาที่ขอ แต่ error เป็นไทย (จับได้ตอนออกแบบ ก่อนรันเขียว)
- `errorBody()` เดิมไม่รับตัวแปรในข้อความ → ต้องแตะ `http.ts` เพิ่ม 1 บรรทัดเพื่อใส่ `{code}` · แชทเรียก `errorBody(lang, code)` โดยทิ้ง `e.extra` → ถ้าไม่แก้ `chat.ts:264` แชทจะได้ "(รหัส {code})" ตัวอักษรตรง ๆ
- สมาชิกถูก serialize อยู่แล้วโดย `loadCustomer(…, lock=true)` (FOR UPDATE ใน `buildQuote`) แต่ก่อนแก้ก็ยังซ้ำได้ (C11 201+201) เพราะไม่มีการตรวจ — ล็อกอย่างเดียวไม่พอ ต้องมีเงื่อนไข · ไม่ล็อกอินไม่มีแถวให้ล็อก → ต้องใช้ advisory lock
- แชทบอกว่าจองซ้ำ**หลังถามครบทุกขั้น**แล้วตอนพิมพ์ "ยืนยัน" (ขั้นเวลายังแสดง 10:00 ว่าง เพราะว่าง = นักบำบัดว่าง) — ตรงตามคำตอบร้าน (ตรวจตอนสร้างนัด) แต่ UX อาจถูกถาม
- TC-BOOK-05 (ดับเบิลแตะปุ่ม) ผ่านทั้งก่อนและหลัง = เหตุผลที่ "หน้าเว็บดูปลอดภัย" ทำให้ทีมเดิมคิดว่ากันซ้ำแล้ว

## 8. เจอระหว่างทาง (นอก CR)

- error ของ API ไม่สนใจ `lang` ใน body (`http.ts:39` `handle()` → `getLang()` ไม่มี override) ทั้งที่ route ใช้ `getLang(body.lang)` กับผลสำเร็จ → ภาษาไม่สม่ำเสมอระหว่าง 201 กับ 4xx
- KI-02 เบอร์ `abc` ยังจองได้ (known issue เดิม) และ BR-21 ข้ามเพราะไม่มีตัวเลขให้เทียบ → คนไม่ล็อกอินที่ใส่เบอร์ไร้ตัวเลขจองซ้ำได้ไม่จำกัด
- นัดซ้ำที่มีอยู่แล้วในฐานจริง (เช่น ของคุณสมชาย) ไม่ถูกตรวจ/รายงาน (ร้านบอกนอกขอบเขต) — ควรมีรายงาน SQL ให้ร้าน
- แชทแสดงรอบ "ว่าง" ตามนักบำบัด ไม่ดูว่าผู้จองมีนัดทับอยู่ (ผู้ใช้ไม่ล็อกอินยังไม่ได้ให้เบอร์ ณ ขั้นนั้น)

## 10. ข้อเสนอแก้พรอมต์

- **H** ส่วนที่ 1 เป็น Plan mode แต่ข้อ 2 ("เขียนคำถามถึงร้าน แล้วค่อยเปิด answers") และข้อ 4 ("docs/impact/CR-03.md") ต้องสร้างไฟล์ → ปัญหาเดียวกับ LAB 6 · เสนอเขียน: "ใน Plan mode ให้แสดงคำถามและเนื้อหา impact ในแผน · หลังผมอนุมัติ (ออกจาก Plan mode) ให้บันทึก `docs/impact/CR-03.md` ก่อนเริ่มแก้" · และข้อ 2 ใน plan mode ถือว่าการ "เขียนคำถาม" คือแสดงในแชทก่อนเปิดคำตอบ
- **H** ส่วนที่ 2 ข้อ 3 "(3 เบราว์เซอร์)" ขัดกับแผน M6 ที่ให้รัน api + chromium · ถ้าตั้งใจ 3 เบราว์เซอร์ให้เขียน `--project=chromium --project=firefox --project=webkit` ชัด ๆ (และบอกว่าต้อง `npx playwright install` ครบ) ไม่งั้นตัดคำว่า 3 เบราว์เซอร์
- **M** ส่วนที่ 1 ข้อ 4 เพิ่ม: "ไล่เทสต์เดิมที่จองทับนัด seed ด้วยบัญชี/เบอร์เจ้าของนัด (เช่น `grep -n "U02\|B02" e2e-legacy/tests`) และกำหนดลำดับ error เมื่อเข้าหลายเงื่อนไข (คิวเต็ม vs นัดซ้ำ)" — ไม่งั้นผู้เรียนจะเจอ TC-BOOK-07 แดงตอน regression (ซึ่งก็เป็นบทเรียนข้อ 5 ได้ ถ้าตั้งใจ ให้คงไว้แต่ใส่ใน "ผลที่คาด")
- **M** ส่วนที่ 2 ข้อ 3 แชท: บอกว่าแชทต้องเดินครบ 5 ข้อความ (จอง → วัน → เวลา → ชื่อ+เบอร์ → ยืนยัน) และส่ง `state` กลับทุกครั้ง · ภาษาของ error API มาจาก cookie `lang` ไม่ใช่ body
- **L** ส่วนที่ 1 ข้อ 1 ระบุบริการให้ชัด ("S02 นวดไทย 90 นาที · quotedTotal 1400") ลดเวลาไปหาใน seed
