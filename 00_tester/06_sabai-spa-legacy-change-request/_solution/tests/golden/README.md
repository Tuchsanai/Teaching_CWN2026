# Golden master ของ API (ตาข่ายกันพลาด · ระบบที่รับมอบ)

**ทุกค่าในโฟลเดอร์นี้เป็นป้าย [E]** = หลักฐานจากระบบที่รับมอบ (ยิง API จริงแล้วบันทึก) ใช้ **ล็อกพฤติกรรมเดิม** เพื่อจับการเปลี่ยนที่ไม่ได้ตั้งใจ — **ไม่ใช่การตัดสินว่าค่าถูกตามกฎร้าน**
กฎธุรกิจต้องมีป้าย `[D:CR-0N]` จากคำตอบร้าน · ถ้า [E] ขัด [D] = ผู้ต้องสงสัยบั๊ก ไม่ใช่ค่าคาดหวัง
อ้างค่าใดจาก golden ให้เขียน `[E golden/<ไฟล์>:<sha8>]` เช่น `[E golden/price.json:a485c485]`

## วิธีรัน (PowerShell จากโฟลเดอร์บท · Node >= 22.18 · ไม่มี dependency)

```powershell
# เทียบกับ golden (ต่าง → พิมพ์เคส + ฟิลด์ แล้ว exit 1)
node tests/golden/run.mjs
# เขียน golden ใหม่ (ทำเฉพาะเมื่อ CR อนุญาตให้เปลี่ยนพฤติกรรม · ดู CLAUDE.md "ห้ามแตะ" และจดใน docs/ORACLE-CHANGES.md)
node tests/golden/run.mjs --update
```

`BASE_URL` ค่าเริ่ม `http://localhost:4000` (พอร์ตอื่น: `$env:BASE_URL="http://localhost:<พอร์ต>"`) · ต้องเปิด `ALLOW_TEST_RESET=1` (สคริปต์เรียก `POST /api/test/reset {"now":"2026-10-10T10:00:00+07:00"}` ก่อนทุกกลุ่ม)

## ฟิลด์ที่ตัดก่อนเทียบ และเหตุผล

| ฟิลด์ | เหตุผล |

| `id` `bookingId` | เลข serial ของฐาน · ขึ้นกับลำดับการรัน/sequence ไม่ใช่พฤติกรรมทางธุรกิจ · ใช้ `code` (B01…) เป็นตัวระบุแทน |

## วัดตาข่ายด้วยการทำพังเอง (mutation แบบมือ · 2026-10-12)

แก้ตัวละ 1 บรรทัด → `up -d --build --wait` → golden → `check-rules` → `e2e-cr` (chromium) → คืนไฟล์ `git checkout -- <ไฟล์>` (git diff ว่างทุกตัว)

| ตัวทำพัง | golden | check-rules | e2e-cr (chromium) | ผล |
|---|---|---|---|---|
| X1 `tier.ts` `spend >= GOLD_MIN` → `>` | ❌ 2/62 ต่าง (`single-S01-U07` `group3-S01-U07` · U07 ยอดสะสม ฿10,000 พอดี) | ❌ 88/90 (E46 E51) | ✅ 6/6 ผ่าน (ไม่จับ) | ถูกจับ |
| X2 `transport.ts` `SEATS_PER_VEHICLE = 4` → `5` | ❌ 3/62 (`package5-P01-guest-H05` `group5-S01-guest-H04` `group5-S01-U06-redeem1-H04-GCPART`) | ❌ 88/90 (E78 E80) | ✅ 6/6 (ไม่จับ) | ถูกจับ |
| X3 `pricing.ts` `GROUP_PCT = 10` → `15` | ❌ 10/62 (ทุกเคสกลุ่ม ≥ 4 คน) | ❌ 83/90 (E27 E28 E79 E84 E85 E87 E88) | ✅ 6/6 (ไม่จับ) | ถูกจับ |

หลังคืนครบ 3 ตัวแล้ว rebuild โค้ดปกติ → golden ผ่าน 62/62 · check-rules 90/90

**ไม่มีตัวที่รอด** แต่ตาข่ายยังบาง:
- X1 ถูก golden จับได้แค่ 2 เคส และทั้งคู่เป็นผู้ใช้คนเดียว (U07 ยอดพอดี ฿10,000) · ขอบ Platinum (฿30,000) มีแค่ U02 ที่ยอดพอดี (U05 = 29,999 อยู่ใต้ขอบ) → ถ้าพัง `>= PLATINUM_MIN` golden จับได้เฉพาะเคสของ U02 (เดี่ยว · แพ็กเกจ · GCLAST · วันเกิด) · เสนอเคสเพิ่ม (ยังไม่เขียน): ราคาของ U02 แบบคู่/กลุ่ม 3 คน และเทียบ U05
- X2 จับได้เฉพาะเคส 5 คน (6 คน ÷ 4 หรือ ÷ 5 ได้ 2 คันเท่ากัน) · เสนอเคส: กลุ่ม 5 คนระยะ ≤ 5 กม. (H01 · ค่ารถ 0 แต่จำนวนคันต้องเป็น 2) และ `GET /api/transport` 4/5/8/9 คน
- `e2e-cr` ไม่จับตัวไหนเลย เพราะ characterization หน้าจองล็อกแค่ลูกค้าไม่ล็อกอินจองเดี่ยว (ไม่มีส่วนลด/รถ) · เสนอเคส UI: กลุ่ม 4 คน + H04 ล็อกยอดหน้าสรุป และสมาชิก U07 ล็อกบรรทัดส่วนลด
