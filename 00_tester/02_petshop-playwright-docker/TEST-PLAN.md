# 📋 แผนการทดสอบ (Test Plan) — PawPantry

## 1. ระบบที่ทดสอบ
เว็บร้านอาหารแมวและหมา **PawPantry** (Next.js) ที่รันใน Docker ที่ `http://localhost:3000`
ทดสอบอัตโนมัติด้วย **Playwright บน Windows** โดยสั่งผ่าน Claude Code

## 2. ขอบเขต
| ทดสอบ ✅ | ไม่ทดสอบ ❌ |
|---|---|
| การทำงานของทุกหน้า (functional) ตั้งแต่ค้นหาจนสั่งซื้อ | การรับเงินจริง (เว็บเป็นระบบจำลอง) |
| การคำนวณราคา ส่วนลด และค่าส่ง | ความเร็วเมื่อมีผู้ใช้จำนวนมาก (load test) |
| การตรวจข้อมูลในฟอร์ม (validation) | ความปลอดภัยเชิงลึก (penetration test) |
| ระบบแนะนำสินค้า · หมวดของเล่น / ของใช้ | |
| 3 เบราว์เซอร์: Chromium, Firefox, WebKit (Safari) · หน้าจอมือถือ · API | |

## 3. วิธีคิด test case (เทคนิคที่ใช้)
| เทคนิค | ตัวอย่างในบทนี้ |
|---|---|
| **Happy path** ทางที่ลูกค้าใช้บ่อย | ซื้อของจนจบ (TC-CHK-03) |
| **Negative test** ใส่ข้อมูลผิด | รหัสผ่านผิด, คูปองหมดอายุ, เบอร์โทร 9 หลัก |
| **Boundary value** ค่าขอบ | ซื้อ ฿790 กับ ฿999 (ส่งฟรี), จำนวนเกินสต็อก |
| **Equivalence partition** แบ่งกลุ่มข้อมูล | ตัวกรอง แมว/หมา, เปียก/แห้ง/ขนม |
| **State** ข้อมูลต้องอยู่ต่อ | รีโหลดแล้วตะกร้าและรายการโปรดยังอยู่ |
| **API / Security** | สั่งซื้อผ่าน API โดยไม่เข้าสู่ระบบต้องได้ 401 |

## 4. ระดับความสำคัญ
- **P1** ถ้าพังแล้วขายของไม่ได้ หรือเงินคำนวณผิด
- **P2** ฟีเจอร์สำคัญ แต่ลูกค้ายังซื้อของได้
- **P3** ความสวยงามหรือกรณีที่เกิดไม่บ่อย

## 6. เกณฑ์ (Entry / Exit criteria)
- **เริ่มทดสอบได้เมื่อ** container `petshop` ขึ้นสถานะ healthy และ `/api/health` ตอบ `{ ok: true }`
- **ผ่านเกณฑ์เมื่อ** test case P1 ผ่านทั้งหมด และอัตราผ่านรวม ≥ 95%
