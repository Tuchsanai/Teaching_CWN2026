หน้าที่ของเราคือ **คัดลอกพรอมต์ → วางใน Claude Code → อ่านผล** ไม่ต้องเขียนโค้ดเอง

## 🐳 ระบบที่ทดสอบ (System Under Test) และสภาพแวดล้อมการทดสอบ

บทเรียนนี้ไม่ครอบคลุมการพัฒนาเว็บไซต์ ระบบที่ใช้ทดสอบคือเว็บไซต์ร้านอาหารสัตว์ **PawPantry** ซึ่งพัฒนาด้วย Next.js และจัดเตรียมไว้ในโฟลเดอร์ `petshop/` แล้ว ระบบนี้ถูกบรรจุเป็น **Docker container** ซึ่งรวมโค้ดและส่วนประกอบที่จำเป็นต่อการทำงานไว้ครบถ้วน

![Docker คือกล่องที่ใส่เว็บไว้ครบ: 1 แพ็กเว็บใส่กล่อง 2 เปิดกล่องแล้วเว็บพร้อมใช้ที่ localhost:3000 3 Playwright ทดสอบ และเครื่องไหนเปิดก็ได้เว็บเหมือนกัน](img/intro-02-docker-new.png)

| ขั้นตอน | ผู้รับผิดชอบ | รายละเอียด |
|---|---|---|
| 1. จัดเตรียมระบบ | ผู้สอน (ดำเนินการแล้ว) | บรรจุเว็บไซต์ PawPantry เป็น Docker container |
| 2. เปิดใช้งานระบบ | ผู้เรียน (LAB 2) | รัน container ให้เว็บไซต์ให้บริการที่ `http://localhost:3000` |
| 3. ทดสอบระบบ | ผู้เรียน + Playwright (LAB 3 เป็นต้นไป) | ตรวจสอบว่าเว็บไซต์ทำงานถูกต้องตามข้อกำหนดใน `petshop/SPEC.md` |

**เหตุผลที่ใช้ Docker:** container ทำให้ทุกเครื่องได้สภาพแวดล้อมการทดสอบ (test environment) เดียวกัน ผลการทดสอบจึง **ทำซ้ำได้ (reproducible)** และเปรียบเทียบกันได้ระหว่างผู้เรียนทุกคน

## 🚦 P1 P2 P3 คืออะไร?

**P = Priority (ความสำคัญ)** บอกว่าถ้า test ข้อนี้ล้ม ต้องรีบแก้แค่ไหน

![P1 สีแดง ขายของไม่ได้หรือเงินผิด ต้องแก้ก่อน, P2 สีเหลือง ฟีเจอร์สำคัญแต่ยังซื้อได้, P3 สีเขียว สวยงามหรือเกิดไม่บ่อย](img/concept-05-priority.jpg)

| ระดับ | ความหมาย | ตัวอย่างในเว็บนี้ | ถ้าล้ม |
|---|---|---|---|
| 🔴 **P1** | ขายของไม่ได้ / **เงินผิด** | ยอดรวมผิด, คูปองลดผิด, สั่งซื้อไม่ได้ | **ต้องแก้ก่อนเปิดใช้** |
| 🟡 **P2** | ฟีเจอร์สำคัญ แต่ยังซื้อได้ | ตัวเลขรายการโปรดไม่ลด, แนะนำสินค้าไม่ตรง | แก้รอบถัดไป |
| 🟢 **P3** | สวยงาม / เกิดไม่บ่อย | หน้า 404, เมนูมือถือ | ว่างแล้วค่อยแก้ |

> 💡 วิธีจำ: ถามตัวเองว่า **"ถ้าพัง ร้านยังขายของได้ไหม?"** ขายไม่ได้ = P1 · ขายได้แต่ฟีเจอร์เสีย = P2 · แค่ไม่สวย = P3

## LAB 1 · พรอมต์รวม: เปิดเว็บ ทดสอบ อัด GIF ทำรายงาน

![หน้าต่าง Claude Code เซสชันใหม่ วางพรอมต์ของ LAB 1 ไว้ในช่องข้อความ กรอบสีแดง](img/lab1-paste.png)

💬 **คัดลอกพรอมต์นี้** (กดปุ่ม Copy มุมขวาของกรอบ)

```text
ในโฟลเดอร์นี้มีเว็บร้านอาหารสัตว์ (petshop) และชุดทดสอบ (e2e) พร้อมแล้ว ไม่ต้องเขียนโค้ดใหม่
1. ในโฟลเดอร์ petshop รัน docker compose up -d --build รอจนขึ้น healthy
2. ในโฟลเดอร์ e2e รัน npm install แล้ว npx playwright test
3. รัน npm run test:gif เพื่ออัดทุก test เป็น GIF
4. เปิด e2e/test-report/TEST-REPORT.md แล้วสรุปให้ผมแบบภาษาง่าย ๆ
ถ้าขั้นไหนไม่ผ่าน ให้หยุดแล้วบอกสาเหตุ ห้ามแก้โค้ดเว็บหรือแก้ test เอง
```

✅ **ผลจริง**

| ขั้น | ผล |
|---|---|
| 1. เปิดเว็บด้วย Docker | ✅ `petshop` ขึ้น **healthy** ที่ http://localhost:3000 |
| 2. ทดสอบ 3 เบราว์เซอร์ | ✅ **120 passed** (40 test × 3 เบราว์เซอร์) ใน 1.1 นาที |
| 3. อัด GIF + MP4 | ✅ ได้ GIF 37 ไฟล์ + MP4 37 ไฟล์ |
| 4. รายงาน | ✅ ผ่าน 100% → **ผ่านเกณฑ์ พร้อมปล่อยใช้งาน** |

💡 **พรอมต์ที่ดีมี 4 อย่าง** (เหมือนบท 01)
1. 📋 **บอกให้ชัดว่าทำอะไร** → "เว็บและ test พร้อมแล้ว ไม่ต้องเขียนใหม่"
2. 🪜 **แบ่งเป็นขั้น** → AI ทำตามลำดับ
3. 🛑 **ทำไม่ได้ ให้หยุดแล้วบอก** → ไม่แอบแก้ test ให้ผ่าน
4. ✅ **ขอผลที่อ่านง่าย** → สรุปภาษาง่าย ๆ

![หน้าต่าง Claude Code เซสชันใหม่ วางพรอมต์ของ LAB 2 ไว้ในช่องข้อความ กรอบสีแดง](img/lab2-paste.png)

## LAB 4 · อ่านแผนการทดสอบ

![หน้าต่าง Claude Code เซสชันใหม่ วางพรอมต์ของ LAB 4 ไว้ในช่องข้อความ กรอบสีแดง](img/lab4-paste.png)

💬 **คัดลอกพรอมต์นี้**

```text
อ่าน TEST-PLAN.md แล้วอธิบายให้คนที่ไม่ใช่โปรแกรมเมอร์ฟัง
ว่าเราจะทดสอบอะไรบ้าง ทำไมต้องลองทั้งข้อมูลถูกและข้อมูลผิด
และ P1 P2 P3 ต่างกันยังไง
```

✅ **ผลจริง** แผนมี **40 test case** แบ่งเป็น 11 เรื่อง

![เช็กลิสต์ 8 เรื่องที่จะทดสอบ: สมัครเข้าสู่ระบบ ค้นหากรอง หน้าสินค้า รายการโปรด ตะกร้าคูปอง สั่งซื้อจนจบ ระบบแนะนำ มือถือและ API](img/intro-03-what-to-test.jpg)

| เรื่อง | จำนวน | ตัวอย่าง |
|---|---|---|
| หน้าแรก | 2 | หน้าแรกแสดงครบ |
| ค้นหา / กรอง | 6 | ค้นหา "แซลมอน" ต้องเจอ 5 รายการ |
| หน้าสินค้า | 4 | สินค้าหมด กดใส่ตะกร้าไม่ได้ |
| รายการโปรด | 3 | ลบแล้วตัวเลขต้องลดทันที |
| ตะกร้า | 4 | ซื้อครบ ฿999 ส่งฟรี |
| คูปอง | 3 | PAW10 ลด 10% |
| สมัคร / เข้าสู่ระบบ | 6 | รหัสผ่านผิดต้องเตือน |
| สั่งซื้อ | 4 | **ซื้อของจนจบ (End-to-End)** |
| ระบบแนะนำ | 4 | ลูกแมวแพ้ไก่ ต้องไม่แนะนำสูตรไก่ |
| มือถือ + API | 4 | สั่งซื้อผ่าน API โดยไม่ login ต้องถูกปฏิเสธ |

![ลูกค้าแมวเดินผ่าน 6 จุด ค้นหา หน้าสินค้า ใส่ตะกร้า ใช้คูปอง เข้าสู่ระบบและที่อยู่ สั่งซื้อสำเร็จ](img/concept-06-e2e-journey.jpg)

![ระบบแนะนำสินค้า: ใส่ แมว ลูกแมว ไม่กินไก่ เข้ากรวย สูตรไก่ถูกคัดออก ได้ 3 ถุงพร้อมเปอร์เซ็นต์ตรงใจ](img/concept-08-recommend.jpg)

👀 **สังเกต**
- test ที่ยากที่สุดคือ **End-to-End** = เดินแทนลูกค้าตั้งแต่ค้นหาจนจ่ายเงิน
- ระบบแนะนำสินค้าต้องเช็กว่า **"ไม่มีไก่หลุดมา"** ไม่ใช่แค่ "มีผลออกมา"

## 📖 คำศัพท์

| คำ | ความหมายง่าย ๆ |
|---|---|
| **Test case** | "ลองทำแบบนี้ ต้องได้ผลแบบนี้" 1 ข้อ |
| **Expected / Actual** | ผลที่คาดหวัง / ผลที่เกิดจริง |
| **Pass / Fail** | ผ่าน (ตรงกัน) / ล้ม (ไม่ตรง) |

| **Happy path / Negative** | ทางที่ใส่ข้อมูลถูก / ทางที่ใส่ข้อมูลผิด |
| **Boundary** | ค่าขอบ เช่น ฿998 / ฿999 |
| **Exit criteria** | เกณฑ์ว่า "ผ่านพอจะปล่อยใช้งานได้" |
| **Docker image / container** | สูตร / ร้านที่เปิดจริง |
| **Playwright** | หุ่นยนต์ที่ใช้เว็บแทนเรา |
