# สร้างเว็บสปาจากพรอมต์ล้วน แล้วทดสอบด้วย Playwright (Copy & Paste)

บทนี้ **ไม่มีโค้ดให้เลย** มีแค่รูป → เราฟังร้าน แล้วให้ Claude เขียนความต้องการ สร้างเว็บ และทดสอบให้ทั้งหมด
หน้าที่ของเราคือ **คัดลอกพรอมต์ → วางใน Claude Code → อ่านผลและตัดสินใจ** ไม่ต้องเขียนโค้ดเอง

![คุณจันทร์เจ้าของร้านต้อนรับสู่สบายใจ สปา น้องบัวมาสคอตดอกบัวโบกมือ เด็กผู้ชายกับหุ่นยนต์ตื่นเต้นหน้าแล็ปท็อปที่เปิดเว็บสปา มีป้าย 4 ฟีเจอร์ AI แนะนำผิว จองคิวทันที สมาชิก + แต้ม ทัวร์ห้อง 360°](img/intro-01-sabai-spa.jpg)

## 🌸 สบายใจ สปา คือเว็บอะไร?

เว็บสปาเพื่อสุขภาพในกรุงเทพฯ มี **"AI" แนะนำผิว · จองคิว · สมาชิกสะสมแต้ม · ทัวร์ห้อง 360°** และอีกเพียบ
ทุกฟีเจอร์ **เราไม่ได้เขียนเอง** แต่ได้มาจากการคุยกับร้าน แล้วให้ Claude สร้างให้

![ทางเดินแบบมืออาชีพ 5 จุด 1 คุยกับร้าน 2 เขียนความต้องการ 3 พรอมต์สร้างเว็บ 4 เปิดเว็บ 5 ทดสอบ เด็กกับหุ่นยนต์เดินตามทาง คุณจันทร์โบกมือรอ](img/intro-03-pro-flow.jpg)

## 🎓 พื้นฐาน: จาก "คำพูด" สู่ "เว็บ" (ดูรูปเป็นหลัก)

> ยังไม่ต้องเปิดคอมก็ได้ ดูรูปทีละรูปก่อน

### 1) ฟังก่อนสร้าง

![ฟังก่อนสร้าง เด็กจดสมุด 2 ช่อง กฎร้าน กับ สิ่งที่อยากได้ ลูกค้าสาวออฟฟิศบอกว่าเครียด อยากจองง่าย ๆ คุณจันทร์บอกว่ายกเลิกก่อน 24 ชม. ฟรี หุ่นยนต์ถือไมค์](img/concept-01-interview.jpg)

**เจ้าของร้าน** บอก "กฎร้าน" (มีตัวเลข) · **ลูกค้า** บอก "อยากได้อะไร"

### 2) User Story = 3 ช่อง

![User Story 3 ช่อง 1 ในฐานะ คนทำงานที่เครียด 2 ฉันอยาก จองตามอารมณ์ 3 เพื่อ ได้ทรีตเมนต์ที่ใช่](img/concept-02-user-story.jpg)

**ในฐานะ… ฉันอยาก… เพื่อ…** = ความต้องการ 1 ข้อ เล่าจากมุมของคนใช้

### 3) เสร็จแล้ว ดูยังไง? (เกณฑ์ยอมรับ)

![เสร็จแล้วดูยังไง เช็กลิสต์ กด เหนื่อย และ เห็นนวดไทยอันดับ 1 ลูกศรไปที่ไฟล์ test หุ่นยนต์บอกว่า ตรวจได้ = เป็น test ได้](img/concept-03-acceptance.jpg)

เขียนให้ **ตรวจได้** (มีตัวเลขหรือข้อความชัด ๆ) → กลายเป็น test ได้ทันที (ในรูปเป็นตัวอย่าง กฎจริงดูใน `spa/SPEC.md`)

### 4) ความต้องการ 3 แบบ: FR / BR / NFR

![ความต้องการ 3 แบบ FR ทำอะไรได้ จองคิว, BR กฎร้าน ห้ามจองซ้อน คุณจันทร์ถือสมุดกฎร้าน, NFR ดีแค่ไหน โหลดไม่เกิน 3 วินาที](img/concept-04-fr-br-nfr.jpg)

**FR** (Functional) เว็บทำอะไรได้ · **BR** (Business Rule) กฎร้าน มีตัวเลข · **NFR** (Non-Functional) ต้องดีแค่ไหน วัดได้

### 5) ทำอะไรก่อน? Must / Should / Could

![ตะกร้า 3 ใบ Must ต้องมี สีแดงใบใหญ่ Should ควรมี สีเหลือง Could มีก็ดี สีเขียว หุ่นยนต์ใส่การ์ดปฏิทินนัดหมายลงตะกร้า Must ก่อน](img/concept-05-must-should.jpg)

ฟีเจอร์เยอะ เวลาน้อย → ทำ **Must** ให้ครบก่อน

### 6) พรอมต์ที่เขียนพรอมต์

![4 ขั้น 1 สั่งช่วยเขียนพรอมต์ 2 หุ่นยนต์ได้ BUILD-PROMPT.md 3 เด็กอ่านแล้ว Copy 4 วางในหน้าต่างใหม่ได้เว็บ](img/concept-06-meta-prompt.jpg)

ให้ Claude เขียน **BUILD-PROMPT.md** ก่อน → เรา **อ่านตรวจได้** และ **ใช้ซ้ำได้** ทุกเมื่อ

### 7) BUILD-PROMPT ต้องมี

![ม้วนกระดาษเช็กลิสต์ 5 ช่อง 1 Next.js + PostgreSQL 2 รูปจาก assets 3 ป้าย data-testid 4 ปุ่มรีเซ็ตข้อมูล 5 โหมดฝังบั๊ก เด็กถือดินสอติ๊ก](img/concept-07-build-prompt-checklist.jpg)

ครบ 5 ช่องนี้ → เว็บที่ได้ **สวยด้วยรูปของเรา และทดสอบได้**

### 8) เว็บ 2 กล่อง

![เว็บ 2 กล่องบนหลังวาฬ Docker กล่อง 1 web หน้าร้าน กล่อง 2 db สมุดบัญชี มีช้างสีฟ้า ลูกศร จอง → บันทึก เด็กเปิด localhost:3000](img/concept-08-two-containers.jpg)

**web** = หน้าร้าน (Next.js พอร์ต 3000) · **db** = สมุดบัญชี (PostgreSQL) เก็บการจอง สมาชิก แต้ม

### 8.1) ระบบทั้งหมดหน้าตาแบบนี้ (System Architecture)

![ระบบของเว็บสปา 1 คอมพิวเตอร์ของเรา Windows มีเบราว์เซอร์เปิดหน้าสบายใจ สปา และ Playwright หุ่นยนต์ทดสอบ ลูกศร localhost:3000 ไปที่วาฬ docker compose ที่แบกกล่อง 2 web Next.js มีหน้าเว็บและ API กับกล่อง 3 db PostgreSQL 16 ลูกศรอ่าน-เขียนข้อมูล ถังข้อมูลไม่หาย และป้าย 4 AI = กฎตายตัว ไม่สุ่ม](img/concept-29-architecture.jpg)

| ① คอมของเรา | ② กล่อง web | ③ กล่อง db | ④ "AI" |
|---|---|---|---|
| เบราว์เซอร์ + Playwright เปิด `localhost:3000` | Next.js: หน้าเว็บ + API | PostgreSQL 16 เก็บข้อมูลถาวร (ปิดแล้วข้อมูลไม่หาย) | กฎตายตัว ไม่สุ่ม ไม่ต้องใช้ API key |

### 9) "AI" ในเว็บนี้ = กฎตายตัว

![AI ในเว็บนี้ = กฎตายตัว เด็กถาม เหนื่อย ทำอะไรดี 2 ครั้ง ได้การ์ด เหนื่อย → นวดไทย เหมือนกันทั้ง 2 ใบ น้องบัวใส่หมวกนักมายากลแอบเปิดสมุดกฎ ถ้า…แล้ว… หุ่นยนต์บอกว่า จึงทดสอบได้](img/intro-04-fake-ai.jpg)

ไม่เรียก AI จริง ใช้ **"ถ้า… แล้ว…"** → ถามเหมือนเดิมได้คำตอบเดิม จึง **ทดสอบได้** และไม่ต้องใช้ API key
