## 1 · อาการ

ตะกร้ายอดสินค้า **฿999 พอดี** ส่งแบบธรรมดา ไม่ใช้ FREESHIP:
ตะกร้าขึ้น "ได้ส่งฟรีแล้ว!" ค่าส่ง "ฟรี" · ปุ่ม "ยืนยันสั่งซื้อ ฿999" → แต่ server บันทึกค่าส่ง ฿50 ยอด **฿1,049** และหน้าคำสั่งซื้อ + ประวัติใน /account แสดง ฿1,049
ใช้ PAW10 ที่ ฿999 ก็เป็นเหมือนกัน (ปุ่ม ฿900 → คำสั่งซื้อ ฿950) · ยอดอื่น (฿998 · ฿1,000) และ FREESHIP/ส่งด่วน ถูกต้อง

## 4 · ต้นเหตุ (white-box · เปิดโค้ดหลังขั้นที่ 2)

`petshop/lib/orders.ts:62-67` (ใน `createOrder` · เรียกจาก `app/api/orders/route.ts:24` POST /api/orders)

```ts
62  const totals = computeTotals({ lines, couponCode, shipping });
63  // PP-231: server must not trust the shipping fee shown in the browser — recompute it here.
64  if (shipping === "standard" && !totals.coupon?.freeShipping) {
65    totals.shipping = totals.subtotal > FREE_SHIPPING_MIN ? 0 : STANDARD_SHIPPING;
66    totals.total = Math.max(0, totals.subtotal - totals.discount + totals.shipping);
67  }
```

กฎจริงอยู่ที่ `petshop/lib/pricing.ts:130-133` `shippingCost()` → `subtotal >= FREE_SHIPPING_MIN ? 0 : STANDARD_SHIPPING` (`FREE_SHIPPING_MIN = 999` ที่ `pricing.ts:39`)

ทำไมหน้าเว็บกับคำสั่งซื้อคิดไม่เท่ากัน:
- หน้าเว็บ (ตะกร้า `CartView` + ปุ่ม `OrderSummary.tsx:11` → `computeTotals`) และ server บรรทัด 62 ใช้ `computeTotals` → `shippingCost` ตัวเดียวกัน (`>=`) → ฿999 ได้ค่าส่ง 0
- แต่ server บรรทัด 64-67 **เขียนกฎค่าส่งซ้ำ** ด้วย `>` (ไม่ใช่ `>=`) แล้ว**เขียนทับ** `totals.shipping` และ `totals.total` → ฿999 > 999 เป็นเท็จ → ค่าส่ง 50 → ยอด 1049
- ราคาทุกตัวเป็นจำนวนเต็มบาท จึงต่างกันเฉพาะ subtotal = 999 พอดี · บล็อกถูกข้ามเมื่อส่งด่วนหรือ FREESHIP จึงถูก (ตรงกับตาราง 3)

คอมเมนต์ PP-231 พูดจริงไหม → **ไม่จริง** ตรวจจาก HAR (`node rea\scratch\bug01-har.mjs out\bug01.har`): POST /api/orders ทั้ง 7 ครั้งส่ง body แค่ `items[{slug,size,qty}] · coupon · shipping:"standard"|"express" · payment:"cod" · address` — **ไม่มีค่าส่ง ไม่มีราคา ไม่มียอดรวม** ส่งไปเลย
server คำนวณเองทั้งหมดอยู่แล้วที่บรรทัด 62 (ราคาจาก `priceLines` ฝั่ง server) บล็อก PP-231 จึง "คำนวณซ้ำ" สิ่งที่ไม่เคยได้มาจาก browser และคำนวณผิดกฎ

## ยังไม่รู้ (ต้องถามเจ้าของร้าน/ทีมเดิม · ไม่เดา)

1. ตั๋ว **PP-231** คืออะไร ตั้งใจกันปัญหาอะไร — โค้ดตอนนี้ไม่รับค่าส่งจาก browser อยู่แล้ว (HAR) แต่อาจมีเหตุอื่นที่ไม่เห็นจากเครื่องทดสอบ

4. ระบบจริงของร้านรันโค้ดรุ่นเดียวกับเครื่องทดสอบหรือไม่ และมีลูกค้าคนอื่นที่ยอด ฿999 พอดีโดนเก็บเกินอีกกี่ราย (ต้องดูข้อมูลระบบจริง — ไม่มีในเครื่องเรา)
