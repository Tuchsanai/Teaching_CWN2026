## ข้อสังเกต 👀
- ข้อ "API ส่ง giftWrap ผิดชนิด" มี 2 แบบที่ต่างกันมาก: ตรวจแค่ยอด (เขียวทันที = guard) กับตรวจ field (แดง) — แยกเป็น 2 TC ทำให้เห็นชัดว่า guard ไม่ได้พิสูจน์ฟีเจอร์
- ยอดที่ server คืนตอนแดง (239/428/221/539) ใช้เช็กได้ว่าตะกร้าและยอดฐานถูก → ข้อแดง "แดงเพราะยังไม่มีฟีเจอร์" จริง ไม่ใช่ test เขียนผิด
- golden `coupons-validate.json` (LAB 4) คือกับดักที่ซ่อนอยู่: ถ้าใส่ค่าห่อใน `evaluateCoupon` แทน `computeTotals` char-money จะแดง — ใส่ไว้ใน impact แล้ว
- UI test 9 ข้อแดงข้อละ ~10 วิ เพราะ `expect(...).not.toBeChecked()` ใช้ expect timeout 8 วิ จาก config (actionTimeout 5 วิ ไม่ครอบ expect) — รวมยังแค่ 32 วิ เพราะ workers 4
- `Invoke-RestMethod` ใน PS 5.1 ถอดชื่อไทยเป็น mojibake (ไม่มี charset) — ราคา/slug ยังใช้ได้ แต่ถ้าผู้เรียนจะยกชื่อสินค้าจาก API ต้องใช้ node/`curl.exe` แทน

## ข้อเสนอแก้พรอมต์
- (M) ข้อ 3 "API ส่ง giftWrap ผิดชนิด" + 🎯 "อาจเขียวตั้งแต่ตอนนี้" — ผลขึ้นกับว่า test ตรวจ field ด้วยไหม · เสนอเขียนในพรอมต์ว่า "ตรวจทั้งยอดและ field giftWrap/giftWrapFee" หรือให้แยก guard กับข้อพิสูจน์ฟีเจอร์
