### 2.1 การเขียนพรอมต์ใน 💬

- **บรรทัดแรก = คำสั่งหลัก + ไฟล์ input + ไฟล์ output** เช่น `อ่าน USER-STORIES.md แล้วเขียน REQUIREMENTS.md เป็น 3 ตาราง`
- **ข้อห้ามอยู่บรรทัด 1–2 ในวงเล็บ** เช่น `(ห้ามเปิดอ่านโค้ดใน web/ และ db/ · ห้ามเปิด web/BUGS.md และ _solution/)` · ทุกพรอมต์ที่ใช้ black-box ต้องย้ำซ้ำ เพราะผู้เรียนเปิดเซสชันใหม่ทุก LAB
- **แบ่งเป็นข้อมีเลข** `1. 2. 3.` (บางครั้ง `ขั้นที่ 1` หรือ `0. เช็กก่อน`) · ข้อย่อยใช้ `   - ` เยื้อง 3 ช่อง · ข้อละ 1–2 บรรทัด
- **ระบุโครงตารางด้วย `|`** เช่น `ตาราง: รหัส | เรื่อง | ใครขอ | ความสำคัญ` · คอลัมน์ "ที่มา" / "มาจาก US ไหน" / "ตรงไหม ✅ / ⚠️ / ❌"
- **ไม่แน่ใจให้หยุด/ถาม** ต้องมีทุกพรอมต์ที่มีการตัดสินใจ: `ถ้าไม่แน่ใจให้เขียนไว้ในหัวข้อ "ยังไม่รู้" อย่าเดา` · `ไม่แน่ใจเรื่องไหนให้ถามผมก่อน` · `ถ้าขั้นไหนไม่ผ่านให้หยุดแล้วบอกสาเหตุ` · `ค่าที่ร้านยังไม่ได้บอกชัด … ให้ติด ⚠️ และเขียนสมมติฐานที่ใช้ ห้ามเดาเงียบ ๆ`
- **ทุกค่าต้องมาจากของจริง** `ทุกค่าต้องมาจากคำสั่งที่รันจริง` · `ตัวเลขเงินคำนวณเองพร้อมวิธีคิด` · `ห้ามแก้ผลที่คาดหวังตามเว็บ ให้ทำ ⚠️ แล้วบอกว่า…`
- **บรรทัดสุดท้าย = ขอสรุปเป็นตาราง** `สรุปเป็นตาราง: ส่วน | จำนวน | ✅ | ⚠️ | ❌`
- **ห้ามอ้าง "LAB x" / "แบบบท 02"** ในพรอมต์ (เซสชันใหม่ไม่รู้จัก · REVIEW-V3 บท 03 จับได้) → อธิบายสิ่งที่ต้องทำตรง ๆ หรืออ้างชื่อไฟล์
- พรอมต์ที่มีผลข้างเคียง (ลบ, stop container) ต้องมี "บอกผมก่อน" / "ถามผมก่อนลบ"
- คำสั่ง shell ในพรอมต์เป็น **PowerShell** (`$env:BUG_MODE=1; docker compose up -d`) ไม่ใช้ bash
- **ความยาว:** ปกติ 5–15 บรรทัด (LAB 0 = 8 · LAB 2 = 9 · LAB 7–11 = 15–22) · พรอมต์สร้างระบบใหญ่ (LAB 5 บท 04) ได้ถึง ~35 บรรทัด · ถ้าเกิน 25 บรรทัดให้พิจารณาแยกเป็น "ส่วนที่ 1 / ส่วนที่ 2" (แบบ LAB 12 บท 04 มี 💬 2 กล่อง)
- input ข้อมูลยาว (เช่นบันทึกสัมภาษณ์) ฝังท้ายพรอมต์หลังบรรทัด `--- บันทึกสัมภาษณ์ ---` และตัวละครขึ้นต้นด้วย emoji (👩‍💼 😩 🧳 💑 🏃‍♀️ ✨)
- LAB ที่ไม่มีพรอมต์ใหม่ เขียน `💬 **LAB นี้ไม่มีพรอมต์ใหม่** พรอมต์คือไฟล์ ...` แล้วให้ตารางขั้น ①②③④

### 2.2 การเขียน ✅ ผลจริง

- บรรทัดเปิด: `✅ **ผลจริง** ได้ \`FILE.md\` · **36 story** (Must 19 · Should 11 · Could 6) · …` หรือ `✅ **ผลจริง: พร้อม 9/9 รายการ**` · บท 03 ใช้ `✅ **ผลจริง (ตัวอย่าง)** ใช้เวลาราว 12 นาที …`
- **ทุก LAB ต้องบอกเวลา** (บท 03 REVIEW-V1 F1 จับ LAB ที่ไม่มีเวลา) · LAB ยาวแจกแจง: `ใช้เวลา ~76 นาที (เขียน test 42 ข้อใน 12 ไฟล์ + รันเต็มรอบละ ~13 นาที × 3 รอบ + รอบ GIF ~6 นาที)`
- **วันที่รันระบุครั้งเดียว** ในย่อหน้า "แต่ละ LAB มี … ✅ ผลจริง (จากการรันจริง 10 ต.ค. 2026)" และใน `_solution/README.md` · ไม่ต้องใส่วันที่ทุก LAB (เวลาเริ่ม/จบละเอียดอยู่ใน `LABn_RESULT.md`)
- ตารางผลมี **ตัวอย่างจริงพร้อมรหัส** (US-14, BR-20, TC-PRICE-04, E87) ไม่ใช่ตัวอย่างสมมติ · ค่าเด่นทำตัวหนา
- ตัวเลขทุกตัวต้องหาเจอใน `_solution/_design/results/LABn_RESULT.md` หรือไฟล์ผลจริง (ผู้รีวิวไล่เทียบทีละตัว)
- ภาพผล: ตารางเดี่ยว = `![…](img/labN-<slug>.png)` ใต้ตาราง · หลายภาพ = **ตาราง markdown 2–3 คอลัมน์** หัวคอลัมน์เป็น emoji + คำบรรยายตัวหนา เช่น `| ❌ กดยืนยัน 2 ครั้ง = 2 นัด | ❌ รหัสบัตรผิด หน้าจอไม่บอกอะไร |` แล้วแถวถัดไปเป็นรูป
- GIF ใส่หัวเรื่องตัวหนาก่อน: `**🎬 TC-BOOK-01 จองคิวจนจบ (E2E)** (วงแดง = จุดที่ Playwright คลิก · ป้ายมุมซ้ายล่าง = ชื่อ test)`
- ภาพแผนภาพจากเอกสารจริง ใส่ป้ายตัวหนา `**System Architecture** (จาก \`DESIGN.md\` จริง)`
- ลิงก์ไฟล์เต็ม: `ดูไฟล์เต็มที่ [_solution/EXPLORATION.md](_solution/EXPLORATION.md)` (บท 03)

### 2.3 👀 สังเกต และ ✔️ ไปต่อได้เมื่อ

- 👀 = **บทเรียนที่ได้จากการรันจริง** (กับดัก ความผิดพลาดของ AI จุดที่สับสนบ่อย) ไม่ใช่สรุปผลซ้ำ · ขึ้นต้น bullet ด้วยตัวหนา เช่น `- **ไม่ตรง ≠ แก้ผลที่คาดหวังตามเว็บ** ทั้ง 4 ข้อคง ⚠️ ไว้…` · ใช้ ⚠️ นำหน้าเรื่องอันตราย
- ✔️ = เงื่อนไขที่ผู้เรียนตรวจเองได้ใน 10 วินาที: ไฟล์มี/ส่วนครบ/ตัวเลขไม่มี ❌/container healthy

## 3. น้ำเสียงและภาษา

| เรื่อง | กฎ | ตัวอย่างจริง |
|---|---|---|
| ประโยค | สั้น 1 ความคิดต่อประโยค ~10–25 คำ · ตัดคำเชื่อมฟุ่มเฟือย · ใช้ `·` คั่นวลีแทน "และ/รวมถึง" | "ทุกรอบเริ่มจากข้อมูลชุดเดียวกัน" |
| บุรุษ | ผู้เรียน = "เรา" · ในพรอมต์ผู้เรียนพูดกับ Claude ว่า "ผม" ("ให้ผมดู", "บอกผมก่อน") · ไม่ใช้ "ท่าน/คุณผู้เรียน" | "หน้าที่ของเราคือ…" |
| ศัพท์อังกฤษ | คงศัพท์เทคนิคเป็นอังกฤษ ไม่แปลง/ไม่ทับศัพท์: test case, User Story, Playwright, container, healthy, seed, reset, oracle, flaky, coverage matrix · ชื่อไฟล์/คำสั่ง/testid อยู่ใน `code` · ครั้งแรกที่ใช้คำใหม่ ให้มีความหมายไทยในวงเล็บหรือในตารางคำศัพท์ | "อย่าอบบั๊กลงในผลที่คาดหวัง (baking the bug in)" |
| คำไทยประจำคอร์ส | ผลที่คาดหวัง · ผลจริง · ค่าขอบ · กฎร้าน · ที่มา · อบบั๊ก · บั๊กปริศนา · โหมดฝังบั๊ก · สำรวจ · ล่ากฎ · พิสูจน์แผน · เว็บผิด / แผนผิด / test เขียนผิด | |

- ย่อหน้าแรก: "งานเดียวกับ [บทเรียนหลัก](../README.md) ทั้ง LAB 0–12 แต่วางพรอมต์ **ครั้งเดียว** แล้ว Claude ทำต่อกันเองจนจบ (ราว 4–5 ชั่วโมง)" + รูป `ft-01-one-prompt.jpg`
- หัวข้อตามลำดับ: `## 🧭 พรอมต์ทำอะไรบ้าง` (ขั้นที่ N = LAB N · อ่านไฟล์ก่อนทำขั้นถัดไป · สะดุดให้วางพรอมต์เดิมซ้ำ + `ft-02-steps.png`) → (ถ้ามีจุดพิเศษ) `## 🤖 จุดที่ต่างจากบทเรียนหลัก: …` → `## 🏷️ หัวใจที่พรอมต์บังคับไว้` → `## 🔀 เลือกพรอมต์ 1 จาก 2 แบบ` → `## 🚀 วิธีใช้` (4 ข้อ) → `## ✅ จบแล้วตรวจอะไร` (5 ข้อ + ตาราง "ขั้น | บทเรียนหลักได้") → `## 🆘 ถ้าสะดุด` → `---` → `## 🅰️ พรอมต์แบบบอกใบ้ (ตามบทเรียนหลัก)` → `## 🅱️ พรอมต์แบบไม่บอกใบ้ (black-box จริง)`
- **ตาราง 🅰️ vs 🅱️** แถว: เหมือน · Claude รู้ · ผลที่น่าจะได้ · ใช้กับงานอื่น · เหมาะกับ · ตามด้วย `> 💡 สอนในห้อง: รัน 🅰️ เป็นตัวอย่างก่อน แล้วลอง 🅱️ แล้วเทียบผล …` และ `<details><summary>ดูว่าพรอมต์สองแบบต่างกันตรงไหนบ้าง (ทีละขั้น)</summary>` ตาราง จุด | 🅰️ | 🅱️ + บรรทัด "**เหมือนกันทุกตัวอักษร:** …"
- **โครงพรอมต์เดียว:** บรรทัดเปิด (input คืออะไร · "ช่วยทำ N ขั้นข้างล่างต่อกันจนจบโดยไม่ต้องรอผม") → `กติกาตลอดงาน` ข้อ 1–7 (ภาษาไทย ตาราง · อ่านไฟล์ขั้นก่อนจากดิสก์ · ทำต่อจากขั้นแรกที่ยังไม่เสร็จ (resume) · ห้ามเปิด README ของบท/fast_track/_solution · ป้าย oracle · คำนวณเองห้ามลอก · ตัดสินแทนผู้เรียนแล้วจดใต้ "ตัดสินแทนผู้เรียน" · ติดจนไปต่อไม่ได้ให้หยุดบอก) → `ขั้นที่ 0 …` ถึง `ขั้นที่ N …` (ขั้นละ 1 ย่อหน้ายาว ข้อย่อย ①②③) → สรุปท้ายเป็นตาราง + ⚠️ + "เรื่องที่ตัดสินแทนผม"
- **🅰️ บอกใบ้** ใส่ตัวเลขตัวอย่าง ค่าขอบ กับดัก และสิ่งที่รอบจริงเจอ (จาก ✅ และ 👀) · ประโยคเปิดมี "ตัวอย่างและเบาะแสในพรอมต์มาจากรอบที่เคยทำจริง … อาจต่างกัน"
- **🅱️ ไม่บอกใบ้** เพิ่มกติกาข้อ `0.` "ให้ทำเหมือนไม่เคยเห็นงานนี้มาก่อน ทุกอย่างที่เขียนลงไฟล์ต้องมาจาก 3 แหล่งเท่านั้น … ห้ามใช้ความรู้เดิมเกี่ยวกับบทเรียนนี้ ห้ามเดาว่าเว็บน่าจะพังตรงไหน เจอแล้วค่อยจด" · ไม่มีชื่อหน้า/ตัวเลข/บั๊กที่รอบจริงเจอ · ใช้กับงานอื่นได้
- พรอมต์ fast_track ยาว 100–130 บรรทัด (บท 04 🅰️ = 128 บรรทัดรวมบันทึกสัมภาษณ์) · ทั้งสองแบบต้องได้ไฟล์ชุดเดียวกัน หัวข้อในไฟล์เหมือนกัน

## 7. เช็กลิสต์ "ต้องตรงสไตล์" (ผู้เขียนและผู้รีวิวใช้)

**โครง**
- ☐ 1. หัวข้อ `##` ครบและเรียงตามข้อ 1 (🧭 → 📦 → 🎓 → 🧰 → 🗺️ → LAB → ✅ รูบริก → 🔁 → ถ้าเจอปัญหา → 🎉 → 📖 → ### ไฟล์ในบทนี้)
- ☐ 2. ชื่อบทลงท้าย `(Copy & Paste)` และย่อหน้าแรกมี "คัดลอกพรอมต์ → วางใน Claude Code → อ่านผล → ตัดสินใจ"
- ☐ 3. มีประโยคหลักของบท 1 ประโยคตัวหนาในเครื่องหมายคำพูด และซ้ำในแถบล่างของไดอะแกรมภาพรวม
- ☐ 4. ตาราง "ต่างจากบทก่อน" มีคอลัมน์บทก่อนหน้าทุกบทที่เกี่ยวข้อง และคอลัมน์บทนี้ตัวหนา
- ☐ 5. หัว LAB รูปแบบ `## LAB n · <ชื่อ>` (จุดกลาง `·`) และคั่นด้วย `---`
- ☐ 6. ทุก LAB มี 🎯 · 💬 **คัดลอกพรอมต์นี้** · ✅ **ผลจริง** · 👀 **สังเกต** · ✔️ **ไปต่อได้เมื่อ:** ตามลำดับนี้
- ☐ 7. ตารางเส้นทางมีคอลัมน์ ⏱️ รอบจริง และลิงก์ anchor ไป LAB ทุกตัวใช้ได้
- ☐ 8. รูบริก 20 ข้อ 5 หมวด และเกณฑ์ ≥ 18 / 14–17 / < 14

**พรอมต์**
- ☐ 9. พรอมต์อยู่ในบล็อก ```` ```text ```` เท่านั้น · แบ่งข้อมีเลข · บรรทัดท้ายขอ "สรุปเป็นตาราง: …" พร้อมหัวคอลัมน์
- ☐ 10. ทุกพรอมต์ที่ต้องตัดสินใจมี "ไม่แน่ใจให้หยุด/ถามผมก่อน/เขียนใน ยังไม่รู้ อย่าเดา"
- ☐ 11. ทุกพรอมต์ใช้ได้ในเซสชันใหม่: ไม่อ้าง "LAB x" "แบบบทก่อน" · อ้างชื่อไฟล์แทน · ข้อห้าม (โค้ด/BUGS/_solution) ซ้ำในทุกพรอมต์ที่เกี่ยว
- ☐ 12. พรอมต์ห้ามแก้ผลที่คาดหวัง/test ให้ผ่าน และให้จำแนก เว็บผิด / แผนผิด / test เขียนผิด
- ☐ 13. คำสั่ง shell เป็น PowerShell · ใช้ได้บน Windows · คำสั่งลบหรือ stop มี "บอกผมก่อน"
- ☐ 14. พรอมต์ในบท = พรอมต์ใน `_design/PROMPTS.md` ฉบับที่รันจริง (หรือมีบันทึกความต่างใน `_solution` §7)

**ผลจริงและตัวเลข**
- ☐ 15. ตัวเลขทุกตัวใน ✅ หาเจอใน `LABn_RESULT.md` หรือไฟล์ผลใน `_solution/` · ไม่มีตัวเลขแต่ง · รันไม่ได้ให้เขียนว่ารันไม่ได้เพราะอะไร
- ☐ 16. ทุก LAB บอกเวลาที่ใช้ (`~N นาที`) และวันที่รันจริงระบุในย่อหน้า 🧰 กับ `_solution/README.md`
- ☐ 17. ตัวอย่างในตารางผลใช้รหัสจริง (US-/BR-/TC-/E..) และเงินแสดงวิธีคิดด้วย `−` `×` `=`
