# Requirements · SiteSafe Inspect

**ที่มา:** `docs/USER-STORIES.md` (US-01 ถึง US-20 · จุดขัดกัน C-01 ถึง C-04 · คำถาม Q-01 ถึง Q-14)
**สถานะ:** ร่างรุ่นแรก ค่าที่มาจาก "ข้อสมมติ" (AS-xx) ต้องให้ลูกค้ายืนยันก่อนถือเป็นข้อตกลง
**ขอบเขตเอกสาร:** ความต้องการเท่านั้น ยังไม่มีการออกแบบระบบและยังไม่มีโค้ด

## คำที่ใช้ในเอกสาร

| คำ | ความหมาย |
|---|---|
| ผลของรูป | หนึ่งในสามค่า: "ผ่าน" · "เตือน" · "ไม่ผ่าน" |
| H | จำนวนคนไม่ใส่หมวกที่ตรวจพบในรูปหนึ่งรูป |
| V | จำนวนคนไม่ใส่เสื้อสะท้อนแสงที่ตรวจพบในรูปหนึ่งรูป |
| ผลล่าสุด | ผลที่คนแก้แล้ว (ถ้ามีการแก้) หรือผลของโมเดล (ถ้าไม่มีการแก้) |
| รูปที่ระบบรับแล้ว | รูปที่ระบบตอบกลับผู้อัปโหลดว่ารับสำเร็จ |
| เวลารอผล | เวลาตั้งแต่ระบบตอบว่ารับรูปแล้ว จนผลของรูปนั้นพร้อมให้เปิดดู |
| Test Set | ชุดรูปทดสอบที่ไม่ถูกใช้ทั้งในการเทรนและการเลือกค่า Threshold ของโมเดล |

## 2. Business Rule (BR)

ลำดับการตัดสินผลของรูป: ใช้ BR-01 ก่อน ถ้าไม่เข้าจึงใช้ BR-02 แล้ว BR-03 ถ้าไม่เข้าข้อใดเลย (H = 0 และ V = 0) ผลคือ "ผ่าน"

| รหัส | กติกา (ตัวเลขที่ตรวจได้) | ต่ำกว่าเส้นแบ่ง | เท่ากับเส้นแบ่ง | สูงกว่าเส้นแบ่ง | อ้าง |
|---|---|---|---|---|---|
| BR-01 | H ≥ 1 → "ไม่ผ่าน" (เส้นแบ่ง H = 1) | H = 0 → ไม่เข้ากติกานี้ ไปดู BR-02 | H = 1 → ไม่ผ่าน | H = 2 → ไม่ผ่าน | US-03 |
| BR-02 | H = 0 และ V ≥ 2 → "ไม่ผ่าน" (เส้นแบ่ง V = 2, AS-03) | V = 1 → ไม่เข้ากติกานี้ ไปดู BR-03 | V = 2 → ไม่ผ่าน | V = 3 → ไม่ผ่าน | US-03, C-03 |
| BR-03 | H = 0 และ V = 1 → "เตือน" (เส้นแบ่ง V = 1) | V = 0 → ผ่าน | V = 1 → เตือน | V = 2 → ไม่ผ่าน (ตาม BR-02) | US-03 |
| BR-04 | อัตราผ่าน = จำนวนรูปที่ผลล่าสุดเป็น "ผ่าน" ÷ จำนวนรูปที่มีผลของวันและไซต์นั้น × 100 (รูป "เตือน" ไม่นับเป็นผ่าน, AS-05) ไซต์ที่อัตราผ่าน < 90% แสดงสีแดง เทียบจากค่าก่อนปัดเศษ วันที่ไม่มีรูปแสดง "ไม่มีข้อมูล" ไม่เป็นสีแดง | 269 ÷ 300 = 89.67% → สีแดง | 270 ÷ 300 = 90.00% → ไม่แดง | 271 ÷ 300 = 90.33% → ไม่แดง | US-13 |
| BR-05 | ขนาดไฟล์ต่อรูป ≤ 15 MB รับ · > 15 MB ปฏิเสธ (AS-06) | 14.9 MB → รับ | 15.0 MB → รับ | 15.1 MB → ปฏิเสธ | US-08 |
| BR-06 | จำนวนรูปต่อการอัปโหลดหนึ่งครั้ง ≤ 50 รูป รับ · > 50 รูป ปฏิเสธทั้งครั้งก่อนรับรูปใด พร้อมข้อความให้แบ่งส่ง (AS-06) | 49 รูป → รับ | 50 รูป → รับ | 51 รูป → ปฏิเสธ | US-06 |
| BR-07 | รายงานของวันนั้นครบทุกไซต์ต้องเปิดดูได้ตั้งแต่ 18:00 น. ของทุกวัน (AS-07) รูปที่เข้าหลัง 18:00 น. ยังนับในรายงานของวันเดียวกัน | 17:59 น. → ยังไม่บังคับว่าต้องพร้อม | 18:00 น. → ต้องเปิดดูได้ | 18:01 น. → ต้องเปิดดูได้ | US-14 |

## 3. Non-functional Requirement (NFR)

### NFR-01 · เกณฑ์ของโมเดล (US-04, C-04)

**การแปลงคำพูดของลูกค้า:** "10 รูปที่มีคนไม่ใส่หมวก ต้องจับได้ 8 รูป" นับที่ระดับ "รูป" ไม่ใช่ระดับกรอบ จึงแปลงเป็น **Image-level Recall ของคลาส "ไม่ใส่หมวก" บน Test Set ≥ 0.80**

| รายการ | นิยาม |
|---|---|
| รูป Positive | รูปใน Test Set ที่เฉลย (Ground Truth) มีคนไม่ใส่หมวกอย่างน้อย 1 คน |
| True Positive (TP) | รูป Positive ที่ระบบให้ H ≥ 1 (ผล "ไม่ผ่าน" ตาม BR-01) |
| False Negative (FN) | รูป Positive ที่ระบบให้ H = 0 |
| False Positive (FP) | รูปที่เฉลยไม่มีคนไม่ใส่หมวก แต่ระบบให้ H ≥ 1 |
| Recall | TP ÷ (TP + FN) |
| Precision | TP ÷ (TP + FP) |

| ตัวชี้วัด | เกณฑ์ | ที่มา |
|---|---|---|
| Image-level Recall คลาส "ไม่ใส่หมวก" | ≥ 0.80 (เกณฑ์ขั้นต่ำ ไม่ใช่เป้าหมาย) | คำพูดของลูกค้า |
| Image-level Precision คลาส "ไม่ใส่หมวก" | ≥ 0.80 | ข้อสมมติ AS-04 จากคำว่า "ถ้าบอกผิดบ่อยผมก็ต้องกลับมาดูเองทุกรูป" |
| Image-level Recall และ Precision คลาส "ไม่ใส่เสื้อสะท้อนแสง" | รายงานค่า ยังไม่เป็นเกณฑ์ผ่าน | ลูกค้ายังไม่ได้ให้ตัวเลข (Q-09) |

เงื่อนไขการวัด
- Test Set มีรูป Positive อย่างน้อย 100 รูป และรูปที่ไม่มีคนไม่ใส่หมวกอย่างน้อย 100 รูป (AS-14)
- ค่า Confidence Threshold เลือกบน Validation Set และกำหนดให้คงที่ก่อนวัดบน Test Set โดยเลือกค่าที่ให้ Recall สูงที่สุดในขณะที่ Precision ยังไม่ต่ำกว่า 0.80
- ตัวอย่างการตัดสินเมื่อมีรูป Positive 100 รูป: จับได้ 79 รูป (0.79) → ไม่ผ่านเกณฑ์ · 80 รูป (0.80) → ผ่าน · 81 รูป (0.81) → ผ่าน

### NFR-02 · SLO ของเวลารอผล (US-05, US-07, C-01, C-02)

เวลารอผลนับจากระบบตอบว่ารับรูปแล้ว จนผลของรูปนั้นพร้อมให้เปิดดู (รวมเวลารอคิว)

| สภาวะ | SLO | ที่มา |
|---|---|---|
| ภาระปกติ: ไซต์เดียวส่งหนึ่งครั้ง ไม่เกิน 50 รูป | p95 ของเวลารอผล ≤ 30 วินาที | คุณวิชัย "ไม่เกินครึ่งนาทีต่อรูป" (AS-01) |
| ช่วงเร่งด่วน: 3 ไซต์ส่งพร้อมกัน ไซต์ละ 50 รูป (150 รูป) | p95 ของเวลารอผล ≤ 300 วินาที และทุกรูปมีผลภายใน 600 วินาที | คุณนภา "สัก 5 นาทีก็ได้" · คุณธนา "ช้าหน่อยได้" (AS-02) |

วัดบนเครื่องที่มี GPU 1 ใบ (NFR-08) ถ้าการทดสอบช่วงเร่งด่วนให้ p95 เกิน 30 วินาที ต้องรายงานตัวเลขจริงให้ลูกค้าทราบพร้อมทางเลือกเพิ่ม GPU

### NFR-03 · ความจุเมื่อรูปเข้าพร้อมกัน 3 ไซต์ (US-10)

- ภาระทดสอบ: 3 ไซต์อัปโหลดพร้อมกัน ไซต์ละ 50 รูป รวม 150 รูป ขนาดรูปละ 8–10 MB
- ตลอดการทดสอบ คำขอที่ระบบตอบผิดพลาด (ระบบล่มหรือไม่ตอบ) < 1% ของคำขอทั้งหมด
- ตลอดการทดสอบ หน้ารายการสถานะเปิดได้ภายใน 3 วินาที (p95)
- เมื่อจบการทดสอบ รูปที่มีผล = รูปที่ระบบรับแล้ว = 150 รูป และเวลารอผลเป็นไปตาม NFR-02 แถวช่วงเร่งด่วน

### NFR-04 · รูปห้ามหาย (US-07, US-10)

- จำนวนรูปที่ระบบรับแล้ว = จำนวนรูปที่อยู่ในสถานะ "เสร็จแล้ว" + "ตรวจไม่สำเร็จ" + "รอคิว" + "กำลังตรวจ" เสมอ รูปที่หายต้องเท่ากับ 0
- ทุกรูปที่ระบบรับแล้วต้องจบที่ "เสร็จแล้ว" หรือ "ตรวจไม่สำเร็จ" (พร้อมเหตุผล) ไม่มีรูปค้างอยู่ในสถานะอื่นเกิน 15 นาที
- เมื่อส่วนที่ตรวจรูปหยุดทำงานกลางคัน (ทดสอบโดยหยุดส่วนนั้นขณะมีรูปรอคิว 50 รูปขึ้นไป) หลังกลับมาทำงาน ทุกรูปต้องได้ผลครบ และแต่ละรูปมีผลของโมเดลเพียง 1 ชุด ไม่ซ้ำ
- รูปต้นฉบับถูกเก็บถาวรก่อนที่ระบบจะตอบผู้อัปโหลดว่ารับแล้ว

### NFR-05 · ความเป็นส่วนตัวของรูป (US-19, US-17)

- เปิดลิงก์รูปโดยไม่ล็อกอิน: ได้รูป 0 ครั้งจากการทดสอบทุกลิงก์ตัวอย่าง
- หัวหน้างานไซต์ ก เปิดรูปหรือผลของไซต์อื่นทางลิงก์โดยตรง: สำเร็จ 0 ครั้ง
- เรียก API โดยไม่มี key หรือ key ผิด: ถูกปฏิเสธ 100% ของการเรียก
- รูปและผลส่งผ่านการเชื่อมต่อที่เข้ารหัส (HTTPS) เท่านั้น
- API key ไม่ปรากฏในซอร์สโค้ด ในหน้าเว็บ และในบันทึกการทำงาน (log)
- รูปไม่ถูกส่งไปยังบริการภายนอกที่ไม่ใช่เครื่องของโครงการนี้
- รุ่นแรกไม่ลบรูปและผลตรวจโดยอัตโนมัติจนกว่าลูกค้าจะกำหนดระยะเวลาเก็บ (AS-12)

### NFR-06 · การยืนยันตัวตนและสิทธิ์ (US-16, US-17, US-18, US-15)

- ผู้ที่ยังไม่ล็อกอินเข้าได้ 0 หน้า นอกจากหน้าล็อกอิน
- รหัสผ่านไม่ถูกเก็บเป็นข้อความที่อ่านได้
- สิทธิ์ของ 3 บทบาท (ผู้จัดการความปลอดภัย · หัวหน้างานไซต์ · ผู้บริหาร) ถูกตรวจที่ฝั่งระบบทุกคำขอ ไม่ใช่เพียงซ่อนปุ่มบนหน้าจอ
- บัญชีผู้ใช้และบทบาทสร้างโดยฝ่ายไอทีเท่านั้น ไม่มีการสมัครเอง (AS-13)

### NFR-07 · ความครบถ้วนของร่องรอยการแก้ผล (US-12)

- 100% ของการแก้ผลมีบันทึกครบ 5 ช่อง: ผู้แก้ · วันเวลา · ผลก่อนแก้ · ผลหลังแก้ · เหตุผล
- ไม่มีบทบาทใดลบหรือแก้ไขบันทึกการแก้ผลผ่านหน้าจอของระบบได้

### NFR-08 · ทรัพยากรของรุ่นแรก (US-20)

- การทดสอบตาม NFR-02 และ NFR-03 ทำบนเครื่องที่มี GPU 1 ใบ
- ผลการทดสอบต้องระบุรุ่นของ GPU ที่ใช้ เพื่อให้ตัวเลข SLO ตรวจซ้ำได้
