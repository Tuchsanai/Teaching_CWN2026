# BUGS-SECRET · SiteSafe Inspect

**เอกสารลับ:** สำหรับผู้สร้างระบบและผู้ตรวจผลการทดสอบเท่านั้น ผู้ทดสอบไม่เปิดไฟล์นี้
รายชื่อนี้อยู่ในไฟล์นี้ที่เดียว ไม่คัดลอกไปเอกสารอื่น หน้าเว็บ log หรือคำอธิบายในโค้ด

เมื่อเว็บรันด้วย `BUG_MODE=1` Business Rule 3 ข้อต่อไปนี้ทำงานผิด ส่วนอื่นทำงานตาม `docs/DESIGN.md`

| # | Business Rule | พฤติกรรมที่ถูก (`BUG_MODE=0`) | พฤติกรรมที่ผิด (`BUG_MODE=1`) | กรณีใน `docs/TEST-DATA.md` ที่ต้องจับได้ | ผลที่เห็นเมื่อผิด |
|---|---|---|---|---|---|
| 1 | BR-02 | H = 0 และ V ≥ 2 → "ไม่ผ่าน" | ใช้ V > 2 แทน V ≥ 2 ทำให้ H = 0, V = 2 เป็น "เตือน" | R-5 | `h0_v2.jpg` ได้ "เตือน" แทน "ไม่ผ่าน" |
| 2 | BR-04 | สีแดงเมื่ออัตราผ่าน < 90% | ใช้ ≤ 90% ทำให้อัตราผ่าน 90.00% พอดีเป็นสีแดง | P-2 · P-5 · P-7 | ไซต์ที่ได้ 270 ÷ 300 และ 9 ÷ 10 แสดงสีแดง |
| 3 | BR-06 | > 50 รูปต่อครั้ง → ปฏิเสธทั้งครั้ง | ปฏิเสธเมื่อ > 51 รูป ทำให้ 51 รูปถูกรับ | N-5 | ส่ง 51 รูปได้ `201` แทน `422` |

## ข้อกำหนดของการทำโหมดนี้

| เรื่อง | ข้อกำหนด |
|---|---|
| ตำแหน่ง | ทั้ง 3 ข้ออยู่ในไฟล์กติกาไฟล์เดียว (`lib/rules`) ซึ่งเป็นที่เดียวที่อ่าน `BUG_MODE` |
| ข้อ 3 | หน้าจออัปโหลดใช้เพดานจาก API ตัวเดียวกัน จึงยอมให้เลือก 51 รูปเมื่อ `BUG_MODE=1` ด้วย |
| สิ่งที่ไม่เปลี่ยน | กรณีอื่นของ 3 กติกานี้ยังถูก: V = 1 → เตือน · V = 3 → ไม่ผ่าน · 89.67% → แดง · 90.33% → ไม่แดง · 50 รูป → รับ · 52 รูป → ปฏิเสธ |
| การปกปิด | ไม่มีข้อความ "bug" บนหน้าจอ ใน `/api/health` ใน log หรือในคำตอบของ API |
| เกณฑ์ของชุดทดสอบ | ชุดทดสอบที่ดีต้องผ่านทั้งหมดเมื่อ `BUG_MODE=0` และไม่ผ่านอย่างน้อย 1 กรณีต่อข้อ เมื่อ `BUG_MODE=1` |
