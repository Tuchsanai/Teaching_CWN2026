## 2. Business Rules (BR) · ทุกข้อมีเส้นแบ่ง 3 ค่า

| ID | กติกา | ต่ำกว่า | เท่ากับ | สูงกว่า | ที่มา |
|---|---|---|---|---|---|
| BR-01 | PDF รับเฉพาะ 1 หน้า (JPG/PNG/PDF เท่านั้น ชนิดอื่นปฏิเสธ 415) | 0 หน้า → ปฏิเสธ (ไฟล์เสีย) | 1 หน้า → รับ | 2 หน้า → ปฏิเสธ 422 | L61 |
| BR-02 | ขนาดไฟล์ ≤ 10.00 MB (A-01) | 9.99 MB รับ | 10.00 MB รับ | 10.01 MB ปฏิเสธ 413 | L61 (A-01) |
| BR-03 | ไฟล์ต่อชุด ≤ 100 (A-02) | 99 รับ | 100 รับ | 101 ปฏิเสธทั้งชุด 422 | L19 |
| BR-04 | ความมั่นใจยอดรวม < 0.90 → ธง LOW_CONF (A-03) | 0.89 ธง | 0.90 ไม่ธง | 0.91 ไม่ธง | L23 |
| BR-05 | \|ผลรวมราคารายการ − ยอดรวม\| > 1.00 บาท → ธง SUM_MISMATCH (A-04) | 0.99 ไม่ธง | 1.00 ไม่ธง | 1.01 ธง | L23, L27 |
| BR-06 | อ่านล้มติดกัน 3 ครั้ง → กองพิมพ์เอง (A-05) | ล้ม 2 → ลองใหม่ | ล้ม 3 → DLQ | (ไม่มีครั้งที่ 4) ถูกนับ 3 | L55 |
| BR-07 | โควตางานด่วน ≤ 20 ใบ/วัน รวมทั้งสำนักงาน (A-06) | ใบที่ 19 รับ | ใบที่ 20 รับ | ใบที่ 21 ปฏิเสธ 409 "เกินโควตาด่วน" | L39, L41 |
| BR-08 | เมื่อมีทั้งคิวด่วนและปกติ หยิบ ด่วน 4 : ปกติ 1 (`UUUUN`) (A-07) | หยิบด่วนติดกัน 3 → ถัดไปด่วน | ติดกัน 4 → ถัดไปต้องปกติ | ไม่มีกรณีด่วน 5 ติดกันเมื่อคิวปกติไม่ว่าง | L35, L41 |
| BR-09 | ใบค้างในคิว (รออ่าน) ≤ 400 (A-08) · เกินตอบ 429 + `Retry-After = ceil(ค้าง ÷ อัตรารวม) วินาที` ขั้นต่ำ 60 สูงสุด 1800 · งานด่วนไม่นับเพดาน | ค้าง 399 + 1 → รับ | ค้าง 400 → ใบใหม่ 429 | ค้าง 401 (เกิดจากด่วน) → ปกติ 429 ด่วนรับ | L53 |
| BR-10 | วันที่ใบเสร็จต้องอยู่ใน 365 วันก่อนวันอัปและไม่เกินวันอัป · นอกช่วง → ธง DATE_RANGE (A-09) | 364 วัน ไม่ธง | 365 วัน ไม่ธง | 366 วัน ธง (และ +1 วันในอนาคต ธง) | L23 |
| BR-11 | งานปกติรอ ≥ 60 นาที ยกเป็นลำดับหยิบถัดไปทันที (aging) (A-10) | 59 นาที ตามกติกาสลับ | 60 นาที หยิบถัดไป | 61 นาที หยิบถัดไป | L41 |
| BR-12 | สรุปเดือน M นับใบที่ **วันที่ใบเสร็จ** อยู่ในวันที่ 1 ถึงวันสุดท้ายของ M (ไม่ใช่วันอัป) เฉพาะ "ยืนยันแล้ว" | 31 ต.ค. → ต.ค. | 1 พ.ย. → พ.ย. | 30 พ.ย. → พ.ย. · 1 ธ.ค. → ธ.ค. | L45, L47, L67 |
| BR-13 | ยอดรวม 0.01–100,000.00 บาท อยู่นอกช่วง → ธง AMOUNT_RANGE (A-11) | 0.00 ธง | 0.01 / 100,000.00 ไม่ธง | 100,000.01 ธง | L23 |
| BR-14 | ลูกค้าร้านอัปได้ ≤ 200 ใบ/วัน/ร้าน (A-12) | ใบที่ 199 รับ | ใบที่ 200 รับ | ใบที่ 201 ปฏิเสธ 429 "เกินโควตาวันนี้" | L45, L53 |

## 3. Non-Functional Requirements (NFR)

| ID | เรื่อง | เกณฑ์ที่วัดได้ | อ้าง |
|---|---|---|---|
| NFR-01 | คุณภาพโมเดล (วัดบน Test Set ≥ 200 ใบอ่านได้ + ≥ 20 ใบอ่านไม่ได้ · A-13) | **M1** Accuracy ยอดรวม (ตรง ±0.01) ≥ 95% · **M2** Silent Error (ยอดผิดและไม่มีธง) = 0 ใบ · **M3** Flag Recall ของใบยอดผิด = 100% · **M4** Flag Rate ≤ 25% · **M5** Abstention บนใบอ่านไม่ได้ ≥ 90% (ตอบ `unreadable` หรือไป DLQ) · **M6** JSON Validity ≥ 99% · **M7** ชื่อร้าน/วันที่ ตรง ≥ 90% · ชื่อรายการ CER ≤ 10% · Threshold ตรึงบน Validation ก่อนเปิด Test | US-06, 07, 08, 09 |
| NFR-02 | SLO งานปกติ | ชุด 100 ใบ ผลครบ (รอตรวจ/พิมพ์เอง) ≤ 30 นาที ในคิวว่าง · p95 ต่อใบ ≤ 30 นาทีในวันพีค | US-10 |
| NFR-03 | SLO งานด่วน | 10 ใบด่วนขณะคิวปกติค้าง 300 ใบ ผลครบ ≤ 5 นาที | US-12 |
| NFR-04 | ความจุช่วงพีค | 800 ใบ/วัน ภายใน 8 ชม. ทำงาน (≥ 100 ใบ/ชม.) · อัตราต่อ Worker ≥ 0.5 ใบ/วินาที (A-14) · เพดานคิว 400 | US-21 |
| NFR-05 | ข้อมูลห้ามหาย | Worker ถูก `kill -9` กลางงาน: ใบหาย 0 · ผลซ้ำ 0 · ใบที่รับแล้วมีผลหรืออยู่ DLQ 100% | US-11, US-20 |
| NFR-06 | ความเป็นส่วนตัว | แยก tenant · TLS ระหว่างเว็บกับ gateway · API key เก็บใน env เท่านั้น ไม่อยู่ใน log · ไม่บันทึกภาพ/ยอดลง log · ลบภาพชั่วคราวบน GPU หลังอ่าน · รหัสผ่าน bcrypt | US-23, US-17 |
| NFR-07 | ความคุ้มของการเพิ่ม GPU | 2 GPU เทียบ 1 GPU: Speedup เทรน ≥ 1.6 เท่า (Efficiency ≥ 80%) และ Speedup อ่าน 100 ใบ (2 Worker) ≥ 1.6 เท่า · รายงานเงินต่อ Epoch และต่อ 100 ใบ 2 แบบ | US-24 |
| NFR-08 | ทนช่วงพีค | ส่งเกินเพดาน: ระบบไม่ล่ม (health 200 ตลอด) · ตอบ 429 ภายใน 2 วินาที | US-20 |
| NFR-09 | ตรวจย้อนได้ | audit log ของการแก้เก็บ ≥ 2 ปี ห้ามลบ/แก้ | US-05, US-27 |
| NFR-10 | ใช้งานง่าย | ยืนยันใบไม่มีธง ≤ 10 วินาทีต่อใบ (เทียบเดิม 2 นาที) · ทุกปุ่มสำคัญมี `data-testid` | US-09 |

## 4. ข้อสมมติ (ตัวเลขที่ทีมตั้งเอง · ต้องยืนยันกับลูกค้าที่ G0)

| ID | ข้อสมมติ | เหตุผล |
|---|---|---|
| A-01 | ไฟล์ ≤ 10 MB | รูปมือถือทั่วไป 2–6 MB |
| A-02 | ชุดละ ≤ 100 ไฟล์ | ลูกค้าพูดถึง "ร้อยใบ" เป็นชุดใหญ่สุด |
| A-03 | เส้นความมั่นใจ 0.90 | ค่าเริ่มต้น จะตรึงใหม่บน Validation |
| A-04 | ผลต่างผลรวมรายการ > 1.00 บาท | เผื่อปัดเศษสตางค์ |
| A-05 | อ่านล้ม 3 ครั้ง → DLQ | ลูกค้าบอกแค่ "อย่าค้างวน" |
| A-06 | ด่วน ≤ 20 ใบ/วัน | กันทุกงานกลายเป็นด่วน |
| A-07 | สลับ 4:1 | ด่วนเสร็จใน 5 นาทีและปกติยังเดิน |
| A-08 | เพดานคิว 400 | ≈ ครึ่งวันพีค (800) |
| A-09 | ช่วงวันที่ 365 วัน | รอบบัญชีปีเดียว |
| A-10 | aging 60 นาที | กันปกติค้างข้ามวัน |
| A-11 | ยอดรวม 0.01–100,000 บาท | ร้านเล็ก ใบเกินแสนผิดปกติ |
| A-12 | ลูกค้าอัป ≤ 200 ใบ/วัน/ร้าน | 60 ราย × 200 > พีค 800 พอเหลือ |
| A-13 | Test Set ≥ 200 + 20 ใบอ่านไม่ได้ | ให้ "5 ใน 100" วัดได้อย่างมีความหมาย |
| A-14 | 0.5 ใบ/วินาที/Worker | ประมาณจาก VLM 2B บน RTX 3090 |
| A-15 | Silent Error = 0 | ตีความ "5 ใบนั้นคนต้องตรวจเจอ" ตรงตัว |
| A-16 | Flag Rate ≤ 25% | ตีความ "ไม่ต้องตรวจทุกช่องทุกใบ" |
