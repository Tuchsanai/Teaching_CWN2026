# User Stories · ReceiptDesk (รอบสกิล agent-team-delivery v1)

ที่มา: `INTERVIEW.md` (อ้างเลขบรรทัดเป็น `L<n>`) · ลำดับความสำคัญ Must / Should / Could

## บทบาท

| บทบาท | ตัวแทนจากการสัมภาษณ์ | หน้าที่ |
|---|---|---|
| พนักงานบัญชี (Staff) | คุณพิมพ์ | อัปโหลด ตรวจ แก้ ยืนยันใบเสร็จ |
| หัวหน้าทีมบัญชี (Lead) | คุณกิตติ | ทุกอย่างของพนักงาน + กำหนดงานด่วน + ดูกองพิมพ์เอง + ดูประวัติแก้ไข |
| เจ้าของสำนักงาน (Owner) | คุณอรทัย | ดูภาพรวม ความเร็ว ค่าใช้จ่าย GPU นโยบายข้อมูล |
| ลูกค้าร้าน (Client) | คุณสมชาย | อัปโหลดใบเสร็จของร้านตัวเอง ดูสถานะการรับ ดูสรุปรายเดือนที่ยืนยันแล้ว |
| ระบบ (System) | — | อ่านใบเสร็จด้วย AI บน GPU เช่า จัดคิว |

## จุดขัดกันในคำพูดลูกค้า + คำถาม

| # | จุดขัดกัน | บรรทัด | ทางที่เลือก (ข้อสมมติ) | คำถามถึงลูกค้า |
|---|---|---|---|---|
| C1 | "ไม่แน่ใจต้องบอก อย่าเดา" vs "ถ้าต้องตรวจทุกช่องทุกใบก็ไม่ประหยัดเวลา" | L23 vs L29 | ธงเฉพาะช่อง/ใบที่ไม่แน่ใจ · Flag Rate ≤ 25% · Silent Error = 0 ก่อน | ยอมให้ธงได้กี่ % ของใบ |
| C2 | งานด่วนต้องแซงคิว vs งานปกติห้ามค้างข้ามวัน | L35 vs L41 | สลับหยิบ ด่วน 4 : ปกติ 1 (BR-08) + งานปกติรอ > 60 นาทียกระดับ (BR-11) + โควตาด่วน (BR-07) | งานด่วนต่อวันมากสุดกี่ใบ |
| C3 | ลูกค้าเห็นเฉพาะตัวเลขที่ยืนยันแล้ว vs ลูกค้าอยากรู้ว่าใบถึงแล้ว | L47 vs L49 | ลูกค้าเห็นสถานะ + เลขใบรับทันที แต่ไม่เห็นยอดก่อนยืนยัน | ลูกค้าเห็นรูปใบที่ตัวเองส่งได้ไหม |
| C4 | "ห้ามล่ม" vs "ถ้าเต็มจริง ๆ ให้บอก" | L53 | รับไม่เกินเพดานคิว (BR-09) เกินแล้วตอบ 429 + Retry-After ไม่รับไว้เงียบ ๆ | เพดานควรเป็นกี่ใบ |
| C5 | ลูกค้าอัปเองได้ vs หัวหน้าคนเดียวตั้งด่วน | L45 vs L39 | ลูกค้าตั้งด่วนไม่ได้ ต้องขอผ่านหัวหน้า | — |
| C6 | "100 ใบผิดได้ 5" กับ "5 ใบนั้นคนต้องตรวจเจอ" | L27 | วัดแยก 2 ตัว: Accuracy ≥ 95% และ Silent Error = 0 | ยอมรับ Silent Error ต่ำกว่า 1% ได้ไหมถ้า 0 ทำไม่ได้ |
