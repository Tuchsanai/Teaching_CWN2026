## ขั้นที่ 11 · ขึ้นระบบจริงบน GPU (เครื่อง e2e-receipt) + เว็บที่พอร์ต 3420

### สิ่งที่ทำ
- **เครื่อง GPU** (2× RTX 3090, ไม่มี Docker) ทุกบริการรันเป็นโปรเซสธรรมดา แยก tmux ละตัว
  - รวม LoRA ที่ดีที่สุด (รอบ 2 GPU ของขั้นที่ 10) เข้ากับ Qwen3-VL-2B-Instruct แล้วเปิด vLLM 0.34.0 จำนวน 2 ตัว GPU ละตัว ชื่อโมเดล `receipt-vlm` ใช้เวลาเปิด 156 วินาที
  - ข้างหน้าเป็น NGINX แบบ `least_conn` ตาม `ai/nginx/nginx.conf` ของทีม (ไม่ได้แก้) ตามด้วย RabbitMQ, API gateway และ GPU Worker 2 ตัว (`worker0`, `worker1`)
- **API key ตัวใหม่** เก็บใน `./.env` ชื่อ `GATEWAY_API_KEY` ส่งให้เครื่อง GPU เป็นไฟล์ `secrets.env` (chmod 600) และใส่ให้ dispatcher ใน `app/.env` ไม่มีการแสดงค่า key ใด ๆ
- **เครื่องนี้** รัน docker compose project `receiptdesk-e2e` (web + dispatcher + PostgreSQL) ที่พอร์ต 3420 ใน `AI_MODE=gateway` เรียก gateway ที่ `http://210.130.226.136:41588`
- **ทดสอบทั้งเส้นทาง** ล็อกอินเป็นคุณพิมพ์ ส่งใบเสร็จจาก Test Set 5 ใบ (te0000–te0004) ผ่านหน้า `/upload` จริงด้วย Playwright
  - ทั้ง 5 ใบถึงสถานะ "รอตรวจ" (`review`) ภายใน 7.2 วินาที และสำเร็จในความพยายามครั้งแรก
  - ยอดรวมใน DB ตรงกับที่ gateway ตอบครบ **5/5 ใบ**
  - เทียบกับเฉลยแล้วอ่านถูก 4/5 ใบ ส่วน te0004 ตอบ 174,000 (เฉลย 174,600) ด้วยความมั่นใจ 0.64 จึงถูกติดธง "ไม่แน่ใจยอดรวม" ตาม BR-04 ให้คนตรวจอีกที
  - ส่งซ้ำอีก 1 รอบได้ผลเหมือนเดิม รอบแรกไม่ได้เก็บคำตอบ gateway ไว้ เพราะตัวเก็บคำตอบชี้ batch ผิด จึงใช้ผลรอบ 2 เป็นหลักฐาน
- **งานโหลดกระจายเท่ากัน** vLLM0 กับ vLLM1 รับไปตัวละ 5 คำขอ และ worker 2 ตัวก็ได้ไปตัวละ 5 ใบ

### สิ่งที่ต้องแก้ (รายละเอียดอยู่ใน `results/deploy/FIXES.md`)
1. **แก้โค้ดแค่ 1 บรรทัด** ใน `app/docker-compose.yml` เปลี่ยนพอร์ตเว็บจาก `'3000:3000'` เป็น `'${WEB_PORT:-3000}:3000'` เพราะเดิมพอร์ตเขียนตายตัวไว้ ส่วน gateway, worker, queue, nginx.conf และ dispatcher ใช้ได้เลยบน GPU จริง ไม่ต้องแก้
2. **RabbitMQ เปิดไม่ขึ้น** ถ้าสั่งในฐานะ root เพราะอ่าน `/root/.erlang.cookie` ไม่ได้ จึงเปลี่ยนไปเปิดด้วยผู้ใช้ `rabbitmq` และ `HOME=/var/lib/rabbitmq` (แก้ที่สคริปต์เปิดบริการ ไม่ได้แก้โค้ด)
3. **ฐานข้อมูลใหม่ไม่มีบัญชีผู้ใช้** เพราะบัญชีถูกสร้างจาก `reset_test_data()` เท่านั้น จึงเรียกฟังก์ชันนี้ผ่าน psql 1 ครั้ง โดยยังปิด test reset ของเว็บไว้ ควรให้ทีมทำสคริปต์ seed บัญชีจริงแยกจากข้อมูลทดสอบ
4. **ยังค้าง:** gateway ยังเป็น HTTP ธรรมดา ทำให้ key วิ่งผ่านอินเทอร์เน็ตโดยไม่เข้ารหัส โค้ดรองรับ TLS แล้ว แต่ compose ยังไม่ mount ไฟล์ CA ให้ dispatcher
