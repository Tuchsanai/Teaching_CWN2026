**5 เรื่องที่เพิ่มในเวอร์ชัน 1**
1. **What-if ก่อนรันทีม** (B2): ใช้ `blocks.json` เดิมโดยไม่แก้ (ตรวจ md5 ก่อนและหลัง) วางเพิ่ม 2 แผน คือ `<plan>-2` ที่ให้ agent พร้อมกัน 2 ตัว และ `<plan>-nocodex` ที่ไม่มี Codex แล้วเทียบ 4 เรื่อง: เวลารวม · Critical Path · บัญชีที่งานหนักที่สุด · บล็อกที่วางไม่ได้ จากนั้นแนะนำแผนที่จะรัน
2. **รันต่อเมื่อมีบล็อกไม่เสร็จ** (C2–C3): ใช้ `team.py run --resume <run_id>` กับ run เดิม รันเฉพาะบล็อกที่ไม่เสร็จ ผู้ทำแก้เฉพาะข้อที่ผู้ตรวจขอในรอบล่าสุด ถ้าผู้ตรวจยังพบกรณีขอบใหม่ทุกรอบ ให้คนตัดสินว่าจะเปลี่ยนขอบเขตการตรวจหรือไม่ (G1c) แล้วจึงใช้ `--set <B>.criteria=` ส่วนข้อที่อยู่นอกขอบเขตจดไว้ที่ `FOLLOW-UPS.md`
3. **เทรนเทียบจำนวน GPU** (C5): เทรน 1 GPU และ N GPU ด้วยค่าเดิมทุกอย่าง วัดเวลาต่อ Epoch จาก `train_runtime` แล้วคิด Speedup · Efficiency · เงินต่อ Epoch (ทั้งคิดตามส่วนของ GPU และคิดตามราคาทั้งเครื่อง) ตัดสินความคุ้มตาม NFR และตรึง Threshold บน Validation ก่อนเปิด Test
4. **Capacity Test ตาม SLO** (C7): ยิงโหลดจากเครื่อง GPU ไปที่ gateway ทดสอบ 5 เรื่อง: ความจุเมื่อมี Worker 1 ตัวเทียบ N ตัว · งานด่วนแซงคิว · คิวเต็มตอบ 429 · Worker ล่ม · ใบที่อ่านไม่ได้เข้า Dead-letter Queue ผลเก็บเป็นไฟล์ตัวเลขและกราฟ 2 รูป
5. **แยก Test Case ตัวอ่านจำลองกับโมเดลจริง** (D2–D3): ทุก TC ใน Test Plan หัวข้อ 5.9 ต้องมีป้าย
   - **M** ต้องกำหนดผลอ่านให้แน่นอน รันกับเว็บตัวอ่านจำลองที่ `mock_port`
   - **A** ไม่ขึ้นกับผลอ่าน รันที่ `mock_port` เพื่อไม่ใช้ GPU
   - **R** ต้องใช้โมเดลจริง รันที่ `web_port` และมีงบจำนวนภาพที่ส่งเข้า GPU
