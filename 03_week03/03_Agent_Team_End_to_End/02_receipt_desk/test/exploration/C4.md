## ข้อสังเกต/ฟีเจอร์ที่พบ

- ค้างจริงตอนทดสอบคือ 313 ไม่ใช่ 310 (หน้าพนักงานก็แสดง 313 / 400) — ทุกการคำนวณ N ในตารางจึงคิดจาก 313 ตามที่ server รายงาน และผลถูกทุกกรณี (เกิน 4, 8 → 1 นาที · เกิน 9, 11, 12, 13 → 2 นาที) ขอบ 8 → 9 ใบเปลี่ยนจาก 1 เป็น 2 นาทีพอดี
- เกิน 1 ใบพอดีต้องส่ง 88 ใบ (≤ 90) จึงไม่ได้ลองตามกติกา GPU — กรณีเกิน 1 ทดแทนด้วยเกิน 4 (N=1)
- body ของ 429 จากเว็บมี `pending`, `limit`, `retryAfterMinutes`, `accepted:0`, `rule` และ header `retry-after` เป็นวินาที (60) แต่ไม่มี `workers_alive` (ต่างจากตัวอย่างของ gateway ใน DESIGN 5.6 แต่ตรงกับตาราง error ของเว็บ) — ลูกค้าจึงตรวจจำนวน Worker เองไม่ได้
- ข้อความบนหน้าลูกค้าแสดงเฉพาะ N นาที ไม่เปิดเผยจำนวนคิว ซึ่งเหมาะกับลูกค้า
- ตารางของร้านเห็นใบ te0010.jpg ที่คนอื่นส่งให้ CL-02 ด้วย (ลูกค้าเห็นใบทุกใบของร้าน ไม่ใช่เฉพาะที่ตัวเองส่ง)
- ไม่ได้ทดสอบ: ส่งสองชุดพร้อมกันที่รวมกันแล้วเกิน 400 (race) เพราะต้องใช้ชุดที่ถูกรับจริง และ urgent จากลูกค้าผ่าน API
