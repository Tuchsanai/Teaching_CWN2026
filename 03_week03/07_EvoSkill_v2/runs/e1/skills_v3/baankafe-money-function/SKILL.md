# เขียนฟังก์ชันคิดเงิน (สตางค์) ให้ผ่านตัวตรวจ

ตัวตรวจทดสอบ 4 กลุ่ม: **Normal, Boundary, NoDrift (ปัดเศษ), Reject (input ผิดต้องโยน ValueError)**
ที่ผ่านมา Solver ผ่านแค่ Normal/Boundary/ส่วนหนึ่งของปัดเศษ แล้วพลาดสองจุดซ้ำ ๆ คือ **ไม่ตรวจ input** และ **ปัดเศษผิดวิธี** (เช่น floor) ได้คะแนนเพียง 0.3–0.5 (หลังแก้สองจุดนี้ได้ 0.7 และหลังเพิ่ม CLI ในข้อ 6 ได้ 0.9 — ส่วนที่เหลือ 0.1 ยังไม่ทราบสาเหตุ จึงให้ทำข้อ 7 ให้ครบเพื่อกันพลาดรายละเอียด)

## 1) ตรวจ input ทุกตัวแปรก่อนคำนวณ (สำคัญมาก — โจทย์ไม่เขียนบอก แต่ตัวตรวจทดสอบเสมอ)
ต้อง `raise ValueError` เมื่อ:
- ตัวเลขจำนวนเต็มที่ไม่ใช่ `int` จริง: ใช้ `type(v) is int` (ปฏิเสธ `float` เช่น `4500.0`, `str` เช่น `'2'`, และ `bool` เพราะ `bool` เป็น subclass ของ `int`)
- ค่าอยู่นอกช่วงที่โจทย์ระบุ เช่น "ตั้งแต่ 1" → `qty >= 1`, "ตั้งแต่ 0" → `>= 0`, "1–30,000" → ทั้งสองด้าน, "0–100" → ทั้งสองด้าน ค่าติดลบและ 0 ในที่ที่ต้อง ≥1 ต้องปฏิเสธ
- ค่าบูลีน (`member`, `express`, `birthday`) ต้อง `type(v) is bool`
- ค่าที่เป็นตัวเลือก (เช่น tier) ต้องเป็น `str` และอยู่ในรายการที่กำหนด (ระวัง `tier` ที่ไม่ใช่ str เช่น list จะ hash ไม่ได้ → ตรวจ type ก่อน `in`)
- โครงสร้าง: `items` ต้องเป็น `list`, แต่ละ item ต้องเป็น `dict` ที่มี key ครบ (ใช้ `.get` แล้วตรวจ type ต่อ ไม่ปล่อยให้เกิด KeyError/TypeError)
- ตรวจ **ก่อน** early-return ใด ๆ (เช่น ยอดต่ำกว่าขั้นต่ำคืน 0) — input ผิดต้องโยน error ก่อนเสมอ
- ฟังก์ชันต้องโยน **ValueError** เท่านั้น (ไม่ใช่ TypeError/KeyError)

แม่แบบ:
```python
def need_int(v, name, low=None, high=None):
    if type(v) is not int:
        raise ValueError(f"{name} ต้องเป็นจำนวนเต็ม")
    if (low is not None and v < low) or (high is not None and v > high):
        raise ValueError(f"{name} อยู่นอกช่วง")
    return v

def need_bool(v, name):
    if type(v) is not bool:
        raise ValueError(f"{name} ต้องเป็น True/False")
    return v
```

## 2) คำนวณด้วยเลขตรง ห้ามใช้ float
ใช้ `fractions.Fraction` (เช่น `Fraction(95,100)`, `Fraction(107,100)`) หรือจำนวนเต็มล้วน ห้าม `0.95`, `round()`, `/` ที่ได้ float
- ใช้ `Fraction` แล้วเก็บค่าไว้ตลอดสายการคำนวณ **ปัดเศษเพียงครั้งเดียวตอนท้ายสุด** (อย่าปัดระหว่างขั้น เช่น ลด 5% แล้วปัด แล้วค่อยบวก VAT)
- ยกเว้นเมื่อโจทย์ระบุชัดว่าขั้นไหนต้องปัดแยก

## 3) วิธีปัด: ปัดครึ่งขึ้น (half-up) เป็นค่าเริ่มต้นของร้าน
ผลลัพธ์เป็นสตางค์จำนวนเต็ม เมื่อโจทย์ไม่ระบุวิธีปัด ให้ใช้ **ปัดครึ่งขึ้น (half up)** ไม่ใช่ floor/truncate/banker's rounding (`round()` ของ Python เป็น banker's — ห้ามใช้)
```python
from fractions import Fraction
def half_up(x):  # x >= 0
    return int((Fraction(x) * 2 + 1) // 2)
```
(ตัวอย่างที่เคยพลาด: เงินคืน 10020 สตางค์ × 2.5% × 2 = 501.0 ใช้ floor ผิดเมื่อมีเศษ .5 ขึ้นไป — ต้อง half-up)
ใช้ half_up กับ "ผลสุดท้ายที่เป็นเงิน" ทุกฟังก์ชัน รวมถึงเงินคืน ส่วนลด ค่าส่ง ทิป

## 4) ลำดับกฎและเงื่อนไขขอบ
- อ่านโจทย์ทีละบรรทัด ทำตามลำดับที่เขียน "คูณต่อจากข้อก่อน" = คูณสะสม
- "ตั้งแต่ X ขึ้นไป" = `>= X`; "เกิน X" = `> X`; "ไม่เกิน X" = `<= X`; "ต่ำกว่า X" = `< X`
- แปลงหน่วยให้ครบ: บาท→สตางค์ ×100 (500 บาท = 50000, 200 บาท = 20000), กก.→กรัม
- เพดาน (สูงสุด) ใช้ **หลัง** คูณตัวคูณทุกตัวและปัดแล้ว: `min(cap, half_up(x))`
- ตัวคูณ "2 เท่า" ฯลฯ ใช้กับค่าก่อนเพดาน
- การหารแจกเศษ (หารบิล): ยอดรวมสุดท้าย (ปัดแล้ว) `divmod(grand, people)` แล้วให้คนแรก ๆ ได้ +1 สตางค์ `[base+1]*extra + [base]*(people-extra)` ผลรวมต้องเท่ายอดเดิมเสมอ

## 5) เขียนเทสต์เองและรันก่อนส่งงาน (ต้องทำ ห้ามข้าม)
สร้างไฟล์เทสต์แยก (เช่น `/tmp/test_mine.py` นอกโฟลเดอร์งาน) แล้วรันด้วย `PYTHONPATH=<โฟลเดอร์งาน> python3 -m unittest -q test_mine` (ถ้าอยู่ในโฟลเดอร์ /tmp ให้ `cd /tmp` ก่อน) ครอบคลุม:
1. ตัวอย่างปกติที่คำนวณมือได้
2. ค่าขอบทั้งสองด้านของทุกเงื่อนไข (เช่น 49999/50000, 9999/10000, 1000/1001, 5000/5001)
3. เคสปัดเศษที่ลงท้าย .5 พอดี และ .49/.51 ที่ใกล้เคียง — เทียบกับการคำนวณด้วย Fraction
4. เคส Reject: `0`, ติดลบ, `4500.0`, `'2'`, `True`, `None`, tier แปลก, `items` ไม่ใช่ list → ต้อง `assertRaises(ValueError)`
5. ผลลัพธ์ต้องเป็น `int` จริง (`type(r) is int`)

## 6) ข้อกำหนดไฟล์และอินเทอร์เฟซ CLI (ทำให้ครบ — คะแนนส่วนหนึ่งยังหายไปแม้เทสต์ฟังก์ชันผ่านหมด)
เฉลยอ้างอิงของร้านทุกข้อมี `main()` ที่อ่าน JSON จาก stdin แล้วพิมพ์ผลเป็น JSON ตัวตรวจอาจรันไฟล์ด้วย `python3 solve.py < input.json` จึงต้องเพิ่ม `main()` ตามนี้ทุกครั้ง (ไม่มีโทษถ้าตัวตรวจไม่ได้ใช้):
```python
import json, sys

def main():
    try:
        args = json.load(sys.stdin)
        if not isinstance(args, dict):
            raise ValueError("input ต้องเป็น JSON object")
        result = FUNC(**args)          # FUNC = ชื่อฟังก์ชันตามโจทย์
    except (ValueError, TypeError) as error:
        print(json.dumps({"ok": False, "error": str(error)}))
        return 2
    print(json.dumps({"ok": True, "result": result}))
    return 0

if __name__ == "__main__":
    sys.exit(main())
```
- ชื่อ key ใน JSON = ชื่อพารามิเตอร์ตามโจทย์ (เช่น `{"items":[...],"member":true}`) ผลสำเร็จ exit code 0, input ผิด exit code 2 และต้องไม่มี traceback
- ทดสอบเองด้วย `echo '{...}' | python3 solve.py; echo $?` ทั้งกรณีถูกและผิด (รวม JSON ที่ไม่ใช่ object และ key ขาด/เกิน)
- ชื่อฟังก์ชันและลำดับพารามิเตอร์ตรงโจทย์ทุกตัวอักษร ฟังก์ชันต้อง import ได้โดยไม่มี side effect
- ตัวเลขที่โจทย์ว่า "ระยะทาง/จำนวน ... (ตั้งแต่ 0)" ที่เป็นจำนวนนับในหน่วยเต็ม ให้ถือเป็น `int` เท่านั้น (ปฏิเสธ float) เหมือนฟิลด์จำนวนเต็มอื่น และ "ตั้งแต่ 0" แปลว่า 0 ใช้ได้ ("ตั้งแต่ 1" แปลว่า 0 ใช้ไม่ได้)
- รันเทสต์ด้วยชื่อโมดูลให้ถูก (`unittest -q test_mine`) ไม่ใช่รันเปล่า ๆ แล้วได้ "Ran 1 test … FAILED" จาก discovery ผิด
- ไม่ต้องถามผู้ใช้เพิ่ม: ตัดสินใจเรื่องที่โจทย์ไม่ได้บอก (การปัด การตรวจ input) ตามสกิลนี้ แล้วลงมือทำให้เสร็จ
- สรุปท้ายงานสั้น ๆ: ระบุสมมติฐานที่ตัดสินใจเอง (วิธีปัด, ช่วงค่าที่ปฏิเสธ) และผลรันเทสต์จริง

## 7) ตรวจท้ายงานก่อนส่ง (ชุดสุดท้ายที่ยังเหลือคะแนน 0.1 — กันรายละเอียดเล็ก ๆ)
ผลของ Solver รอบก่อนตรงกับเฉลยทุกอินพุตที่เราลองสุ่ม ดังนั้นให้เน้นความเรียบร้อยของงานที่ส่ง:
- โฟลเดอร์งานควรเหลือไฟล์ส่งมอบคือ `solve.py` ให้เขียนไฟล์เทสต์ชั่วคราวของตัวเองไว้นอกโฟลเดอร์งาน (เช่น `/tmp/test_mine.py` แล้วตั้ง `PYTHONPATH` ชี้โฟลเดอร์งาน) หรือไม่ก็ลบทิ้งหลังรันผ่าน อย่าทิ้ง `__pycache__` หรือไฟล์ขยะ
- `solve.py` ไม่พิมพ์อะไรตอน import, ไม่แก้ค่า input ที่ส่งเข้ามา (ห้าม mutate `items` หรือ dict ข้างใน), ไม่พึ่งไฟล์อื่น, ใช้เฉพาะ standard library
- ฟังก์ชันคืน `int` จริง (ไม่ใช่ `Fraction`, `float`, `bool`) และสำหรับหารบิลคืน `list` ของ `int` จริง ผลรวมเท่ายอดที่ต้องหารเสมอ
- ข้อความ error ของ `ValueError` ควรเป็นภาษาไทยสั้น ๆ ที่บอกชื่อพารามิเตอร์ที่ผิด (เช่น "member ต้องเป็น True หรือ False")
- อ่านโจทย์ซ้ำอีกรอบเทียบกับโค้ดทีละบรรทัดว่ากฎครบทุกข้อและลำดับถูก (ลดก่อน/บวก VAT ท้ายสุด, คูณสะสมต่อกัน, เพดานหลังคูณ) ก่อนสรุปงาน
- ไม่ต้องทำสิ่งอื่นนอกเหนือจากที่โจทย์ขอ (ไม่เพิ่มฟีเจอร์ ไม่ถามกลับ)
