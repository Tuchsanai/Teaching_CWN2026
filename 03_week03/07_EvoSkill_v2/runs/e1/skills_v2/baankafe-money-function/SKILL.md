# เขียน solve.py คิดเงินให้ผ่านตัวตรวจ

ตัวตรวจรัน unit test 4 กลุ่ม: **Normal** (ค่าปกติ), **Boundary** (ค่าที่ขอบเงื่อนไข เช่น พอดี 500 บาท / 1000 กรัม / 100 บาท), **NoDrift** (ค่าที่ทำให้ float หรือการปัดหลายรอบผิดไปหนึ่งสตางค์), **Reject** (input ผิดต้อง `raise ValueError`) · งานก่อนหน้านี้เสียคะแนนครึ่งหนึ่งเพราะไม่ทำ Reject และเดานโยบายผิด จึงต้องทำครบทุกข้อด้านล่าง

## ขั้นตอน
1. อ่านโจทย์ให้ครบ ทำรายการเงื่อนไขทุกข้อ + ลำดับการคำนวณ ("คูณต่อจากข้อก่อน", "VAT เป็นขั้นสุดท้าย")
2. อ่านสกิล `baankafe-house-policies` — โจทย์ไม่ได้เขียนกฎบางข้อ (ปัดเศษทิศไหน, กรณีพิเศษ, ข้อจำกัด) ต้องใช้กฎของร้านนั้น
3. คัดลอก `template.py` (อยู่ในโฟลเดอร์สกิลนี้) เป็น `solve.py` แล้วแก้ ห้ามลบ `main()` (อ่าน JSON จาก stdin → พิมพ์ `{"ok":..., "result":...}`)
4. เขียนฟังก์ชันชื่อและ signature ตรงตามโจทย์เป๊ะ (ชื่อ parameter ก็ต้องตรง เพราะเรียกด้วย `**args`)
5. เขียนเทสต์ของตัวเองแล้วรัน (ดูด้านล่าง) ก่อนส่งเสมอ

## การคำนวณ
- ใช้ `fractions.Fraction` ล้วน ห้าม float, ห้าม `round()` ของ Python (เป็น banker's rounding)
- คูณอัตราเป็นเศษส่วน: 5% → `Fraction(95,100)`, VAT 7% → `Fraction(107,100)`, ×1.5 → `Fraction(150,100)`
- **ปัดเศษครั้งเดียวตอนท้ายสุด** ห้ามปัดระหว่างทาง (ยกเว้นโจทย์สั่งให้ปัดขั้นกลางชัด ๆ)
- เงื่อนไขขอบ: "ตั้งแต่ X ขึ้นไป" = `>= X`, "เกิน X" = `> X`, "ไม่เกิน X" = `<= X` · เทียบเงื่อนไขกับยอดก่อนลด (ตัวเลขจริงที่โจทย์พูดถึง) เว้นแต่โจทย์บอกเป็นอย่างอื่น
- หน่วย: โจทย์ใช้สตางค์ แต่เกณฑ์เขียนเป็นบาท → แปลง ×100 (500 บาท = 50000)
- "ตามสัดส่วนของกรัม" = คิดเป็นเศษส่วนเต็ม เช่น `Fraction(1500 * (g - 5000), 1000)` ไม่ปัดเป็นกิโลก่อน

## การตรวจ input (Reject) — ทำทุกฟังก์ชัน ก่อนคำนวณ
- จำนวนเต็มต้องเป็น `type(v) is int` พอดี → ปฏิเสธ float (`4500.0`), str (`'2'`), bool, None
- ตรวจช่วงตามโจทย์: "ตั้งแต่ 1" → `>=1`, "ตั้งแต่ 0" → `>=0`, "0–100" → ช่วงปิดทั้งสองด้าน, "1–30,000" ตามนั้น
- flag (member/express/birthday) ต้อง `type(v) is bool`
- ค่าแจกแจง (tier ฯลฯ) ต้องเป็น str และอยู่ในชุดที่อนุญาต ไม่งั้น ValueError
- list/dict: ตรวจว่าเป็น list/dict จริง, แต่ละ item มี key ครบ และค่าถูก type/ช่วง (ใช้ `item.get(...)` แล้วส่งเข้า `need_int` ได้ key หาย = ValueError ไม่ใช่ KeyError)
- ใช้ exception ชนิด `ValueError` เท่านั้น (ไม่ใช่ TypeError/KeyError/assert)
- list ว่าง (items=[]) ไม่ผิดถ้าโจทย์ไม่ห้าม → ยอด 0

## เทสต์ก่อนส่ง
เขียนเทสต์ด้วย `unittest` ไว้ที่ `/tmp/<ชื่องาน>/test_solve.py` (นอกโฟลเดอร์งาน) แล้วรันด้วย `PYTHONPATH=<โฟลเดอร์งาน> python3 -m unittest -q test_solve` จากโฟลเดอร์ของเทสต์ (อย่าใช้ `python3 -I` เพราะ import solve ไม่เจอ) ต้องมี:
- ค่ามือคำนวณเอง 2–3 ค่า, ค่าที่ขอบเงื่อนไขทั้งสองข้าง (X-1, X, X+1)
- ค่าที่เศษสตางค์ลงที่ .5 พอดีและ .4999 (ตรวจทิศการปัด)
- Reject: ค่า 0/ติดลบ, float, str, bool, tier แปลก, key หาย
- ตรวจด้วยว่าผลเป็น `int` จริง (`type(r) is int`) และ `python3 solve.py < input.json` ทำงานได้

ในคำตอบสุดท้าย ให้บอกสมมติฐานที่เลือก (ทิศการปัด, กฎพิเศษ) สั้น ๆ

## ส่งมอบ
- โฟลเดอร์งานควรมีเฉพาะ `solve.py` ที่เป็นผลงานจริง: ลบไฟล์ชั่วคราว/เทสต์/`__pycache__` ที่สร้างไว้ในโฟลเดอร์งานออกก่อนจบ
- `solve.py` ต้อง import ได้โดยไม่มี side effect (โค้ดรันอยู่ใต้ `if __name__ == "__main__"` เท่านั้น) ไม่มี `print` ตอน import
- ฟังก์ชันที่คืนค่า ต้องคืน `int` ล้วน (ไม่ใช่ `Fraction`/float) และ list ที่คืนต้องเป็น list ของ int
- ตรวจ input ให้ครบทุก parameter รวมตัวที่ "ตั้งแต่ 0" (เช่น `distance_km` ต้องเป็น int ไม่รับ float) — ใช้ `need_int` ทุกตัว
