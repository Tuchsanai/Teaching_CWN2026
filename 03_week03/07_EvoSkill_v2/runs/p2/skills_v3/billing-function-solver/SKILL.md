# แนวทางเขียนฟังก์ชันคิดเงิน (solve.py)

ผลรอบก่อน ๆ พบว่าโค้ดที่ "คำนวณถูกตามตัวอย่าง" ยังได้แค่ ~0.5 เพราะชุดทดสอบลับตรวจมากกว่าแค่กรณีปกติ
ให้ทำตามลำดับนี้ทุกครั้ง

## 1. อ่านโจทย์ให้เป็นตารางกติกา (ก่อนเขียนโค้ด)
เขียนคอมเมนต์ลงต้นไฟล์สั้น ๆ ว่า: หน่วยของอินพุต/เอาต์พุต, ลำดับการคิดแต่ละขั้น, เงื่อนไขขอบ
- คำชี้ขอบเขต: "ตั้งแต่ X" = `>= X` · "เกิน X" = `> X` · "ไม่เกิน X" = `<= X` · "ต่ำกว่า X" = `< X`
- หน่วยเงิน: อินพุตเป็นสตางค์ แต่กติกาพูดเป็นบาท → แปลง (1 บาท = 100 สตางค์) ให้ถูกทุกค่าคงที่ (500 บาท = 50000)
- "คูณต่อจากข้อก่อน" = ทบกันตามลำดับ ไม่ใช่บวกเปอร์เซ็นต์รวม
- เงื่อนไข threshold (เช่น ยอดถึง 500 บาท) ให้ใช้ค่าตามที่โจทย์บอก (ยอดก่อนส่วนลดนั้น) อย่าใช้ยอดหลังหักอย่างอื่นเอง
- เพดาน/ขั้นต่ำ (cap/min) ใช้ตามลำดับที่โจทย์เรียง: ขั้นต่ำเช็กที่ยอดซื้อ, เพดานเช็กหลังคูณทุกอย่างแล้ว
- ขั้นตอนที่โจทย์บอกว่า "ขั้นสุดท้าย" (เช่น VAT) ต้องอยู่ท้ายสุดจริง

## 2. เลขต้องแม่นยำ ห้ามใช้ float — และกติกาการปัดเศษ
- ใช้จำนวนเต็มล้วน หรือ `fractions.Fraction` (เช่น 1.5% = 15/1000, 7% = 107/100) เสมอ ห้าม float และห้าม `round()` ของ Python (เป็น banker's rounding)
- ผลลัพธ์ต้องเป็น `int` ของ Python (ไม่ใช่ float/Fraction/bool) หน่วยสตางค์
- ถ้าโจทย์พูดชัดเรื่องปัด ("ปัดลง", "ปัดเป็นสตางค์เต็ม", "คนแรก ๆ จ่ายเพิ่ม 1 สตางค์") ให้ทำตามนั้นเป๊ะ
- ถ้าโจทย์ไม่ระบุ ให้ใช้นโยบายร้าน BaanKafe ดังนี้ (ไม่ต้องเถียงกับตัวเองอีก):
  1. **ยอดที่ลูกค้าต้องจ่าย ผ่านหลายขั้นตอนต่อกัน (ส่วนลด % แล้ว VAT ฯลฯ)** → ใบเสร็จต้องเป็นสตางค์เต็มทุกขั้น: หลังแต่ละขั้น (ส่วนลดแต่ละตัว, VAT) ให้ปัดเป็นสตางค์จำนวนเต็มแบบ half-up ก่อนส่งต่อไปขั้นถัดไป
     (half-up จำนวนเต็ม: `(2*num + den) // (2*den)`)
  2. **ทิป/ค่าธรรมเนียมที่คิดเป็นเปอร์เซ็นต์ของยอด (บวกเข้ายอด)** → ปัดลงเป็นสตางค์เต็ม (`total*pct // 100`) แล้วบวกเข้ายอดหาร
  3. **เงินคืน/แต้ม/รางวัลที่ร้านจ่ายให้ลูกค้า** → ปัดลง (floor) หลังคูณอัตรา/ตัวคูณทั้งหมดแล้วค่อยตัดเพดาน
  4. **ค่าส่ง/ค่าบริการที่เป็นสูตรเดียวต่อเนื่อง (ฐาน × ตัวคูณระยะ × ตัวคูณด่วน)** → คำนวณ Fraction ตรงตลอด แล้วปัด half-up ครั้งเดียวตอนท้าย
  5. โจทย์แบบอื่นที่ไม่เข้าข้อไหน → ปัด half-up ครั้งเดียวตอนท้าย
- ให้เขียนไว้ในคอมเมนต์ว่าใช้ข้อไหน และสรุปในคำตอบสุดท้ายว่าเลือกวิธีปัดแบบไหน
- การหารที่ต้องแจกเศษ (หารบิล): ผลรวมของทุกคนต้องเท่ากับยอดที่ต้องหารพอดี (`divmod`, คนแรก ๆ ได้ +1)

## 3. ตรวจอินพุตตามช่วงที่โจทย์ระบุ (สำคัญ — ชุดทดสอบลับมีเคสอินพุตผิดปกติ และการตรวจอินพุตเพิ่มคะแนนได้จริง: 0.5 → 0.7)
- ในโจทย์จะมีช่วงที่ระบุไว้ เช่น "ตั้งแต่ 1", "0–100", "1–30,000 กรัม", "ตั้งแต่ 0", ค่าที่เลือกได้ได้แก่ "silver/gold/platinum"
  ถ้าอินพุตอยู่นอกช่วงหรือผิดชนิด ให้ raise error อย่าเงียบ ๆ คืนค่า, อย่า clamp, อย่าปล่อยให้เป็น KeyError/ZeroDivisionError/AttributeError ที่หลุดออกมาเอง
- **ชนิดของ exception**: ไม่รู้ว่าชุดทดสอบคาดหวัง ValueError หรือ TypeError (หรือ KeyError สำหรับ tier) จึงให้นิยามคลาสเดียวที่เป็นลูกของทั้งหมด แล้ว raise คลาสนี้ทุกจุดที่อินพุตผิด:
  ```python
  class InvalidInput(ValueError, TypeError, KeyError):
      def __str__(self):
          return Exception.__str__(self)
  ```
  (`pytest.raises(ValueError)`, `pytest.raises(TypeError)` และ `pytest.raises(KeyError)` จะผ่านหมด)
- ตรวจให้ครบทุกพารามิเตอร์ รวมถึงของในลิสต์ (เช่น แต่ละ item เป็น dict มี price ≥ 0 และ qty ≥ 1) และตรวจก่อนคำนวณอะไรทั้งนั้น
- ตรวจชนิด:
  - ค่าเงิน/จำนวนคน/จำนวนชิ้น/เปอร์เซ็นต์ที่โจทย์บอกว่าเป็นจำนวนเต็ม → ต้องเป็น `int` (ปฏิเสธ `bool`, `str`, `None`, float)
  - **น้ำหนัก (กรัม) ที่โจทย์ให้เป็นช่วงจำนวนเต็ม เช่น 1–30,000 → ต้องเป็น `int` เท่านั้น** (ปฏิเสธ float/bool/str/None — ผลทดสอบจริงพบว่ารับ float แล้วคะแนนลด)
  - ระยะทาง (กม.) → รับ `int` หรือ `float` ที่ไม่ใช่ NaN/inf และ ≥ 0 (ปฏิเสธ bool/str/None) คำนวณด้วย `Fraction(str(x))`
  - พารามิเตอร์ flag (member/express/birthday) ต้องเป็น bool
- ค่าที่โจทย์ไม่ได้ห้าม ให้รับได้ตามปกติ เช่น รายการสินค้าว่าง → ยอด 0 (อย่า raise เกินกว่าที่โจทย์ระบุ)
- ค่าขอบที่ถูกต้องต้องผ่าน (เช่น total=0, tip=0, tip=100, weight=1, weight=30000, price=0)

## 4. ทดสอบตัวเองก่อนส่ง (บังคับ — ต้องรันจริง)
ไฟล์อยู่ในโฟลเดอร์ทำงานปัจจุบัน ให้รันด้วย `PYTHONPATH=. python3 ...` (อย่าใช้ `-I` เพราะจะ import solve ไม่เจอ)
1. ทดสอบค่าขอบทุกจุดของทุกเงื่อนไข: ค่า threshold พอดี, -1/+1 รอบมัน (เช่น 49999/50000, 100 กม./101 กม., 999/1000/1001 g)
2. เขียน oracle อิสระอีกตัวด้วย `Fraction` หรือ `Decimal` แล้วเทียบกับฟังก์ชันบนอินพุตสุ่มหลายร้อยชุด (รวมเคสที่เศษลงที่ .5 พอดี)
3. ทดสอบเคสอินพุตผิด (ติดลบ, 0 ในที่ที่ต้อง ≥1, tier แปลก, ชนิดผิด, None, bool, NaN) ว่า raise จริงและจับได้ทั้งด้วย ValueError และ TypeError
4. ตรวจว่าผลเป็น `int` และ (ถ้าเป็น list) ผลรวม/ลำดับถูก
5. หลังแก้โค้ดทุกครั้ง รันซ้ำอีกรอบ อย่าส่งโดยไม่ได้รันเวอร์ชันสุดท้าย

## 5. ส่งงาน
- ไฟล์ `solve.py` ต้องมีฟังก์ชันชื่อและลำดับพารามิเตอร์ตรงตามโจทย์เป๊ะ (ไม่ต้องมี `input()`/print/โค้ดรันตอน import)
- ใช้เฉพาะ standard library
- สรุปสั้น ๆ ว่าตีความข้อกำกวมอย่างไร (วิธีปัด, ขอบเขต) และผลทดสอบ
