# สกิล: ฟังก์ชันคำนวณเงินใน solve.py

โจทย์กลุ่มนี้สั้นและเขียนง่าย แต่ตัวตรวจเป็น test ซ่อนที่เทียบผลตรงตัว epoch ก่อนหน้าทุกข้อได้เพียง 0.4–0.5 ทั้งที่โค้ดตรงตามตัวอักษร
สาเหตุคือ **ข้อที่โจทย์ไม่ได้ระบุ**: วิธีปัดเศษ (ผลทดลองยืนยันว่าต้องปัดครึ่งขึ้นตอนท้าย) และการตรวจอินพุตนอกช่วง (ต้อง raise ValueError) ไม่ใช่ตรรกะหลัก
ดังนั้นต้องไล่หาข้อกำกวมอย่างเป็นระบบก่อนเขียน

## ขั้นตอน

1. เขียนไฟล์ `solve.py` ในโฟลเดอร์ทำงานปัจจุบัน ให้มีฟังก์ชันชื่อตรงตามโจทย์ (ลายเซ็นตรงตัว)
2. ไล่เช็กลิสต์ข้อกำกวมด้านล่างทีละข้อ แล้วเขียนคอมเมนต์สั้น ๆ ในโค้ดว่าเลือกอะไร
3. ใช้เลขจำนวนเต็มหรือ `fractions.Fraction` เท่านั้น ห้าม float และห้าม `round()` ของ Python
4. ทดสอบเองด้วย `python3 -c "from solve import ..."` รันจากโฟลเดอร์ที่มี solve.py **อย่าใส่ `-I`** เพราะ `-I` ตัดโฟลเดอร์ปัจจุบันออกจาก path จนหา `solve` ไม่เจอ
5. ลองกรณีขอบ: ค่า 0, ค่าต่ำสุด, ค่าพอดีเส้นแบ่ง (เช่น 50000 สตางค์พอดี, 1000 กรัมพอดี, 100 กม.พอดี, 10000 สตางค์พอดี), ค่าที่หารไม่ลงตัว, ค่าที่ชนเพดาน
6. ในคำตอบสุดท้ายให้ระบุกติกาปัดเศษที่ใช้ และกรณีที่ยังไม่ได้ทดสอบ อย่าอ้างว่า "ถูกทุกกรณี"

## เช็กลิสต์ข้อกำกวม

- **หน่วย**: อินพุตเป็นสตางค์ แต่ตัวเลขในโจทย์มักเป็นบาท (500 บาท = 50000, 40 บาท = 4000) แปลงให้ครบทุกค่าคงที่ รวมถึงอัตราต่อกิโลกรัม/ต่อกรัม
- **ลำดับขั้นตอน**: ทำตามลำดับที่โจทย์เขียน "ต่อจากข้อก่อน/ขั้นสุดท้าย/อีก" แปลว่าคูณซ้อนกัน ไม่ใช่บวกเปอร์เซ็นต์เข้าด้วยกัน
- **ฐานของเงื่อนไข**: เกณฑ์ เช่น "ยอดรวมตั้งแต่ 500 บาท" ตัดสินจากยอดก่อนลด ("ตั้งแต่/ขึ้นไป" = `>=`, "เกิน" = `>`, "ไม่เกิน" = `<=`, "ต่ำกว่า" = `<`)
- **เพดาน/ขั้นต่ำ**: เพดาน "ต่อบิล" ใช้กับค่าสุดท้ายหลังคูณตัวคูณทั้งหมด
- **การปัดเศษ**: ดูหัวข้อถัดไป

## กติกาปัดเศษและการตรวจอินพุต

ผลจากการทดลองที่ผ่านมา (คะแนน 0–1 ต่อข้อ จากโจทย์ซ่อน ~10 test ต่อข้อ):

| กติกา | t1 | t2 | t3 | t4 |
|---|---|---|---|---|
| ปัดครึ่งขึ้นตอนท้าย ไม่ตรวจอินพุต | 0.5 | 0.5 | 0.45 | – |
| **H: ปัดครึ่งขึ้นตอนท้าย + raise ValueError เมื่ออินพุตนอกช่วง** | **0.6** | **0.6** | **0.55** | **0.5** |
| ปัดลง / ปัดขึ้น / ปัดครึ่งขึ้นทุกขั้น | 0.2–0.4 | 0.4–0.5 | 0.27 | 0.3–0.4 |
| banker's ตอนท้าย | 0.4 | 0.4 | 0.36 | 0.4 |
| float + `round()` ทุกขั้น | 0.3 | 0.4 | 0.27 | 0.3 |

ข้อสรุป: **ปัดครึ่งขึ้น (`(2n+d)//(2d)`) ครั้งเดียวตอนท้าย บนเลขแม่นยำ (Fraction/จำนวนเต็ม) คือพื้นฐานที่ถูก**
และการตรวจอินพุตนอกช่วงให้ผลดีขึ้นทุกข้อ แต่ยังไม่เต็ม ส่วนที่ยังขาดน่าจะเป็นรายละเอียดของการตรวจอินพุตที่ยังไม่ครบ

### พื้นฐานที่ใช้เสมอ (แบบ H)
- คำนวณแม่นยำด้วย Fraction/จำนวนเต็มตลอด ปัดครึ่งขึ้นครั้งเดียวตอนท้ายสุด คืน `int`
- ห้ามปัดเศษระหว่างขั้น ยกเว้นขั้นที่โจทย์สั่งให้เป็นจำนวนเต็มจริง ๆ (เช่น การแจกสตางค์ที่เหลือตอนหารบิล)
- ตรวจอินพุตก่อนคำนวณ: ค่านอกช่วงที่โจทย์ระบุ (เช่น "ตั้งแต่ 1", "0–100", "1–30,000", "ตั้งแต่ 0") → `raise ValueError`; ค่าที่เป็นหมวด (เช่น tier) ที่ไม่อยู่ในรายการ → `raise ValueError`

### ส่วนที่ยังทดลอง: รายละเอียดการตรวจอินพุต
ดูชื่อโฟลเดอร์ทำงานปัจจุบัน (`pwd`) ว่าลงท้ายด้วย `-r1`, `-r2` หรือ `-r3` (ถ้าไม่เจอ ให้ใช้ r1) แล้วเพิ่มจากพื้นฐาน H ดังนี้:

| ลงท้าย | การตรวจอินพุตเพิ่มเติม |
|---|---|
| `-r1` | **H1**: ชนิดข้อมูลผิด (None, str, bool ในที่ที่ต้องเป็นตัวเลข, float ในที่ที่ต้องเป็นจำนวนเต็ม เช่น qty/people/tip_percent/price/amount/total) → `raise TypeError`; ช่วงผิด → `ValueError`; list ว่างหรือ 0 รายการยังคืนค่าตามสูตร (เช่น 0) |
| `-r2` | **H2**: อะไรก็ตามที่ผิด (ชนิดผิด, ช่วงผิด, คีย์ใน dict หาย, flag ที่ไม่ใช่ bool, list ว่างที่โจทย์ให้ "ตั้งแต่ 1 รายการ") → `raise ValueError` อย่างเดียวทุกกรณี |
| `-r3` | **H3**: เหมือน H1 แต่ list ว่าง/ไม่มีรายการ → `raise ValueError` และ flag ที่ไม่ใช่ bool (เช่น 1, "yes", None) → `raise TypeError` |

ค่าตัวเลขที่เป็นหน่วยต่อเนื่อง (distance_km, weight_g) รับทั้ง int และ float ได้ แต่ไม่รับ bool/str/None
ค่า NaN/inf ให้ `raise ValueError`

กรณีหารบิล: ปัดเศษเฉพาะตอนคิดยอดรวมหลังทิปให้เป็นสตางค์ แล้วค่อยหารและแจกสตางค์ที่เหลือให้คนแรก ๆ (`divmod`); ผลรวมของ list ต้องเท่ากับยอดรวมเสมอ

ในคำตอบสุดท้ายให้ระบุว่าใช้ H1/H2/H3 เพื่อให้อ่านย้อนจาก trace ได้

## ข้อควรระวังอื่น

- ถ้าค่าอยู่ในช่วงที่โจทย์รับรองให้คืนค่าเสมอ
- อย่าเปลี่ยนชนิดที่คืน: ต้องเป็น `int` (ไม่ใช่ float / Fraction) และ list ของ `int` ถ้าโจทย์ขอ list
- ไม่ต้องสร้างไฟล์อื่นนอกจาก `solve.py` (ไฟล์ทดสอบชั่วคราวลบทิ้งหรือไม่ต้องเก็บ)
