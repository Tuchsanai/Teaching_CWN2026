# เขียนฟังก์ชันคิดเงินให้ถูกทั้งค่าและการ reject

ตัวตรวจรันเทสต์ 4 กลุ่ม: **Normal / Boundary / NoDrift / Reject** · rollout ก่อนหน้า logic ถูกแต่ได้แค่ 0.3–0.6 เพราะ
1. **ไม่ validate input เลย** → กลุ่ม Reject ตกหมด (เสียไปประมาณครึ่งหนึ่งของคะแนน)
2. **ปัดเศษผิด** (ใช้ `//` ปัดลง ทั้งที่ควร half-up) → กลุ่ม NoDrift ตก
3. ไม่ได้เขียน `test_solve.py` ไว้คู่กับ `solve.py`

## ขั้นตอน
1. อ่านโจทย์ทีละบรรทัด จดกฎเป็นลำดับ (ลดก่อน/บวก VAT ทีหลัง ฯลฯ) และดูว่าเงื่อนไขเป็น `>=` หรือ `>` ("ตั้งแต่ X ขึ้นไป" = `>=`, "เกิน X" = `>`, "ไม่เกิน X" = `<=`, "ต่ำกว่า X" = `<`)
2. แปลงหน่วยเป็นสตางค์ทุกค่า (บาท × 100) และ % เป็น `Fraction(n, 100)`
3. คำนวณด้วย `fractions.Fraction` ล้วน ห้ามใช้ float, ห้ามปัดกลางทาง · **ปัดครั้งเดียวตอนท้าย** แบบ half-up
   - โจทย์ไม่ได้ระบุวิธีปัด → ใช้ half-up (ปัดครึ่งขึ้น) **ไม่ใช่ floor/`//`** และไม่ใช้ `round()` ของ Python (เป็น banker's rounding)
   - ถ้ามีเพดาน (min/max) ให้ปัดก่อนแล้วค่อย `min(...)` ตามเฉลย; เพดาน/ขั้นต่ำเทียบเป็นสตางค์
   - ค่าที่เป็นส่วนของหน่วย (เช่น กรัมที่เกิน × บาท/กก.) ให้คิดเป็น Fraction ตามสัดส่วนจริง ไม่ปัดเป็นกิโลก่อน
4. **Validate input ทุกตัว ก่อนคำนวณ** แล้ว `raise ValueError` (ดู template) — ห้าม raise TypeError/KeyError
   - จำนวนเต็ม: `type(v) is int` (ปฏิเสธ float, str, bool, None) แล้วเช็กช่วงตามโจทย์ ("ตั้งแต่ 0" → `low=0`, "ตั้งแต่ 1" → `low=1`, "0–100" → `low=0, high=100`)
   - bool: `type(v) is bool` (ปฏิเสธ 0/1/"true")
   - enum (เช่น tier): `type(v) is str and v in ตาราง` — ค่าที่ไม่รู้จักต้อง ValueError
   - list/dict: เช็ก `type(items) is list`, แต่ละ item เป็น `dict`, มี key ครบ, ค่าใน key ผ่านกฎ int+ช่วง (เช่น qty ≥ 1, price ≥ 0) · list ว่างตามโจทย์ถ้าไม่ห้ามก็ให้ผ่าน
   - ช่วงที่โจทย์ระบุ (เช่น น้ำหนัก 1–30,000) ถือเป็นข้อบังคับ ต้อง reject นอกช่วง
   - **ห้ามใส่ default ให้ parameter** (เช่น `express=False`) — ใช้ signature ตามโจทย์ตรง ๆ
5. เขียน `test_solve.py` (unittest) ข้างกับ `solve.py` — ดูโครงใน `template_test.py` · epoch ก่อนหน้า solve.py ถูกต้องแล้วแต่ได้ 0.9 ไม่เต็ม ซึ่งน่าจะเหลือที่คุณภาพของชุดเทสต์ จึงให้เขียนเทสต์ให้ "จับบั๊กได้จริง":
   - แยกเป็น 4 class: `Normal`, `Boundary`, `NoDrift`, `Reject` แต่ละ case เป็น method แยก (`test_normal_1`, `test_boundary_2`, ...) อย่างน้อย Normal 3 · Boundary 3 · NoDrift 2 · Reject 4+
   - ค่าคาดหวังต้อง **คำนวณมือ/เขียนเป็นตัวเลขตายตัว** ห้ามเรียกฟังก์ชันตัวเองหรือสูตรเดียวกับโค้ดมาสร้างค่าคาดหวัง (ยกเว้นเสริมเป็นรอบที่สองด้วย Fraction)
   - Boundary: **ทุก threshold ต้องทดสอบทั้งสองฝั่ง** (t−1, t, t+1) ด้วยค่าที่ผลต่างกันจริง เช่น ขั้นต่ำ 10000 ต้องมีเทสต์ที่ 9999→0 และ 10000 (และ 10001) → ไม่ใช่ 0 · ถ้าเพดานมีอยู่ ต้องมีเคสที่ยังไม่ชนเพดาน เคสพอดีเพดาน และเคสเกินเพดาน · ค่าต่ำสุด/สูงสุดของช่วง (0, 1, 30000, people=1, tip 0 และ 100)
   - NoDrift: เลือกค่าที่ก่อนปัดลงท้าย .5 พอดี หรือ .4/.6 เพื่อแยก half-up ออกจาก floor/round()/ปัดสองรอบ แล้วใส่ค่ากลาง 1 ข้อที่ต้อง "รวมก่อนปัดครั้งเดียว" (ถ้าปัดทีละขั้นผลจะต่างกัน)
   - Reject: ครบทุก parameter ทุกชนิด — ต่ำกว่าช่วง (qty 0, ติดลบ), สูงกว่าช่วง (tip 101, น้ำหนัก 30001), float ที่ค่าเป็นจำนวนเต็ม (`4500.0`), str (`'3'`), bool (`True`), None, enum แปลก, และ item ที่ขาด key / ไม่ใช่ dict ถ้ามี list
   - รัน `python3 -m unittest -q test_solve` ให้ผ่าน แล้วลอง "ทำลาย" โค้ดตัวเองสั้น ๆ 2–3 จุด (เปลี่ยน `>=` เป็น `>`, เปลี่ยน half_up เป็น floor) เพื่อดูว่าเทสต์ล้มจริง ถ้าไม่ล้มให้เพิ่มเคส แล้วคืนโค้ดเดิม
6. ผลลัพธ์ต้องเป็น `int` ของ Python จริง ๆ (ไม่ใช่ Fraction/float)

## Template (`template_solve.py` สำหรับ solve.py · `template_test.py` สำหรับ test_solve.py)
คัดลอกโครงจาก `template_solve.py` แล้วแทนเฉพาะตัวฟังก์ชันหลัก · ท้ายไฟล์มี `main()` อ่าน JSON จาก stdin → พิมพ์ `{"ok":..., "result":...}` ให้คงไว้ (exit code 2 เมื่อ ValueError/TypeError)

## กฎของโจทย์ประเภท "หารเป็นงวด"
- รวมก่อนแล้วปัดครั้งเดียว จากนั้น `divmod(grand, people)` ให้คนแรก ๆ ได้ +1 สตางค์ตามจำนวน `extra`; ผลรวมของ list ต้องเท่ากับยอดรวมเสมอ

## อย่าทำ
- อย่าสรุปว่า "ผ่านแล้ว" จากการลองไม่กี่ค่า โดยไม่ได้เทสต์ reject และขอบ
- อย่าเดาวิธีปัดเป็น floor แล้วแค่บอกผู้ใช้ท้ายคำตอบ — เลือก half-up ตั้งแต่แรก
