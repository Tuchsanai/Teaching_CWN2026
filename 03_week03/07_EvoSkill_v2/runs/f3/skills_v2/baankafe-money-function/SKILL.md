# เขียนฟังก์ชันคิดเงินของ BaanKafe ให้ผ่านเทสต์ที่ซ่อนอยู่

ข้อมูลจากรอบที่แล้ว: โค้ดที่ Solver เขียนโดยไม่มีสกิล **คำนวณตัวเลขถูกเกือบหมด** แต่ได้คะแนนแค่ ~0.4–0.5
เพราะ (1) ไม่ตรวจ input เลย (เทสต์กลุ่ม Reject ตกทุกข้อ) และ (2) พลาด "นโยบายร้าน" ที่ไม่เขียนในโจทย์
(ดูสกิล `baankafe-known-policies`) เทสต์จริงมี 4 กลุ่ม: Normal, Boundary, NoDrift (เศษสตางค์/การปัด), Reject (ต้อง raise ValueError)

## ข้อบังคับที่ถูกลืมบ่อยที่สุด: ต้องมี CLI `main()` ใน solve.py ทุกครั้ง
ข้อมูล epoch 1: ทุกครั้งที่ตรรกะถูกหมดและ validate ครบ แต่ solve.py **ไม่มี `main()` + `if __name__ == "__main__"`**
ได้แค่ 0.7 ส่วนที่มี `main()` แบบแม่แบบได้ 0.9 — มาตรฐานของร้านคือ solve.py รันเป็นโปรแกรมได้ด้วย:
`echo '{"amount":20000,"tier":"gold","birthday":true}' | python3 solve.py` →
stdin เป็น JSON object ที่ key = ชื่อพารามิเตอร์ของฟังก์ชัน (เรียก `fn(**args)`),
สำเร็จ → พิมพ์ `{"ok": true, "result": <int หรือ list>}` exit code 0,
ValueError/TypeError → พิมพ์ `{"ok": false, "error": "..."}` exit code 2
**ให้คัดลอก `main()` จาก `solve_template.py` ทั้งก้อน เปลี่ยนแค่ `example_fn` เป็นชื่อฟังก์ชันของโจทย์** (ห้ามตัดทิ้งแม้โจทย์ไม่ได้พูดถึง)
ใส่ docstring ของโมดูลและของ helper อธิบายนโยบาย/การปัดเป็นภาษาไทยด้วย (เฉลยอ้างอิงมีทั้งหมด)

## ขั้นตอน
1. อ่านโจทย์ → อ่านสกิล `baankafe-known-policies` ดูว่างานนี้ (หรืองานคล้ายกัน) มีนโยบายแฝงไหม
2. คัดลอก `solve_template.py` (อยู่โฟลเดอร์สกิลนี้) มาเป็น `./solve.py` แล้วเขียนฟังก์ชันตามโจทย์ ชื่อฟังก์ชัน/พารามิเตอร์ต้องตรงโจทย์เป๊ะ
3. เขียนเทสต์สั้น ๆ รันเอง: ค่ากลาง, ขอบเขต (พอดี / ต่ำกว่า 1 หน่วย), เศษสตางค์, input ผิด
4. ไฟล์ต้องอยู่ที่ `./solve.py` import ได้โดยไม่มี side effect (ส่วน main ใส่ใน `if __name__ == "__main__"`)
5. ตรวจ CLI ก่อนจบ: `echo '<json ตัวอย่าง>' | python3 solve.py` ต้องได้ `{"ok": true, ...}` และกรณี input ผิดต้องได้ `{"ok": false, ...}` exit 2
   (หมายเหตุ: `python3 -I` ไม่ใส่ cwd ใน path → import solve ไม่เจอ ให้ใช้ `PYTHONPATH=. python3 -c ...` แทน)
6. เขียน `test_solve.py` (unittest: Normal/Boundary/NoDrift/Reject) ไว้ข้าง solve.py ด้วย ใช้ค่าจากตัวอย่างในสกิล known-policies

## กติกาตรวจ input (สำคัญที่สุด — เสียคะแนนมากสุดรอบก่อน)
ทุกพารามิเตอร์ต้องตรวจ แล้ว `raise ValueError` (ไม่ใช่ TypeError/AssertionError/KeyError):
- จำนวนเต็ม (สตางค์, qty, people, น้ำหนัก, ระยะทาง, เปอร์เซ็นต์): ต้อง `type(v) is int` — **ปฏิเสธ float (เช่น 10000.0), str ('3'), bool (True)**, None
- ช่วงตามโจทย์: "ตั้งแต่ 0" → ติดลบ reject · "ตั้งแต่ 1" → 0 และติดลบ reject · "1–30,000" → นอกช่วง reject · "0–100" → นอกช่วง reject
- flag (member, express, birthday): ต้อง `type(v) is bool` (ปฏิเสธ 0/1/"True")
- ค่า enum (เช่น tier): ต้องเป็น `str` และอยู่ในรายการที่โจทย์ให้ (ตัวพิมพ์ตามโจทย์) — ค่าที่ไม่รู้จัก/ไม่ใช่ str → ValueError (ระวัง tier ที่ unhashable เช่น list: เช็ค type ก่อน `in`)
- list/dict: `items` ต้องเป็น list, แต่ละตัวเป็น dict ที่มี key ครบ, ค่าในนั้นตรวจแบบเดียวกัน (price ≥ 0, qty ≥ 1) ไม่ใช่ dict/ขาด key → ValueError
- ตรวจ input ให้ครบ **ก่อน** คำนวณหรือคืนค่าก่อนเวลา (เช่นกรณี 0 / ยอดต่ำกว่าขั้นต่ำ ก็ยังต้อง validate ก่อน)
- list ว่าง `[]`: โจทย์ไม่ห้าม → ถือยอดรวม 0 (ไม่ error) เว้นแต่โจทย์สั่ง

## การคำนวณและการปัดเศษ
- ห้ามใช้ float ทั้งหมด ใช้ `fractions.Fraction` (หรือจำนวนเต็มล้วน) คูณทุกขั้นให้ครบแล้ว **ปัดครั้งเดียวตอนจบ** (ห้ามปัดระหว่างขั้น เว้นแต่โจทย์สั่งชัด)
- เปอร์เซ็นต์ → Fraction(95,100) ฯลฯ ; "คูณต่อจากข้อก่อน" = คูณทบกัน ตามลำดับที่โจทย์เขียน (VAT ท้ายสุดเมื่อโจทย์บอกว่าสุดท้าย)
- ทิศทางการปัด เมื่อโจทย์ไม่ระบุ:
  - เงินที่ลูกค้า**จ่าย**ร้าน (ยอดบิล, ค่าส่ง, ทิป, ยอดหาร) → ปัดครึ่งขึ้น (half-up): `int((x*2+1)//2)` กับ Fraction ที่ไม่ติดลบ ไม่ใช่ `round()` ของ Python (ปัดแบบ banker's)
  - เงินที่ร้าน**จ่ายออก**ให้ลูกค้า (เงินคืน cashback, รางวัล) → ปัดลง (floor)
- หารเท่า ๆ กัน: `base, extra = divmod(total, n)` → `extra` คนแรกจ่าย base+1 ผลรวมต้องเท่ายอดเดิมเสมอ

## การอ่านขอบเขตในโจทย์ภาษาไทย
- "บาท" → ×100 เป็นสตางค์ เช่น 500 บาท = 50000, 100 บาท = 10000, 200 บาท = 20000
- "ตั้งแต่ X ขึ้นไป" / "ไม่เกิน X" → รวม X · "เกิน X" / "ต่ำกว่า X" → ไม่รวม X
- "ส่วนที่เกิน 5,000 กรัม กิโลกรัมละ 15 บาท (ตามสัดส่วนของกรัม)" → (w-5000)×1500/1000 สตางค์ ต่อกรัม ไม่ปัดเป็นกิโล
- เงื่อนไขที่ใช้กับยอด: ใช้ยอดรวมก่อนลด (subtotal) ตามที่โจทย์ระบุ ไม่ใช่ยอดหลังลด
- เพดาน (สูงสุด) ใช้หลังคูณตัวคูณทั้งหมดและหลังปัด

## เมื่อโจทย์เงียบเรื่องกรณีมุม
อย่าเดาแบบง่ายที่สุดแล้วจบ ลองถามตัวเองตามนี้ (ร้านจริงมักมีนโยบายแฝง):
- ค่าเป็น 0 (ระยะ 0, ยอด 0) แปลว่าอะไรในทางธุรกิจ? (รับเองที่ร้าน → ไม่คิดค่าส่ง)
- มีสิทธิ์/ขีดจำกัดตามระดับหรือบริการหรือไม่? (ระดับต่ำสุดอาจไม่ได้โบนัส; บริการด่วนอาจรับน้ำหนักไม่เกินค่าหนึ่ง)
- ตัวเลขที่โจทย์ให้ช่วงกว้าง แต่บริการบางแบบอาจรับแค่ช่วงย่อย → นอกช่วงให้ ValueError
ดู `baankafe-known-policies` ก่อน ถ้างานตรงกับรายการนั้น ให้ใช้นโยบายนั้น
