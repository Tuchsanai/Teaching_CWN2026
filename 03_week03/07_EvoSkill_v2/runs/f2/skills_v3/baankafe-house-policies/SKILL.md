# กฎร้านที่โจทย์ไม่ได้บอก (ใช้ตัดสินใจเมื่อโจทย์เงียบ)

โจทย์ BaanKafe สั้น แต่เทสต์ตรวจ "มาตรฐานร้าน" ที่ซ่อนอยู่ด้วย Solver ถามกลับไม่ได้ จึงต้องใช้กฎด้านล่าง
ก่อนเขียนโค้ด ถามตัวเองว่า: **กรณีขอบ/ข้อยกเว้นใดที่ร้านจริงต้องมี แต่โจทย์ไม่ได้พูดถึง?**

## ข้อกำหนดรูปแบบไฟล์ (ทุกโจทย์)
`solve.py` ต้องมี `main()` แบบ stdin JSON → stdout JSON ตามแม่แบบใน `baankafe-money-function` เสมอ (ขาด = เสียคะแนน) และมี `test_solve.py` คู่กัน

## หลักทั่วไป
1. input ที่ผิดชนิดหรือนอกช่วง → `ValueError` (รายละเอียดใน `baankafe-money-function`)
2. ยอดที่ลูกค้าจ่าย → ปัดครึ่งขึ้น; เงินที่ร้านจ่ายออก (เงินคืน) → ปัดลง
3. เศษหารไม่ลงตัวในการแบ่ง: แจกทีละ 1 สตางค์ให้คนแรก ๆ ผลรวมต้องเท่ายอดเดิมเสมอ
4. ยอด 0 เป็นค่าที่ถูกต้อง (บิล 0 บาท → [0,0,...])
5. สิทธิพิเศษ/ตัวคูณที่เป็น "โบนัส" ของระดับต่ำสุดมักไม่ได้รับ และบริการพิเศษ (ส่งด่วน) มักมีเพดานน้ำหนัก; ค่าส่งที่ไม่ต้องส่งจริง (ระยะ 0) = 0 — ถ้าเงื่อนไขแบบนี้เป็นไปได้กับโจทย์ ให้ใช้ตามรายการด้านล่าง

## นโยบายที่ทราบแล้วต่อฟังก์ชัน (ใช้เมื่อโจทย์ตรงกัน)
- **cafe_bill(items, member)**: เกณฑ์ลด 5% คือ `subtotal >= 50000` สตางค์; ลดแล้วคูณ member 0.90 ต่อ; VAT ×1.07 ท้ายสุด; half_up ครั้งเดียว; `price >= 0` (0 ได้), `qty >= 1`; items เป็น list ของ dict
- **split_bill(total, people, tip_percent)**: `grand = half_up(total*(100+tip)/100)`; `base, extra = divmod(grand, people)`; คน `extra` คนแรกได้ base+1; total>=0, people>=1, tip 0–100 (int)
- **shipping_fee(weight_g, distance_km, express)**: weight 1–30000, distance>=0 (ทั้งคู่ int ไม่ใช่ float/bool); **distance_km == 0 = ลูกค้ารับเองที่ร้าน → ค่าส่ง 0** (แม้ express); **express และ weight_g > 20000 → `ValueError`** (ส่งด่วนรับไม่เกิน 20,000 กรัม); ขั้นน้ำหนัก ≤1000 → 4000, ≤5000 → 8000, เกินกว่านั้น 8000 + 1.5 สตางค์ต่อกรัมส่วนเกิน (1500 สตางค์/กก.) ด้วย Fraction; ระยะ > 100 ×1.2; express ×1.5; half_up ครั้งเดียวตอนท้าย
- **cashback(amount, tier, birthday)**: amount>=0 int; tier ∈ silver/gold/platinum (str) ไม่งั้น ValueError; `amount < 10000` → 0; อัตรา 1.5%/2.5%/4% ด้วย Fraction; **เดือนเกิด ×2 เฉพาะ gold และ platinum (silver ไม่ได้สิทธิ์)**; ปัดลง แล้ว `min(..., 20000)`

## ลำดับการตัดสินใจในฟังก์ชัน (ใช้กับทุกโจทย์)
1. ตรวจชนิด/ช่วงของ **ทุก** พารามิเตอร์ก่อน → 2. ตรวจข้อจำกัดของบริการพิเศษ (ถ้าผิด `ValueError` แม้ผลจะเป็น 0) → 3. คืนค่าลัด (0 / ต่ำกว่าเกณฑ์) → 4. คำนวณด้วย Fraction ตามลำดับในโจทย์ → 5. ปัดครั้งเดียว → 6. เพดาน/เพดานต่ำ

## กรณีโจทย์ใหม่ที่ไม่อยู่ในรายการ
- ใช้หลักทั่วไป + เทียบกับรูปแบบข้างบน (ขอบ "ไม่เกิน/ตั้งแต่", ค่า 0, ข้อจำกัดของบริการพิเศษ, สิทธิ์ระดับล่างสุด, เพดานต่อบิล)
- ถ้าเลือกตีความกฎที่โจทย์ไม่ระบุ ให้เลือกแบบที่เป็นปกติของร้านจริงและไม่ทำให้ input ที่โจทย์อนุญาตชัดเจน (ในช่วงที่ระบุ) พัง
- อย่าตีความว่า "ช่วงที่โจทย์ให้" เป็นแค่คำแนะนำ — ค่านอกช่วงคือ `ValueError`
