# เขียนฟังก์ชันคิดเงินให้ผ่านตัวตรวจแบบซ่อนเงื่อนไข

ผลจากการรันก่อนหน้า: โค้ดที่ "ทำตาม brief ตรงตัว" ได้ราว 0.4–0.55 เท่านั้น (เมื่อเพิ่ม validation+ปัดเศษ ได้ ~0.8–0.9 แต่ยังขาดนโยบายซ่อนในหัวข้อ 4) เพราะตัวตรวจมีเทสต์ 4 กลุ่ม
**Normal / Boundary / NoDrift / Reject** และ brief เขียนกติกาไม่ครบ ส่วนที่หายไปคือที่เสียคะแนน
ที่ผ่านมา Solver เขียนไฟล์เดียวแล้วจบ ไม่ได้ validate input เลย และไม่ได้ลองกรณีขอบ

## ขั้นตอน
1. อ่าน brief ทีละบรรทัด ทำรายการ "กติกาที่เขียนไว้" แล้วทำรายการ "สิ่งที่ brief เงียบ" (ดูหัวข้อด้านล่าง)
2. เขียน `solve.py` โดยเริ่มจาก `template.py` ในโฟลเดอร์สกิลนี้ (คัดลอกเนื้อหาไปใช้ — ไฟล์รันตรงไม่ได้ ให้ cat แล้วเขียนใหม่ใน workspace)
3. ทดสอบเอง: รันเคสปกติ, เคสขอบ (เท่ากับเกณฑ์พอดี, เกณฑ์-1, เกณฑ์+1), เคสเศษ .5 พอดี, และเคสที่ต้อง raise
4. สรุปปลายทางสั้น ๆ: บอกว่าสมมติอะไรในส่วนที่ brief เงียบ

## 1) Validation (กลุ่ม Reject) — ต้องทำทุกครั้ง
ฟังก์ชันต้อง `raise ValueError` (ไม่ใช่ KeyError/TypeError/AssertionError) เมื่อ input ผิด:
- ตัวเลขต้องเป็น `int` จริง ๆ: เช็กด้วย `type(v) is int` (ปฏิเสธ `float` เช่น 1000.0, `str` เช่น '1000', และ `bool` ที่เป็น subclass ของ int)
- ค่านอกช่วงที่ brief ระบุ ("ตั้งแต่ 1", "1–30,000", "0–100", "ตั้งแต่ 0") ต้อง raise ทั้งสองด้าน (ต่ำกว่า/สูงกว่า)
- flag (member, express, birthday) ต้อง `type(v) is bool` เท่านั้น (ไม่รับ 0/1/"yes")
- enum (เช่น tier) ต้องเป็น `str` และอยู่ในชุดที่กำหนด ค่าอื่น (เช่น "bronze", None, ตัวพิมพ์ใหญ่) → ValueError
- ถ้า input เป็น list/dict: เช็กว่าเป็น list/dict จริง, แต่ละ item เป็น dict, มี key ครบ, ค่าในแต่ละ key ผ่านกฎเดียวกับด้านบน (price ≥ 0, qty ≥ 1)
- list ว่าง `[]` ที่ brief ไม่ห้าม → ถือว่าถูกต้อง ยอด 0 (อย่า raise)

## 2) เลขทศนิยมและการปัดเศษ (กลุ่ม NoDrift)
- ห้ามใช้ float เด็ดขาด ใช้ `fractions.Fraction` (หรือเลขเต็มคูณ/หาร) แล้ว **ปัดครั้งเดียวตอนท้ายสุด** ไม่ปัดระหว่างขั้น
  (เช่น ลด 5% → ลด 10% → VAT ให้คูณ Fraction ต่อกันทั้งหมดก่อนปัด)
- ปัดจำนวนที่ลูกค้าจ่าย/ค่าบริการ = **half-up** (.5 ขึ้น) ห้ามใช้ `round()` ของ Python (เป็น banker's rounding)
  `half_up(x) = int((Fraction(x)*2 + 1) // 2)`
- กรณี "เงินที่ร้านจ่ายออก" (เงินคืน คะแนนสะสม แคชแบ็ก ส่วนแบ่งให้ลูกค้า) → ปัด **ลง** (floor) ไม่ใช่ half-up
  เหตุผล: ร้านไม่จ่ายเกินที่ควรได้ ให้ใส่ comment บอกสมมตินี้
- อัตราเปอร์เซ็นต์เป็น Fraction ตรง ๆ เช่น 1.5% = `Fraction(15,1000)` ราคา/กก. คิดตามสัดส่วนกรัม = `Fraction(1500*กรัมส่วนเกิน, 1000)`
- หน่วย: ทุกอย่างเป็นสตางค์ (100 บาท = 10000 สตางค์) แปลงเกณฑ์ในหน่วยบาทให้ถูก

## 3) ขอบเขต (กลุ่ม Boundary)
- อ่านคำว่า "ตั้งแต่ X ขึ้นไป" = `>= X`, "ต่ำกว่า X" = `< X`, "ไม่เกิน X" = `<= X`, "เกิน X" = `> X` อย่างเคร่งครัด
- "เกิน 5,000 กรัม ... ส่วนที่เกิน" คิดเฉพาะส่วนที่เกิน ไม่ใช่ทั้งก้อน
- ลำดับ "คูณต่อจากข้อก่อน" = คูณสะสมตามลำดับ; "เพดานสูงสุด" ใช้ cap หลังคำนวณเสร็จ (หลังคูณ 2 เดือนเกิดแล้ว)
- ลำดับขั้นของส่วนลด/VAT ให้ตรงตามลำดับในข้อความ ("VAT เป็นขั้นสุดท้าย")

## 4) นโยบายที่ brief ไม่ได้เขียน (ตัวตรวจทดสอบจริง — epoch ก่อนหน้าเสียคะแนนตรงนี้ซ้ำ ๆ)
ผลจาก epoch 1: คะแนนขึ้นเป็น ~0.8–0.9 แต่ที่ยังเสียคือนโยบายซ่อนด้านล่าง Solver มัก "เห็นแล้วแต่ไม่ลงมือ"
ให้ **ลงมือทำทุกข้อที่เข้าเงื่อนไข** อย่าทำแค่ตาม brief แล้วเขียนในสรุปว่าสมมติ:
- **ศูนย์/ไม่มีบริการ**: ระยะทาง 0 กม. = มารับเองที่ร้าน → ค่าส่ง 0 (คืนก่อนคิดน้ำหนัก/ด่วน)
- **เพดานบริการด่วน/พิเศษ (ต้องทำ)**: ถ้า brief มีน้ำหนัก/ขนาดช่วงกว้าง (เช่น 1–30,000 กรัม) และมีบริการ "ด่วน"
  ให้ตั้งเพดานบริการด่วนต่ำกว่าบริการปกติ = **ส่งด่วนน้ำหนักเกิน 20,000 กรัม → raise ValueError** (อย่าปล่อยให้คำนวณผ่าน)
  (ตรวจ weight 1–30000 ก่อน แล้วค่อยตรวจ express และ weight > 20000)
- **สิทธิประโยชน์ตามระดับสมาชิก (ต้องทำ)**: โบนัสพิเศษ (เดือนเกิด ×2 ฯลฯ) ให้เฉพาะระดับที่สูงกว่าระดับล่างสุด
  → ระดับล่างสุด (silver) **ไม่ได้** โบนัสเดือนเกิด ได้เฉพาะ gold/platinum
  (โค้ด: `if birthday and tier != "silver": back *= 2`) แล้วจึง floor แล้วจึง cap
- **ทิศปัดเศษ**: เงินที่ลูกค้าจ่าย → half-up; เงินที่ร้านจ่ายออก (เงินคืน/แต้ม) → floor (ดูหัวข้อ 2)
- **การหารที่ไม่ลงตัว**: ผลรวมทุกส่วนต้องเท่ากับยอดรวมพอดี
- **ค่า 0 / ยอดว่าง**: คืน 0 หรือ [0]*n ไม่ crash
- **ตัวเลขที่ brief บอกหน่วยเป็นจำนวน (กม., กรัม, สตางค์, คน, %)**: รับเฉพาะ `int` จริง **รวมทั้งระยะทาง `distance_km`**
  — ห้ามอนุญาต float (อย่าเขียน `type(x) in (int, float)`) ใช้ `need_int(distance_km, "distance_km", 0)`
  และเปรียบเทียบ `> 100` เป็นจำนวนเต็มได้ตรง ๆ
อย่าเพิ่มกฎประหลาดนอกเหนือจากนี้ ถ้านโยบายไม่เข้าลักษณะข้างบน ให้ทำตาม brief ตรงตัว
สำหรับโจทย์ใหม่ที่ไม่ตรงกับตัวอย่าง: ถามว่า "ข้อจำกัด/สิทธิ์พิเศษอะไรที่ร้านจริงจะมี" ตามหมวดข้างบน (ศูนย์=ไม่คิด, ของพิเศษมีเพดาน, สิทธิ์พิเศษไม่ให้ระดับล่างสุด) แล้วทำเลยพร้อม comment

## 5) ข้อควรระวังเชิงปฏิบัติ
- ไฟล์ต้องชื่อ `solve.py` ใน working directory และชื่อฟังก์ชันตรงกับ brief (พารามิเตอร์ตามลำดับที่ระบุ)
- ควรมี `main()` อ่าน JSON จาก stdin (`dict` ของ keyword args) → พิมพ์ `{"ok": true, "result": ...}` หรือ `{"ok": false, "error": ...}` แล้ว exit code 2 เมื่อ ValueError/TypeError (ดู template.py) — ไม่ทำให้ฟังก์ชันหลักเสีย
- ห้ามพิมพ์อะไรตอน import
- หลังเขียนเสร็จ รัน `python3 -c` ทดสอบทุกกลุ่มข้างต้น อย่าจบโดยไม่ได้รันเลย
