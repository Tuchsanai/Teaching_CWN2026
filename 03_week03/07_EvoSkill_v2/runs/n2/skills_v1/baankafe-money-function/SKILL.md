# เขียน solve.py ฟังก์ชันคิดเงิน

ผลงานจะถูกตรวจด้วยชุดเทสต์ 4 กลุ่ม: **Normal** (ค่าปกติ), **Boundary** (ขอบเงื่อนไข เช่น `>=` vs `>`), **NoDrift** (เศษสตางค์ต้องถูกเป๊ะ), **Reject** (input ผิดต้อง `raise ValueError`) · rollout ที่ผ่านมาได้แค่ ~0.5 เพราะเขียนแค่สูตรตามโจทย์ ไม่ตรวจ input และไม่รู้นโยบายที่โจทย์ไม่ได้เขียน (ดูสกิล `baankafe-policy-conventions`)

## ขั้นตอน
1. อ่านสกิล `baankafe-policy-conventions` ก่อนเขียน แล้วไล่ดูว่ากฎข้อไหนเข้ากับโจทย์
2. คัดลอก `solve_template.py` (อยู่โฟลเดอร์เดียวกับสกิลนี้ ใช้ `cat` อ่านแล้วเขียนลง `solve.py` ในโฟลเดอร์ทำงาน) แล้วแก้ฟังก์ชันหลัก ใช้ชื่อฟังก์ชัน/พารามิเตอร์ตรงตามโจทย์เป๊ะ
3. เขียนเทสต์เองสั้น ๆ แล้ว **รันจริง** (`python3 -m unittest` หรือสคริปต์ assert) อย่างน้อย: ค่าปกติ, ค่าที่ขอบทั้งสองข้าง, ค่าที่ทำให้เกิดเศษสตางค์, input ผิดชนิด/ผิดช่วง · คำนวณคำตอบที่คาดด้วยมือ/Fraction แยกจากโค้ด อย่าลอกสูตรเดียวกัน
4. ในสรุปท้ายงาน ระบุสมมติฐานที่ใช้ตอนโจทย์เงียบ (ไม่มีผู้ใช้ให้ถามระหว่างทาง ต้องตัดสินใจเองตามสกิลนี้)

## กฎการคิดเลข
- ใช้ `fractions.Fraction` และเลขจำนวนเต็มเท่านั้น **ห้าม float** (เช่น `* 0.95`, `round()` ของ Python ที่ปัดแบบ banker's ก็ห้าม)
- ทำตามลำดับขั้นที่โจทย์เรียง ("คูณต่อจากข้อก่อน", "VAT เป็นขั้นสุดท้าย") และ **ไม่ปัดระหว่างทาง** ปัดครั้งเดียวตอนท้าย (ยกเว้นโจทย์สั่งปัดชัด ๆ เช่นหารบิลที่ต้องได้สตางค์เต็มต่อคน)
- ปัดเศษ: เงินที่ลูกค้าจ่าย → `half_up` · เงินที่ร้านจ่ายออก (เงินคืน) → `round_down` (รายละเอียดในสกิลนโยบาย)
- หน่วยเงินใน input/output คือสตางค์ (1 บาท = 100 สตางค์) แปลงเกณฑ์ที่เป็นบาทเป็นสตางค์ให้ถูก เช่น 500 บาท = 50000
- เงื่อนไข "ตั้งแต่ X ขึ้นไป" = `>= X`, "เกิน X" = `> X`, "ไม่เกิน X" = `<= X`, "ต่ำกว่า X" = `< X`
- หารบิล/แบ่งเศษ: `divmod` แล้วให้คนแรก ๆ ได้ +1 ผลรวมต้องเท่ายอดรวมเสมอ

## กฎการตรวจ input (กลุ่ม Reject — เสียคะแนนมากถ้าขาด)
ทุกพารามิเตอร์ต้องตรวจก่อนคิด แล้ว `raise ValueError(...)` เมื่อผิด:
- จำนวนเต็ม: ต้อง `type(v) is int` — **`True/False`, `float` (เช่น `4500.0`), `str` (เช่น `"3"`) ต้องถูกปฏิเสธ** (`isinstance(v, int)` ไม่พอเพราะ bool ผ่าน)
- ช่วงค่า: ใช้ช่วงที่โจทย์ระบุ ("ตั้งแต่ 1" → `>=1`, "0–100" → `0..100`, "1–30,000" → `1..30000`) ราคาติดลบ/จำนวน 0 ต้อง reject
- bool: ต้อง `type(v) is bool` (ไม่รับ 0/1/"yes")
- enum (เช่น tier): ต้องเป็น `str` และอยู่ในชุดที่กำหนดเท่านั้น ถ้าไม่รู้จัก → ValueError (ห้าม KeyError)
- list/dict: ตรวจชนิด และตรวจสมาชิกทุกตัว (`items` ต้องเป็น list, แต่ละตัวเป็น dict ที่มี key ครบและค่าถูกชนิด) key หายต้อง ValueError ไม่ใช่ KeyError
- ชนิดที่ผิดต้องให้ `ValueError` เท่านั้น ไม่ใช่ TypeError/KeyError/AttributeError

## ส่วน main()
แม่แบบมี `main()` อ่าน JSON object จาก stdin (`{"ok": true, "result": ...}` / `{"ok": false, "error": ...}` exit 2 เมื่อผิด) ให้คงไว้ เพราะอาจถูกเรียกแบบ CLI · ต้อง import `solve` ได้โดยไม่รันอะไรเอง (ใช้ `if __name__ == "__main__"`)
