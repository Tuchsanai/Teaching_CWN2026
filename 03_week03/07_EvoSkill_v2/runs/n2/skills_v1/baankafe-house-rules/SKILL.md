# กติการ้าน BaanKafe (จากเฉลยคะแนนเต็มที่ผู้ใช้อนุญาตให้ดู)

โจทย์ของ BaanKafe เขียนสั้น แต่เฉลยมี "นโยบาย" ที่ไม่ได้อยู่ในโจทย์ Solver ที่ไม่รู้จะเสียคะแนนใน Boundary/NoDrift ทุกครั้ง ให้ใช้กติกานี้เป็นค่าเริ่มต้น และเมื่อเจอโจทย์ใหม่ของร้านเดียวกันให้คิดแบบเดียวกัน

## 1) การปัดเศษ
| กรณี | วิธี |
|---|---|
| ยอดที่ลูกค้า **จ่าย** (บิล, VAT, ค่าส่ง, ยอดรวมรวมทิป) | ปัดครึ่งขึ้น (half-up) ที่สตางค์ **ครั้งเดียวตอนจบ** |
| เงินที่ร้าน **จ่ายออก/ให้ลูกค้า** (เงินคืน cashback, รางวัล, แต้ม, refund) | **ปัดทิ้ง (floor)** — ร้านไม่จ่ายเกินสิทธิ์ |
| เศษจากการหารคน | แจกคนแรก ๆ คนละ 1 สตางค์ (divmod) |
| ขีดจำกัดสูงสุด (cap) | ปัด/คำนวณก่อน แล้ว `min(cap, ค่า)` |

ไม่ปัดระหว่างขั้นตอน (เช่น หลังลด 5% แล้วลด 10% แล้ว VAT ให้คูณ 95/100·90/100·107/100 แล้วปัดครั้งเดียว) เว้นแต่โจทย์สั่งชัด

## 2) เกณฑ์ "ตั้งแต่/ต่ำกว่า/เกิน"
- "ตั้งแต่ X ขึ้นไป" → `>= X`; "ต่ำกว่า X" → `< X` (ได้ 0); "ไม่เกิน X" → `<= X`; "เกิน X" → `> X`
- เกณฑ์เป็นบาท ต้องแปลงเป็นสตางค์ (×100) ก่อนเทียบ และเทียบกับ **ยอดก่อนลด** (subtotal) เมื่อโจทย์ว่า "ยอดรวม"
- ขั้นบันไดชนิด "เกิน 5,000 กรัม บวกส่วนที่เกิน" → คิดเฉพาะส่วนเกิน `(w-5000)` ตามสัดส่วน ไม่ใช่ปัดเป็นกิโล

## 3) เฉลยที่ตรวจแล้วของโจทย์ที่เคยเจอ (ใช้ตรงๆ ได้)

### cafe_bill(items, member)
- subtotal = Σ price×qty (price ≥0 int, qty ≥1 int; ปฏิเสธ qty 0/ลบ, float, str)
- subtotal ≥ 50000 → ×95/100; member → ×90/100; สุดท้าย ×107/100; half-up
- items ต้องเป็น list, member ต้องเป็น bool
- ตัวอย่าง: [{4500×2}],False → 9630; True → 8667; [{49999×1}] → 53499; [{50000×1}] → 50825; [{4505×1}],True → 4338

### split_bill(total, people, tip_percent)
- ตรวจ total ≥0 int, people ≥1 int, tip_percent 0–100 int
- grand = half_up(total×(100+tip)/100) — ปัด **ยอดรวมทีเดียว** ไม่ปัดทิปแยก (ปัดแยกทำให้ผิดในบางเคส)
- base, extra = divmod(grand, people); คืน `[base+1]*extra + [base]*(people-extra)`
- ตัวอย่าง: (10000,3,0)→[3334,3333,3333]; (10000,7,10)→[1572,1572,1572,1571,1571,1571,1571]; (2,3,0)→[1,1,0]

### shipping_fee(weight_g, distance_km, express)
- ตรวจ weight_g int 1–30000, distance_km int ≥0, express bool
- **นโยบายซ่อน S2**: express และ weight_g > 20000 → `raise ValueError` (ส่งด่วนรับไม่เกิน 20,000 กรัม)
- **นโยบายซ่อน S1**: distance_km == 0 → คืน 0 (ลูกค้ารับเองที่ร้าน) — ตรวจ input/S2 ก่อนแล้วค่อยคืน 0
- ฐาน: ≤1000 → 4000; ≤5000 → 8000; เกิน → 8000 + 1500×(w-5000)/1000 (Fraction)
- distance > 100 → ×120/100; express → ×150/100 ต่อจากนั้น; half-up ครั้งเดียว
- ตัวอย่าง: (3000,150,False)→9600; (5106,150,True)→14686; (5217,50,True)→12488; (1001,10,False)→8000

### cashback(amount, tier, birthday)
- ตรวจ amount int ≥0, tier ∈ {silver,gold,platinum} (str), birthday bool
- amount < 10000 → 0 (หลังตรวจ input)
- อัตรา silver 15/1000, gold 25/1000, platinum 4/100
- **นโยบายซ่อน C1**: เดือนเกิดคูณ 2 เฉพาะ gold และ platinum — **silver ไม่ได้สิทธิ์** (ยังได้ 1.5% ปกติ)
- **นโยบายซ่อน C2**: ปัดทิ้ง (floor) ไม่ใช่ half-up; cap = min(20000, floor(...)); 
- ตัวอย่าง: (10015,platinum,True)→801; (10020,gold,True)→501; (20000,platinum,True)→1600; (20000,silver,False)→300; (500000,platinum,False)→20000

## 4) เมื่อเจอโจทย์ใหม่ของ BaanKafe (ไม่ใช่ 4 ข้อข้างบน)
ถามตัวเองตามรายการนี้แล้วเลือกค่าเริ่มต้นตามร้าน:
1. เงินที่ลูกค้าจ่าย → half-up; เงินที่ร้านให้ → floor
2. ค่าที่เป็น 0 / กรณี "รับเอง/ไม่มีของ/ไม่มียอด" ควรได้ 0 หรือไม่ (เช่น ระยะ 0 = ฟรี)
3. มีสิทธิ์/โปรโมชันบางระดับที่ไม่ควรได้สิทธิ์ซ้อน (ระดับต่ำสุดมักไม่ได้โบนัสพิเศษ)
4. มีเพดานการให้บริการ (น้ำหนัก/จำนวน) ของบริการพิเศษ เช่น ด่วน ที่ควร reject
5. ลำดับ "คูณต่อจากข้อก่อน" = คูณสะสมตามลำดับที่เขียน
ถ้าโจทย์ระบุกติกาไว้ชัด **โจทย์ชนะเสมอ** ข้อสันนิษฐานข้างต้นใช้เฉพาะช่องว่างที่โจทย์ไม่พูดถึง และให้เขียนข้อสันนิษฐานเป็นคอมเมนต์ใน solve.py กับสรุปท้ายคำตอบ
