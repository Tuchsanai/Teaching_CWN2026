# เขียนฟังก์ชันคิดเงินให้ผ่านตัวตรวจที่ซ่อนอยู่

ตัวตรวจของโจทย์กลุ่มนี้ทดสอบ 4 หมวด: **Normal** (ค่าทั่วไป), **Boundary** (ค่าที่ขอบเงื่อนไขพอดี),
**NoDrift** (เศษทศนิยม/ปัดเศษ ต้องตรงสตางค์) และ **Reject** (input ผิดต้อง raise `ValueError`)
โจทย์ไม่ได้เขียนเรื่อง Reject และการปัดเศษไว้ตรง ๆ แต่ตัวตรวจเช็กเสมอ — rollout ก่อนหน้าที่ข้ามสองเรื่องนี้ได้คะแนนแค่ ~0.3–0.5

## ขั้นตอน
1. อ่านโจทย์ ทำรายการ: พารามิเตอร์ + ชนิด + ช่วงที่ยอมรับ, กฎแต่ละข้อ, ลำดับการคำนวณ
2. คัดลอก `template.py` ในโฟลเดอร์สกิลนี้ (`cp <path-ของสกิล>/template.py solve.py`) แล้วแก้เฉพาะฟังก์ชันหลัก
   ต้องวางไฟล์ที่ `solve.py` ใน working directory และชื่อฟังก์ชันตรงกับโจทย์เป๊ะ
3. เขียนเทสต์สั้น ๆ ของตัวเองครอบคลุมทั้ง 4 หมวด แล้ว **รันจริง** ก่อนจบ (อย่าจบโดยไม่ได้รัน)
4. ตอบสรุปสั้น ๆ ว่าตีความเงื่อนไขกำกวมอย่างไร

## 1) ตรวจ input — raise ValueError (ห้ามปล่อยเป็น TypeError/ผ่านเงียบ ๆ)
- จำนวนเต็มต้อง `type(v) is int` เท่านั้น: **ปฏิเสธ float (แม้ 1000.0), str ('3'), bool (True), None**
- ตรวจช่วงตามโจทย์: "ตั้งแต่ 0" → `>= 0`, "ตั้งแต่ 1" → `>= 1`, "1–30,000" → `1 <= v <= 30000`, "จำนวนเต็ม 0–100" → `0..100`
  ค่าลบ, 0 ในที่ที่ต้อง ≥1, เกินช่วงบน → ValueError
- พารามิเตอร์ bool (member, express, birthday) ต้อง `type(v) is bool`
- enum (เช่น tier) ต้องเป็น `str` และอยู่ในรายการที่โจทย์ให้ มิฉะนั้น ValueError (ระวัง unhashable เช่น list ใน `in dict`: เช็ก type str ก่อน)
- list ของ dict (items): ต้องเป็น `list`, ทุกสมาชิกเป็น `dict`, ตรวจ field ทุกตัว (`.get` แล้ว need_int) — key ขาด → ValueError
  list ว่างให้คืน 0 (ถ้าโจทย์ไม่ห้าม) ไม่ใช่ error
- ตรวจ **ก่อน** ทำ short-circuit ใด ๆ (เช่น ก่อน `if amount < 10000: return 0`) เพื่อให้ input ผิดถูก reject เสมอ

## 2) การปัดเศษ — ห้ามใช้ float, ห้าม floor/`round()`
- เงินทั้งหมดเป็นสตางค์ (int). 1 บาท = 100 สตางค์ — แปลงเกณฑ์ในโจทย์เป็นสตางค์ให้ถูก (500 บาท = 50000, 100 บาท = 10000, 200 บาท = 20000)
- คำนวณด้วย `fractions.Fraction` (เปอร์เซ็นต์ 7% = `Fraction(107,100)`, 1.5% = `Fraction(15,1000)`)
- **ปัดครึ่งขึ้น (half-up) เป็นจำนวนเต็มสตางค์ ครั้งเดียวตอนท้าย** ด้วย `half_up` ใน template
  - ห้ามใช้ `//` ตรง ๆ (ปัดลง), ห้ามใช้ `round()` ของ Python (banker's rounding), ห้ามใช้ float
  - ห้ามปัดระหว่างขั้นตอน ถ้าโจทย์ไม่สั่ง (ส่วนลดหลายขั้น/VAT/ตัวคูณ คูณต่อกันเป็น Fraction แล้วปัดตอนท้าย)
  - ถ้าโจทย์บอกให้ได้ยอดเป็นจำนวนเต็มก่อนแล้วค่อยแบ่ง (เช่นหารบิล) ให้ปัด half-up ที่ "ยอดรวมที่ต้องหาร" ก่อน แล้วค่อยแบ่งด้วยจำนวนเต็ม
- cap/ขั้นต่ำ (min/max) ใช้กับค่าหลังคำนวณตามลำดับที่โจทย์เขียน: เช่น คำนวณ → ปัดครึ่งขึ้น → `min(cap, ...)`
- การหารไม่ลงตัวที่โจทย์สั่ง "คนแรก ๆ จ่ายเพิ่ม 1 สตางค์": `base, extra = divmod(grand, n)`; `[base+1]*extra + [base]*(n-extra)` ผลรวมต้องเท่ากับ grand เสมอ

## 3) ตีความเงื่อนไขและขอบ (Boundary)
| ถ้อยคำในโจทย์ | เงื่อนไข |
|---|---|
| ตั้งแต่ X / X ขึ้นไป | `>= X` |
| เกิน X / มากกว่า X | `> X` |
| ไม่เกิน X / ไม่มากกว่า X | `<= X` |
| ต่ำกว่า X / น้อยกว่า X | `< X` |
| สูงสุด X | `min(X, v)` |
- เกณฑ์ "ยอดรวม" ให้เทียบกับยอดรวมก่อนส่วนลดใด ๆ เว้นแต่โจทย์ระบุอย่างอื่น
- "ลดอีก 10%" / "คูณต่อจากข้อก่อน" / "บวกเพิ่ม" = **คูณต่อกันตามลำดับ** (×0.95 แล้ว ×0.90) ไม่ใช่บวกเปอร์เซ็นต์รวมกัน
- "บวกตามสัดส่วน" (เช่น ส่วนที่เกินกิโลละ 15 บาท คิดตามกรัม) = `Fraction(rate * excess, unit)` ไม่ปัดเป็นกิโลเต็ม
- "ขั้นสุดท้าย" (เช่น VAT) = คูณเป็นขั้นตอนสุดท้ายก่อนปัด
- ทำตามถ้อยคำและลำดับในโจทย์ตรง ๆ อย่าเพิ่มกฎที่โจทย์ไม่ได้บอก

## 4) ทดสอบก่อนจบ
เขียน `test_solve.py` (unittest) อย่างน้อย: ค่าปกติ 3 ค่า (คำนวณมือแยกอิสระ), ค่าที่ขอบทั้งสองฝั่ง (X-1 และ X),
เคสเศษครึ่งสตางค์พอดีที่ half-up กับ floor ให้ผลต่างกัน, และ Reject: ค่าลบ, 0, float, str, bool, enum ผิด
รัน `python3 -m unittest -q test_solve` ให้ผ่านทั้งหมด

## 5) ตรวจรอบสุดท้ายก่อนส่ง (ผลรอบก่อนผ่านเทสต์พื้นฐานหมดแล้ว เหลือรายละเอียดเหล่านี้)
- **ตัวเลขทุกตัวที่โจทย์ให้หน่วยเป็นสตางค์/กรัม/กม./คน/ชิ้น/เปอร์เซ็นต์จำนวนเต็ม ให้รับเฉพาะ `int`** ถ้าโจทย์ไม่ได้บอกว่าเป็นทศนิยม
  (เช่น `distance_km` ให้ปฏิเสธ float; อย่าเปิดรับ float เองเพราะ "โจทย์ไม่ได้ห้าม") — ใช้ `need_int` กับทุกพารามิเตอร์ตัวเลข
- ทดสอบเพิ่ม: `True`/`False` ส่งเข้าช่องตัวเลข, `None`, `float('nan')`, `float('inf')`, ค่าใหญ่มาก (10**12) ต้องไม่ crash ด้วย error ชนิดอื่น
- ทดสอบ CLI จริงด้วย subprocess: `echo '{"...": ...}' | python3 solve.py` ต้องได้ `{"ok": true, "result": ...}` และ input ผิดได้ `{"ok": false, ...}` exit code 2
- ผลรวม/ค่าที่คืนต้องเป็น `int` ล้วน (ไม่ใช่ `Fraction`/float/bool) และ list ที่คืนต้องเป็น `list` ของ `int`
- เหลือไฟล์ใน working directory เฉพาะที่จำเป็น: `solve.py` (+ `test_solve.py` ของตัวเองได้) ไม่ทิ้งไฟล์ชั่วคราว/`__pycache__` ที่ไม่จำเป็น
- ทำความสะอาด `solve.py` ที่คัดลอกจาก template: เปลี่ยน docstring บรรทัดแรกให้บอกว่าฟังก์ชันนี้คืออะไร (อย่าทิ้งคำว่า "template"), ลบ helper ที่ไม่ได้ใช้ (เช่น `need_bool` ถ้าไม่มีพารามิเตอร์ bool), ไม่เหลือ `FUNCTION_NAME`/`TODO`
- ใส่ CLI test (subprocess) และเคสค่าใหญ่ 10**12 ไว้ใน `test_solve.py` ด้วย เพื่อให้ไฟล์เทสต์ที่ส่งมาครบทั้งฟังก์ชัน ขอบ การปัดเศษ reject และ CLI; ไฟล์เทสต์ต้องรันผ่านด้วย `python3 -m unittest -q test_solve`
- รายงานสุดท้ายให้สั้น ตรงความจริง: บอกว่าเทสต์อะไรรันแล้วผ่านจริง และข้อสมมติที่ตีความเอง (ไม่อ้างสิ่งที่ไม่ได้รัน)

## หมายเหตุ
- ไม่ต้องมี dependency ภายนอก ใช้ stdlib (`fractions`) เท่านั้น
- ใน template มี `main()` อ่าน JSON จาก stdin → พิมพ์ `{"ok":..., "result":...}` ทิ้งไว้ได้ (ไม่รบกวนการ import)
