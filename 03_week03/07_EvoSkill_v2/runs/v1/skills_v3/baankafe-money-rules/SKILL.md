# กติกาคิดเงินแบบสตางค์ (BaanKafe)

## 1. เลขต้องแม่นยำ ไม่มี float
- ใช้ `fractions.Fraction` หรือจำนวนเต็มล้วน (คูณก่อนหารเสมอ) — ห้าม `*0.95`, `/100` แบบ float, ห้าม `round()` (ปัดแบบ banker's)
- เปอร์เซ็นต์ → `Fraction(95,100)`, `Fraction(107,100)` ฯลฯ
- คูณตามลำดับที่โจทย์เขียน (เช่น ลดตามยอด → ลดสมาชิก → VAT เป็นขั้นสุดท้าย) แล้ว**ปัดครั้งเดียวตอนจบ** ห้ามปัดระหว่างทาง
- เงื่อนไขตามเกณฑ์ ("ตั้งแต่ 500 บาท") เทียบกับยอดก่อนลดเป็นสตางค์ (500 บาท = 50000) และ "ตั้งแต่/ขึ้นไป" = `>=`, "เกิน" = `>`, "ไม่เกิน" = `<=` — แปลงบาท→สตางค์ให้ครบทุกค่าคงที่ (ขั้น, เพดาน, เกณฑ์ขั้นต่ำ)
- ค่า "ต่อกิโลกรัมคิดตามสัดส่วนกรัม" → `Fraction(rate * (g - base), 1000)` ไม่ปัดก่อนคูณต่อ

## 2. ทิศการปัดเศษ (โจทย์มักไม่บอก)
- เงินที่**ลูกค้าจ่าย** (บิล ค่าส่ง ยอดหารบิล) → ปัดครึ่งขึ้น: `int((x*2 + 1) // 2)` กับ Fraction ที่ไม่ติดลบ
- เงินที่**ร้านจ่ายออก** (เงินคืน cashback แต้ม) → **ปัดลง** (floor) ไม่ปัดครึ่งขึ้น
- ใช้เพดาน (`min(cap, ...)`) หลังปัดเสร็จ

## 3. หารบิล
- ยอดรวม = ปัดครึ่งขึ้นหนึ่งครั้งของ `total*(100+tip)/100` แล้ว `divmod(grand, people)`; คนแรก ๆ ได้ +1 เท่าจำนวนเศษ; ผลรวมของ list ต้องเท่ากับ grand เสมอ (ตรวจด้วย assert ตอนทดสอบ)

## 4. กฎแฝงที่โจทย์มักไม่เขียน — ตัดสินใจอย่างสมเหตุสมผลทางธุรกิจ
โจทย์สั้นแต่ตัวตรวจมีเคสขอบเชิงนโยบาย เมื่อ brief เงียบ ให้พิจารณาข้อเหล่านี้ทุกครั้ง แล้วเลือกตามเหตุผลทางธุรกิจที่เป็นธรรมชาติที่สุด และเขียนสมมติฐานไว้เป็น comment และสรุปให้ผู้ใช้ทราบ:
- **ศูนย์/ไม่มีบริการ**: ระยะทาง 0 กม. = ลูกค้ารับเองที่ร้าน → ค่าส่ง 0 ไม่ใช่ราคาขั้นต่ำ
- **ข้อจำกัดของบริการพิเศษ**: บริการด่วน/พิเศษมักมีเพดาน (เช่น น้ำหนักสูงสุดต่ำกว่าปกติ) — ถ้ามีเกณฑ์สูงสุดของบริการปกติ ให้คิดว่าบริการด่วนอาจรับได้น้อยกว่า (เช่น ≤ 20,000 กรัม แล้ว ValueError เมื่อเกิน)
- **สิทธิพิเศษแยกตามระดับสมาชิก**: โบนัส "เดือนเกิด ×2" ไม่ได้ให้ทุก tier — **ใช้ค่าเริ่มต้นนี้: silver ไม่ได้โบนัส ให้ gold/platinum เท่านั้น** (epoch 1: rollout ที่ให้ silver ×2 ตาม brief ตรงตัวถูกหักคะแนน ส่วนที่ไม่ให้ได้คะแนนเต็มส่วนนี้) อย่าเปลี่ยนใจเพราะ brief ไม่ได้ยกเว้น
- **เกณฑ์ขั้นต่ำก่อนได้สิทธิ์**: ตรวจเกณฑ์ขั้นต่ำก่อนคูณโบนัส และเพดานตอนท้าย
หลักคิด: ถ้ากฎใดดูแปลกถ้าใช้กับทุกกรณีอย่างตรงตัว (ศูนย์, ระดับล่างสุด, ค่าสูงสุดของช่วง) ให้ถามตัวเองว่าธุรกิจจริงจะทำอย่างไร

## 5. เช็กลิสต์ก่อนจบ
1. ฟังก์ชันชื่อและลำดับพารามิเตอร์ตรงตามโจทย์ใน `solve.py`
2. ทำตามสกิล `baankafe-strict-validation` ครบ
3. ทดสอบค่าขอบทั้งสองฝั่งของทุกเกณฑ์ (เช่น 49999/50000, 999/1000/1001, 9999/10000) และเคสที่ปัดครึ่งพอดี
4. ไม่มี float, ไม่มี `round()`
