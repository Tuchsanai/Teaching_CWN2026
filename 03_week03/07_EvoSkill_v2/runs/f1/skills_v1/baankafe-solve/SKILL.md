# วิธีทำโจทย์ฟังก์ชันคิดเงินของ BaanKafe

ตัวตรวจให้คะแนนด้วยเทสต์ซ่อน 4 กลุ่ม: **Normal / Boundary / NoDrift (เศษสตางค์ห้ามเพี้ยน) / Reject (input ผิดต้อง `raise ValueError`)**
ผลรอบที่ผ่านมา: สูตรคำนวณถูกเกือบหมด แต่ **เสียคะแนนครึ่งหนึ่งเพราะไม่ตรวจ input เลย** และพลาดกฎเฉพาะกรณีที่ร้านกำหนดแต่โจทย์ไม่ได้เขียน ห้ามเขียนแค่สูตรแล้วจบ

## ขั้นตอน (ทำทุกข้อ)
1. อ่านโจทย์ แยกให้ครบ: พารามิเตอร์ + ชนิด + ช่วงที่ยอมรับ, ลำดับการคำนวณ, เงื่อนไขขอบ (`ตั้งแต่`/`เกิน`/`ไม่เกิน`/`ต่ำกว่า` ต่างกัน), หน่วย (บาท vs สตางค์ — โจทย์มักให้เกณฑ์เป็นบาท แต่ input เป็นสตางค์ ให้คูณ 100)
2. คัดลอกแม่แบบ `./skills/baankafe-solve/template_solve.py` ไปเป็น `solve.py` แล้วเติมตรรกะ (มี helper ตรวจ input + ปัดเศษพร้อมใช้)
3. ใช้ `Fraction` / จำนวนเต็มล้วน **ห้ามใช้ float** ห้ามปัดเศษระหว่างทาง ปัดครั้งเดียวตอนจบ (ยกเว้นโจทย์สั่งให้ปัดขั้นกลางชัดเจน เช่น "ยอดที่ต้องหาร = ยอดบิลบวกทิป" ปัดเป็นสตางค์ก่อนแล้วค่อยหาร)
4. ใส่การตรวจ input ตามหัวข้อ "ตรวจ input" ด้านล่าง
5. พิจารณา "กฎเฉพาะกรณี" ด้านล่าง
6. เขียนเทสต์สั้น ๆ เองแล้วรัน (`python3 -c` หรือไฟล์ test แยกนอก solve.py) ครอบคลุม: ตัวอย่างปกติ, ค่าตรงขอบทั้งสองฝั่ง (เช่น 49999/50000, 999/1000/1001), ค่าที่ทำให้เกิดเศษครึ่งสตางค์, input ผิดทุกแบบ ตรวจด้วยมือว่าผลตรงกับที่คิดจากโจทย์
7. ใน solve.py ต้องมีฟังก์ชันชื่อตามโจทย์เป๊ะ import ได้โดยไม่มี side effect (ส่วน `main()` อ่าน JSON จาก stdin ให้ครอบด้วย `if __name__ == "__main__"`)

## ปัดเศษ (มาตรฐานร้าน)
- เงินที่ **ลูกค้าจ่าย/ร้านเรียกเก็บ** (บิล, ค่าส่ง, ยอดหารบิล) → **ปัดครึ่งขึ้น** (half-up) เป็นสตางค์: `int((Fraction(x)*2+1)//2)`
- เงินที่ **ร้านจ่ายออก** (เงินคืน/cashback/แต้ม/รางวัล) → **ปัดลง** (floor) ห้ามปัดขึ้น: `int(Fraction(x)//1)`
- ห้ามใช้ `round()` (ปัดแบบ banker's) และห้ามใช้ float
- เพดาน (max) ใช้หลังคำนวณ/คูณทวีคูณเสร็จ และเทียบกับค่าที่ปัดแล้วก็ได้ (`min(cap, floor(x))`)
- ส่วนลด/VAT/ค่าธรรมเนียมเป็นเปอร์เซ็นต์ → คูณต่อกันเป็น Fraction ตามลำดับที่โจทย์เขียน แล้วปัดครั้งเดียว
- หารคนแบบกระจายเศษ: `base, extra = divmod(grand, people)` คนแรก ๆ `extra` คนได้ `base+1`; ผลรวมต้องเท่ากับ grand เสมอ

## ตรวจ input (ส่วนที่เสียคะแนนมากที่สุด)
ทุกฟังก์ชันต้อง `raise ValueError` (ไม่ใช่ KeyError/TypeError/AssertionError และห้ามคืนค่าเงียบ ๆ) เมื่อ:
- ชนิดผิด: ใช้ `type(v) is int` — **ปฏิเสธ float (เช่น 4500.0), str (เช่น '2'), bool (True/False ไม่ใช่ int), None** แม้ค่าจะดูถูกต้อง
- flag ที่ควรเป็น True/False (`member`, `express`, `birthday`) ต้อง `type(v) is bool`
- นอกช่วงที่โจทย์ระบุ: เช่น จำนวนคน/จำนวนชิ้นต้อง ≥ 1, ยอดเงิน ≥ 0, น้ำหนัก 1–30000, tip 0–100 (ตรวจทั้งขอบล่างและขอบบน)
- ค่า enum ไม่อยู่ในรายการ (เช่น tier = "bronze") และ tier ที่ไม่ใช่ str (ตรวจ `type(tier) is str` ก่อน `in` เพื่อไม่ให้เกิด TypeError กับ unhashable)
- โครงสร้างผิด: `items` ไม่ใช่ list, สมาชิกไม่ใช่ dict, ขาด key (`item.get(...)` แล้วตรวจชนิด จะได้ ValueError ไม่ใช่ KeyError)
- ใส่การตรวจ **ก่อน** ลอจิกพิเศษใด ๆ (เช่น คืน 0 ก่อนเวลา) เพื่อให้ input ผิดถูกปฏิเสธเสมอ
- รายการว่าง `items=[]` ที่โจทย์ไม่ห้าม → ยอด 0 (ไม่ error) ยกเว้นโจทย์ระบุว่าต้องมีอย่างน้อย 1

## กฎเฉพาะกรณีของร้าน (โจทย์ไม่เขียน แต่เทสต์ซ่อนตรวจ)
ร้านมีนโยบายที่ไม่อยู่ในโจทย์ ถ้าเจอโจทย์เหล่านี้ (หรือคล้ายกัน) ให้ใช้ตามนี้:
- **cashback**: ยอด < 10000 สตางค์ → 0; เงินคืนปัดลง; เพดาน 20000 สตางค์; **เดือนเกิดคูณ 2 เฉพาะ gold และ platinum — silver ไม่ได้สิทธิ์เดือนเกิด** (นโยบาย C1)
- **shipping_fee**: **distance_km == 0 = ลูกค้ารับเองที่ร้าน → ค่าส่ง 0** (S1, ต้องตรวจ input ก่อน); **express=True และ weight_g > 20000 → ValueError** (S2); ขอบ 1000/5000 กรัมเป็น "ไม่เกิน" (รวมค่าขอบในขั้นล่าง); 100 กม. พอดีไม่คิดเพิ่ม (เกินจึงคิด)
- **cafe_bill**: เกณฑ์ลด 5% = ยอดรวม ≥ 50000 สตางค์ (ตรวจที่ยอดรวมก่อนส่วนลด); price ≥ 0, qty ≥ 1; ลำดับ: ลด 5% → ลดสมาชิก 10% → VAT 7%; ปัดครั้งเดียวตอนท้าย
- **split_bill**: grand = half_up(total × (100+tip)/100) แล้ว divmod; total ≥ 0, people ≥ 1, tip 0–100 จำนวนเต็ม

### เมื่อเจอโจทย์ใหม่ที่ไม่เคยเห็น
ก่อนเขียน ให้ถามตัวเองว่ามีกรณีพิเศษแบบเดียวกับข้างบนไหม แล้วเลือกตามหลักนี้:
1. ค่า 0 ของปริมาณที่ทำให้บริการไม่เกิดขึ้น (ระยะ 0, จำนวน 0) → มักไม่คิดเงิน
2. สิทธิพิเศษ/โบนัสบางระดับสมาชิก อาจไม่ใช้กับทุกระดับ — ระดับล่างสุดมักไม่ได้
3. บริการแบบด่วน/พิเศษ มักมีเพดานน้ำหนัก/ปริมาณต่ำกว่าบริการปกติ → เกินให้ ValueError
4. ถ้าโจทย์ไม่ได้ห้ามชัด ๆ ให้ทำตามถ้อยคำโจทย์ก่อน; กรณีไม่แน่ใจจริง ๆ ให้ปฏิเสธ (ValueError) ค่าที่ผิดปกติ/อยู่นอกขอบเขตธุรกิจ มากกว่าคืนตัวเลขเดา
5. เขียนกฎที่ตีความเองเป็นคอมเมนต์ในโค้ด และสรุปให้ผู้ใช้ในคำตอบสุดท้ายสั้น ๆ
