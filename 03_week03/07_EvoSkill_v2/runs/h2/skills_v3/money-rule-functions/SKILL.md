# การเขียนฟังก์ชันคำนวณเงินจากกติกาภาษาไทย

## ขั้นตอนหลัก

1. **แตกกติกาเป็นรายการ** เขียนทุกประโยคที่มีตัวเลขหรือเงื่อนไขเป็นข้อ ๆ ตามลำดับที่โจทย์เขียน ห้ามข้ามข้อ ห้ามรวมข้อโดยไม่ได้ตั้งใจ
2. **ล็อกสัญญาของฟังก์ชัน** ชื่อฟังก์ชัน ชื่อและลำดับพารามิเตอร์ ค่าเริ่มต้น และชนิดค่าที่คืนต้องตรงกับโจทย์ทุกตัวอักษร ชื่อไฟล์ให้ใช้ชื่อที่โจทย์ระบุ (เช่น `solve.py`) ในโฟลเดอร์ทำงานปัจจุบัน
3. **เลือกหน่วย** ถ้าโจทย์กำหนดหน่วยเป็นสตางค์ ให้รับและคืนค่าเป็นสตางค์ ถ้าอินพุตเป็นบาท ให้แปลงเป็นสตางค์ก่อนคำนวณ (1 บาท = 100 สตางค์)
4. **เขียนโค้ด** แล้วทดสอบตามหัวข้อการทดสอบด้านล่าง
5. **คำตอบสุดท้าย** ระบุไฟล์ ฟังก์ชัน กติกาที่ใช้ตามลำดับ ข้อสมมติฐานที่เลือกเอง และผลการทดสอบ

## ตารางคำไทยที่บ่งความหมาย

| คำหรือวลีในโจทย์ | ตีความเป็น |
|---|---|
| ตั้งแต่ ... ขึ้นไป, ไม่น้อยกว่า | `>=` (รวมค่านั้นเอง) |
| เกิน, มากกว่า | `>` (ไม่รวมค่านั้น) |
| ไม่เกิน, ไม่เกินกว่า | `<=` (รวมค่านั้นเอง) |
| ต่ำกว่า, น้อยกว่า | `<` (ไม่รวมค่านั้น) |
| ... เกินจาก X ส่วนที่เกิน, ส่วนที่เกิน X | คิดอัตราเฉพาะส่วนที่เกิน X ไม่ใช่คิดทั้งก้อน |
| คิดตามสัดส่วน, เศษของ ... | เชิงเส้น ไม่ปัดเป็นช่วงเป็นก้อน ให้คิดเป็นเศษส่วนก่อน |
| ลด X% อีก, คิดอีก, ต่อจากข้อก่อน | คูณต่อเนื่องกับยอดหลังข้อก่อน ไม่บวกอัตรารวมกัน |
| บวก X%, VAT X% | คูณด้วย (1 + X%) |
| เพดาน, สูงสุด ... ต่อบิล | cap ที่ค่าส่วนนั้นหลังใช้ตัวคูณทุกตัวที่ระบุก่อนหน้าในโจทย์ |
| N เท่า, สองเท่า | คูณด้วย N ก่อนนำไปเทียบเพดาน |
| ทิป X% | ยอดทิป = ยอด × X / 100 แล้วบวกเข้ายอดที่ต้องหาร |

**หลักการลำดับ:** ถ้าโจทย์เรียงกติกาไว้เป็นขั้น ให้คิดตามลำดับนั้น ยกเว้นโจทย์บอกชัดว่าเป็นอย่างอื่น
**หลักการเมื่อกำกวม:** เลือกการตีความที่ตรงตามตัวอักษรของโจทย์มากที่สุด แล้วบอกในคำตอบว่าเลือกอะไรและทางเลือกอื่นคืออะไร

### ค่าเริ่มต้นเมื่อโจทย์กำกวม (ใช้ตามนี้ เว้นแต่โจทย์บอกเป็นอย่างอื่น)

- **เกณฑ์ยอดซื้อ** (เช่น ยอดรวมตั้งแต่ 500 บาท) ใช้ยอดก่อนหักส่วนลดทุกชนิด
- **ส่วนลดหลายชั้น** คิดต่อเนื่องจากยอดที่เหลือ ไม่บวกเปอร์เซ็นต์รวมกัน
- **เพดาน** ใช้กับผลสุดท้ายของส่วนนั้น หลังคูณเท่าหรือคูณอัตราแล้ว
- **ทิป** รวมทิปเข้ากับยอดบิลเป็นเศษส่วนก่อน ปัดครึ่งขึ้นครั้งเดียวที่ยอดรวม แล้วจึงหารคน (ไม่ปัดทิปแยกต่างหาก)
- **ค่าที่อยู่ที่ขอบเขตพอดี** ทำตามเครื่องหมายในโจทย์ (ตั้งแต่/ไม่เกิน รวมค่านั้น, เกิน/ต่ำกว่า ไม่รวม)
- **การตีความที่เลือกต่างจากค่าเริ่มต้น** ให้ระบุในคำตอบพร้อมผลลัพธ์ของทางเลือกนั้นเสมอ

## รูปแบบกติกาที่พบบ่อย (ใช้ได้กับโจทย์ที่ไม่เหมือนตัวอย่าง)

- **ขั้นบันได:** "ไม่เกิน A ... เกิน A ไม่เกิน B ..." ให้ตีความเป็นช่วงที่ไม่ทับกัน และถ้าโจทย์ไม่ได้บอกว่าคิดทั้งก้อนหรือเฉพาะส่วนเกิน ให้ใช้ค่าคงที่ของช่วงนั้น แต่ถ้าโจทย์ใช้คำว่า "ส่วนที่เกิน" หรือ "คิดตามสัดส่วน" ให้คิดเฉพาะส่วนที่เกินเท่านั้น
- **ค่าขั้นต่ำและสูงสุด (clamp):** ค่าขั้นต่ำมักใช้กับยอดก่อนคำนวณ เช่น "ต่ำกว่า X ไม่ได้" คืน 0 หรือคิดเพิ่มให้ถึง X ตามที่โจทย์บอก ค่าสูงสุดใช้กับผลลัพธ์ของส่วนนั้นเป็นขั้นสุดท้าย
- **เปอร์เซ็นต์ของเปอร์เซ็นต์:** แปลงเป็นเศษส่วนก่อนคูณ เช่น 1.5% = `Fraction(15, 1000)` ไม่ปัดระหว่างทาง
- **แต้มสะสมหรือคะแนน:** ถ้าโจทย์ให้ "ทุก X บาท ได้ 1 แต้ม" ใช้การหารจำนวนเต็มลง (ปัดทิ้ง) เว้นแต่โจทย์บอกเป็นอย่างอื่น และต้องคิดจากหน่วยที่โจทย์กำหนด
- **ค่าติดลบ (การคืนเงิน/ลดหนี้):** ถ้าโจทย์ไม่ได้อนุญาตให้ติดลบ ให้ `raise ValueError` แต่ถ้าโจทย์ระบุวิธีคิดของค่าติดลบ ให้ทำตามนั้นและปัดแบบเดียวกันกับค่าบวก (half-up ที่ค่าสัมบูรณ์แล้วใส่เครื่องหมาย) เพื่อให้สมมาตร
- **วันที่หรือเดือน:** ถ้าเงื่อนไขเป็นเดือนหรือวัน ให้ใช้ค่าที่โจทย์ส่งมา (เช่น `birthday: bool`) ตามที่ระบุ อย่าสร้างการเดาวันที่จากเวลาปัจจุบัน
- **เงื่อนไขซ้อนกันหลายข้อ:** เขียนตารางค่าทดสอบที่ครอบคลุมทุกคู่ของเงื่อนไข (เช่น สมาชิก × เกณฑ์ × ค่าที่เกิน) อย่างน้อยหนึ่งกรณีต่อคู่

## สัญญาของฟังก์ชันและการส่งงาน

- ใช้ชื่อฟังก์ชัน ชื่อพารามิเตอร์ และลำดับพารามิเตอร์ตามโจทย์เป๊ะ อย่าเพิ่มพารามิเตอร์ที่โจทย์ไม่ได้กำหนด และอย่าใส่ค่าเริ่มต้นที่โจทย์ไม่ได้ให้ (โจทย์ที่เขียน `f(a, b)` ก็ให้เป็น `f(a, b)`)
- ค่าที่คืนต้องเป็น `int` จริง ไม่ใช่ `Fraction`, `Decimal` หรือ `float` และถ้าคืนลิสต์ ต้องเป็น `list` ตามลำดับคนที่โจทย์ระบุ
- ไฟล์ที่ส่งอยู่ในโฟลเดอร์ทำงานเริ่มต้น (ไม่ใช่ในโฟลเดอร์ `skills/`) และ import ได้โดยไม่ต้องติดตั้งอะไรเพิ่ม
- ถ้าโจทย์มีตัวอย่างผลลัพธ์ ให้ฟังก์ชันคืนค่าตรงทุกตัวอย่างก่อนทำอย่างอื่น

## ความแม่นยำของเงิน

- ห้ามใช้ `float` ในการคำนวณเงิน ใช้ `fractions.Fraction` ระหว่างทาง
- **ปัดครั้งเดียวที่ค่าที่คืน** เป็นจำนวนเต็มสตางค์ด้วย "ปัดครึ่งขึ้น" (half-up) เว้นแต่โจทย์ระบุ "ปัดทิ้ง/ปัดลง" หรือ "ปัดขึ้น" อย่าปัดในทุกขั้นเพราะจะทำให้ผลต่างไปทีละ 1 สตางค์
- การหารให้ลงตัวด้วย `divmod` แล้วกระจายเศษทีละ 1 สตางค์ให้คนลำดับต้น ๆ ตามที่โจทย์กำหนด

```python
import math
from fractions import Fraction

def to_frac(x):
    """รับได้ทั้ง int, float, Decimal โดยไม่เกิดคลาดเคลื่อนจาก float"""
    return Fraction(str(x))

def round_half_up(f):
    """ปัดครึ่งขึ้นเป็นจำนวนเต็ม ใช้ครั้งเดียวตอนคืนค่า (ยอดไม่ติดลบ)"""
    return math.floor(f + Fraction(1, 2))
```

## การรับอินพุต

- อย่าปฏิเสธค่าที่เป็นตัวเลขที่ถูกต้องเพียงเพราะชนิดไม่ใช่ `int` เช่น `10000.0` ควรรับได้
- `bool` ไม่ควรถูกนับเป็นตัวเลข (ตรวจด้วย `isinstance(x, bool)` ก่อนได้)
- ตรวจเฉพาะขอบเขตที่โจทย์ระบุ เช่น ค่าติดลบ ช่วง 0–100, ช่วงน้ำหนัก ค่าตัวเลือกที่ไม่รู้จักให้ `raise ValueError`
- ค่าที่อยู่ในขอบเขตที่โจทย์ระบุต้องคืนผลเสมอ ห้าม raise

## การทดสอบ

- **ห้ามใช้ `python3 -I` เมื่อต้อง import `solve` จากโฟลเดอร์ปัจจุบัน** โหมดนี้ตัด path ปัจจุบันออก ทำให้ `ModuleNotFoundError` ทั้งที่ไฟล์อยู่ตรงนั้น ใช้ `python3 solve.py` หรือ
  `python3 -c "import sys; sys.path.insert(0, '.'); from solve import f; print(f(...))"` แทน
- ทดสอบด้วยค่าที่คำนวณด้วยมือ (หรือด้วย `Fraction`) และเทียบให้ตรงทุกค่า
- ทดสอบค่าขอบเขต: เท่ากับเกณฑ์, เกณฑ์ -1 สตางค์, เกณฑ์ +1 สตางค์, ค่า 0, ค่าที่ชนเพดานพอดี, ค่าที่ผลลัพธ์เป็นครึ่งสตางค์พอดี
- ทดสอบลำดับการคิดด้วยค่าที่ผลต่างระหว่างลำดับต่างกัน เพื่อยืนยันว่าโค้ดคิดตามลำดับที่โจทย์กำหนด
- ตรวจว่าผลรวมของการหาร (ถ้ามี) เท่ากับยอดรวมพอดี

## ข้อผิดพลาดที่พบบ่อย

- ตีความ "เกิน" กับ "ตั้งแต่" สลับกัน ทำให้ค่าขอบเขตผิด
- บวกอัตราส่วนลดรวมกันแทนการคูณต่อเนื่อง
- คิดอัตราทั้งก้อนแทนการคิดเฉพาะส่วนที่เกิน
- ปัดเศษในทุกขั้น จนผลต่างไปทีละ 1 สตางค์
- ใช้ `float` หรือ `round()` ของ Python ซึ่งปัดแบบ banker's rounding (ปัดครึ่งเข้าเลขคู่) ไม่ใช่ครึ่งขึ้น
- ใส่ `assert` ที่ค่าคาดหวังผิด แล้วโค้ดพังตอนรัน จึงควรตรวจค่าคาดหวังด้วยมือก่อนเขียน
