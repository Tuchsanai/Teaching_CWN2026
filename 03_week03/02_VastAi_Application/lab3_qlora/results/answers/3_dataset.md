ขั้นที่ 3 เสร็จแล้วครับ ครูตอบครบ 570 บท ได้ Dataset 485 บท และลบเครื่อง `vapp-lab3-teacher` แล้ว ตรวจซ้ำแล้วไม่มีเครื่องป้าย `vapp-lab3*` เหลืออยู่ เครื่องป้ายอื่นไม่ได้แตะ และไม่ได้แสดงค่า key บนจอ

**โค้ด `make_dataset.py` ทำอะไร**
1. สร้าง system prompt จากข้อมูลร้านใน `code/web/db/init.sql` ให้ตรงกับ `buildSystemPrompt()` ของเว็บทุกตัวอักษร ต่างกันแค่ "วันเวลาปัจจุบัน" ที่ใช้ค่า `now` ของแต่ละบท
2. ส่งให้ครูตอบทีละข้อความแบบเดียวกับเว็บ คือ temperature 0.3, max_tokens 1024 และตัด `<think>` ออก ประวัติแชทเก็บคำตอบเต็มที่มีแท็กจอง ส่งพร้อมกันทีละ 8 บท คำตอบดิบเก็บไว้ที่ `data/teacher_raw.jsonl` ถ้าหยุดกลางทางก็ทำต่อจากที่ค้างได้
3. ตรวจคำตอบด้วยกติกาเดียวกับ `e2e/tests/check.ts` และตรวจ markdown กับแท็กจองเพิ่ม บทที่ผิดให้ตอบใหม่ตั้งแต่ข้อความแรกได้ 1 ครั้ง ถ้ายังผิดก็ทิ้งทั้งบท
4. สลับลำดับด้วย seed 7 แบ่ง 90/10 แล้วเขียนเป็น `messages` พร้อม `expects` และสรุปตัวเลขไว้ที่ `results/dataset_report.json`

### ข้อมูลจริง 1 รายการจาก Training Set (`q0416`) อธิบายทีละช่อง
```json
{"id":"q0416","kind":"english","kind_th":"ภาษาอังกฤษ","now":"2027-02-06 14:22",
 "messages":[{"role":"system","content":"คุณคือ \"น้องสบายใจ\" … (2,855 ตัวอักษร)"},
             {"role":"user","content":"What's the price of a foot reflexology massage?"},
             {"role":"assistant","content":"The price for a foot reflexology massage (45 minutes) is 300 baht."}],
 "expects":[{"has":["300"],"not":[],"lang":"en","booking":"none","no_markdown":true,
             "must":"ต้องมี 300 · ต้องยังไม่มีแท็กจอง · ตอบภาษาอังกฤษ"}],
 "retried":false}
```
| ช่อง | คืออะไร |
|---|---|
| `id` | รหัสบทเดียวกับใน `questions.jsonl` ใช้ตามกลับไปดูต้นทางได้ |
| `kind` / `kind_th` | ชนิดคำถาม ใช้นับจำนวนต่อชนิด |
| `now` | วันเวลาปัจจุบันของบทนี้ ใส่ไว้ใน system prompt เพื่อให้คิดคำว่า "พรุ่งนี้" หรือส่วนลดตามวันได้ถูก |
| `messages[0]` system | คำสั่งและข้อมูลร้านชุดเดียวกับที่เว็บส่งให้โมเดล โมเดลเล็กจึงเรียนกับ prompt เดียวกับที่จะใช้จริง |
| `messages[1]` user | ข้อความลูกค้า ซึ่งเป็นสิ่งที่โมเดลได้เห็น |
| `messages[2]` assistant | คำตอบของครูที่ผ่านการตรวจแล้ว ซึ่งเป็นสิ่งที่โมเดลเล็กต้องเรียนให้ตอบได้ (คิด loss เฉพาะส่วนนี้) |
| `expects[i]` | เงื่อนไขของคำตอบ assistant ข้อที่ i: `has` ต้องมี, `not` ห้ามมี, `lang` ภาษา, `booking` ต้องมีหรือห้ามมีแท็กจอง, `no_markdown` ห้ามใช้ markdown, `must` คำอธิบายภาษาคน ขั้นที่ 5 ใช้ช่องนี้วัดผลด้วย |
| `retried` | `true` ถ้าบทนี้ผ่านได้ตอนที่ให้ตอบใหม่ |

### ตัวอย่างคำถามกับคำตอบของครู 6 แถว (จาก Training Set)
| ชนิด | ลูกค้า | ครูตอบ (ย่อ) |
|---|---|---|
| ราคาและบริการ | อยากนวดยาว ๆ ทั้งตัวแบบไทยเต็มที่ครับ | แนะนำ "นวดไทยแผนโบราณ 2 ชั่วโมง" 120 นาที ราคา 600 บาท… |
| ส่วนลด | นักศึกษา 2 คน นวดน้ำมันหอมระเหยคนละครั้ง รวมเท่าไหร่ | 600 บาท ลด 15% เหลือ 510 บาทต่อคน … 2 คน รวม 1,020 บาทค่ะ |
| บริการที่ไม่มี | ร้านมีบริการพอกโคลนรึเปล่าคะ? | ขออภัยค่ะ ร้านไม่มีบริการพอกโคลน… (ไม่บอกราคาที่แต่งขึ้นเอง) |

**มี 2 จุดที่ทำต่างจากที่สั่งตรง ๆ**
- **ตัวเลขที่มีจุลภาค:** ตอนตรวจ ผมนับ "1,147.50" เป็นเลขเดียวกับ 1147.50 เพราะกติกาเดิมของ `check.ts` ตัดคำตอบที่เลขถูกแต่มีจุลภาคทิ้งไป ถ้าอยากให้ตรวจเข้มเท่า `check.ts` ให้ลบบรรทัดเดียวใน `contains()` แล้วรันสคริปต์ใหม่
- **คัดลอกไฟล์เข้า container:** ใน container ไม่มี `questions.jsonl` และ `init.sql` จึงคัดลอกจากโฟลเดอร์บนเครื่องนี้เข้าไปก่อนรัน แล้วคัดลอกผลกลับออกมา

**ข้อควรระวังสำหรับขั้นที่ 4:** คำถามภาษาอังกฤษผ่านแค่ครึ่งเดียว (25/50) และจองคิวแบบครบในข้อความเดียวผ่าน 17/40 เพราะครูมักตอบภาษาไทย หรือขอให้ยืนยันก่อนจอง สองชนิดนี้จึงมีตัวอย่างน้อยใน Dataset และโมเดลเล็กอาจยังพลาดเคสแบบนี้ (เช่นเคส #18) นอกจากนั้นมีบางบทที่ผ่านกติกาแต่เนื้อความขัดกันเอง เช่น `q0507` ข้อความบอกว่า "กรุณายืนยัน" แต่ใส่แท็กจองมาด้วย
