## สิ่งที่ทำ
- **โค้ด:** อยู่ใน `lab8_job_queue/code/`
  - `gateway.py` ทำตามสเปกทุกข้อ (POST /jobs, GET /jobs/{id}, GET /jobs, GET /stats) และเพิ่ม GET /health ที่ไม่ต้องใช้ key
  - `worker.py` ใช้ prompt และวิธีอ่านเดียวกับ `sync_api.py`
  - เพิ่ม `common.py` ไว้ประกาศคิวให้สองไฟล์ใช้ค่าเดียวกัน
  - คิวงานเป็น durable ข้อความ persistent จำกัด 1000 งาน (เกินแล้ว gateway ตอบ 503) งานที่พังไป dead-letter queue
  - Worker แจ้งสถานะกลับ gateway ผ่านคิว event และทุกตัวต่อ RabbitMQ ใหม่เองเมื่อการเชื่อมต่อหลุด
- **loadtest:** `loadtest.py` ถูกปรับให้ส่งผ่านคิว เก็บตัวเดิมไว้เป็น `loadtest_sync.py` ผลการวัดอยู่ใน `lab8_job_queue/results/queue_1worker/` มีความยาวคิวทุก 1 วินาทีอยู่ใน `queue_timeline`
- **ทดสอบ 1 งาน:** gateway ตอบ 202 ใน 0.03 วินาที งานเสร็จใน 11.0 วินาที อ่านใบเสร็จได้ 4/4 ใบ ส่งโดยไม่มี key ได้ 401

## ปัญหาที่เจอและแก้แล้ว
1. **RabbitMQ เปิดไม่ขึ้น** เพราะอ่านไฟล์ `/root/.erlang.cookie` ไม่ได้ จึงเปิดเป็นผู้ใช้ rabbitmq โดยตั้ง HOME ให้ถูก ตอนนี้ต้องสั่ง `rabbitmqctl` แบบ `cd /var/lib/rabbitmq; HOME=/var/lib/rabbitmq rabbitmqctl ...` ส่วนหน้า management ที่พอร์ต 15672 ใช้ได้ปกติ
2. **CUDA error 804 หลัง apt install:** ตอนติดตั้ง apt ไปสร้างแคชไลบรารีใหม่ ทำให้โปรแกรมไปเลือก libcuda ตัว compat ซึ่งใช้กับไดรเวอร์ 535 บน RTX 3090 ไม่ได้ ผมย้ายไฟล์ `/etc/ld.so.conf.d/00-compat-*.conf` ไปไว้ที่ `/root/ld.so.conf.d.disabled/` แล้วรัน `ldconfig` ใหม่ ถ้าใช้ apt ติดตั้งอะไรบนเครื่องนี้อีก ให้ตรวจเรื่องนี้ซ้ำ

**เครื่อง vapp-lab8 ยังเปิดอยู่และคิดเงินอยู่** RabbitMQ, gateway (พอร์ต 8000) และ Worker บน GPU 0 ยังรันอยู่ GPU ใบที่สองยังว่าง ส่วน API แบบ synchronous ปิดไปแล้ว
