Throughput ในตารางนับเฉพาะคำขอที่สำเร็จ

- **ทำไมรอบไม่ส่งซ้ำมีคำขอมากกว่า:** คำขอที่ล้มได้ error กลับทันที ผู้ใช้จึงส่งคำขอถัดไปได้เร็ว
- **ช่วงหลังเปิดคืนก็ยังมี error:** process ที่เพิ่งเปิดคืนตอบ 503 ระหว่างอุ่นโมเดล ถ้าไม่ส่งซ้ำ ผู้ใช้จะได้ 503 นี้ไปตรง ๆ
- **ทำไมกลับมาช้า:** server อุ่นโมเดลครบทุกขนาด batch 1–32 ก่อนรับงาน จึงใช้ราว 90 วินาที ผลรายวินาทีจึงยังเห็นแค่ replica 0 ไปจนถึงวินาทีที่ 45 หลังจากพร้อมแล้ว ผมยิงทดสอบ 8 คำขอ ได้ครบทั้ง 8 process รวม 9100–9103 ของ replica ที่เปิดคืน

**สิ่งที่เพิ่มในโค้ด** (แก้ใน container แล้วนำขึ้นเครื่องแล้ว)
- `cluster.sh`:
  - `kill <replica>` ปิดกะทันหันด้วย kill -9
  - `start <replica> [--wait]` เปิดคืนด้วยค่าเดิม
  - `up ... --retry on|off` เลือกว่าคำขอที่ล้มจะให้ NGINX ส่งต่อไป process อื่นหรือไม่ (รวม POST ด้วย)
- `loadgen.py`: เพิ่มโหมด `--users N --duration S --at "วินาที:คำสั่ง" --track gpu1` เก็บผลรายวินาที (คำขอที่สำเร็จแยกตาม replica, error, p95, การใช้ GPU)
- `run_failover.sh`: สคริปต์รันทั้ง 2 รอบ

**ปัญหาที่เจอระหว่างทาง 2 เรื่อง** (ผล 2 ชุดแรกใช้ไม่ได้ ลบทิ้งแล้วรันใหม่)
1. **ตัวยิงโหลดเดิมมี bug:** แต่ละ process รอ thread แค่ 15 วินาทีนับจากเริ่มยิง process ที่มีผู้ใช้คนเดียวจึงเลิกยิงก่อนเวลา ทำให้กราฟดูเหมือนตกที่วินาทีที่ 15 และหยุดที่วินาทีที่ 30 แก้แล้ว
   - bug นี้น่าจะกระทบผลเก่าที่ N=1 และ N=4 ด้วย (รวม gpu2 และ base1) Throughput ระดับนั้นน่าจะต่ำกว่าจริงราว 1 ใน 3 ส่วนค่าความจุไม่ได้ใช้ระดับนั้นตัดสิน ผมยังไม่ได้รันผลเก่าใหม่
2. **CPU ของเครื่องจำกัดที่ ~26 core** แม้จะมองเห็น 192 core ตอนเปิด replica คืน torch เปิด thread เต็มจนทั้งเครื่องถูกจำกัด CPU และ replica 0 ช้าลงไปด้วย ตอนนี้ `start` เปิดคืนแบบลดลำดับความสำคัญ CPU (nice 10) และจำกัดไว้ process ละ 2 thread
