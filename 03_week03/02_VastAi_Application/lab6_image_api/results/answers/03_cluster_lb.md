ตัวเปิดระบบเขียนเสร็จแล้ว และเปิดระบบแบบพื้นฐานบนเครื่อง vapp-lab6 (RTX 3090 × 2) ได้แล้ว ทดสอบจากนอกเครื่องผ่านพอร์ต 8080 ผ่านครบทั้ง 3 ข้อ

## โค้ด `lab6_image_api/code/cluster.sh`
- มี 3 คำสั่ง คือ `cluster.sh up <replica> <process> <batch>` · `cluster.sh status` · `cluster.sh down` ตอนเปิด (`up`) จะเช็กก่อนว่าจำนวน replica เป็น 1–2 และไม่เกินจำนวน GPU ที่มีในเครื่อง
- replica ลำดับ r ใช้ GPU ใบที่ r ส่วน process ลำดับ p เป็น uvicorn แยกตัว ฟังที่ `127.0.0.1:(9000 + r×100 + p)` คือฟังภายในเครื่องเท่านั้น ถ้า batch = 1 ใช้โหมด `single` ถ้ามากกว่า 1 ใช้โหมด `microbatch` และตั้ง `MAX_BATCH` ตามค่าที่ส่งมา
- สคริปต์เขียนค่า NGINX ให้ upstream มีทุก process โดยไม่ระบุวิธีแจก จึงเป็น round-robin ฟังที่ `0.0.0.0:8080` และแนบหัว `X-Upstream` ในคำตอบ เพื่อดูได้ว่าคำขอไปถึง process ไหน
- API key เก็บใน `/workspace/lab6/.env` ถ้ายังไม่มีจะสุ่มใหม่ครั้งเดียว ถ้ามีแล้วใช้ค่าเดิม ค่าที่ตั้งไว้กับ PID และ log อยู่ใน `/workspace/lab6/run/` ซึ่งคำสั่ง `status` อ่านจากที่นี่
- คำสั่ง `up` จะปิด server เดิมก่อน รวมถึงตัวที่เปิดจาก `run_single.sh` ในขั้นก่อน แล้วรอจน `/health` ของทุก process ตอบ 200 (รอได้นานสุด 300 วินาที) จึงพิมพ์ว่า "เปิดเสร็จ"

## คำขอเดินทางผ่านอะไรบ้าง
```
ผู้ใช้ (นอกเครื่อง)
   │  POST http://203.0.113.50:41234/v1/detect   + Authorization: Bearer <key>
   ▼
Vast.ai port mapping   41234 (ภายนอก) ──► 8080 (ในเครื่อง)
   ▼
NGINX :8080  (Load Balancer จุดเดียว · round-robin)
   │        upstream lab6_servers
   ├──► 127.0.0.1:9000  replica 0 / process 0 ── GPU 0   ◄ เปิดอยู่ตอนนี้
   ├┄┄► 127.0.0.1:9001  replica 0 / process 1 ── GPU 0   (มีเมื่อ process ≥ 2)
   └┄┄► 127.0.0.1:9100  replica 1 / process 0 ── GPU 1   (มีเมื่อ replica = 2)
            │
            ▼  FastAPI: ตรวจ key → แปลงรูป → คิว → YOLO บน GPU → JSON
   คำตอบย้อนกลับทางเดิม (มีหัว X-Upstream บอกว่า process ไหนตอบ)
```
