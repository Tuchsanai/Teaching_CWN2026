# GPU 1 ใบ รองรับผู้ใช้พร้อมกันได้ 18 คน ที่ p95 ≤ 500 ms

ผลนี้มาจากการวัดจริงบน **vapp-lab5** (RTX 3090) ในระบบแบบพื้นฐาน: replica 1 ตัว, 1 process, batch = 1 วัดจนเห็น DONE แล้ว

## อธิบายโค้ด `lab5_image_api/code/loadgen.py`
- ตัวยิงแตกเป็นหลาย process (สูงสุด 8) ผู้ใช้ 1 คนคือ 1 thread ที่ถือ connection ของตัวเอง ส่งรูปตัวอย่าง 6 รูปวนเข้า NGINX :8080 พอได้คำตอบก็ส่งรูปถัดไปทันที ถ้ารอเกิน 10 วินาทีนับเป็น error
- ทุกระดับยิง 20 วินาที นับเฉพาะคำขอที่จบในช่วงวินาทีที่ 5–20 ระหว่างนั้นเก็บ GPU util ทุกใบทุก 0.5 วินาที และ CPU ของ server, NGINX และตัวยิงเป็นจำนวน core
- จากคำตอบของ API อ่าน replica ที่ตอบ เวลาภายใน server (decode + queue + inference) และขนาด batch
- ก่อนเริ่มยิงอุ่นระบบ 5 วินาทีโดยไม่นับผล ไล่ N ไปจนไม่ผ่าน 2 ระดับติดกัน แล้วซอยครึ่ง 3 รอบ บันทึกที่ `/workspace/lab5/results/<ชื่อ>.json` และพิมพ์ความจุตามด้วย DONE

## ตอนเต็มความจุ GPU ทำงานแค่ราว 12–13%
- Throughput ตันที่ราว 38–39 req/s ตั้งแต่ N=16 ขึ้นไป เพิ่มคนแล้วได้แค่คิวยาวขึ้น p50 เพิ่มตาม N/38 พอดี เช่น N=32 ได้ราว 840 ms
- เวลาภายใน server เกือบทั้งหมดคือรอคิว ส่วนงาน GPU จริงต่อรูปมีแค่ราว 24 ms
- **คอขวดอยู่ที่ server process เดียวที่ทำงานทีละคำขอ (batch = 1)** ไม่ใช่ GPU ทั้ง process ใช้ CPU ราว 1.2 core โดยส่วนใหญ่วนอยู่ใน Python ทั้งแปลงรูป, เตรียมข้อมูลเข้าโมเดล, ประมวลผลผลลัพธ์ และ event loop
- NGINX ใช้ราว 0.03 core ตัวยิงใช้ราว 0.03 core จึงไม่ใช่คอขวด
- GPU ใบที่ 2 ว่าง 0% ตลอด

## สิ่งที่ควรรู้
- **รอบแรกได้ผลไม่สะอาด จึงวัดซ้ำ** รอบแรกได้ความจุ 14 คน เพราะที่ N=16 server ค้างไปช่วงหนึ่ง (GPU เหลือ 2%, timeout 13.8%) ขณะที่ N=32 กลับเรียบ และค่า CPU ของตัวยิงติดลบ ผมแก้ให้วัด CPU 0.5 วินาทีก่อนจบระดับแล้ววัดใหม่ ผลรอบนี้คือ base1 ส่วนรอบแรกเก็บไว้เป็น `base1_try1.json`
- **อาการค้างเป็นช่วงยังเกิดในรอบที่สอง** เห็นที่ p99 = 7.2 s ตอน N=24 และ p95 = 9 s ตอน N=64 แต่ยังไม่ถึง 10 วินาทีจึงไม่นับเป็น error ผมยังไม่ได้หาสาเหตุ
- **CPU ของตัวยิงที่ N=1 และ 4 ยังขึ้น −0.01** ถือว่าเท่ากับ 0 แต่การวัดยังไม่สมบูรณ์
