เปิด API สร้างภาพบนเครื่อง vapp-lab9 แล้ว ทดสอบจากนอกเครื่องผ่านทั้ง 2 ข้อ

**ผลทดสอบ** (ยิงจาก container `multi-account` ไปที่ `http://203.0.113.10:41234` พอร์ตภายนอกที่ต่อเข้าพอร์ต 8000 บนเครื่องเช่า)
1. ส่งข้อความ 1 ข้อพร้อม key ได้ HTTP 200 กลับมาเป็นภาพ JPEG 512×512 ขนาด 40 KB บันทึกไว้ที่ `lab9_hybrid/results/sync_test.jpg`
2. ส่งแบบไม่มี key ได้ 401 `{"detail":"invalid or missing API key"}` ลองใส่ key ผิดก็ได้ 401 เหมือนกัน
3. ลองเพิ่มเพื่อเช็กข้อกำหนด 500 คำขอ: ยิงพร้อมกัน 500 คำขอ ได้ 200 ครบทั้ง 500 ใช้เวลารวม 234 วินาที ช่วงที่ยังยิงอยู่ `/stats` แสดงคำขอที่รอคิว 458 รายการ ไม่มีคำขอไหนล้มเหลว

**เวลาที่ใช้ต่อภาพ** (RTX 3090 สร้างทีละ 1 ภาพ)
- เฉพาะเวลาสร้างภาพบน GPU เฉลี่ย **0.47 วินาที** (`/stats` นับจาก 506 ภาพ)
- เวลาที่ผู้ใช้รอจริงเมื่อไม่มีคิวคือประมาณ 1.4 วินาที เพราะรวมเวลาเดินทางของเครือข่ายด้วย
- ถ้ามีคิวยาว คนท้ายแถวต้องรอเกือบ 4 นาที

**โค้ด `lab9_hybrid/code/sync_server.py` (78 บรรทัด)**
- **API key:** ถ้ายังไม่มีไฟล์ key จะสุ่มขึ้นมาใหม่แล้วเก็บที่ `/workspace/lab9/api_key.txt` บนเครื่องเช่า ตั้งสิทธิ์ให้เจ้าของอ่านได้คนเดียว (`chmod 600`) ทุกคำขอต้องส่ง key มาใน header `X-API-Key` และเซิร์ฟเวอร์ตรวจด้วย `compare_digest`
- **โมเดล:** โหลด SDXL-Turbo (fp16) ขึ้น GPU ใบแรก (`cuda:0`) ครั้งเดียว แล้วสร้างภาพทดลอง 1 รอบก่อนเริ่มรับคำขอ ตั้งค่าภาพ 512×512 แบบ 4 steps
- **การเข้าคิว:** ใช้ thread สร้างภาพตัวเดียว (`ThreadPoolExecutor(max_workers=1)`) คำขอที่มาพร้อมกันจึงยืนรอกันเองโดยไม่บล็อกเซิร์ฟเวอร์ ส่วน uvicorn ตั้ง `--backlog 2048` และ `ulimit -n 65535` ไว้ จึงรับคำขอค้างได้เกิน 500
- **Endpoints:**
  - `POST /generate` ตอบกลับเป็น `image/jpeg`
  - `GET /health` บอกชื่อโมเดลและ GPU
  - `GET /stats` บอกจำนวนคำขอที่รับมา (`received`) จำนวนภาพที่สร้างเสร็จ (`done`) จำนวนที่รอคิวอยู่ และเวลาเฉลี่ยต่อภาพ

เซิร์ฟเวอร์รันเป็นงานเบื้องหลังด้วย `nohup uvicorn` ใน `/workspace/lab9/code` บนเครื่องเช่า log อยู่ที่ `/workspace/lab9/sync_server.log` ค่า key ไม่ได้ถูกแสดงตรงไหนเลย ตอนทดสอบดึงเข้าตัวแปรผ่าน SSH เท่านั้น
