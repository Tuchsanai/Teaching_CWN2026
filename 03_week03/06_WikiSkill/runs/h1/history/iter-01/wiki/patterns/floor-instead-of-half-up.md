# ปัดเศษด้วย floor (`//`) แทน round half up

## อาการ
- ข้อตรวจ `half_up` พลาดทุกกรณี โดยค่าที่ได้น้อยกว่าที่คาด 1 สตางค์
- ตัวอย่าง: `cashback(10020,"gold",false)` คาด 251 ได้ 250 (10020×2.5% = 250.5) และ `split_bill(1010,1,5)` คาด [1061] ได้ [1060] (1010×1.05 = 1060.5)

## สาเหตุ
- โจทย์เขียนแค่ "คืนเป็นจำนวนเต็มสตางค์" ไม่บอกวิธีปัด Agent จึงเลือกเองเป็น floor (`//`) ทั้งที่เป็นเรื่องเงิน
- Agent เขียนในคำตอบว่า "ปัดทิ้งเศษ (floor) ถ้าต้องการต่างไปบอกได้" แต่ไม่มีใครถามกลับ ตัวตรวจคาดหวัง **half up** (.5 ปัดขึ้น)
- ทุกเคสที่ Agent ทดสอบเอง ไม่มีเศษ .5 พอดี จึงไม่เห็นว่าพลาด

## หลักฐาน
- iteration 1: t4-cashback-r1 และ t4-cashback-r3 (ใช้ `amount * rate // 1000`) พลาด 3/3 กรณี
- iteration 1: t2-split-bill-r1 (`tip = total * tip_percent // 100`) พลาด 3/3 กรณี
- ผ่าน: t1-cafe-bill-r2 ใช้ `_mul_div_round` ปัดครึ่งขึ้น และ t3-shipping-fee-r3 ใช้ `int(fee + Fraction(1,2))` ผ่าน `half_up` ทั้งคู่

## วิธีแก้
- งานเงินที่ผลลัพธ์เป็นสตางค์ ให้ปัดแบบ half up เสมอ ห้ามใช้ `//` เป็นตัวปัดสุดท้าย และห้ามใช้ `round()` เพราะ Python ปัดแบบ banker's
- ค่าไม่ติดลบ: `def div_half_up(n, d): return (2*n + d) // (2*d)`
- ตัวอย่าง: `div_half_up(amount * rate_bp * mult, 10000)`
- ก่อนจบ ให้ทดสอบด้วยค่าที่ลงเศษ .5 พอดี เช่น 10020 × 2.5% ต้องได้ 251
