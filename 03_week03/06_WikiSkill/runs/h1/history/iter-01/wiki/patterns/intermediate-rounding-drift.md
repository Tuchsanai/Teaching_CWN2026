# ปัดเศษหลายขั้นหรือปัดก่อนคูณต่อ ทำให้ผลเพี้ยน 1 สตางค์ (no_drift)

## อาการ
- ข้อตรวจ `no_drift` พลาด คาด 4338 ได้ 4339, คาด 301 ได้ 300
- ตัวอย่าง: `cafe_bill([{"price":4505,"qty":1}], true)` คาด 4338 ได้ 4339 และ `cashback(10020,"silver",true)` คาด 301 ได้ 300

## สาเหตุ
- Agent ปัดทุกขั้นที่เป็นเงิน (หลังลด 5%, หลังลดสมาชิก, หลัง VAT) ทำให้ error สะสม 4505×0.9 = 4054.5 ถูกปัดเป็น 4055 ก่อนคูณ 1.07
- ในอีกกรณี Agent ปัดทิ้งก่อนคูณ 2 (150.3 → 150 → 300) แทนที่จะคูณ 2 ก่อนแล้วปัดครั้งเดียว (300.6 → 301)
- Agent อธิบายไว้ในคำตอบว่า "ปัดทุกขั้น ผลต่างอาจเป็น 1 สตางค์" แปลว่ารู้ความเสี่ยงแต่ไม่ได้ตรวจกับข้อกำหนด

## หลักฐาน
- iteration 1: t1-cafe-bill-r2 พลาด 3/3 กรณี (ปัดทุกขั้นด้วย `_mul_div_round`)
- iteration 1: t4-cashback-r1 พลาด 3/3, t4-cashback-r3 พลาด 2/3
- ผ่าน: t3-shipping-fee-r3 ใช้ `Fraction` คูณทุกขั้น (×6/5, ×3/2) แล้วปัดครั้งเดียวตอนท้าย ผ่านทั้ง `no_drift` และ `half_up`
- t2-split-bill-r1 ผ่าน `no_drift` เพราะมีขั้นคำนวณเดียว

## วิธีแก้
- เก็บผลระหว่างทางเป็นจำนวนเต็มที่ยังไม่หาร หรือใช้ `fractions.Fraction` ตลอดทุกขั้น (ลด 5%, ลดสมาชิก, VAT, คูณ 2) แล้วปัดครั้งเดียวที่ผลสุดท้าย
- ตัวอย่าง: `total = Fraction(subtotal) * Fraction(95,100) * Fraction(90,100) * Fraction(107,100)` แล้วใช้ half up ตอนคืนค่า
- ถ้าโจทย์มีเพดาน (เช่น cap 200 บาท) ให้ปัดก่อนแล้วจึง `min(...)` เทียบเพดาน
- ถ้าโจทย์ระบุชัดว่าให้ปัดทีละขั้น จึงปัดทีละขั้นได้ ถ้าไม่ระบุให้ปัดครั้งเดียว
- ใช้คู่กับ `floor-instead-of-half-up.md`
