# ไม่ตรวจช่วงค่าที่โจทย์ระบุ ทำให้ค่านอกช่วงไม่ถูกปฏิเสธ (reject_value)

## อาการ
- ข้อตรวจ `reject_value` พลาด: `cafe_bill([{"price":4500,"qty":0}], false)` ต้อง raise `ValueError` แต่คืน 0
- ฟังก์ชันคืนค่าปกติให้อินพุตที่อยู่นอกช่วงที่โจทย์เขียนไว้ (qty ตั้งแต่ 1)

## สาเหตุ
- โจทย์ระบุช่วงในวงเล็บหรือท้ายพารามิเตอร์ เช่น "จำนวนชิ้น (ตั้งแต่ 1)", "น้ำหนัก 1–30,000", "tip 0–100", "people ตั้งแต่ 1" แต่ไม่ได้บอกตรง ๆ ว่าให้ reject
- Agent ที่ผ่านข้อนี้ validate ช่วงของตัวแปรหลักไว้ แต่ t1-cafe-bill-r2 ข้ามการตรวจ price/qty เลย

## หลักฐาน
- iteration 1: t1-cafe-bill-r2 พลาด 3/3 (ไม่มี validation เลย)
- ผ่าน `reject_value`: t2-split-bill-r1 (`total<0`, `people<1`, tip นอก 0–100), t3-shipping-fee-r3 (weight นอก 1–30000, distance<0), t4-cashback-r1/r3 (amount<0, tier ไม่รู้จัก)

## วิธีแก้
- ก่อนเขียนฟังก์ชัน ให้ไล่ทุกพารามิเตอร์ในโจทย์ จดช่วงค่าที่ถูกต้อง แล้วเขียนเงื่อนไข `raise ValueError` ครบทุกตัวแปร รวมถึงช่วงของสมาชิกใน list ด้วย
- ตัวอย่างสำหรับ items: ทุกตัวต้องมี `price >= 0` และ `qty >= 1`
- ขอบเขตต้องตรงตามโจทย์: "ตั้งแต่ 1" คือ `>= 1` ปฏิเสธ 0, "0–100" คือรับ 0 และ 100 ปฏิเสธ 101 และ -1
- ลำดับตรวจ: ชนิดก่อน (ดู `reject-non-int-inputs-as-valueerror.md`) แล้วค่อยตรวจช่วง
- ข้อความ error เขียนบอกว่าตัวแปรไหนผิด เพราะ CLI จะนำข้อความไปใส่ใน `error`
