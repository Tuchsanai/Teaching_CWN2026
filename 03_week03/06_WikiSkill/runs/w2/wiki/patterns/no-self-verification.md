# no-self-verification: Agent ส่งงานโดยไม่รัน หรือรันแค่กรณีปกติเพียง 2–4 ค่า

## อาการ
ตัวตรวจไม่ได้รายงานข้อนี้ตรง ๆ แต่เห็นผ่านผลรวม:
- ข้อที่ Agent ไม่เคยลองเลยตกหมด: `reject_value`, `reject_type`, `cli_ok`, `cli_error`, `tests`
- ข้อ `policy` ตกใน 2 โจทย์ที่ใช้ตัวตรวจข้อนี้ (cashback, shipping_fee) โดย Agent ไม่รู้ตัว
- คะแนนทุกงานอยู่ที่ 0.40–0.50 และไม่มีงานไหนผ่านครบ

## สาเหตุ
- trace t4-cashback-r1 และ t4-cashback-r3: Agent เขียนไฟล์แล้วจบเลย และบอกในคำตอบเองว่า “ยังไม่ได้รันหรือทดสอบ”
- trace t3-shipping-fee-r3, t1-cafe-bill-r1, t2-split-bill-r1: รันด้วย `python3 -c` เพียง 2–4 ค่า ล้วนเป็นกรณีปกติ ไม่มีกรณีอินพุตผิด ไม่มีการเรียก `python solve.py` ผ่าน stdin จึงไม่เห็นว่า CLI ไม่มีอยู่ ไม่เห็น error ชนิดผิด
- Agent ใช้ผลรันที่ได้ตรงกับที่คิดมือมาสรุปว่างานถูก (เช่น t3 เขียนว่า “ได้ค่าตรงกับที่คิดมือ”) ทั้งที่ครอบคลุมแค่ส่วนเล็กของสิ่งที่ตัวตรวจดู
- ทั้ง 5 งานไม่ได้ทบทวนข้อความโจทย์เทียบกับโค้ดอีกรอบ (เช่น เงื่อนไข “ต่ำกว่า/ตั้งแต่”, ช่วงค่าของอินพุต)

## หลักฐาน
งานที่ล้ม (ทุกงาน ไม่มีงานผ่านให้เทียบ):
- t4-cashback-r1: “ผมสร้างไฟล์ solve.py ... แต่ยังไม่ได้รันหรือทดสอบ” (คำสั่งที่ใช้ 2 ครั้ง ทั้งคู่ไม่ใช่การรัน solve.py)
- t4-cashback-r3: “ฉันเขียน cashback ใน solve.py เสร็จแล้ว แต่ยังไม่ได้รันทดสอบ”
- t3-shipping-fee-r3: รัน `print(shipping_fee(1000,0,False), shipping_fee(5000,101,False), ...)` 4 ค่า ไม่มีกรณีผิด; ยังทิ้งโค้ดเกินความจำเป็นไว้ในบรรทัด return (`... if False else ...`) ซึ่งตัว Agent เองสังเกตเห็นแต่ไม่ได้แก้
- t1-cafe-bill-r1: รัน 3 ค่า (`c([...],True)`, `c([...],False)`, `c([],False)`) ไม่มีกรณีผิด
- t2-split-bill-r1: รัน 2 ค่า และเขียนเองว่า “ยังไม่ได้ทดสอบกรณีอื่น”

## วิธีแก้
ก่อนส่งงานให้ทำเช็กลิสต์ตรวจตัวเองและรันจริงทุกข้อ:
1. รัน `solve.py` ด้วยคำสั่งจริง ไม่ใช่แค่ import: ส่ง JSON ผ่าน stdin หนึ่งกรณีสำเร็จและหนึ่งกรณีผิด ดู stdout และ `echo $?`
2. รันกรณีผิดผ่านฟังก์ชันโดยตรงอย่างน้อย: ค่านอกช่วง, float, ชนิดผิด ต้องได้ `ValueError` ไม่ใช่ error ชนิดอื่นหรือคืนค่า
3. รัน `test_solve.py` ที่เขียนไว้ให้ผ่าน (ดู missing-test-file)
4. อ่านโจทย์ทีละบรรทัดแล้วเทียบกับโค้ด สำหรับทุกกฎมีกรณีทดสอบ ‘พอดีขอบ’ และ ‘เกินขอบ’ อย่างละหนึ่ง
5. ถ้าตัวเองบอกในคำตอบว่า “ยังไม่ได้รัน/ยังไม่ได้ทดสอบ” ให้กลับไปรันก่อนส่ง อย่าส่งงานพร้อมคำเตือนนั้น
6. ถ้าเห็นโค้ดที่ไม่เรียบร้อยหรือซ้ำซ้อนในผลงานตัวเอง ให้แก้ก่อนส่ง ไม่ใช่แจ้งไว้ในคำตอบ
