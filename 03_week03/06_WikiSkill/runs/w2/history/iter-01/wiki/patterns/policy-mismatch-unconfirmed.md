# policy-mismatch-unconfirmed: ข้อ policy ตก (ยังไม่ยืนยันสาเหตุ) ผลที่ได้ต่างจากที่ตัวตรวจคาดมาก

## อาการ
สถานะ: ยังไม่ยืนยัน
- t4-cashback-r1 และ t4-cashback-r3: `policy: cashback(20000, "silver", true) คาด 300 ได้ 600 · พลาด 3 จาก 6 กรณี`
- t3-shipping-fee-r3: `policy: shipping_fee(3000, 0, false) คาด 0 ได้ 8000 · พลาด 4 จาก 6 กรณี`
- t1-cafe-bill-r1 และ t2-split-bill-r1 ไม่มีข้อ `policy` ในรายการตรวจ จึงไม่มีข้อมูลของโจทย์สองแบบนี้

## สาเหตุ
ยังไม่ยืนยัน มีเพียงเบาะแสต่อไปนี้:
- ค่าที่ตัวตรวจคาดต่างจากการอ่านโจทย์ตรง ๆ มาก: cashback แบบเดือนเกิดควรคูณ 2 (ได้ 600 จาก 20000 silver) แต่ตัวตรวจคาด 300 (เท่ากับไม่คูณ 2); shipping 3000 กรัม ระยะ 0 กม. คิดตามราคาน้ำหนักได้ 8000 แต่ตัวตรวจคาด 0
- ในสองโจทย์นี้ Agent ทุกตัวอ่านโจทย์แบบตรงตัวและให้คำตอบเหมือนกัน (cashback ผิดชุดเดียวกัน 3/6 ทั้งสองรอบ) แปลว่าไม่ใช่ความผิดพลาดสุ่ม
- สมมติฐานที่เป็นไปได้ (ยังไม่มีหลักฐานแยกว่าข้อใดจริง): (ก) ตัวตรวจ policy มีเงื่อนไขหรือการตีความที่โจทย์ฉบับที่ Agent เห็นไม่ได้เขียนไว้ชัด เช่นกรณีระยะ 0 หรือการซ้อนกันของเงื่อนไข (ข) ลำดับการใช้กฎ (เพดาน/ค่าขั้นต่ำ/การคูณ) ต่างจากที่ Agent ตีความ (ค) ความต่างของหน่วยหรือรอบการปัดเศษ ใน trace นี้ยังตรวจแยกไม่ได้ เพราะเราเห็นแค่กรณีแรกที่ตกของแต่ละงาน ไม่เห็นรายการกรณีที่ผ่าน
- Agent ทั้งสองโจทย์เลือกวิธีตีความเองเงียบ ๆ ในจุดที่โจทย์กำกวม (เช่นปัดเศษลง) แล้วแจ้งในคำตอบสุดท้ายเท่านั้น ไม่ได้ลองตรวจว่าตัวอย่างเดี่ยวสองสามกรณีสมเหตุสมผลหรือไม่

## หลักฐาน
งานที่ล้ม (ทุกงาน ไม่มีงานผ่านให้เทียบ):
- t4-cashback-r1: `rate = RATES_PERMILLE[tier]; if birthday: rate *= 2; result = amount * rate // 1000; return min(result, MAX_CASHBACK)` → ตกที่ `cashback(20000, "silver", true)` คาด 300 ได้ 600
- t4-cashback-r3: ตรรกะเดียวกัน (`multiplier = 2 if birthday else 1`) ผลเดียวกัน พลาด 3/6
- t3-shipping-fee-r3: ชั้นน้ำหนักตามโจทย์ (`<=1000→4000`, `<=5000→8000`) ตกที่ `shipping_fee(3000, 0, false)` คาด 0 ได้ 8000 พลาด 4/6

## วิธีแก้
เนื่องจากสาเหตุยังไม่ยืนยัน ให้ผู้ปรับสกิลอย่าเพิ่งเขียนกฎเฉพาะโจทย์ลงสกิล ให้ใช้หลักทั่วไปเท่านั้น:
1. เมื่อโจทย์กำกวมหรือมีเงื่อนไขหลายข้อซ้อนกัน ให้ Agent เขียนตารางตัวอย่างที่คิดด้วยมือจากข้อความโจทย์อย่างน้อย 5–6 กรณี (รวมกรณีที่ปิดเงื่อนไขแต่ละข้อทีละข้อ และกรณีค่าเป็น 0/ขอบ) แล้วเทียบกับผลรันจริงของตัวเอง ถ้าผลสุดโต่งผิดความคาด (เช่น ค่าส่ง 0 หรือเงินคืนไม่คูณ) ให้ย้อนอ่านโจทย์ใหม่
2. เขียนข้อสมมติทุกข้อที่เลือกเองลงในคอมเมนต์ใกล้โค้ดและในเทส เพื่อให้แยกได้ภายหลังว่าผิดที่การตีความหรือที่โค้ด
3. รอบถัดไปควรพยายามดูรายการกรณีทั้ง 6 ของ `policy` (ถ้ามีใน trace) เพื่อยืนยันว่ากรณีที่ตกคือกรณีประเภทใด แล้วค่อยอัปเดตหน้านี้ว่าเป็นการตีความผิด หรือโจทย์ขาดข้อมูล
