# money-rounding-half-up

## อาการ
- `half_up` และ `no_drift` ล้ม: ได้ค่าต่ำกว่าที่คาด 1 สตางค์ เมื่อผลคำนวณมีเศษ
- `cashback(10020,"gold",false)` คาด 251 ได้ 250 (เศษ .5 ถูกตัดทิ้ง)
- `cashback(10020,"silver",true)` คาด 301 ได้ 300 (เศษ .6 ถูกตัดทิ้ง)
- `split_bill(1010,1,5)` คาด `[1061]` ได้ `[1060]` (ทิป 50.5 ถูกปัดลง)

## สาเหตุ
- โจทย์ไม่ระบุวิธีปัดเศษ Agent จึงเลือก floor (`//`) ทั้งที่ตัวตรวจคาดว่าเป็นปัดครึ่งขึ้น (half-up) กับเงินสตางค์
- Agent เขียนในคำตอบว่า "โจทย์ไม่ได้ระบุ ผมเลือกปัดลง" แต่ไม่ได้เปลี่ยนไปใช้ค่าเริ่มต้นที่ปลอดภัยกว่า
- ข้อสังเกตว่าเลือกเอง ไม่ใช่การแก้ปัญหา

## หลักฐาน
- ล้ม: t4-cashback-r1 (`amount*rate*mult // 10000`), t4-cashback-r3 (`// 1000`), t2-split-bill-r1 (`total*tip_percent // 100`)
- ผ่าน `half_up`/`no_drift`/`boundary`: t1-cafe-bill-r1 ใช้เลขจำนวนเต็มล้วน เก็บ num/den แล้วปัด half-up ครั้งเดียวตอนท้าย `(2*num+den)//(2*den)`; t3-shipping-fee-r3 ใช้ `Fraction` แล้วบวก 1/2 ตอนท้าย

## วิธีแก้
1. คำนวณด้วยจำนวนเต็มหรือ `Fraction` ตลอด ห้ามใช้ float
2. เก็บผลเป็นเศษส่วน `num/den` แล้วปัด **ครั้งเดียวตอนท้าย** ด้วย half-up สำหรับค่าไม่ติดลบ:
   `result = (2*num + den) // (2*den)`
3. อย่าปัดกลางทาง: ถ้ามีหลายขั้น (ลด → VAT, ยอด + ทิป) ให้คูณเศษส่วนต่อกันก่อน
4. กรณีเปอร์เซ็นต์ เช่น cashback: `num = amount*rate_bp*mult`, `den = 10000` (rate เป็น basis point) แล้วค่อย `min(result, cap)`
5. กรณี split_bill: ปัดยอดรวม (บิล + ทิป) แบบ half-up ก่อน แล้วค่อย `divmod(grand, people)` แจกเศษ 1 สตางค์ให้คนแรก ๆ
6. ทดสอบเองด้วยค่าที่เศษลงที่ .5 พอดีและ .6 เพื่อดูว่า half-up ทำงานจริง
