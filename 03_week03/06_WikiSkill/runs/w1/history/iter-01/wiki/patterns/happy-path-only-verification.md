# happy-path-only-verification

## อาการ
- Agent จบงานใน 2–3 คำสั่ง ผ่านเฉพาะข้อ `contract`, `basic` (และ `half_up`/`boundary` ในบางตัว) คะแนน 0.30–0.50
- คำตอบสุดท้ายรายงานว่า "ผลตรงกับที่คำนวณด้วยมือ" ทั้งที่ล้ม 5–7 ข้อ

## สาเหตุ
- Agent ทดสอบแค่ค่าปกติ 2–5 ค่า ที่คำนวณคาดไว้จากตรรกะเดียวกับที่เขียน จึงยืนยันตัวเองเป็นวงกลม
- ไม่เคยรันกรณีผิด, CLI, หรือค่าที่เศษ .5
- ข้อสงสัยของโจทย์ (วิธีปัด) ถูกบันทึกเป็นข้อสันนิษฐานในคำตอบ แทนที่จะเลือกค่าเริ่มต้นที่ปลอดภัย
- ตอนยังไม่มีสกิล Agent เช็กโฟลเดอร์ `./skills` แล้วไปต่อทันทีเมื่อไม่พบ ไม่มีการวางแผนตรวจงานเอง

## หลักฐาน
- t4-cashback-r1/r3 (0.30), t1-cafe-bill-r1 (0.50), t2-split-bill-r1 (0.40), t3-shipping-fee-r3 (0.50)
- t2-split-bill-r1: รัน `python3 -I -c "from solve import ..."` ได้ `ModuleNotFoundError` เพราะ `-I` ตัด cwd ออกจาก sys.path แล้ว fallback ไปรันอีกแบบ ใช้ได้แต่เสียเวลา ควรรันแบบไม่มี `-I` จากโฟลเดอร์งาน

## วิธีแก้
ก่อนจบทุกครั้งให้ไล่ checklist นี้และรันจริง:
1. ฟังก์ชันตามโจทย์ ผ่านตัวอย่างปกติและค่าขอบ
2. เศษสตางค์ปัด half-up ครั้งเดียวตอนท้าย (money-rounding-half-up)
3. ทุกพารามิเตอร์ตรวจช่วงและชนิด แล้ว raise `ValueError` (missing-input-validation)
4. มี CLI อ่าน stdin JSON ใน `solve.py` และรันทดสอบเองแล้ว exit 0 / exit 2 (missing-cli-entrypoint)
5. มี `test_solve.py` และรันผ่าน (missing-test-file)

ถ้าโจทย์ไม่บอกวิธีปัดหรือพฤติกรรมขอบ ให้เลือกแบบมาตรฐานของงานเงิน (half-up, reject ค่าผิด) ไม่ใช่แบบที่เขียนง่ายที่สุด
