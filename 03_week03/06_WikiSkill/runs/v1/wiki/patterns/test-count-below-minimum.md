# test-count-below-minimum: มี test_solve.py แต่มีเทสต์น้อยกว่า 6 เมธอด

## อาการ
- ข้อ `tests` เป็นข้อเดียวที่ตก (ได้ 9/10 = 0.90) ใน 5 จาก 8 Trace ที่สุ่มในรอบ 2
- ข้อความตัวตรวจ: "unittest พบ 4 เทสต์ (ต้องมีอย่างน้อย 6)" หรือ "พบ 5 เทสต์"
- ไฟล์มีอยู่และรันผ่านหมด (`Ran 4 tests ... OK`) Agent จึงรายงานว่าเสร็จ

## สาเหตุ
- ตัวตรวจนับจำนวน test method (`def test_...`) ไม่ใช่จำนวน assertion เกณฑ์ขั้นต่ำ 6 ไม่อยู่ทั้งในโจทย์และในสกิล
- สกิลระบุหมวดที่ต้องครอบคลุม 4 หมวด (ปกติ · ขอบ · .5 · ValueError) Agent จึงเขียน 1 เมธอดต่อหมวด และยัด assertion จำนวนมากไว้ในเมธอดเดียว (เช่น `test_invalid` วน loop 10 ค่า) ได้เพียง 4–5 เมธอด
- Agent ดูแค่ว่า `OK` ไม่ได้เทียบตัวเลข `Ran N tests` กับเกณฑ์ เพราะไม่รู้ว่ามีเกณฑ์
- t1-cafe-bill-r2 ลบเทสต์ placeholder ทิ้งโดยไม่เพิ่มทดแทน จาก 5 เหลือ 4

## หลักฐาน
- iteration 2 ล้ม (4 เมธอด): t3-shipping-fee-r1, t3-shipping-fee-r2, t1-cafe-bill-r2
- iteration 2 ล้ม (5 เมธอด): t4-cashback-r2, t1-cafe-bill-r3
- iteration 2 ผ่าน: t1-cafe-bill-r1 (6 เมธอด), t4-cashback-r3 (6), t2-split-bill-r1 (7) ส่วนต่างคือแยกเมธอดละเอียดกว่า เช่น `test_threshold_exact` / `test_below_threshold` / `test_half_up` / `test_cap` แยกกัน
- โค้ด solve.py ของทั้ง 8 Trace ผ่านทุกข้ออื่น ความต่างของคะแนนมาจากจำนวนเมธอดอย่างเดียว

## วิธีแก้
1. เขียนเทสต์ 1 เมธอดต่อ 1 พฤติกรรม ตั้งเป้า 8 เมธอดขึ้นไปเพื่อเผื่อ (เกณฑ์คือ 6)
2. แยกอย่างน้อย: ปกติ · ขอบล่าง · ขอบบน/เพดาน · เศษ .5 ปัดขึ้น · ค่าติดลบ/0 · float · bool · enum ผิด หรือ key ขาด (ใช้ `assertRaises(ValueError)` เมธอดละประเภท)
3. ก่อนตอบ ดูเลข `Ran N tests` ในผลรัน `python3 -m unittest -q` ต้อง N >= 6 ถ้าน้อยกว่าให้เพิ่มเมธอดก่อน
4. ห้ามลบเทสต์ทิ้งเพื่อให้ผ่าน ถ้าลบต้องเพิ่มทดแทนให้จำนวนไม่ลด
5. ข้อเสนอสำหรับสกิล: เขียนเกณฑ์ "อย่างน้อย 6 เมธอด (แนะนำ 8)" ลงในหัวข้อ 4 และเพิ่มเงื่อนไข "Ran N tests ต้อง N >= 6" ในหัวข้อ 5 ที่ตรวจก่อนตอบ
