## เรื่องราว

แบรนด์เครื่องใช้ไฟฟ้าได้ข้อความจากโซเชียลวันละหลายพันข้อความ ทีมดูแลลูกค้าอ่านไม่ทัน ข้อความร้องเรียนจึงถูกตอบช้าจนลุกลาม
แบรนด์ต้องการเว็บ **VoiceOfCustomer**: วางข้อความเป็นชุด → ระบบแยกประเภท → ข้อความเชิงลบขึ้นให้จัดการก่อน → หัวหน้าทีมแก้ผลได้ → รายงานรายวันต่อทีม

| บทบาทในโจทย์กลาง | ในเรื่องนี้คือ |
|---|---|
| ผู้ส่งงาน (`staff1` · `staff2`) | เจ้าหน้าที่ทีม Facebook (`U1`) และทีม LINE (`U2`) |
| ผู้ตรวจทาน (`reviewer1`) | หัวหน้าทีมดูแลลูกค้า |
| งานด่วน | ข้อความจากโพสต์ที่กำลังเป็นกระแส |
| รายการ | ข้อความ 1 ข้อความ (1 บรรทัดใน `submit-text`) |

## Dataset

| เรื่อง | ค่า |
|---|---|
| ชื่อ | [`pythainlp/wisesight_sentiment`](https://huggingface.co/datasets/pythainlp/wisesight_sentiment) บน Hugging Face · สัญญาอนุญาต CC0 |
| ชุดวัดผล | split `test` (2,671 ข้อความ) ใช้ **800 ข้อความแรก** ตามลำดับในไฟล์ |
| ขนาดไฟล์ | ทั้งชุด 3.2 MB |
| เฉลย | คอลัมน์ `category`: 0 = `pos` · 1 = `neu` · 2 = `neg` · 3 = `q` (คำถาม) |
| สัดส่วนใน split `test` | `neu` 1,453 · `neg` 683 · `pos` 478 · `q` 57 (ไม่สมดุล) |

ข้อความในชุดวัดผลที่ยาวเกิน 500 ตัวอักษร ให้ตัดเหลือ 500 ตัวอักษรแรกก่อนส่ง

### ตัวอย่างข้อมูลจริง

ข้อความจาก split `test` (เป็นข้อความจริงจากโซเชียล จึงมีภาษาพูด คำสะกดผิด ชื่อสินค้า และคำหยาบปนอยู่)

| เฉลย | ข้อความ |
|---|---|
| `neg` | ภาคเหนือไม่ค่อยมีสาขาเลย สองมาตรฐานมาก!! เพิ่มสาขาหน่อยสิครับ |
| `neg` | เราใช้ซีวิค เวลาเช็คระยะทีนึงก็ตกประมาณ 4-5 พันเลยค่ะ ไม่รวมอะไหล่พิเศษต่างๆ เคยได้ยินว่าของโตโยต้าถูกกว่านี้ ฮือ |
| `pos` | ทีเด็ดครับบอกเลย |
| `neu` | ในเว็บไซต์จะแจ้งสาขาที่ไม่ร่วมรายการค่ะ ^^ |
| `neu` | เครื่อง v6 กี่ ccครับ เพราะเห็นของที่toyota บ้านเรา เอาเข้ามา 3.5 v6 ยังปาไป ห้าล้านกว่าเลยครับ |
| `q` | มีแอลกอฮอลมั้ยคะ |

ข้อสังเกต: แถวที่ 5 เป็นประโยคคำถามแต่เฉลยเป็น `neu` · เฉลยของชุดนี้มีความกำกวมตามธรรมชาติ ซึ่งเป็นเหตุผลที่ต้องวัดด้วยตัวชี้วัด ไม่ใช่ดูด้วยตา

## โมเดลและการเทรน (ระยะ M)

| เรื่อง | ค่า |
|---|---|
| โมเดลตั้งต้น | เลือก 1 แบบ: โมเดลภาษาไทยแบบ Encoder เช่น `airesearch/wangchanberta-base-att-spm-uncased` หรือ LLM ที่อ่านภาษาไทยได้ เช่น `Qwen/Qwen3-4B-Instruct-2507` |
| ชุดเทรน | split `train` 21,628 ข้อความ (ใช้ทั้งหมดหรือสุ่มอย่างน้อย 5,000 ข้อความ) · split `validation` 2,404 ข้อความใช้เลือก checkpoint |
| สิ่งที่เทรน | Fine-tune ให้จำแนก 4 ประเภท (Encoder: เทรนทั้งโมเดล · LLM: เทรนด้วย LoRA) · ต้องรับมือกับข้อมูลไม่สมดุล |
| Baseline | LLM สำเร็จรูปที่ยังไม่เทรน ตอบเป็น JSON จากคำสั่ง (prompt) อย่างเดียว |
| ค่าที่ต้องเลือกเอง | จำนวน epoch · learning rate · วิธีรับมือข้อมูลไม่สมดุล |

`confidence` คือความน่าจะเป็นของประเภทที่โมเดลเลือก

**ผลจากโมเดลต่อ 1 ข้อความ:** `label` (`pos` · `neu` · `neg` · `q`) และ `confidence` (0.00–1.00)

## กติกาเฉพาะ R1–R4

| รหัส | เรื่อง | กติกา |
|---|---|---|
| R1 | ข้อความเชิงลบ | `neg` และ confidence ≥ 0.80 → `ALERT` · `neg` และ confidence < 0.80 → `WARN` |
| R2 | คำถาม | `q` → `WARN` ทุกค่า confidence |
| R3 | ไม่มั่นใจ | `pos` หรือ `neu` และ confidence < 0.50 → `WARN` · ≥ 0.50 → `OK` |
| R4 | ข้อความสั้นเกิน | ข้อความที่ตัดช่องว่างแล้วเหลือน้อยกว่า 3 ตัวอักษร หรือโมเดลตอบ `label` นอก 4 ค่า → `INVALID` |

**เกณฑ์สีแดงของรายงาน (G11):** อัตราปกติ < 60.0

## รูปแบบจำลอง (AI_MODE=mock)

ข้อความขึ้นต้นด้วย `[[<label>:<confidence × 100>]]` เช่น `[[neg:80]] ส่งของช้ามาก` = `neg` confidence 0.80
ข้อความที่ไม่มีส่วนนำหน้า = `neu` confidence 0.90 · ส่วนนำหน้าไม่นับเป็นความยาวของข้อความ ทั้งใน G2 และ R4
ส่วนนำหน้าที่ `label` ไม่ใช่ 4 ค่า เช่น `[[xyz:90]]` = โมเดลตอบ `label` นอก 4 ค่า → `INVALID` ตาม R4
บรรทัดว่างใน `submit-text` คือข้อความ 0 ตัวอักษร ชุดนั้นถูกปฏิเสธตาม G2

| ข้อความ | สถานะ | เพราะ |
|---|---|---|
| `[[neg:80]] ส่งของช้ามาก` | `ALERT` | R1 เท่ากับ 0.80 พอดี |
| `[[neg:79]] ส่งของช้ามาก` | `WARN` | R1 |
| `[[q:99]] เปิดกี่โมงครับ` | `WARN` | R2 |
| `[[pos:49]] ก็ดีนะ` | `WARN` | R3 |
| `[[pos:50]] ก็ดีนะ` | `OK` | R3 เท่ากับ 0.50 พอดี |
| `[[pos:90]] ดี` | `INVALID` | R4 เหลือ 2 ตัวอักษร |
| `[[abc:90]] ส่งของช้ามาก` | `INVALID` | R4 `label` นอก 4 ค่า |

## การวัดคุณภาพ AI (ขั้น C2)

| เรื่อง | ค่า |
|---|---|
| `truth` | `"pos"` · `"neu"` · `"neg"` หรือ `"q"` |
| `prediction` | `{"label": "...", "confidence": 0.00}` |
| ตัวชี้วัด 1 | `macro_f1` = ค่าเฉลี่ยของ F1 ทั้ง 4 ประเภท (คำตอบนอก 4 ค่านับเป็นผิด) |
| ตัวชี้วัด 2 | `recall_neg` = จำนวนข้อความ `neg` ที่ทายถูก ÷ จำนวนข้อความ `neg` ทั้งหมด |
| เกณฑ์รับ | `macro_f1` ≥ 0.45 **และ** `recall_neg` ≥ 0.70 → `pass` |
