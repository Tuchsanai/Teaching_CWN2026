## 5. Test Case

รูปแบบ: รหัส · ขั้นตอน · ผลที่คาดหวัง (คำนวณ) · ที่มา · ระดับความสำคัญ (P1 = กติกาความปลอดภัย / รูปหาย / สิทธิ์รั่ว · P2 = ตัวเลขรายงานหรือฟังก์ชันหลัก · P3 = รอง)

**ขั้นร่วมทุก TC**
1. reset: `POST http://127.0.0.1:3410/api/test/reset` header `X-Test-Key: sitesafe-test-reset-key` · body `{}` หรือ `{"now":"<ISO 8601 +07:00>"}` (ต้องเปิด `ENABLE_TEST_RESET=1`) → ต้องได้ `200` `{"reset":true,"sites":3,"users":5,"photos":1233,"overrides":1}` ก่อนเริ่ม ถ้าไม่ใช่ `200` ให้หยุด (reset ทำให้ทุกคนหลุดล็อกอิน ต้องล็อกอินใหม่)
2. อัปโหลด 1 ครั้ง = `POST /api/uploads` `{"count":n}` → `201` ได้ `batchId` · แล้วส่งทีละไฟล์ `POST /api/uploads/{batchId}/photos` → บันทึก HTTP status และ `photoId` ของ**แต่ละไฟล์** · "แถว +k" = จำนวนแถว `photos` หลังลบก่อน
3. โหมด: **mock** = `AI_MODE=mock` (H, V จากชื่อไฟล์ `h{H}_v{V}`) · **real** = gateway และโมเดลจริงบน GPU · สคริปต์ HTTP ส่ง header `Cookie` เอง (cookie เป็น Secure)

"ผลที่คาดหวัง" ที่เป็นสถานะ HTTP ถือตาม API ใน DESIGN หัวข้อ 5 ซึ่งต่อยอดจาก FR
