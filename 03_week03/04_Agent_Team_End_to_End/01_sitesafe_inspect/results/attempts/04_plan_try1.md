# แผน sitesafe (วางแผนเท่านั้น ยังไม่ได้รันจริง)

วางแผนใน container `multi-account` ด้วยสกิล dag-planner (`doctor` → `dag` → `plan`) จาก `./docs/REQUIREMENTS.md` และ `./docs/DESIGN.md` ได้ 10 บล็อก ใช้บัญชี yolo2, yolo3, cyolo1 และ agent พร้อมกันสูงสุด 3 ตัว (เพดาน 3) ไม่ได้สั่ง `export` หรือ `run` และไม่ได้เปิดข้อมูลล็อกอินของบัญชีใด

## ไฟล์ใน `./plan`

| ไฟล์ | เนื้อหา |
|---|---|
| `plan/blocks.json` | ไฟล์บล็อก 10 บล็อก (สกิล ขนาด ความยาก ไฟล์ผล เกณฑ์เสร็จ) |
| `plan/dag.png` | ภาพ DAG พร้อม rank สายวิกฤต ป้ายสกิล และบัญชี |

| `plan/PLAN.md` · `plan/plan.json` | ไฟล์แผน (โควตา ตารางแจกงาน เหตุผล KC-QUEST) |

## บล็อกที่ใช้สกิล review

**B03 · API gateway + คิว RabbitMQ** ผู้ทำ yolo2 (Claude) ผู้ตรวจ cyolo1 (Codex) สูงสุด 2 รอบ
เหตุผล: ถ้าบล็อกนี้ผิด รูปที่ระบบรับแล้วอาจหายหรือได้ผลซ้ำ (NFR-04 ซึ่งกู้คืนไม่ได้) และการตรวจ API key ผิดทำให้รูปรั่วออกนอกระบบ (NFR-05) อีกทั้งเป็น API Contract ที่ทั้ง dispatcher, GPU Worker และ mock-gateway ต้องทำตาม

## ข้อสังเกต

- Critical Path ของสกิลคิดจากขนาดงาน (โทเคน) แต่ใน Gantt บล็อกที่กำหนดเวลาจบจริงคือสาย B03 → B04 (จบนาทีที่ 75) เพราะ B03 ต้องรอ agent ว่าง 2 ตัวจึงเริ่มได้ที่นาทีที่ 20 ส่วน B07 จบก่อนที่นาทีที่ 63.8
- yolo3 อยู่ในรายชื่อบัญชีแต่ไม่ได้งาน เพราะ KC-QUEST ให้คะแนน yolo2 สูงกว่าทุกบล็อก (โควตาที่อ่านได้ตอนวางแผน: cyolo1 เหลือ 100% · yolo2 82% · yolo3 67%) yolo3 จึงเป็นบัญชีสำรอง
- เวลาเป็นค่าประมาณจากขนาดบล็อก ยังไม่มีตัวปรับเวลาจากการรันจริง (k = 1)
- ก่อนรันจริงต้องคัดลอก `./docs` ไปไว้ที่ `/workspace/plans/sitesafe/app/docs` เพราะรายละเอียดของทุกบล็อกอ้าง `docs/DESIGN.md` และ agent ทำงานในโฟลเดอร์ `app/` ของแผน
- การเช่า GPU และการเทรนโมเดลจริงไม่อยู่ในแผนนี้ B05 เขียนโค้ดกับ unit test และ B10 ทดสอบด้วยโหมด mock

เวลาที่ใช้: ~8 นาที
