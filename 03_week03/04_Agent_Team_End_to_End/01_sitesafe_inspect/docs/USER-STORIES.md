# User Stories · SiteSafe Inspect

**ที่มา:** `INTERVIEW.md` (บันทึกการสัมภาษณ์ บริษัท ไทยมั่นคงก่อสร้าง จำกัด)
**สถานะ:** ร่างรุ่นแรก รอลูกค้ายืนยันจุดที่ขัดกันและคำถามท้ายไฟล์
**ขอบเขตเอกสาร:** ความต้องการเท่านั้น ยังไม่มีการออกแบบระบบและยังไม่มีโค้ด

## บทบาทที่ลูกค้าพูดถึง

| บทบาท | ใครในบันทึก | ที่มา |
|---|---|---|
| ผู้จัดการความปลอดภัย | คุณวิชัย | เห็นทุกไซต์ ดูรูปที่มีปัญหา สั่งหยุดงาน ดูรายงาน |
| หัวหน้างานไซต์ | คุณนภา (ไซต์สาทร) | ถ่ายและอัปโหลดรูป เห็นเฉพาะไซต์ตัวเอง |
| ผู้บริหาร | (ไม่ได้ร่วมสัมภาษณ์) | ดูรายงานได้อย่างเดียว |
| ฝ่ายไอที | คุณธนา | กำหนดสิทธิ์ ความปลอดภัยข้อมูล และค่าใช้จ่าย |

## ระดับความสำคัญ

- **Must** ขาดแล้วรุ่นแรกใช้งานจริงไม่ได้ หรือลูกค้าใช้คำว่า "ต้อง / ห้าม"
- **Should** ลูกค้าขอไว้ แต่รุ่นแรกยังใช้งานได้ถ้าส่งตามมาทีหลัง
- **Could** มีก็ดี (รอบนี้ไม่มีข้อใดเข้าระดับนี้ เพราะลูกค้าไม่ได้พูดถึงสิ่งที่ "มีก็ดี" สิ่งที่เลื่อนได้ลูกค้าระบุเองว่าไว้รุ่นหน้า จึงอยู่ในหัวข้อ "นอกขอบเขต")

ระดับเป็นข้อเสนอของทีมพัฒนาจากน้ำเสียงของลูกค้า ต้องให้ลูกค้ายืนยัน

## User Stories

### กลุ่ม A · ตรวจรูปและตัดสินผล

#### US-01 · ระบบชี้รูปที่มีคนไม่ใส่อุปกรณ์ พร้อมตีกรอบ — Must
**ในฐานะ** ผู้จัดการความปลอดภัย **ฉันต้องการ** ให้อัปโหลดรูปแล้วระบบบอกว่ารูปไหนมีคนไม่ใส่หมวกหรือไม่ใส่เสื้อสะท้อนแสง พร้อมตีกรอบให้ดู **เพื่อ** ไม่ต้องเปิดดูเองทีละรูป

**ที่มา:** คุณวิชัย — "อยากให้อัปโหลดรูปแล้วระบบบอกเลยว่ารูปไหนมีคนไม่ใส่หมวกหรือไม่ใส่เสื้อสะท้อนแสง ตีกรอบให้ดูด้วย" และ "วันหนึ่ง 3 ไซต์รวมกันราว 300 รูป ดูไม่ทันครับ"

**เกณฑ์ยอมรับ**
- รูปที่มีคนไม่ใส่หมวก แสดงกรอบรอบคนนั้นและระบุว่า "ไม่ใส่หมวก"
- รูปที่มีคนไม่ใส่เสื้อสะท้อนแสง แสดงกรอบรอบคนนั้นและระบุว่า "ไม่ใส่เสื้อสะท้อนแสง"
- รูปที่ทุกคนใส่ครบ ไม่มีกรอบแจ้งปัญหา
- ผลของแต่ละรูประบุจำนวนคนไม่ใส่หมวกและจำนวนคนไม่ใส่เสื้อสะท้อนแสง

#### US-02 · ดูเฉพาะรูปที่มีปัญหา — Must
**ในฐานะ** ผู้จัดการความปลอดภัย **ฉันต้องการ** ดูเฉพาะรูปที่มีปัญหา **เพื่อ** ใช้เวลากับรูปที่ต้องตัดสินใจเท่านั้น

**ที่มา:** คุณวิชัย — "ผมจะได้ดูเฉพาะรูปที่มีปัญหา"

**เกณฑ์ยอมรับ**
- มีมุมมองที่แสดงเฉพาะรูปที่ผลเป็น "ไม่ผ่าน" หรือ "เตือน" โดยไม่มีรูป "ผ่าน" ปน
- จำนวนรูปในมุมมองนี้เท่ากับจำนวนรูป "ไม่ผ่าน" + "เตือน" ของช่วงที่เลือก

#### US-03 · กติกาตัดสิน ผ่าน / เตือน / ไม่ผ่าน — Must
**ในฐานะ** ผู้จัดการความปลอดภัย **ฉันต้องการ** ให้ระบบตัดสินแต่ละรูปตามกติกาของบริษัท **เพื่อ** ให้ผลตรงกับเกณฑ์ที่ใช้สั่งงานจริง

**ที่มา:** คุณวิชัย — "มีคนไม่ใส่หมวกแม้แต่คนเดียวคือไม่ผ่าน ส่วนเสื้อสะท้อนแสง ถ้าไม่ใส่เกิน 2 คนในรูปเดียวถึงจะไม่ผ่าน คนเดียวให้เป็นเตือน"

**เกณฑ์ยอมรับ**
- รูปที่มีคนไม่ใส่หมวก ≥ 1 คน → "ไม่ผ่าน"
- รูปที่ไม่มีคนไม่ใส่หมวก และมีคนไม่ใส่เสื้อสะท้อนแสง 1 คน → "เตือน"
- รูปที่ไม่มีคนไม่ใส่หมวก และมีคนไม่ใส่เสื้อสะท้อนแสงมากกว่า 2 คน (3 คนขึ้นไป) → "ไม่ผ่าน"
- รูปที่ทุกคนใส่ครบ → "ผ่าน"
- กรณีไม่ใส่เสื้อสะท้อนแสงพอดี 2 คน ลูกค้ายังไม่ได้ระบุ (ดู C-03 / Q-01) ยังไม่กำหนดเกณฑ์จนกว่าจะได้คำตอบ

#### US-04 · ความแม่นของการจับคนไม่ใส่หมวก — Must
**ในฐานะ** ผู้จัดการความปลอดภัย **ฉันต้องการ** ให้โมเดลจับรูปที่มีคนไม่ใส่หมวกได้แม่นพอ **เพื่อ** ไม่ต้องกลับไปดูเองทุกรูปเหมือนเดิม

**ที่มา:** คุณวิชัย — "โมเดลต้องแม่นด้วยนะ ถ้าบอกผิดบ่อยผมก็ต้องกลับมาดูเองทุกรูปเหมือนเดิม" และ "10 รูปที่มีคนไม่ใส่หมวก ต้องจับได้อย่างน้อย 8 รูป"

**เกณฑ์ยอมรับ**
- บนชุดรูปทดสอบที่มีคนไม่ใส่หมวก ระบบตัดสิน "ไม่ผ่าน" ได้ไม่น้อยกว่า 80% ของรูป (อย่างน้อย 8 ใน 10 รูป)
- ชุดรูปทดสอบและวิธีนับต้องตกลงกับลูกค้าก่อน (ดู Q-09)

#### US-05 · เห็นผลเร็วพอที่จะสั่งหยุดงาน — Must
**ในฐานะ** ผู้จัดการความปลอดภัย **ฉันต้องการ** เห็นผลของรูปภายในเวลาไม่เกินครึ่งนาทีต่อรูป **เพื่อ** โทรสั่งหยุดงานได้ทันเมื่อมีคนไม่ใส่หมวก

**ที่มา:** คุณวิชัย — "แต่ของผมต้องเห็นผลทันทีนะ ถ้ามีคนไม่ใส่หมวกผมต้องโทรสั่งหยุดงานเดี๋ยวนั้น" และ "ไม่เกินครึ่งนาทีต่อรูปก็พอรับได้"

**เกณฑ์ยอมรับ**
- ผลของรูปหนึ่งรูปแสดงภายใน 30 วินาที (จุดเริ่มจับเวลาและกรณีอัปโหลดหลายรูปพร้อมกันต้องยืนยัน ดู C-01, C-02, Q-02)

### กลุ่ม B · อัปโหลดรูป

#### US-06 · อัปโหลดทีละหลายรูป — Must
**ในฐานะ** หัวหน้างานไซต์ **ฉันต้องการ** อัปโหลดรูปทีละหลายรูปในครั้งเดียว **เพื่อ** ส่งรูปของการเดินตรวจหนึ่งรอบได้โดยไม่ต้องอัปทีละรูป

**ที่มา:** คุณนภา — "ของหนูขออัปโหลดทีละหลายรูปนะคะ เดินรอบหนึ่งได้ 40–50 รูป ถ้าต้องอัปทีละรูปไม่ไหว"

**เกณฑ์ยอมรับ**
- เลือกและส่งรูป 50 รูปได้ในการอัปโหลดครั้งเดียว
- หลังส่ง รูปทั้ง 50 รูปปรากฏในรายการงานครบ ไม่มีรูปตกหล่น

#### US-07 · อัปเสร็จแล้วไปทำงานอื่นได้ และเห็นว่างานยังอยู่ในคิว — Must
**ในฐานะ** หัวหน้างานไซต์ **ฉันต้องการ** อัปโหลดเสร็จแล้วออกจากหน้าจอไปทำงานอื่นได้ และกลับมาเห็นว่างานยังอยู่ในคิว **เพื่อ** กลับไปคุมงานต่อได้โดยไม่ต้องรอหน้าจอค้างและมั่นใจว่ารูปไม่หาย

**ที่มา:** คุณนภา — "แล้วอย่าให้ต้องรอหน้าจอค้าง หนูต้องกลับไปคุมงานต่อ" และ "อัปเสร็จแล้วไปทำอย่างอื่นได้เลยค่ะ กลับมาดูอีกทีสัก 5 นาทีก็ได้ ขอแค่เห็นว่างานยังอยู่ในคิว ไม่ได้หายไป"

**เกณฑ์ยอมรับ**
- หลังกดส่งรูป ผู้ใช้ปิดหน้าจอหรือไปหน้าอื่นได้ทันที งานยังดำเนินต่อ
- เมื่อกลับเข้ามา เห็นสถานะของทุกรูปที่ส่งไป (เช่น รอคิว / กำลังตรวจ / เสร็จแล้ว)
- จำนวนรูปในรายการสถานะเท่ากับจำนวนรูปที่ส่ง

#### US-08 · รับรูปขนาดใหญ่จากมือถือ — Should
**ในฐานะ** หัวหน้างานไซต์ **ฉันต้องการ** อัปโหลดรูปจากมือถือที่มีขนาด 8–10 MB ได้ **เพื่อ** ใช้รูปที่ถ่ายจากหน้างานได้เลย

**ที่มา:** คุณนภา — "รูปจากมือถือหนูบางรูปใหญ่ 8–10 MB นะคะ"

**เกณฑ์ยอมรับ**
- รูป JPG หรือ PNG ขนาด 10 MB อัปโหลดสำเร็จและได้ผลตรวจ
- (เพดานขนาดไฟล์ที่แน่นอน และการจัดการรูปถ่ายติดนิ้วหรือรูปมืด ลูกค้ายังไม่ได้ระบุ ดู Q-07, Q-08)

#### US-09 · รับเฉพาะ JPG และ PNG — Must
**ในฐานะ** ฝ่ายไอที **ฉันต้องการ** ให้ระบบรับเฉพาะไฟล์ JPG กับ PNG **เพื่อ** ไม่ต้องรองรับไฟล์ชนิดอื่น

**ที่มา:** คุณธนา — "รับเฉพาะ JPG กับ PNG ครับ ไฟล์อื่นไม่ต้องรับ"

**เกณฑ์ยอมรับ**
- ไฟล์ JPG และ PNG อัปโหลดได้
- ไฟล์ชนิดอื่น (เช่น PDF, HEIC, MP4) ถูกปฏิเสธพร้อมข้อความบอกเหตุผล และไม่ถูกเก็บในระบบ

#### US-10 · รูปเข้าพร้อมกัน 3 ไซต์ ระบบไม่ล่มและรูปไม่หาย — Must
**ในฐานะ** ฝ่ายไอที **ฉันต้องการ** ให้ระบบรับรูปที่เข้ามาพร้อมกันจาก 3 ไซต์ในช่วงเช้าได้โดยไม่ล่มและไม่ทำรูปหาย **เพื่อ** ให้ใช้งานได้จริงในชั่วโมงเร่งด่วน แม้จะช้าลงบ้าง

**ที่มา:** คุณธนา — "ถ้าช่วงเช้ารูปเข้ามาพร้อมกัน 3 ไซต์ ระบบต้องไม่ล่ม ช้าหน่อยได้ แต่รูปห้ามหาย"

**เกณฑ์ยอมรับ**
- ทดสอบอัปโหลดพร้อมกัน 3 ไซต์ ไซต์ละ 50 รูป (รวม 150 รูป) ระบบยังตอบสนองตลอดการทดสอบ
- เมื่อจบการทดสอบ ทั้ง 150 รูปมีผลตรวจครบ จำนวนรูปที่มีผล = จำนวนรูปที่ส่ง

### กลุ่ม C · แก้ผลและร่องรอยการแก้

#### US-11 · หัวหน้างานกดแก้ผลที่โมเดลดูผิด — Should
**ในฐานะ** หัวหน้างานไซต์ **ฉันต้องการ** กดแก้ผลได้ว่ารูปนี้จริง ๆ ผ่าน **เพื่อ** แก้กรณีที่โมเดลดูผิด เช่น คนอยู่ไกลหรือหันหลัง

**ที่มา:** คุณนภา — "บางทีโมเดลอาจจะดูผิดนะคะ คนอยู่ไกล ๆ หรือหันหลัง หนูขอกดแก้ผลได้ว่ารูปนี้จริง ๆ ผ่าน" · คุณวิชัย — "แก้ได้"

**เกณฑ์ยอมรับ**
- หัวหน้างานเปลี่ยนผลของรูปในไซต์ตัวเองเป็น "ผ่าน" ได้
- หลังแก้ รูปแสดงผลที่แก้แล้ว และมีเครื่องหมายว่าเป็นผลที่คนแก้

#### US-12 · เก็บร่องรอยการแก้ผล — Must (เมื่อมี US-11)
**ในฐานะ** ผู้จัดการความปลอดภัย **ฉันต้องการ** รู้ว่าใครแก้ผล แก้เมื่อไร และยังเห็นผลเดิมของโมเดล **เพื่อ** ตรวจสอบการแก้ผลย้อนหลังได้

**ที่มา:** คุณวิชัย — "แก้ได้ แต่ต้องรู้ว่าใครแก้ แก้เมื่อไร และผลเดิมของโมเดลต้องยังอยู่"

**เกณฑ์ยอมรับ**
- ทุกการแก้ผลบันทึกชื่อผู้แก้ วันและเวลาที่แก้
- ผลเดิมของโมเดลยังดูได้หลังการแก้ ไม่ถูกเขียนทับ
- ผู้จัดการความปลอดภัยเปิดดูประวัติการแก้ของรูปใดก็ได้

### กลุ่ม D · รายงาน

#### US-13 · รายงานสรุปรายวันต่อไซต์ — Must
**ในฐานะ** ผู้จัดการความปลอดภัย **ฉันต้องการ** รายงานสรุปรายวันแยกตามไซต์ **เพื่อ** เห็นภาพรวมความปลอดภัยของแต่ละไซต์ในแต่ละวัน

**ที่มา:** คุณวิชัย — "สรุปรายวันต่อไซต์: ถ่ายกี่รูป ไม่ผ่านกี่รูป คนไม่ใส่หมวกกี่คน อัตราผ่านกี่เปอร์เซ็นต์ ... ถ้าอัตราผ่านต่ำกว่า 90% ให้ขึ้นสีแดง"

**เกณฑ์ยอมรับ**
- รายงานของหนึ่งวันต่อหนึ่งไซต์แสดง 4 ค่า: จำนวนรูปที่ถ่าย · จำนวนรูปไม่ผ่าน · จำนวนคนไม่ใส่หมวก · อัตราผ่าน (%)
- ไซต์ที่อัตราผ่านต่ำกว่า 90% แสดงเป็นสีแดง ไซต์ที่ 90% ขึ้นไปไม่เป็นสีแดง
- ตัวเลขในรายงานตรงกับผลของรูปในวันและไซต์นั้น (สูตรอัตราผ่านต้องยืนยัน ดู Q-05)

#### US-14 · ส่งรายงานให้ผู้บริหารทุกเย็น — Should
**ในฐานะ** ผู้จัดการความปลอดภัย **ฉันต้องการ** ให้รายงานสรุปรายวันถึงผู้บริหารทุกเย็น **เพื่อ** ให้ผู้บริหารรับทราบสถานะความปลอดภัยทุกวัน

**ที่มา:** คุณวิชัย — "ส่งผู้บริหารทุกเย็น"

**เกณฑ์ยอมรับ**
- รายงานของวันนั้นพร้อมให้ผู้บริหารเปิดดูได้ทุกเย็น ครบทุกไซต์
- (ช่องทางส่งและเวลาที่ถือว่า "เย็น" ลูกค้ายังไม่ได้ระบุ ดู Q-04)

#### US-15 · ผู้บริหารดูรายงานได้อย่างเดียว — Must
**ในฐานะ** ผู้บริหาร **ฉันต้องการ** เข้าดูรายงานได้ **เพื่อ** ติดตามสถานะความปลอดภัยของไซต์งาน

**ที่มา:** คุณธนา — "ผู้บริหารดูรายงานได้อย่างเดียว"

**เกณฑ์ยอมรับ**
- บัญชีผู้บริหารเปิดรายงานสรุปรายวันได้
- บัญชีผู้บริหารอัปโหลดรูปไม่ได้ และแก้ผลไม่ได้

### กลุ่ม E · สิทธิ์ ความปลอดภัยข้อมูล และค่าใช้จ่าย

#### US-16 · ล็อกอินด้วยอีเมลกับรหัสผ่าน — Must
**ในฐานะ** ฝ่ายไอที **ฉันต้องการ** ให้ผู้ใช้ล็อกอินด้วยอีเมลกับรหัสผ่าน **เพื่อ** ให้ระบบรู้ว่าผู้ใช้เป็นใครและมีสิทธิ์อะไร

**ที่มา:** คุณธนา — "ล็อกอินด้วยอีเมลกับรหัสผ่านพอครับ"

**เกณฑ์ยอมรับ**
- ล็อกอินด้วยอีเมลและรหัสผ่านที่ถูกต้องเข้าใช้ได้
- อีเมลหรือรหัสผ่านผิด เข้าใช้ไม่ได้
- ผู้ที่ยังไม่ล็อกอินเข้าหน้าใดในระบบไม่ได้

#### US-17 · หัวหน้างานเห็นเฉพาะไซต์ของตัวเอง — Must
**ในฐานะ** ฝ่ายไอที **ฉันต้องการ** ให้หัวหน้างานเห็นเฉพาะข้อมูลของไซต์ตัวเอง **เพื่อ** จำกัดการเข้าถึงข้อมูลตามหน้าที่

**ที่มา:** คุณธนา — "หัวหน้างานเห็นเฉพาะไซต์ของตัวเอง"

**เกณฑ์ยอมรับ**
- หัวหน้างานไซต์ ก เห็นรูป ผล และรายงานของไซต์ ก เท่านั้น
- หัวหน้างานไซต์ ก เปิดรูปหรือผลของไซต์อื่นไม่ได้ แม้เข้าทางลิงก์โดยตรง

#### US-18 · ผู้จัดการความปลอดภัยเห็นทุกไซต์ — Must
**ในฐานะ** ผู้จัดการความปลอดภัย **ฉันต้องการ** เห็นข้อมูลของทุกไซต์ **เพื่อ** ดูแลความปลอดภัยครบทั้ง 3 ไซต์

**ที่มา:** คุณธนา — "คุณวิชัยเห็นทุกไซต์"

**เกณฑ์ยอมรับ**
- บัญชีผู้จัดการความปลอดภัยเห็นรูป ผล และรายงานของทั้ง 3 ไซต์

#### US-19 · รูปไม่เปิดเป็นสาธารณะ และ API ต้องมี key — Must
**ในฐานะ** ฝ่ายไอที **ฉันต้องการ** ให้รูปไม่ถูกเปิดเป็นสาธารณะ และ API ต้องใช้ key **เพื่อ** ปกป้องรูปที่มีใบหน้าคนงาน

**ที่มา:** คุณธนา — "รูปมีหน้าคนงาน ห้ามเปิดเป็นสาธารณะ API ต้องมี key"

**เกณฑ์ยอมรับ**
- เปิดลิงก์ของรูปโดยไม่ล็อกอิน ไม่ได้รูป
- เรียก API โดยไม่มี key หรือ key ผิด ถูกปฏิเสธ
- เรียก API ด้วย key ที่ถูกต้อง ใช้งานได้

#### US-20 · เริ่มจากเครื่อง GPU ใบเดียว — Should
**ในฐานะ** ฝ่ายไอที **ฉันต้องการ** ให้รุ่นแรกเริ่มใช้งานด้วย GPU ใบเดียว (เช่าเป็นชั่วโมงได้) **เพื่อ** คุมค่าใช้จ่ายในช่วงเริ่มต้น

**ที่มา:** คุณธนา — "เครื่อง GPU เช่าเป็นชั่วโมงได้ แต่ขอเริ่มจากใบเดียวก่อน"

**เกณฑ์ยอมรับ**
- การทดสอบรับงานของรุ่นแรก (รวม US-10) ทำบนเครื่องที่มี GPU 1 ใบ
- (ความเร็วตาม US-05 อาจทำไม่ได้บน GPU ใบเดียวเมื่อรูปเข้าพร้อมกัน ดู C-02)
