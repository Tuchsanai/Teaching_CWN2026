### ข้อสังเกต/ฟีเจอร์ที่พบ

1. ธง BR-04/BR-05 คิดครั้งเดียวตอนระบบอ่าน การแก้ราคารายการหรือยอดรวมไม่ทำให้ธงเปลี่ยน (ทั้งเพิ่มและลบธง) จึงยืนยันใบที่ผลรวมรายการต่างจากยอดรวมเกือบ 28,000 บาทได้โดยไม่มีคำเตือน · ควรให้ผู้เขียน Requirement ชี้ว่า BR-05 ใช้กับ "ยอดที่อ่านได้" เท่านั้น หรือควรเตือนหลังแก้ด้วย
2. ใบจริงทุกใบได้ชื่อร้าน `UNKNOWN` และวันที่ `1900-01-01` · FR-03 ต้องอ่าน 5 ช่อง จึงยังไม่ครบ (ช่องที่ไม่ได้อยู่ใน charter นี้ ส่งต่อผู้ดูแล FR-03)
3. UI ปิดปุ่มยืนยันเมื่อยอดรวม < 0.01 แต่ไม่แสดงข้อความ `confirm-error` บอกเหตุผล ผู้ใช้อาจไม่รู้ว่าทำไมกดไม่ได้
4. API มีรหัส error ที่ไม่อยู่ในตาราง DESIGN 9.2: `total_not_checked` (422) · `review_not_opened` (409) · `bad_request` (400)
5. `GET /api/receipts/{id}` อย่างเดียวนับเป็น "เปิดดูรายละเอียดแล้ว" ตาม FR-12 (ไม่ต้องดูผ่านหน้าจอ)
6. ข้อความธงบอกค่าที่ใช้ตัดสินชัดเจน (ความมั่นใจ 0.6642 · ต่าง 20000.00 บาท) ดีต่อการตรวจ
