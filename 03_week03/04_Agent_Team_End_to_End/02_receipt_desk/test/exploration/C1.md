## ข้อสังเกต/ฟีเจอร์ที่พบ

- ⚠️ หน้าตรวจใบของ broken-trunc.jpg ขึ้น "ไม่พบไฟล์รูปของใบนี้ — ตรวจจากต้นฉบับกระดาษ หรือแจ้งผู้ดูแลระบบ" ทั้งที่ `GET /api/receipts/{id}/image` ตอบ 200 (image/jpeg 600 ไบต์) จริง ๆ คือไฟล์เสียแสดงผลไม่ได้ ไม่ใช่ไม่พบไฟล์ ข้อความอาจทำให้พนักงานเข้าใจผิดว่าไฟล์หาย (เบี่ยงเล็กน้อย ไม่ผิดกฎ)
- ⚠️ ประวัติ (W17) ของใบอ่านไม่ได้มีเหตุการณ์ processing แค่ครั้งเดียว และเวลา processing กับ unreadable เท่ากันทุกมิลลิวินาที ทั้งที่ attempts = 3 ดูจากประวัติไม่ได้ว่าลองอ่านกี่ครั้ง เมื่อไร (ตรวจ BR-07 ได้จากตัวเลข attempts เท่านั้น)
- ⚠️ ใบของ C1 ถูกอ่านเสร็จภายใน ~9 วินาที ทั้งที่คิวงานปกติค้าง 318 ใบ (processing 0) ดูเหมือนใบที่ค้างไว้ตอน reset ถูกพักไว้ ใบใหม่จึงแซงคิว ควรให้ผู้ทดสอบเรื่องคิว/ลำดับ (FIFO) ตรวจต่อ
- size-under/size-equal อ่านได้ merchant = "UNKNOWN", วันที่ 1900-01-01 แต่ไม่ติดธงใด ๆ (ยอดรวม 60000.00 ตรงเฉลย) — นอกขอบเขต C1 ส่งต่อผู้ทดสอบ BR-04 ว่าค่าวันที่/ชื่อร้านที่ไม่สมเหตุผลควรเตือนหรือไม่
- ฟีเจอร์ที่พบ: ระบบตรวจชนิดไฟล์จากเนื้อไฟล์ (magic bytes) ไม่เชื่อนามสกุลหรือ MIME ที่ส่งมา · error ของ API แบบรวม (`files[]` ระบุ index, name, error, rule ทุกไฟล์) · หน้าอัปโหลดแสดงคิวงานปกติ "318 / 400" · หน้าอ่านไม่ได้มีคอลัมน์ "อ่านไปแล้ว (ครั้ง)" และ "ย้ายมาเมื่อ" · หน้าตรวจบอกเงื่อนไขที่ยังขาดก่อนกดยืนยันเป็นรายการ (BR-06, ติ๊กเทียบยอด, หมวด, วันที่) · มีคีย์ลัด Ctrl+Enter / Ctrl+S / Alt+→
