## ข้อสังเกต/ฟีเจอร์ที่พบ

1. **P-05 ทดสอบได้ไม่เต็มจากบัญชีลูกค้า:** id ของใบเป็น UUID จึงเดา id จริงของ S-08 ไม่ได้ ทุกค่าที่ลองได้ 404 not_found แต่ยังไม่ได้พิสูจน์ด้วย id จริงของ S-08 · ควรให้บัญชีสำนักงานหา id ของ S-08 ก่อน แล้วลองซ้ำด้วยบัญชีลูกค้า (W12 และ W13)
2. **รหัส error ของรูปต่างกัน:** รูปของใบ seed ของร้านตัวเอง (S-01…S-07) ได้ `404 image_missing` ("ไม่พบไฟล์รูปของใบนี้") แต่ใบที่ไม่มีอยู่หรือของร้านอื่นได้ `404 not_found` · ถ้า W13 เช็กว่ามีไฟล์รูปก่อนเช็กว่าเป็นของร้านไหน ใบร้านอื่นที่ไม่มีไฟล์รูปจะตอบ image_missing และบอกได้ว่าใบนั้นมีอยู่ (ทดสอบไม่ได้เพราะไม่รู้ id ของ S-08 ต้องลองด้วยข้อ 1)
3. **ใบ seed ไม่มีไฟล์รูป:** ลูกค้าเปิดรูป S-01…S-07 ของร้านตัวเองไม่ได้ (404 image_missing) · ถ้าเป็นข้อจำกัดของข้อมูลทดสอบควรเขียนไว้ใน TEST-DATA
4. **ข้อมูลใช้ร่วมกันระหว่างผู้ทดสอบ:** CL-01 มีใบ pending-*/TD-*/urgent-*/broken-* ของผู้ทดสอบคนอื่นเกือบ 330 ใบ และระหว่างทดสอบมีคนยืนยัน broken-trunc.jpg (120.50 วันที่ 2026-11-19) ยอด พ.ย. จึงเปลี่ยนจาก 1,340.00 เป็น 1,460.50 · ค่าคาดหวัง E-02/E-05 ใช้ได้เฉพาะช่วงหลังรีเซ็ตเท่านั้น แต่กฎ "ผลรวมทุกหมวด = ยอดเดือน" ยังถูกทุกครั้ง
5. **หน้า /portal ใช้งานยาก:** ตารางใบเสร็จไม่แบ่งหน้า (330 แถว) และส่วน "รายจ่ายแยกหมวด" อยู่ท้ายตาราง ลูกค้าต้องเลื่อนลงไปไกลมาก · API W11 ส่งได้ทีละ 200 ใบถ้าไม่ระบุ limit (count 324 แต่ limit 200)
6. **ตัวกรอง flagged / overdue ถูกเงียบไว้สำหรับลูกค้า:** คืนทุกใบโดยไม่บอก error (ต่างจาก status ที่ตอบ 400) · ไม่รั่วข้อมูล แต่ไม่สม่ำเสมอ
7. คำตอบของ W7 ตอนอัปโหลดมีสถานะภายใน `"status":"queued"` และข้อมูลคิว `pendingNormal`/`limit` ของทั้งสำนักงานส่งถึงลูกค้า · ไม่ใช่ตัวเลขจากใบ แต่เป็นข้อมูลภายในที่ลูกค้าไม่จำเป็นต้องเห็น
