## อัลกอริทึมทีละขั้น (โค้ดอยู่ใน `scripts/opt/`)

1. **ตัววัดเร็ว** (`lib.mjs`): ใช้ `kit/lib/common.mjs` (`launch/newPage/openResults` ตัวเดียวกับ kit อ่านอย่างเดียว ไม่ได้แก้) → `fonts.ready` → 1000 ms → screenshot 1366×900 → pixelmatch threshold 0.1 includeAA false กับ `reference.png` เปิดหน้าครั้งเดียว แล้วลองค่าใหม่โดยแทนข้อความของ `<style id="opt-candidate">` → รอ 2 rAF + fonts.ready + 250 ms (ให้ transition ของสวิตช์จบ) → ถ่ายใหม่ (~75 ms/ภาพ ~0.5 วิ/ค่า)
   **ตรวจว่าตรงกับ kit:** r0 kit = 64321 px · ตัววัดเร็ว = 64321 px · r2 kit = 53255 / เร็ว = 53255 · r3 kit = 50655 / เร็ว = 50655 (ตรงทุกพิกเซล)
2. **แบ่ง diff เป็นบริเวณ** (`regions()`): นับพิกเซลแดง (255,0,0) ต่อแถบ 75 px + หากลุ่มพิกเซลที่ติดกันแบบ 8 ทิศ (ขยาย 3 px ให้ตัวอักษรในคำเดียวกันรวมกลุ่ม) → จุดกลางกล่องแต่ละกลุ่ม `elementsFromPoint` → element เล็กสุดที่กล่องคลุม ≥30% ของกลุ่ม → เรียงตามจำนวนแดง (`probe.mjs` → `probe.json`) เช่น r0: `.list-sub` 3580 · หัวเว็บ 3198 · toast 2983 · `.results-info-button` 2470 · `.tab.on` 2114 · `.insight-head h4` 1853 …
3. **ตัวแปร + coordinate descent** (`opt.mjs`): สไตล์ของ selector ของบริเวณเหล่านั้นเป็นตัวแปร (ค่าเริ่ม = computed style) ฟอนต์เป็นตัวเลือกแบบกลุ่ม (เฉพาะฟอนต์ที่มีในเครื่องและสัญญาอนุญาตเปิด: TLWG = GPL-2+ font exception, Liberation = OFL, FreeSans = GPL+FE) ตัวเลข: ลอง `+step` แล้ว `−step` ถ้าดีขึ้นเดินต่อทางเดิมจนไม่ดีขึ้น ถ้าไม่ดีขึ้นทั้งสองทางลด step ครึ่งหนึ่ง (จนถึง step/4) แล้วไปตัวแปรถัดไป วนหลายรอบจนรอบหนึ่งไม่ดีขึ้นหรือหมดงบเวลา
   - ชุด A (`vars-a.json`, 35 ตัวแปร: ฟอนต์ · ขนาด · น้ำหนัก · ระยะห่างตัวอักษร · ความสูงแถว) งบ 420 วิ → 695 ค่า
   - ชุด B (`vars-b.json`, 19 ตัวแปร: สีพื้น/เส้นของแท็บ ชิป ป้าย · ระยะห่างตัวอักษร · กรอบป้ายสายการบิน) งบ 180 วิ → 309 ค่า
4. **ข้อจำกัดแบบแข็ง** ตรวจก่อนเก็บทุกค่าที่ทำให้ diff ลดลง (ไม่ผ่าน = ทิ้งทันที ใช้ค่าเดิม)
   a. `page.locator('body').ariaSnapshot()` ต้องเท่ากับสตริงที่จับตอนเปิดหน้า (ต้นขั้นที่ 2) ทุกตัวอักษร
   b. `GUARD_FN` ในหน้า: ทุก element ที่มองเห็นและมีข้อความของตัวเอง + `::before/::after` ที่มี content เป็นข้อความ → font-size ≥ 12 px · contrast WCAG ≥ 4.5:1 เทียบพื้นที่ทับซ้อนจริง (ไล่บรรพบุรุษ ผสม alpha; พื้นไล่สีคิดทุก color stop เอาค่าแย่สุด) · opacity สะสมทุกบรรพบุรุษ = 1 · ความกว้าง/สูง ≥ 75% ของ element เดียวกันใน v4 (เปิด v4 ที่พอร์ต 5084 ด้วยขั้นตอนเดียวกัน, key = tag.class + ข้อความ 30 ตัวแรก ที่ไม่ซ้ำ; ตรงกัน 297 element → `v4-sizes.json`) · ตัดบรรทัดกลางคำ: ไล่ทีละอักษรด้วย `Range.getClientRects()` จุดที่ขึ้นบรรทัดใหม่ต้องเป็นขอบคำของ `Intl.Segmenter('th', {granularity:'word'})`
   แอปตอนเริ่ม **ไม่ผ่าน** (ตัวอักษร 11 px 10 จุด, contrast < 4.5 35 จุด) → ซ่อมก่อนเริ่มค้น (r1)
5. **เขียนลงแอป**: ค่าที่ได้เขียนลง `src/components/results-tuned.css` (import ต่อจาก `results-v4.css`) ฟอนต์ใส่ใน `globals.css` พร้อม `@font-face` ที่ใช้ `local()` ก่อนแล้วตกไปไฟล์ใน `public/fonts/` (ผู้ใช้จริงได้ฟอนต์เดียวกัน ใบอนุญาตใน `public/fonts/TLWG-LICENSE.txt`) → build → `measure.sh` เต็ม → เก็บถ้า Score ดีขึ้นและ gate ผ่าน

## ข้อจำกัด / สิ่งที่ควรรู้
- ฟอนต์ที่ได้ ("Tlwg Typo") เป็นฟอนต์ความกว้างคงที่ของ TLWG ซึ่ง descent เลือกเพราะ diff ต่ำสุด อ่านได้ปกติแต่หน้าตาคล้ายพิมพ์ดีด ถ้าอยากได้ฟอนต์ทั่วไปกว่านี้ อันดับถัดไปในชุดเดียวกันคือ Loma/Waree (diff สูงกว่า)
- ค่าใน `results-tuned.css` ใช้ `!important` ตามที่วัดตอนฉีด CSS (เพื่อให้ผลตรงกับตัววัดเร็ว)
- สีเส้นใต้แท็บ #1a73e8 เป็นเพียงค่าสี ไม่ได้คัดลอกโลโก้/ฟอนต์/โค้ดของ Google ไม่มีโค้ดตรวจว่ากำลังโดนทดสอบ ไม่มีเนื้อหาซ่อน
- ใช้เวลาไปราว 45 นาที จึงหยุดการค้นหาหลัง r3 ยังเหลือบริเวณแดงมาก (หัวเว็บ/โลโก้ ~4.3k px, toast 2.5k, กรอบแท็บ) ที่ต้องเปลี่ยนเลย์เอาต์หรือแบรนด์จึงจะลดได้
