ทำเสร็จแล้ว สกิล `gpu-api-capacity` อยู่ที่ `lab5_image_api/skill_v0/` และติดตั้งไว้ที่ `.claude/skills/gpu-api-capacity/` แล้ว สองที่นี้มีไฟล์เหมือนกันทุกไฟล์ ยังไม่ได้รันสกิลกับเครื่องจริง ซึ่งจะได้ลองในขั้นที่ 11

## โครงของสกิล

```
gpu-api-capacity/
├── SKILL.md      name + description (บอกว่าใช้เมื่อไร เช่น "ทำ LAB 5 ซ้ำ", "Micro-batching ช่วยได้กี่เท่า")
└── scripts/      โค้ดจากรอบจริง 11 ไฟล์
```

`SKILL.md` แบ่งเป็นส่วนต่าง ๆ ดังนี้
- **หลักใช้งาน:** งานที่แตะ Vast.ai ทุกอย่างให้ใช้สกิล `vastai` และห้ามแก้ไฟล์ของสกิลนั้น มีแผนผังโฟลเดอร์ `/workspace/lab5/` บนเครื่องเช่า และตารางบอกหน้าที่ของแต่ละสคริปต์
- **ค่าที่ปรับได้:** ดูตารางด้านล่าง พร้อมตารางชุดที่วัด (คำสั่ง `cluster.sh up`, คำสั่งวัด, ไฟล์ผล, เวลาอ้างอิง)
- **ขั้นตอน 5 ขั้น:** เช่าเครื่อง → ติดตั้งและทดสอบจากนอกเครื่อง → ยิงโหลดทีละชุด (ถ้า N ไหนพลาดแค่ครั้งเดียว ให้วัดซ้ำ) → รวมผลและทำกราฟบนเครื่องนี้ → ลบเครื่องและดูบิลจริง
- **เกณฑ์ตรวจผ่าน:** ใส่ตัวเลขจากรอบจริงไว้เทียบ คือ 22 → 52 → 104 → 176 คน, least_conn ได้ 256 เทียบ 176 และ 72 เทียบ 32 คน, ตอน replica ล่มถ้า NGINX ไม่ส่งซ้ำมี error 36.9% แต่ถ้าส่งซ้ำ error เป็น 0
- **กติกาเรื่องเงิน:** ลบเครื่องเสมอ แม้ขั้นไหนล้มก็ดึงผลกลับก่อนแล้วลบ · ห้ามเกินเพดานราคา · เช่าได้ครั้งละ 1 เครื่อง · แตะเฉพาะเครื่องป้ายของตัวเอง · งบอ้างอิงคือรอบเต็ม 2 ชม. 40 นาที จ่ายจริง $1.011 · ถ้าเครื่องเปิดเกิน 3 ชั่วโมงต้องรายงานก่อนทำต่อ
- **สรุปตอนจบ:** ตารางและประโยคสรุปความจุ ถ้าไม่ได้วัดชุด `gpu1` ต้องบอกด้วยว่าตัวเลขเทียบกับ `base1` นั้นรวมผลของวิธีประมวลผลกับผลของ GPU ใบที่ 2 ไว้ด้วยกัน

## ค่าที่ปรับได้และค่าเริ่มต้น

| ค่า | ค่าเริ่มต้น |
|---|---|
| รุ่นและจำนวน GPU | RTX 3090 × 2 (ถ้าใช้ 1 ใบ จะตัดชุด gpu2, lb, failover ออกเอง) |
| เพดานราคา | $0.60/ชม. สำหรับ 2 ใบ · $0.30/ชม. สำหรับ 1 ใบ |
| ป้ายเครื่อง | `vapp-lab5` |
| เกณฑ์ SLO | p95 ≤ 500 ms และ error < 1% |
| ระดับ N | 1,4,16,32,64,128,256,512,1024 · ระดับละ 20 วินาที (warm-up 5 วินาที) · timeout 10 วินาที · ซอยครึ่งหา N ที่พอดีเกณฑ์ 3 รอบ |
| แบบที่จะวัด | `base1` `batch1` `gpu1` `gpu2` `lb` `failover` |
| อื่น ๆ | batch 32 · 4 process ต่อ GPU · เงื่อนไขเลือกเครื่อง (ใช้ CPU ที่ได้จริง ≥ 24 core) · image/disk/พอร์ต 8080 · ผู้ใช้ตอนทดสอบ replica ล่ม · `out_dir` · `keep_machine` |

เงื่อนไขเลือกเครื่องใช้ค่า CPU ที่ได้จริง (`cpu_cores_effective`) เพราะรอบจริงเครื่องโชว์ 192 core แต่ได้ใช้จริงประมาณ 27 core

## ไฟล์ที่เก็บเข้าไปใน `scripts/`

- **คัดลอกมาตรง ๆ:** `server.py` `cluster.sh` `run_single.sh` `run_lb_compare.sh` `run_failover.sh` `summ_lb.py`
- **คัดลอกแล้วเพิ่มตัวเลือก (ค่าเริ่มต้นยังเหมือนรอบจริง):**
  - `loadgen.py`: เพิ่ม `--levels` `--level-s` `--warmup` `--timeout` `--slo-p95` `--slo-err` `--bisect` และ `--recheck N --times 3` ไว้วัดซ้ำระดับที่พลาดครั้งเดียว แบบที่เกิดกับ gpu2 ที่ N=64
  - `report.py`: รันได้แม้วัดไม่ครบทุกชุด (กราฟที่ขาดข้อมูลจะข้ามไป) และอ่านเกณฑ์ SLO จากไฟล์ผล ทดสอบกับผลจริงทั้งหมดแล้ว ได้ `metrics.json` ตรงกับของเดิม และทดสอบชุดย่อย base1 + gpu2 ก็รันผ่าน
  - `test_api.py`, `make_grid.py`: ระบุพาธเองได้ ทดสอบสร้างภาพตารางรูปจากผลจริงแล้วผ่าน
- **ไฟล์ใหม่:** `install.sh` เป็นไฟล์เดียวที่ไม่ได้มาจากรอบจริง เพราะหาคำสั่งติดตั้งของรอบนั้นไม่เจอ ผมรวบรวมรายการแพ็กเกจจาก import ของโค้ด และเขียนบอกไว้ใน SKILL.md แล้ว ไฟล์นี้จะถูกทดสอบจริงครั้งแรกในขั้นที่ 11

สคริปต์ `.sh` ทุกไฟล์ผ่านการตรวจไวยากรณ์ (`bash -n`) และ `.py` ทุกไฟล์ parse ผ่าน
