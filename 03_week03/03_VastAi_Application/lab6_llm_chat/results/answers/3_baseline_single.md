## สรุป: ยิงโหลดแชทบอทบน GPU 1 ใบ แบบตอบทีละคำถาม (เครื่อง vapp-lab6, RTX 3090)

ผลที่ได้คือรองรับได้ 2 คน ระดับ N = 1 และ 2 ผ่าน SLO ส่วน N = 3 และ 4 ไม่ผ่านติดกัน 2 ระดับ ตัวยิงจึงหยุดเองก่อนถึง N = 6 และ 8 ตามกติกาที่ตั้งไว้ ไม่มีระดับไหนผลก้ำกึ่ง ค่าที่ใกล้เส้นที่สุดคือ TTFT p95 ของ N = 2 ได้ 1.60 วินาที ห่างเส้น 2 วินาทีอยู่ 20% จึงไม่ต้องวัดซ้ำ

| คำถาม | คำตอบจริง (ย่อ) | token ขาเข้า / คำตอบ | TTFT | เวลารวม |
|---|---|---|---|---|

| ทิชชู่ม้วนกับทิชชู่กล่อง แบบไหนคุ้มกว่าครับ | ทิชชู่ม้วนคุ้มกว่า เพราะราคาถูกและใช้ได้ทั้งในบ้านและนอกบ้าน… | 86 / 69 | 0.05 วิ | 0.85 วิ |

| N | TTFT p50 / p95 (วิ) | token/วิ ต่อผู้ใช้ p50 / p5 | token/วิ รวม | คำถามที่รอคิว (เฉลี่ย / สูงสุด) | error | ผ่าน SLO ไหม |

**อ่านผลอย่างไร**
- ความเร็วต่อผู้ใช้คงที่ราว 84 token/วินาที และ token/วินาทีรวมคงที่ราว 82 ไม่ว่า N จะเท่าไร เพราะ GPU ตอบได้ทีละคำถามเท่านั้น
- ผู้ใช้ที่เพิ่มเข้ามาไปต่อคิวรอ จำนวนที่รอคิวเท่ากับ N − 1 พอดี TTFT จึงเพิ่มขึ้นราว 1 วินาทีต่อผู้ใช้ 1 คน (หนึ่งคำตอบใช้ราว 1 วินาที)
- เกณฑ์ที่ทำให้ไม่ผ่านคือ TTFT เพียงอย่างเดียว ความเร็วต่อผู้ใช้และ error ผ่านทุกระดับ
- vLLM ตัวเดียว (vllm-1) รับคำถามทั้งหมด
- GPU 0 ทำงาน 97–100% ร้อนสูงสุด 67°C และ clock อยู่ราว 1,860–1,880 MHz ไม่มีการลด clock เพราะร้อน ส่วน GPU 1 ว่างตลอด (210 MHz, 54°C)
- ตัวยิงใช้ CPU รวมแค่ราว 1.4% จึงไม่ได้เป็นคอขวด

**ชุดคำขอที่ใช้ยิง** อยู่ในภาพ `lab6_llm_chat/results/dataset_samples.png` เป็นตารางคำถาม 8 ข้อคู่กับคำตอบจริง จำนวน token และเวลา คำขอ 1 รายการคือ `POST http://127.0.0.1:8000/v1/chat/completions` (เข้าทาง NGINX) มีช่องดังนี้:
- **header**
  - `Authorization: Bearer <API key>` ถ้าไม่มี key จะถูกปฏิเสธด้วย 401
  - `Content-Type: application/json`
- **body**
  - `model: "shop-bot"` คือชื่อโมเดลที่ vLLM เปิดไว้
  - `stream: true` ให้ส่งคำตอบทีละ token
  - `max_tokens: 150` คือเพดานความยาวคำตอบ
  - `stream_options.include_usage: true` ให้ข้อความสุดท้ายบอกจำนวน token ขาเข้าและขาออก
  - `messages` มี 2 ข้อความ:
    - `system` บอกบทบาทพนักงานร้าน ให้ตอบภาษาไทย สุภาพ ไม่เกิน 3 ประโยค
    - `user` คือคำถามที่สุ่มจาก 40 ข้อ
