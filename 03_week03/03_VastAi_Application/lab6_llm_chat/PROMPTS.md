# LAB 6 · พรอมต์ Copy & Paste — แชทบอท LLM รองรับผู้ใช้พร้อมกันกี่คน

คำถามของ LAB: แชทบอท LLM แบบ streaming บน GPU 1 ใบ รับผู้ใช้พร้อมกันได้กี่คน · Continuous Batching ช่วยให้ GPU ใบเดิมรับได้เพิ่มกี่เท่า · เพิ่มเป็น 2 GPU หลัง Load Balancer แล้วรับได้เพิ่มกี่เท่า

วางทีละพรอมต์ในช่องพิมพ์ของ Claude Code app (เปิดที่โฟลเดอร์ของบทนี้) ทำตามลำดับขั้นที่ 1 → 9 ให้ครบในรอบเดียว · ขั้นที่ 1–7 ใช้ **เครื่องเดียวกัน** ต่างกันแค่วิธีเสิร์ฟและจำนวน GPU
โค้ดทุกไฟล์ AI เขียนให้จากพรอมต์ ลงในโฟลเดอร์ `lab6_llm_chat/code/` (เริ่มจากโฟลเดอร์ว่าง) · ผลการวัดอยู่ที่ `lab6_llm_chat/results/`
LAB นี้ **เสียเงินจริง** ราว $0.5–1 (เครื่อง RTX 3090 2 ใบ ราว $0.35/ชม.) · เครื่องเปิดค้างตั้งแต่ขั้นที่ 1 ถึงขั้นที่ 7 จึงต้องทำขั้นที่ 7 ทุกครั้ง

นิยามที่ใช้ทั้ง LAB
- **ผู้ใช้พร้อมกัน (Concurrent Users, N)** = ผู้ใช้จำลอง N คน แต่ละคนถาม รอคำตอบจนจบ แล้วถามข้อใหม่ทันที (closed-loop ไม่มี think time)
- **เกณฑ์ SLO** ของแชทบอท: TTFT p95 ≤ 2 วินาที (95% ของคำถามเห็นตัวอักษรแรกภายใน 2 วินาที) · 95% ของคำถามได้ความเร็ว ≥ 15 token/วินาที · error < 1%
- **"รองรับได้ N คน"** = ระดับ N สูงสุดที่ผ่านเกณฑ์ SLO และทุกระดับที่ต่ำกว่าก็ผ่านด้วย
- **ระดับที่ผลก้ำกึ่ง** (TTFT p95 หรือความเร็วต่อผู้ใช้ห่างจากเส้นเกณฑ์ไม่เกิน 5%) ให้วัดซ้ำอีก 2 ครั้ง แล้วตัดสินด้วยค่ากลาง (median) ของ 3 ครั้ง เพื่อไม่ให้ผลแกว่งครั้งเดียวมาตัดสิน

## ขั้นที่ 2 · เขียนสคริปต์เปิดแชทบอท แล้วเปิดบน GPU 1 ใบ (~12 นาที)

```text
เตรียมเครื่อง เขียนสคริปต์เปิดแชทบอท แล้วเปิดบน GPU 1 ใบ

   - เปิด vLLM 1 หรือ 2 ตัว ตัวละ 1 GPU คนละพอร์ต ชื่อโมเดลที่ผู้ใช้เรียกคือ shop-bot ความยาวบริบท 4096 token

   - ต้องใช้ API key ที่สคริปต์สุ่มเองและเก็บไว้บนเครื่องที่เช่า · ระบบที่เปิดแล้วต้องทำงานต่อได้แม้การเชื่อมต่อหลุด
3. เปิดแชทบอท 1 GPU แบบ Continuous Batching แล้วทดสอบบนเครื่องที่เช่า: ถามคำถามลูกค้าร้านขายของใช้ในบ้าน 2 ข้อพร้อม key (ตอบไม่เกิน 150 token) · เรียกแบบไม่มี key ต้องถูกปฏิเสธ
```

## ขั้นที่ 3 · เขียนตัวยิงโหลด แล้ววัด Baseline: GPU 1 ใบ ตอบทีละคำถาม (~12 นาที)

```text

เครื่องที่ใช้คือเครื่องป้าย vapp-lab6 · กุญแจ SSH อยู่ที่ /workspace/vastai_lab/Devtool_SSH/devtoolSSH

เขียนตัวยิงโหลด แล้ววัดว่าแชทบอทบน GPU 1 ใบที่ตอบทีละคำถาม (ไม่มี batching) รองรับผู้ใช้พร้อมกันได้กี่คน

3. เปิดแชทบอท 1 GPU แบบตอบทีละคำถาม แล้วยิงโหลดบนเครื่องที่เช่าด้วย N = 1, 2, 3, 4, 6, 8 ให้รันต่อได้แม้การเชื่อมต่อหลุด แล้วคัดลอกผลกลับมาไว้ที่ lab6_llm_chat/results ของโฟลเดอร์ปัจจุบันนอก container
4. ให้ผู้เรียนเห็นชุดคำขอที่ใช้ยิง: ทำภาพตารางคำถาม 8 ข้อจากชุด 40 ข้อ คู่กับคำตอบจริงของแชทบอท จำนวน token และเวลา
   เก็บที่ lab6_llm_chat/results/dataset_samples.png ของโฟลเดอร์ปัจจุบันนอก container และอธิบายคำขอ 1 รายการว่ามีช่องอะไรบ้าง
```

```text
เขียนประโยค "1 ใบ N₁ คน → 2 ใบ N₂ คน (x เท่า, efficiency y%)" บอกว่า GPU 2 ใบได้งานเท่ากันไหม และประมาณว่าถ้าเพิ่มเป็น 3 ใบน่าจะได้กี่คน (บอกว่าเป็นการคำนวณ ไม่ใช่ผลวัด) แล้วบอกว่าเครื่องยังเปิดอยู่
```

## ขั้นที่ 6 · ทดลองเสริม: Round Robin เทียบ least_conn เมื่อคำตอบยาวไม่เท่ากัน (~8 นาที)
