ตอนนี้เว็บเลือกคุยได้ทั้งโมเดลเดิม (Base) และโมเดลที่เทรนแล้ว (Fine-tuned) และมีหน้า /compare สำหรับเทียบคำตอบ ลองครบทั้ง 4 อย่างในเบราว์เซอร์แล้วทำงานได้ทุกอย่าง มีเรื่องเดียวที่ต้องรู้ คือตอนจองคิว โมเดล Fine-tuned ตอบผิดในข้อความแรก (รายละเอียดอยู่ในตารางผลการลอง)

ก่อนเริ่มงาน ไฟล์ `chatbot.env` มีอยู่แค่ใน container `multi-account` (ขั้นที่ 5 รันในนั้น) เลยคัดลอกมาไว้ที่ `lab3_qlora/chatbot.env` บนเครื่องนี้ ไฟล์นี้อยู่ใน `.gitignore` และไม่ได้แสดงค่า key บนจอ

**สิ่งที่แก้**
1. `docker-compose.yml`: ตั้งชื่อ project เป็น `vapp-lab3` ใช้พอร์ต 3403 และอ่านที่อยู่ AI server กับชื่อโมเดลจาก `../../chatbot.env` เปิดเว็บ + PostgreSQL ได้ด้วยคำสั่ง `docker compose up -d --build` คำสั่งเดียว
2. `/api/chat` รับค่า `model` (`base` หรือ `ft`) เพิ่มได้ ถ้าไม่ส่งมาจะใช้โมเดลเริ่มต้นของเว็บ ซึ่งเก็บในตาราง `app_settings` และอ่านใหม่ทุกข้อความ จึงสลับได้ขณะเว็บเปิดอยู่ด้วย `PUT /api/model {"model":"base"}` ตอนนี้ค่าเริ่มต้นคือ Fine-tuned
3. หน้าแชทมีปุ่มเลือกโมเดล 3 แบบ (ค่าเริ่มต้น / Base / Fine-tuned) ใต้คำตอบแต่ละข้อบอกว่าโมเดลไหนตอบ ส่วนที่ชุดทดสอบ 26 เคสใช้ (`data-testid` ทุกตัว, รูปแบบ SSE, การจอง) ไม่ได้แตะเลย
4. หน้า `/compare` ใหม่ ถาม 2 โมเดลทีละตัวด้วย system prompt เดียวกับหน้าแชท ไม่ยิงพร้อมกัน เพื่อให้ตัวเลข token/วินาทีเทียบกันได้ตรง ๆ หน้านี้ตรวจแท็กจองแต่ไม่บันทึกการจองจริง และเก็บคำถามล่าสุดในตาราง `compare_runs`

**สถานะตอนนี้**
- **เว็บยังเปิดอยู่:** `vapp-lab3-web-1` และ `vapp-lab3-db-1` ทำงานอยู่ ทั้ง 3 หน้าตอบ 200
- **เครื่อง Vast ป้าย `vapp-lab3` น่าจะยังเปิดอยู่:** AI server ตอบคำถามทุกข้อข้างบน แต่ตอนเช็กรายการเครื่องรอบสุดท้ายผ่าน vastai ไม่เจอบรรทัดของ `vapp-lab3` เลยยืนยันจากรายการเครื่องไม่ได้ ควรเช็กอีกรอบก่อนเริ่มขั้นที่ 7
- **ชุดทดสอบขั้นที่ 7:** `e2e/run-all.sh` ยังตั้งค่าเริ่มต้นเป็นพอร์ต 3300 และใช้โฟลเดอร์ `../frontend` ตอนล้างตาราง ไม่ได้แก้ไฟล์นี้เพราะเป็นของชุดทดสอบ ตอนรันต้องตั้ง `BASE_URL=http://localhost:3403` และล้างตารางของ project `vapp-lab3` เอง
