## ผลวัด Base เทียบ Fine-tuned บน Validation Set

ทดสอบ 48 บทสนทนา รวม 85 ข้อความที่ลูกค้าพิมพ์ ทั้งสองโมเดลได้ประวัติแชทเดียวกัน ตั้ง temperature 0 และตรวจด้วยเงื่อนไขที่กำกับไว้ใน Dataset

| ตัวชี้วัด | Base (qwen3-4b-base) | Fine-tuned (qwen3-4b-sabaijai) |
|---|---|---|
| คำตอบที่ถูก (85 ข้อ) | 87.1% | **94.1%** |
| แท็กจองถูกรูปแบบ (8 ข้อที่ข้อมูลครบ) | 100% | 100% |
| ข้อมูลในแท็กจองถูกครบ (8 ข้อ) | 100% | 100% |
| ใส่แท็กจองทั้งที่ข้อมูลไม่ครบ (77 ข้อ) ↓ ยิ่งน้อยยิ่งดี | 6.5% | **1.3%** |
| ลงท้ายว่า "ครับ" (83 ข้อภาษาไทย) ↓ | 3.6% | **0%** |
| มีคำไทยปนในคำตอบภาษาอังกฤษ (2 ข้อ) ↓ | 100% | **0%** |
| ความเร็ว (token/วินาที, ส่งทีละคำขอ) | 55.0 | 50.6 |
| VRAM ที่ server ใช้ (สูงสุด) | 21.4 GB จาก 24 GB | 21.4 GB จาก 24 GB (server เดียวกัน) |

- **VRAM:** ค่า VRAM เป็นของทั้ง server เพราะสองโมเดลอยู่บน GPU ตัวเดียวกัน ตัวเลขสูงเพราะ vLLM จองหน่วยความจำล่วงหน้าไว้ 85% ของการ์ด ไม่ได้แปลว่าโมเดลใช้จริงเท่านั้น
- **ความเร็ว:** Fine-tuned ช้ากว่าราว 8% เพราะ server ต้องคำนวณ adapter เพิ่ม
- **ตัวหารเล็ก:** ข้อที่ต้องใส่แท็กจองมีแค่ 8 ข้อ และข้อภาษาอังกฤษมีแค่ 2 ข้อ ตัวเลขสองแถวนี้จึงแกว่งง่าย
- **จุดที่ Fine-tuned แย่ลง:** มี 2 ข้อที่ Base ถูกแต่ Fine-tuned ผิด คือถามว่า "ลด 10% ต้องมาก่อนกี่โมง" แล้ว Fine-tuned ตอบสั้นเกินจนไม่บอกว่าเป็นวันจันทร์ถึงพฤหัสบดี

## ตัวอย่าง 2 ข้อที่สองโมเดลตอบต่างกัน

1. **"นวดไทย 2 ชั่วโมง ราคานักศึกษาเท่าไหร่นะคะ"** (คำตอบที่ถูกคือ 510 บาท)
   - Base: "600 - (600 x 15%) = **460 บาท**" คิดเลขผิด
   - Fine-tuned: "ราคาปกติ 600 บาท สำหรับนักศึกษาลด 15% **เหลือ 510 บาทค่ะ**" ถูก
2. **"ธนพล โทร 0833438489 อยากนัดนวดแก้ปวดหลัง 18 ก.พ. ตอน 08:00 น.นะครับ"** (เป็นเวลาก่อนร้านเปิด)
   - Base: รับจองให้และใส่แท็ก `[BOOKING]…08:00` ซึ่งผิด เพราะร้านยังไม่เปิด
   - Fine-tuned: "ขออภัยค่ะ ร้านเปิดให้บริการตั้งแต่ 10:00 น. … กรุณาแจ้งเวลาใหม่" ถูก

## โค้ดทำอะไร
- **`serve.sh`:** เปิด `vllm serve` ตัวเดียวที่พอร์ต 8000 ชื่อโมเดลเดิมคือ `qwen3-4b-base` และเพิ่ม adapter เป็นชื่อ `qwen3-4b-sabaijai` ด้วย `--enable-lora --lora-modules`
- **API key:** สุ่มใหม่ด้วย `secrets` แล้วเก็บในไฟล์ที่เปิดอ่านได้เฉพาะเจ้าของ (chmod 600) ส่งให้ vLLM ทางตัวแปร `VLLM_API_KEY` จึงไม่โผล่ทั้งบนจอและในรายการโปรเซส ทดสอบแล้วว่าถ้าไม่ใส่ key จะได้ 401
- **`eval_val.py` เตรียมคำถาม:** แตกแต่ละบทสนทนาเป็นรายข้อ ใช้ข้อความก่อนหน้าจาก Dataset เป็นประวัติแชท แล้วส่งให้ทั้งสองโมเดลทีละคำขอ
- **`eval_val.py` ตรวจคำตอบ:** ใช้กติกาเดียวกับตอนสร้าง Dataset (`make_dataset.py`) คือคำที่ต้องมี คำต้องห้าม ภาษา markdown และแท็กจอง แล้วนับเป็น % ตามตัวชี้วัด
- **วัดความเร็วและ VRAM:** ความเร็วคิดจากจำนวน token ที่ตอบหารด้วยเวลา ส่วน VRAM อ่านด้วย `nvidia-smi` ผ่าน SSH ทุก 2 วินาทีระหว่างวัด ผลทั้งหมดรวมคำตอบรายข้อเก็บไว้ที่ `lab3_qlora/results/val_eval.json`
