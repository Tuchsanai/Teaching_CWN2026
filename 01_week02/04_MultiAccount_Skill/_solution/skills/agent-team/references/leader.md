# หัวหน้าทีม (lead), การสลับหัวหน้า และงบโทเค็น

## หลักการ

1. สถานะอยู่ในไฟล์: `state.json` (เป้าหมาย งานทั้งหมด หัวหน้าปัจจุบัน `leader`, ประวัติ `lead_history`) + `handoff.md` (ทำอะไรแล้ว งานทั้งหมดตอนนี้ ขั้นต่อไป การตัดสินใจ)
2. ผู้ควบคุม = `team.py lead` (สคริปต์ ไม่ใช้โทเค็น) รันหัวหน้าทีม 1 รอบ (episode) ต่อการเรียก 1 ครั้ง และรันตัวจัดคิวลูกทีมใน process ของตัวเอง
3. ลูกทีมไม่ผูกกับหัวหน้า: `dispatch` แค่เพิ่มงานลง `state.json` ตัวจัดคิวรันลูกทีมเป็น process แยก ผลลง `out/`

## คำสั่งของหัวหน้า (หัวหน้าได้รับใน prompt พร้อม path จริง)

| คำสั่ง | ทำอะไร |
|---|---|
| `dispatch --run R --tasks-file f.json` | แจกหลายงานครั้งเดียว `[{"id","prompt","expect"?,"account"?,"difficulty"?,"depends_on"?,"kind"?}]` · id ซ้ำไม่แจกซ้ำ |
| `dispatch --run R --id t1 --prompt "…" [--expect int]` | แจกทีละงาน |
| `wait --run R [--ids a,b] [--timeout 300]` | รอจนงานจบ พิมพ์สถานะ/ค่า/path |
| `combine --run R --ids a,b,c --output P [--title T] [--headings]` | ต่อ `out/*.md` เป็นไฟล์เดียว (ไม่เสียโทเค็น) |
| `checkpoint --run R --done "…" --next "…" --decisions "…"` | เขียน `handoff.md` |
| `finish --run R --result P --summary "…"` | บันทึกว่าเป้าหมายเสร็จ |
| `status --run R --brief` | ดูงานทั้งหมด |

## เมื่อไรสลับหัวหน้า

| ชนิด | เงื่อนไข | สิ่งที่เกิด |
|---|---|---|
| เชิงรุก | โทเค็นของหัวหน้า (นับสดจาก stream-json ของ Claude ทุกข้อความ; Codex นับหลังจบรอบ) > `--lead-token-budget` หรือแจกงานครบ `--max-dispatch-per-episode` หรือโควตา session ≥ `--quota-threshold` | ทุกคำสั่งของหัวหน้า (dispatch/wait/combine) ตอบ "งบหัวหน้าหมด" ทันที → หัวหน้าเขียน checkpoint แล้วจบรอบ · ถ้าไม่จบภายใน `--over-budget-grace` (120 s) ผู้ควบคุม kill เอง |
| เชิงรับ | process หัวหน้าถูก kill / รอบล้ม (โควตาหมด, rate limit, ล็อกอินหมดอายุ) / เกิน `--episode-timeout` / heartbeat ไม่อัปเดตเกิน `--heartbeat-timeout` | ผู้ควบคุมต่อท้าย `handoff.md` ว่าหัวหน้าล้มก่อน checkpoint ให้ใช้ `state.json` เป็นหลัก แล้วเริ่มหัวหน้าคนใหม่ |
| ไม่สลับ | รอบจบปกติ ยังไม่ finish และงบยังเหลือ | หัวหน้าคนเดิมเริ่มรอบถัดไป (สูงสุด `--max-episodes` 8) |

ผู้สืบทอด: ตาม `--succession` ก่อน ไม่งั้นอัตโนมัติ = บัญชีที่ตรวจแล้วพร้อม ไม่ถูกหยุดรับงาน ไม่อยู่ใน `--exclude` ไม่เคยล้ม/หมดงบในฐานะหัวหน้าใน run นี้ ฝั่งเดียวกันก่อนแล้วจึงข้ามฝั่ง โควตาใช้ไปน้อยสุด (หัวหน้าเป็น Codex ได้)

ทุกการสลับ: `state.json.lead_history` (ts, from, to, type, reason, episode, tokens, checkpoint) · `board.md` · ledger `event: lead_switch` · ตารางสรุปท้าย `lead`

## งบโทเค็นและโควตาลูกทีม

- tokens ของบัญชีใน run = Σ (input รวม cache + output) ของทุกการเรียกงานของบัญชีนั้น (ไม่นับการตรวจความพร้อม)
- ตรวจทันทีที่งานแต่ละชิ้นจบ: เกิน `--worker-token-budget` (N หรือ `บัญชี=N`) หรือโควตา ≥ `--quota-threshold` (ค่าเริ่มต้น 80%) → บัญชีนั้น "หยุดรับงาน" งานที่กำลังรันทำจนจบ งานในคิวที่วางแผนให้บัญชีนั้นย้ายไปบัญชีอื่น (`worker_switch`) — งานที่ผู้ใช้ระบุบัญชีเองไม่ย้าย จะล้มพร้อมเหตุผล
- ก่อนแจกงาน: อ่านโควตาทุกบัญชีที่พร้อม (Claude `/usage` ไม่เสียโทเค็น · Codex rollout ล่าสุด) วางแผนให้บัญชีที่งานน้อย/โควตาเหลือมากก่อน
- `status` ตาราง: บัญชี | บทบาท | งานที่รัน | งานในคิว | tokens ใน run (/ งบ) | โควตาล่าสุด (เวลาของข้อมูล) | สถานะ (พร้อม / ใกล้หมด ≥ เกณฑ์−20% หรือ ≥ 80% ของงบ / หยุดรับงาน / ใช้ไม่ได้)

## ค่าที่ `--demo` ตั้งให้ (เปลี่ยนได้ด้วย flag เดียวกัน)

| เหตุการณ์ | ค่า |
|---|---|
| หัวหน้าคนแรก | Claude ที่พร้อมและโควตาใช้น้อยสุด · `--simulate-crash <คนแรก>` (kill ทันทีหลัง dispatch ครั้งแรก) |
| หัวหน้าคนที่สอง | `--lead-token-budget <คนที่สอง>=1` |
| ลูกทีมที่หมดงบ | บัญชีพร้อมตัวสุดท้าย `--worker-token-budget <บัญชี>=1` |
| คิว | `--per-account 1` (งานจึงรอคิวและย้ายได้) · ความยากงานลูกทีม 1 |

ต้องมีบัญชีพร้อมอย่างน้อย 3 บัญชีจึงเกิดครบทั้ง 3 เหตุการณ์ (หัวหน้า 2 คนที่ถูกสลับ + ผู้ปิดงาน) · เวลาโดยประมาณ 2–4 นาทีกับ `--lead-model haiku`
