# KC-QUEST (สูตรย่อ) — `scripts/kcquest.py`

ดึงจาก `tools/orch.py` เฉพาะ rank · capacity · คะแนน · เลือก + จอง (สูตรและน้ำหนักเหมือนเดิม) แล้วขยายให้บล็อกหนึ่งใช้หลายบัญชีได้

## ① rank + สายวิกฤต

```
c_j     = ขนาดของบล็อก j (S 0.6 · M 1.5 · L 3 ล้านโทเคน)
rank(j) = c_j + max_{k ∈ succ(j)} rank(k)        succ(j) = บล็อกที่รอ j · ไม่มีใครรอ = c_j
สายวิกฤต = เริ่มจากบล็อกต้นทางที่ rank มากสุด แล้วเดินไปยังบล็อกที่รอซึ่ง rank มากสุด จนสุดทาง
crit_j  = rank(j) ÷ max rank   (0..1 ใช้ในตัวแปร V)
```

## ② โควตา → headroom → capacity

| แหล่ง | ค่า |
|---|---|
| `team.py check --json` (base skill agent-team) | ใช้เฉพาะบัญชี `status = ready` |
| `team.py quota --json` | `session_pct` / `week_pct` + เวลารีเซ็ต (`session_resets` `week_resets`) · `week_other` = เพดานเฉพาะรุ่น (นับเป็นเพดานสัปดาห์อีกตัว) · Codex: `primary/secondary` (หน้าต่าง < 7 วัน = session) · รอบที่รีเซ็ตไปแล้ว = 0% |
| `--accounts a:N` | สมมติเหลือ N% ในหน้าต่าง 5 ชม. (week 0%) · ถ้าทุกบัญชีมี `:N` จะไม่เรียก `team.py` เลย (วางแผนได้โดยไม่มีบัญชีล็อกอิน) |

```
headroom_s = 100 − ใช้ไป 5 ชม. · headroom_w = 100 − max(ใช้ไปสัปดาห์, ใช้ไปสัปดาห์ของรุ่น)
slot       = 0 ถ้า headroom ≤ 2 · ไม่งั้น max(1, min(3, headroom // 8))      (3 = เพดานต่อบัญชีของ agent-team)
r_s, r_w   = % ต่อ 1M โทเคน ตามแพลน (max 1.0/0.12 · team 2.0/0.25 · pro 1.0/0.15 · อื่น 2.0/0.25)
margin     = max(2, r · speed_mtok_h · 0.25 ชม. · (งานบนบัญชี+1))
capacity   = min( (h_s − m_s)/(σ·r_s) [+ โควตา 5 ชม. ใหม่ถ้ารีเซ็ตก่อนงานเสร็จ], (h_w − m_w)/(σ·r_w) )    σ = 1.3
ปิดงานได้   ⇔ c ≤ capacity และ งานบนบัญชี < slot
```

## ③ คะแนน = Σ w · factor  (×100)

| ตัวแปร | สูตร | w |
|---|---|---|
| U ความเร่งด่วนวันหมดอายุ | 24 / (24 + ชั่วโมงก่อนรีเซ็ตสัปดาห์) | 0.40 |
| F best-fit | min(1, q_w / h_w) — งานพอดีถัง เก็บถังใหญ่ให้งานใหญ่ | 0.20 |
| R ที่ว่างหน้าต่าง 5 ชม. | max(0, h_s − q_s) / 100 | 0.15 |
| V ความเร็ว × วิกฤต | speed(yolo 1.0 · cyolo 0.7) × crit_j | 0.15 |
| L โหลด | งานบนบัญชี / slot | −0.10 |

q_s = σ·r_s·c, q_w = σ·r_w·c (โควตาที่งานจะใช้)

## ④ เลือก + จอง (จำลองตามเวลา)

ทุกครั้งที่มีบล็อกพร้อม (dependency เสร็จ): เรียง **MRV** (บล็อกที่มีบัญชีรับได้น้อยสุดก่อน) → rank มากก่อน → ขนาด → แต่ละบล็อกเลือกบัญชีให้ทุกบทบาท **ทีละบทบาท** คะแนนสูงสุดแล้ว `reserve_on` (ลด h_s, h_w และใช้ slot) ทันที ถ้าบทบาทใดไม่มีใครรับ → คืนการจองทั้งบล็อกแล้วรอรอบถัดไป · บล็อก `exclusive` รันเมื่อไม่มีบล็อกอื่นรันอยู่และไม่เริ่มอะไรระหว่างนั้น · รวม agent พร้อมกันไม่เกิน `--max-agents`

| skill | บทบาท (c = ขนาดบล็อก) | บังคับฝั่ง |
|---|---|---|
| yolo | ผู้ทำ c | Claude |
| cyolo · image | ผู้ทำ c | Codex |
| review | ผู้ทำ c → ผู้ตรวจ 0.3c | ผู้ทำ: `worker` หรือคะแนนสูงสุด · ผู้ตรวจ: **คนละ CLI** |
| debate | ผู้ตอบ c (Claude) + ผู้ตอบ c (Codex) → ผู้ตัดสิน 0.3c | ผู้ตัดสินคนละบัญชี |
| best_of | ผู้ตอบ c × n → ผู้ตัดสิน 0.3c | ทุกบทบาทคนละบัญชี |

เวลา (ชม.) = max(c / speed ของผู้ทำ/ผู้ตอบ) + Σ(0.3c / speed ของผู้ตรวจ/ผู้ตัดสิน) · speed = yolo 7.2 · cyolo 4.8 M tok/ชม. · **× k ของสกิล** จาก `/workspace/plans/calib.json` (⑥ เรียนรู้) · ทุกบทบาทถือ slot ตลอดช่วงของบล็อก → Gantt แผนไม่มีช่วงที่บัญชีใดเกิน slot
