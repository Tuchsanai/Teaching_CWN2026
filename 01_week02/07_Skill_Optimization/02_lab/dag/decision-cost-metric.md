คำตอบ: # ตัวชี้วัดต้นทุนที่เลือกล่วงหน้า
เลือก **context_tokens**: โทเคนขาเข้าทั้งหมดต่อรอบ รวมโทเคนที่อ่านจาก cache โดยตรึงวิธีนับก่อนวัด
เหตุผล 1: งาน Playwright ต้องอ่านโค้ด หน้าเว็บ และผลทดสอบซ้ำ ตัวชี้วัดนี้สะท้อนปริมาณข้อมูลที่สกิลให้โมเดลอ่านเพื่อหา แก้ และพิสูจน์บั๊ก
เหตุผล 2: เปรียบเทียบได้โดยไม่ขึ้นกับราคาตามรายการหรือส่วนลด cache และไม่ให้ประโยชน์เพียงเพราะรวมหลายคำสั่งเป็น tool call เดียว
จุดอ่อน: ไม่รวมโทเคนขาออก เวลารันเครื่องมือ และเวลารอ build/ทดสอบ จึงอาจลดลงแม้ต้นทุนเงินจริงหรือเวลารวมเพิ่มขึ้น
เกณฑ์เมื่อคะแนนเท่ากัน: ค่าเฉลี่ย context_tokens ต่อรอบของรุ่นใหม่ต้อง ≤ 90% ของรุ่นเดิม โดยใช้ชุดโจทย์ โมเดล และเงื่อนไขการรันเดียวกัน
