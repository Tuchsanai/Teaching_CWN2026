# ANSWER · hw06-churn-ml-pipeline

**โจทย์:** pipeline ทำนายลูกค้าเลิกใช้บริการ ตั้งแต่เตรียมข้อมูล เทรนโมเดล เก็บผลการทดลอง เปิดเป็น API และหน้า dashboard ติดตามผล

1. **สายวิกฤต:** B02 → B04 → B05 → B06 → B10 ยาว 9.6 ล้านโทเคน (0.6 + 1.5 + 3 + 1.5 + 3) · คิดย้อนจากบล็อกสุดท้าย: rank(B10) = 3 (ไม่มีใครรอ) · rank(B06) 1.5 + max(B10 3) = 4.5 · rank(B05) 3 + max(B06 4.5, B09 3.6) = 7.5 · rank(B04) 1.5 + max(B05 7.5, B07 4.5) = 9 · rank(B02) 0.6 + max(B04 9) = 9.6
2. **สกิลหลายบัญชีและสกิลภาพ:**
   - **B03** `debate` เพราะตัวชี้วัดที่ผิดกับข้อมูลไม่สมดุลทำให้เลือกโมเดลผิด
   - **B05** `review` ความยาก 4 เพราะข้อมูลรั่วและการเทียบโมเดลผิดวิธีตรวจเองยาก
   - **B09** `best_of` เพราะเป็นงานเขียนสื่อสาร อยากได้ฉบับที่อ่านง่ายที่สุด
   - ไม่ใช้ `image` เพราะกราฟสร้างจากโค้ด
3. **ลูกศรที่ตัดไม่ได้:** B04 → B05: การเทรนต้องใช้ชุด train/test จากขั้นเตรียมข้อมูล · **คู่ที่ตั้งใจไม่ใส่ลูกศร:** B08 กับ B05: dashboard ยึดตัวชี้วัดจาก eval-decision.md จึงไม่ต้องรอผลเทรน
4. เหลือ agent สูงสุด 2: วางแผนได้แค่ **4/10 บล็อก** B03 ไม่มีบัญชีรับ เพราะ debate ต้องใช้ 3 บัญชีพร้อมกัน เกินเพดาน 2 และ B05, B06, B08, B09, B10 ที่รออยู่จึงถูกบล็อกตาม · ตัวเลขเวลารวม 32.5 นาที (เทียบกับ 100.0 นาทีที่ agent 4) จึงใช้เทียบไม่ได้ ต้องเปลี่ยนสกิลของบล็อกนั้นหรือใช้ agent อย่างน้อย 3
