# 01-stories.md — User Stories ระบบจองห้องประชุม

**ขั้นตอน:** สร้าง User Stories จากกฎธุรกิจ B01–B06
**บริบท:** ห้อง `<ROOM_A>`, `<ROOM_B>` เปิดจอง 09:00–17:00 เฉพาะวันทำการ; วันตัวอย่างในเกณฑ์ทดสอบคือ `<BOOKING_DATE>`
**บทบาท:** `<REQUESTER_A>` (ผู้ขอจอง), `<RECEPTION_A>` (ต้อนรับ), `<ADMIN_A>` (ผู้ดูแลระบบ)
**นอกขอบเขต:** ไม่มีการจ่ายเงิน ไม่มีอีเมล ไม่มีขั้นตอนอนุมัติ
**ช่องทาง:** CLI เดียว (โหมด `SIMULATION`)

## ตาราง User Stories

| ID | บทบาท | ฉันต้องการ…เพื่อ… | Source B | Acceptance criteria |
|---|---|---|---|---|
| US-01 | `<REQUESTER_A>` | ฉันต้องการดูรายการห้องและช่วงเวลาว่างของแต่ละห้องตามวันที่ระบุ เพื่อเลือกห้องและช่วงเวลาที่จองได้ก่อนทำรายการ | B01 | AC-01.1 ระบุวัน `<BOOKING_DATE>` แล้วระบบแสดง `<ROOM_A>` และ `<ROOM_B>` พร้อมช่วงว่างภายใน 09:00–17:00<br>AC-01.2 ถ้า `<ROOM_A>` มีรายการ 09:00–10:00 อยู่แล้ว ช่วงว่างที่แสดงของ `<ROOM_A>` ต้องไม่รวม 09:00–10:00 (เช่น แสดง 10:00–17:00)<br>AC-01.3 ห้องที่ไม่มีรายการเลยแสดงช่วงว่าง 09:00–17:00 เต็มวัน<br>AC-01.4 ระบุวันที่ไม่ใช่วันทำการ ระบบแจ้งว่าไม่เปิดให้บริการ ไม่แสดงช่วงว่าง |
| US-02 | `<REQUESTER_A>` | ฉันต้องการจองห้องที่เปิดรับจอง โดยระบุห้อง วัน เวลาเริ่ม และเวลาจบ เพื่อให้ได้ห้องในช่วงเวลาที่ต้องการโดยไม่ทับกับรายการของคนอื่น | B02, B03 | AC-02.1 จอง `<ROOM_A>` วัน `<BOOKING_DATE>` 09:00–10:00 ขณะห้องว่างและเปิดรับจอง → สำเร็จ ได้รหัสรายการ<br>AC-02.2 เวลาเริ่มต้องน้อยกว่าเวลาจบ; ขอ 10:00–10:00 หรือ 11:00–10:00 → ปฏิเสธ<br>AC-02.3 ช่วงเวลาต้องอยู่ใน 09:00–17:00; ขอ 08:30–09:30 หรือ 16:30–17:30 → ปฏิเสธ<br>AC-02.4 (กันทับ) มีรายการเดิม `<ROOM_A>` 09:00–10:00; ขอ `<ROOM_A>` วันเดียวกัน 09:30–10:30 → ปฏิเสธ<br>AC-02.5 (ติดกันได้) มีรายการเดิม `<ROOM_A>` 09:00–10:00; ขอ `<ROOM_A>` วันเดียวกัน 10:00–11:00 → อนุญาต<br>AC-02.6 (คนละห้อง) มีรายการเดิม `<ROOM_A>` 09:00–10:00; ขอ `<ROOM_B>` วันเดียวกัน 09:00–10:00 → อนุญาต<br>AC-02.7 (กดพร้อมกัน) ผู้ขอสองคนส่งคำขอ `<ROOM_A>` วันเดียวกันช่วงทับกันพร้อมกัน → สำเร็จเพียงหนึ่งรายการ อีกรายการถูกปฏิเสธ<br>AC-02.8 ขอจองห้องที่ `<ADMIN_A>` ปิดรับจองอยู่ → ปฏิเสธ |
| US-03 | `<REQUESTER_A>` | ฉันต้องการยกเลิกรายการจองของตนเองก่อนเวลาเริ่ม เพื่อคืนช่วงเวลานั้นให้คนอื่นใช้ได้ | B04 | AC-03.1 (เจ้าของ ยังไม่เริ่ม) `<REQUESTER_A>` ยกเลิกรายการของตนที่ยังไม่ถึงเวลาเริ่ม → สำเร็จ สถานะเป็น "ยกเลิก"<br>AC-03.2 (ว่างหลังยก) หลังยกเลิก 09:00–10:00 ของ `<ROOM_A>` แล้ว ผู้ขอคนอื่นจอง `<ROOM_A>` 09:00–10:00 วันเดียวกัน → อนุญาต<br>AC-03.3 (คนอื่น) ผู้ใช้ที่ไม่ใช่เจ้าของรายการสั่งยกเลิก → ปฏิเสธ รายการคงเดิม<br>AC-03.4 (ถึง/เลยเวลาเริ่ม) เจ้าของสั่งยกเลิกเมื่อเวลาปัจจุบันถึงหรือเลยเวลาเริ่มแล้ว → ปฏิเสธ<br>AC-03.5 ยกเลิกรายการที่ถูกยกเลิกไปแล้วหรือไม่มีอยู่ → ปฏิเสธพร้อมข้อความแจ้ง |
| US-04 | `<RECEPTION_A>` | ฉันต้องการดูรายการจองรายวันของทุกห้อง เพื่อเตรียมห้องและตอบคำถามผู้มาติดต่อได้ | B05 | AC-04.1 ระบุวัน `<BOOKING_DATE>` แล้วระบบแสดงรายการจองของ `<ROOM_A>` และ `<ROOM_B>` ทั้งหมดในวันนั้น เรียงตามเวลาเริ่ม แสดงห้อง ช่วงเวลา และผู้จอง<br>AC-04.2 รายการที่ถูกยกเลิกแล้วไม่แสดงเป็นรายการใช้งาน (หรือแสดงพร้อมสถานะ "ยกเลิก" อย่างชัดเจน)<br>AC-04.3 วันที่ไม่มีรายการเลย ระบบแสดงว่า "ไม่มีรายการจอง"<br>AC-04.4 `<RECEPTION_A>` สั่งแก้ไขหรือยกเลิกรายการแทนผู้จอง → ปฏิเสธ รายการคงเดิม |
| US-05 | `<ADMIN_A>` | ฉันต้องการเปิดหรือปิดการรับจองใหม่ของแต่ละห้อง เพื่อควบคุมการใช้งานห้องโดยไม่กระทบรายการที่จองไว้แล้ว | B06 | AC-05.1 `<ADMIN_A>` สั่งปิดรับจอง `<ROOM_A>` → สถานะห้องเป็น "ปิดรับจอง"; คำขอจองใหม่ของ `<ROOM_A>` ถูกปฏิเสธ<br>AC-05.2 (คงรายการเดิม) ก่อนปิดมีรายการ `<ROOM_A>` `<BOOKING_DATE>` 09:00–10:00; หลังปิด รายการนี้ยังอยู่และยังแสดงในรายวันของ `<RECEPTION_A>`<br>AC-05.3 `<ADMIN_A>` สั่งเปิดรับจอง `<ROOM_A>` อีกครั้ง → คำขอจองใหม่ของ `<ROOM_A>` ทำได้ตามปกติ<br>AC-05.4 ปิด `<ROOM_A>` ไม่กระทบ `<ROOM_B>`; จอง `<ROOM_B>` ยังทำได้<br>AC-05.5 ผู้ใช้บทบาทอื่น (`<REQUESTER_A>`, `<RECEPTION_A>`) สั่งเปิด/ปิดรับจอง → ปฏิเสธ |

## คำถามค้าง (ไม่ขยายขอบเขต)

1. วันหยุด: นอกจากเสาร์–อาทิตย์ ระบบต้องรู้จักวันหยุดนักขัตฤกษ์หรือไม่ และใครเป็นผู้กำหนด
2. ระยะจองล่วงหน้า: จำกัดจำนวนวันล่วงหน้าที่จองได้หรือไม่ และจองย้อนหลัง/ในวันเดียวกันได้หรือไม่
3. NFR: เกณฑ์เวลาตอบสนองและการรับมือคำขอพร้อมกันในโหมด `SIMULATION` ต้องวัดอย่างไร
