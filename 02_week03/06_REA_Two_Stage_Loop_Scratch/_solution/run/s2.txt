Two-stage loop · ขั้นที่ 2 (loop พิกเซล): จูนเฉพาะค่าใน tokens.css โดยโครงสร้างล็อกไว้
เริ่มจาก /workspace/arena6/app (tag structure-lock) คัดลอกทั้งโฟลเดอร์ (รวม git) ไปเป็น /workspace/arena6/app-s2 รันที่พอร์ต 5096 (แอปขั้นที่ 1 ที่ 5095 เปิดไว้เหมือนเดิม)
วัดยืนยันก่อนว่า kit/measure.sh ได้โครงสร้าง% เท่าตอนล็อก และ loop/aria-lock.mjs ได้ hash ตรง structure.lock
ถ้าขั้นที่ 1 ใช้งบครบแล้ว gate ยังไม่ผ่าน ให้ทำขั้นนี้ต่อได้ (ห้ามแก้โครงสร้างหรือพฤติกรรมเพิ่ม) โดย gate ของขั้นนี้คือ "ห้ามต่ำกว่าตอนล็อก"

ขอบเขต: แก้ได้แค่ "ค่า" ของตัวแปรใน src/styles/tokens.css · ทุก commit ต้องผ่าน loop/scope-check.sh stage2 structure-lock

สร้างเครื่องมือเองใน /workspace/arena6/loop/pixel/:
1. ตัววัดเร็ว: เปิดหน้าผลค้นหาครั้งเดียวแบบเดียวกับ rulers/visual (1366×900 · pixelmatch 0.1 · includeAA false · reference.png) แล้วลองชุดค่าใหม่ด้วยการแทน tokens ใน :root ทันที ตรวจก่อนว่าค่าตอนเริ่มได้จำนวนพิกเซลตรงกับ kit
2. ตัวกัน (ตรวจทุกชุดค่าก่อนเก็บ ไม่ผ่านทิ้งทันที):
   a. ตัวล็อกโครงสร้าง: SHA-256 ของ ariaSnapshot() ตรงกับ structure.lock
   b. ตัวกันอ่านไม่ออก: ตัวอักษร ≥ 12 px · contrast ≥ 4.5:1 (รวม ::before/::after) · opacity ข้อความ = 1 · element ≥ 75% ของ size-baseline.json · ห้ามตัดบรรทัดกลางคำ (Intl.Segmenter('th'))
   c. ตัวกันช่องโหว่ของตัววัด (บทเรียนจากรอบทดลองก่อน ที่ optimizer ลด visual diff ด้วยการทำหน้าให้แย่ลง):
      - แถวเที่ยวบินแถวแรกต้องอยู่ในจอแรก (ขอบล่าง ≤ 900 px) และห่างจากตำแหน่งใน visual-baseline.json ไม่เกิน 150 px
      - สีของตัวแปรข้อความ (--color-text*) ต้องเป็นสีกลาง ๆ (saturation ≤ 20%) และ contrast ≥ 7:1 สำหรับข้อความหลัก
      - ข้อความในช่องกรอกทุกช่องต้องไม่ล้นหรือถูกตัด (scrollWidth ≤ clientWidth)
3. แบ่งภาพ diff สีแดงเป็นบริเวณ (แถบ 75 px + กลุ่มพิกเซลที่ติดกัน) → จับคู่ element → ตัวแปรที่คุม element นั้น → เรียงตามพิกเซลแดง

Loop พิกเซล ไม่เกิน 2 รอบ (รอบ = ค้น → เขียนค่าลง tokens.css → build → kit/measure.sh เต็ม → เก็บ/ย้อนกลับ):
- รอบ P1 · ตัวแปรรวม: ฟอนต์ (เฉพาะที่มีในเครื่องและสัญญาอนุญาตเปิด) · ขนาดพื้นฐาน · น้ำหนัก · ความสูงแถว · สเกลระยะห่าง · สีหลัก
- รอบ P2 · ตัวแปรรายส่วน: เรียงตามบริเวณที่แดงมากสุดหลัง P1
- coordinate descent: ลอง x ± step ไปทางที่ visual diff ลด ถ้าไม่ดีขึ้นทั้งสองทาง step ลดครึ่ง แล้วไปตัวแปรถัดไป · บันทึกจำนวนชุดที่ลองและที่ตัวกันทิ้ง แยกตามตัวกัน
- เก็บรอบนั้นถ้า gate ไม่ต่ำกว่าตอนล็อก · hash ตรง · ตัวกันผ่านทุกข้อ · Score ดีขึ้น ไม่งั้นย้อนกลับ · 1 รอบ = 1 commit + tag p1 / p2
- ถ้าแอปตอนเริ่มไม่ผ่านตัวกัน ให้ปรับค่าให้ผ่านก่อนเป็นรอบ P0 (ไม่นับในงบ)
