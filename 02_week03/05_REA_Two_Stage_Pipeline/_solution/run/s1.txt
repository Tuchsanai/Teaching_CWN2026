Two-stage pipeline · ขั้นที่ 1: ล็อกโครงสร้าง
เริ่มจากแอป v4 ใน /workspace/arena/base-v4 (ผลวัด v4 อยู่ที่ /workspace/arena/out/v4/report.json) คัดลอกไปเป็น /workspace/arena/pipe1 ให้รันที่พอร์ต 5091 (เปลี่ยนพอร์ตทั้งฝั่ง host และในแอป) แล้ว git init + commit แรกเป็น baseline

อัลกอริทึม "structure compiler":
1. อ่าน token โครงสร้างที่ "ขาด" และ "เกิน" จาก report.json ของ measure.sh แล้วเทียบ original.yml กับ snapshot ของเรา (บทบาท + ชื่อ + ตำแหน่งในต้นไม้)
2. สร้าง "รายการแก้" (edit script) เรียงตามผลต่อคะแนนโครงสร้าง: เปลี่ยนชื่อ · เพิ่ม · ลบ โดยกรองข้อที่ชนกับชื่อที่ test ใช้หาออก
3. ทำตามรายการทีละกลุ่มเป็นส่วนประกอบจริงที่ผู้ใช้เห็นและใช้ได้ (หัวข้อ ส่วน search region ปุ่ม สวิตช์ ที่ต้นฉบับมี) วางให้ตรงตำแหน่งในภาพอ้างอิงเพื่อไม่ให้ visual diff แย่ลงมาก
4. หลังแต่ละกลุ่ม วัดด้วย measure.sh เก็บถ้า Score ดีขึ้นและ gate ผ่าน ไม่งั้นย้อนกลับ
เป้าหมาย: โครงสร้าง% สูงที่สุด (ขั้นที่ 2 จะลด visual diff ต่อ)

กติกา (ห้ามละเมิด)
- วัดด้วย /workspace/arena/kit/measure.sh http://localhost:5091 <โฟลเดอร์ผล> เท่านั้น ห้ามแก้ไฟล์ใน kit/ และห้ามแก้เกณฑ์ของ test
- คะแนนรวม Score = โครงสร้าง% − visual diff% · gate ต้องผ่านทุกรอบ: acceptance ≥ 74/82 · differential 8/8 · เที่ยวบิน 300 · ตัดสินว่าจะเก็บหรือย้อนกลับด้วย Score รวม (ยอมให้ไม้บรรทัดหนึ่งแย่ลงเล็กน้อยได้ ถ้า Score รวมดีขึ้นและ gate ผ่าน)
- ใช้ git ทุกขั้น 1 รอบ = 1 commit เพื่อย้อนกลับได้
- ห้ามโกง: ห้ามเขียนโค้ดที่ตรวจว่ากำลังโดนทดสอบ ห้ามซ่อนเนื้อหาไว้ให้เฉพาะเครื่องอ่าน ห้ามคัดลอกโลโก้/แบรนด์/โค้ด/ฟอนต์ลิขสิทธิ์ของ Google ห้ามฝังภาพหน้าจอของต้นฉบับ ทุกอย่างต้องเป็นของจริงที่ผู้ใช้เห็นและใช้ได้ และชื่อที่ตั้งต้องตรงกับข้อความที่ผู้ใช้เห็นบนจอ
- ชื่อที่ชุดทดสอบใช้หา ห้ามเปลี่ยน: ลิงก์แถวเที่ยวบินต้องขึ้นต้นด้วย "เที่ยวบิน" · ปุ่ม "ค้นหาเที่ยวบิน" · ตัวเรียงต้องมีคำว่า "เปลี่ยนลำดับการจัดเรียง"
- ข้อมูลอ้างอิง: /workspace/arena/docs · kit/src/structure/original.yml · kit/src/visual/reference.png · ผลวัด v4 ที่ /workspace/arena/out/v4/report.json
- ใช้เวลาไม่เกิน 45 นาที
