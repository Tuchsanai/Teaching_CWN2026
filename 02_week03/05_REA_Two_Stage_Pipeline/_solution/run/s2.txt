Two-stage pipeline · ขั้นที่ 2: ปรับพิกเซลบนเลย์เอาต์ใหม่ โดยล็อกโครงสร้างไว้
เริ่มจากผลของขั้นที่ 1 ใน /workspace/arena/pipe1 คัดลอกทั้งโฟลเดอร์ (รวม git) ไปเป็น /workspace/arena/pipe2 ให้รันที่พอร์ต 5092 แล้ววัดยืนยันว่าได้โครงสร้างเท่ากับขั้นที่ 1

อัลกอริทึม "constrained pixel optimizer":
1. ตัววัดเร็ว: เขียนสคริปต์ที่ทำขั้นตอนเดียวกับ visual diff ของ kit (เปิดหน้าผลค้นหาแบบเดียวกัน 1366×900 pixelmatch threshold 0.1 includeAA false) แต่เปิดหน้าครั้งเดียวแล้วลองค่าใหม่ด้วยการใส่ CSS ทันที ตรวจว่าได้ค่าตรงกับ kit
2. แบ่งภาพ diff สีแดงเป็นบริเวณ (แถบ 75 px + กลุ่มพิกเซลที่ติดกัน) → จับคู่กับ element ด้วยกล่องตำแหน่ง → เรียงตามจำนวนพิกเซลแดง
3. แปลงสไตล์ของ element เหล่านั้นเป็นตัวแปร (ฟอนต์ที่มีในเครื่องและสัญญาอนุญาตเปิด · ขนาดตัวอักษร · น้ำหนัก · ระยะห่าง · ความสูงแถว · ความกว้าง · สี) แล้วค้นหาแบบ coordinate descent: ลองค่า ±step ไปทางที่ visual diff ลดลง ถ้าไม่ดีขึ้นให้ลด step ครึ่งหนึ่ง แล้วไปตัวแปรถัดไป
4. ข้อจำกัดแบบแข็ง ตรวจทุกค่าก่อนเก็บ ถ้าไม่ผ่านให้ทิ้งทันที:
   a. ตัวล็อกโครงสร้าง: ariaSnapshot() ของหน้าต้องเหมือนตอนเริ่มขั้นที่ 2 ทุกตัวอักษร
   b. ตัวกันอ่านไม่ออก: ตัวอักษร ≥ 12 px · contrast ข้อความกับพื้น ≥ 4.5:1 (รวมตัวอักษรใน ::before/::after) · opacity ของข้อความ = 1 · element ต้องกว้างและสูง ≥ 75% ของขนาดใน v4 (วัดจาก v4 ที่พอร์ต 5084) · ห้ามตัดบรรทัดกลางคำ (ตรวจด้วย Intl.Segmenter('th'))
   ถ้าแอปตอนเริ่มไม่ผ่านตัวกันอ่านไม่ออก ให้ซ่อมให้ผ่านก่อนเริ่มค้น
5. เมื่อได้ชุดค่าที่ดีขึ้นชัดเจน เขียนลง CSS ของแอป build ใหม่ แล้วรัน measure.sh เต็ม เก็บถ้า Score ดีขึ้นและ gate ผ่าน ไม่งั้นย้อนกลับ
เป้าหมาย: visual diff% ต่ำที่สุด โดยโครงสร้างไม่ตกและแอปยังอ่านง่าย
