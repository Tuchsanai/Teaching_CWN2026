## ข้อจำกัดของคะแนน: ฐานมีข้อที่ล้มอยู่แล้ว

ก่อนใส่บั๊ก acceptance ล้ม 8/82 ข้อ: B20, B22, C13, C31, F05, F08, F14, F16; differential ล้ม 4/8 สถานการณ์: S1, S3, S4, S7

ดังนั้นคะแนนดิบที่สูงไม่ได้ยืนยันว่าชุดทดสอบแยก mutant ออกจากฐานได้ทุกตัว ข้อ F08/F14/F16 ของ acceptance ระบุว่ายืนยันผ่าน UI ไม่ได้ตั้งแต่ต้น ส่วน differential ฐานมีความต่างเรื่องชื่อสายการบิน การตัดสินจาก exit code เพียงอย่างเดียวจึงปะปนปัญหาเดิม

ตารางต่อไปแยกเฉพาะ **ข้อที่ผ่านบนฐาน แต่ล้มบน mutant** เพื่อให้เห็นหลักฐานการตรวจพบเพิ่มเติม วิธีนี้เป็นเกณฑ์อนุรักษนิยม: อาจพลาดบั๊กใหม่ที่เพิ่มความผิดในข้อที่ล้มบนฐานอยู่แล้ว จึงไม่ควรนำไปตีความว่า mutant ที่ไม่มีข้อใหม่หลุดรอดแน่นอน

ตัวอย่าง: M02 ทำให้ differential S4 รายงาน 300 แทน 18 ใบ และ M04 ทำให้ S3 เหลือ 299 แทน 300 ใบ แม้ S4/S3 จะล้มบนฐานอยู่แล้วด้วยเรื่องชื่อสายการบิน ส่วน M05 เปลี่ยนเงื่อนไขตรงค่าขอบราคา แต่ไม่มีข้อผ่าน→ล้มใหม่ในทั้งสองชุด จึงยังไม่มีหลักฐานจากสถานะรายข้อว่าชุดทดสอบตรวจจับบั๊กขอบนี้ได้

## วิธีรันและหลักฐาน

- สำเนาฐาน: `mutants/base/`; การเปลี่ยนแปลงแต่ละตัว: [manifest.json](mutants/manifest.json) (ระบุข้อความก่อน/หลังครบถ้วน)
- Acceptance ใช้สำเนาไฟล์ `.cjs` จาก `/workspace/rea-flight-v3/accept` ทุกไบต์ รัน `BASE_URL=http://localhost:5090 ACCEPT_WORKERS=6 node mutants/runs/<id>/accept/run.cjs` จำนวน 82 ข้อ
- Differential ใช้สำเนา `.mjs` และ `lib/` จาก `diff/` ทุกไบต์ รัน `node --require ./mutants/endpoint.cjs ./mutants/runs/<id>/diff/run.mjs v3` จำนวน 8 สถานการณ์ พร้อมรันต้นฉบับแช่แข็งใหม่ทุกครั้ง ไม่ใช้ผลเก่าแทนเฉลย
- `endpoint.cjs` เป็น harness ตั้งค่า Playwright context: เปลี่ยน baseURL ที่ differential กำหนดตายตัวจาก `http://localhost:5083` เป็น `http://localhost:5090` เท่านั้น ไม่แก้ scenario/assertion/test และไม่ส่ง request ไปยัง v3 ที่พอร์ตเดิม
- Runner: [run.py](mutants/run.py); คำสั่งทำซ้ำ `python mutants/run.py` (เขียนทับหลักฐานรอบเดิม) ใช้ `docker compose -p mutation-<id> -f mutants/<id>/mutation-compose.yml up -d --build` รอ `/api/health` แล้วรันสองชุด ก่อน `down -v --remove-orphans` ใน `finally`
- [ผลรวม JSON](mutants/outcomes.json); หลักฐานแยกรอบที่ `mutants/runs/base/` และ `mutants/runs/M01/` ถึง `M10/`: `compose.log`, `acceptance.log`, `differential.log`, `cleanup.log`, JSON รายข้อ, screenshot, video และ GIF
- [SHA-256 ของต้นฉบับชุดทดสอบ](mutants/test-hashes.json); ตรวจทั้งต้นฉบับและสำเนาทุกรอบว่าเหมือนเดิม; ผลตรวจใน [verification.json](mutants/verification.json)
- ปิด container และลบ volume ของ Compose project สำหรับฐานและ mutant ทั้งหมดหลังจบ ไม่หยุดแอปเดิมที่พอร์ต 5081–5083
