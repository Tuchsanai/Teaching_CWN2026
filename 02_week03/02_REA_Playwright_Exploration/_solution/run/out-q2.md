ทำครบทั้ง 3 ข้อแล้ว แต่มีเรื่องที่ต้องแจ้งก่อน: งานนี้ **ไม่ได้อ่านอย่างเดียว 100%** เครื่องมือ `capture_browser_scenario` แบบ connect โหลด URL ค้นหาเดิมซ้ำ 1 ครั้ง (`goto_start`) ก่อนเก็บข้อมูล หลังจากนั้นไม่มีการคลิกหรือกรอกอะไรเลย ผลคือข้อมูลใน `flights-full.json` มาจากหน้าที่โหลดใหม่ตอน 23:21 น. แต่เที่ยวบินทั้ง 22 ใบตรงกับหน้าเดิมทุกใบ ทั้งราคา เวลาออก และเวลาถึง ผมระบุเรื่องนี้ไว้ใน `flights-full.json` และใน EXPLORATION.md แล้ว

## เครื่องมือ REA ที่ใช้

| เครื่องมือ | สถานะ | หมายเหตุ |
|---|---|---|
| `list_browser_targets` | ✅ | พบแท็บผลค้นหา 1 แท็บ แต่ URL เป็นแบบ `?q=Flights from Bangkok to Tokyo…` ไม่ใช่ `/search?tfs=` อย่างที่เขียนไว้ในส่วน B |
| `inspect_web_page` | ⚠️ ได้บางส่วน | ได้ accessibility tree แต่ **ไม่ได้ข้อมูลที่ฝังในหน้า** เพราะ policy ของ REA ตัดสคริปต์ที่ไม่มี URL ออกไป 82 ตัว และ DOM เก็บแค่ความยาวของข้อความ ไม่เก็บตัวข้อความ |
| `capture_browser_scenario` (connect, รอ 300ms) | ✅ แต่โหลดหน้าซ้ำ | ได้ DOM เต็มขนาด 3.25 MB ซึ่งมีข้อมูลที่ฝังในหน้า (`ds:0`–`ds:4`) อาจตั้งค่า locale/timezone ของแท็บนั้นค้างไว้ด้วย |
| `capture_web_screenshot` | ✅ | ได้ภาพหน้าจอ ตรวจ sha256 แล้วตรง |
| `export_evidence_bundle` | ✅ | ได้ 4 records |
| `jq` | ❌ ไม่มีในเครื่อง | ใช้ Python แทน |

## สิ่งที่พบเพิ่ม
- **ช่วงราคาปกติ ฿4,950–7,200** ที่ค้างอยู่ในส่วน E มีอยู่ในข้อมูลของหน้าค้นหาจริง ข้อมูลเดียวกันยังมีประวัติราคา 61 จุด
- **ช่วงราคาของตัวกรองไม่ตรงกัน:** ข้อมูล 22 ใบแรกให้ ฿7,635–194,610 แต่ slider ที่เห็นตอนสำรวจคือ ฿10,000–310,000 ซึ่งเห็นหลังโหลดครบ 300 ใบ ผมอนุมานว่าช่วงนี้คำนวณจากชุดผลลัพธ์ที่โหลดอยู่
- **SL 394** ใช้เลขเที่ยวบินเดียวกันทั้งสองขา (DMK→TPE→NRT)
- **NH 878/808/806** ทำการบินจริงโดย Air Japan ตรงกับข้อความ "ดำเนินการโดย Air Japan" ในหน้า
- **ระดับการปล่อยก๊าซ** ในข้อมูลเป็นรหัส 1/2/3 ซึ่งตรงกับข้อความในหน้าครบทั้ง 22 ใบ (ต่ำ / โดยเฉลี่ย / สูง)
- **คำถามเรื่องลำดับในแท็บ "ถูกที่สุด" (ส่วน E) ยังตอบไม่ได้:** ข้อมูลที่ดึงมาเป็นของแท็บ "ดีที่สุด" ในแท็บนี้ ฿11,580 อยู่ในกลุ่มยอดนิยม ส่วน ฿8,802 เป็นใบแรกของกลุ่มอื่นๆ แต่ยังพิสูจน์ไม่ได้ว่าแท็บ "ถูกที่สุด" แบ่งกลุ่มแบบเดียวกัน จึงไม่ได้แก้ส่วน E

ไฟล์หลักฐานทั้งหมดอยู่ใน `evidence/` มีผลดิบจาก REA, DOM, ข้อมูลที่ถอดแล้ว (`embedded-ds.json`), ภาพหน้าจอ, สคริปต์ที่ใช้ถอดข้อมูลและแก้เอกสาร และสำเนา EXPLORATION.md ก่อนแก้ (`EXPLORATION.before-rea.md`)
