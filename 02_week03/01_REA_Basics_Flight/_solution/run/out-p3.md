วิเคราะห์เสร็จแล้ว ผลบันทึกไว้ที่ `evidence/code-analysis.json` ทั้งหมดทำแบบอ่านอย่างเดียว ไม่มีการคลิก พิมพ์ เปลี่ยนหน้า หรือรัน JS บนหน้าเว็บ โค้ดที่ดึงมาถูกอ่านเป็นข้อความเท่านั้น ไม่ได้รัน

## 1. หน้านี้สร้างด้วยอะไร

| ข้อสรุป | สถานะ | หลักฐาน |
|---|---|---|
| เป็นแอปบนแพลตฟอร์ม Boq ของ Google ไฟล์ JS ชื่อ `boq-travel.FlightsFrontendUi_desktop_ms.th` | ยืนยันแล้ว | URL ของ JS จาก www.gstatic.com และค่า `CLOSURE_DEFINES["boq...FORM_FACTOR"]="DESKTOP"` |
| ใช้ framework ภายในของ Google ชื่อ **Wiz** ไม่ใช่ React, Angular หรือ Vue | ยืนยันแล้ว | ใน DOM มี attribute `jscontroller` 943 ตัว, `jsaction` 1,501 ตัว, `jsname` 3,169 ตัว และแท็ก `<c-wiz>` 5 ตัว ส่วนร่องรอยของ React, ng-version และ Vue ไม่พบเลย |
| ใช้ Closure Compiler บีบโค้ดและแบ่งเป็นโมดูล | ยืนยันแล้ว | โค้ดแบ่งโมดูลด้วยรูปแบบ `_.t("id") … _.w()` และมีข้อความลิขสิทธิ์ของ Closure Library |

| ปุ่มและเมนูใช้ Material components รุ่นภายใน (class `VfPpkd-*`) | อนุมาน | ในโค้ดไม่มีชื่อ library ระบุไว้ |

## 2. โมดูลไหนดูแลส่วนไหน

| ส่วนบนหน้า | โมดูล | สถานะ |
|---|---|---|
| แถบเรียงลำดับ | `U5T3Ef` | ยืนยันแล้ว เพราะมีค่าโหมดเรียง `{BEST:1,…}` และป้ายชื่อแต่ละโหมดอยู่ในโมดูลนี้ |
| ช่องต้นทาง/ปลายทาง และปุ่มสลับ | `ZGTFnd` | ยืนยันแล้ว เพราะมี `origin`, `destination`, `setSelections()` และข้อความ "สลับต้นทางกับปลายทางแล้ว" |

| ปุ่ม "ตัวกรองทั้งหมด" และปุ่มตัวกรองย่อย | `ebuxPc` | อนุมาน |
| ตัวกรองจำนวนครั้งที่แวะพัก | `bzUZHf` | อนุมาน |
| รายการเที่ยวบิน (หัวข้อ, คำอธิบายการจัดอันดับ) | `q0xTif`, `xEh8Cb`, `GsNaRb` | อนุมาน |

การจับคู่ส่วนใหญ่อาศัยข้อความภาษาไทยบนหน้า เพราะชื่อในโค้ดถูกบีบจนอ่านไม่ออก และ DOM ที่เก็บมามีแต่ชื่อ attribute ไม่มีค่า จึงยังโยง jscontroller id กับ element บนหน้าแบบหนึ่งต่อหนึ่งไม่ได้

## 3. ข้อมูลเที่ยวบิน 1 ใบ และการเรียงลำดับ

ข้อมูลมาจาก ds:1 (RPC `LqxFAb` = GetShoppingResultsPrefetch) ตำแหน่งของช่องต่าง ๆ ยืนยันโดยเทียบค่ากับที่เห็นบนหน้าจอ เช่น SL, DMK→NRT, 06:20→16:25, 485 นาที = 8 ชม. 5 นาที และ ฿7,635

| ช่อง | ตัวอย่าง | สถานะ |
|---|---|---|
| รหัสและชื่อสายการบิน | SL / ไทยไลอ้อนแอร์ | ยืนยันแล้ว |
| สนามบินต้นทาง/ปลายทาง, วันเวลาออก/ถึง | DMK [2026,11,15] [6,20] → NRT [16,25] | ยืนยันแล้ว |
| ระยะเวลารวม (นาที) | 485 | ยืนยันแล้ว |
| รายการ segment แต่ละขา (เลขเที่ยวบิน, รุ่นเครื่องบิน, ระยะห่างที่นั่ง, เวลา) | SL 394, Boeing 737, 74 ซม. | ยืนยันแล้ว |
| จำนวนแวะพัก | ไม่มีช่องโดยตรง ได้จากจำนวน segment ลบ 1 | ยืนยันแล้ว |
| จุดแวะพัก | เวลารอ 60 นาที, TPE, ไทเป | ยืนยันแล้ว |
| ราคา | 7635 | ยืนยันแล้ว |
| CO2 (กรัม) | 363000 / 371000 | อนุมาน |
| token base64 สำหรับขั้นจองต่อ | `CjRIQ0tf…` | อนุมาน |

## 4. สิ่งที่นำไปใช้สร้างแอปจองตั๋วเล็ก ๆ ได้

| แนวทาง | ที่มา |
|---|---|
| แยกโมเดลเป็น Itinerary (ราคา, token, ระยะเวลารวม, จุดแวะ) กับ Segment (ข้อมูลแต่ละขา) | ยืนยันแล้ว (Google ทำแบบนี้) |
| เก็บเวลาเป็นเวลาท้องถิ่นของสนามบิน และเก็บระยะเวลาเป็นนาทีแยกไว้ ไม่คำนวณจากเวลาออก/ถึงที่ข้าม timezone | ยืนยันแล้ว |
| ให้ API ส่งกลับ 2 กลุ่ม คือ best ไม่กี่ใบ กับ others ที่เรียงตามราคา และใช้ค่าโหมดเรียง 6 แบบ | ยืนยันแล้ว |
| ส่งข้อมูลสำหรับตัวกรอง (ช่วงราคา, สายการบิน) มาพร้อมผลค้นหา จะได้ไม่ต้องเรียก API เพิ่ม | อนุมาน |
| ใช้ token ต่อ itinerary เพื่อไปขั้นจอง และใช้รหัสเมืองแทนชื่อสนามบิน เพื่อรวม BKK+DMK หรือ NRT+HND ได้ | อนุมาน |
| สูตร "ดีที่สุด" ของเราเอง เช่น `price*w1 + duration*w2 + stops*w3` และทำ SSR ด้วย Next.js/Nuxt แทน Wiz | ออกแบบเอง |
| ใช้เป็นแนวคิดเท่านั้น ไม่ควรคัดลอกโค้ดหรือเรียก API ภายในของ Google ข้อมูลเที่ยวบินจริงให้ใช้ API ที่เปิดให้บริการ เช่น Amadeus หรือ Duffel | คำแนะนำ |
