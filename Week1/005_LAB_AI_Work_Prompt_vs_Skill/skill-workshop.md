# สร้างและปรับ Skill ด้วยการสนทนา — 35 นาที

[กลับหน้าหลัก](README.md) · [แนวคิด](theory.md) · [การเตรียมเครื่องและ native discovery](setup.md)

เป้าหมาย: บอก AI ให้สร้างคู่มือที่ใช้ซ้ำได้ ตรวจแปดส่วน และขอแก้ด้วยภาษาธรรมชาติ ผู้เรียน **ไม่เขียนโค้ด ไม่แก้ YAML/frontmatter หรือ config เอง** ผู้สอนเตรียมโฟลเดอร์ฝึกสร้างแยกจากพื้นที่ทดลองและให้สำเนา canonical/lab3.md เป็น instruction.md พร้อม references.md/template.md ของ Lab3

## 1. สร้างไฟล์จริงด้วย Prompt (10 นาที)

เปิด Codex ในโฟลเดอร์ฝึกสร้างที่ผู้สอนเตรียม วางข้อความนี้ในช่องสนทนา:

```text
ช่วยสร้าง Skill ภาษาธรรมชาติชื่อ complaint-triage สำหรับจัดคิวข้อร้องเรียนตามนโยบายในโปรเจกต์ฝึกนี้
อ่าน instruction.md ที่ผู้สอนให้เป็นเนื้อหา canonical ใช้ข้อความนั้นเป็น body ทุกตัวอักษร ไม่ย่อ ไม่ปรับกติกา
สร้างไฟล์ .agents/skills/complaint-triage/SKILL.md ในโปรเจกต์นี้จริง ใส่ YAML name เป็น complaint-triage และ description ภาษาไทยว่าจัดคิวร้องเรียนเทียบออเดอร์กับนโยบายและร่างตอบให้คนตรวจ
ไม่มี scripts และไม่แก้ไฟล์ config หรือโฟลเดอร์บัญชี
ให้ body ครบวัตถุประสงค์ เงื่อนไขใช้ ข้อมูลที่ต้องมี ขั้นตอน ข้อมูลขาด/ข้อยกเว้น รูปแบบผลลัพธ์ เกณฑ์ตรวจรับ และข้อจำกัด/การใช้ซ้ำ ตามต้นฉบับ
อ่านไฟล์ที่เขียนกลับมา ตรวจว่า body ตรง instruction.md และรายงาน path กับสิ่งที่ตรวจจริง ห้ามอ้างว่าทดสอบ native discovery แล้วเพียงเพราะสร้างไฟล์สำเร็จ
```

ผู้สอนตรวจว่าได้ไฟล์จริงตาม [ต้นฉบับ SKILL.md เต็ม](skills/complaint-triage/SKILL.md) เปิดดูเพื่อชี้ตำแหน่งชื่อ คำอธิบาย และแปดส่วน AI เป็นผู้เขียนส่วนหัวให้ ผู้เรียนอ่านและถามแก้คำอธิบายได้ตามภาษาปกติ

สร้างอีกสองชนิดด้วยแนวทางเดียวกันโดยผู้สอนจัด instruction.md ของ Lab นั้นให้ และใช้ชื่อ requirements-check หรือ shop-recovery; ต้นฉบับพร้อมใช้: [วิเคราะห์ความต้องการ](skills/requirements-check/SKILL.md), [กู้ร้าน](skills/shop-recovery/SKILL.md) แต่ละ Skill ไม่มีสคริปต์ helper ร้านเป็นโปรแกรมสำเร็จรูปของ Lab แยกจากตัว Skill

## 2. ตรวจว่าถูกค้นพบจริง (รวมในช่วงสร้าง)

ปิดและเปิด Codex ใหม่ในโปรเจกต์ฝึกเดิม ใช้ `/skills` หรือพิมพ์ `$` แล้วเลือก complaint-triage ตรวจชื่อและเส้นทางที่แสดง บันทึกหลักฐานในใบงาน จากนั้นใช้ `$complaint-triage` กับข้อมูลใหม่ที่ผู้สอนให้ ดู trace ว่าโหลด Skill ตัวนี้ หากไม่เห็นชื่อให้ผู้สอนช่วย ไม่แก้ config เองและไม่สรุปว่าการแนบไฟล์คือ native Skill

ขั้นตอนนี้อ้างอิง [OpenAI Build skills](https://learn.chatgpt.com/docs/build-skills) และหลักฐาน local ใน setup.md; สถานะการทดสอบของผู้เขียนยังแยก pending ใน verification.md ผู้เรียนเติมผลจริงของตนเองได้หลังทำ

## 3. ดูข้อผิดพลาดที่สร้างไว้แล้ว (5 นาที)

หลังรอบเปรียบเทียบหลักของกลุ่มนั้นเสร็จ ผู้สอนเปิด [กรณีสาธิต](instructor/demo/known-flaw.md) และ v1/v2 ไม่ให้ผู้เรียนที่ยังไม่ทำชุด C เห็นเฉลย C ล่วงหน้า หากกำหนดสาธิตก่อน Lab3 ให้ใช้เพียงการชี้ประโยค “7วันเสมอ” และเลื่อนคำตอบ C ไปหลัง transfer

v1 จงใจจำจำนวนวันคงที่ การตอบซ้ำสม่ำเสมอจึงอาจผิดสม่ำเสมอด้วย **นี่คือกรณีบกพร่องและคำตอบสมมติที่ผู้สอนสร้าง ไม่ใช่การกล่าวว่าได้สังเกตความผิดจากการรันจริงแล้ว**

## 4. ขอให้ AI ปรับคู่มือ (10 นาที)

ในโปรเจกต์ demo แยกซึ่งผู้สอนวาง v1 ไว้ วาง Prompt:

```text
ทบทวน .agents/skills/complaint-triage/SKILL.md ในโปรเจกต์ demo นี้
กรณีสาธิตที่ผู้สอนสร้างพบว่าคู่มือฝัง “7 วันเสมอ” ทั้งที่นโยบายใหม่อาจกำหนด5วัน จึงทำให้ใช้ซ้ำผิด
ปรับ Skill ให้ทุกครั้งตรวจผู้อนุมัติ ฉบับ วันมีผล และขอบเขตแทนฉบับเก่า อ่านจำนวนวันและวิธีนับจาก input ปัจจุบัน ไม่จดจำจำนวนวันจากโจทย์เก่า
คงการไม่อนุมัติแทนคนและไม่ส่งข้อความ/คืนเงินจริง ไม่เพิ่มโค้ด สคริปต์ หรือแก้ config
เขียนไฟล์จริงแล้วสรุปข้อความเดิม ข้อความใหม่ และเหตุผล พร้อมเกณฑ์ทดสอบว่าถ้าผ่านมา7วันแต่นโยบายมีผลใหม่กำหนด5วันต้องไม่ถือว่าอยู่ในสิทธิ์ปกติ อย่าอ้างว่าทดสอบแล้วหากยังไม่ได้รัน
```

v2 ตัวอย่างเต็มอยู่ [ไฟล์ v2](instructor/demo/v2/complaint-triage/SKILL.md) ใช้เป็นแนวตรวจ ไม่บังคับว่าข้อความใหม่ของผู้เรียนต้องตรงทุกตัวอักษรนอกการทดลองหลัก

## 5. ใช้กับข้อมูลใหม่และตรวจ (10 นาที)

ใช้ session ใหม่กับชุด C ให้ทั้ง v1 และ v2 ได้ข้อมูล/โมเดล/เวลาเหมือนกัน ถ้าทดลองหลังเห็นเฉลยแล้วให้ติดป้าย exposed demonstration ห้ามปนกับคะแนน reuse ที่ต้องวัดก่อนแก้และก่อนเห็นเฉลย

```text
$complaint-triage อ่าน input.md ชุดใหม่ พร้อม references.md และ template.md ทำงานให้ครบ ตรวจว่าเกณฑ์วันมาจากนโยบายฉบับใดและมีอำนาจใช้หรือไม่ แยกสิ่งที่ยังต้องให้คนตัดสิน ห้ามใช้ผลรอบก่อน
```

บันทึกว่าสร้างกี่นาที ปรับกี่นาที ใช้งานกี่นาที และผลจริงเป็นอย่างไร ตัวอย่าง v2 ไม่ใช่การรับประกันว่าคำตอบจะถูก ต้องตรวจทุกเคสตามเกณฑ์เสมอ การปรับ Skill ใน workshop ไม่เปลี่ยน frozen canonical ของรอบเปรียบเทียบหลัก
