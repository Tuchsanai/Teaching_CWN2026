# Lab 2 · DevOps — ภารกิจ 30 นาที กู้เว็บก่อนเปิดขาย

[กลับหน้าหลัก](../../README.md) · [ใบงาน](worksheet.md) · [คำใบ้](hints.md) · [แบบผลลัพธ์](template.md)

## เป้าหมายและเวลา

เวลา 95 นาทีตามกำหนดการหลัก ไม่รวมเตรียมเครื่อง ผู้เรียนจะอ่านหลักฐาน บอกสิ่งที่ยังไม่รู้ ใช้ AI ตามขั้นตอน ตรวจร่าง และเปรียบเทียบวิธีใช้คำแนะนำซ้ำได้ ทุกคนใช้ Prompt/Skill/คำสั่งสำเร็จรูปเท่านั้น **ไม่มีงานเขียนหรือแก้โค้ด สคริปต์ หรือ config**

สถานการณ์: อีก 30 นาทีร้านเปิดแคมเปญแต่เว็บเข้าไม่ได้ เริ่มจากบริการหยุด แล้วต่อยอดเป็นอัปเดตเสีย แต่ละเหตุการณ์มีสาเหตุหลักเพียงหนึ่งอย่าง คุณเป็นผู้ประสานงานกู้ร้าน ไม่ต้องเขียนโปรแกรม

สิ่งที่ส่ง: อาการ หลักฐาน สาเหตุ คำสั่งและเหตุผล ผล HTTP จริงทั้งสามหน้า และบันทึกเปิดเบราว์เซอร์ พร้อมใบงานและคะแนนร่างแรก/ฉบับแก้ ผู้สอนเก็บร่างแรกก่อนให้คำใบ้

## เตรียมและไฟล์ที่ต้องอ่าน

ผู้สอนเปิดโปรเจกต์แยกของรอบนั้นให้ พร้อม `input.md`, `references.md`, `template.md` และ `instruction.md` (ฝั่ง Prompt) หรือ Skill ที่ค้นพบได้ (ฝั่ง Skill) เปิด session ใหม่ทุกครั้ง ห้ามใช้ resume และห้ามแนบเฉลยหรือร่างจากรอบก่อน

ไฟล์ต้นทางของข้อมูล: บัตรเหตุการณ์ input.md และคู่มือ references.md รหัสบรรทัดอยู่ในไฟล์เพื่อให้อ้างอิงได้ง่าย

| ความยาก | A | B | ใช้เทียบอย่างไร |
|---|---|---|---|
| basic | experiments/inputs/lab2-basic-A.md | experiments/inputs/lab2-basic-B.md | จับคู่ภายใน basic เท่านั้น |
| rollback | experiments/inputs/lab2-rollback-A.md | experiments/inputs/lab2-rollback-B.md | จับคู่ภายใน rollback เท่านั้น |
| transfer | experiments/inputs/lab2-transfer-C.md | — | งานใช้ซ้ำ ไม่ใช่ A/B ที่เทียบคะแนนหลัก |

[คู่มือคำสั่งเต็ม](commands.md) เป็นเอกสารอ้างอิงที่ทั้งสองแบบได้รับเหมือนกัน ผู้สอนรัน reset ตามบัตรก่อนเริ่มจับเวลา ผู้เรียนอย่าเปิดดูต้นฉบับใน instructor/runtime

## ทำทีละขั้น

1. ดูสาธิตคำสั่งและการคัดลอกหลักฐาน 10 นาที ก่อนรอบทดลอง ผู้สอนตั้ง basic-A หรือ basic-B ไว้ให้
2. ภารกิจ basic รอบละ 15 นาที: วางคำสั่งด้านล่างใน Terminal ทีละบรรทัด แล้วคัดลอกผลทั้งหมดลง Prompt ให้ AI วิเคราะห์

```bash
./labctl status
./labctl logs
./labctl verify
```

3. อ่านเหตุผลของ AI เทียบคู่มือ ถ้าหลักฐานรองรับจึงรันคำสั่งซ่อมจากคู่มือ แล้ว `./labctl verify` อีกครั้ง ผล FAIL ก่อนแก้เป็นส่วนหนึ่งของโจทย์ ไม่ต้องติดตั้งอะไร
4. `./labctl open` แล้วเปิด URL ในเบราว์เซอร์ กดลิงก์สินค้าและคำสั่งซื้อจำลอง บันทึกผลตามคู่มือ เก็บหลักฐานก่อน `./labctl stop`
5. ผู้สอนเตรียมพื้นที่ใหม่และ basic อีกชุด เปิด session ใหม่ ทำอีกแบบ 15 นาที ไม่ใช่เอาเว็บที่ซ่อมแล้วไปเทียบ
6. ต่อรอบ rollback สองแบบรอบละ 15 นาที ผู้สอนเตรียม rollback-A/B ก่อนจับเวลา ใช้ขั้นตรวจเดิมแต่ห้ามสรุปว่า start เป็นคำตอบทุกครั้ง
7. ตรวจและอภิปราย 15 นาที ใช้ transfer-C อีก 10 นาที แล้ว stop ทุกครั้งก่อนจบ

หลักฐานหน้าร้านไม่แทนผลสินค้าและคำสั่งซื้อ หากไม่มีเบราว์เซอร์เข้าถึงให้ผู้สอนแก้สภาพแวดล้อมก่อนคาบ ห้ามนับผล HTTP อัตโนมัติเป็นการตรวจหน้าจอของคน

## Prompt พร้อมคัดลอกในช่องสนทนา Codex

**เริ่ม — ฝั่ง Prompt:** ผู้สอนจัด instruction.md ให้มีเนื้อหาเต็มเหมือน body ของ Skill ทุกไบต์ การอ่านไฟล์นี้เป็นการส่ง Prompt แบบไฟล์เพื่อไม่ตกหล่น หากใช้แบบวางข้อความ ให้คัดลอกเนื้อหา instruction.md ทั้งหมดมาต่อก่อนข้อความด้านล่าง ห้ามใช้เพียงตัวอย่างสั้นแทนในการเปรียบเทียบ

```text
อ่าน instruction.md ทั้งหมดเป็นคำสั่งของฉัน แล้วทำงานกับ input.md, references.md และ template.md ตามนั้น ส่งร่างภาษาไทย ใช้เฉพาะไฟล์ที่ให้ ไม่อ่านเฉลยหรือผลรอบอื่น
```

**เริ่ม — ฝั่ง native Skill:** ตรวจพบชื่อก่อน แล้วใช้

```text
$shop-recovery ทำงานกับ input.md, references.md และ template.md ส่งร่างภาษาไทย ใช้เฉพาะไฟล์ที่ให้ ไม่อ่านเฉลยหรือผลรอบอื่น
```

ทั้งสองแบบใช้คำสั่งวิเคราะห์/แก้/ตรวจต่อไปนี้เหมือนกัน การช่วยเหลือทุกครั้งต้องบันทึก ใช้ก่อนผู้สอนเปิดเฉลย

**วิเคราะห์**

```text
นี่คือผล status/logs/verify ที่ฉันเพิ่งคัดลอกมา ช่วยแยกอาการกับสาเหตุ ระบุสิ่งที่ยังไม่รู้ เลือกคำสั่งถัดไปจาก references.md พร้อมเหตุผลและผลที่ควรเห็น รอผลจริงก่อนสรุปว่าซ่อมแล้ว
```

**แก้ไข**

```text
เทียบผลล่าสุดกับคู่มืออีกครั้ง ถ้าคำสั่งก่อนหน้าไม่แก้สาเหตุให้บอกเหตุผล เลือกการแก้ทีละอย่างจากคู่มือ ห้ามแก้ไฟล์หรือใช้ reset ระหว่างกู้ ถ้าเกินคู่มือให้ส่งต่อผู้สอน
```

**ตรวจคำตอบ**

```text
ตรวจหลักฐานหลังแก้: HTTP หน้าร้านมีชื่อถูกหรือไม่ สินค้าและคำสั่งซื้อจำลองผ่านหรือไม่ แยกผลอัตโนมัติกับการเปิดเบราว์เซอร์จริง สิ่งใดยังไม่ทดสอบให้เขียนว่ายังไม่ตรวจ
```

## ตัวอย่างสำหรับอภิปรายหลังส่งร่าง

ตัวอย่างคำตอบที่ไม่ดี **ผู้สอนสร้างขึ้นเพื่อให้จับข้อผิดพลาด ไม่ใช่ผลโมเดลที่สังเกตจริง**: “status ขึ้น RUNNING จึงเปิดขายได้เลย” — ผิดเพราะ v2-bad ยังรันได้แต่ทุกหน้าตอบ 503 และยังไม่มีหลักฐานสินค้า/คำสั่งซื้อ

ตัวอย่างครบทั้งงานและการให้คะแนนอยู่ในเฉลยผู้สอนของ Lab 2 ผู้สอนแสดงหลังทั้งสองรอบเท่านั้น เพื่อไม่ปนเปื้อนการทดลอง ผู้เรียนใช้ template.md ดูรูปแบบก่อนทำได้ทั้งสองแบบ

## โจทย์นำไปใช้ใหม่

เปิด session ใหม่ ใช้ Skill เดิมโดยไม่แก้ body ก่อนรอบแรก พร้อม input.md ชุด C และ references.md/template.md ของ Lab นี้ แล้ววาง:

```text
ใช้คู่มือเดิมกับ input.md ชุด C อ่านกฎและข้อมูลใหม่ทั้งหมด ระบุสิ่งที่เปลี่ยนจากขอบเขตงานเดิมและผลต่อคำตอบ อย่าใช้เฉลยหรือผลรอบก่อน ถ้าคู่มือใช้ไม่ได้ให้บอกส่วนที่ต้องปรับก่อนตัดสินใจ
```

เรียก Skill ด้วยชื่อด้านบนก่อนข้อความนี้ บันทึกผลแรกเป็น reuse ก่อนแก้คู่มือ เวลาปรับคู่มือหลังจากนั้นเป็น maintenance แยก ไม่ย้อนเปลี่ยนคะแนนครั้งแรก
