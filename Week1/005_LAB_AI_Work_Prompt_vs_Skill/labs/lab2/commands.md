# คู่มือคำสั่งร้านจำลอง v1 — ใช้จากรากพื้นที่ Lab

ผู้เรียนคัดลอกคำสั่งเท่านั้น ไม่มีขั้นตอนแก้โปรแกรมหรือไฟล์ตั้งค่า ทุกคำสั่งควบคุมเฉพาะร้านในสำเนานี้ คำว่า API ใน Lab หมายถึง endpoint ทดสอบสำเร็จรูปที่เปิดอ่าน ไม่ต้องต่อระบบจริง

| คำสั่งพร้อมวาง | เมื่อใด | ผลที่เกิด | สิ่งที่ควรเห็น |
|---|---|---|---|
| `./labctl setup` | เตรียมครั้งแรกก่อนจับเวลา | สร้างข้อมูลจำลอง basic-A แบบหยุดอยู่; ซ้ำแล้วเก็บงานเดิม | READY basic-A หรือ SETUP already exists |
| `./labctl open` | ขอ URL ไปเปิดเว็บ | พิมพ์ URL ปัจจุบัน ไม่เปิดเบราว์เซอร์อัตโนมัติ | Open in browser หรือยังไม่มี URL |
| `./labctl status` | เริ่มตรวจและหลังแก้ | ตรวจ process ของ Lab และเวอร์ชัน | STOPPED/RUNNING, release, ชื่อร้าน |
| `./labctl logs` | หาหลักฐานประกอบ | อ่านท้ายบันทึกเหตุการณ์และ HTTP ของ instance นี้ | START/STOP/ROLLBACK หรือรหัส 503 |
| `./labctl start` | หยุดอยู่และ release ดี | เริ่มเวอร์ชันปัจจุบัน ไม่เปลี่ยนเวอร์ชัน | RUNNING v1-good พร้อม URL; ถ้า v2-bad ยังเสีย |
| `./labctl rollback` | รัน v2-bad แล้ว HTTP 503 | หยุดเฉพาะ Lab กลับ v1-good แล้วเริ่ม | RUNNING v1-good พร้อม URL ใหม่; ถ้าเป็น v1-good อยู่จะ NO_CHANGE และไม่ช่วยกรณีหยุด |
| `./labctl verify` | ก่อนและหลังแก้ | ขอ HTTP จริงสามหน้าและตรวจเนื้อหา | PASS สามรายการ + VERIFIED; ถ้ายังเสีย FAIL และ exit 1 |
| `./labctl reset basic-A` | ผู้สอนให้เริ่มรอบ basic A ใหม่ | หยุด Lab นี้และตั้ง v1-good แบบหยุด | READY basic-A |
| `./labctl reset basic-B` | เริ่มรอบเทียบ basic B | สาเหตุเดียวกัน เปลี่ยนชื่อร้าน | READY basic-B |
| `./labctl reset rollback-A` | เริ่มรอบต่อยอด A | เริ่ม v2-bad ที่ตอบ 503 | READY rollback-A |
| `./labctl reset rollback-B` | เริ่มรอบเทียบต่อยอด B | สาเหตุเท่ากับ rollback-A เปลี่ยนชื่อร้าน | READY rollback-B |
| `./labctl reset transfer-C` | โจทย์นำไปใช้ใหม่ | ร้านใหม่ v2-bad | READY transfer-C |
| `./labctl stop` | เก็บหลักฐานเสร็จ/เลิกเรียน | หยุดเฉพาะ process ที่ตรวจว่าเป็นของ Lab นี้ | STOPPED only this lab instance |

`reset` ไม่ใช่วิธีซ่อมระหว่างรอบ: เปลี่ยนโจทย์และทำให้เปรียบเทียบไม่ได้ ไม่มีข้อมูลการขายจริงให้เก็บหรือกู้ ระบบไม่บันทึกคำสั่งซื้อถาวร บันทึกเหตุการณ์เดิมคงอยู่พร้อมเวลาและเส้น RESET ให้แยกแต่ละรอบ ถ้าต้องการรอบทดลองอิสระใช้พื้นที่ใหม่ตามผู้สอน

## เลือกการแก้จากหลักฐาน

- STOPPED และ v1-good พร้อม verify ติดต่อไม่ได้ → start แล้ว verify
- RUNNING และ v2-bad พร้อม HTTP 503 → rollback แล้ว verify
- หลักฐานไม่เข้าแบบใด หรือแก้แล้วยังไม่ผ่าน → ส่ง status, logs, verify ให้ผู้สอน ห้ามเดาคำสั่งติดตั้ง แก้พอร์ต หรือฆ่า process อื่น
- RUNNING ไม่พอ; PASS ต้องรวม root ที่มีชื่อร้านตรง และ `/api/products` มี DEMO-1 ราคา 99 และ `/api/order-smoke` มี DEMO-ORDER จำนวน 2 ยอด 198 และ persisted=false

## เปิดเบราว์เซอร์ตรวจจริง

หลังแก้ รัน `./labctl open` แล้วคัดลอก URL ทั้งบรรทัดหลังคำว่า Open in browser ไปช่องที่อยู่ของเบราว์เซอร์บนเครื่องเดียวกัน อย่าใช้ URL เก่าหลัง rollback เพราะ port อาจเปลี่ยน

1. เห็นหัวเรื่องร้านใบชา A / ร้านดอกไม้ B / ร้านสมุด C ตรงกับบัตรโจทย์ และเวอร์ชัน v1-good
2. กด “1. ดูสินค้าทดสอบ” เห็นข้อความข้อมูลสินค้า DEMO-1 สมุดฝึกงาน ราคา 99 แล้วกดย้อนกลับ
3. กด “2. ตรวจคำสั่งซื้อจำลอง” เห็น DEMO-ORDER, quantity 2, total 198, persisted false เป็นผลทดสอบ ไม่มีการซื้อจริง
4. บันทึกชื่อร้าน URL เวลา และสิ่งที่เห็นในใบงาน หากยังไม่ได้เปิด ให้ทำเครื่องหมาย “ยังไม่ตรวจเบราว์เซอร์” แม้ automated verify ผ่าน
