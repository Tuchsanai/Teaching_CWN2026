## เป้าหมายและเวลา

เวลา 65 นาทีตามกำหนดการหลัก ไม่รวมเตรียมเครื่อง ผู้เรียนจะอ่านหลักฐาน บอกสิ่งที่ยังไม่รู้ ใช้ AI ตามขั้นตอน ตรวจร่าง และเปรียบเทียบวิธีใช้คำแนะนำซ้ำได้ ทุกคนใช้ Prompt/Skill/คำสั่งสำเร็จรูปเท่านั้น **ไม่มีงานเขียนหรือแก้โค้ด สคริปต์ หรือ config**

สถานการณ์: ร้านกำลังทำระบบรับออเดอร์ แต่ฝ่ายขาย คลัง และเอกสารกติกาพูดไม่ตรงกัน เป้าหมายไม่ใช่ตัดสินแทนเจ้าของ แต่ทำให้รู้ว่าข้อตกลงส่วนใดใช้ได้และส่วนใดต้องถาม

สิ่งที่ส่ง: ความต้องการพร้อมหลักฐาน คำถาม กติกาที่ยืนยันได้ และสถานการณ์ตรวจรับที่ไม่เดาผล พร้อมใบงานและคะแนนร่างแรก/ฉบับแก้ ผู้สอนเก็บร่างแรกก่อนให้คำใบ้

## ทำทีละขั้น

1. อ่านตัวอย่างแชตหนึ่งรอบ วงคำว่า “น่าจะ” และดูว่าใครมีอำนาจตัดสิน ใช้เวลา 5 นาที
2. อ่านประชุมและนโยบายครบแล้วใช้ Prompt เริ่มงานด้านล่าง เก็บคำตอบแรกภายใน 15 นาที
3. ตรวจตารางว่าแต่ละแถวเป็นข้อเท็จจริง ข้อขัดแย้ง หรือสิ่งที่ขาด มีรหัสบรรทัดรองรับหรือไม่ อย่าเชื่อว่าข้อความใหม่กว่าเท่ากับคำอนุมัติ
4. ใช้ Prompt วิเคราะห์/แก้/ตรวจตามต้องการ นับจำนวนข้อความขอแก้และคำใบ้ เก็บฉบับแก้แยกจากร่างแรก
5. เปิด session ใหม่ ทำอีกแบบด้วยชุดใหม่ที่จับคู่ไว้ ไม่เอาคำตอบเดิมให้ AI ดู
6. หลังสองรอบ ผู้สอนเปิดเฉลยและตรวจร่วมกัน 15 นาที แล้วใช้ชุด C 10 นาทีเพื่อดูว่าคู่มือรองรับการอนุมัติกติกาใหม่จริงหรือไม่

## Prompt พร้อมคัดลอกในช่องสนทนา Codex

**เริ่ม — ฝั่ง Prompt:** ผู้สอนจัด instruction.md ให้มีเนื้อหาเต็มเหมือน body ของ Skill ทุกไบต์ การอ่านไฟล์นี้เป็นการส่ง Prompt แบบไฟล์เพื่อไม่ตกหล่น หากใช้แบบวางข้อความ ให้คัดลอกเนื้อหา instruction.md ทั้งหมดมาต่อก่อนข้อความด้านล่าง ห้ามใช้เพียงตัวอย่างสั้นแทนในการเปรียบเทียบ

```text
อ่าน instruction.md ทั้งหมดเป็นคำสั่งของฉัน แล้วทำงานกับ input.md, references.md และ template.md ตามนั้น ส่งร่างภาษาไทย ใช้เฉพาะไฟล์ที่ให้ ไม่อ่านเฉลยหรือผลรอบอื่น
```

**เริ่ม — ฝั่ง native Skill:** ตรวจพบชื่อก่อน แล้วใช้

```text
$requirements-check ทำงานกับ input.md, references.md และ template.md ส่งร่างภาษาไทย ใช้เฉพาะไฟล์ที่ให้ ไม่อ่านเฉลยหรือผลรอบอื่น
```

ทั้งสองแบบใช้คำสั่งวิเคราะห์/แก้/ตรวจต่อไปนี้เหมือนกัน การช่วยเหลือทุกครั้งต้องบันทึก ใช้ก่อนผู้สอนเปิดเฉลย

**วิเคราะห์**

```text
อธิบายว่าแถวใดมีหลักฐานชัด แถวใดขัดกัน แถวใดไม่มีข้อมูล ระบุรหัสบรรทัดทั้งสองด้าน อย่าเพิ่งเลือกกติกาแทนเจ้าของร้าน
```

**แก้ไข**

```text
ทบทวนร่างเดิมกับเอกสาร แก้เฉพาะข้อที่ไม่มีหลักฐานหรือปิดประเด็นเร็วไป เพิ่มคำถามที่ใช้ตัดสินใจได้ และคงผลตรวจรับเป็นรอยืนยันเมื่อยังไม่ตกลง
```

**ตรวจคำตอบ**

```text
ตรวจว่าทุกประเด็นมีหลักฐานและสถานการณ์ตรวจรับ เรื่องที่ขัดกันหรือข้อมูลขาดต้องไม่แสดงผลคาดหวังเป็นข้อยุติ รายงานสิ่งที่ผ่าน สิ่งที่ต้องแก้ และส่งฉบับแก้
```

## ตัวอย่างสำหรับอภิปรายหลังส่งร่าง

ตัวอย่างคำตอบที่ไม่ดี **ผู้สอนสร้างขึ้นเพื่อให้จับข้อผิดพลาด ไม่ใช่ผลโมเดลที่สังเกตจริง**: “ใช้คูปองร่วมคะแนนได้ ยกเลิกหลังจ่ายได้ และคืนเปลี่ยนใจได้ เพราะแชตใหม่กว่า ทดสอบแล้วต้องผ่านทั้งหมด” — ผิดเพราะเลือกแหล่งเองและเปลี่ยนเรื่องรอตัดสินเป็นกติกายืนยัน

ตัวอย่างครบทั้งงานและการให้คะแนนอยู่ในเฉลยผู้สอนของ Lab 1 ผู้สอนแสดงหลังทั้งสองรอบเท่านั้น เพื่อไม่ปนเปื้อนการทดลอง ผู้เรียนใช้ template.md ดูรูปแบบก่อนทำได้ทั้งสองแบบ

## โจทย์นำไปใช้ใหม่

เปิด session ใหม่ ใช้ Skill เดิมโดยไม่แก้ body ก่อนรอบแรก พร้อม input.md ชุด C และ references.md/template.md ของ Lab นี้ แล้ววาง:

```text
ใช้คู่มือเดิมกับ input.md ชุด C อ่านกฎและข้อมูลใหม่ทั้งหมด ระบุสิ่งที่เปลี่ยนจากขอบเขตงานเดิมและผลต่อคำตอบ อย่าใช้เฉลยหรือผลรอบก่อน ถ้าคู่มือใช้ไม่ได้ให้บอกส่วนที่ต้องปรับก่อนตัดสินใจ
```

เรียก Skill ด้วยชื่อด้านบนก่อนข้อความนี้ บันทึกผลแรกเป็น reuse ก่อนแก้คู่มือ เวลาปรับคู่มือหลังจากนั้นเป็น maintenance แยก ไม่ย้อนเปลี่ยนคะแนนครั้งแรก
