## เครืองมือ
   ใช้ Excalidraw วาดรูปการสอน และ Playwright CLI** ในการทดลองจริงผ่าน web ทั้ง capture รูปทดลองจริง


-ช่วยออกแบบสื่อการสอนเรื่อง **“แก้ปัญหาการทำงานด้วย AI: เปรียบเทียบการใช้ Prompt ทั่วไปกับการใช้ Skill”** สำหรับ **คนทั่วไปที่ใช้คอมพิวเตอร์และสนทนากับ AI ได้** โดยไม่ต้องมีพื้นฐานการเขียนโปรแกรม System Analysis หรือ DevOps

ครอบคลุม 3 ด้าน ได้แก่ **System Analysis, DevOps และการใช้ LLM แก้ปัญหาธุรกิจ** เริ่มจากโจทย์ที่เข้าใจง่าย แล้วเพิ่มความท้าทายทีละขั้น

**ข้อกำหนดสำคัญ:** ผู้เรียนต้องแก้ปัญหาด้วย **Prompt คำสั่งสำเร็จรูป และ Skill เท่านั้น** ห้ามกำหนดให้เขียนหรือแก้โค้ด สคริปต์ หรือไฟล์ตั้งค่าระบบด้วยตนเอง ทุก Lab ต้องมีข้อมูลพร้อมใช้ แนวทางแก้ปัญหา ตัวอย่าง และคำใบ้ให้ทำตามได้

1. **อธิบาย Skill ให้คนทั่วไปเข้าใจ**

   อธิบายว่า Skill คืออะไรในบริบทของ AI Agent ประกอบด้วยอะไร และต่างจากการพิมพ์ Prompt สั่งงานแต่ละครั้งอย่างไร โดยใช้ตัวอย่างจากการทำงานที่พบได้ทั่วไป

   ในบทเรียนนี้ให้เน้น Skill ที่ประกอบด้วยคำแนะนำภาษาธรรมชาติ ขั้นตอนทำงาน เอกสารอ้างอิง และรูปแบบผลลัพธ์ โดยไม่ต้องเขียนโปรแกรมประกอบ

   อธิบายประโยชน์เรื่องการทำงานตามขั้นตอน ความสม่ำเสมอ และการใช้ซ้ำ พร้อมข้อจำกัด เช่น คำแนะนำไม่ครบ นโยบายล้าสมัย หรือ Skill ไม่เหมาะกับโจทย์ และชี้แจงว่าการใช้ Skill ไม่ใช่การฝึกโมเดลใหม่

2. **Lab 1: System Analysis — เปลี่ยนความต้องการที่กระจัดกระจายให้เป็นข้อตกลงที่ชัดเจน**

   **สถานการณ์:** เจ้าของร้านต้องการระบบรับคำสั่งซื้อ แต่ข้อมูลอยู่ในข้อความแชต บันทึกประชุม และนโยบายร้าน บางเรื่องไม่ครบหรือขัดแย้งกัน เช่น การใช้ส่วนลด การยกเลิกคำสั่งซื้อ และการคืนสินค้า

   เตรียมเอกสารตัวอย่างสั้น ๆ ที่คนทั่วไปอ่านเข้าใจได้ ให้ผู้เรียนแนบข้อมูลแล้วใช้ AI ช่วยรวบรวมความต้องการ ตรวจหาข้อขัดแย้ง และตั้งคำถามที่ต้องถามเจ้าของร้านเพิ่มเติม

   **แนวทางแก้ปัญหา:** รวบรวมข้อมูล → แยกเรื่องให้เป็นหมวดหมู่ → ตรวจความกำกวมและความขัดแย้ง → ระบุสิ่งที่ต้องถามเพิ่ม → สรุปกติกาและวิธีตรวจรับงาน โดยไม่เติมข้อมูลที่ยังไม่มีหลักฐาน

   **ตัวอย่าง Prompt:**
   “ช่วยอ่านเอกสารที่แนบ แล้วสรุปว่าเจ้าของร้านต้องการอะไร แยกข้อมูลที่ชัดเจน ข้อมูลที่ขัดแย้ง และข้อมูลที่ยังขาด พร้อมเสนอคำถามที่ควรถามเพิ่ม และระบุว่าแต่ละประเด็นมาจากเอกสารใด”

   **ผลลัพธ์ที่ต้องส่ง:** ตารางความต้องการ รายการคำถาม กติกาการทำงานของระบบ และตัวอย่างสถานการณ์ที่ใช้ตรวจว่าระบบทำงานถูกต้อง ทั้งหมดเขียนด้วยภาษาธรรมชาติ

   **Skill ที่ใช้:** ผู้ช่วยตรวจความครบถ้วนและความสอดคล้องของความต้องการ

3. **Lab 2: DevOps — ภารกิจ 30 นาที กู้เว็บร้านค้าก่อนเปิดขาย**

   **สถานการณ์:** อีก 30 นาทีร้านค้าจะเปิดแคมเปญขายสินค้า แต่เว็บไซต์เปิดไม่ได้ ผู้เรียนต้องใช้ AI ช่วยตรวจหาสาเหตุ เลือกคำสั่งแก้ไข และยืนยันว่าเว็บกลับมาใช้งานได้

   ใช้ระบบตัวอย่างสำเร็จรูปในสภาพแวดล้อม Lab ที่เตรียมไว้แล้ว ผู้เรียนไม่ต้องสร้างระบบหรือแก้ไฟล์ตั้งค่า แยกเวลาเตรียมเครื่องออกจากเวลาเล่นภารกิจ

   เตรียมคำสั่งที่คัดลอกใช้ได้สำหรับเปิด Lab ตรวจสถานะ ดูข้อความแจ้งปัญหา เริ่มบริการ กู้คืนเวอร์ชันเดิม ตรวจผล และรีเซ็ต Lab โดยอธิบายทุกคำสั่งว่าใช้เมื่อใด ทำอะไร และควรเห็นผลแบบไหน

   เริ่มจากเหตุขัดข้องง่าย ๆ เช่น บริการเว็บไซต์หยุดทำงาน แล้วเพิ่มรอบต่อยอด เช่น อัปเดตแล้วเว็บใช้งานไม่ได้และต้องกลับไปใช้เวอร์ชันเดิม แต่ละรอบมีสาเหตุหลักหนึ่งสาเหตุ

   **แนวทางแก้ปัญหา:** สังเกตอาการ → ใช้คำสั่งตรวจสอบ → ส่งผลให้ AI ช่วยแปลความหมาย → เลือกคำสั่งแก้ไขจากคู่มือ → ตรวจยืนยันผล

   **ตัวอย่าง Prompt:**
   “เว็บไซต์เปิดไม่ได้ นี่คือคู่มือคำสั่งและผลตรวจระบบ ช่วยอธิบายปัญหาเป็นภาษาง่าย ๆ เลือกคำสั่งถัดไปจากคู่มือ พร้อมบอกเหตุผลและผลที่ควรเห็น หากข้อมูลยังไม่พอ ให้บอกว่าต้องตรวจอะไรเพิ่ม”

   **ผลลัพธ์ที่ต้องส่ง:** อาการที่พบ หลักฐาน สาเหตุที่สรุปได้ คำสั่งที่ใช้ และผลตรวจหลังแก้ไข โดยต้องยืนยันว่าเว็บไซต์ใช้งานได้จริงภายใน Lab

   **Skill ที่ใช้:** ผู้ช่วยตรวจและกู้ระบบทีละขั้น ซึ่งตรวจหลักฐานก่อนเสนอวิธีแก้ และตรวจยืนยันหลังดำเนินการ

4. **Lab 3: LLM ด้านธุรกิจ — จัดการข้อร้องเรียนให้ทันและตอบตรงตามนโยบาย**

   **สถานการณ์:** ร้านค้าได้รับข้อความร้องเรียนจำนวนมาก ทำให้ตอบช้า จัดลำดับงานไม่เหมาะสม และตอบเรื่องคืนสินค้าหรือคืนเงินไม่สม่ำเสมอ

   เตรียมข้อความลูกค้า ตารางคำสั่งซื้อ นโยบายร้าน และเกณฑ์ความเร่งด่วนจากข้อมูลจำลอง ให้ผู้เรียนแนบข้อมูลและสั่งงาน AI โดยไม่ต้องเชื่อมต่อ API หรือเขียนโปรแกรม

   **แนวทางแก้ปัญหา:** อ่านข้อความ → ตรวจข้อมูลคำสั่งซื้อ → เทียบกับนโยบาย → จัดลำดับความเร่งด่วน → เสนอแนวทางและร่างคำตอบ → ระบุกรณีที่ต้องขอข้อมูลเพิ่มหรือส่งต่อให้เจ้าหน้าที่

   ครอบคลุมกรณีปกติ ข้อมูลไม่ครบ คำขอที่ขัดกับนโยบาย และกรณียกเว้นที่ผู้เรียนต้องรู้ว่าไม่ควรให้ AI ตัดสินใจเอง

   **ตัวอย่าง Prompt:**
   “ช่วยจัดลำดับข้อความร้องเรียนจากข้อมูลที่แนบ โดยใช้เกณฑ์ความเร่งด่วนและนโยบายร้าน ระบุเหตุผล แนวทางดำเนินการ และร่างคำตอบลูกค้า พร้อมอ้างอิงนโยบายที่เกี่ยวข้อง หากข้อมูลไม่ครบ ให้ระบุสิ่งที่ต้องถามเพิ่ม”

   **ผลลัพธ์ที่ต้องส่ง:** ตารางจัดลำดับงาน เหตุผลประกอบ แนวทางดำเนินการ ร่างคำตอบ และรายการที่ต้องขอข้อมูลเพิ่มหรือส่งต่อ

   **Skill ที่ใช้:** ผู้ช่วยจัดการข้อร้องเรียนตามข้อมูลและนโยบายธุรกิจ

5. **มีตัวช่วยให้ทำต่อได้ในทุก Lab**

   ทุก Lab ต้องประกอบด้วย:

   * **คู่มือทีละขั้น:** บอกว่าต้องเริ่มตรงไหน แนบข้อมูลอะไร และควรตรวจผลอย่างไร
   * **Prompt พร้อมใช้:** ครอบคลุมการเริ่มงาน วิเคราะห์ แก้ไข และตรวจคำตอบ
   * **คำสั่งสำเร็จรูปเมื่อจำเป็น:** คัดลอกใช้ได้ พร้อมคำอธิบายและผลที่คาดว่าจะเห็น
   * **ตัวอย่างผลลัพธ์:** แสดงลักษณะคำตอบที่ครบถ้วนและข้อผิดพลาดที่ควรสังเกต
   * **คำใบ้สามระดับ:** ชี้จุดสังเกต บอกขั้นตอนถัดไป และแสดงวิธีแก้พร้อมเหตุผล
   * **แนวทางเมื่อติดขัด:** บอกว่าควรนำข้อมูลหรือผลลัพธ์ส่วนใดกลับไปถาม AI

   ใช้คำอธิบายที่คนทั่วไปเข้าใจ และอธิบายศัพท์เทคนิคเมื่อปรากฏครั้งแรก

6. **สาธิตการสร้างและปรับ Skill โดยไม่เขียนโค้ด**

   เลือกเครื่องมือที่ผู้เรียนเปิดใช้ Skill ได้โดยไม่ต้องเขียนโปรแกรม และอธิบายขั้นตอนใช้งานให้ทำตามได้

   ให้ผู้เรียนใช้ AI ช่วยร่าง Skill เป็นข้อความคำแนะนำ พร้อมตัวอย่างเนื้อหา SKILL.md ที่ระบุวัตถุประสงค์ เงื่อนไขการใช้งาน ข้อมูลที่ต้องมี ขั้นตอนทำงาน วิธีจัดการข้อมูลไม่ครบ รูปแบบคำตอบ และเกณฑ์ตรวจรับงาน

   สาธิตการปรับ Skill จากข้อผิดพลาดที่พบ เช่น เพิ่มขั้นตอนตรวจนโยบาย เพิ่มการขอข้อมูล หรือเพิ่มการตรวจยืนยันผล แล้วนำ Skill เดิมไปใช้กับข้อมูลชุดใหม่

7. **เปรียบเทียบแบบไม่ใช้ Skill กับแบบใช้ Skillอย่างเป็นธรรม**

   ให้ทั้งสองแบบได้รับข้อกำหนด ข้อมูลอ้างอิง คู่มือคำสั่ง ตัวช่วย โมเดล เครื่องมือ และเวลาที่เทียบเคียงกัน แบบไม่ใช้ Skill ต้องได้รับ Prompt ที่ชัดเจนและครบถ้วน

   แสดงผลลัพธ์ ข้อผิดพลาด และสิ่งที่ผู้เรียนต้องตรวจแก้ของทั้งสองแบบ ใช้โจทย์ใหม่ที่มีความยากใกล้เคียงกันและสลับลำดับการทดลอง เพื่อลดผลจากการจำเฉลย

   ประเมินด้วยความถูกต้อง ความครบถ้วน เวลาที่ใช้ จำนวนครั้งที่ต้องแก้ไข จำนวนครั้งที่ขอคำใบ้ และความสามารถในการใช้ซ้ำ โดยเพิ่มตัวชี้วัดเฉพาะแต่ละ Lab:

   * **System Analysis:** ตรวจพบข้อขัดแย้งและข้อมูลที่ขาดได้ครบเพียงใด
   * **DevOps:** เลือกวิธีแก้ได้ถูกต้องและตรวจยืนยันการฟื้นบริการได้หรือไม่
   * **LLM ด้านธุรกิจ:** ตอบตรงตามนโยบายและลดงานตรวจแก้ได้เพียงใด

   แยกเวลาสร้างและดูแล Skill ออกจากเวลาใช้งาน จัดทำแบบบันทึกคะแนนที่กรอกได้โดยไม่ต้องเขียนโปรแกรม และสรุปผลเป็นตาราง

   **ห้ามแต่งผลการทดลองหรือสรุปล่วงหน้าว่า Skill ต้องดีกว่าเสมอ** หากยังไม่ได้ทดลองจริง ให้ระบุว่าเป็นผลที่คาดหวัง พร้อมอธิบายว่า Skill ช่วยหรือไม่ช่วยภายใต้เงื่อนไขใด

8. **จัดชุดสื่อให้พร้อมนำไปสอน**

   แต่ละ Lab ต้องมีวัตถุประสงค์ ระยะเวลา วิธีเตรียมตัว สถานการณ์ ชุดข้อมูลหรือเอกสารพร้อมใช้ คู่มือทีละขั้น Prompt คำสั่งที่จำเป็น ตัวอย่าง Skill ใบงาน คำใบ้ เกณฑ์ประเมิน เฉลยสำหรับผู้สอน และคำถามอภิปราย

   คำสั่งและขั้นตอนต้องตรงกับเครื่องมือที่เลือก พร้อมระบุสถานะการตรวจสอบตามจริง หากยังไม่ได้ทดสอบ ให้แยกออกจากส่วนที่ตรวจสอบแล้วอย่างชัดเจน

   เพิ่มโจทย์ต่อยอดที่เปลี่ยนข้อมูลหรือข้อกำหนด เพื่อให้ผู้เรียนฝึกนำ Skill ไปใช้กับสถานการณ์ใหม่

**เป้าหมายของบทเรียน:** คนทั่วไปสามารถใช้ Prompt คำสั่งสำเร็จรูป และ Skill เพื่อแก้ปัญหาอย่างมีขั้นตอน เข้าใจเหตุผลของการตัดสินใจ ตรวจสอบคำตอบของ AI และประเมินได้ว่า Skill ช่วยให้งานดีขึ้นจริงหรือไม่ โดยไม่ต้องเขียนโค้ด
